## What Went Well

- **All five audit slices shipped in one release** — The monthly audit feature (Group A: API-only checks for CodeQL/Dependabot/branch-protection/credential-expiry; Group B: optional BATS security-regression subset via `K3DM_HERMES_AUDIT_RUN_BATS=1`) deployed smoothly alongside three webhook fixes (F1/F2/F3), delivering comprehensive hardening in a single 1.32.0 milestone.

- **`audit.py` kept pure** — The Hermes audit module remained a pure logic/reporting library with no mutation path; the bats subprocess runner was isolated in `bin/k3dm-hermes` (`audit()` subcommand), preserving the invariant that Hermes audit is read-only and can degrade gracefully on missing scopes.

- **CI cred-dir failure root-caused in an ubuntu container** — A BATS security-regression test (F2 egress hardening) failed on the first Linux CI run, but was root-caused systematically in a container rather than guessed or dismissed. The issue — test used `${HOME}` which on Linux mktemp resolves to `/tmp` (an in-scope path for the sandbox deny-list) — was caught and fixed before merge.

- **Git-egress gap caught by Copilot and closed with fail-closed guard + tests** — The Copilot PR #123 review flagged that git network subcommands (clone/fetch/pull/push/remote/ls-remote/submodule) were not blocked by the F2 sandbox hardening, creating an egress bypass. The fix added a fail-closed guard + regex test coverage and shipped within the same release.

## What Went Wrong

- **F2 sandbox tests verified only on macOS before CI** — Codex-authored security-regression tests (commit `97d96366`) for the `/ask` sandbox hardening passed locally on macOS but had a latent Linux-only failure. The scope test built its out-of-scope path from `${HOME}`, but the BATS suite exports `HOME=$(mktemp -d)`, which on Linux lives under `/tmp` — an in-scope sandbox prefix. This only surfaced on the first PR CI run, requiring a fix post-author.

- **F2 egress hardening missed git network subcommands** — The initial `/ask` sandbox hardening (F2) blocked curl/wget/ssh and shell escapes but did not explicitly block git network subcommands, creating a potential egress bypass via `git clone` / `git push` to exfil data. This gap was caught by Copilot during the PR review and closed with a fail-closed guard in the same release.

## Process Rules Added

| Rule | Why | Example |
|------|-----|---------|
| **Sandbox scope tests must use fixed absolute paths outside the allow-list, never `${HOME}`-derived paths** | The test suite reassigns `HOME` to a `mktemp -d`, which on Linux resolves under `/tmp` (an in-scope sandbox prefix). Tests expecting a path outside scope must use a fixed location like `/opt/testdata` or a tmpdir outside `/tmp`. | The F2 test now creates out-of-scope files in a fixed directory, not `${HOME}/test-out-of-scope.txt`. |
| **Egress-blocking hardening must cover git network subcommands** | Git (clone/fetch/pull/push/remote/ls-remote/submodule) can exfil data over the network; a denylist-based sandbox that blocks curl/wget/ssh must also block git's network commands or risk egress bypass. | F2 sandbox now has an explicit regex guard on git subcommands: `git (clone\|fetch\|pull\|push\|remote\|ls-remote\|submodule)` fails closed. |
| **Codex-authored tests verified only on macOS must be run on Linux (container) before claiming green** | Latent platform-specific failures (path resolution, temp dir location, syscall behavior) may hide until CI runs the test on Linux. Any test written for a service that may run on multiple platforms must be smoke-tested in the target platform before merge. | F2 security-regression tests written on macOS should have been run in a container image matching the CI environment before PR merge. |

## Decisions Made

1. **Monthly audit is a report-only feature (no actuator).** The audit.py module never proposes repairs, never writes state, and never executes actions. Every check degrades gracefully to "unavailable" on a missing scope rather than fabricating a clean bill of health.

2. **Release-table rows are written at post-merge.** The v1.32.0 row added to README.md and docs/releases.md reflects post-merge facts (PR merged, SHA, branch protection restored) rather than pre-merge speculation.

3. **Hermes↔Slack approval stays v1.33.0.** The next milestone (Hermes↔Slack interactive approval, Option A) remains scoped for v1.33.0 after the webhook hardening clears the way. No scope creep into v1.32.0.

## Theme

**One paragraph:**

v1.32.0 hardens the `/ask` webhook before it becomes the control surface for Hermes↔Slack interactive approval, and gives Hermes a read-only monthly security conscience that reports degradation gracefully. The three F-series fixes (F1 fix-mode privilege escalation, F2 sandbox egress bypass, F3 response_url SSRF/exfil) lock down the webhook's privilege model, sandbox confinement, and output routing. The monthly audit adds observability without mutation — a pure reporting lens on open CodeQL/Dependabot alerts, branch-protection posture, and credential expiry, optional and graceful on missing scopes. Three deployment cycles (v1.30.0 Phase-2 repairs → v1.31.0 token expiry advisory → v1.32.0 hardening) brought Hermes from a passive monitor to a proposal engine to a hardened platform guardian.
