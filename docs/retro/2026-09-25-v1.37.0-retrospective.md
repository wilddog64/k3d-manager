# Retrospective — v1.37.0

**Date:** 2026-09-25

**Milestone:** v1.37.0 — webhook decomposition and gates that prove what they claim

**PR:** #131 — merged to main (925c43e7)

**Participants:** Claude, Codex, Gemini, Copilot

## What Went Well

The webhook monolith decomposition delivered on its goal: four modules extracted (`webhook/policy.py`, `webhook/smoke.py`, `webhook/agent.py`, `webhook/lifecycle.py`, `webhook/status.py`) with explicit entrypoint dependencies injected, a complete route table documented in the architecture docs, and every extracted function proven by mutation tests before merge. Authorization was hardened alongside: unknown actor roles now default to `reader` rather than `admin`, and POST authorization enforces both route floors and dynamic policy, auditing every request exactly once.

The ACG Tier 2 gate was rewritten correctly — it now calls `_secret_load_data`, the same loader the session check uses, and arms the upstream fail-closed gate (`K3DM_ACG_REQUIRE_CREDENTIALS=1`) so readability is the claim under test. The implementation required a fake `security` **executable** on `PATH` to be discovered at all, surfacing the kind of environment-dependency gap that unit tests routinely hide.

The live smoke gate executed and reported honestly — 2 failures found, 0 regressions in v1.37.0. Both failures traced to stale gate defaults, not to changes this release shipped. Four findings the gate surfaced were filed as specs and deferred to v1.38.0 with the understanding that a gate reporting red on a healthy cluster has paid for itself: it proved the methodology works.

## What Went Wrong

Two of v1.37.0's own tests could not fail. Copilot caught both:

1. **A negated `rg` disappearance guard** (`scripts/tests/lib/hostinger_pushgateway_port_forward.bats:19`) passed when `rg` was absent or lacked PCRE2 support, silently accepting environments the test could not measure. Fixed with `grep -nE` + explicit status assertion (returns `1` only for "no lines matched", rejects missing binary or bad pattern with exit `2`).

2. **Two Alertmanager route tests** (`scripts/tests/plugins/e2e_observability.bats:225,230`) took a hard dependency on PyYAML, which is not a declared dependency elsewhere in the repo. Where PyYAML is absent the tests raise `ModuleNotFoundError` and fail even when the template is correct. Switched to `yq`, which four other suites already invoke unguarded; added a non-empty assertion on `select` output so deleting the warning route entirely passes.

Both findings represent the same defect class this release exists to eliminate: a check that returns green without exercising what it claims to cover.

## Process Rules Added

| Rule | Rationale |
|---|---|
| Never assert a disappearance with `! <tool>` — invert on an exact status instead | `!` inverts *any* non-zero exit. `grep` returns `1` only for "no matches" and `2` for errors. Asserting `-eq 1` rejects missing binaries and bad patterns that `! grep` silently accepts. |
| A test may only depend on tooling some other suite already depends on unguarded | PyYAML was guarded in `argocd.bats` — that guard was the signal not to take a hard dependency on it. If a tool is optional elsewhere, it remains optional in new tests. |
| A `select`/filter query needs a non-empty assertion | Deleting the thing under test passes without it. `run yq -r 'select(...)'` with `[ -n "${output}" ]` on the next line. |

## Decisions Made

**CodeQL alert 25 was renamed, not dismissed.** The field `config_secret` carried a Secret name, not a credential value, and CodeQL's clear-text-logging heuristic classifies sources by identifier name. The rename (`config_secret` → `config_ref`, `config_secret_missing` → `config_ref_missing`) is the honest fix independently of CodeQL — a reader would reasonably expect `config_secret` to hold a credential. Blast radius: three files, zero external consumers. The change was verified live (emits `"config_ref": "alertmanager-smtp-secret"`) and pushed with reasoning in the `alert_delivery` docstring so the next reader does not re-tidy the name back.

**Four CodeQL alerts 23/24/26/27 (`posix_spawn` injection) were dismissed as false positives.** The executable in both cases is hard-coded at every call site (`"make"` or `"aws"` or an absolute path); argument validation is closed-allowlist (target must be a key of `MAKE_TARGETS`, args must match anchored patterns over metacharacter-free charsets). `shlex.quote` is applied on top of that. The alerts surfaced because the webhook decomposition made an interprocedural taint path *visible* to CodeQL; the code's defensive capability did not change. Dismissals carry in-code markers pointing at the documented reasoning.

## Theme

This release finally moved what had been stalled since v1.36.0: the webhook monolith split and the hardening of ACG Tier 2 authentication. The two Copilot findings exposed the deeper lesson — a test that never fails is not a protection, and the methodology for fixing it is not to ignore the failure but to wire the gate so it *can* fail. The smoke gate, by reporting true failures on a healthy cluster, proved the methodology works: four findings traced to stale test defaults, not to changes v1.37.0 introduced. The reusable pattern is to instrument stages before theorizing about why one fails; a `count=0` selector on a rendered visible form is a wrong pattern, never a slow page.
