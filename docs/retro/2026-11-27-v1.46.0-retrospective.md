# Retrospective — v1.46.0

**Date:** 2026-11-27
**Milestone:** Cloud-request trust and operator acceptance, plus hub reliability fixes
**PR:** #166 — squash-merged to main (`f2a5f7a3`), tag `v1.46.0`
**Participants:** Claude (spec, verify, land), Luna, Flash, Terra, Astra, Hydrogen, Carbon (workers), Neon and Argon
(blind reviews), operator (intents, promotes, live steps, merge). Copilot capped until 2026-12-01.

## What Went Well

- **Plan 1 (submitter authentication)** landed in six child specs over one day and was live-verified on 2026-11-25.
- **The model experiment across plans 2 and 3 worked:** seven worker models each took one child spec and all passed
  independent verification (`v1460-p2a`…`p2e`, `p3a`…`p3d`). Assignment by spec shape, not by vendor, held up.
- **The live run caught what CI could not.** The first hub `make-test-pytest` (3005 passed) exposed two drift tests
  that only passed where a developer machine supplied a backup pytest. The fast gate, during the land, caught a second
  test that leaked the managed venv's pytest. Both were fixed before merge.
- **W1 (promote restarts changed agents) was proven live** on the first promote that included it.
- **The Argon release review was scored against the code:** 2 fixed, 1 captured, 1 traced to Claude's own review-spec
  wording rather than the code.

## What Went Wrong

- **A red required check went unseen.** CodeQL failed on every PR #166 head from opening (the documented `proc.py` spawn
  false positive moved one line by `5625527b`). Claude reported heads ready while reading only the test jobs. Alerts
  40/41 dismissed with a recurrence note; the existing rule (all check-runs on the head SHA) was the right one and was
  not followed.
- **Worker tests that could not fail:** Flash's precedence test for the fast gate matched a marker the gate never
  prints. A mutant (venv lookup first) found it.
- **`land` fights the subtree workflow:** W4 needed a manual rebuild, subtree pull, cherry-pick and ff-push twice;
  `land`/`verify` then refused the task (`v1460-acgssh-k3dm-luna` left with 0 lands). Captured as P3.
- **Docs-only pushes reset CI and moved the promote ref three times in one day**, which led to the freeze rule below.
- **A review spec repeated a commit-message claim** (`91609294`, "host lookup uses `ssh -G`") instead of the spec's
  contract, producing Argon's B1 false positive.
- **Six escapes** were traced back to v1.46.0 work (see Dispatch Review), mostly approval-card wording and acceptance
  oracle gaps that the combine reviews found after landing.
- **The auto-mode classifier now blocks Claude from disabling `enforce_admins`.** The operator ran it; `/create-pr`
  step 7 still assumes Claude does.

## Theme

v1.46.0 set out to make cloud requests trustworthy (authenticated submitters, routed notices) and to make the
operator's acceptance checks repeatable. It did both, then spent its last two days on hub reliability: promotes now
restart what changed, stale sandbox apps get cleaned up, and the hub can finally run its own pytest suite. The
recurring lesson was that a check only counts if it can fail and is actually read. A worker test that could never go
red, a red CodeQL check nobody looked at, and a reminder hook that announced landings that never happened all looked
like safeguards. The live run on the hub was what separated passing from proven.
