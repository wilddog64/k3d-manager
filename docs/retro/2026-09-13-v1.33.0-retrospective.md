# v1.33.0 Release Retrospective (2026-09-13)

## What Went Well

1. **Codex smoke test gate**: Webhook 13/13 passed twice (serial runs), cluster-health 9/0, node 14/14, pytest 69/69 — all verification targets met before PR merge.

2. **Scope discipline**: PR #126 stayed focused on the three headline features (Hermes Slack approvals, Kine circuit breaker, hub recovery hardening) plus bug fixes. 19 bug specs in `docs/bugs/` were filed, scoped, and solved — no runaway scope creep.

3. **Copilot collaboration**: Copilot review landed 4 findings (Kine registration base64, Vault role path unescaped, duplicate CHANGELOG headings, BATS nesting simplification). All were addressed before merge, no false positives, and the "nesting simplified anyway" finding actually improved code clarity.

4. **Branch protection discipline**: enforce_admins was re-enabled immediately after merge verification (confirmed true via `gh api`), closing the merge-gate window.

## What Went Wrong

1. **Draft PR anti-pattern**: PR #126 was opened as a draft initially — Copilot review requests don't register on draft PRs, so the first round of findings were missed. Rule established: never draft PRs; user correction unlocked the gate.

2. **GitGuardian false-positive handling**: A base64 "root-token" BATS stub in a test file triggered a false-positive incident (37233897). User resolved it via the GitGuardian API `IGNORE` endpoint. No process failure — the tool flagged test data correctly — but it consumed review cycles.

3. **Live sandbox register was stale**: During the merge window, ApplicationSets on the hub were still pinned to `k3d-manager-v1.33.0` branch-tracking. A blanket reapply would have re-named the istio-ambient apps (because the values-branch ref would re-pin) — avoided via a read-only verify check, but it exposed the ApplicationSet reapply entrypoint spec as a pending v1.34.0 workitem.

4. **gh CLI 401 (locked login keychain)**: One push attempt failed with auth 401 — root cause was a locked macOS login keychain (not a token issue). Recovery: `security unlock-keychain`. The failure was transient and didn't block the release, but it highlighted that the keychain must be open before any git/gh operations.

## Process Rules Added

1. **Never draft PRs** — PR request + Copilot review don't work on drafts; always open as a normal PR, request Copilot review, and merge only after all gates pass.

2. **ApplicationSet reapply is a live operator step, not a script step** — a blanket reapply on a release branch can rename or re-purpose deployed applications. The spec-driven entrypoint (`deploy_argocd_applicationsets`) exists, but the decision to reapply should live with the operator, not be automatic on merge.

3. **Check git status before pushing** — Codex had staged code from a prior session; the commit included the correct files, but a pre-push `git status` check would have surfaced any unintended staging.

## Decisions Made

1. **GitGuardian incident 37233897 marked resolved** — false positive on base64 test stub; user resolved via API ignore; no policy change needed (test data should be flagged).

2. **Kine circuit breaker gated on explicit opt-in (`K3DM_HERMES_AUTO_KINE_GUARD=1`)** — prevents accidental ArgoCD pause from a misdiagnosed Kine stall; no automatic behavior in the codebase (grep-proven invariant preserved).

3. **ApplicationSet reapply deferred to v1.34.0 spec** — the entrypoint exists, but the integration spec (when/how to call it, what validation gates apply) needs closure; pending approval from the operator before any live run.

4. **BATS negation (`! grep`) follow-up deferred to v1.34.0** — identified via Copilot as a source of flakes (mid-test negations never fail), but the fix scope is large; captured as `docs/bugs/v1.33.0-bugfix-stale-bats-grep-assertions.md` for follow-up.

## Theme

**Hermes Slack approvals + Kine resilience + hub recovery hardening.** This release closes three major workstreams: interactive incident response (Slack approval buttons), proactive Kine stall detection (circuit breaker), and 19 operational fixes that hardened hub recovery so rebuilds no longer lose state (Vault role policies, Keycloak secrets, ArgoCD credentials, port-forward interference).
