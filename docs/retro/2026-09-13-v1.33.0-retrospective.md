# v1.33.0 Release Retrospective (2026-09-13)

## What Went Well

1. **Codex smoke test gate**: Webhook 13/13 passed twice (serial runs), cluster-health 9/0, node 14/14, pytest 69/69 — all verification targets met before PR merge.

2. **Scope discipline**: PR #126 stayed focused on the three headline features (Hermes Slack approvals, Kine circuit breaker, hub recovery hardening) plus bug fixes. 19 bug specs in `docs/bugs/` were filed, scoped, and solved — no runaway scope creep.

3. **Copilot collaboration**: Copilot raised 4 findings. Three were real: the Kine registration Secret base64 decode, the unescaped Vault role path, and the duplicate CHANGELOG headings. The fourth said the BATS quoting in `platform_ops_appset_diff.bats` was invalid; that was a false positive, since the suite passed. The test was still simplified to `run awk` with `$output` assertions and checked against a negative fixture.

4. **Branch protection discipline**: enforce_admins was re-enabled immediately after merge verification (confirmed true via `gh api`), closing the merge-gate window.

## What Went Wrong

1. **Draft PR anti-pattern**: PR #126 was opened as a draft, which the user never asked for. It was converted to a normal PR and Copilot review was requested afterwards.

2. **GitGuardian false positive**: a Vault root-token stub in a BATS fixture raised incident 37233897. The GitGuardian GitHub check ignores `.gitguardian.yaml`, so the only way to clear it was in the dashboard, which the user did.

3. **ApplicationSet reapply risk**: the release step says to reapply the ApplicationSets, but a blanket reapply of all rendered sets would have renamed the istio-ambient apps. A read-only check (`argocd_check_values_branch` plus `kubectl diff` of all 12 rendered sets) showed every values ref was already on `k3d-manager-v1.33.0` and nothing changed, so no apply was needed.

4. **enforce_admins not disabled when gates passed**: Claude waited for GitGuardian to clear before disabling `enforce_admins`, so the user could not merge and had to ask. It should be disabled as soon as CI, Copilot, smoke and scope gates pass.

## Process Rules Added

1. **Never draft PRs** — PR request + Copilot review don't work on drafts; always open as a normal PR, request Copilot review, and merge only after all gates pass.

2. **ApplicationSet reapply stays a required release step (CLAUDE.md), but never a blanket reapply**: verify read-only first; if there is drift, reapply only the affected sets through a scoped entrypoint (spec'd for v1.34.0), with the operator's go.

3. **Disable `enforce_admins` as soon as the PR gates pass** (create-pr step 7). Do not hold it back for checks that do not block the merge.

## Decisions Made

1. **GitGuardian incident 37233897 resolved by the user** as a false positive on test data. No policy change.

2. **Kine circuit breaker gated on explicit opt-in (`K3DM_HERMES_AUTO_KINE_GUARD=1`)** — prevents accidental ArgoCD pause from a misdiagnosed Kine stall; no automatic behavior in the codebase (grep-proven invariant preserved).

3. **ApplicationSet reapply deferred to v1.34.0 spec** — the entrypoint exists, but the integration spec (when/how to call it, what validation gates apply) needs closure; pending approval from the operator before any live run.

4. **BATS negation (`! grep`) follow-up deferred to v1.34.0**: a mid-test `! grep` never fails a test, and PR #126 added 15 of them. Tracked in `docs/bugs/v1.33.0-bugfix-stale-bats-grep-assertions.md`.

## Theme

**Hermes Slack approvals + Kine resilience + hub recovery hardening.** This release closes three major workstreams: interactive incident response (Slack approval buttons), proactive Kine stall detection (circuit breaker), and ~20 operational fixes that hardened hub recovery so rebuilds no longer lose state (Vault role policies, Keycloak secrets, ArgoCD credentials, port-forward interference).
