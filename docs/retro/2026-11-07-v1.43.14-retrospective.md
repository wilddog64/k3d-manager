# Retrospective — v1.43.14

**Date:** 2026-11-07
**Milestone:** dispatch-stall gates, sudoers hardening, context cost
**PR:** #156 — merged to main (`82c1d9c8`)
**Participants:** Claude, Codex, Luna, Copilot

## What Went Well

- Plans and bug fixes landed in this release, among them per-turn Claude context cost, the `control` machine role, the Hub machine-role guard, resume-reason recording and the verification-ladder panel fix. The memory bank records offline verification for each, with live checks pending where the operator had to run them.
- Verifier evidence is now required for dispatch passes. Legacy claims are shown separately rather than counted as verified.
- Copilot's two inline findings were valid and fixed with tests shown red before the fix: the tunnel-port cast that could crash the status run, and a hardcoded Homebrew bash path in a bats helper.
- Every CI red after the first was reproduced and fixed on the branch, and each fix was proven by a test or a mutation rather than by a rerun alone.

## What Went Wrong

- **Release PR CI went red five times in sequence, all on Linux-only gaps.** Each one was hidden until the previous one passed, because the lint job stops at the first red step:
  1. A hardcoded `/opt/homebrew/bin/bash` in a bats helper (exit 127 on the Linux runner).
  2. `rg`, BSD `stat -f` and `plutil` absent or incompatible on Ubuntu (`1f2381c2`).
  3. The pytest drift fixture swapped `HOME`, so the nested Python lost the `pip --user` pytest install (`562a504b`).
  4. `codex_dispatch.bats` S1 test raced the worker's post-exit git bookkeeping. Proven by a mutation: an injected `sleep 1` between `write-tree` and `reset` failed the old helper (`bf83dfd4`).
  5. Ruff F841 and F401 in branch-added test files. Ruff is not installed on the Mac, so `make lint-python` had never run locally.
- **Copilot's review summary carried findings that were never posted inline.** Two were valid and fixed (blank `K3DM_STATUS_CHANNEL_ID` counted as configured; a dead unasserted `run grep`). Two were false (Dependabot `directories` with globs is supported; `$(cat ...)` strips the trailing newline). Triage is in `docs/issues/2026-11-07-copilot-pr156-review-findings.md`.
- **The "Human continuation prompts" dashboard panel does not count human turns.** It counts coordinator-to-sub-agent resume and intervention events. The fix is queued as the v1.43.17 human-operator-turns plan.
- **Over the release cap.** v1.43.14 reached six plans in the working tree; the fleet-host CPU and memory alerts plan moved to v1.43.16 before it started.

## Process Rules Added

| Rule | Where |
|------|-------|
| Before pushing a CI fix, run every remaining lint-job step locally, including pinned ruff in a scratch venv and `make validate-manifests` (candidate rule) | `docs/issues/2026-11-07-copilot-pr156-review-findings.md`, CI red 5 |
| Read the Copilot review body, not only the inline threads | `docs/issues/2026-11-07-copilot-pr156-review-findings.md` |
| A test that swaps `HOME` and starts another Python must carry the user site (`PYTHONUSERBASE`) with it | `docs/issues/2026-11-07-copilot-pr156-review-findings.md`, CI red 3 |
| A test that waits on a "done" signal must wait for the process to exit, not for the exit marker alone | `docs/issues/2026-11-07-copilot-pr156-review-findings.md`, CI red 4 |

## Decisions Made

- The ApplicationSet values ref stays on the release branch for this release. The `deploy/hub` ref is planned as v1.43.15 and v1.43.16 work, with a hub live-write guard.
- The fleet-host CPU and memory alerts plan moved to v1.43.16, since it had not started and its raw captures were never stored.
- The Hub-specific plans need the operator's dispatch go. None were dispatched during this release.

## Theme

v1.43.14 closed the dispatch gap that let stalled sub-agents look finished. Most of its time went to the CI path rather than the feature code. The Linux-only reds came one at a time because the lint job stops at the first failure. The lesson is to run the whole gate locally before pushing a fix, not to fix one red at a time.
