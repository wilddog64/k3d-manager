# Retrospective — v0.4.9

**Date:** 2026-08-14
**Milestone:** DRY_RUN guard primitives (Phase 0 of foundation-first DRY_RUN)
**PR:** #40 — merged to main (`1327c86`)
**Participants:** Claude, Codex, Copilot

## What Went Well

- **Foundation-first sequencing held.** The predicate + wrapper (`_dry_run_active`,
  `_dry_guard`) landed in the shared library *before* any k3d-manager wiring, so the
  downstream `make up`/`make down` guards (Phases 1–3) build on a released, subtree-pulled
  primitive instead of a private re-implementation.
- **Tiny, testable surface.** Two functions, pure logic, fully covered by BATS
  (`scripts/tests/lib/system.bats`) — no cluster, no mocks. The predicate's contract
  (`DRY_RUN=1` true; anything else false) is asserted directly.
- **Copilot caught a real portability bug.** The new tests sourced `scripts/lib/system.sh`
  repo-relative inside `bash -c` subshells, which passes only from repo root (as CI runs).
  Copilot flagged it; fixed to reuse the file's existing absolute `$SYSTEM_LIB` from
  `setup()`. Verified green from a foreign cwd (`/tmp`).

## What Went Wrong

- **Spec pasted divergent test scaffolding.** The plan doc's test block used repo-relative
  `source` lines instead of the file's established `setup()`/`$SYSTEM_LIB` convention,
  which is what produced the portability finding. The fix was mechanical, but the spec
  should have matched the existing test file's conventions up front.
- **`mktemp -u` in a test** — racy sentinel-path pattern; replaced with `mktemp` + `rm -f`.

## Process Rules Added

| Rule | Where |
|------|-------|
| Test specs must reuse the target test file's existing `setup()`/lib-path convention, not paste divergent repo-relative `source` lines | `docs/issues/2026-08-14-copilot-pr40-review-findings.md` |

## Decisions Made

- **DRY_RUN guards mutating operations only.** Read-only probes (`kubectl get`,
  `k3d cluster list`, `aws sts`, `launchctl list`) stay unguarded so status and inspection
  paths keep functioning under `DRY_RUN=1`. This is the contract downstream guards inherit.
- **No secrets in DRY_RUN log lines.** `_dry_guard` logs a human description, never the
  command's token/key arguments.
- **Phases 1–3 are k3d-manager's, not the library's.** The library ships the primitive;
  wiring it into `bin/cluster-up`/`cluster-down` and the provider functions happens
  downstream after the subtree pull.

## Theme

A deliberately small release: one predicate, one wrapper, and the discipline to ship them
through the shared library first. The value isn't the eight lines of Bash — it's that
every consumer now guards mutations against one audited primitive instead of scattering
`if [[ "$DRY_RUN" ]]` checks. Copilot earned its keep by catching a cwd-dependent test that
CI's repo-root working directory would have masked indefinitely.
