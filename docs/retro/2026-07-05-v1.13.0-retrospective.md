# Retrospective — v1.13.0

**Date:** 2026-07-05
**Milestone:** Webhook modularization Phase 1 + isolated smoke gate + security/infrastructure fixes
**PR:** #103 — merged to main (`28f38058`)
**Participants:** Claude, Codex, Gemini, Copilot

## What Went Well

- **Webhook modularization Phase 1 executed cleanly** — extracted `config.py`, `render.py`, `proc.py`, and `auth.py` as pure, verbatim helpers from the monolith without behavioral changes or external contract shifts; each slice validated independently with py_compile + import checks + BATS + audit.
- **Isolated webhook smoke gate** (`bin/smoke-test-webhook`) successfully boots a throwaway server on an overridden `K3DM_JOB_DIR`/`K3DM_RUN_DIR` without disturbing the live `:7443` instance; now gates all remaining modularization phases.
- **Webhook BATS isolation fixed live-dir pollution** — stubbed `make` and `K3DM_GEMINI_BIN`, isolated `K3DM_JOB_DIR`/`K3DM_RUN_DIR`, serialized per-test cluster-idle waits; the test suite no longer launches Chrome/agy or pollutes `~/.local/share/k3d-manager/webhook-jobs/` or triggers false Slack orphan-job alerts from shared-state mutation.
- **Multiple critical fixes landed together** — Vault token hyiene (stdin instead of argv), Trivy Operator RBAC (chart/image skew realignment), Trivy ServiceMonitor release-label isolation; all validated live on the cluster.
- **CodeQL path-injection resolved both ways** — dismissed false positives and also rewrote `_safe_job_dir` to a CodeQL-recognized `os.path.realpath`+`os.path.join`+`startswith` sanitizer pattern; verified clean at source (zero alerts post-scan).

## What Went Wrong

- **CodeQL false positive on `_safe_job_dir`** — the regex-allowlist + parent-containment barrier pattern was flagged as path-injection because CodeQL's Python taint tracker doesn't recognize the containment proof; solution was both to dismiss (immediate green) and to rewrite in CodeQL-friendly form.
- **agy/Antigravity runtime state leaked into repo root** — launching agy from the k3d-manager working directory caused the pre-commit hook's broad `git add .` to stage `.wrangler/cache/` CF account file, `antigravity-cli/antigravity-oauth-token` (live token), and a stray `gemini-config` gitlink; nothing committed (HEAD clean), but cleanup required and `.gitignore` hardening to isolate Antigravity namespace.
- **Trivy Operator CrashLoop root cause initially misdiagnosed** — Gemini/Loki logs pointed to cache-sync timeout under a `cpu: 100m` limit; real cause was chart/image RBAC version-skew (missing PV/PVC permissions in the `0.24.1` chart); fixed by pinning the chart to `0.33.2` with no resource-limit change.
- **Live launchd webhook ran stale pre-v1.12.0 code** — after the v1.12.0 merge (which added `provider=` param to `/cluster-status`), the running webhook was never restarted, so every `/cluster-status hostinger` call raised `TypeError` silently in the worker thread; discovered during post-merge Slack ops.

## Process Rules Added

| Rule | Source | Impact |
|------|--------|--------|
| Always `make restart-webhook` after `bin/k3dm-webhook` changes | [[feedback_restart_webhook_after_verify]] | Prevents stale code in launchd webhook after git merge/pull |
| Never launch agy/Antigravity from inside a git repo working dir | agy runtime-state repo pollution incident | Protects against pre-commit hook `git add .` sweeping live tokens/config into staging |
| CodeQL path sanitizers must follow `os.path.realpath`+`os.path.join`+`startswith(base+os.sep)` pattern | CodeQL Python taint-analysis limitations | Ensures dismissals don't recur; fixes pattern recognized by tool |

## Decisions Made

- **Webhook modularization deferred from v1.12.0 → v1.13.0** — prioritized stabilizing the remote-operator access layer first; Phase 1 extraction chosen as low-risk, verbatim slice to unblock subsequent phases without external contract changes.
- **Antigravity/agy namespace isolated in `.gitignore`** — `antigravity-cli/`, `.wrangler/`, `gemini-config/` added to project `.gitignore` to prevent runtime state of external tools from leaking into the repo; remedies the OAuth-token incident without blocking agy access.
- **Webhook smoke gate now gates all modularization phases** — every remaining slice (Phase 2–5) must validate the smoke gate (HTTP 200 / valid health payload) before commit, so the `sys.path` shim and module wiring remain correct as dependencies evolve.
- **CodeQL path-injection fixed at source** — rather than relying on dismissals, rewrote `_safe_job_dir` to use recognized `os.path.realpath` + containment check; provides evidence-based validation that the pattern is safe, not just permission-based acceptance.

## Theme

v1.13.0 focused on **stabilizing the webhook architecture through modularization and comprehensive test-suite isolation**, delivering Phase 1 of the 5-phase webhook extraction plan while simultaneously fixing critical security (Vault token exposure in process argv) and infrastructure issues (Trivy RBAC, webhook BATS pollution) discovered during v1.12.0. The release reinforced two operational disciplines: always restart the launchd webhook after code changes, and never launch external tools like Antigravity from inside the git working directory to prevent their runtime state from leaking into version control.
