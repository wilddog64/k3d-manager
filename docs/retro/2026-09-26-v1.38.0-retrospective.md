# Retrospective — v1.38.0

**Date:** 2026-09-26

**Milestone:** v1.38.0 — give a cloud agent eyes on the cluster without giving it a credential

**PR:** #132 — merged to main (`6f0fb4af`)

**Participants:** Claude, Codex, Copilot

## What Went Well

- **The trust boundary held as a design, not as a rule.** The bridge reads an untrusted branch
  and never lets its bytes reach argv, a shell string or a prompt — the bare clone makes a
  worktree impossible by construction, and the hard-coded method-per-action table means a
  request file cannot choose its own HTTP verb. Both are structural, so a later agent cannot
  weaken them by being careless.
- **The two-token model was verified live, not assumed.** An authenticated reader
  `POST /api/v1/cluster-status` returned 202 and the credential-bound role ceiling was
  exercised end to end before the PR.
- **A gate hole in Part 1 was caught by reading, not by testing.** The role check sat behind
  `get_route is not None`, which left `/api/v1/health?...` ungated. No test would have failed.
- **A pre-existing v1.37.0 bug surfaced while verifying someone else's work** — the
  decomposition had dropped `return results` from `_smoke_test_services`, so
  `GET /api/v1/health` raised `TypeError` and dropped the connection. Fixed in `f6d60b00`.
- **The vacuous-suite bug was found and closed in the same release it was introduced.**
  `cloud_bridge.py` (20 tests, including the drift guards) was passing vacuously under
  `make test-python-unit` and absent from `make test-pytest` — two suites that ran nowhere.

## What Went Wrong

- **A review suggestion was nearly applied without being executed.** Copilot's `mktemp -u`
  finding was a real symlink race, but its proposed remedy — drop `-u` and create the file —
  would have made `make init-cloud-requests` die at rc 128, because git refuses a zero-byte
  index (`index file smaller than expected`). It was caught only by running the suggestion in a
  scratch repo. That target runs once, on a fresh setup, where nobody is watching.
- **A flagged occurrence was treated as a count on first read.** Copilot flagged one
  `https://127.0.0.1:7443`; the class had three. One was wrong for a second, unrelated reason:
  a cloudflared ingress `service:` addresses the local origin and Cloudflare terminates TLS at
  its edge, so it would have been `http://` even had the push path been built.
- **The same-day fix got the least review.** Both code findings were in guard and how-to text
  written after the main body of work, once attention had moved on.
- **A Haiku subagent reported back before CI finished**, having been told to poll to
  conclusion. Every claim it made — CHANGELOG structure, commit on origin, README table shape
  — had to be re-verified, and its release row had drifted from house style and was rewritten.
- **A memory-bank commit pushed after the merge window missed the squash.** `875f97da` queued
  the cloud-bridge architecture doc and is not in `main`; it had to be cherry-picked onto
  `k3d-manager-v1.39.0` during post-merge. A push to a branch whose PR is already merge-ready
  is a push into a closing window.
- **The milestone closed with four of its five specs unimplemented**, which is the scope
  problem below rather than an execution failure.

## Process Rules Added

| Rule | Rationale |
|---|---|
| Do not apply a review suggestion without executing it first | Copilot's `mktemp -u` remedy was a correct diagnosis with a fix that fails at rc 128. Correct finding, broken fix, and only running it reveals which. |
| When a reviewer flags a string, grep for the whole class | A flagged occurrence is a sample, not a count. One `https://` flagged, three present. |
| A request header may only ever narrow a role — the credential sets the maximum | Any code letting a header raise a role is privilege escalation. Added to `.github/copilot-instructions.md` as a review gate. |
| The `cloud-requests` branch is untrusted input | Its bytes may come from a compromised cloud session. Nothing on it may reach argv, a shell string, `eval`, or an AI prompt. |
| Any new push-triggered workflow must be branch-scoped and exclude `cloud-requests` | A workflow that fires on that branch would execute attacker-chosen content. |
| A `GIT_INDEX_FILE` must not pre-exist as a zero-byte file | Reverses the usual "create the temp file properly" advice for this one case: `mktemp -d` and place the index inside, so the namespace is reserved but the index file does not yet exist. |
| Ask for the job list, not the run conclusion | `stage2` skipped under a green run. Here it was label-gated by design, but the conclusion alone could not say so. |

## Decisions Made

- **The reader token reads env `K3DM_WEBHOOK_TOKEN_READER` then Keychain only — no `TOKEN_FILE`
  fallback.** A shared file would collapse the two roles into one secret, defeating the whole
  two-token model.
- **The loopback listener stays plain HTTP and there is nothing to verify.** No `https://` URL,
  no `SSLContext`, and equally no `--insecure`/`verify=False`. The credential is safe in the
  clear only because the socket never leaves the loopback interface, so no env var may point
  the host off-box. This is the single most likely thing for a future agent to "upgrade" into
  a bug.
- **The push path was deliberately not built** — no cloudflared ingress, no Access application,
  no service token. The pull model needs none of them.
- **`ask` and `analyze` are excluded from the allowlist despite being reader-rated**, because
  both take free text that would become an AI prompt.
- **`make test` and `make test-bin` stay unexposed** to Slack and the bridge pending a sweep of
  `scripts/tests/` for reachability-dependent live mutation.
- **Cluster-tier CI (`stage2`) remains opt-in** behind the `ci:cluster-tests` label rather than
  running on every PR.

## Theme

The release answers a narrow question — how does an agent with only a GitHub connection learn
anything true about a cluster it cannot reach? — and refuses the obvious answer. No token is
placed in a cloud environment, no tunnel is opened, no endpoint is exposed. Instead a branch
becomes the only medium, the bridge polls it from the inside, and the credential never leaves
the laptop. Everything interesting in the design is a constraint rather than a capability: the
bare clone that cannot check out, the hard-coded method table that a request cannot influence,
the ordered reject chain, the two tokens that cannot be collapsed into one. The milestone's own
lesson mirrors that shape. Both of the code defects Copilot caught were in the guardrails, not
the feature, and the more instructive of the two arrived with a fix that would have broken the
thing it protected — which is why the rule that came out of it is about executing a suggestion
rather than about `mktemp`.
