# Retrospective — v1.24.1

**Date:** 2026-08-13  
**PR #115 merged to main:** e7a32bb9f4bc1ca2a0187332782bd6b62ed16c31  
**Participants:** Claude, Codex, Gemini, Copilot

## Milestone

**Concise provider-aware cluster status + Slack summary.** A point release on top of v1.24.0. `make status` now defaults to a concise, color-coded service-health summary (with `make status-full` for the detailed report and `make status-json` for stable machine-readable output), follows the active cluster provider, and takes `SERVICE=<name>` for focused per-service diagnostics. The same summary reaches Slack as a concise emoji-severity one-liner. The CVE remediation dashboard is split into live Current Status and historical Remediation History tables. Verified live on the hub: `make status-json` returns `overall=healthy` for `k3s-hostinger`, and the Slack path renders a live emoji-based summary with real cluster data.

**Scope split executed 2026-08-13:** The branch formerly named `k3d-manager-v1.25.0` held only status/observability work (zero workstream G implementation), so it was renamed to `k3d-manager-v1.24.1` and is being cut as a point release; `v1.25.0` is reserved for workstream G (Stripe/Go live acceptance + E2E verification harness).

## What Went Well

1. **Branch-hygiene reconciliation was thorough.** Orphaned commits from the dead-end `k3d-manager-v1.23.0` (squash-merged release) were identified and rescoped onto the active development branch. The live CVE dashboard and exporter were already running the newer version on hub, so carrying them forward ensured consistency.

2. **Live status verification was methodical.** Each component (provider selection, Keychain token, ArgoCD/Grafana credentials, LaunchAgent KUBECONFIG rendering) was tested independently before end-to-end integration. The Slack summary was smoke-tested against real cluster data in the correct emoji/count format.

3. **Dashboard ApplicationSet repointing was done early and correctly.** The grafana-dashboards appsets were reapplied with `K3D_MANAGER_BRANCH=k3d-manager-v1.25.0` (the forward-ported version, not v1.24.0) and verified Synced/Healthy. This prevented the live cluster from rolling back to the older verbose dashboard format.

4. **Copilot's static findings were quick to address.** The Makefile shell-injection quoting fix was minimal; doc sweeps (roadmap + plan-header) were scoped clearly and completed in one follow-up commit.

## What Went Wrong

1. **Doc-rename sweep was incomplete on first pass.** When the branch was renamed `v1.25.0`→`v1.24.1` and plan docs renumbered, the `docs/roadmap.md` milestone references and the plan doc's own status header were not updated. This created stale pointers that had to be surfaced by static review (Copilot).

2. **ApplicationSet repointing was only partial.** The dashboards appset was repointed to v1.24.1, but `observability`, `observability-acg`, and `services-git` appsets were left still tracking v1.23.0. While the content is identical (no live reversion), this creates a hygiene debt — the v1.23.0 branch cannot be safely deleted until a full hub repoint is done as a release-grade step.

3. **Standing docs (roadmap, API reference, Copilot instructions) were not proactively audited.** New binaries (`bin/cluster-status-summary`) and Make targets (`status-full`, `status-json`) were shipped without a pre-commit check that standing documentation still reflects the actual contract.

## Process Rules Added

| Rule | Owner | Rationale |
|------|-------|-----------|
| **Doc-rename sweep = roadmap + plan-header** | Release ops | Roadmap milestone references and plan doc status headers are living docs that lag branch/doc renames unless explicitly checked. Add to pre-PR gate. |
| **Make passthrough flags = quote user input at authoring** | Code review | New Make recipes accepting user input (`SERVICE=`, `CLUSTER=`, etc.) must interpolate via `"$(VAR)"` at definition, not at call site. Violates CLAUDE.md shell-injection rule. Catch in first-pass review. |
| **Pre-commit: audit standing docs for new binaries/targets** | Code review | Whenever new `bin/` scripts or Make targets are added, verify they are mentioned in `docs/api/functions.md`, `.github/copilot-instructions.md`, and `memory-bank/projectbrief.md`. |
| **Release: full hub repoint gate = all appsets + ArgoCD check** | Release ops | Partial ApplicationSet repointing creates hygiene debt (branch cannot be deleted). Full repoint must include observability, services-git, and dashboards appsets, then run `argocd_check_values_branch` to confirm all targets. Document as a blocking release step. |

## Decisions Made

1. **v1.24.1 as a point release (vs. rolling into v1.25.0).** Scope split was necessary because the branch held only observability polish (status modes, Slack summary, dashboard cleanup) with zero workstream G implementation. Cutting v1.24.1 separately allows the hub to ship concise status immediately, and v1.25.0 can focus on Stripe/Go live acceptance without backwards-compatibility churn.

2. **Defer full hub repoint to the next release.** The observability appset repointing involves `services-git`, which pulls service-manifest deltas. A partial repoint (dashboards only) is safe because the exporter content is identical. Full repoint is deferred to v1.25.0 release-ops to avoid coupling unrelated work.

3. **Keep v1.23.0 branch until full repoint.** Although v1.23.0 is a released dead-end (squash-merged), it cannot be safely deleted until `observability`, `observability-acg`, and `services-git` appsets are repointed. Deleting it now would strand the live hub mid-cut-over.

## Theme

**Make cluster status legible.** The user-facing status report was becoming unwieldy (multi-section wall of text), hard to consume in the terminal, and unsuitable for Slack (ANSI art does not render). This release introduces three output modes — concise (default), full (detailed diagnostics), and JSON (automation/Slack) — each suited to its audience. The status command now respects the active cluster provider (from `~/.local/share/k3d-manager/active-provider`) and can focus on a single service for triage. The Slack `/cluster-status` webhook endpoint now returns a crisp emoji-severity summary instead of a wall of text. The CVE remediation dashboard is split into live Current Status (what is happening now) and historical Remediation History (audit), with the exporter marking which events are superseded. All three improvements make observability actionable: fewer cognitive cycles to detect a problem, faster drill-down to the root cause, and a repeatable audit trail.
