# Retrospective — v0.4.12

**Date:** 2026-08-21
**Milestone:** Count-agnostic ACG CloudFormation agent fleet (Phase A)
**PR:** #43 — squash-merged to main (`c4f3211`); stamped `v0.4.12` (`c1df1be`); tag + release live
**Participants:** Claude, Codex, Copilot

## What Went Well

- **Property-preserving template emitter.** Codex's `_acg_render_template` clones the reference
  agent block verbatim and re-emits it N times, so every per-agent property (instance profile,
  security group, block-device mapping, tags, the SSM `!If` conditional) is preserved by
  construction rather than re-listed — no per-property drift risk as the fleet grows.
- **Fail-fast validation.** `_acg_validate_agent_count` rejects non-numeric / `< 1` counts before
  any `aws` call, proven by a BATS test that asserts no AWS invocation file is ever written.
- **CI-parity make targets.** `make shellcheck-lib` + `make bats` mirror the two CI jobs, closing
  the gap where `make all` never exercised `acg.sh` locally.
- **Independent verification held.** Claude re-ran the gates and rendered the template against both
  the upstream and the drifted k3d-manager runtime template before trusting the "done" report.

## What Went Wrong

- **Lexical vs numeric agent ordering shipped in the first cut.** Discovery used
  `sort_by(@, &OutputKey)`, which puts `Agent10` before `Agent2`. Correct at the ACG cap (N≤4) but
  it undercut the count-agnostic story. Fixed with numeric awk-index sort + a `Agent10` regression
  test before release.
- **`mktemp` portability slipped past local runs.** The template `XXXXXX.yaml` (X's mid-string)
  works under GNU `mktemp` but fails under BSD/macOS `mktemp`, and the call lacked a failure check.
  Copilot caught it; fixed to the repo's `mktemp -t name.XXXXXX` + `|| return 1` convention.
- **Stale `--help`.** `acg_provision --help` still described a fixed 3-node / `ubuntu-1,ubuntu-2`
  cluster after the function became count-agnostic. Copilot caught it.
- **Guard regex was too loose.** The no-hardcoded-agent test used `Agent[12]`, which also matches
  `Agent10`/`Agent12`. Tightened to `Agent[12]([^0-9]|$)`.

## Process Rules Added

| Rule | Where | Why |
| ---- | ----- | --- |
| Prefer `mktemp -t name.XXXXXX` (+ `\|\| return 1`) over mid-string-`X` path templates | convention | Portable to BSD/macOS `mktemp`; matches the rest of the repo |
| Guard regexes over numeric-suffixed identifiers must anchor the digit (`[12]([^0-9]\|$)`) | convention | Avoid false matches on `10`/`12` when guarding against `1`/`2` |

## Decisions Made

- **The checked-in two-agent template stays the documented reference; the runtime emitter generates
  N.** Regenerating the k3d-manager template from bare upstream would revert the SSM `!If`
  IAM-restricted-sandbox fix (`fef71219`/`40f1d19a`), so Phase B B1 is a no-op, not a regenerate.
- **Node-provision + join test target lives in k3d-manager (`make fleet-up`), not lib-foundation.**
  lib-foundation is the ACG module library only — empty `scripts/lib/providers/`, no dispatcher/bin,
  and the k3s-join code lives in k3d-manager.

## Theme

Phase A made the ACG fleet count-agnostic without touching the reference template: a verbatim-clone
emitter preserves every per-agent property by construction, and fail-fast validation keeps bad counts
away from AWS. The rough edges were all in the periphery — lexical ordering, `mktemp` portability, a
stale help string, a loose guard regex — each caught by verification or Copilot and fixed before the
stamp. The runner half (deriving hosts, parallel join, readiness, the `make fleet-*` targets) is
Phase B in k3d-manager.
