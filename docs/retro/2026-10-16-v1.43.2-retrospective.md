# Retrospective — v1.43.2

**Date:** 2026-10-16
**Milestone:** v1.43.2 — hub recovery fixes from the 2026-10-15 rebuild, e2e result visibility, and Bug Tracking dashboard fixes
**PR:** #143 — merged to main (`93f9b940`), tag `v1.43.2`, GitHub release `v1.43.2`
**Participants:** Claude, Codex, Copilot

## What Went Well

- The real hub rebuild on 2026-10-15 (run `20261016T012103Z`) completed: 9/9 steps rc 0, verify V1–V5 and V8 true. Each manual workaround it needed was written up as a bug, and all four recovery fixes landed (`861abb7b`, `e5b93aee`, `ffe7ce6a`, `68aa8aa1`). The live proof is the 2026-10-29 rebuild drill.
- Codex worked in one worktree per fix, landed serially. Claude verified each one by checking the new tests against the pre-fix source and running mutation tests. The mutations caught a never-failing `! grep` assertion (fix 2) and a skipped promtool test (e2e republish).
- The Bug Tracking dashboard became usable: a bug table with priority colours, a Release filter, version-sorted releases, Status and Verified columns, and a Live-verified column. Sixteen v1.43.2 fixes are now marked VERIFIED or LIVE-VERIFIED with evidence.
- An e2e setup failure now shows up in the Failure causes panel as "aborted at <phase>" instead of an empty panel. This was confirmed live for run `1792155966-29279`.
- Before the PR, both app clusters passed the live smoke test (`smoke-test-cluster-health` 9/9). Copilot left no findings.

## What Went Wrong

- The rebuild itself destroyed what the restore needed: hub-up's Vault init overwrote the M4 DR shards (P1). The PVC field ownership, the ESO refresh order and the missing export SA were found only on a fresh hub. The stubbed tests modelled the old hub, not a new one.
- A hub rebuild wiped the e2e history (no `e2e-result` ConfigMaps), and the dashboard went blank without any alert. `E2EResultsMissing` and `make e2e-republish` now cover this.
- The live-verified spec said "same value mappings", and the Verified column kept the pre-split label "✓ live". The fix (`4929bf97`) was caught by the operator's eye, not by a test.
- The VectorDB index run was marked failed by an unguarded 120 s metrics publish. The same unguarded call sits in Hermes's poll (P3, v1.43.3).
- `cluster-up` left an in-shell ACG watcher printing into the operator's terminal, so a finished shell looked hung (P3, v1.43.3).
- Claude's `enforce_admins` DELETE was denied by the permission classifier, so the operator toggled protection by hand.
- CodeQL could not complete on the large commits during the PR (operator report). The CodeQL run on main after the merge passed on `93f9b940`.

## Process Rules Added

| Rule | Where |
|---|---|
| `scripts/` must not change and nothing may be committed in the main tree while the operator's `make` runs from it | memory `feedback_never_mutate_script_while_make_up_runs` |
| A bug doc's Verified/Live-verified status requires named evidence | `docs/bugs/` headers; Bug Tracking dashboard |
| `E2EResultsMissing` alert plus `make e2e-republish` after any hub rebuild | rebuild runbook |

## Decisions Made

- v1.43.3 is mostly a bug-fix release, with two operator-approved features: fixed-in release attribution (from tag ancestry; `unknown` when no transition is found) and a PR checks dashboard (k3d-manager only; Copilot reviews are not checks).
- The dispatch-dashboard per-spec P3 moved to v1.43.3. The e2e-sandbox ArgoCD CRD fix stays on v1.43.4.
- Release attribution on the Bug Tracking dashboard is currently filed-in. Fixed-in arrives in v1.43.3.

## Theme

v1.43.2 turned a real, messy hub rebuild into four tested recovery fixes. It also made the things the rebuild hid visible: the e2e history, setup aborts, and which bugs are actually fixed and proven live. Most failures this cycle came from gaps between what the stubs modelled and what a fresh hub really looks like. That is why the next live drill, on 2026-10-29, is the real acceptance test.
