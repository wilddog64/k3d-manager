# Retrospective — v1.35.0

**Date:** 2026-09-18

**Milestone:** v1.35.0 — Dark Test Suites, Workstation Dependency Purge, Linux Portability Fix

**PR:** #128 — merged to main (`e259c718`)

**Participants:** Claude, Codex, Gemini, Copilot

---

## What Went Well

- **Automatic discovery replaced hand-maintained lists.** Before this release, CI's BATS file list was hardcoded in `ci.yml`, and new suites had to be manually added or they stayed dark. The diff at `6064796c` wired CI to run `make test` directly, which discovers all suites under `scripts/tests/` and `scripts/tests/etc/` dynamically. Now a new file lands and is gated immediately.

- **The release found its own bugs.** Turning on the dark suites (`make test-bin`, `make test-python-unit`, `make test-pytest`, and 120 pytest tests) with `6064796c` and `6eb1866e` immediately surfaced three "green on macOS, red on Linux" defects in the release's own code:
  - `rg` (ripgrep) called but absent on `ubuntu-latest` — and worse, two call sites were `run rg …` + `[ "$status" -ne 0 ]`, so the missing binary (exit 127) *satisfied* the negative assertion, making them silently **vacuous**, not red.
  - `keycloak.bats` copying a fixture from `shopping-cart-infra`, a sibling checkout CI never clones.
  - `set -euo pipefail` recipes running under `/bin/sh` (dash on Ubuntu), which rejects `pipefail`.
  - All three were pre-existing and dark until the Makefile's discovery mechanism gated them.

- **Copilot found dependency hardening in the code.** Two Copilot findings (F2/F3) named the same defect twice: `argocd.sh` and `k3s-hostinger.sh` required `_acg_provider_state_dir` from `lib/provider.sh` but sourced it behind a guard (`if [[ -r ]]`) or not at all, respectively. Neither was a live bug today because the dispatcher happened to load it first, but the silent contract violation meant a refactor could break them. Fixing it (source explicitly in both) immediately surfaced a BATS defect: `provider_contract.bats:241` had been passing only because its `setup()` leaked the real function into the BATS process.

- **Isolation reproduced the whole class.** The "host-tool dependency" bug was reproduced in a scratchpad worktree with no sibling repos, exactly mirroring CI's isolation. That reproduction proved the defect was not a test flake or an environment edge case, but a structural dependency on the operator's workstation.

- **Local reproducibility is now in the playbook.** `/bin/dash` is installed on this workstation, so `make SHELL=/bin/dash test-bin` reproduces the sh-vs-bash failure deterministically, without a CI round trip. The pattern is reusable: stub the nondeterminism (os version, tool presence, environment state) and re-run locally before trusting a green.

## What Went Wrong

- **Dark suites let `make test` stay red for a full release.** The `_e2e_kustomization_images` hardcoded count (3 images) was stale since `978ea60f` added a fourth app, but `e2e_image_prune.bats` is not in CI's hand-maintained BATS file list. Local `make test` was 947/947 green on the developer's machine after every run while CI stayed green, and the test failed silently in production until someone ran `make test` on the command line. This is the exact problem v1.35.0 was supposed to close — the solution is applied, but it took a full release to land.

- **Vacuous assertions passed code review.** Two `run rg …` + `[ "$status" -ne 0 ]` assertions passed review on 3+ occasions because the pattern looks correct and the suite was green locally (since `rg` is installed). The absence of a tool on CI made the assertions pass without assertion, and nobody checked whether the call site was critical. `set -e` ignores `! cmd` for the exact same reason — both are now linted out by v1.35.0's new `bats_negation_lint`.

- **Latent defects sat in live targets.** `fleet-render` and `fleet-plan` (two live AWS targets) carried the same `set -euo pipefail` → `sh`/`dash` defect. Copilot's review found the three new test targets, but the diff did not include the fleet recipes, so they were only discovered by examining the whole Makefile after the Copilot finding. If either target is ever run on a Linux host (e.g., a GitOps controller, a webhook server, a scheduled agent), it will fail.

- **The discovery mechanism was invented *after* the dark suites had gone unmonitored.** Suites are still dark if they are not under `scripts/tests/` (e.g., embedded in a plugin or a library); the rule's blind spots are not yet documented.

## Process Rules Added

1. **Automatic test discovery is now the single source of truth.** CI runs `make test` (and the `make test-*` entrypoints) rather than hand-maintaining a file list. New suites land and are gated on the same commit.

2. **Vacuous assertions are now linted.** `scripts/tests/lib/bats_negation_lint.bats` flags `! cmd` patterns and `run …` followed by `[ "$status" -ne 0 ]` on missing/absent tools. The pattern is kept in scope (because the regex is broad and legitimate use cases exist), but the pattern is now visible in code review.

3. **sh vs bash is now locally reproducible.** `/bin/dash` is available on the operator's workstation, so `make SHELL=/bin/dash <target>` can reproduce the Ubuntu CI failure locally without a round trip. This is the pattern to apply to other nondeterministic failures (os version, tool presence, environment state).

4. **Workstation dependencies are now blocked by CI.** A test that requires `rg`, a sibling repo, or a local Keycloak realm is dark unless the machinery is mocked/skipped/guarded in a way that passes in isolation (a scratchpad worktree with no neighbors). This catches the dependency before merge.

5. **Standing docs get audited in release close-out.** `memory-bank/projectbrief.md` claimed "no Python in the critical path"; that was false since Hermes landed. `docs/api/functions.md` was stale (12 E2E functions undocumented, the entire `e2e_remote.sh` surface invisible). `.github/copilot-instructions.md` needed new review rules (test reachability: discovery not lists, `bin/` coverage, host-state stubbing, deadlines checked before the first probe). These now go into the post-merge audit.

## Decisions Made

1. **Tier 2 E2E moved to v1.36.0.** The `e2e_verify_sandbox` entrypoint that `docs/plans/v1.25.0-e2e-harness-tier2-sandbox.md` names does not exist — unimplemented since v1.25.0. The precondition (live ACG login gate) has never passed live since the false-green fix landed, and Tier 2's Stripe acceptance would stack on top of it. Defer to the next release with a precondition audit.

2. **Standing docs audit is now a release gate.** After every release, review `memory-bank/projectbrief.md`, `.github/copilot-instructions.md`, `docs/api/functions.md`, and README/`docs/releases.md` tables for staleness. Document new public functions, new review rules, new plugin dependencies, new entrypoints, and fixes to architectural claims.

3. **Copilot review on this PR delivered hardening, not critical fixes.** F2/F3 (implicit dependencies hardened to explicit) would not have shipped as bugs on their own. That they appeared in the diff at all was because the discovery mechanism gated a much larger scope of tests, which in turn gated code Copilot could then review. The causal chain worked: turn on the dark suites → surface a code defect → Copilot reviews it → apply the hardening.

## Theme

**Dark Test Suites.** Before v1.35.0, 947 BATS tests and 120 pytest tests ran locally on the developer's machine but not in CI. The barrier was not "hidden", it was structural: the tests sat in `scripts/tests/` but CI's hand-maintained BATS list excluded most of them. When `6064796c` switched CI from a list to automatic discovery, the `make test` command became the single source of truth for both local runs and CI. That one change gated 3 pre-existing defects (workstation tool dependencies, a sibling-repo fixture, and a `/bin/sh` vs `bash` incompatibility) in the first run. The release was named after the defects it exposed, because turning on the lights (in CI and locally together) immediately found things that needed fixing.

## Key Insights

- **An alias that masks the real tool is a blind spot in code review.** `grep` → `rg` on this workstation made `rg` calls look local-green, so a suite that works here appeared to work everywhere. The remedy: sweep `scripts/tests/` for uses of aliased tools before merge.

- **A negative assertion (exit 127 satisfies "status -ne 0") is the most dangerous kind of green.** Not red, not failing — it looks like it passed. Two `run rg …` + `[ "$status" -ne 0 ]` call sites on CI got a missing binary (127) and called it success. Linting is the only reliable catch.

- **Latent defects hide in live code when the test suite is dark.** `fleet-render` and `fleet-plan` are two AWS targets that have never been tested in CI and would fail on a Linux host. They were discovered by auditing the entire Makefile after Copilot found the three new test targets — a full audit was only triggered because the diff mentioned them.

- **Fixtures owned by a sibling repo should not be copied.** `keycloak.bats` copied a realm fixture from `shopping-cart-infra`, which CI does not clone. The copy would drift from the deployed realm. The correct idiom already existed at `shopping_cart.bats:86` (an `if [[ -d ]]` guard), so the outlier was not a pattern, just an oversight.

- **Multiple agents, multiple samples, one green.** Codex's report claimed `MAKETEST_EXIT=0` after discovering all suites in both macOS and Linux-sim mode; Claude's rerun (unpiped) found `MAKETEST_EXIT=2`, `ok=945 notok=1`. The CI reds were real, not a testing artifact. One agent's green is one sample; it proves a single happy path, not an invariant.
