# Retrospective — v1.20.0

**Date:** 2026-08-01

**Milestone:** CVE auto-patch loop hardening

**PR:** #109 — merged to main (`9da73458`)

**Participants:** Claude, Codex, Gemini, Copilot

## What Went Well

The CI-green + Copilot gates caught a real Codex Makefile `.PHONY` regression before merge. Commit `0a316fb6` ("fix(make): reconcile platform ops after up") intended a single-line addition but inadvertently clobbered adjacent tokens, duplicating `uninstall-alertmanager-auth-proxy` and dropping `install-alertmanager-auth-proxy` + `uninstall-alertmanager-port-forward` from the `.PHONY` list. Copilot's review flagged the duplicate and the missing target (finding 1); independent verification found the third casualty. Commit `a711bae7` restored all four targets to their correct place.

Codex's `03fe5684` app-cve-scan fix (exit-0 semantics on per-service failures) passed all spec gates and moved immediately to production via `make platform-ops`. It silenced the recurring triage-bot loop on the misleading "Trivy exits 1 on CRITICAL" diagnosis and downgraded per-service remediation-job failures to warnings, while keeping the genuine job-level failure (zero matched VulnerabilityReports) non-zero.

The milestone isolated 9 actionable code-level fixes from 76 commits of docs/memory noise across the branch, with a surgical CHANGELOG that surfaces only the real production changes.

## What Went Wrong

BATS test 9 in `scripts/tests/plugins/app_cve_scan.bats` asserted the old exit-1 behavior for incomplete remediation and would have failed CI — caught and fixed inline (commit `28307f46`) rather than caught by the spec gate in the plan document. The stale test was a silent blocker that the spec-verification step did not account for.

The Makefile `.PHONY` regression in commit `0a316fb6` is a class of maintenance hazard: a wide single-line edit hides adjacent-token loss from code review because the diff on one long line compresses the corruption. The wide list is brittle to manual edits.

## Process Rules Added

| Rule | Owner Guidance |
|------|----------------|
| Makefile `.PHONY` mutation guard | After any edit to the Makefile `.PHONY` line, run a count check — every entry appears once and resolves to a defined target (or is intentionally virtual). `sed -n '14p' Makefile` counts are the simplest verification. |

## Decisions Made

**Exit-0 semantics for the CVE scan batch:** per-service remediation failures (unresolved digests, failed rebuilds) notify as warnings but must NOT fail the Job. Only a run that matched zero VulnerabilityReports fails the Job exit code. This prevents the triage bot from looping on failed pods when some services self-heal while others are waiting on image rebuilds.

**Pod-level observability:** both `app-cve-scan-cronjob.yaml` and `cve-scan-cronjob.yaml` pod templates now carry `app` and `app.kubernetes.io/name` labels so Kubernetes and Prometheus alerts render the workload name instead of the cryptic `app ''`.

## Theme

v1.20.0 made the CVE auto-patch loop actually run end-to-end. v1.18.0 wired up the Trivy→webhook→`app-cve-scan` detect→patch architecture, but the many ways it broke in practice prevented any workloads from being patched. v1.20.0 fixes the non-zero-exit-on-partial-failure that was killing the Job, adds the missing pod labels for observability, and corrects the ArgoCD-application name prefix so the patch actually targets the real cluster-prefixed apps instead of bare service names (26 remediation jobs had been failing silently on the wrong name). Failed scan pods no longer accumulate; the Hub chart is read from live deployment metadata instead of a guessed path; and `make up` reconciles the platform-ops stack so the CVE monitors are present after a cold cluster bring-up instead of needing a manual remedial deployment step.
