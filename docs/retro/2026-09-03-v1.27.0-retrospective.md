## What Went Well

### Three-Latch Supply-Chain Gate Delivered End-to-End
The entire CVE-loop closure shipped intact across all three verification gates:

- **BUILD latch:** CI signs first-party images and attaches a cosign vuln attestation (`type: https://cosign.sigstore.dev/attestation/vuln/v1`) at build time (Stage C).
- **PROMOTE latch:** The promoter refuses to advance a CVE-remediation candidate unless it passes both `cosign verify` **and** `cosign verify-attestation` (default-off, behind `COSIGN_VERIFY=1` and `COSIGN_VERIFY_ATTESTATION=1`).
- **ADMIT latch:** A Kyverno `verifyImages` ClusterPolicy whose `attestations:` block requires the vuln attestation beside the signature; ships in `Audit` mode with Enforce gated behind `SIGNING_ALLOW_ENFORCE=1`.

All three latches shipped **inert by default**, enabling a staged Audit→Enforce rollout path without cluster risk. The signing plugin (`scripts/plugins/signing.sh`) is modular and fully tested (signing.bats 20/20).

### Foundation-Managed vCluster CLI Resolved the Pinned Binary Contract
Part A (lib-foundation `v0.4.13`, PR #44) landed without incident; Part B rewired the vcluster module from ambient `PATH` to a single `foundation_ensure_vcluster_cli` contract with self-healing connection refresh. The live `make e2e` CLI-contract gate passed: real vcluster `0.32.1` downloaded, verified, and atomically installed into the managed path. Dependency management is now durable and testable.

### Adaptive Checkout Load Testing + Observable Cost Controls
The k6 checkout generator (Slice F) is driven by an adaptive controller with stop-condition hysteresis and opt-in guards, reducing cluster CPU churn during acceptance. Monitoring-pause/resume (`make monitoring-pause/resume`) reclaims ~1.1 cores while keeping Grafana up; layered resume supports lite (LAYER=1) and full (LAYER=2) rollout modes.

### M2 Remote E2E Runner Preflight + Publisher Bridge Complete

The durability spec (`docs/issues/2026-08-24-e2e-publish-back-source-pin-durability.md`) grounds the `from=` IP pin and `-o AddressFamily=inet` mitigations in code, closing a silent-lockout risk.

## What Went Wrong

### Pre-PR BATS Gate Started at Red
The local full test suite on `k3d-manager-v1.27.0` reported 13 failures. Investigation bucketed them into two categories:

- **9 branch-related** (all test-only; production code correct/intentional): stale guards from LDAP chart migration, ghcr pull-secret ServiceAccount move, node-health threshold bump, argocd self-healing rework, and vCluster test-harness bugs from an earlier commit. All were fixed locally and pushed.
- **4 pre-existing local-macOS-env failures:** These fail on `main` too and pass in CI. Not PR-blocking, but they signal brittleness in the local test environment setup (documented in `docs/issues/2026-09-03-bats-preexisting-local-macos-env-failures.md`).

The pre-PR gate delay was _procedurally_ correct (catch test regressions early) but the repeated fix-and-verify cycle consumed a day. The root cause is that new features (LDAP migration, vCluster version bump) were not backward-compatible with existing test expectations — the milestone branch accumulates drift from `main` during active development.

### CodeQL False Positive — Fixed Defensively
CodeQL raised 2 HIGH alerts on `py/clear-text-storage-sensitive-data` in the webhook's status output writers. The FP was traced to a value-insensitive taint model (the webhook password only hits the login POST body, never the output), but the user chose to **harden defensively** anyway. The fix required two taint-breaking mitigations:

1. Replace the `str.replace(secret, marker)` redaction barrier (which CodeQL modeled as _injecting_ the secret via the `.replace` argument) with a precompiled `re.sub` alternation.
2. Remove the `kc_realm` interpolation from the success message (the only `_smoke_secret`-derived value in any returned detail).

The result is CodeQL GREEN and behavior-unchanged. The _lesson_ is that value-insensitive taint models trip on redaction barriers — use precompiled regex patterns, not string replacement, to avoid the taint-flow artifact.

### E2E Image Contract Mismatch Remains Unresolved
The M2 remote runner's live acceptance gate reported 45/102 test failures because the E2E client expects flat API responses and numeric prices while the deployed services return `{data: ...}` envelopes and string prices. Root-cause analysis was not completed; stale vCluster cleanup was needed before retry, suggesting an idempotency gap in the harness. The resolved E2E image (`sha-0c2505b`) was built and pushed to handle the envelope mismatch, but it was not rerun through the M2 live gate before merge. This acceptance loop remains open for post-merge validation.

### Hub Control-Plane Saturation Incident (2026-09-02)
ArgoCD OAuth redirects and Grafana public 502s traced to k3s API/etcd failures under ~650–880% CPU saturation. Server and agents were restarted but the API remained unstable. The incident is documented in `docs/issues/2026-09-02-hub-control-plane-saturation-causing-public-502.md` and represents a gap in workload-level mitigation and durable URL/status fixes.

### ApplicationSets Reapply Deferred (Post-Merge Step)
Per CLAUDE.md rules, ApplicationSets must be reapplied on every release to unfreeze the `$values` ref from `main` (where it was frozen during v1.27.0 branch work) back to the release branch. This step is required for the cluster to consume the committed config changes and is gated post-merge.

## Decisions Made

1. **Ship all three CVE-loop latches inert by default.** The staged Audit→Enforce rollout was prioritized over immediate enforcement to reduce cluster risk during early validation.

2. **Harden defensively against CodeQL FPs.** Even though the clear-text-storage alert was traced to a false-positive taint model, the defensive redaction fixes (precompiled regex, dropped interpolation) were applied anyway — they improve code quality and demonstrate commitment to secure defaults.

3. **Defer E2E image multi-run acceptance to post-merge.** The M2 runner preflight and publisher are live; the full multi-run acceptance gate will execute after the Tier-1 image contract is confirmed.

4. **Document pre-existing local-macOS-env failures as not-blocking.** Four test failures (455/457/767/773) fail on `main` too and pass in CI; they are environment-specific brittleness, not PR-blocking regressions.

5. **Keep all four v1.27.0 plan docs in-release.** The 4/5 scope cap was respected; no split was needed.
