# Retrospective — v1.15.0

**Date:** 2026-07-13
**Milestone:** security & multi-cluster provider hardening
**PR:** [#105](https://github.com/wilddog64/k3d-manager/pull/105) — merged to main (`14cdaea6`)
**Participants:** Claude, Codex, Gemini, Copilot

## What Went Well

- All 4 code tasks landed and were independently verified before the PR: WS3 Phase 2 per-context hub-Vault CSS (`46f400b9`), WS3 Phase 3 default-provider demote + reachability preflight (`2f74acf3`), Trivy Standalone→ClientServer migration (`855a06e4`), and the js-yaml DoS bump via the lib-foundation v0.4.4 subtree (`999edb81`).
- The Trivy ClientServer migration was **live-verified on the hub** (scan jobs no longer hit the `cache may be in use` timeout) before staging the PR, not just asserted in a test.
- Copilot caught two **genuine** CI coverage gaps — the review earned its keep rather than producing noise.
- The js-yaml Dependabot alert (GHSA-h67p-54hq-rp68) auto-closed on merge exactly as designed; no manual dismissal needed.
- Release scope stayed inside the 5-plan cap by splitting WS3 across v1.14.0/v1.15.0.

## What Went Wrong

- **Tests authored but not gated.** New BATS suites under `scripts/tests/etc` and `scripts/tests/plugins` were written but never added to the CI `bats` invocation (scoped to `scripts/tests/lib` only), so they were documentation, not gates. Copilot flagged it; fixed in `a41f8987`.
- **Fleet ApplicationSets pinned to a release branch.** The hub's `observability`/`observability-acg` appsets were pinned to `k3d-manager-v1.15.0` and `services-git` to the already-stale `k3d-manager-v1.14.0`. Deleting the merged branch (or the next `deploy` with a default `K3D_MANAGER_BRANCH`) would have broken sync or re-pinned stale — a latent landmine that required a manual post-merge re-point to `main`.
- **Post-merge tracking gap.** After the merge, the release-completion steps (tag / GitHub release / next branch / retro) were briefly believed done but had not actually run — caught by verifying tag/release/branch existence against `origin` rather than trusting the assumption.

## Process Rules Added

| Rule | Source | Where |
|------|--------|-------|
| When a spec adds BATS tests, confirm the target directory is actually in the CI `bats` invocation (`.github/workflows/ci.yml`) — a test outside the scanned path is documentation, not a gate. | Copilot PR #105 finding | `docs/issues/2026-07-13-copilot-pr105-review-findings.md` |
| Post-merge must re-point fleet ApplicationSets off the release branch to `main` (they default to the checked-out branch via `K3D_MANAGER_BRANCH`), or a branch delete / next deploy breaks fleet sync. | This retro | post-merge carry-forward |

## Decisions Made

- **WS3 split:** Phases 2–3 shipped in v1.15.0; Phase 1 (per-context Kubernetes auth mount) shipped in v1.14.0 — per the scope-cap rule.
- **Trivy topology:** migrate to ClientServer mode via the chart's **built-in shared Trivy server**, not a separately managed deployment.
- **CI test scope:** defer the whole `scripts/tests/plugins` directory from CI until the `kubectl`/relay stubs are isolated from real binaries on `PATH`; wire in individual green files (e.g. `trivy_operator_observability.bats`) as their code lands.
- **Default provider:** demoted off `k3s-aws`; a bare invocation no longer defaults to an AWS cluster, and an unreachable target now fails fast via a reachability preflight.

## Theme

v1.15.0 was a hardening pass rather than a feature push: close a dev-dependency DoS advisory, stop Trivy's concurrent-scan cache-lock failures by sharing a built-in Trivy server, and make multi-cluster registration safer (per-context hub-Vault connectivity so a second app cluster can't clobber the first, plus a safer default provider that fails fast when unreachable). The recurring lesson was about **gates versus artifacts** — tests and ApplicationSet pins both existed but weren't wired to the state they were meant to protect, and only verification against the live/remote source of truth surfaced the gaps. The fixes were small; the discipline of checking that each safeguard is actually load-bearing was the real work.
