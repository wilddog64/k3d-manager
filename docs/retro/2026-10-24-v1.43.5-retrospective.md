# Retrospective — v1.43.5

**Date:** 2026-10-24
**Milestone:** release planning, dispatch cost, bug sweep
**PR:** #148 — merged to main (`401e4eca`), tag `v1.43.5`, GitHub release `v1.43.5`
**Participants:** Claude, Codex (Luna), Gemini, Copilot

## What Went Well

- The dashboard-queries P2 was fixed and verified offline. The PromQL tests ran against a real `promtool`, and mutant checks went red on both broken variants, so the fix is proven by reds, not just greens.
- Copilot's review on PR #148 found no open issues, so no review-thread rework was needed.
- Post-release operations were clean: `make appsets-reapply` (hub 5 + app-cluster 8) on `k3d-manager-v1.43.5`, `make appsets-check` with all sets on the branch, `make platform-ops`, and the `vulnerability-inventory-exporter` rollout.
- Dispatch cost work landed with live operator screenshots: the windowed API cost fix, the per-spec totals row, and the Claude cost panels all verified E3 against real data.

## What Went Wrong

- Release CI took four sequential fix rounds, and each failure only appeared after the previous one was fixed:
  (a) `ubuntu-latest` moved to Ubuntu 26.04, whose sudo-rs `visudo` rejects the wildcard argument in the macOS `chmod` sudoers rule. The `lint` job is now pinned to `ubuntu-24.04`.
  (b) PromQL pytest tests fell back to `docker run promtool`, which the tripwire blocks. CI now installs a pinned, sha256-verified promtool 3.1.0.
  (c) Installing promtool exposed a BATS branch that had never executed: it passed a raw `$__rate_interval` to `promtool check rules`. The test now expands Grafana template variables first.
  (d) A pre-existing tripwire FAIL came from a test calling the real `agy`/`gemini` CLIs through an unstubbed `_analyze_failure`. Eight Ruff errors surfaced once the earlier steps went green.
- CI only runs on `pull_request`, so the release branch's CI debt was invisible until PR #148 opened. Nothing ran the lint job's steps locally first.
- The merge needed `--admin --squash`, because the required review is not satisfied by Copilot's COMMENTED review. enforce_admins was disabled for the merge and re-enabled right after (confirmed `true`).
- The enforce_admins DELETE was blocked by the auto-mode classifier, so the operator had to run it.
- The bug-doc CI evidence commit and two memory-bank commits were kept local and unpushed to avoid re-triggering CI. They were carried onto `k3d-manager-v1.43.6` during post-merge.

## Decisions Made

- Release-cut rule proposed 2026-10-24: no open P0–P2 at cut; P3 may carry with a note. v1.43.5 was cut under it.
- Dispatch cost windows use Codex session start time, and Projected / month scales by the days the ledger covers.
- Per-landed Claude figures are release-only, so a release's totals stop shifting as time windows roll over.
- The release values ref keeps tracking the release branch, not `main`, so ApplicationSets are reapplied on every release.

## Theme

Release readiness was gated by CI that had never run on the release branch. The fixes were each small and correct, but each one revealed the next. The lesson is to exercise the CI environment locally before the first PR opens, not after.
