## What Went Wrong

- **WS3 Phase 1 spec had a latent bug** — vault.sh auth mount derived from `cluster_name` instead of `app_context` in the spec's own code block; Codex implemented it faithfully. Only breaks where kube-context ≠ cluster name (EKS/AKS/GKE). Fix applied post-hoc in Copilot round (commit 3175ec99). **Action:** Before next phase, peer-review spec code blocks for context-keyed derivations.
- **Trivy metric typo** — `trivy_clusterrole_clusterrbacassments` missing "esse" found in three places (observability.sh:655, BATS assertion, bug-spec doc). Emptied ClusterRole RBAC report until fixed. **Action:** Pin metric names to canonical source before mocking.

## Process Rules Added

| Rule | Rationale |
|------|-----------|
| **Prometheus/PromQL query strings** — When a test pins a Prometheus query string, the mock's case arm and the assertion must derive from the metric's canonical name, not copy-paste the code-under-test string. | Typo cascades (WS3 metric name, test assertion, bug doc). Canonical source is the Prometheus scrape config or the query tool output, not the inline string. |
| **Context-keyed helpers** — When a helper is context-keyed and sibling sites key on context, the spec's example must pass the context. Cross-check the mount argument before handoff. | WS3 Phase 1 spec derived mount from `cluster_name` but vault.sh needed `app_context`. Peer-review spec code blocks before Codex runs. |
