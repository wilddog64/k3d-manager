# Retrospective — v1.45.0

**Date:** 2026-11-23
**Release:** v1.45.0 (PR #164 merged to main, `0c27b830`; tag `v1.45.0`)
**Participants:** Claude, Codex, Gemini, Copilot

## Theme

Remote promote approval (plan 1, 2a–2e), secure remote access (plans 2 and 4: travel password bundle, web console A and C), and process/observability (plans 3 and 5, trimmed). Carried out to the next `/release-groom`: web-console part B, `make-up-app-none`, multi-project M3/M4, stall-recovery parts 1/3/5.

## What Went Well

- Independent Acceptance verifiers ran on 2c (root daemon) and 2e (CVE-pin branch); both PASS. 2e's M13 failure was stale spec text, amended to the operator's 2026-11-20 fail-loud decision.
- Red-team gate (Fable and Astra, blind) found 20 findings with no P0 or P1; the gate did not block the release PR.
- Claude read-only hub smoke test passed before merge (30/30 apps Synced/Healthy, 4 nodes Ready).
- Scope check mapped all feature code to the five plans; out-of-plan fixes were added to CHANGELOG rather than dropped.
- Argon blind review passed with two low findings, both no change.

## What Went Wrong

- Copilot was capped until 2026-12-01, so PR #164 had no GitHub review. Admin override was used to merge (enforce_admins deleted on main for the merge, restored after).
- Live checks were owed at merge time: 2d E11 and the multi-project M2 live check. Travel bundle E3/E5 are event-driven and still open.
- Land refusals were frequent across remote-promote slugs (see Dispatch Review); the 2b land needed five attempts, with a 10s wall-clock TTY deadline failing under load (P3 bug filed).
- dr-drill on m2 failed on istioctl 1.32.0 rejecting k3s 1.32.0 (IST0142); the m2 cluster was not the live hub, and the drill also hit a locked login Keychain and an unexplained V4 exit (bugs filed, triaged to v1.45.1).
- The 2026-11-22 hub-deploy first attempt used a stale REF (142 commits behind); the promoter refused, so no change was made.
- CodeQL #38/#39 were false positives; dismissal was blocked for Claude and needed the operator.

## Process Rules Added

- Red-team gate before a release PR (spec `docs/plans/v1.45.0-red-team-gate.md`); findings become bug docs, P0/P1 block the PR.
- Admin override for a merge is recorded in the PR body and memory-bank, with enforce_admins restored immediately after merge.
- Independent Acceptance verifiers (worktree-isolated, scratch HOME, sandbox-exec denying sudo and launchctl) for security-critical dispatches.

## Decisions Made

- Red-team P2s and the DR-drill istioctl bug go to v1.45.1 (operator, 2026-11-23); the root-installer writable-checkout finding (Fable #3) is P2 and does not block v1.45.0.
- Copilot-capped release PRs get a blind Argon review in place of Copilot.
- Web-console part B, `make-up-app-none`, multi-project M3/M4 and stall-recovery parts 1/3/5 deferred to `/release-groom`.
- Hub reads m5-air as the live hub (k3s 1.32.0, Istio 1.31.1); m2 is an older EOL cluster.
