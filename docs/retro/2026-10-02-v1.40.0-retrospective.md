# Retrospective — v1.40.0

**Date:** 2026-10-02
**Milestone:** Hermes prior art and app-health sensing, reader-tier cloud bridge diagnostics, cloud-request artifacts, and Slack `/ask-docs`
**PR:** not yet created

## What Went Well

- The five v1.40.0 plans were explicit about the release surface: Hermes prior-art and retrieval evaluation, the Hermes app-health delta sensor, cloud-bridge test targets with a tripwire, cloud-request artifacts, and `/ask-docs`. (`docs/plans/v1.40.0-hermes-prior-art-and-retrieval-eval.md`, `docs/plans/v1.40.0-hermes-app-health-delta-sensor.md`, `docs/plans/v1.40.0-cloud-bridge-test-targets.md`, `docs/plans/v1.40.0-cloud-request-artifacts.md`, `docs/plans/v1.40.0-slack-corpus-qa.md`)
- Slack threading now covers `/ask`, `/ask-docs`, and `/cluster-status`; `/ask` and `/ask-docs` retain response-URL delivery outside the configured bot channel. (`61d6d3fb`, `609df49f`)
- The retrieval evaluation is now measured against both embeddings and an offline TF-IDF control, with hard negatives included. (`0ded5a83`, `e35fcba9`, `9de895b2`, `docs/guides/vector-store.md`)
- The e2e harness gained diagnostics that made failure state visible: a recorded make log and a substrate dump. (`docs/bugs/2026-10-02-e2e-recorded-log-lags-live-run.md`, `docs/bugs/2026-10-02-e2e-substrate-failure-leaves-no-pod-state.md`)

## What Went Wrong

- The 2026-10-02 e2e chain exposed five separate harness and substrate failures: a GHCR credential path reported the wrong remedy, vcluster reconcile parsed a table as names, service-link injection clobbered `RABBITMQ_PORT`, the Keycloak realm roles were nested incorrectly, and the vcluster test seed remained a table after production switched to JSON. (`docs/bugs/2026-10-02-ghcr-pat-resolver-misleading-remedies.md`, `docs/bugs/2026-10-02-vcluster-reconcile-parses-list-table-as-names.md`, `docs/bugs/2026-10-02-e2e-service-link-env-clobbers-rabbitmq-port.md`, `docs/bugs/2026-10-02-e2e-keycloak-realm-roles-nesting.md`, `docs/bugs/2026-10-02-vcluster-bats-orphan-seed-still-a-table.md`)
- The recorded log initially lagged the live run because `script(1)` was not flushing on each write; the recorded-log bug document names the failure and its platform-specific flush flags. (`docs/bugs/2026-10-02-e2e-recorded-log-lags-live-run.md`)
- The last e2e run, `1790962990-9267`, reported 49 passed and 8 failed; all 8 failures were in `api/payments.spec.ts`. The cause recorded for that run was that the e2e-tests image publish never ran for `wilddog64/shopping-cart-e2e-tests` commit `755ad2d`; it was re-dispatched manually. (`memory-bank/progress.md`)
- Codex's sandbox could not write `.git`, so Claude committed the implementation; the standing user rule remains that implementation goes to Codex. (`memory-bank/progress.md`)

## Process Rules Added

| Rule | Where | Why |
|---|---|---|
| Preserve a recorded make log that flushes during the run. | `docs/bugs/2026-10-02-e2e-recorded-log-lags-live-run.md` | A lagging log hides the failure while the harness is still running. |
| Save substrate state before teardown on a substrate failure. | `docs/bugs/2026-10-02-e2e-substrate-failure-leaves-no-pod-state.md` | Teardown otherwise removes the pods, events, and logs needed for diagnosis. |
| Use structured output for vcluster reconciliation and keep test seeds aligned with it. | `docs/bugs/2026-10-02-vcluster-reconcile-parses-list-table-as-names.md`, `docs/bugs/2026-10-02-vcluster-bats-orphan-seed-still-a-table.md` | Human-readable tables created false orphan names and stale tests. |
| Treat retrieval as advisory until a larger labelled set supports a filing gate. | `docs/guides/vector-store.md` | The live result improved bugs only and added intrusion. |

## Decisions Made

- The release keeps `/ask-docs` as reader-only, bounded, redacted, advisory documentation search, with a configurable provisional retrieval floor. (`docs/plans/v1.40.0-slack-corpus-qa.md`, `cccf9748`)
- Cloud-bridge test targets remain reader-tier and run behind the tripwire that blocks real cluster, cloud, and keychain tools. (`docs/plans/v1.40.0-cloud-bridge-test-targets.md`, `0c697005`)
- The first completed cloud job response may carry credential-scrubbed artifacts, while raw job output is not published. (`docs/plans/v1.40.0-cloud-request-artifacts.md`, `5d915bea`)
- The retrieval result is not a filing gate: the guide says to treat `find-similar-docs` output as advisory and not to read a high score as “do not file.” (`docs/guides/vector-store.md`)

## Theme

v1.40.0 made diagnostics more useful across three surfaces: Hermes records more actionable state, the cloud bridge exposes bounded read-only checks and scrubbed artifacts, and Slack can keep answers with the conversation. (`docs/plans/v1.40.0-hermes-app-health-delta-sensor.md`, `docs/plans/v1.40.0-cloud-bridge-test-targets.md`, `docs/plans/v1.40.0-cloud-request-artifacts.md`, `61d6d3fb`)

The e2e failures show the same operational lesson from several angles: output format, environment injection, credential diagnosis, and teardown order are all part of the test contract. The recorded make log and substrate dump made those failures inspectable while the run was active. (`docs/bugs/2026-10-02-ghcr-pat-resolver-misleading-remedies.md`, `docs/bugs/2026-10-02-e2e-service-link-env-clobbers-rabbitmq-port.md`, `docs/bugs/2026-10-02-e2e-recorded-log-lags-live-run.md`, `docs/bugs/2026-10-02-e2e-substrate-failure-leaves-no-pod-state.md`)
