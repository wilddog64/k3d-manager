## What Went Well

- **Clean Copilot review:** Zero findings on the final PR submission. The issue detection pipeline is working well across authorization, secret hygiene, and scope boundaries.
- **Live e2e smoke testing:** Long debugging day with Gemini paid off — GHCR credential paths, service-link environment variable collisions (RABBITMQ_PORT clobbering), Keycloak realm roles, and payment JWT role converter all surfaced and fixed before merge. The e2e-tests PR #10 landing in parallel confirmed the test harness works end-to-end.
- **Incremental CI fixes:** Two red lights caught and fixed early (bats_negation_lint + stale /ask-docs usage string, then pytest test_cloud_artifacts git identity), keeping iteration tight and preventing merge delays.

## What Went Wrong

- **BATS negation assertions:** Nine new bare `! cmd` BATS negations added this release could never fail under `set -e`. Found by linter (104dee7d), fixed by converting to `run` + status check. This is a recurring pattern that should be caught at author time, not in CI. The `bats_negation_lint.bats` guard exists but was not green when it should have been.
- **Git identity in CI:** Test passed locally (macOS git guesses identity via user.useConfigOnly) but failed only on the cloud runner. The bridge clone had no git identity set, invisible until reproduced with `HOME=tmp + user.useConfigOnly=true` (d661d13d). This is a **test determinism** debt — local pass with CI red is the failure mode of environment-dependent tests.
- **Long e2e debugging cycle:** The Gemini live session was substantial. Keycloak realm roles + payment JWT conversion + form-encoding edge cases in e2e-tests required multiple iterations. This was not a defect in k3d-manager itself but in the e2e harness, caught only by live Tier 2 testing, not by unit gates.

## Process Rules Added

- **Bare negations in BATS are a linter offense:** `bats_negation_lint.bats` must be green on every pre-commit. Establish a pre-commit hook or CI gate if linting is not enforced.
- **Environment-dependent tests surface in CI only:** Cloud runners should have `user.useConfigOnly=true` and `HOME=/tmp` set by default to catch git identity, keychain, and profile path assumptions in tests before they reach CI.

## Decisions Made

- **k3dm-smoke-user Vault sync:** Moving credentials to Vault with ExternalSecret sync prevents hub rebuild from leaving `/cluster-status` with stale smoke-token warnings. The seed logic prefers Vault → legacy Secret → generate, and passes secrets via stdin only, never argv.
- **`/cluster-status` threading:** Moving the per-check report into the message thread keeps the channel clean and avoids burying the channel with repeated runs. This required pushing `channel_id` through the relay.
- **Hermes findings with hostnames:** Surfacing failed hostnames and clickable CI run links in Hermes reports makes root-cause triage actionable. The status-history legend explains the 0/1/2 encoding.

## Theme

**One lesson learned four times: different problems require different solutions.**

1. **BATS negations** — a guard that is supposed to fail under `set -e` but doesn't needs a control-flow assertion, not a syntax check. `run ! cmd` (correct) vs `! cmd` (silently no-op).
2. **Git identity in test clones** — a missing `.git config` with `user.name`/`user.email` is silent on macOS (system default), loud on Linux. The fix was 2 lines; the detection was the real cost.
3. **Keycloak realm roles** — the e2e suite was testing Keycloak login but with the wrong realm set in the JWT. Tier 2 live testing found this because unit tests never run Keycloak.
4. **Hermes status ConfigMap label** — the `hermes-status` ConfigMap label was spliced into the YAML as a string (`key=value`), not a label map. This made `metadata.labels` a string and failed every apply since v1.34.0, so the Hermes Status dashboard never had data. The manifest is now built as JSON with a real label map.

Each was a different class of problem (control flow, environment, test scope, YAML structure), each needed a different fix, and each was invisible to the previous release's gate.
