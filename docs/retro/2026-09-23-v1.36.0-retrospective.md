## What Went Well

### Documentation Link Validation Gate
The `make check-doc-links` gate shipped as a production check, scanning 1,739 files for broken links and anchors. The gate is wired into the `.githooks/pre-commit` hook, configured to validate staged `.md` files only, preventing regressions at commit time. This closes a long-standing review gap — docs have lived without structural validation. The pre-commit hook runs silent on success and names each broken file on failure, making it actionable and non-intrusive.

### Tier 2 E2E Verification Gate
The `e2e_verify_sandbox` feature shipped for Tier 2 (ACG/Stripe) acceptance runs, integrating with the vCluster preflight harness. The feature includes deterministic failure classification via the Hermes `e2e_triage` module and live smoke probe integration for real-time outage detection. The smoke gate caught a real production outage — 47 hours of ImagePullBackOff in shopping-cart-apps — that CI did not surface and an operator-run `make up` would have silently ignored.

### E2E Failure Classification Deduplication
Hermes `e2e_triage` consolidated duplicate failure classifications from 42 code paths across two repos and 14 pytest test suites into a single shared module. All E2E verdict text now flows through one function, enabling consistent incident attribution and eliminating false categories from appearing in alert summaries. The correlation pipeline routes failures to the right stakeholders based on root cause, not symptom.

### Live Smoke Detection Caught a Production Outage
The unified `make smoke` target and its live-gate integration proved the value of structured observability. A 47-hour GHCR ImagePullBackOff (402 Forbidden on manifest HEAD) ran silently in the hub's shopping-cart-apps namespace while CI checked only the cluster status API. The smoke gate ran `kubectl` health checks and caught the registry auth failure in real time, leading to the immediate identification and repair of a stale `github/pat` token in Vault — the first defect in the credential chain that static checks cannot catch.

## What Went Wrong

### Repeated Misreading of ACG Auto-Login Status
Claude asserted across three separate sessions (two in this milestone, one prior) that Tier 2 needed a manual ACG sign-in step in `pw-profile`. The user corrected this twice and was right both times. The ACG auto-login has been fully wired since v1.14.0 / lib-foundation v0.4.1; the CI spec and code review all confirmed it was wired. The root cause was an unpopulated Keychain item `k3dm-acg-pluralsight`. When the Keychain read returns no credential, `cdp.sh:184-185` swallows the error with `2>/dev/null || true`, so the session gate gets two empty strings and takes its `ACG_SESSION_EXPIRED` branch, which surfaces to a non-TTY caller (Claude's shell) as a session-expired error. The symptom correctly suggested "gate not wired" but the gate **was** wired — the credential was missing. The fix is an operator Keychain population, not code. This distinction will require documenting a preflight check that explicitly names this Keychain item and surfaces its absence early.

### GHCR Token Fix Did Not Propagate to Vault Automatically
A GHCR 403 / ImagePullBackOff ran for 47 hours. The morning's `gh auth refresh` fixed the credential in the operator's Keychain, but nothing automatically propagated it to `secret/data/github/pat` in Vault — which is what the ExternalSecret actually reads. Writing the k8s Secret directly (via `kubectl apply` of a fresh `.dockerconfigjson`) appeared to succeed and was reverted by ESO within seconds. The correct diagnosis required reading the value back and comparing it to `gh auth token`, which revealed the mismatch. This exposed a gap in the credential restore path: the operator's local credential refresh does not reach the cluster without a **second, explicit Vault write**. The 47-hour gap shows this is a design friction worth eliminating in future credential rotation refactors.

### E2E Preflight Phase Checks Nothing
`e2e_verify_sandbox` sets `_E2E_ACTIVE_PHASE="preflight"` but then performs no checks — its first live action is `acg_extend_playwright` at line 315. When a credential is missing (e.g., the Keychain item), the check fails silently inside Playwright (waiting for the "Sign in" button that never appears) and the summary blames the `extending-sandbox` phase. The error attribution is incorrect, confusing postmortems. The spec for v1.37.0 Task 1 adds an explicit `_e2e_sandbox_preflight_auth` check that runs before Playwright and surfaces credential gaps early with a clear error message.

### E2E Skip Flag Allows Unsigned-Out Browser Runs
The `K3DM_ACG_SKIP_SESSION_CHECK=1` flag exists to bypass the ACG session gate (`cdp.sh:167`), designed as a diagnostic override. However, it allows an acceptance run to drive a signed-out browser, which is a correctness defect: an unsigned session will silently drop OAuth redirects that a signed session would handle, producing false-negative test results. This variable must be refused for Tier 2, not used to get a green run. The v1.37.0 spec marks this as a decision: the auto-login enablement work deliberately requires **no upstream lib-foundation change**, so the refusal logic lives in k3d-manager only.

## Process Rules Added

- **Keychain credential freshness check:** When ACG/Playwright gates are wired and appear "not wired" to a non-TTY caller, run a preflight that explicitly loads and names the required Keychain items. This surfaces missing credentials before Playwright initialization.
- **Read the value back after Vault writes:** After writing a credential to Vault (especially ones backed by distributed systems like GHCR tokens), read the new value back and validate it against an external source of truth (e.g., `gh auth token`, `vault read`, a live test API call). A successful HTTP 200 from the write does not prove the value persisted correctly or matches what the consumer expects.
- **E2E phase attribution:** The `_E2E_ACTIVE_PHASE` marker must correspond to an actual check that runs in that phase. If a phase marker is set but its checks are skipped, errors will be misattributed to the next phase. Add a guard: assert that at least one live action runs per phase.
- **Skip-check overrides must be refused, not used to pass gates:** A diagnostic flag like `K3DM_ACG_SKIP_SESSION_CHECK` that bypasses a correctness gate should trigger an explicit refusal for production runs, not silently allow the gate to be skipped. Distinguish "running offline" (legitimate use) from "running unsigned" (correctness failure).

## Decisions Made

- **ACG auto-login enablement is QUEUED to v1.37.0, not fixed in v1.36.0.** The v1.14.0 lib-foundation change already wired the gate fully; the remaining work is an explicit preflight check and Keychain item population (operator action). The code change deliberately requires **no upstream lib-foundation change**, keeping the diff small and the review scope tight. The auto-login feature itself is complete and tested; only the UX (early error naming) is pending.
- **`K3DM_ACG_SKIP_SESSION_CHECK` refusal is mandated for Tier 2.** A diagnostic flag that bypasses a session gate must not be used to paper over missing credentials in production. The v1.37.0 spec adds an explicit refusal branch in the e2e plugin, leaving the flag available for offline diagnostics only.
- **`K3DM_ACG_PLURALSIGHT` Keychain population is an operator action,** not a code fix. The ACG account MFA status determines the path: (A) no MFA → populate once, gate is stable. (B) MFA → no auto-login by design, `pw-profile` session only. The blocking question is whether the ACG account carries MFA; the answer determines the long-term design.

## Theme

**Observability and credential hygiene brought a production defect to the surface in real time.** The smoke gate's `make smoke` integration caught a 47-hour registry auth outage that CI could not see, proving the value of structured health checks that exercise the full platform (API + images + identity). The outage also exposed a credential rotation gap: a local credential refresh (via `gh auth refresh`) does not propagate to the cluster automatically. Fixing this gap — making credential rotation bidirectional — is a v1.37.0 roadmap item. The related ACG auto-login misdiagnosis shows how session-gate symptoms (empty credentials) can read as "gate not wired" when they actually mean "credential missing." Fixing the UX to distinguish these cases is a v1.37.0 task.
