## What Went Well

- The release shipped the expired-sandbox reaper and the node-health tunnel restart as code with tests, not as manual runbook steps. (`CHANGELOG.md` `[1.42.0]`, `bin/k3dm-sandbox-reaper`, `bin/k3dm-node-health-watch`)
- Copilot's overview review reported 0 findings, and the operator dismissed the three pre-existing CodeQL alerts as false positives after reading them against the code. (`docs/issues/2026-10-09-copilot-pr138-review-findings.md`)
- The `test-all` run before merge was green: 2664 cases, 0 failed, exit 0. The Prometheus last-success timestamp advanced, which confirmed the test-metrics fix end to end. (`memory-bank/activeContext.md`, 2026-10-09 entries)
- The live Slack `/ask-docs` recency fix and the Grafana test-metrics panels were verified against live data, not only against BATS. (`memory-bank/progress.md`, 2026-10-09 entries)

## What Went Wrong

- CI lint caught an undefined `REPO_ROOT` (pyflakes F821) in `bin/k3dm-webhook` `_publish_test_metrics`. The call was wrapped in a broad `except`, so the `NameError` was swallowed and the webhook test-all fallback metrics were never published. Only PR CI caught it. Fixed in `8c7c33f8` with a direct test. (`docs/issues/2026-10-09-copilot-pr138-review-findings.md` §1)
- A CodeQL alert (#34, ambiguous regex in a test assertion) needed a fix on an `assert` line. `_agent_audit` treats an edited assert line as a removed assert, so the operator committed the fix with `--no-verify` in `0e74f3f2`. The guard works as designed, but it leaves a gap: a correct one-token regex change in a test cannot land through the normal path. (`docs/issues/2026-10-09-copilot-pr138-review-findings.md` §2)
- CodeQL re-reported three pre-existing `main` alerts because the PR touched their files. #31 and #32 (`py/clear-text-storage-sensitive-data` in `scripts/lib/webhook/status.py`) are false positives: the redactor is injected at runtime by `configure_runtime`, and CodeQL sees the identity default. #33 (`py/incomplete-url-substring-sanitization` in `scripts/tests/hermes/test_hermes.py`) is a test substring check. The operator dismissed all three as false positives. (`docs/issues/2026-10-09-copilot-pr138-review-findings.md` §3)
- The expired-sandbox reaper's live reap and the node-watch tunnel restart are both event-triggered. Neither could be exercised before release, so both shipped as "verify on next occurrence" rather than as verified behaviour. A vCluster cannot simulate them: virtual nodes have no kubelet, tunnel, CNI, or AWS. (`memory-bank/activeContext.md`, 2026-10-09 "Event-triggered checks" entry)

## Process Rules Added

| Rule | Where | Why |
|---|---|---|
| Every helper injected through `_helpers` needs one direct, unstubbed test, not only stubbed lifecycle tests. | `docs/issues/2026-10-09-copilot-pr138-review-findings.md` §1 | The stubbed publisher hid an undefined name until CI linted it. |
| Event-triggered behaviour ships marked "verify on next occurrence" with the exact grep or log to check. | `memory-bank/activeContext.md` (2026-10-09 release decision) | A vCluster cannot reproduce kubelet, tunnel, or AWS lapse events. |
| Queue a fault drill for each event-triggered check instead of relying on chance. | `docs/plans/v1.45.0-node-tunnel-fault-drill.md` | The tunnel restart path needs a deliberate, operator-run fault injection. |
| Keep the release spec count at 5 or fewer per milestone. | `memory-bank/progress.md`, `docs/plans/` | v1.43.0 and v1.44.0 are at the cap; v1.45.0 holds the drill spec. |

## Decisions Made

- v1.42.0 ships with the event-triggered checks marked "verify on next occurrence" rather than blocking the release on a live ACG lapse or a tunnel fault. (`memory-bank/activeContext.md`)
- CodeQL alerts #31, #32, and #33 are dismissed as false positives. They stay as tracked debt on `main` and are not a required check. (`docs/issues/2026-10-09-copilot-pr138-review-findings.md` §3)
- The node-tunnel fault drill is queued for v1.45.0 as `make drill-node-tunnel`, operator-run, with PASS, FAIL, and INCONCLUSIVE outcomes. (`docs/plans/v1.45.0-node-tunnel-fault-drill.md`)
- The release branch rule holds: the ApplicationSet values ref tracks the release branch, so `make appsets-reapply` is a required release step. (`CLAUDE.md`)

## Theme

v1.42.0 made the platform recover on its own and say so when it does. The reaper, the tunnel restart, and the Slack fixes all target failures that were previously found by hand. The remaining risk is in the event-triggered paths. Their first real occurrence is the test, and the v1.45.0 drill is how the team stops relying on that chance.
