## What Went Wrong

- **The S2 tests were vacuous and CI missed it.** The `_kubectl` stub returned where the real `_kubectl` exits, so a missing Secret looked fine offline. Only Fable's probe with the real `_kubectl` found it.
- **The xtrace leak was not in the spec.** The security rule covers tokens in arguments and logs, but the spec for code that handles unseal shards asked for no `set -x` trace test. `_no_trace` only silences the wrapped command, so the `printf` arguments and `shard=` assignments still traced. The bats suite also stubs `_no_trace` as a pass-through, which made S2-6 fail even after the fix until the real one was loaded.
- **About 15 P3 bug docs were captured from the two reviews** (7 from Argon, 8 from Fable). Six findings overlapped (stall scan, slug collision, `scheme=branch`, status `unknown`, resample withdraw, unlabelled pod) and got Fable confirmation sections. Nine of the 2026-11-18 docs name `6972d10a` (multi-project M1) as the origin, so one task produced most of the escapes.
- **Flash stage 2 stalled about 3 hours.** The K1 stub `_kubectl(){ cat >/dev/null; }` blocked on the new `get secret` call, which has no stdin. Claude stopped the worker and added `</dev/null`. Claude also fixed S2-3 (stderr overwritten by a later `run grep`) and B4-16 (grep matched the land TMPDIR path because the slug contains `keychain`; now `grep -qx`, with a control).
- **Claude's first bats run for stage 2 ran against the main repo,** because `source_plugin` uses `$PWD/scripts` and the `smartcd` cd failed. It was rerun from the worktree with builtin `cd`.
- **dirused tasks were recorded under v1.44.2.** The OOB (out of band) dispatches started before M1 landed, so the ledger holds them under `v1.44.2` with no `project` key. The stall-watch events also lack `project` (`docs/bugs/2026-11-17-stall-watch-ledger-events-lack-project.md`).
- **Land refusals continued:** 4 across the 6 k3d-manager tasks and 5 across the 10 OOB tasks (see Dispatch Review).
- **Live checks are still open** (see Decisions Made): webhook W1-W6/E2, watchdog stage 2, and the stall row.
- **Weekly quota use was 53% at 5.2 days in.** Last week ran about 14% per day and this week about 10.2% per day. Dispatch starts were down 21% per day, resumes up 40%, commits up 26%. Cost per start was flat at about 0.75%. Resumes rose while starts fell, so more of the spend went to rework.

## Process Rules Added

- **A spec that moves shards, tokens or keys through shell variables carries a `set -x` trace test as a `must_not`,** with the real `_no_trace` loaded, because the bats suite stubs `_no_trace` (process note in `docs/issues/2026-11-18-argon-pr163-review-findings.md`).
- **A stub must behave like the tool it replaces on failure.** The S2 stub exits where the real `_kubectl` exits; a stub that returns turns a failure path into a pass.
- **Medium and high-risk release diffs get Argon first, then Fable blind,** with Claude adjudicating. Pair 5 supports Argon-first plus Fable on high-risk release diffs (`docs/reviews/reviewer-trial-fable-vs-argon.md`).
- **Review findings are filed as `docs/bugs/` docs with an Introduced-by line,** so the Dispatch Review can count escapes per task by grep.

## Theme

Make the Vault-sealed path honest, and let two blind reviewers check the DR code the tests could not. The release added a sensor, a Vault-first diagnosis and the watchdog stage 2 fix, and the diff reviews caught two medium defects (a secret trace and a silent exit) that vacuous stubs and CI had passed. The lesson is that a test stub must fail the way the real tool does, and that the multi-project work, which produced most of the P3 escapes, needs a second review at spec time.
