# Retrospective — v0.4.10

**Date:** 2026-08-20
**Milestone:** ACG sandbox & CDP-pipeline reliability hardening
**PR:** #41 — merged to main (`bc70cef`), squash-merge; released as tag `v0.4.10`
**Participants:** Claude, Copilot

## What Went Well

- A routine **sanity check caught two latent problems** before they bit: (1) five ACG fixes had
  been committed **directly to `main`**, bypassing the PR + Copilot-review gate, and (2) the
  k3d-manager subtree had **diverged from upstream** via a bare revert (the "revert-a-subtree-merge"
  trap).
- **Revert-forward recovery worked cleanly.** `main` is ruleset-protected against force-push
  (`non_fast_forward`), so instead of rewriting history we reverted the five direct commits with a
  normal forward commit (`0ddb716`, tree == v0.4.9), then re-applied them via cherry-pick onto a
  `feat/v0.4.10` branch and merged through PR #41. The fixes picked up the Copilot review they had
  originally skipped.
- **Subtree content anchor stayed reachable.** Because the recovery was revert-forward (not a history
  rewrite), the original commit `223e4dd` remains an ancestor of `main`, so the k3d-manager subtree
  that already vendored it is unaffected — even though the PR ended up squash-merged.
- The subtree in k3d-manager was re-synced to upstream (reapply-the-revert + a proper
  `git subtree pull`), advancing the split metadata so the next pull won't re-conflict.

## What Went Wrong

- **Five fixes landed directly on `main`** (`0a2c4cc..223e4dd`), bypassing the established
  `feat/vX.Y.Z` + PR + Copilot flow. This was the root cause of the entire cleanup.
- The first attempt to reconcile the k3d-manager subtree used a **bare revert of a subtree merge**,
  which silently de-synced the subtree from upstream and would have broken the next subtree pull.
- **Local `main` drifted 2 commits ahead of origin** in k3d-manager — doc commits had been made on
  `main` instead of the release branch (recovered by resetting `main` to `origin/main`; content was
  preserved on the milestone branch).

## Process Rules Added

| Rule | File | Note |
|------|------|------|
| (reinforcement, no file change) | — | lib-foundation fixes go on a `feat/vX.Y.Z` branch + PR, **never** direct to `main`. The convention already existed; the lapse — not a missing rule — caused this milestone. |

## Decisions Made

- **Undo direct-to-main commits with revert-forward, not force-push**, whenever `main` is
  ruleset-protected against non-fast-forward. Re-introduce the reverted content via a normal PR so it
  passes the required review gate. This keeps published history intact and any downstream subtree
  anchors reachable.
- When reconciling the vendored subtree, prefer **reapply-the-revert + `git subtree pull`** over a
  bare revert, so the subtree stays in sync with upstream and split metadata advances.

## Theme

A sanity check became a history-hygiene cleanup. Five ACG reliability fixes — stale-route credential
recovery, CDP listener reclaim, and browser-launch test isolation — had slipped straight onto `main`
outside the review flow, and the k3d-manager subtree had quietly diverged from upstream. Rather than
rewrite published history (which the branch ruleset forbids anyway), we reverted `main` forward to the
last release, re-introduced the exact same fixes through a reviewed PR, and re-synced the subtree.
The end state is identical in content to where we started, but now every fix has a PR, a Copilot
review, and a tagged v0.4.10 release behind it — and the subtree is provably back in step with
upstream.
