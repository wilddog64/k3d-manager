# Retrospective — v1.26.0

**Date:** 2026-08-21
**Milestone:** Fleet node lifecycle + E2E promotion gate + stale managed-registration cleanup
**PR:** #117 — merged to main (`1bbe5439`)
**Participants:** Claude, Codex, Gemini, Copilot

## What Went Well

- **Fleet Phase A + Phase B live-verified at scale** — ACG_AGENT_COUNT=4 (5-node cluster, the ACG cap) provisioned all agents concurrently and reached Ready; two live-only defects (`_k3s_agent_is_ready` private-IP matcher, `fleet-plan` change-set syntax) surfaced only during E2E acceptance, caught before merge, fixed in-release (commits `46bfdf1c`, `35e9ecf2`, `0274fdde`). lib-foundation `v0.4.12` generation and `make fleet-render|validate|plan|up` rungs provided a durable offline→live verification ladder. Suite 17/17 green; teardown clean.

- **E2E promotion gate fully wired and observable** — run → JSON artifact → result-event ConfigMap → exporter metrics (`e2e_run_info`, `e2e_last_run_pass`, `e2e_last_run_timestamp_seconds`, `e2e_last_run_duration_seconds`, `e2e_last_success_timestamp_seconds`) → Grafana dashboard + alerts. A failed acceptance run was captured faithfully and drove the alert firing (`E2EVerificationFailing`), proving the full chain end-to-end.

- **Stale-cluster cleanup production-ready and safety-verified** — live acceptance on a real expired sandbox with 23 unrelated survivors: all survivors exact-match baseline, hostinger untouched, cleanup completed in ~3s with zero orphans. Blocking Finding 2a (cleanup hung on Secret deletion) fixed in-release (`0274fdde`), re-verified. JSONL audit trail retained.

- **Copilot review gap closed before merge** — test coverage for the managed `register_app_cluster` fail-closed guard was absent; two focused `provider_contract.bats` cases added (`525d69d0`), bringing coverage to 54/54.

- **Staged rollout prevented live regressions** — Tier 1 vCluster E2E harness + stale-cluster cleanup + fleet verification all proved end-to-end in live ACG sandbox before release, surfacing real defects that static analysis missed.

## What Went Wrong

- **Three blocking/medium findings surfaced only in live acceptance** — `_k3s_agent_is_ready` false-negative (private-IP resolution), `fleet-plan` broken change-set invocation, and `cleanup-stale-clusters` hang on Secret deletion all required in-release fixes. The static test suite did not catch these (BATS mocks the fleet/cluster abstractions; real ACG behavior differs). Finding 1a (empty duration metric, cosmetic) and Finding 2b (dispatcher strips `--confirm`) deferred as tracked issues in `docs/issues/`.

- **Shipped 3 of 5 scopes** — foundation-managed vCluster CLI and M2 remote E2E runner remained specs in `docs/plans/`. Scope was clear before the milestone; both remain open follow-ups for v1.27.0 or later.

- **Hit the 5-plan-doc cap** — all five scope specs were filed before implementation kicked off. A 6th scope proposed during the milestone would have triggered a split. This is by design (keep releases focused); splitting is the correct response, not a failure to plan.

## Process Rules Added

**Standing rule reinforced (already in CLAUDE.md):** "Always commit changes you made" — every feature and fix from this milestone was committed on the release branch before merging to main; no uncommitted changes leaked into the PR. This is not a new rule but was actively enforced during this release.

**New decision (branch protection):** `enforce_admins` admin-override merge pattern — when a release branch cannot merge due to enforcement, disabling `enforce_admins` for a user override (then restoring it in post-merge) is acceptable per the /post-merge skill. This happened for v1.26.0; both states were verified.

No other standing rules or code conventions changed.

## Decisions Made

- **Ship 3/5 scopes now; defer 2 as follow-ups.** Fleet and E2E gate were live-verified and durable; stale-cleanup was production-ready. Foundation-vcluster-CLI and M2-runner specs remain for v1.27.0 or later without slowing the release.

- **Values ref keeps tracking the release branch (not main).** ApplicationSets template their source as `${K3D_MANAGER_BRANCH}`, which was frozen to the old branch until reapplied. This release codifies the decision: values ref **stays on the release branch**. Reapplying the sets for both hub and ACG is now a required release step (not optional).

- **Enforce_admins disabled for admin-override merge.** When merge-protection blocks a release PR that is otherwise ready, the admin disables `enforce_admins` on main to merge, then /post-merge restores it. This happened for v1.26.0 and is now a documented pattern.

## Theme

The v1.26.0 release trades breadth (5 scopes) for depth and durability: fleet node lifecycle became count-agnostic with live multi-node verification; the E2E promotion gate became observable and wired into the alerting pipeline; and stale-cluster cleanup became safe enough to run with confidence. Each shipped feature proved itself end-to-end on a live ACG sandbox before any code merged to main. Three live-only defects emerged during acceptance and were fixed in-release — a win for staged rollout discipline. The remaining two scopes (foundation-vcluster CLI, M2 runner) stay focused and scoped for later; this release stays lean and verified, not broad and theoretical.
