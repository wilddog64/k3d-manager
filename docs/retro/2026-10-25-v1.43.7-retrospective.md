# Retrospective — v1.43.7

**Date:** 2026-10-25
**Milestone:** Cross-repo dispatch, Argo CD pin, dashboards fit
**PR:** #150 — merged to main (`d0c247dc`)
**Participants:** Claude, Codex (Luna), Gemini (agy), Copilot

## What Went Well

- All five plans landed in one day: hub Argo CD pinned upgrade (`750e9736`), cross-repo dispatch
  (`97d05b85`), worker/coordinator model telemetry (`0d5c58db`), landing latency and human
  interventions (`559b7840`), and the bug-dashboard auto release selection (`f6e92ffd`).
- The P1 Vault incident (a rejected unseal cache triggered a destructive reinit) went from filing to
  a landed fix (`f11e0c6e`) in about an hour. `hub_data_unseal_dr` and the repoint recovered the hub,
  and ESO was fully synced by 06:08 PDT.
- Most bug fixes were live-verified from operator screenshots the same day. They include the
  forecast floor, rejected-attempt tokens, agy Per spec, OrbStack phase 1, the run-log Loki link,
  the Fix commit column and auto release selection.
- Claude's review caught real defects before land: invalid PromQL in the OrbStack rule, a Per spec
  index collision, default-codex vendor `google`, an out-of-spec `--add-dir` widening and a stale
  loop variable in the Fix commit column (`e3bef10b`).
- Copilot found no issues on PR #150.

## What Went Wrong

- The hub went down at 05:36 PDT when the OrbStack update prompt appeared. The update had been
  staged since 10-23, and docker stopped before anyone clicked. Prevention: auto-check off, update
  by hand in the rebuild window.
- `deploy_vault --confirm` on a sealed Vault purged state after the cached shards were rejected
  (P1). ESO then stayed 403 because the Kubernetes auth config held vault-0's pod-bound token.
- Two CI reds on PR #150 were already red on the branch before release prep, and were found only at
  the PR:
  - the 5m refresh change broke the Host Disk dashboard test, which pinned every top-level key;
  - a roadmap edit added v1.43.10 without `docs/release-milestones.json`.
  A bare `! grep` in `codex_dispatch.bats` (from `71f70dd2`) also failed the BATS negation lint.
- Dashboard readability took many small rounds (panel 48 stat → bar gauge, panel 85 labels five
  times, table widths three times). Each needed a sync and a screenshot.
- Claude set `argocd.argoproj.io/refresh=normal` on `hub-grafana-dashboards`, a write outside its
  read-only rule. It was disclosed the same turn.
- Claude stopped mid-session on the first observed five-hour usage limit (21:55Z), with PR #150
  open. This led to the v1.43.10 quota telemetry plan.

## Process Rules Added

| Rule | Where |
|---|---|
| `deploy_vault` never reinitialises when the unseal cache is rejected; it refuses and points to DR | `scripts/plugins/vault.sh` (`_vault_reinit_refused`) |
| Every new plan or bug doc keeps a `**Priority:**` line and an Acceptance block; review results are to be recorded with `verify` | `docs/plans/v1.43.10-spec-and-fix-quality.md` (proposed) |
| Run the full `make test-pytest` before calling a branch green, not a few files | session practice (this retro) |
| Dashboard tests pin keys except the ones a release is expected to change (refresh) | `scripts/tests/bin/test_cni_ipam_dashboard.py` |

## Decisions Made

- v1.43.7 was cut on 10-25, ahead of the 11-03 Argo CD window. The live evidence still owed is
  carried in `docs/roadmap.md`:
  - the Vault unseal-cache E3 and the Argo CD pin at the 10-29 rebuild;
  - `make argocd-upgrade` on 11-03 (11-10 fallback), from `main` or the open release branch;
  - cross-repo E3, worker-model E2 and rollup-race E2 (through 11-01).
- v1.43.9 was full, so new plans went to a new patch release, v1.43.10. It holds context-threshold
  comparison, quota telemetry, and spec and fix quality (3 of 5).
- Spec and fix quality uses separate signals with no combined score. Escapes are linked only by an
  explicit `**Caused by:**` header.

## Theme

v1.43.7 made the dispatch pipeline measure itself: who worked on a spec (worker and coordinator
model), how long it waited between exit and land, how often a human had to step in, and which repo
a dispatch touched. It also pinned the hub's Argo CD so the 11-03 upgrade is one guarded command. A
P1 Vault incident and an OrbStack-induced outage tested the recovery paths on the same morning, and
both held. The release closed with the question of quality, not just cost, which v1.43.10 now plans
to answer.
