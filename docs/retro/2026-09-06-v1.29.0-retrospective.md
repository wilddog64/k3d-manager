## What Went Well

- **Hermes Phase-1 (off-hub read-only ops agent)** — five stdlib-only sensors (ESO sync via webhook, ArgoCD per-app health via get-only `hermes` account, public-endpoint reachability probe, node/data-layer via webhook, GitHub CI Actions read-only API), deterministic anti-flap correlator with multi-signal debounce, bounded Slack summarizer posting only on sustained degradation, launchd agent (`bin/k3dm-hermes`, `bin/k3dm-hermes-setup`, plist template), installed via lib-foundation **v0.4.15** `_install_hermes_agent`/`_uninstall_hermes_agent` with jittered `StartInterval`. Read-only-only access model (three credentials: reused webhook bearer, new ArgoCD `hermes` get-only account in values.tmpl, user-minted GitHub fine-grained PAT), **reports-and-stops by design** (no mutation path in codebase, no direct kube-apiserver credential, no kubeconfig). Guide: `docs/guides/hermes.md`; scope: `docs/architecture/hermes-phase1-monitoring-scope.md`. WS0–3 planned, spec'd, and implemented on-branch; live activation (ArgoCD values + token minting) completed pre-merge.

- **Self-healing Vault bring-up seeders** — `observability_seed_grafana` (public wrapper; fresh-generate-if-absent) and `signing_restore` (non-destructive restore from Keychain) so grafana + cosign KV auto-heal after cluster rebuild wipes the Vault raft (recurring post-incident exposure now closed). Codex authored core code + BATS, Claude ran live verify + hardening pass. Two bugs surfaced in live run (signing_restore missing `_vault_login` call, grafana seed was private-only) fixed immediately (`7eaaf897`, `ae9d8cb4`); live re-run proved all four remediation targets healthy. 32/32 BATS green, shellcheck clean.

- **`deploy_argocd_applicationsets`** — public dispatcher entrypoint that surgically reapplies **all** ApplicationSets (`observability`, `observability-acg`, `monitoring`, `services-git`, etc.) so each `$values` source is re-pinned to the current release branch, then self-verifies with `argocd_check_values_branch`. Durable alternative to ad-hoc scratchpad renders. Live activation on v1.29.0 found 6 Applications still pinned to v1.28.0; reapply corrected all to v1.29.0.

- **Release-ledger backfill** — README releases table and `docs/releases.md` were 3 versions behind (added v1.28.0/v1.27.0/v1.25.0 summaries from CHANGELOG; v1.25.0 intentionally folded into v1.26.0). v1.29.0 and v1.30.0 release rows deferred to next branch per convention.

- **Copilot security hardening** — two xtrace secret-leak findings (commit `60c01632`) identified and fixed pre-merge: (1) `_hermes_sensor_webhook` leaked the webhook bearer token in `-x` traces when re-probing on transient failures; (2) `_observability_rotate_prometheus_basic_auth` leaked the generated password. Both fixed by wrapping the sensitive calls in `set +x`/`set -x` guards. Patterns documented for future use.

- **lib-foundation v0.4.15 subtree sync** — Hermes agent install helpers merged cleanly; subtree untouched.

- **Clean release sequence** — all four v1.29.0 specs written (Hermes phase1 impl + access/install, vault seeders, bug fixes), offline CI green, pre-PR BATS gate passed, PR merged with Copilot review findings addressed, branch protection restored, tag and release published, next branch created.

## What Went Wrong

- **Hermes webhook sensor bugs delayed live verify** — BATS stubbed Vault writes during seeder testing (`43ce7732`) so `signing_restore` missing `_vault_login` and grafana seed privacy issue both slipped through until live run. Uncovered during post-merge smoke test, caught and fixed immediately, but could have blocked release. Root cause: stubbed infra makes it easy to skip auth-layer coverage. Lesson: mock at system boundaries, not at the auth layer.

- **Release-ledger backfill incomplete initially** — first pass added v1.28.0/v1.27.0 but missed v1.25.0 (a smaller entry). CHANGELOG gap intentional (folded into 1.26.0), but README/releases.md consistency check should have been explicit. Minor friction, quickly resolved, v1.29.0 row itself deferred to convention.

- **Hermes Phase-2/3 scopes not in v1.29.0** — WS1 sensor set (ArgoCD per-app health, webhook tunnel for node pressure), WS2 correlator Slack integration, and WS4 guide were scoped but deferred to v1.30.0 to keep v1.29.0 shippable and reviewable. All infrastructure committed; Phase 2 is unblocked.

## Decisions Made

1. **Hermes Phase-1 ships; Phases 2–3 → v1.30.0**
   - Phase-1 (WS0–3: access model, install helpers, public agent) complete and live-verified.
   - Phase-2 (WS1–2: ArgoCD sensor, correlator Slack) scoped but deferred to keep v1.29.0 lean.
   - Phase-3 deferred further (guide + APM feedback loop).
   - All foundational infrastructure (read-only creds, agent bootstrap, log structure) is in place.

2. **Vault seeder defaults: grafana = fresh-generate, cosign = restore-first**
   - grafana: no backup exists; fresh-generate-if-absent is safe.
   - cosign: Keychain backup exists (user holds the key); restore-first preserves user's signing identity across rebuilds.
   - Decision locked in `docs/plans/v1.29.0-vault-seeder-self-heal-grafana-cosign.md` and implemented.

3. **ApplicationSet reapply entrypoint — new standard process**
   - Every release now: `./scripts/k3d-manager deploy_argocd_applicationsets --confirm`.
   - Replaces ad-hoc `./.envrc` renders and scratchpad trial-and-error.
   - Self-verifying; repeatable on any branch.
   - Required release step documented in CLAUDE.md §Reapply the ApplicationSets on every release.

## Theme

v1.29.0 enables **the platform to observe itself without being touched by observability** — Hermes Phase-1 is a read-only, off-hub monitoring agent that runs on the laptop alongside the k3dm webhook, ingests cluster/CI health signals through existing credential boundaries (webhook bearer, ArgoCD get-only account, GitHub fine-grained PAT), and posts Slack summaries only when sustained multi-signal degradation suggests something needs human intervention. Reports-and-stops by design: no mutation path in the codebase, no direct kube-apiserver credential, no kubeconfig. Alongside this, **self-healing Vault seeders** close the recurring post-incident exposure — grafana and cosign KV now regenerate/restore automatically on bring-up instead of requiring manual re-seeding after every cluster rebuild. Together, these shape the next phase: an observability layer that operates *outside* the cluster, carries zero infrastructure debt, and leaves the platform in a state where a rebuild is just a rebuild, not a scope-creep incident recovery.
