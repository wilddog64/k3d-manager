# Retrospective — v1.12.0

**Date:** 2026-07-04
**Milestone:** v1.12.0 — Observability, Remote Operations, and Infrastructure Hardening
**PR:** #102 — merged to main (`e128e8b3`)
**Participants:** Claude, Codex, Gemini, Copilot

## What Went Well

- **App-image CVE auto-update pipeline** — ArgoCD Image Updater now watches shopping-cart app images, gates promotion on Trivy vulnerability reports, and writes back immutable SHAs instead of `:latest`. The feature survives cluster rebuilds because Image Updater is provisioned during bootstrap.
- **Remote operator access over Slack/Cloudflare** — Slack relay now assigns per-command roles and forwards headers; `bin/k3dm-webhook` enforces minimum roles (returns 403 for insufficient access) and maintains JSONL audit trails. First two slices shipped: role enforcement and read-only diagnostics.
- **App CVE visibility in status and Grafana** — `make status` now surfaces app CVE scan results plus Trivy VulnerabilityReport and infra-security summaries. Hub Grafana dashboard shows Image Updater readiness and watched-app churn with auto-refresh every 5m.
- **Public Alertmanager access** — Exposed via Cloudflare behind a credential-rereading basic-auth proxy that picks up password rotation without restart.
- **Trivy Operator observability** — Scan-job failures and infra-security findings now surface in Grafana with new Prometheus alert rules routed to the analyzer webhook.
- **Debug artifacts moved out of /tmp** — Script-owned output now lands in `~/.local/share/k3d-manager/run`; cleanup job prunes those artifacts and age-prunes stale repo-owned `/tmp` leftovers safely.
- **Hostinger refresh hardening** — Refresh is now idempotent, reapplies GitOps/observability/data ApplicationSets to the hub, clears stale app ownership, restores Alertmanager access, re-resolves frontend nginx upstream DNS, and self-heals the GHCR pull secret.
- **Vault token hygiene** — Refresh no longer inlines Vault tokens in logged auth commands; the app-cluster policy rewrites every refresh and canonical secrets seed from the source Vault for parity.
- **GitHub wiki bootstrapped** — Published `Home`, `Architecture`, `Operations`, `Observability`, `Slack-Commands`, `Troubleshooting`, and `_Sidebar` pages with starter operator documentation.
- **Slack reliability improvements** — Relay acks immediately and relays commands in the background; webhook accepts provider kwarg; worker smoke-tests after deploy.

## What Went Wrong

- **CI observability tests not OS-portable** — Tests 128–130 relied on the real `_is_mac()` and `launchctl` binary, so they passed locally on macOS but failed on Linux CI. Fix: forced `_is_mac() { return 0; }` in those specific tests to stub the macOS-only guard.
- **HTTP Response Splitting in alertmanager-auth-proxy** — CodeQL flagged that the auth proxy forwarded backend response headers verbatim without sanitizing CR/LF. Fix: strip `\r` and `\n` from both header name and value before re-emitting.
- **Fluent Bit image used :latest tag** — Container images must use pinned tags for reproducibility. Fix: pinned `fluent/fluent-bit:3.1.9`.
- **ACG watch startup exit code masked** — `acg_watch_start` unconditionally returned success even when the underlying start failed. Fix: capture exit code and return early on failure before retargeting logs.
- **Vault token still visible in argv** — `_vault_exec` passes `VAULT_TOKEN` via `kubectl exec -- env "VAULT_TOKEN=..." ...`, exposing the token in process argv despite removing it from the logged command string. **Deferred to v1.13.0** (pre-existing behavior on `main`; this milestone actually improved it by removing token from logged commands).
- **GitGuardian GitHub App doesn't read repo config** — The repo `.gitguardian.yaml` kept the **ggshield CLI** clean, but the server-side **GitHub App** doesn't read repo config. False positive in `scripts/tests/plugins/shopping_cart_seed_idempotent.bats` had to be resolved via API.

## Process Rules Added

| Rule | Rationale |
|------|-----------|
| Tests that assert output from macOS/launchd-guarded code paths **MUST stub `_is_mac`** so they are deterministic on Linux CI. | Tests 128–130 failed on Linux CI because they relied on the real macOS guard. Stubs ensure cross-platform CI consistency. |
| GitGuardian server-side check state lives on the workspace/dashboard and API — in-repo `.gitguardian.yaml` ignores cover the CLI only. | The GitHub App doesn't read repo config, so false positives must be resolved server-side. Update both local ignore config and server-side incident status to avoid future confusion. |

## Decisions Made

- **Webhook modularization design approved, implementation deferred to v1.13.0** — The design (`docs/plans/v1.12.0-webhook-modularization.md`) was completed and documented, but full in-repo decomposition of `bin/k3dm-webhook` is too large for this release and was moved to v1.13.0 as a separate spec.
- **Vault token-in-argv fix deferred to v1.13.0 as a dedicated bugfix** — This is pre-existing behavior on `main` and was already improved this cycle (token no longer in logged commands). Fully removing argv exposure (via stdin or file) warrants its own spec, test coverage, and live verification rather than folding into a 165-commit release PR.
- **Fluent Bit pinned to 3.1.9** — Confirmed as the intended release for the observability stack. Commit `4197ab18` locks this version.
- **ACG watch reloads after log path retargeting** — The watcher LaunchAgent now reloads immediately after plist retargeting so the new log paths take effect on the live agent without requiring a manual restart. Commit `02975e0a`.
- **Remote-operator-access shipping in two slices, command broker deferred** — First slice (role enforcement, commit `4bc12bfe`) and second slice (read-only diagnostics, commit `90332c2a`) shipped in v1.12.0. The richer troubleshooting command broker was deferred to v1.13.0 to keep the scope bounded.
- **enforce_admins re-enabled immediately after merge** — Branch protection was disabled to allow the merge; re-enabled via API before v1.13.0 branch creation.
- **Next milestone branch created on merge commit** — `k3d-manager-v1.13.0` points to `e128e8b3`, matching the v1.12.0 tag so next-cycle work can proceed in parallel.

## Theme

**v1.12.0 brings observability and remote operations to the forefront.** The app-image CVE pipeline makes supply-chain security visible in real time, while the new remote operator access pattern over Slack/Cloudflare opens a controlled path for cluster inspection and troubleshooting from anywhere. Infrastructure hardening — cleaner debug artifact handling, better Vault token hygiene, self-healing Alertmanager access, and idempotent Hostinger refresh — makes operations more predictable and less fragile. The GitHub wiki bootstrap closes a documentation gap for new operators, and the Trivy integration surfaces both infra-security and app vulnerabilities in Grafana so visibility is one dashboard away. Together, these changes shift k3d-manager from a launch-and-monitor tool to a proactive, auditable, self-healing infrastructure for local Kubernetes dev work.
