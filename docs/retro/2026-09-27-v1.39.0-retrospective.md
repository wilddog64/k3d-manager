# Retrospective — v1.39.0

**Date:** 2026-09-27
**Milestone:** Prior-art similarity search over the docs corpus, plus vectordb health monitoring
**PR:** not yet created — close-out artifacts landed first
**Participants:** Claude, Codex, Copilot, operator

## What Went Well

- **The advisory-everywhere contract held under four different real failures.** A withdrawn
  endpoint, a first-request 429, a spent daily quota and an unreadable keychain all occurred
  live, and none of them ever blocked filing a bug doc: `find-similar-docs` reported on stderr
  and exited 0 every time. The one design rule stated up front — a dedup aid must never become a
  new way for filing to fail — is the rule that survived contact.
- **Per-batch commits turned three failed runs into one successful index.** The first
  implementation embedded the whole corpus into memory and wrote once at the end. Had it shipped,
  the 429 at document 900 would have discarded 900 paid-for API calls against a ~1,000/day
  ceiling — i.e. it would have cost a full day's allowance and produced nothing. Instead each run
  resumed: 900, then 805, then done.
- **The per-day cap was settled by reasoning, not by spending quota.** The 429 refused 62s of
  backoff on 2026-09-26; the same key served 805 documents with zero 429s on 2026-09-27. A limit
  that refuses a minute of waiting one day and is free the next is a daily allowance resetting at
  the day boundary. No probe was run, so the diagnosis cost nothing it was diagnosing.
- **Mutation-proving caught wording regressions, not just logic.** Every new test this release was
  run against the pre-fix source first. The retry test showed the old code sleeping its guessed
  `2.0s` in place of the server's `31s`; the quota test asserted a `RequestsPerDay` string against
  the literal `embeddings API returned HTTP 429` the live run produced; the `paused` test failed
  against the old `unavailable` line verbatim.

## What Went Wrong

- **Four separate failures shared one shape, and it took four rounds to name it.** `HTTP 404` read
  as a credential problem; a bare `HTTP 429` could not distinguish a throttle from a spent
  allowance; `unavailable` could not distinguish a quota stop from a broken store; `rows: 0` could
  not distinguish a healthy mid-run read from a dead one. In each case a message collapsed two
  causes with *opposite* remedies. This is now a stated review question rather than a thing
  rediscovered per-incident.
- **The diagnostic bug was an ordering bug, which no test would have caught.** The 429 body was
  parsed only on the paths that go on to retry, so the exhausted-attempts path — the only message
  a human ever reads — raised before the body was read. Both branches were individually tested and
  correct. Tests assert that a structure behaves, never whether it should exist in that order.
- **The guide documented a run that cannot happen.** It called the quota "per minute" and put a
  cold index at "roughly half an hour", true only of the bucket the pacing already handles. The
  free-tier cold start is two sittings. Written from the design rather than from a measurement,
  and no cold start had been completed when it was written.
- **The credential slot is still not durable, and this was visible from day one.** Retrieval works
  only from a shell holding an `export`. Every consumer that matters — launchd Hermes, the
  webhook, any agent shell — is non-interactive, and `gemini-cli-api-key` is ACL-gated on
  interaction, so widening it for an interactive terminal does not close the gap. The Vault copy
  was designed, documented and never written; the release ships with retrieval unusable by any
  agent.
- **A corpus count was stale in three places** (1,704 vs 1,705) because it was written as prose
  rather than derived. Small, but it is the kind of number a reader trusts.

## Process Rules Added

| Rule | Where | Why |
|---|---|---|
| A failure message must name the cause, not just the status, when two causes have opposite remedies | this retro; applied in `_error_detail` | four failures this release shared exactly this shape |
| A spent quota is `paused`, not `unavailable` | `scripts/index-docs.py` | "unavailable" invites lowering the pacing, which spends the next day's allowance |
| Do not lower `EMBED_MIN_INTERVAL` or add retries to defeat a daily cap | `docs/guides/vector-store.md` | retries against a standing limit burn tomorrow's quota and hide the stop |
| Do not set a similarity score threshold on current evidence | memory-bank; v1.40.0 eval | the observed band spanned 0.021 and any cutoff in it discards the correct document |

## Decisions Made

- **Exactly one keychain slot holds the embeddings key, plus one Vault copy.** The guide previously
  told the operator to create `k3dm-embeddings-api-key` holding a copy of what the Gemini CLI item
  already held — two items on one machine sharing a lock state and a failure domain, doubling what
  rotation must touch while surviving nothing the original would not. The resolution order is a
  *preference* order, not a set of copies to keep in sync. The Vault copy is worth having precisely
  because it is a different failure domain (locked keychain, launchd with no session, another host).
- **The vector store is a rebuildable cache, not a system of record.** Local-path storage, no
  durability guarantee; losing it costs one re-index. This is what makes the whole component cheap
  to reason about, and it is why the index-age sensor matters more than backups.
- **Retrieval quality stays labelled UNMEASURED until the v1.40.0 eval.** The first real query gave
  the first datapoint and it points at ranking rather than recall: the document holding the correct
  cause ranked 4th of 5, inside a score band of 0.785–0.764.
- **`EMBED_BATCH` sizes the commit chunk, not an API call.** There is no batch endpoint to use —
  `batchEmbedContents` was withdrawn and now answers 404.

## Theme

This release gives the dedup check a memory. The exact-slug glob could only ever match a name
someone had already guessed right, which is why the same ESO defect got refiled under a name it
could not match, and similarity search over the docs corpus closes that gap. But most of the
release's work went somewhere else: into making four failures explain themselves. A withdrawn
endpoint that looked like a bad credential, a rate limit that looked like an outage, a spent daily
allowance that looked like a broken store, and a mid-run read that looked identical whether the run
was alive or dead — each was a message that collapsed two causes with opposite remedies, and each
cost real time to tell apart by hand. The fixes are small; the lesson is that a diagnostic is a
product surface, and that ordering matters as much as content, because the message a human actually
reads is the one on the path that gives up. The release ends one step short of done: the store is
full, the sensor is green, the first ranked query returned, and the credential that makes retrieval
work still lives only in the operator's shell.
