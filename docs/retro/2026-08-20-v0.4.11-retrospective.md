# Retrospective — v0.4.11

**Date:** 2026-08-20
**Milestone:** js-yaml security bump (CVE-2026-59870, dev-only transitive)
**PR:** #42 — merged to main (`b92f494`, squash); release stamp `0b574b1`; tag `v0.4.11`
**Participants:** Claude, Copilot

## What Went Well

- **A routine subtree sync surfaced a real security alert.** Pulling v0.4.10 down into
  k3d-manager put the vendored ACG lockfile in front of the consumer's Dependabot, which flagged
  `js-yaml` CVE-2026-59870 (alert #6). The alert only exists on the consumer because lib-foundation
  itself has Dependabot alerts disabled — the subtree is what gives the code any alerting at all.
- **The authoritative advisory field beat the summary text.** The advisory summary said "fix not
  backported," which would have implied a painful major-version bump or an `overrides` shim. The
  structured `first_patched_version: 3.15.1` field told the real story: a patch release inside the
  existing `^3.13.1` range. Reading the structured data instead of the prose turned a scary-looking
  HIGH into a one-line lockfile bump.
- **Upstream-first discipline held.** The alert path was the vendored copy
  (`scripts/lib/foundation/scripts/lib/acg/package-lock.json`), but the fix went to the lib-foundation
  source and flowed down via subtree pull — not a direct edit of the vendored tree.
- **Full PR gate was honored for a trivial change.** Even a 3-line lockfile bump went through
  CI (shellcheck/bats/acg) + Copilot review + thread resolution before merge. Copilot caught a
  genuine doc-staleness nit (the issue note's "Installed: 3.15.0" reading as current post-merge),
  which was fixed and resolved.

## What Went Wrong

- **Nothing material.** The one process friction was that Copilot's review did not auto-attach the
  instant the PR opened — it landed a few minutes later, so the initial gate check showed no review.
  Waiting for it (rather than merging on a green-CI-only signal) was the correct call.

## Process Rules Added

| Rule | File | Note |
|------|------|------|
| (reinforcement, no file change) | — | Trust the advisory's structured `first_patched_version` over the prose summary when deciding whether a fix is in-range. The two disagreed here; the structured field was right. |

## Decisions Made

- **Dev-only transitive vulns still get fixed, not dismissed, when an in-range patch exists.** Even
  though `js-yaml` here only parses trusted istanbul coverage config (no untrusted-YAML surface), a
  clean in-range bump was available, so the bump is strictly cheaper and lower-risk than filing a
  dismissal. Dismissal is reserved for cases where no safe fix exists.
- **Security bumps to the vendored ACG lockfile are lib-foundation releases**, tagged and flowed down
  via subtree pull — reaffirming that the consumer's Dependabot alert is a lib-foundation signal in
  disguise.

## Theme

A changelog-only subtree sync quietly did the most useful thing in the milestone: it handed the
vendored ACG lockfile to k3d-manager's Dependabot, which flagged a HIGH `js-yaml` CVE that the source
repo — with its own alerts disabled — never would have seen. The advisory's prose made it look
un-fixable ("not backported"), but the structured patched-version field revealed a clean in-range
patch. One lockfile line, released upstream as v0.4.11, then pulled back down, closes the alert — with
the whole change still passing CI and a Copilot review that caught a doc nit along the way.
