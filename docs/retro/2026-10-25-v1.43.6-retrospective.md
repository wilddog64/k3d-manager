# Retrospective — v1.43.6

**Date:** 2026-10-25
**Milestone:** Per-agent dispatch data
**PR:** #149 — merged to main (`61256041`)
**Participants:** Claude, Codex (Luna), Gemini (agy), Copilot

## What Went Well

- The dispatcher now records agy (Gemini 4 Argon) alongside Codex, so per-agent cost and quota
  efficiency come from one ledger instead of separate guesses.
- Splitting Agent Dispatch into Dispatch, Cost and Activity kept every panel. The pre-split
  fixture test proved each panel kept its queries, field config and options through the move.
- Copilot raised one finding (an H1 heading in the dispatch how-to), fixed in one commit.
- The operator's screenshots caught readability defects that offline tests could not: truncated
  Agent Activity titles and bar labels, and an unreadable Per run evidence table. The first is
  fixed in v1.43.6; the second is parked to v1.43.7.
- The appsets reapply and `make platform-ops` ran from the release branch before the merge. That
  was valid: the values ref tracks the release branch, and the checkout matched the PR head.

## What Went Wrong

- Three CI reds were each hidden behind the previous one, because the lint job stops at the first
  failing step:
  - `bats_negation_lint`: a bare `! grep` line;
  - pytest: the Bug Tracking query fixture was pinned to v1.43.5 after the dashboard default moved
    to v1.43.6, and v1.43.9 was missing from `docs/release-milestones.json`;
  - ruff F541: 19 extraneous `f` prefixes from `8cf6ee5f`.
- Ruff is not installed locally, so the F541 failure surfaced only in CI. A throwaway venv with
  `ruff==0.15.8` reproduced it in seconds.
- A memory-bank push made after disabling `enforce_admins` restarted the ~15-minute CI run.
- The `_agent_audit` hook reads a rewritten assert as a removed one. The F541 cleanup needed its
  `allow assert-removed` marker.
- Hub kine compaction stalled again on 2026-10-24. Recorded as a recurrence; the remedy is the
  10-29 rebuild, not a restart.

## Process Rules Added

| Rule | Where |
|---|---|
| Hold memory-bank and doc pushes while a PR's CI run is in flight; commit locally and push once it is green | session practice (this retro) |
| Run ruff 0.15.8 locally (throwaway venv) before pushing Python test changes | session practice (this retro) |
| Dashboard fixtures derive the release from the dashboard default, never a literal | `scripts/tests/bin/test_dashboard_queries.py` |

## Decisions Made

- The Agent Dispatch run-evidence fix (horizontal Run outcomes, one joined row per attempt with
  Codex tokens, slug links to the spec) ships in v1.43.7, not v1.43.6, so the release did not take
  another CI cycle.
- Kine: no restart; rebuild on 2026-10-29; recheck the `state.db` size on 2026-10-25.

## Theme

v1.43.6 made agent cost a per-agent fact: Codex and agy runs land in one ledger, verified
deliveries carry their token cost, and the dashboards were split so each question has its own page.
The release itself was slowed by small, serial CI failures that local tooling could have caught,
and by pushes that restarted CI mid-run. The lesson is the same in both cases: run the full lint
locally, and leave a green-pending run alone.
