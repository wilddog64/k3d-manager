# Retrospective — v1.45.1

**Date:** 2026-11-25
**Milestone:** v1.45.1 — security and DR bug-fix release
**PR:** #165 — merged to main (19d396ed)
**Participants:** Claude, Codex (Luna/Flash), Argon, operator

## What Went Well

- The release stayed inside its bug-fix scope: every fix came from `docs/bugs/` with a Branch line naming `k3d-manager-v1.45.1`, and no feature work entered the release.
- Live verification was done on real hosts before close. The DR drill, istioctl pin, TOTP enrolment, chmod and ArgoCD alert fixes were checked against live runs (see the LIVE-VERIFIED entries in the CHANGELOG `[1.45.1]` section).
- The V4 defect 1 fix was proven live: drill `20261125T173312Z` on m2 ran V0–V9 to a report with all checks true (RTO 644 s).
- Argon's blind review of PR #165 returned no high or medium findings. Its two low findings were triaged without code change: one was refuted by reading the line (the pipeline left side runs in a subshell), one was real but unreachable in production (`docs/issues/2026-11-25-argon-pr165-review-findings.md`).
- The ledger shows acceptance verification by an independent verifier for most landed tasks (`verify` events with `result: pass`).

## What Went Wrong

- 6 LANDED fixes were missed by a Branch-line filter and caught at create-pr pre-flight. (Stated in the post-merge brief; the listed sources do not record it.)
- Claude gave a promote command before CI finished. (Stated in the post-merge brief; the listed sources do not record it.) Now a standing rule.
- Land refusals were frequent: 18 `land_refused` events in v1.45.1 (10 `target_diverged` or `target_moved_during_land`, 5 `scope`, 3 `fast-gate`), so landing kept stalling on the target branch moving under a dispatch.
- Dispatch-side verification gaps: several landed tasks have no `verify` event in the ledger (see Dispatch Review), and the CVE-pin branch fix (`cve-pins-branch-trusted-without-verification`) has a `target_diverged` refusal with no verify event.
- The memory-bank files grew large (activeContext.md about 50 KB, progress.md about 44 KB) during the release, which made handoffs slower to read.

## Process Rules Added

- A pipeline's left-hand side runs in a subshell, the same as `$(...)`. Review specs should say so next to any `[ a ] && [ b ]` check, so a failure path that exits 0 is caught at spec time (Argon process note, 2026-11-25).
- Standing rule: no promote command until CI is finished and green on the head SHA. (From the post-merge brief; the rule is recorded there, not in the listed sources.)

## Decisions Made

- Operator waived V4 defect 2 live E4 (the V4-false path). Offline proof accepted. Drill failure-path hook filed in `docs/ideas.md` (2026-11-25 row, inbox).
- Operator accepted the token-bug (`app-cluster-token-in-kubectl-argv`) verify half on offline proof, after the E9 scan half passed live and the verify half could not be exercised (6 events all applied).
- Gate recovery-paste fix (`2026-11-25-console-gate-recovery-code-paste-and-lookalikes-rejected-silently`) was dispatched to Flash after Fable review, filed P2 and triaged into v1.45.1 on operator instruction.
- `enforce_admins` on main was deleted for the v1.45.0 merge at operator request and restored after v1.45.1 (per post-merge state).
