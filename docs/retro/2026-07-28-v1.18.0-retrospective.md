# Retrospective — v1.18.0

**Date:** 2026-07-28

**Milestone:** First-mile CVE gap closure (event-driven Trivy→webhook→app-cve-scan auto-patch + Dependabot on 5 shopping-cart repos)

**PR:** #108 — merged to main (85742ef7)

**Participants:** Claude, Codex, Gemini, Copilot

## What Went Well

- **Event-driven CVE auto-patch fully realized.** Trivy vulnerability alert now fires the k3dm webhook → re-runs app-cve-scan → updates the running workload. The detect→patch loop is closed without manual intervention.
- **Dependabot enabled across all 5 shopping-cart repos on day one.** Scope stayed tight (exactly one `.github/dependabot.yml` per repo), ecosystem matching was precise (gomod/npm/maven/maven/pip), and all initial PRs merged without errors.
- **Webhook token disaster recovery baked into cluster-rebuild bootstrap.** The macOS Keychain→Secret sync eliminates the silent-failure trap where `k3dm-webhook-token` absence caused Alertmanager to reject the entire configuration.
- **Values-branch drift now observable at a glance.** `make status` reports ApplicationSet frozen-to-stale-branch cases that previously went unnoticed (the hub `grafana-dashboards-hub` appset was silently inert on v1.16.0 for days).
- **Platform-ops (CVE scan, dashboards, webhook token) now survives cluster rebuild.** Folding it into the ArgoCD bootstrap path prevents the entire alert pipeline from silently vanishing on a cold rebuild.
- **Hub Grafana dashboard for CVE auto-patch loop observability.** Real-time visibility into Trivy alerts, remediation outcomes, and per-namespace vulnerability counts.
- **lib-foundation v0.4.8 cleared the brace-expansion transitive DoS advisory.** Security debt reduced at the library layer.

## What Went Wrong

- **GitGuardian App check vs .gitguardian.yaml config confusion.** The GitGuardian **App** reads workspace incident status (GitHub → Pluralsight service account → GitGuardian dashboard), not the `.gitguardian.yaml` file in the repo. Resolving the incident in the App was necessary; `.gitguardian.yaml` alone does NOT clear PR checks. This distinction cost diagnosis time during PR review.
- **Values-branch-freezing trap stayed silent for too long.** The hub `grafana-dashboards-hub` ApplicationSet was targeting `k3d-manager-v1.16.0` while the real changes landed on v1.18.0. ArgoCD rendered stale manifests, but selfHeal + prune meant manual edits reverted immediately and no drift alarm existed. Now formalized: **ApplicationSets must be reapplied on every release** so the `${K3D_MANAGER_BRANCH}` template variable points to the current release, not a stale past branch.
- **AlertmanagerConfig CRD syntax initially written in plain Alertmanager dialect.** The spec called for structured matchers and dual child routes, but the implementation used plain YAML until live-verify caught it. `yaml.safe_load` does not catch CRD dialect mismatches — only Kubernetes apply does. Added a durable gate: AlertmanagerConfig must be validated against the `monitoring.coreos.com/v1alpha1` CRD schema, not just YAML parse.
- **k3dm-webhook-token Secret missing on every fresh rebuild.** Platform-ops namespace was absent because the ClusterOps bootstrap path only auto-runs once; subsequent rebuilds skipped it. The Secret absence silently caused Alertmanager to reject the entire AlertmanagerConfig, with no operator-visible error. The secret was manually recreated post-diagnosis and DR was implemented, but the gap existed for 2+ days.
- **Phantom "Go CI" required check on shopping-cart repos prevented normal merges.** The check was never emitted by any workflow, so every merge required `enforce_admins` bypass. Initial confusion about the scope of the fix (real checks vs just removing the phantom) delayed the permanent solution slightly.

## Process Rules Added

- **Reapply ApplicationSets on every release.** The `${K3D_MANAGER_BRANCH}` template variable freezes to whatever branch was checked out when the set was last applied. Config committed to a newer branch is inert until the sets are reapplied. Decision: the values ref tracks the **release branch**, not `main` — this is a required release step.
- **AlertmanagerConfig CRD dialect validation.** Plain YAML parse is insufficient; new AlertmanagerConfigs must be validated against the Prometheus Operator CRD schema (structured matchers, camelCase timings, nested `route.routes[]`).
- **Platform-ops fold-into-bootstrap non-negotiable.** CVE scan + dashboards + webhook-token sync must be part of the ArgoCD bootstrap path so they survive a cold rebuild.
- **values-branch drift must be visible.** Integrate the drift detector into status checks (now live in make status) so a set targeting a stale branch is immediately obvious instead of silently rendering old manifests.

## Decisions Made

- **shopping-cart Dependabot settings finalized for permanent operation:**
  - `required_approving_review_count: 0` (solo maintainer cannot self-approve; user owns this decision).
  - Real PR check contexts replace the phantom "Go CI" (verified per-repo on main first).
  - Auto-merge for semver-minor/patch + security CVEs; majors left for review.
  - All three require `enforce_admins=true` during normal operation.
- **webhook-token disaster recovery path is Keychain-backed.** On every platform-ops deploy, the Secret auto-syncs from macOS Keychain (`k3dm-webhook-token`/`k3dm` → `cicd/k3dm-webhook-token`). Extension generalized to support other secrets (app-rebuild gh-token follows the same pattern).
- **values-branch-tracking is release-branch-pinned, not main-tracking.** The ApplicationSet `${K3D_MANAGER_BRANCH}` references the release branch (e.g., `k3d-manager-v1.18.0`), not main. This is critical for multi-release state (hub on v1.18.0, ACG spoke on v1.16.0, each tracking their own branch's config).

## Theme

**First-mile CVE gap closure.** A Trivy vulnerability report on a running app now drives an automatic patch end-to-end: the alert fires the webhook → re-runs app-cve-scan → the app updates. For CVEs Trivy can't rebuild (e.g., transitive dependency bumps), Dependabot is enabled on all five shopping-cart repos so dependency CVEs self-heal into PRs. The entire loop — detect, alert, remediate, update — is now observable on the hub Grafana dashboard and durable across cluster rebuilds.
