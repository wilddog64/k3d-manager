# Retrospective — v1.16.0

**Date:** 2026-07-23  
**Milestone:** v1.16.0 — ambient mesh app-tier + multi-cluster hardening  
**PR:** #106 — merged to main (`4c5d3556`)  
**Participants:** Claude, Codex, Gemini, Copilot

## Theme

Migrate the hostinger shopping-cart workloads from sidecar injection to Istio **ambient** (ztunnel + istio-cni, HBONE/mTLS with zero sidecar containers). Make the ambient path durable across `make refresh` and cold `k3s-aws` rebuilds. Harden multi-cluster ArgoCD so a second app cluster no longer clobbers the first. Right-size control-plane/observability CPU for the 2-CPU hostinger node. Ship lib-foundation **v0.4.7** via subtree.

## What Went Well

- **Ambient dataplane end-to-end proof:** `frontend → basket-service` traffic rode HBONE on `:15008` with mutual SPIFFE identities both directions. All 3 running `shopping-cart-apps` workloads showed `protocol: HBONE` while `shopping-cart-data` and `shopping-cart-payment` stayed `TCP` — exact in-scope/out-of-scope split as designed.
- **Multi-cluster ArgoCD hardening landed:** ArgoCD appsets now derive `APP_CLUSTER_NAME` from the active cluster instead of hardcoded hostinger; `services-git` Application names are keyed by cluster, so a second app cluster no longer collides with the first.
- **lib-foundation subtree integration smooth:** v0.4.7 merged upstream, contains `acg_restart` orphaned-sandbox recovery and `_acg_sweep_stale_artifacts` tmp hygiene. Subtree pull into k3d-manager was conflict-free; CLAUDE-verified byte-identical vendored state.
- **Speculative bug discovery (non-blocking):** A live-fix session on hub Grafana exposed that argocd ServiceMonitors and Image Updater were never deployed. Round 1 + Round 2 specs and fixes landed cleanly; hub now self-heals both components during bootstrap.
- **Copilot review findings addressed:** All PR #106 Copilot comments (set-e loop safety, trap hygiene, wget token config, CI test coverage) were fixed before merge.

## What Went Wrong

- **Spec scope creep (ambient-cni-vars):** The istio-ambient appset specification understated the failure mode. Unset `AMBIENT_CNI_CONF_DIR`/`AMBIENT_CNI_BIN_DIR` caused the bootstrap to **abort** (not silently continue), dropping 5 subsequent appsets including `services-git` — the very workload the appset was supposed to deploy. Blast radius was mid-bootstrap collateral, and the failure was not scoped in the original spec's Problem section. Tightened the language in the appended fix spec.
- **Stale code trap (argocd-image-updater):** `_argocd_configure_post_deploy` was dead code (zero callers) and never executed, so Image Updater was never deployed. Round 1 misdiagnosed the reason (spec said "bootstrap branch not exercised") — the actual root cause was the containing function is orphaned. Round 2 fixed by moving the real call into `deploy_argocd_bootstrap`'s live path. Future audit needed on the now-orphaned post-deploy function.
- **CPU pressure narrative failure:** The original spec asserted sidecar injection was the cause of hostinger's CPU pressure. Post-sidecar removal, requests climbed 1910m → 1960m (UP, not down). Real capacity constraint is non-app workloads (trivy-server, observability, control plane). Sidecar removal was correct for the ambient mesh but did not solve the CPU oversubscription. Spec narrative was incorrect; blocked future CPU-right-sizing work being based on a false root cause.
- **CNI paths divergence (substrate-aware fix required):** Fresh k3s+flannel uses `/var/lib/rancher/k3s/agent/etc/cni/net.d` and `/var/lib/rancher/k3s/data/cni`, but the hardcoded Cilium defaults in istio-cni broke istio-cni pod startup. Required a CNI-substrate-aware appset parameterization. The regression happened because istio_ambient.sh defaulted to Cilium paths without checking the actual CNI provider.

## Process Rules Added

- **Spec language precision:** Problem statements must name exact failure modes (abort, silent drop, wrong output) not vague descriptions. Root-cause analysis is mandatory before writing fix specs.
- **Non-blocking vs. blocking bugs:** Live-fix sessions may surface unrelated bugs. These must have their own specs and not be bundled into the main release narrative. The hub Grafana argocd ServiceMonitor + Image Updater issue was non-blocking (hub stayed operationally healthy) but needed two rounds of refinement.
- **Dead-code audits are expensive:** A single orphaned function triggered two rounds of spec rewrites. Future refactors must include a pass for callers via `grep -rn` to prevent orphaned code from hiding bugs.
- **CPU measurements are ground truth:** Narrative claims about resource pressure must be backed by live `kubectl top node` and request summation, not assumptions. The "sidecars caused CPU starvation" story persisted for 3+ days until measured.

## Decisions Made

- **Ambient enrollment is app-tier only (v1.16.0):** `shopping-cart-apps` namespace is marked `istio.io/dataplane-mode: ambient` and deployed sidecar-free. Data-layer and payment namespaces remain sidecar-injected; they will graduate in a future release (`v2.0.0-ambient-only-retire-sidecar` spec).
- **k3s-aws cold-rebuild hardening:** All `(( var++ ))` post-increment wait loops were replaced with assignment form so `set -e` does not abort. `k3sup --k3s-version` pinned so provisioning survives `update.k3s.io` channel outages. `K3S_AMBIENT_MESH=true` defaulted in the up flow so Cilium installs for ambient.
- **Hostinger Trivy CPU right-sizing:** Trivy server memory request trimmed `200m` → `50m` on both hub and app-cluster observability values so `product-catalog` can schedule. `istiod` and `ztunnel` CPU requests right-sized for 2-CPU node.
- **Multi-cluster AppProject registration:** shopping-cart `AppProject` now permits all 4 clusters as `destinations`. `services-git` Application names are cluster-keyed via `${APP_CLUSTER_NAME}` so appsets no longer collide.
- **Hub ArgoCD durability (Round 2 durable fix):** argocd ServiceMonitors and Image Updater are now deployed live from git during `deploy_argocd_bootstrap`, not as a manual live-only fix. Bootstrap now handles both CRD-guarded SM creation and image-updater deployment in one atomic apply.

## Known Outstanding Items

- **`_argocd_configure_post_deploy` is orphaned:** Still contains Istio VirtualService creation + Vault/ESO configuration logic that never runs. Needs a separate audit: wire back in or delete.
- **Hostinger `istio-ambient` appset is single-cluster:** Only one cluster can hold ambient at a time (design limit). When re-applied for hostinger, it re-points off `ubuntu-k3s`. Needs a multi-cluster generator design for v1.17.0+.
- **`make status` blind to mesh/CNI health:** `cluster-status` was BLIND to istio/cilium/ztunnel/ambient state, so the mesh sat broken ~3 days unnoticed. Fixed in `da67e2bf` (mesh section added) but does not yet verify service login (Keycloak token freshness).
- **OCI k3s provider has leaky `envsubst` allowlist:** `k3s-oci.sh:678-683` globs every appset through `envsubst '$ARGOCD_NAMESPACE'` (one var) against files with five placeholders. Pre-existing, not a regression, but needs scoping.
