## What Went Well

- **Parallel multi-cloud Phase 1–3b shipped** — provider-scoped state (`_ACG_STATE_DIR`), flat-state one-time migration, active-provider set tracking (`active-providers/` marker-dir), hub-bootstrap lock (prevents concurrent double-create), per-app-cluster Prometheus port offset, kubeconfig-merge lock, and `require-unambiguous-provider` gate. 14/14 + 20/20 + 23/23 BATS tests added; all offline-verifiable scopes complete.

- **Public-endpoint probe (`bin/public-endpoint-probe`)** — read-only, K-of-K reachability sampling, edge-down vs single-service discrimination via exit codes. `make status-public` target wired. shellcheck-clean, all verdict paths verified via stubbed curl.

- **lib-foundation v0.4.14 subtree sync** — ACG Playwright robust-click fix pulled and merged cleanly; subtree untouched.

- **LDAP–Jenkins separation** — Jenkins LDAP fixtures pruned from `home.org` seed; AD-schema fixtures retained (load-bearing for `dirservices_activedirectory.bats` regression coverage). LDAP↔SSO decoupling surfaced as a separate follow-up.

- **ArgoCD monitoring-namespace guard** — CRD existence check added; Copilot caught the missing namespace-level guard before merge, preventing silent inert apply on rebuild.

- **Clean release sequence** — all three v1.28.0 specs written, offline CI green, one pre-PR BATS gate issue (test-only, fixed), PR merged with Copilot review resolved, branch protection restored, tag and release published, next branch created.

## What Went Wrong

- **LDAP↔SSO coupling discovery (late)** — during live v1.28.0 ops, found that Keycloak federates `osixia/openldap` image (community, dynamically provisioned) NOT the seeded `openldap` (bitnami chart). Fixtures created for seeded LDAP are inert in this config. Decision on whether to re-home the fixture to osixia or uncouple SSO remains OPEN (see Decisions below).

- **ArgoCD CRD guard incomplete initially** — first implementation guarded only the CRD, not the monitoring namespace. Copilot found it; fix landed before merge, but review catch-and-fix process ate review latency.

- **Hub CPU overcommit not durably fixed** — temporary `make monitoring-pause` applied mid-release but resume blocked on other fixes. Structural CPU issue remains: single-node hub over-capacity for multi-replica workloads. Deferred to hardware upgrade (Mac Mini M5).

## Decisions Made

1. **LDAP↔SSO decoupling — DECISION DEFERRED**
   - Issue: seeded `openldap` pod fixtures are inert; Keycloak federates the osixia image instead.
   - Options: (A) re-home fixtures to osixia config, (B) uncouple SSO from LDAP in Keycloak, (C) purge seeded LDAP, federate osixia only.
   - Follow-up doc: `docs/issues/2026-09-04-keycloak-federates-osixia-ldap-not-seeded-openldap.md`
   - Carries forward to v1.29.0 (or later if deprioritized).

2. **Zero-downtime rollouts QUEUED until Mac Mini M5 (October 2026)**
   - Root cause: M4 Air 24GB hub has zero CPU headroom for 2+ replicas of stateless tier.
   - Spec remains in git (`docs/plans/v1.28.0-platform-zero-downtime-rollouts.md`), marked hardware-gated.
   - v1.28.0 ships only the two deliverables that fit on current hardware.

3. **Jenkins LDAP fixtures — KEEP code, mark DEPRECATED**
   - Jenkins feature is unused (disabled by default, not deployed).
   - Decision: code retained for reference, marked DEPRECATED in docs; do NOT remove until Jenkins is fully decommissioned.
   - AD-schema fixtures kept (load-bearing for test coverage).

## Theme

v1.28.0 enables **concurrent multi-cloud provisioning from a single git repository** — the parallel-multi-cloud work frees `cluster-up/down/refresh` to operate on any of N active cloud providers (k3s-aws, k3s-hostinger) without state corruption or port conflicts. Alongside this, **Hermes Phase-1's public-endpoint probe** provides the sensor infrastructure for the hub's future autonomous ops layer, able to detect edge-down vs service-down conditions. Together, these lay the foundation for the roadmap's kops-for-k3s multi-site provisioning and automated resilience. The human-facing release is smaller than initially scoped (zero-downtime deferred to hardware), but the architectural shape — multi-provider state isolation + honest status probing — is clean and ready for scale.
