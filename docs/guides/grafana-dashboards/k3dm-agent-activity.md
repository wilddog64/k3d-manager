# k3dm Agent Activity (`k3dm-agent-activity`) — hub

[← Grafana dashboards index](../grafana-dashboards.md)

The **Agent Activity** dashboard contains Claude context and compaction panels, all Codex session activity, quota readings and efficiency, and agy activity. Its **Window** selector offers `1d`, `7d`, and `30d` only. Use the **Agents** link to switch between Agent Dispatch, Agent Cost, and Agent Activity while retaining the time range and window. Bar gauges on this dashboard are horizontal with fixed font sizes. In the half-width panels (Compactions by trigger, Context incidents) each series name sits left of its bar; in the quarter-width panels (Untracked by repo, Sessions by mode, Tokens by repo and the agy gauges) it sits above the bar, so a long repo name such as `shopping-cart-frontend` reads in full. **Untracked by repo** and **Tokens by repo** show the eight largest repos and fold the rest into one `other` bar, so names stay readable.

The **All Codex activity** row counts every Codex session file on this machine, including sessions outside the dispatcher. Dispatch worktree sessions count under the repo they were dispatched for; `other` means names outside the 30-day top 10 plus sessions with no usable working directory. **Codex at API prices, all sessions** totals priced sessions only; **Unpriced Codex sessions** shows sessions excluded because their model has no published rate or usage counts are missing. `mode` is `exec` for headless `codex exec`, `interactive` for the Codex TUI, and `other` for any other originator; other validated working-directory names are folded into `other` after the ten busiest repositories. Untracked means detected sessions minus sessions associated with a dispatch record, matched by session id. A session from before plan 4's `usage-backfill` ran reads as untracked until that backfill runs. Quota panels show Codex's own limits as of the newest session sample; they are not live readings. Claude's weekly limit is not recorded in a local file and is not shown. Quota efficiency is reported only when timestamped observations and independently verified delivery events cover an interval within the same reported reset cycle; otherwise the readings and coverage status remain unavailable. Its quota denominator is global Codex use, including interactive and untracked sessions, and is not attributable solely to dispatched workers. The agy activity panels report the host named by **agy data source**. When that host has an agy brain directory, they count its local interactive and print transcript sessions; otherwise they use its local wrapper ledger. Hosts are not combined, and `mode` and `repo` are `unknown` for transcript sessions because agy transcripts do not include those fields. A `none` source warns that this host has neither source; panels show No data when a selected window has no sessions, rather than showing zero. The wrapper remains useful for dispatch linkage, but it is not required for transcript collection. Token totals include only parseable token fields. Interactive sessions may have no token fields, so token data can be absent while session counts remain visible. The activity rows sit below **Claude context and compaction** and use the time-window selector.

The **Claude context and compaction** row measures what context compaction costs Claude per verified spec. A "verified spec" is a `docs/bugs` or `docs/plans` document newly created with a closed `**Status:**` or transitioned from an open status to a closed status in a commit within the window. Backfilled status lines and closed-to-closed edits do not count. Counts carry one of three levels: `live` (`LIVE-VERIFIED`), `verified` (`VERIFIED`, `FIXED`, or `Fixed on/in`), and `unverified` (every other closed status). **Claude cost per verified spec** divides Claude API-equivalent cost (not subscription usage) by the all-level count; **Claude cost per live-verified resolution** divides it by the `live` count. Both show "No data" when their denominator is zero. Release branches are squash-merged, so closures within a release branch are dated to the squash-merge commit and can bunch into one window. **Compactions per verified spec** divides total `compact_boundary` events in the window by all-level verified specs, **Compactions by trigger** splits those compactions by `auto` or `manual` trigger, and **Re-read share after compaction** shows the share of file reads in the window that first re-read a file after a compaction boundary in the same session. File reads include the `Read` tool and Bash commands that only read files (for example `cat`, `sed -n`, `rg`); commands that write, such as `>>` or `sed -i`, are not counted. **Wasted re-read share** counts only re-reads whose content is identical to the pre-compaction read; a re-read after the file changed is needed and is not counted as waste. **Context incidents** splits `resumption-failure` and `missing-context-correction` counts by kind, **Auto-compact setting (configured)** shows the latest non-future `auto_compact_tokens` setting, which is ignored when it exceeds the session context window, and **Observed compaction point** shows the mean context size at automatic compactions in the window (transcript `compactMetadata.preTokens`), the threshold that actually applied; the incident panels are only as complete as the hand tally in [context-window-experiment.md](../../metrics/context-window-experiment.md).
