# k3dm Agent Activity (`k3dm-agent-activity`) — hub

[← Grafana dashboards index](../grafana-dashboards.md)

The **Agent Activity** dashboard contains Claude context and compaction panels, all Codex session activity, quota readings and efficiency, and agy activity. Its **Window** selector offers `1d`, `7d`, and `30d` only. Use the **Agents** link to switch between Agent Dispatch, Agent Cost, and Agent Activity while retaining the time range and window. Bar gauges on this dashboard are horizontal with fixed font sizes. In the half-width panels (Compactions by trigger, Context incidents) each series name sits left of its bar; in the quarter-width panels (Untracked by repo, Sessions by mode, Tokens by repo and the agy gauges) it sits above the bar, so a long repo name such as `shopping-cart-frontend` reads in full.

The **All Codex activity** row counts every Codex session file on this machine, including sessions outside the dispatcher. Dispatch worktree sessions count under the repo they were dispatched for; `other` means names outside the 30-day top 10 plus sessions with no usable working directory. **Codex at API prices, all sessions** totals priced sessions only; **Unpriced Codex sessions** shows sessions excluded because their model has no published rate or usage counts are missing. `mode` is `exec` for headless `codex exec`, `interactive` for the Codex TUI, and `other` for any other originator; other validated working-directory names are folded into `other` after the ten busiest repositories. Untracked means detected sessions minus sessions associated with a dispatch record, matched by session id. A session from before plan 4's `usage-backfill` ran reads as untracked until that backfill runs. Quota panels show Codex's own limits as of the newest session sample; they are not live readings. Claude's weekly limit is not recorded in a local file and is not shown. Quota efficiency is reported only when timestamped observations and independently verified delivery events cover an interval within the same reported reset cycle; otherwise the readings and coverage status remain unavailable. Its quota denominator is global Codex use, including interactive and untracked sessions, and is not attributable solely to dispatched workers. The **All agy activity** row counts only runs made through the local `agy` wrapper; `mode` and `repo` follow the same meanings, and interactive runs never carry usage. The activity rows sit below **Claude context and compaction** and use the time-window selector.

The **Claude context and compaction** row measures what context compaction costs Claude per verified spec. **Claude cost per verified spec** divides the time window's Claude cost at API list prices (not subscription usage) by `k3dm_claude_verified_specs`, where a "verified spec" is a `docs/bugs` or `docs/plans` document whose `**Status:**` line moved to a closed state in a commit within the window (shows "No data" when the count is 0). **Compactions per verified spec** divides total `compact_boundary` events in the window by verified specs, **Compactions by trigger** splits those compactions by `auto` or `manual` trigger, and **Re-read share after compaction** shows the fraction of `Read` tool calls in the window that re-read a file already read before the latest compaction boundary in the same session. **Context incidents** splits `resumption-failure` and `missing-context-correction` counts by kind, and **Auto-compact threshold** shows the latest non-future `auto_compact_tokens` setting; the incident panels are only as complete as the hand tally in [context-window-experiment.md](../../metrics/context-window-experiment.md).
