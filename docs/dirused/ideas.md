# dirused ideas

dirused is tracked separately from k3d-manager (operator, 2026-11-15): its ideas live here, not in `docs/ideas.md`, and never enter a k3d-manager release. Interim location until dirused keeps its own records (see the multi-repo row in `docs/ideas.md`).

| Date | Idea | Source | Status |
|---|---|---|---|
| 2026-11-16 | **Elevated (Administrator) mode for purge.** Some files can only be deleted from an elevated process (ACLs granting delete to Administrators only, files under system or other users' folders). Operator: run "either specific /privilege or in gui prompt for admin user". Shape: a switch (e.g. `/elevate`) that relaunches dirused through the UAC prompt (`ShellExecute` verb `runas`) with the same arguments; the elevated child has its own console, so its output and exit code must come back through a temp file or pipe. No `requireAdministrator` manifest (every run, including read-only scans, would prompt). Notes: elevation does not delete a file another process has **open** (sharing violation even for admin), so purge should report "in use" and could offer delete-at-reboot (`MoveFileEx` `MOVEFILE_DELAY_UNTIL_REBOOT`, needs admin) or name the locking process (Restart Manager). Local UAC gives no rights on `\\node\C$`; remote purge needs an admin account on the target. Belongs with the purge milestone (parent plan `docs/plans/dirused-windows-disk-usage-tool.md`, M6). | operator + Claude, 2026-11-16 | inbox |
| 2026-11-16 | **On-host scanning / MFT reads.** Scan on the target itself (local NTFS, or reading the MFT the way WizTree does) instead of over SMB, for much faster fleet scans. Needs remote execution and admin on the target. Deferred from M1c, which first cuts SMB round trips (`docs/plans/dirused-m1c-summary-top-and-fast-scan.md` Part B). | operator + Claude, 2026-11-16 | inbox |
| 2026-11-17 | **Fast top-level default, `/deep <level>`, `/exact`, size after the path.** A bare `dirused \\node` or drive root (no `/summary`) walks the whole drive and prints the 50 largest directories and files anywhere, with `logical X  on disk Y` on every line; slow over SMB and hard to read. New default: the volume line, then one line per top-level directory, largest first, with its full-subtree size taken from the folder listing only (no per-file `CreateFile` / `GetFileInformationByHandle` / `GetCompressedFileSize`, today three extra SMB round trips per file in `src/Dirused.Core/Scanner.cs`). `/deep <level>`: directories down to that many levels (level 1 = the default), sizes always the full subtree, `/top N` still caps rows; replaces today's largest-anywhere report (a largest-files `/files` switch only if wanted later). `/exact`: today's on-disk sizes and hard-link dedup, at today's speed; shows a second column only where on-disk differs from logical by more than one cluster (compressed or sparse files). Text layout: path first, size after it, paths padded to the longest in the listing so sizes form one right-aligned column (two spaces instead of padding when a path is wider than the console); sizes du-style `28K`, `1.2M`, `3.4G` (binary units). JSON/CSV keep raw byte counts. Multi-target (`/file`, several targets, `\\node` over several shares): `/deep` and `/exact` apply to every target exactly as for one (proposed by Claude, operator unsure, confirm at spec time); with more than one target and no `/timeout`, one stderr line suggests `/timeout` and `/summary` for fleet checks, and the run proceeds. Breaking change to the bare default, so the README and `/help` text change with it; measure the speedup on the office fleet (before/after wall time on one `\\node`) before claiming a number. | operator, 2026-11-17: "instead of list all contents of a given drive, can we just list top level directories with the size (human readble 10k, 1m, 1G)", "can we put size after the path?", "yes, we can add /deep <level> and /exact but I am not sure if we want to have these to apply to multiple node from /file though" | inbox — spec next |
