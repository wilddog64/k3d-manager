## Root cause

- **197, 198, 1070.** `3b789adf` changed `_observability_wait_for_prometheusrule_crd` from
  `get crd` + `kubectl wait` to a jsonpath read that must print `True`. It also added
  `_observability_warn_if_prometheus_kind_unserved`, which reads `kubectl api-resources`. The
  existing stubs print nothing, so the wait never succeeds. In 197/198 it sleeps the real 36×5s
  first. Test 1070 also asserts the `kubectl wait` call that was deliberately removed. The Codex
  prompt for `3b789adf` named only three BATS files, so these suites were never run. That gap is
  Claude's.
- **972.** The test pins the number of self-clearing `RETURN` traps in `keycloak.sh` to exactly 2.
  `d5b986f4` added a third one, which is also correctly self-clearing. The count is the wrong
  invariant; the real one is "every `rm -rf "$wd"` RETURN trap is self-clearing", and the test's
  first assertion already checks that no old-style trap exists.
- **58.** Eight new bare `! cmd` lines. Under `set -e` a bare `!` never fails the test. This is a
  **third recurrence** of `2026-09-14-bats-bare-negation-assertions-never-fail.md`. It went unseen
  because `ci.yml` does not run on pushes to a release branch.

## Fix spec

### F1 — `scripts/tests/lib/observability.bats`, the `kubectl` stubs in tests 197 and 198 only

The stub at line 123 (test "deploy_observability_acg calls envsubst with …") and the one at line 201
(test "deploy_observability_acg falls back to generated Prometheus config …"). In each, replace

```bash
  kubectl() {
    printf "%s\n" "$*" >> "${KUBE_STUB_LOG}"
  }
```

with

```bash
  kubectl() {
    printf "%s\n" "$*" >> "${KUBE_STUB_LOG}"
    case "$*" in
      *"get crd prometheusrules.monitoring.coreos.com"*) printf 'True' ;;
      *"api-resources --api-group=monitoring.coreos.com"*) printf 'prometheuses.monitoring.coreos.com\n' ;;
    esac
  }
```

In both tests, directly before `run deploy_observability_acg`, add
`export K3DM_ACG_RULES_CRD_ATTEMPTS=1 K3DM_ACG_PROM_DISCOVERY_ATTEMPTS=1`. A future stub mismatch then
fails at once instead of sleeping for minutes. Do not touch the other `kubectl` stubs in this file.

### F2 — `scripts/tests/plugins/observability_k3dm_tests_rules.bats`, test "PrometheusRule CRD wait allows rules apply after delayed creation"

Replace the `_kubectl` stub's `get crd` branch

```bash
    if [[ "$*" == *"get crd"* ]]; then
      local gets
      gets=$(grep -c 'get crd' "${calls}" || true)

    fi
```

with

```bash

      return 0
    fi
```

and replace the assertion

```bash

```

with

```bash
  [ "$(grep -c 'wait.*crd/prometheusrules.monitoring.coreos.com' "${calls}" || true)" -eq 0 ]
```

Check that the next test, "PrometheusRule CRD wait skips apply when creation never completes", still
passes unchanged. Its stub never prints `True`, so it should.
