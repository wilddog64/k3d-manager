# Bugfix: v1.25.0 — wire Slack `/cluster-status` to the concise status contract

**Branch:** `k3d-manager-v1.25.0`
**Files:** `bin/k3dm-webhook` (+ optional `scripts/tests/lib/webhook.bats`)

---

## Problem

The v1.25.0 `make status` refactor (`docs/plans/v1.25.0-status-output-contract.md`) added concise
`--summary` and structured `--json` modes to `bin/cluster-status`, and the contract's **§Slack
integration** requires `/cluster-status` to consume that JSON/summary and render **only** a header,
error/warning lines, and compact health counts with **emoji severity** (`:x:` / `:warning:` /
`:white_check_mark:`) and **no ANSI codes**.

That Slack section was never implemented. `/cluster-status` on the hostinger provider routes to
`_run_hostinger_status`, which runs **bare** `bin/cluster-status` — now defaulting to `--full` — and
dumps the entire verbose, ANSI-prone report into a Slack ```` ``` ```` code block (then head/tail
truncates it). The reader gets a wall of text instead of the intended one-line severity summary.

**Root cause:** `_run_hostinger_status` predates the `--summary`/`--json` modes and was never updated;
`bin/cluster-status` with no flag defaults to `_status_mode=full`.

---

## Reproduction

```
Slack: /cluster-status        # (hostinger provider active)
→ 🖥️ *Hostinger app cluster status*
  ```<full multi-section report, ANSI-derived glyphs, truncated middle>```
```

Expected (per contract):
```
:white_check_mark: *Cluster status: HEALTHY* — `k3s-hostinger`  (12 ok / 1 warn / 0 fail)
:warning: pushgateway: connection refused (optional)
```

---

## Fix

Consume `bin/cluster-status --json` and render it with Slack emoji severity. The `--json` mode already
emits **no ANSI** and a stable schema:

```json
{"overall":"healthy|warn|fail|unknown","provider":"...","context":"...",
 "errors":[{"id","service","status":"error","message","http_code"?,"ready"?}],
 "warnings":[{...,"status":"warning"}],"checks":[...],
 "counts":{"services_failed":N,"services_warning":N,"services_healthy":N}}
```

### Change 1 — add a shared Slack formatter (insert immediately **before** `def _run_hostinger_status`)

```python
def _format_status_summary_slack(payload, provider):
    """Render bin/cluster-status --json as a concise, ANSI-free Slack message (contract §Slack)."""
    overall = str(payload.get("overall", "unknown"))
    emoji = {"healthy": ":white_check_mark:", "warn": ":warning:",
             "fail": ":x:", "unknown": ":grey_question:"}.get(overall, ":grey_question:")
    counts = payload.get("counts", {}) or {}
    header = f"{emoji} *Cluster status: {overall.upper()}* — `{provider}`"
    if counts:
        header += ("  ({} ok / {} warn / {} fail)".format(
            counts.get("services_healthy", 0),
            counts.get("services_warning", 0),
            counts.get("services_failed", 0)))
    out = [header]
    for item in payload.get("errors", []):
        out.append(":x: {}: {}".format(
            item.get("service") or item.get("id") or "?", str(item.get("message", ""))[:250]))
    for item in payload.get("warnings", []):
        out.append(":warning: {}: {}".format(
            item.get("service") or item.get("id") or "?", str(item.get("message", ""))[:250]))
    if overall == "unknown":
        out.append("_status source unavailable — run `make restart-webhook` on the hub_")
    return "\n".join(out)
```

### Change 2 — `_run_hostinger_status`: consume `--json`, format for Slack, keep a raw fallback

**Exact old block (the `try:` body, from `(job_dir / "status").write_text("running")` through the
`_finish("success")` that precedes the `except`):**

```python
    try:
        (job_dir / "status").write_text("running")
        import shlex as _shlex_hs
        repo_root = Path(__file__).resolve().parent.parent
        status_bin = repo_root / "bin" / "cluster-status"
        status_out, status_timeout = _posix_spawn_capture(
            ["/bin/bash", "-c",
             f"CLUSTER_PROVIDER=k3s-hostinger {_shlex_hs.quote(str(status_bin))} && echo __WEBHOOK_SUCCESS__"],
            timeout=180,
        )
        if status_timeout:
            _log("\n❌ *Hostinger status timed out* after 180s — run `make status CLUSTER_PROVIDER=k3s-hostinger` manually")
            _finish("failed")
            return
        report = status_out.replace("__WEBHOOK_SUCCESS__", "").rstrip()
        _log("🖥️ *Hostinger app cluster status*")
        if report:
            # Slack limits a message to roughly 4k characters. Keep both the
            # opening reachability sections and the final service/login health
            # sections instead of showing only the tail of the report.
            if len(report) > 3500:
                report = (report[:1600]
                          + "\n… (middle of report truncated) …\n"
                          + report[-1800:])
            _log("```\n{}\n```".format(report))
        if "__WEBHOOK_SUCCESS__" not in status_out:
            _log("⚠️ hostinger-status exited non-zero")
        _finish("success")
```

**Exact new block:**

```python
    try:
        (job_dir / "status").write_text("running")
        repo_root = Path(__file__).resolve().parent.parent
        status_bin = repo_root / "bin" / "cluster-status"
        # --json emits no ANSI; pass our own bearer token so the summary tool can
        # reach /api/v1/health without a Keychain read (launchd children can't).
        _status_env = dict(os.environ)
        _status_env.update({"CLUSTER_PROVIDER": "k3s-hostinger", "NO_COLOR": "1",
                            "K3DM_WEBHOOK_TOKEN": _get_token() or ""})
        status_out, status_timeout = _posix_spawn_capture(
            [str(status_bin), "--json"], timeout=180, env=_status_env,
        )
        if status_timeout:
            _log("\n❌ *Hostinger status timed out* after 180s — run `make status CLUSTER_PROVIDER=k3s-hostinger` manually")
            _finish("failed")
            return
        payload = None
        for _line in reversed(status_out.strip().splitlines()):
            _line = _line.strip()
            if _line.startswith("{") and _line.endswith("}"):
                try:
                    payload = json.loads(_line)
                    break
                except ValueError:
                    continue
        if payload is not None:
            _log(_format_status_summary_slack(payload, "k3s-hostinger"))
        else:
            # Fall back to the raw report if --json could not be parsed.
            report = status_out.rstrip()
            _log("🖥️ *Hostinger app cluster status*")
            if report:
                if len(report) > 3500:
                    report = report[:1600] + "\n… (middle of report truncated) …\n" + report[-1800:]
                _log("```\n{}\n```".format(report))
        _finish("success")
```

Notes:
- `bin/cluster-status --json` exits `1` when a service is in error; `_posix_spawn_capture` returns
  stdout regardless of exit code, so the JSON is still captured and rendered.
- `_get_token()` is already imported at the top of `bin/k3dm-webhook`.

## Non-goals (explicit)

- **`_run_cluster_status` (generic / ACG path) is out of scope.** It is a bespoke ACG-reachability
  report (hub nodes, SSH tunnel `:6443`, sandbox TTL probe, per-app ArgoCD health) that is **not**
  backed by `bin/cluster-status --json`, and it already renders with Slack emoji rather than ANSI. The
  contract's §Slack concern is the service-health summary, which is the hostinger / `make status`
  path. If a concise ACG summary is wanted later, file a follow-up.

## Risks

- **Re-entrancy:** `bin/cluster-status --json` calls the webhook's own `/api/v1/health` on
  `localhost:7443`. The webhook is threaded, so a concurrent health request while the job runs is
  fine. The token is passed via env (above) so it does not depend on Keychain access from a launchd
  child.
