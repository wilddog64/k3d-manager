# Bugfix: v1.25.0 — DRY_RUN support across the cluster lifecycle (make up + make down, all providers)

**Branch (k3d-manager):** `k3d-manager-v1.25.0`
**Branch (lib-foundation):** `feat/v0.4.9` (Phase 0 — separate repo; fresh next-release branch at the v0.4.8 tip)
**Files (k3d-manager):** `scripts/lib/system.sh` (synced), `bin/cluster-up`, `bin/cluster-down`,
`scripts/lib/providers/k3s-aws.sh`, `k3s-oci.sh`, `k3s-hostinger.sh`, `k3s-gcp.sh`, `k3s-az.sh`
**Files (lib-foundation):** `scripts/lib/system.sh`, `scripts/tests/…` (BATS)

---

## Problem

`DRY_RUN=1` is honored in **exactly one place** in the entire cluster lifecycle — the new
`_k3s_aws_deregister_cluster` (k3s-aws.sh). Everywhere else it is ignored:

- `DRY_RUN=1 make down CLUSTER_PROVIDER=k3s-aws` **really tears down** the EC2/CloudFormation stack,
  kills port-forwards, unloads launchd agents, deletes the hub cluster, and prunes Docker — while only
  *dry-running* the hub deregister. A "dry run" that destroys is a footgun (OWASP-style least-surprise bug).
- `DRY_RUN=1 make up …` likewise provisions for real.

**Root cause:** there is no shared DRY_RUN guard primitive, and none of the teardown/provision side-effects
are gated on it. `make up`/`make down` route through several code paths (`bin/cluster-up`,
`bin/cluster-down`, and the dispatcher `deploy_cluster`/`destroy_cluster` → `_provider_*` functions), none
of which check `DRY_RUN`.

**Secondary bug (found while tracing this):** `make down CLUSTER_PROVIDER=k3s-aws` routes through
`bin/cluster-down`, which runs its **own** inline teardown and **never calls
`_provider_k3s_aws_destroy_cluster`** — so the `_k3s_aws_deregister_cluster` hub-cleanup added in
`v1.25.0-bugfix-k3s-aws-hub-deregister` **does not fire on the `make down` path**, only on the direct
`destroy_cluster` dispatcher path. See **Phase 3**.

## The guard primitive (Phase 0 — lib-foundation)

Two helpers, next to `_info`/`_warn` in foundation `scripts/lib/system.sh`:

```bash
# Return success when a dry run is active. Use as a predicate to gate multi-step blocks:
#   if _dry_run_active; then _info "DRY_RUN: would …"; else <block>; fi
function _dry_run_active() {
  [[ "${DRY_RUN:-0}" == "1" ]]
}

# Guard a SINGLE destructive/provisioning command. In DRY_RUN mode, log the intent and skip
# (return 0). Otherwise run the command and preserve its exit status.
#   _dry_guard "delete VM ${_AZ_VM_NAME}" az vm delete --resource-group "${rg}" --name "${_AZ_VM_NAME}" --yes
function _dry_guard() {
  local _desc="${1:-}"
  shift || true
  if _dry_run_active; then
    _info "DRY_RUN: would ${_desc}"
    return 0
  fi
  "$@"
}
```

**Usage rule:**
- **Single command** (one argv, no pipes/redirs/subshells): wrap with `_dry_guard "desc" cmd args…`.
- **Multi-step block** (pidfile read + kill + rm, launchctl + rm, pipelines, conditionals): gate the whole
  block with `if _dry_run_active; then _info "DRY_RUN: would <desc>"; else <block>; fi`.
- **Never** put a command that has already run its side effect inside `_dry_guard` (evaluate args are fine;
  the command itself must be the thing guarded).

## Phase 2 — per-op guards across up + down (k3d-manager)

Apply the **Usage rule** to every side-effect op listed below. This section gives the full op inventory
(file + anchor + description + which helper form) plus fully-worked exact examples. Each enumerated op MUST
end up guarded; the DoD grep gate verifies coverage.

> guarded in **2c** — do **not** double-guard the call site here.

**Worked example — single command (`_dry_guard`):**

Old:
```bash
rm -f "${HOME}/.local/share/k3d-manager/active-provider"
```
New:
```bash
_dry_guard "remove active-provider marker" rm -f "${HOME}/.local/share/k3d-manager/active-provider"
```

**Worked example — multi-step block (`_dry_run_active`):**

Old:
```bash
    _info "[acg-down] Tearing down CloudFormation stack (AWS)..."
    if aws sts get-caller-identity --region "${ACG_REGION}" --query 'Arn' --output text >/dev/null 2>&1; then
      acg_teardown --confirm || \
        _info "[acg-down] CloudFormation teardown failed — sandbox may have been recreated with new credentials. Stack cleanup skipped; continuing Hub teardown."
    else
      _info "[acg-down] AWS credentials invalid or expired — sandbox already removed. Skipping CloudFormation teardown."
    fi
```
New:
```bash
    _info "[acg-down] Tearing down CloudFormation stack (AWS)..."
    if _dry_run_active; then
      _info "[acg-down] DRY_RUN: would run acg_teardown --confirm (delete CloudFormation stack)"
    elif aws sts get-caller-identity --region "${ACG_REGION}" --query 'Arn' --output text >/dev/null 2>&1; then
      acg_teardown --confirm || \
        _info "[acg-down] CloudFormation teardown failed — sandbox may have been recreated with new credentials. Stack cleanup skipped; continuing Hub teardown."
    else
      _info "[acg-down] AWS credentials invalid or expired — sandbox already removed. Skipping CloudFormation teardown."
    fi
```

### 2b — `bin/cluster-up` (provision shared + k3s-aws path)

Guard each provisioning/side-effect op (block-gate unless marked single). Anchors from the current file:

| Anchor | Description | Form |
|---|---|---|
| `launchctl bootout "gui/$(id -u)" …cloudflare-tunnel.plist` (early cleanup) | pre-clean cloudflared agent | block |
| `deploy_cluster --provider "${_cluster_provider}" --confirm` | provision remote cluster | single |
| `tunnel_start` | start autossh tunnel | single |
| `deploy_cluster --provider k3d "${HUB_CLUSTER_NAME}"` | create local hub | single |
| `k3d cluster start "${HUB_CLUSTER_NAME}"` | start existing hub | single |
| `deploy_vault --confirm` / `deploy_ldap --confirm` / `deploy_argocd --confirm` | core platform installs | single (each) |
| `deploy_argocd_bootstrap --confirm` | argocd bootstrap | single |
| `deploy_vault --re-unseal` | re-unseal vault | single |
| Vault pf launchd `bootout` + `bootstrap` | (re)load Vault pf agent | block |
| argocd pf launchd `unload` + `load` | (re)load ArgoCD pf agent | block |
| every `_run_command … launchctl {bootout,bootstrap,load,install}` for browser listeners | load browser listeners | block (each listener) |

> `bin/cluster-up` is large (~87KB). The rule is mechanical: any line that mutates cluster/host state
> (installs, `launchctl` load/bootout/bootstrap, `k3d cluster`, `deploy_*`, `_run_command` that writes)
> gets guarded. Read-only probes (`kubectl get`, `k3d cluster list`, `launchctl list`, `aws sts`) are **not**
> guarded. When in doubt: does it change state? If yes → guard.

**Worked example — single command (`_dry_guard`):**

Old:
```bash
  deploy_cluster --provider "${_cluster_provider}" --confirm
```
New:
```bash
  _dry_guard "provision ${_cluster_provider} cluster (deploy_cluster --confirm)" \
    deploy_cluster --provider "${_cluster_provider}" --confirm
```

### 2c — provider `deploy` + `destroy` functions

For each provider file, guard the state-mutating ops in **both** `_provider_<p>_deploy_cluster` and
`_provider_<p>_destroy_cluster`. Read-only checks and `--help`/`--confirm` argument validation are **not**
guarded (a dry run must still validate args and print help).

**k3s-aws destroy** (`_provider_k3s_aws_destroy_cluster`) — guard: watcher `kill`+`rm` (block), SSM tunnel
`kill`+`rm` (block), `tunnel_stop` (block), `acg_teardown --confirm` (block). `_k3s_aws_deregister_cluster`
already self-guards. **k3s-aws deploy** (`_provider_k3s_aws_deploy_cluster`) — guard `acg_provision`,
`deploy_app_cluster`, `tunnel_start`, watcher start.

**k3s-gcp destroy** — guard (single, each): `gcloud compute instances delete …`,
`gcloud compute firewall-rules delete …`; block-gate the SSH-config `awk`+`mv`+`chmod` and the
`kubectl config delete-context`. **deploy** — guard instance/firewall create, kubeconfig write.

Worked example (single):
```bash
  _dry_guard "delete GCE instance ${_GCP_INSTANCE_NAME}" \
    gcloud compute instances delete "${_GCP_INSTANCE_NAME}" \
      --project="${project}" --zone="${zone}" --quiet
```
(Keep the trailing `|| _info "[k3s-gcp] Instance not found — skipping"` on the guarded call so the
not-found fallback still applies in real mode; in DRY_RUN `_dry_guard` returns 0 so the `||` is skipped.)

**k3s-az destroy** — guard `az vm delete …` (single); block-gate SSH-config edit + `kubectl config delete-context`.
**deploy** — guard VM create, NSG rule, kubeconfig write.

**k3s-hostinger destroy** — guard the SSH `k3s-uninstall.sh` `_run_command` (block, preserve the rc handling),
`_hostinger_deregister_cluster` (block), `kubectl config delete-context` (block),
`rm -f "${_HOSTINGER_KUBECONFIG}"` + `rm -f active-provider` (single each). **deploy** — guard the remote
k3s install, kubeconfig merge, `_hostinger_register_cluster`, appset reapply.

**k3s-oci destroy** — guard `_oci_deregister_cluster` (block) and `_oci_destroy_infrastructure` (block; keep
the interactive `read … yes` confirm OUTSIDE the guard — validation runs in dry mode, the destroy does not).
**deploy** — guard instance/VCN create, kubeconfig write, `_oci_register_cluster` if present.

## Phase 3 — make-down k3s-aws must run the deregister

`bin/cluster-down`'s `k3s-aws)` branch never calls the hub deregister. Add it so `make down` cleans the hub
the same way the dispatcher path does. Place after the `acg_teardown` block, before `rm -f active-provider`:

**New block (k3s-aws branch of `bin/cluster-down`):**
```bash
    _info "[acg-down] Deregistering sandbox from hub ArgoCD..."
    if _dry_run_active; then
      _info "[acg-down] DRY_RUN: would deregister cluster-ubuntu-k3s + generated Applications from hub"
    elif declare -f _k3s_aws_deregister_cluster >/dev/null 2>&1; then
      _k3s_aws_deregister_cluster || _warn "[acg-down] hub deregister reported an issue"
    else
      # shellcheck source=/dev/null
      source "${REPO_ROOT}/scripts/lib/providers/k3s-aws.sh" 2>/dev/null \
        && _k3s_aws_deregister_cluster || _warn "[acg-down] hub deregister unavailable"
    fi
```

> This depends on `_k3s_aws_deregister_cluster` from `v1.25.0-bugfix-k3s-aws-hub-deregister` (already merged
> at `d6217640`). Do not redefine it.

## Rules

- `set -euo pipefail`; double-quote all expansions; no bare `sudo` (route via `_run_command`); LF only.
- `shellcheck -S warning` clean on every changed file (both repos).
- **Read-only probes are never guarded** — a dry run must still detect state and print an accurate plan.
- `_dry_guard` wraps a single command only; multi-step blocks use the `_dry_run_active` predicate.
- Do not weaken any existing `|| true` / `--ignore-not-found` / rc-handling semantics.
- No secrets in argv/logs; the DRY_RUN log lines must not print tokens/keys.
