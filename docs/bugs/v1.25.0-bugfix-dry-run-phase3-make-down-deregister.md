# Bugfix: v1.25.0 — Phase 3: `make down` (k3s-aws) must deregister the sandbox from hub

**Branch:** `k3d-manager-v1.25.0`
**File:** `bin/cluster-down` (+ BATS)
**Depends on:** Phase 1 helpers (merged `f5057e73`) and Phase 2 per-op guards (in flight).
Sequence this **after** Phase 2 lands on the branch — see "Before You Start".

---

## Problem

`make down CLUSTER_PROVIDER=k3s-aws` tears down the CloudFormation stack but leaves the sandbox
**registered in hub ArgoCD**: the hub keeps a `cluster-ubuntu-k3s` cluster Secret and the generated
Applications that target it. On the next sandbox recreation these become stale, orphaned rows
(dead `ubuntu-k3s` contexts / Applications) that must be cleaned by hand.

**Root cause:** `bin/cluster-down` bypasses the `destroy_cluster` dispatcher. The dispatcher destroy
path calls `_k3s_aws_deregister_cluster` (`scripts/lib/providers/k3s-aws.sh:333`), but `bin/cluster-down`'s
`k3s-aws)` branch (lines 48–64) only sources `aws.sh` / `acg.sh` / `tunnel.sh` and runs `acg_teardown` —
it never calls the deregister. `make down` uses `bin/cluster-down`, so the hub cleanup never runs.

---

## Reproduction

```bash
# with a registered k3s-aws sandbox and the hub ArgoCD up
make down CLUSTER_PROVIDER=k3s-aws
# expected: hub cluster Secret cluster-ubuntu-k3s and its generated Applications are gone
# actual:   they remain — kubectl get secret -n argocd | grep ubuntu-k3s  → still present
```

## Fix

### Change — `bin/cluster-down`: add hub deregister to the `k3s-aws)` branch

Insert the new block **inside** the `k3s-aws)` branch, immediately after the `acg_teardown` /
`else` block that ends at line 63, and **before** the branch's `;;` at line 64.

**Exact anchor (lines 57–64, unchanged — for locating the insertion point):**

```bash
    _info "[acg-down] Tearing down CloudFormation stack (AWS)..."
    if aws sts get-caller-identity --region "${ACG_REGION}" --query 'Arn' --output text >/dev/null 2>&1; then
      acg_teardown --confirm || \
        _info "[acg-down] CloudFormation teardown failed — sandbox may have been recreated with new credentials. Stack cleanup skipped; continuing Hub teardown."
    else
      _info "[acg-down] AWS credentials invalid or expired — sandbox already removed. Skipping CloudFormation teardown."
    fi
    ;;
```

**Exact new block — insert between the closing `fi` (line 63) and the `;;` (line 64):**

```bash
    _info "[acg-down] Deregistering sandbox from hub ArgoCD..."
    if _dry_run_active; then
      _info "[acg-down] DRY_RUN: would deregister cluster-ubuntu-k3s + generated Applications from hub"
    elif declare -f _k3s_aws_deregister_cluster >/dev/null 2>&1; then
      _k3s_aws_deregister_cluster || _warn "[acg-down] hub deregister reported an issue"
    else
      # shellcheck source=/dev/null
      source "${REPO_ROOT}/scripts/lib/providers/k3s-aws.sh" 2>/dev/null \
        && _k3s_aws_deregister_cluster || _warn "[acg-down] hub deregister unavailable"
    fi
```

**Why this shape:**
- Dry mode logs the intent and does **not** source the provider or call the function — the plan line
  prints without any hub reads/writes.
- Real mode calls the deregister if already defined; otherwise sources `k3s-aws.sh` first. The provider
  is not sourced by the `k3s-aws)` branch today, so the `declare -f` guard + fallback source is required.
- `|| _warn` keeps teardown non-fatal — a hub that is already gone must not block the rest of `make down`.
