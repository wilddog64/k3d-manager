**Branch:** `k3d-manager-v1.25.0`
**File:** `bin/cluster-down` (+ BATS)
**Depends on:** Phase 1 helpers (merged `f5057e73`) and **Phase 2b (`d2263cc2`, on the branch)**.
Line anchors below are re-anchored to the tree at `d2263cc2` — read the file before editing to confirm.

## Problem

Two independent defects on the `make down` path, both fixed here because both live in `bin/cluster-down`:

**Defect 1 — k3s-aws sandbox is never deregistered from hub.**
`make down CLUSTER_PROVIDER=k3s-aws` tears down the CloudFormation stack but leaves the sandbox
**registered in hub ArgoCD**: the hub keeps a `cluster-ubuntu-k3s` cluster Secret and the generated
Applications that target it. On the next sandbox recreation these become stale, orphaned rows
(dead `ubuntu-k3s` contexts / Applications) that must be cleaned by hand.

**Root cause:** `bin/cluster-down` bypasses the `destroy_cluster` dispatcher. The dispatcher destroy
path calls `_k3s_aws_deregister_cluster` (`scripts/lib/providers/k3s-aws.sh:333`), but `bin/cluster-down`'s
`k3s-aws)` branch (lines 52–79) only sources `aws.sh` / `acg.sh` / `tunnel.sh` and runs `acg_teardown` —
it never calls the deregister. `make down` uses `bin/cluster-down`, so the hub cleanup never runs.

**Defect 2 — `DRY_RUN=1 make down` fires real sudo on local providers.**
The `*)` case branch (line 100 — the path **every local/dev provider** takes: orbstack/k3d/k3s all route
here via `make down`) never sources `scripts/lib/system_overrides.sh`. The common launchd teardown block
after `esac` calls `_run_command --prefer-sudo -- launchctl bootout system …` for the Keycloak/ArgoCD/
frontend browser listeners (lines ~179/204/230/246). Those ops are guarded **only** by the `_run_command`
dry-run bridge (Part C of Phase 2b deliberately relies on it). With the override unsourced on the `*)`
path, the bridge is absent and those calls execute **real `sudo launchctl bootout` under `DRY_RUN=1`**.

**Root cause:** Phase 2b sourced `system_overrides.sh` inside each cloud branch (k3s-aws/gcp/az) but not
in `*)`. Spy-confirmed: `*)` path → `REAL launchctl CALLED …`; override sourced → `[dry-run] sudo launchctl …`.

## Reproduction

```bash
# Defect 1: with a registered k3s-aws sandbox and the hub ArgoCD up
make down CLUSTER_PROVIDER=k3s-aws
# expected: hub cluster Secret cluster-ubuntu-k3s and its generated Applications are gone
# actual:   they remain — kubectl get secret -n argocd | grep ubuntu-k3s  → still present

# Defect 2: with a local orbstack/k3d hub and browser-listener launchd agents loaded
DRY_RUN=1 make down CLUSTER_PROVIDER=orbstack
# expected: every teardown op previews "[dry-run] …" and touches nothing
# actual:   sudo launchctl bootout of the browser listeners runs for real
```

## Fix

### Change 1 — `bin/cluster-down`: add hub deregister to the `k3s-aws)` branch

Insert the new block **inside** the `k3s-aws)` branch, immediately after the `acg_teardown`
`if/elif/else` block that ends at line 78 (`fi`), and **before** the branch's `;;` at line 79.

**Exact anchor (lines 70–79, unchanged — for locating the insertion point):**

```bash
    _info "[acg-down] Tearing down CloudFormation stack (AWS)..."
    if _dry_run_active; then
      _info "[acg-down] DRY_RUN: would run acg_teardown --confirm (delete CloudFormation stack)"
    elif aws sts get-caller-identity --region "${ACG_REGION}" --query 'Arn' --output text >/dev/null 2>&1; then
      acg_teardown --confirm || \
        _info "[acg-down] CloudFormation teardown failed — sandbox may have been recreated with new credentials. Stack cleanup skipped; continuing Hub teardown."
    else
      _info "[acg-down] AWS credentials invalid or expired — sandbox already removed. Skipping CloudFormation teardown."
    fi
    ;;
```

**Exact new block — insert between the closing `fi` (line 78) and the `;;` (line 79):**

```bash
    _info "[acg-down] Deregistering sandbox from hub ArgoCD..."
    if _dry_run_active; then
      _info "[acg-down] DRY_RUN: would deregister cluster-ubuntu-k3s + generated Applications from hub"
    elif declare -f _k3s_aws_deregister_cluster >/dev/null 2>&1; then
      _k3s_aws_deregister_cluster || _warn "[acg-down] hub deregister reported an issue"
    else
      # shellcheck source=/dev/null
      source "${REPO_ROOT}/scripts/lib/providers/k3s-aws.sh" 2>/dev/null \
        && _k3s_aws_deregister_cluster || _warn "[acg-down] hub deregister unavailable"
    fi
```

**Why this shape:**
- Dry mode logs the intent and does **not** source the provider or call the function — the plan line
  prints without any hub reads/writes.
- Real mode calls the deregister if already defined; otherwise sources `k3s-aws.sh` first. The provider
  is not sourced by the `k3s-aws)` branch today, so the `declare -f` guard + fallback source is required.
- `|| _warn` keeps teardown non-fatal — a hub that is already gone must not block the rest of `make down`.

### Change 2 — `bin/cluster-down`: source the dry-run bridge on the `*)` (local-provider) path

**Exact anchor (lines 100–102, unchanged):**

```bash
  *)
    _info "[acg-down] Unknown CLUSTER_PROVIDER '${_cluster_provider}' — skipping remote teardown"
    ;;
```

**Exact new block — replace those three lines with:**

```bash
  *)
    source "${REPO_ROOT}/scripts/lib/system_overrides.sh"
    _info "[acg-down] Unknown CLUSTER_PROVIDER '${_cluster_provider}' — skipping remote teardown"
    ;;
```

**Why this shape:**
- The `*)` branch sources no plugins, so a single `source` here wraps the clean base `_run_command`
  correctly — **no `unset -f __k3dm_base_run_command` is needed** (unlike cluster-up, where plugins
  re-load and clobber the wrapper). It matches how the cloud branches source it, just moved earlier so
  it also covers non-cloud providers.
- After this, the common launchd block's bridge-only `_run_command … launchctl bootout` ops preview
  `[dry-run] …` under `DRY_RUN=1` on the local path, matching the cloud branches.
