# Bugfix: v1.24.0 — hostinger status report drops the header when long

**Branch:** `k3d-manager-v1.24.0`
**Files:** `bin/k3dm-webhook`, `scripts/tests/lib/webhook.bats`

> **Split from D (`v1.24.0-webhook-auth-reconcile.md`) 2026-08-10.** The archive `webhook.bats`
> bundled a hostinger-report-truncation test with the auth tests, but the truncation code is an
> unrelated Slack-message-length UX fix in `bin/k3dm-webhook` — it does not belong in the "fail closed
> on Slack sig" commit. Filed separately here; the D spec drops its test.

---

## Problem

`_run_hostinger_status` (`bin/k3dm-webhook:2415`) posts only the **tail** of the status report
(`report[-3500:]`) to Slack. Slack caps a message at ~4k chars, so a long hostinger status report loses
its **opening reachability/header sections** — the reader sees only the final chunk, missing the top of
the report. The fix (present on `archive/k3d-manager-v1.22.0-integration`, never carried to `main`)
keeps both the head and the tail with a truncation marker in the middle.

**Root cause:** the tail-only slice was written before reports grew long enough to overflow 3500 chars;
the head+tail fix landed only on the archive branch and was not brought forward when the webhook work
was split.

---

## Reproduction

Trigger a hostinger status whose report exceeds 3500 chars (e.g. many services). On `main`, the Slack
post shows only `report[-3500:]` — the reachability header is gone.

---

## Fix

### Change 1 — `bin/k3dm-webhook`: keep head + tail instead of tail-only

**Exact old block (lines 2413–2415):**

```python
        _log("🖥️ *Hostinger app cluster status*")
        if report:
            _log("```\n{}\n```".format(report[-3500:]))
```

**Exact new block:**

```python
        _log("🖥️ *Hostinger app cluster status*")
        if report:
            # Slack limits a message to roughly 4k characters. Keep both the
            # opening reachability sections and the final service/login health
            # sections instead of showing only the tail of the report.
            if len(report) > 3500:
                report = (report[:1600]
                          + "\n… (middle of report truncated) …\n"
                          + report[-1800:])
            _log("```\n{}\n```".format(report))
```

### Change 2 — `scripts/tests/lib/webhook.bats`: source-grep test for the head+tail slice

Bring this test verbatim from `archive/k3d-manager-v1.22.0-integration:scripts/tests/lib/webhook.bats`
(it greps the `bin/k3dm-webhook` source, so it lands in the same commit as Change 1):

```bash
@test "hostinger status keeps report header and final health sections when long" {
    run grep -F -- "middle of report truncated" "${BATS_TEST_DIRNAME}/../../../bin/k3dm-webhook"
    [ "${status}" -eq 0 ]
    run grep -F -- "report[:1600]" "${BATS_TEST_DIRNAME}/../../../bin/k3dm-webhook"
    [ "${status}" -eq 0 ]
    run grep -F -- "report[-1800:]" "${BATS_TEST_DIRNAME}/../../../bin/k3dm-webhook"
    [ "${status}" -eq 0 ]
}
```
