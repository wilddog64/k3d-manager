# Bugfix: v1.23.0 — Grafana rotator fails `openssl: not found` on alpine/k8s → rotation still can't complete

**Branch:** `k3d-manager-v1.23.0`
**Files:** `scripts/etc/argocd/platform-ops/grafana-credential-rotator.yaml`
**Status:** QUEUED — uncovered during the runAsNonRoot live-verify (2026-08-08). Portable replacement live-verified in the same image (uid 65534).
**Severity:** high — the third and final latent blocker; with the pod now able to start, the rotator aborts before it rotates anything.

---

## Problem

With the `runAsNonRoot` startup blocker fixed (`a66463e1`), the rotator pod finally starts as
uid 65534 — and immediately fails:

```
/bin/sh: openssl: not found
```

The script generates the new password with `openssl rand -hex 24`
(`grafana-credential-rotator.yaml:109`), but the pinned image `docker.io/alpine/k8s:1.31.4` does
**not** ship `openssl`. `$new` is never assigned, `set -eu` aborts the job, the `restore` trap fires,
and no rotation occurs.

**Root cause:** `openssl` is not present in `alpine/k8s:1.31.4`. This defect was masked until now
because the pod could never start (the two prior blockers: `runAsNonRoot` with no `runAsUser`, and
the missing DB-apply step). It is the same image-capability class as the earlier
`bitnami/kubectl → alpine/k8s` re-pin.

> Only the Grafana rotator uses `openssl` — `grep -rn openssl scripts/etc/argocd/` returns exactly
> this one line. The LDAP rotator (also on `alpine/k8s`) does not, so no sibling fix is needed.

---

## Live findings & mechanism verification (2026-08-08)

- `command -v openssl` inside `alpine/k8s:1.31.4` (run as uid 65534) → **MISSING**.
- `/dev/urandom`, `od`, `head`, `tr` are all present. The portable replacement
  `head -c 24 /dev/urandom | od -An -tx1 | tr -d ' \n'` produces a **48-hex-char** string —
  byte-for-byte the same length/charset as `openssl rand -hex 24` (24 bytes → 48 hex chars).
- Verified live: the replacement emits a valid 48-char lowercase-hex token in the same image/uid.

---

## Fix — generate the password from `/dev/urandom` (no openssl dependency)

**File:** `scripts/etc/argocd/platform-ops/grafana-credential-rotator.yaml`

**Exact old block (line 109):**

```bash
                  new="$(openssl rand -hex 24)"
```

**Exact new block:**

```bash
                  new="$(head -c 24 /dev/urandom | od -An -tx1 | tr -d ' \n')"
```

Notes:
- 24 bytes of `/dev/urandom` → 48 lowercase-hex chars, identical entropy and format to
  `openssl rand -hex 24`.
- `$new` is still fed on stdin only to `reset-admin-password` (secret-hygiene rule preserved) and
  PUT to Vault via `jq` — no password on argv.
- Purely the generation command changes; the `restore` trap, Vault PUT, ESO force-sync, rollout,
  and DB-apply steps are untouched.
