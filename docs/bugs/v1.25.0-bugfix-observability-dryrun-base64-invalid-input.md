# Bugfix: v1.25.0 — observability DRY_RUN: `base64: invalid input` from previewed secret reads

**Branch:** `k3d-manager-v1.25.0`
**Files:** `scripts/plugins/observability.sh`

---

## Problem

Running the observability deploy path in DRY_RUN mode prints `base64: invalid input` to stderr
and a misleading warning:

```
INFO: [observability] Reading Alertmanager credentials from Vault...
base64: invalid input
WARN: [observability] Alertmanager Vault secret not found — skipping SMS config
WARN: [observability] Run: make alertmanager-secret to configure
...
base64: invalid input
```

**Root cause:** the Alertmanager credential path reads the Vault root token with

```bash
_vault_token=$(_kubectl get secret vault-root -n secrets \
  --context k3d-k3d-cluster -o jsonpath='{.data.root_token}' | base64 --decode)
```

Under DRY_RUN, `_kubectl` → `_run_command -- kubectl …`, and the `_run_command` override
(`scripts/lib/system_overrides.sh:41–60`) does **not** execute the command — it prints a
`[dry-run] kubectl get secret …` **preview banner to stdout**. That banner is captured by
`$(…)` and piped into `base64 --decode`, which fails on the non-base64 text (`base64: invalid
input`). `_vault_token` is then garbage/empty, the follow-on Vault `curl` returns nothing, and
the code prints the **false-negative** "Alertmanager Vault secret not found."

The read is side-effect-free, so nothing is actually broken — but the noise is misleading and
the "secret not found" warning is wrong (the read simply never ran). This is a DRY_RUN
correctness follow-on to the DRY_RUN Phases 1–4 work: a **read** whose output is consumed
downstream must execute under dry-run, not be previewed.

Proof:
```
$ printf '[dry-run] kubectl get secret vault-root -n secrets\n' | base64 --decode
base64: invalid input          # exit 1
$ printf '' | base64 --decode  # empty (cluster absent) — no error, exit 0
```

**Precedent for the fix:** `bin/cluster-up:409` performs this exact vault-root read with plain
`kubectl` (not `_kubectl`) for precisely this reason.

Two occurrences are seen on the hub path (lines 39 + 201); three more latent copies (401, 556,
580) are on the ACG / helper paths and have the same defect.

---

## Reproduction

```bash
DRY_RUN=1 ./scripts/k3d-manager deploy_observability   # (or the make target that reaches it)
# → "base64: invalid input" + false "Alertmanager Vault secret not found"
```

Expected (dry-run): no `base64: invalid input`; the read either returns the real token (live
hub) or empty (no hub) and the Alertmanager block proceeds/skips cleanly.

---

## Fix

### Change 1 — `scripts/plugins/observability.sh`: read secrets with plain `kubectl`

The Vault-root read is non-mutating and its output is consumed by `base64 --decode`, so it must
run even under dry-run. Replace `_kubectl` with plain `kubectl` in the **five** vault-root read
lines only. The anchor string `_kubectl get secret vault-root` is unique to these reads.

**Exact old line (occurs 5×, at lines 38, 200, 400, 555, 579):**

```bash
  _vault_token=$(_kubectl get secret vault-root -n secrets \
```

**Exact new line (all 5):**

```bash
  _vault_token=$(kubectl get secret vault-root -n secrets \
```

> Apply to all 5 occurrences (indentation is identical). Do NOT change any other `_kubectl`
> call — only the `get secret vault-root` reads whose stdout feeds `base64 --decode`. The
> `--context k3d-k3d-cluster -o jsonpath='{.data.root_token}' | base64 --decode` continuation
> line is unchanged.
