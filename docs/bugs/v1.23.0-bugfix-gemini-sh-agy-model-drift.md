# Bugfix: v1.23.0 — gemini.sh agy fallback chain uses retired model IDs

**Branch:** `k3d-manager-v1.23.0`
**Files:** `scripts/plugins/gemini.sh`, `scripts/tests/lib/antigravity.bats`
**Status:** QUEUED. Companion to the webhook fix `8e7a5c79` (browser-automation path).
**Severity:** low-medium — breaks ACG/browser-automation agy flows when invoked; not the alert path.

---

## Problem

`scripts/plugins/gemini.sh` `_GEMINI_MODELS` is a 429/rate-limit fallback chain of **retired** model
IDs (`gemini-2.5-flash`, `gemini-2.0-flash`, `gemini-1.5-flash` — all gone from `agy`). Any
`_agy_prompt` call (github-session check, browser automation) fails model selection on every entry
and exhausts the chain. Same drift class as [[reference_agy_model_id_drift]]; the webhook default was
already re-fixed (`8e7a5c79`), this is the remaining stale path.

**Root cause:** hardcoded model IDs; `agy` retires them. Current valid IDs (from `agy models`
2026-08-08) encode effort: `gemini-3.6-flash-{high,medium,low}`, `gemini-3.5-flash-{high,medium,low}`,
`gemini-3.1-pro-{high,low}`, `claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium`.

The `antigravity.bats` suite mocks `agy` and asserts the specific chain entries, so it is **coupled** —
it must be updated in lockstep.
