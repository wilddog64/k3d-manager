# Bugfix: v1.13.0 — make CodeQL recognize `_safe_job_dir` path sanitizer

**Branch:** `k3d-manager-v1.13.0`
**Files:** `scripts/lib/webhook/config.py`

---

## Problem

CodeQL default-setup flags `scripts/lib/webhook/config.py:47-48` (`_safe_job_dir`)
with `py/path-injection` ("Uncontrolled data used in path expression", high severity)
on every PR that touches or moves this code. The code is **already safe** — `job_id`
is validated against a strict allowlist `^[0-9a-f]{8}$` (no slashes, no `..`, fixed
8 hex chars) and the resolved candidate's parent must equal `JOB_DIR`. But CodeQL's
Python taint tracker does not model a `re.match` + `.group()` guard as a sanitizer,
nor does it reliably recognize the pathlib `.parent.resolve()` containment check, so
it reports the tainted `job_id` reaching the path construction.

**Root cause:** the sanitizer is expressed in a form (regex allowlist + pathlib
`.parent` comparison) that CodeQL's `py/path-injection` query does not recognize as
breaking taint. The same code was dismissed as a false positive on `main` in
`bin/k3dm-webhook`; the v1.13.0 modularization moved it into `config.py`, so CodeQL
re-numbered the finding (alerts #17/#18, since dismissed via Option A).

This is a CI-noise / recurrence bug, not a security defect — path traversal is
already impossible.

---

## Fix

Rewrite `_safe_job_dir` to use the `os.path` normalization + `startswith` containment
pattern that CodeQL's `py/path-injection` query **does** recognize as a sanitizer,
while preserving exact behavior (return a resolved path that is a direct child of
`JOB_DIR`, else raise `ValueError`).

### Change 1 — `scripts/lib/webhook/config.py`: rewrite `_safe_job_dir`

**Exact old block (lines 41–50):**

```python
def _safe_job_dir(job_id):
    """Return resolved job directory only if it is a valid hex job ID and a direct child of JOB_DIR."""
    m = _JOB_ID_RE.match(job_id)
    if not m:
        raise ValueError(f"invalid job_id: {job_id!r}")
    safe_id = m.group(0)
    candidate = (JOB_DIR / safe_id).resolve()
    if candidate.parent.resolve() != JOB_DIR.resolve():
        raise ValueError(f"invalid job_id: {job_id!r}")
    return candidate
```

**Exact new block:**

```python
def _safe_job_dir(job_id):
    """Return resolved job directory only if it is a valid hex job ID and a direct child of JOB_DIR."""
    m = _JOB_ID_RE.match(job_id)
    if not m:
        raise ValueError(f"invalid job_id: {job_id!r}")
    safe_id = m.group(0)
    base = os.path.realpath(str(JOB_DIR))
    candidate = os.path.realpath(os.path.join(base, safe_id))
    if not candidate.startswith(base + os.sep) or os.path.dirname(candidate) != base:
        raise ValueError(f"invalid job_id: {job_id!r}")
    return Path(candidate)
```

`os.path.realpath` + `os.path.join` + a `startswith(base + os.sep)` containment
check is the canonical pattern CodeQL recognizes. The `os.path.dirname(candidate)
!= base` clause preserves the original "direct child only" contract. Return type
stays `pathlib.Path` so callers are unaffected. `os` and `Path` are already imported
(config.py:10, :12).
