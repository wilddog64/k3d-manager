## Finding 1 — CI sensor change masks the R4 rerun precondition

### Evidence

`3d0c5478` changed `scripts/lib/hermes/sensors.py` `ci()` so that the **first** bad check of any
conclusion populates `ci_data`:

```python
if check.get("conclusion") in ("failure", "timed_out", "cancelled"):
    bad.append(...)
    if not ci_data:                      # was: if conclusion in ("timed_out","cancelled") and not ci_data
        ci_data = {..., "conclusion": check["conclusion"]}
```

`scripts/lib/hermes/repairs.py` `_r4_precondition` (line ~91) only fires when
`data["conclusion"] in ("timed_out", "cancelled", "stuck")`. Before the change, a `failure` never
claimed `ci_data`, so a later `cancelled`/`timed_out`/`stuck` check still did. Now, with check-runs
`[failure, cancelled]`, `ci_data.conclusion == "failure"` and R4 never fires. The intent of
`3d0c5478` was only to expose `run_url` for the Grafana drilldown.

### Fix

In `ci()`, keep two candidates while iterating:

- `rerunnable` — the first check whose conclusion is `timed_out` / `cancelled`, or the first stuck
  `in_progress` check (conclusion `"stuck"`);
- `first_bad` — the first bad check of any kind.

After the loop: `ci_data = rerunnable or first_bad`. Both carry `repo`, `run_id`, `run_url`
(`latest.get("html_url", "")`) and `conclusion`. This restores the pre-`3d0c5478` R4 behavior
exactly and still gives a pure-`failure` run a `run_url`.

`bad` (the evidence string list) and its order are unchanged.

### Tests — `scripts/tests/hermes/test_hermes.py`

Extend the existing CI test source fixture so it can return a list of check-runs, then add:

1. `[failure, cancelled]` → `data.conclusion == "cancelled"`, `run_url` present, and
   `repairs._r4_precondition` returns `True` for that record (status degraded).
2. `[failure, in_progress-older-than-max-age]` → `conclusion == "stuck"`, R4 precondition `True`.
3. `[failure]` only → `conclusion == "failure"`, `run_url` present, R4 precondition `False`.
4. `[cancelled, failure]` → `conclusion == "cancelled"`.

Mutation check (run, confirm red, restore): change `ci_data = rerunnable or first_bad` to
`first_bad or rerunnable` — test 1 and 2 must fail.

## Finding 2 — "Latest test result" panel turns exit code into a verdict

### Evidence

`e3db399e` retitled the k3dm-tests exit-code table to **Latest test result** and mapped
`0 → PASS`, `1 → FAIL`, `2 → EXPECTED ENVIRONMENT` (yellow). But:

- `k3dm_test_exit_code` is the **make** exit code (`Makefile` `test-metrics`), and `make` exits **2
  whenever any recipe fails**. A genuine BATS failure therefore renders yellow
  "EXPECTED ENVIRONMENT".
- `bin/k3dm-test-metrics` declares the metric `INFORMATIONAL ONLY`, and declares
  `k3dm_test_cases_failed` "THE health signal". The dashboard already has a **Failed cases** panel.
- Codes other than 0/1/2 (e.g. 130) are unmapped, contradicting the panel description.
- `last_over_time(...[7d])` with `Time` hidden can show a week-old value with no age.
- The `instance` label is renamed `Runner`, but `instance` is the Pushgateway, not the runner; the
  meaningful label is `target`.

### Fix — `scripts/etc/grafana/dashboards/k3dm-tests-configmap.yaml` panel id 7 only

- Title: `Make exit code (informational)`.
- Description: state that this is the `make test-all` exit code, that `make` returns 2 for **any**
  failed recipe (including the expected missing-pytest case), and that pass/fail is the
  **Failed cases** panel.
- Query: `k3dm_test_exit_code` as an instant table (drop `last_over_time[7d]`; freshness is the
  existing **Suite freshness** panel).
- Remove the PASS / FAIL / EXPECTED ENVIRONMENT value mappings and their colors. No verdict text,
  no green/yellow/red on this panel.
- Columns: keep `target` (renamed `Target`) and `Value` (renamed `Exit code`); exclude `Time`,
  `__name__`, `instance`, `job`.

Do not change any other panel, the exporter, or the Makefile `test-metrics` target.

### Tests — `scripts/tests/plugins/grafana_dashboard_appsets.bats`

Replace the test `k3dm tests dashboard presents a readable latest result` with one that parses the
JSON (`yq` → `jq`) and asserts on panel id 7 via `jq`, not on source-line substrings:

1. `.title == "Make exit code (informational)"`;
2. the panel has no value mappings containing `PASS` or `EXPECTED ENVIRONMENT`
   (`jq` over `.fieldConfig.defaults.mappings`);
3. the expr is `k3dm_test_exit_code` and does not contain `last_over_time`;
4. the description mentions `Failed cases`;
5. a panel titled `Failed cases` with expr `k3dm_test_cases_failed` still exists.

Mutation check: restore the `"2": { "text": "EXPECTED ENVIRONMENT" ... }` mapping — test 2 must fail.

## Finding 3 — `fix-sync` skips login when a stale ArgoCD context exists

### Evidence

`Makefile` `fix-sync` / `fix-force-sync` decide whether to log in with:

```bash
if ! argocd account get-context --server '$(ARGOCD_SERVER)' ... ; then <mint token>; fi
```

`argocd account get-context` reads only the local `~/.config/argocd/config`; it never asks the
server whether the token is valid. With an expired token in that file (the exact case
`a7fb7798 fix(make): refresh stale ArgoCD sync sessions` targeted), the check succeeds, login is
skipped, and `argocd app sync` fails `Unauthenticated`. After an ArgoCD rebuild every stored token
is invalid (`server.secretkey` regenerated), so this is the common case, not an edge case.

### Fix

Replace the check with a server-side probe:

```bash
argocd account get-user-info --server "${server}" --grpc-web --plaintext --insecure -o json
```

Treat the session as valid **only** when the command exits 0 **and** the JSON has
`"loggedIn": true` (parse with `python3 -c`, already a dependency of this recipe). Any other
outcome — non-zero exit, unparsable output, `loggedIn` false/absent — mints a fresh token through
the existing `/api/v1/session` path and exports `ARGOCD_AUTH_TOKEN`, which overrides the stale
config-file token for the `argocd app sync` child.

This is implemented inside the new script from Finding 4, not in the Makefile.

## Finding 4 — ~20-line sync recipe duplicated across two Makefile targets

### Evidence

`fix-sync` and `fix-force-sync` (`Makefile` ~855–902) carry byte-identical port-forward, Vault
password lookup, API login and cleanup logic; only `--force` and the timeout differ. The recipe took
eight fix commits to get right and the two copies will drift.

### Fix

Create `bin/argocd-app-sync` (executable, `set -euo pipefail`, structured like
`bin/get-keycloak-password`: resolve `REPO_ROOT`, `source "${REPO_ROOT}/scripts/lib/system.sh"`).

```text
Usage: bin/argocd-app-sync <app> [--force] [--timeout SECONDS]
Env:   ARGOCD_SERVER (default localhost:8080), ARGOCD_SCHEME (default http),
       INFRA_CONTEXT (default k3d-k3d-cluster), ARGOCD_NS (default cicd),
       ARGOCD_ADMIN_PASSWORD (optional)
```

Behavior must be identical to the current recipe, in the same order:

1. If `ARGOCD_SERVER` is `localhost:8080` and `${ARGOCD_SCHEME}://${ARGOCD_SERVER}/healthz` is not
   reachable, start `kubectl --context "$INFRA_CONTEXT" -n "$ARGOCD_NS" port-forward
   svc/argocd-server 8080:443` in the background, wait up to 30s for `/healthz`, fail with the log
   path kept on timeout. The port-forward is the one place plain `kubectl` is used instead of
   `_kubectl`, because it must be a direct background child whose PID `kill` reaches. All other
   kubectl calls (secret reads) go through `_kubectl --no-exit` with `--context`.
2. Session probe per Finding 3.
3. If no valid session, resolve the password in the existing order: `ARGOCD_ADMIN_PASSWORD` →
   Vault `secret/data/argocd/admin` via `127.0.0.1:18200` using the `secrets/vault-root` token
   through a 0600 header file → `argocd-initial-admin-secret`. Error messages unchanged.
4. Mint the token: `python3` builds the JSON body from the password on **stdin**, pipes it to
   `curl -sf --max-time 30 -H 'Content-Type: application/json' --data-binary @-
   "${ARGOCD_SCHEME}://${ARGOCD_SERVER}/api/v1/session"`, and `python3` extracts `.token`.
   The password and token must never appear in argv, stdout, stderr or `set -x` trace.
5. `argocd app sync "$app" [--force] --timeout "$timeout" --server "$ARGOCD_SERVER" --grpc-web
   --plaintext --insecure` with `ARGOCD_AUTH_TOKEN` exported when minted.
6. A single `trap ... EXIT` kills/waits the port-forward and removes **both** the port-forward log
   (unless kept for diagnosis) and the Vault header file. Use `mktemp` under `${TMPDIR:-/tmp}` for
   both, not `$$`-named paths.

Use `${ARGOCD_SCHEME}` for every URL, including `/healthz` (the current recipe hardcodes `http://`
on the health checks).

Makefile — both targets become one line after the existing `APP` guard:

```make
fix-sync: ## APP is required
	@test -n "$(APP)" || { echo "Usage: make fix-sync APP=<argocd-app-name>"; exit 1; }
	@ARGOCD_SERVER='$(ARGOCD_SERVER)' ARGOCD_SCHEME='$(ARGOCD_SCHEME)' INFRA_CONTEXT='$(INFRA_CONTEXT)' ARGOCD_NS='$(ARGOCD_NS)' ./bin/argocd-app-sync '$(APP)' --timeout 120

fix-force-sync: ## APP is required
	@test -n "$(APP)" || { echo "Usage: make fix-force-sync APP=<argocd-app-name>"; exit 1; }
	@ARGOCD_SERVER='$(ARGOCD_SERVER)' ARGOCD_SCHEME='$(ARGOCD_SCHEME)' INFRA_CONTEXT='$(INFRA_CONTEXT)' ARGOCD_NS='$(ARGOCD_NS)' ./bin/argocd-app-sync '$(APP)' --force --timeout 180
```

Keep the `##` help comments. `make fix-list` output must be unchanged. The Slack/ask fix-mode path
(`bin/k3dm-ask-bash`, which allows `make fix-*`) needs no change.

### Tests — new `scripts/tests/bin/argocd_app_sync.bats`

Stub `kubectl`, `argocd`, `curl` on `PATH` in `BATS_TEST_TMPDIR`; each stub appends its argv (and,
for `argocd app sync`, whether `ARGOCD_AUTH_TOKEN` is set — not its value) to a log. Use a
distinctive fake password such as `s3cr3t-fixture-pw`. No network, no Keychain, no real cluster.

1. **Stale session** — `get-user-info` prints `{"loggedIn": false}` exit 0 → curl `/api/v1/session`
   is called and `app sync` runs with `ARGOCD_AUTH_TOKEN` set.
2. **Probe error** — `get-user-info` exits 1 → token is minted.
3. **Valid session** — `{"loggedIn": true}` → no `/api/v1/session` call; `app sync` runs.
4. **Force** — `--force --timeout 180` reach `argocd app sync`.
5. **Secret hygiene** — after tests 1–2 the fake password and fake token do not appear in any stub
   argv log or in `$output`.
6. **Port-forward lifecycle** — first `/healthz` curl fails, later succeeds → port-forward started
   with `--context k3d-k3d-cluster -n cicd`; after exit no port-forward process from the test
   remains and no temp files are left in the test `TMPDIR`.
7. **Password resolution order** — `ARGOCD_ADMIN_PASSWORD` set → no kubectl secret read.
8. **Missing app** → usage error, non-zero, no argocd call.

Update `scripts/tests/bin/fix_targets.bats`: replace
`make fix-sync bootstraps the local ArgoCD port-forward and uses grpc-web` with a `make -n` test
asserting both targets invoke `./bin/argocd-app-sync` with the right app, `--timeout 120` /
`--force --timeout 180`, and that the Makefile no longer contains `account get-context`.
