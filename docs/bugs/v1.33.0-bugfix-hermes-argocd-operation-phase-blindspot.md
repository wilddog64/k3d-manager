# Bug: Hermes ArgoCD sensor is blind to failed sync operations

**Filed:** 2026-09-11
**Branch:** `k3d-manager-v1.33.0`
**Severity:** High — silent data loss; a green dashboard over a broken app.

## Summary

`argocd()` in `scripts/lib/hermes/sensors.py` classifies an Application as bad only
when `health == "Degraded"` or `sync == "OutOfSync"`. It never inspects
`status.operationState.phase`.

An ArgoCD sync operation that **errors before reaching the PostSync phase** leaves
every tracked resource comparing `Synced` — because the resources really were
applied. Only the hooks are missing, and hooks are not tracked resources. The app
therefore reports `Synced / Healthy` while its last operation sits at
`phase: Error`, and auto-sync/self-heal will never re-run it: there is no drift to
correct. The failure is permanent and invisible.

## How this was found

The `product-catalog` API served `HTTP 200` over an empty database for ~12 hours.
Root cause: `argocd-repo-server` was crash-looping (28 restarts) during the
`11:11:44Z → 11:18:51Z` sync. The operation died on
`ComparisonError: ... dial tcp 10.43.86.193:8081: connect: connection refused (retried 5 times)`
before PostSync, so the `product-catalog-seed` and `product-catalog-fts-index`
hooks never ran. Schema present, zero rows. Recovered only by an operator-initiated
sync (`kubectl patch application ... {"operation":{...}}`).

Hermes reported `argocd healthy` throughout.

```python
        for app in apps:
            status = app.get("status", {})
            health = status.get("health", {}).get("status")
            sync = status.get("sync", {}).get("status")
            phase = status.get("operationState", {}).get("phase")
            name = app.get("name") or app.get("metadata", {}).get("name", "unnamed")
            project = app.get("project") or app.get("spec", {}).get("project", "default")

        if bad:
            status = "degraded" if _debounced("argocd", True, threshold, state) else "healthy"
            detail = ", ".join(bad[:3])
            if len(bad) > 3:
                detail = f"{detail} (+{len(bad) - 3} more)"
            return record("argocd", status, detail)
```

Add this module-level constant immediately after the existing `GITHUB_SERVICE = "k3dm-hermes-gh-token"` line:

```python
TERMINAL_OPERATION_FAILURES = ("Error", "Failed")
```

### Why `elif`, not a third `or`

An app already flagged by health/sync keeps its existing evidence string
unchanged. This keeps current alert text stable and makes the new signal additive
— it can only *add* apps to `bad`, never re-word an existing finding.

### Why `Error` and `Failed` only

ArgoCD operation phases are `Running`, `Terminating`, `Failed`, `Error`,
`Succeeded`. Only `Failed` and `Error` are terminal failures. `Running` and
`Terminating` are in-flight and MUST NOT alert — a sync in progress is normal.
An app with no `operationState` at all (e.g. `hub-loki`) yields `phase = None`,
which is not in the tuple, so it is correctly ignored.

## Change 2 — repair the name/project lookup

`argocd app list -o json` emits `v1alpha1.Application` objects, where the name
lives at `metadata.name` and the project at `spec.project` — not at the top level.
The current `app.get('name', 'unnamed')` therefore renders every real alert as
`default/unnamed Degraded/OutOfSync`, which names no app and is unactionable.

The `name` / `project` locals in Change 1 read the top-level key first and fall
back to the CR path, so both the existing unit-test fixtures (top-level keys) and
real CLI output resolve correctly. This is included because the evidence string is
the sensor's entire output value; an alert that cannot name the failing app does
not close the gap this bug is about.

```python
def test_argocd_flags_failed_operation_behind_green_status():
    def app(name, health, sync, phase):
        status = {"health": {"status": health}, "sync": {"status": sync}}
        if phase:
            status["operationState"] = {"phase": phase}
        return {"metadata": {"name": name}, "spec": {"project": "shop"}, "status": status}

    green_failed = json.dumps([app("identity", "Healthy", "Synced", "Failed")])
    state = {}
    results = [argocd(lambda *_: (0, green_failed), state, token="x") for _ in range(4)]
    assert [r["status"] for r in results] == ["healthy", "healthy", "healthy", "degraded"]
    assert "shop/identity" in results[-1]["evidence"]
    assert "last-op=Failed" in results[-1]["evidence"]

    green_error = json.dumps([app("data-layer", "Healthy", "Synced", "Error")])
    error_state = {}
    assert [argocd(lambda *_: (0, green_error), error_state, token="x")["status"]
            for _ in range(4)][-1] == "degraded"

    for benign in ("Succeeded", "Running", "Terminating", None):
        payload = json.dumps([app("ok", "Healthy", "Synced", benign)])
        out = argocd(lambda *_: (0, payload), {}, token="x")
        assert out["status"] == "healthy", f"phase {benign} must not alert"
        assert out["evidence"] == "1 applications healthy"


def test_argocd_evidence_names_apps_from_cr_shape_and_truncates():
    apps = [{"metadata": {"name": f"app{i}"}, "spec": {"project": "shop"},
             "status": {"health": {"status": "Degraded"}, "sync": {"status": "OutOfSync"}}}
            for i in range(5)]
    state = {}
    for _ in range(4):
        out = argocd(lambda *_: (0, json.dumps(apps)), state, token="x")
    assert out["status"] == "degraded"
    assert "shop/app0" in out["evidence"]
    assert "unnamed" not in out["evidence"]
    assert "(+2 more)" in out["evidence"]
```
