# Bug: seeder self-heal entrypoints unusable standalone

**Filed:** 2026-09-06
**Branch:** k3d-manager-v1.29.0
**Follow-up to:** commit `43ce7732` (self-healing bring-up seeders for grafana + cosign)

## Symptom

Running the two seeders standalone against the live cluster (Vault in namespace
`secrets`, release `vault`) both failed:

```
$ ./scripts/k3d-manager signing_restore secrets vault
Error making API request.
URL: GET http://127.0.0.1:8200/v1/sys/internal/ui/mounts/secret/cosign/signing
Code: 403. Errors:
* permission denied

$ ./scripts/k3d-manager _observability_seed_grafana_if_absent secrets vault
Error: '_observability_seed_grafana_if_absent' is private (names starting with '_' cannot be invoked).
```

`signing_status secrets vault` (which logs in) reported
`vault_key=present keychain_backup=present eso_public_secret=absent` — so the cosign
key material is fine, but the ESO public-key secret is the thing that actually needs
healing, and `signing_restore` is the entrypoint meant to heal it.

## Root cause

1. **`signing_restore` never calls `_vault_login`.** Its siblings all authenticate
   first — `signing_init` (signing.sh:359), `signing_rotate_key` (signing.sh:377),
   `signing_status` (signing.sh:407) — but `signing_restore` (signing.sh:385) jumps
   straight to `_signing_vault_key_exists`. `_vault_exec` only sends a token when
   `_VAULT_SESSION_TOKENS[<ns>/<release>]` is populated (vault.sh:261), which only
   `_vault_login` does. Without it every `vault` call in the restore path 403s.

2. **The grafana seed has no public entrypoint.** `_observability_seed_grafana_if_absent`
   is `_`-prefixed, so the dispatcher refuses to invoke it. Its only trigger today is a
   full `deploy_observability` run. A self-heal needs a standalone public function.

BATS did not catch either: the suites stub Vault, so the missing login is invisible,
and no test asserted a public grafana-seed entrypoint exists.

## Fix

### `scripts/plugins/signing.sh` — `signing_restore`

Add the login call right after the two `local` lines, mirroring the siblings:

```bash
function signing_restore() {
  local vault_ns="${1:-${VAULT_NS:-${VAULT_NS_DEFAULT:-vault}}}"
  local vault_release="${2:-${VAULT_RELEASE:-${VAULT_RELEASE_DEFAULT:-vault}}}"
  _vault_login "${vault_ns}" "${vault_release}"
  if _signing_vault_key_exists "${vault_ns}" "${vault_release}"; then
```

### `scripts/plugins/observability.sh` — new public wrapper

Add a public `observability_seed_grafana` that logs in and delegates to the private
seed. Place it immediately after `_observability_seed_grafana_if_absent`:

```bash
function observability_seed_grafana() {
  local vault_ns="${1:-secrets}" vault_release="${2:-vault}"
  _vault_login "${vault_ns}" "${vault_release}"
  _observability_seed_grafana_if_absent "${vault_ns}" "${vault_release}"
}
```

Defaults match the private seed and `_observability_apply_grafana_rotator`'s call
(`secrets`/`vault`), so the standalone path targets the same mount as bring-up.

## Follow-on (same live run): graceful skip when admission namespace absent

The live re-run exposed a third rough edge. On a cluster without the Kyverno
admission stack, `signing_restore`'s tail (`_signing_apply_pub_externalsecret`)
hard-failed with `namespaces "kyverno" not found` — the cosign public-key
ExternalSecret targets `SIGNING_ADMISSION_NAMESPACE` (default `kyverno`), which does
not exist until `deploy_image_signing` stands up admission. For an idempotent
self-heal entrypoint meant to be safe to run anytime, that error is misleading:
nothing consumes the public key until admission is deployed, so the step should be a
no-op, not a failure.

**Fix:** guard `_signing_apply_pub_externalsecret` — if the admission namespace does
not exist, `_warn` and `return 0` (skip) instead of applying and failing.

```bash
function _signing_apply_pub_externalsecret() {
  local template="${SCRIPT_DIR}/etc/signing/externalsecret-cosign-pub.yaml.tmpl"
  [[ -r "${template}" ]] || { _err "[signing] ESO template not found: ${template}"; return 1; }
  if ! _kubectl --no-exit get namespace "${SIGNING_ADMISSION_NAMESPACE}" >/dev/null 2>&1; then
    _warn "[signing] admission namespace ${SIGNING_ADMISSION_NAMESPACE} not found; skipping cosign public-key ExternalSecret (deploy image signing admission first)"
    return 0
  fi
  ...
}
```

Tests (`scripts/tests/plugins/signing.bats`): assert the function skips (no apply,
returns 0) when the namespace is absent, and applies when it exists.
