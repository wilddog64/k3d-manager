# Bugfix: v1.13.0 — webhook bats suite writes jobs into the live dir and fires false Slack orphan alerts

**Branch:** `k3d-manager-v1.13.0`
**Files:** `scripts/tests/lib/webhook.bats`

---

## Problem

The webhook bats suite does not isolate `K3DM_JOB_DIR`/`K3DM_RUN_DIR`, so its webhook
writes queued `/cluster` jobs into the **live** `:7443` instance's shared job dir
(`~/.local/share/k3d-manager/webhook-jobs/`). A `/cluster` job left `status == "running"`
when `teardown_file` kills the bats webhook is orphaned in that shared dir. On the next
live webhook restart, `_clear_stale_jobs()` (`bin/k3dm-webhook:1268-1288`) flips it to
`failed` and pushes a **false** Slack alert:

> ❌ *cluster-down* orphaned — webhook restarted mid-job; check cluster state manually (job `106cbbf0`)

The observed alert (job `106cbbf0`, `action=down`) traces to
`scripts/tests/lib/webhook.bats:403` — `@test "POST /cluster with action=down returns 202 and job_id"` —
whose fire-and-forget job was orphaned in the live dir by a pre-stub bats run.

**Root cause:** `setup_file()` boots the webhook without setting `K3DM_JOB_DIR`/`K3DM_RUN_DIR`,
so `config.py` (`JOB_DIR`/`RUN_DIR`, lines 27 & 30) falls back to the live default paths shared
with the running `:7443` instance. The `make`-stub (`e998dddb`) stops the Chrome launch but does
NOT stop the shared-dir pollution or the orphan alert.

This is the "Follow-up (out of scope)" flagged in
`docs/bugs/v1.13.0-bugfix-webhook-bats-live-make-isolation.md`, now upgraded from a cleanliness
issue to an active defect (live-dir mutation + false Slack alerts).

---

## Reproduction

```bash
bats scripts/tests/lib/webhook.bats
ls ~/.local/share/k3d-manager/webhook-jobs/   # new job dirs appear from the bats run
```

- **Expected:** the bats run leaves `~/.local/share/k3d-manager/webhook-jobs/` untouched (no new
  subdirs), and no Slack "cluster-<action> orphaned" alert fires on the next live webhook restart.
- **Actual:** the bats run creates job dirs in the live path; jobs left `running` at teardown are
  later reported as orphaned by the live instance.

---

## Fix

Isolate `K3DM_JOB_DIR`/`K3DM_RUN_DIR` to per-run temp dirs in `setup_file()` before booting the
webhook, and remove them in `teardown_file()`. Because these env vars are exported in `setup_file`,
each `@test` inherits them, so test 368 (`POST /cluster with response_url stored in job dir`) must
read the isolated `${K3DM_JOB_DIR}` path instead of the hardcoded live path — otherwise it breaks.

This is a **test-harness-only** change — `bin/k3dm-webhook` is not touched.

### Change 1 — `scripts/tests/lib/webhook.bats`: isolate job/run dirs before booting the server

**Exact old block (lines 28–34):**

```bash
    export _BATS_STUB_BIN
    _BATS_STUB_BIN="$(mktemp -d)"
    printf '#!/bin/sh\nexit 0\n' > "${_BATS_STUB_BIN}/make"
    chmod +x "${_BATS_STUB_BIN}/make"
    export PATH="${_BATS_STUB_BIN}:${PATH}"

    REPO_ROOT="$(cd "${BATS_TEST_DIRNAME}/../../.." && pwd)"
```

**Exact new block:**

```bash
    export _BATS_STUB_BIN
    _BATS_STUB_BIN="$(mktemp -d)"
    printf '#!/bin/sh\nexit 0\n' > "${_BATS_STUB_BIN}/make"
    chmod +x "${_BATS_STUB_BIN}/make"
    export PATH="${_BATS_STUB_BIN}:${PATH}"

    # Isolate job/run dirs so queued /cluster jobs never write into the live
    # :7443 instance's dir. Without this, a job left "running" when teardown_file
    # kills the webhook is orphaned in the live dir and fires a false Slack
    # "cluster-<action> orphaned" alert on the next live webhook restart.
    export K3DM_JOB_DIR K3DM_RUN_DIR
    K3DM_JOB_DIR="$(mktemp -d)"
    K3DM_RUN_DIR="$(mktemp -d)"

    REPO_ROOT="$(cd "${BATS_TEST_DIRNAME}/../../.." && pwd)"
```

### Change 2 — `scripts/tests/lib/webhook.bats`: remove the isolated dirs on teardown

**Exact old block (lines 46–49):**

```bash
teardown_file() {
    [[ -n "${_BATS_WEBHOOK_PID:-}" ]] && kill "${_BATS_WEBHOOK_PID}" 2>/dev/null || true
    [[ -n "${_BATS_STUB_BIN:-}" ]] && rm -rf "${_BATS_STUB_BIN}" || true
}
```

**Exact new block:**

```bash
teardown_file() {
    [[ -n "${_BATS_WEBHOOK_PID:-}" ]] && kill "${_BATS_WEBHOOK_PID}" 2>/dev/null || true
    [[ -n "${_BATS_STUB_BIN:-}" ]] && rm -rf "${_BATS_STUB_BIN}" || true
    [[ -n "${K3DM_JOB_DIR:-}" ]] && rm -rf "${K3DM_JOB_DIR}" || true
    [[ -n "${K3DM_RUN_DIR:-}" ]] && rm -rf "${K3DM_RUN_DIR}" || true
}
```

### Change 3 — `scripts/tests/lib/webhook.bats`: read the isolated job dir in test 368

**Exact old block (line 377):**

```bash
    job_file="${HOME}/.local/share/k3d-manager/webhook-jobs/${job_id}/response_url"
```

**Exact new block:**

```bash
    job_file="${K3DM_JOB_DIR}/${job_id}/response_url"
```
