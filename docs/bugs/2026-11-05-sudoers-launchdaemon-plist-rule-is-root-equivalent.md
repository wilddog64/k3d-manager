# Bug: LaunchDaemon and exec wildcard sudoers rules are root-equivalent

**Status:** OPEN — design needed; not dispatched
**Priority:** P1
**Severity:** high — local privilege escalation through rules that headless `acg-up` currently relies on.
**Filed:** 2026-11-05
**Detected by:** `docs/issues/2026-11-02-acg-phase-c-privileged-inventory.md` (Terra Phase C worktree), confirmed by Claude against `bin/install-sudoers.sh` at `7c9927e9`.
**Branch:** `k3d-manager-v1.43.14`
**Approval:** operator, 2026-11-05: "go with your recommendation" (B plus C). Claude has since found that B is insufficient (see the finding below). The amended design is pending the operator; not dispatched.
**Related:** `docs/bugs/2026-11-05-sudoers-passwordless-rules-grant-root-escalation.md` (narrow fix, dispatched first)

## Evidence

- `NOPASSWD: /usr/bin/install -m 644 * /Library/LaunchDaemons/com.k3d-manager.*.plist` together with `NOPASSWD: /bin/launchctl bootstrap system /Library/LaunchDaemons/com.k3d-manager.*.plist`.
  The caller writes the plist, chooses its `ProgramArguments`, and bootstraps it as a root daemon.
  Headless callers: `bin/cluster-up:906,1573,1748,1813` and `scripts/lib/providers/k3s-hostinger.sh:730`.
- `NOPASSWD: /bin/rm -f /Library/LaunchDaemons/com.k3d-manager.*.plist *`: the trailing `*` lets the caller delete any file as root.
- `NOPASSWD: /usr/local/bin/k3s *`, `/usr/bin/systemctl *`, `/usr/bin/apt-get *`, `dnf *`, `yum *` and `microdnf *` are each root-equivalent wherever the binary exists (for example `apt-get -o APT::Update::Pre-Invoke::=...`).
  They are harmless on macOS only while those paths stay absent.

## Design options (for the operator)

- **A.** A root-owned plist installer: `/usr/local/bin/k3d-manager-install-daemon <label> <port>...`. It renders each plist from a fixed template in a root-owned directory and accepts only allowlisted labels and numeric ports. The sudoers file would then allow only this helper.
- **B.** Drop passwordless plist install entirely. The listeners are installed once with a password by a `make browser-listeners` target, and headless runs only `bootstrap`/`bootout` the existing root-owned plists.
- **C.** Split the sudoers file per OS so the Linux wildcards never appear on macOS, and the reverse.

Recommendation: B plus C. They are the smallest change and need no new privileged code, which is the lesson from `2026-11-02-acg-up-stalls-at-system-keychain-trust`.

## Finding: option B is insufficient (Claude, M4, 2026-11-05)

The root daemons run user-writable code, so a user-level process gets root **without any sudoers rule**:
- All four browser-listener daemons run as root: no `UserName` key, with `KeepAlive` true. Their `ProgramArguments` is `/bin/bash <wrapper>`, and every wrapper is owned by the user:
  - `~/.local/share/k3d-manager/k3s-aws/bin/{argocd-browser-https,keycloak-browser-http,frontend-browser-http}.sh`
  - `~/.local/share/k3d-manager/bin/frontend-browser-http.sh`
  - All are `cliang:staff`, generated by `bin/cluster-up` (for example `_argocd_write_browser_https_wrapper`, around line 859).
- The wrappers run Homebrew's `socat` and `curl` as root. `/opt/homebrew/bin/socat` is also owned by the user.
- Editing a wrapper (or `socat`) runs the edit as root at the next `KeepAlive` respawn. The remaining passwordless `launchctl bootout`/`bootstrap` rules make that respawn immediate.
- Moving the listeners off root is not possible as-is. A non-root bind of `127.0.0.1:81` and of `127.0.0.1:444` fails with `PermissionError: [Errno 13]`, because macOS exempts only wildcard binds from the privileged-port check.

The fix must therefore stop root from executing anything user-writable, not only remove sudoers rules. The candidate designs are pending the operator's choice:
- **D1. pf redirect.** A one-time, password-gated pf anchor redirects `127.0.0.x:443/80` to user high ports. The listeners become user LaunchAgents, so there is no root daemon. The LaunchDaemon sudoers rules and the system plists are removed. Needs a spike: pf `rdr` on `lo0` for local traffic is unverified here.
- **D2. Root-owned runtime.** A one-time, password-gated install puts static wrappers, plus pinned copies of `socat` and `curl`, in a root-owned directory (`/usr/local/libexec/k3d-manager`, `root:wheel` 0755). Per-sandbox values (ports, cert paths) come from a data file that the wrapper validates strictly and never sources. Headless runs only `bootout`/`bootstrap`. This keeps a root process that parses user data.
- C (split sudoers per OS) applies to either.

## Acceptance

To be written once D1 or D2 is chosen.
