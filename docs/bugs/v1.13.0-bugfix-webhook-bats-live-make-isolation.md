# Bugfix: v1.13.0 — webhook bats suite runs live `make up` and launches Chrome

**Branch:** `k3d-manager-v1.13.0`
**Files:** `scripts/tests/lib/webhook.bats`

---

## Problem

Running the webhook bats suite (`bats scripts/tests/lib/webhook.bats`) still pops a Chrome
window every run, even after the `K3DM_GEMINI_BIN` stub (`7231e3ff`) closed the `agy`
analysis path. The `POST /api/v1/cluster` tests return `202` immediately, but the handler
queues a **background daemon job** that runs the real `make up` — and for the aws/gcp
providers `make up` drives Playwright Chromium (Chrome).

**Root cause:** `setup_file()` in `webhook.bats` boots the real webhook and lets queued
`/cluster` jobs execute the real `make`. `_run_cluster` (`bin/k3dm-webhook:444-445`) runs
`["make", "up", "CLUSTER_PROVIDER=k3s-aws"]`, and the k3s-aws provider
(`scripts/lib/providers/k3s-aws.sh:48`) calls `acg_extend_playwright`, which launches
Chromium. Four tests trigger this every run:

| bats test | line | queued command |
|-----------|------|----------------|
| `POST /cluster with provider=gcp` | 146 | `make up CLUSTER_PROVIDER=k3s-gcp` |
| `POST /cluster with unknown provider defaults to aws` | 157 | `make up CLUSTER_PROVIDER=k3s-aws` |
| `POST /cluster with response_url stored in job dir` (provider=aws) | 357 | `make up CLUSTER_PROVIDER=k3s-aws` |
| `POST /cluster with action=up` (default provider aws) | 381 | `make up CLUSTER_PROVIDER=k3s-aws` |

> This is the "Follow-up (out of scope)" flagged in
> `docs/bugs/v1.13.0-bugfix-webhook-bats-agy-isolation.md`. That fix closed the minor
> `agy`/`_call_gemini` leak; this closes the dominant `make up` → `acg_extend_playwright`
> leak. `/cluster-refresh` (test 264) runs `bin/cluster-refresh --no-login-prompt`, which
> suppresses the interactive browser — it is NOT a culprit and needs no change.

---

## Reproduction

```bash
bats scripts/tests/lib/webhook.bats
```

- **Expected:** all tests pass with no GUI side effects.
- **Actual:** all tests pass, but a Chrome window opens (from the `make up` jobs spawned by
  the four `/cluster` 202-returning tests above).

---

## Fix

Stub `make` with a no-op on `PATH` in `setup_file()` before booting the webhook.
`_posix_spawn_job` (`bin/k3dm-webhook:349-367`) executes queued cluster jobs as
`bash -c "cd REPO && make up …"`, resolving `make` from the inherited `PATH`, so a no-op
`make` on `PATH` neutralizes every live `make up`/`make down`/resume job at once. The
`/cluster` tests only assert the `202`/`queued` response (fire-and-forget), so a no-op
`make` changes no assertion. After `make` returns 0, the only follow-on spawns are
`kubectl` via `_posix_spawn_capture` (no browser) and `_call_gemini` (already stubbed to
`/usr/bin/true` by `7231e3ff`) — so together the two stubs close every browser path.

This is a **test-harness-only** change — `bin/k3dm-webhook` is not touched, keeping the
in-flight webhook modularization clean.

### Change 1 — `scripts/tests/lib/webhook.bats`: stub `make` before booting the server

**Exact old block (lines 15–26):**

```bash
setup_file() {
    export K3DM_WEBHOOK_TOKEN
    K3DM_WEBHOOK_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(16))')"
    export K3DM_WEBHOOK_PORT="${_WEBHOOK_PORT}"

    # Stub the analysis binary so queued /analyze and /diagnostics jobs cannot
    # spawn the real agy CLI (which launches Chrome via ACG browser automation).
    export K3DM_GEMINI_BIN="/usr/bin/true"

    REPO_ROOT="$(cd "${BATS_TEST_DIRNAME}/../../.." && pwd)"
    python3 "${REPO_ROOT}/bin/k3dm-webhook" &
    export _BATS_WEBHOOK_PID=$!
```

**Exact new block:**

```bash
setup_file() {
    export K3DM_WEBHOOK_TOKEN
    K3DM_WEBHOOK_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(16))')"
    export K3DM_WEBHOOK_PORT="${_WEBHOOK_PORT}"

    # Stub the analysis binary so queued /analyze and /diagnostics jobs cannot
    # spawn the real agy CLI (which launches Chrome via ACG browser automation).
    export K3DM_GEMINI_BIN="/usr/bin/true"

    # Stub make so queued /cluster jobs cannot run the real make up/down, which
    # for the aws/gcp providers drives acg_extend_playwright -> Chromium (Chrome).
    # _posix_spawn_job runs `bash -c "cd REPO && make ..."`, resolving make from
    # PATH, so a no-op stub on PATH neutralizes every live cluster job.
    export _BATS_STUB_BIN
    _BATS_STUB_BIN="$(mktemp -d)"
    printf '#!/bin/sh\nexit 0\n' > "${_BATS_STUB_BIN}/make"
    chmod +x "${_BATS_STUB_BIN}/make"
    export PATH="${_BATS_STUB_BIN}:${PATH}"

    REPO_ROOT="$(cd "${BATS_TEST_DIRNAME}/../../.." && pwd)"
    python3 "${REPO_ROOT}/bin/k3dm-webhook" &
    export _BATS_WEBHOOK_PID=$!
```

### Change 2 — `scripts/tests/lib/webhook.bats`: remove the stub dir on teardown

**Exact old block (lines 36–38):**

```bash
teardown_file() {
    [[ -n "${_BATS_WEBHOOK_PID:-}" ]] && kill "${_BATS_WEBHOOK_PID}" 2>/dev/null || true
}
```

**Exact new block:**

```bash
teardown_file() {
    [[ -n "${_BATS_WEBHOOK_PID:-}" ]] && kill "${_BATS_WEBHOOK_PID}" 2>/dev/null || true
    [[ -n "${_BATS_STUB_BIN:-}" ]] && rm -rf "${_BATS_STUB_BIN}" || true
}
```

## Follow-up (out of scope — do NOT implement here)

The bats suite still does not isolate `K3DM_JOB_DIR`/`K3DM_RUN_DIR`, so its
`_clear_stale_jobs()` mutates the live `:7443` instance's job dir. Isolating those dirs is
complicated by test 357 (`POST /cluster with response_url stored in job dir`), which reads
the hardcoded live path `${HOME}/.local/share/k3d-manager/webhook-jobs/${job_id}/response_url`
— isolating `K3DM_JOB_DIR` breaks that test unless it is updated to read the isolated dir.
File a separate bugfix to (a) isolate `K3DM_JOB_DIR`/`K3DM_RUN_DIR` in `setup_file()` and
(b) update test 357 to read the isolated path. Not part of this Chrome fix.
