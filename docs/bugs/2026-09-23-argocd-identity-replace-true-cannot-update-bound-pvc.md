# `shopping-cart-identity` is permanently OutOfSync: `Replace=true` cannot update a bound PVC

**Filed:** 2026-09-23
**Branch:** `k3d-manager-v1.37.0`
**Severity:** Medium — the Application has been unable to sync since at least 2026-09-21, so no
identity manifest change reaches the cluster, and `keycloak-realm-reconcile` has been `Failed 0/1`
for 2d1h. Nothing is currently broken at runtime (`health: Healthy`), which is why it has gone
unnoticed.
**Status:** FIX LANDED in `shopping-cart-infra` `00d0d8a` (#101, "exempt bound PVCs from Replace=true so shopping-cart-identity can sync"), seen 2026-09-30 — live confirmation pending: Hermes `argocd` should stop reporting `shopping-cart-identity Healthy/OutOfSync`.

## Symptom

```

```

```
one or more synchronization tasks completed unsuccessfully, reason: error when replacing
"/dev/shm/1481311740": PersistentVolumeClaim "postgres-keycloak-pvc" is invalid:
spec: Forbidden: spec is immutable after creation except resources.requests and
volumeAttributesClassName for bound claims
- 	VolumeName:       "pvc-e32941a3-014a-4149-b102-6d478871be37",
+ 	VolumeName:       "",
- 	StorageClassName: &"local-path",
+ 	StorageClassName: nil,
  (retried 5 times).
```

The live PVC is `Bound` to `pvc-e32941a3-014a-4149-b102-6d478871be37` on `local-path`.

## Root cause

The Application sets:

```json
"syncOptions": ["CreateNamespace=true", "Replace=true"]
```

`Replace=true` makes ArgoCD issue `kubectl replace` rather than apply/patch. The git manifest
legitimately omits `volumeName` and `storageClassName` — both are assigned by the cluster at bind
time — so the replacement spec blanks them. A **bound** PVC's spec is immutable apart from
`resources.requests` and `volumeAttributesClassName`, so the API server rejects the whole
replacement, and because a sync is atomic every other resource in the Application is held back with
it.

This is not drift and not a manifest error. Any `Replace=true` Application containing a bound PVC
will wedge itself the same way on its first resync after the PVC binds.

The earlier read of this defect — "needs `ignoreDifferences`" — was incomplete. `ignoreDifferences`
alone does not fix a `Replace=true` sync, because the replacement payload is the whole object.

## Where the fix goes — not in this repo

```json
"sources": [
  {"repoURL": "https://github.com/wilddog64/shopping-cart-infra.git", "path": "identity/keycloak"},
  {"repoURL": "https://github.com/wilddog64/shopping-cart-infra.git", "path": "identity/ldap"}

```

The Application has **no `ownerReferences`** and is not generated by any ApplicationSet — it is
excluded from `services-git` by
`docs/bugs/v1.4.5-bugfix-services-git-identity-exclude.md`. It is applied out-of-band, so this
cannot be fixed by editing `scripts/etc/argocd/applicationsets/`. Locate the applying manifest
before writing any change.

## Fix options, preferred first

1. **Per-resource override (surgical).** Annotate only the PVC in `shopping-cart-infra`:
   ```yaml
   metadata:
     annotations:
       argocd.argoproj.io/sync-options: Replace=false
   ```
   Keeps `Replace=true` wherever it was actually needed and exempts the one object that cannot
   tolerate it.
2. **Drop `Replace=true` from the Application** and let ArgoCD apply/patch. Requires knowing why it
   was set; if it was added to force through an immutable-field conflict elsewhere, removing it
   trades this failure for that one.
3. **`ignoreDifferences` on `spec.volumeName` and `spec.storageClassName` plus
   `RespectIgnoreDifferences=true`.** Correct for ordinary drift suppression and worth having, but
   **insufficient on its own** while `Replace=true` stands.

Do not "fix" this by deleting and recreating the PVC. It is Keycloak's Postgres data on
`local-path`, whose `reclaimPolicy` is `Delete`.

**A plain sync does not clear this and should not be attempted as a remedy.** The failure is
deterministic: the API server rejects the replacement every time, the retry limit is 5, and a
`Failed` operation phase blocks self-heal
(`reference_argocd_selfheal_reverts_out_of_band_patch` / `argocd_error_phase_blocks_selfheal`).
Syncing again only reproduces the same 8-minute failure.

**Correction to the Verification section above.** That section asks whether the `Failed 0/1`
`keycloak-realm-reconcile` Job was caused by this sync failure, flagging the link as inferred.
It was not. The two pod logs end:

```
Creating browser-with-conditional-otp flow...
environment: line 104: awk: command not found
```

The Keycloak image is `ubi9-micro`, which ships bash, grep and sed but **no `awk`, `jq` or
`python3`** (`reference_keycloak_image_has_no_awk`). That is an independent defect in the
reconcile script, and it is the actual root cause of the two red SSO lines. Fixing the
`Replace=true` PVC problem will let the Job be *created*; it will then fail again on the missing
`awk` until the script parses CSV in bash instead. **Two fixes are required, not one** — and
because this one blocks the Job from existing at all, it must land first or the awk fix cannot be
observed.

`realm-shopping-cart.json` at 12,429 bytes, far under the 262,144-byte last-applied-annotation limit.
Server-side apply covers size anyway.

### F1 — fix (`bin/cluster-up` + `scripts/tests/bin/cluster_up.bats` only)

In the Step 10c `shopping-cart-identity` heredoc:

1. In `syncOptions`, replace `- Replace=true` with `- ServerSideApply=true`. Keep
   `- CreateNamespace=true`.
2. Under `metadata.annotations`, next to the existing `argocd.argoproj.io/sync-wave: "-1"`, add
   `argocd.argoproj.io/compare-options: ServerSideDiff=true`. Without it, SSA leaves the app perpetually
   OutOfSync with no real diff; see `reference_argocd_ssa_without_ssdiff_perpetual_outofsync`.
3. No other change to the heredoc, the wait loop or the timeout.
