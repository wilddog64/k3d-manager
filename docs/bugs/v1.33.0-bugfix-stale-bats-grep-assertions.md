## Root cause 1 — `/readyz` probe leaks into the dry-run assertion (failures #1, #2)

`scripts/lib/provider.sh:235` defines `_acg_context_reachable`, which runs a bare
`kubectl --context "${ctx}" --request-timeout=5s get --raw=/readyz`. It is called from
`_acg_resolve_provider` (`scripts/lib/provider.sh:246`) whenever `CLUSTER_PROVIDER` is
**unset**, to pick a live context.

The suite runs each case under `env -i` with a `BASE_ENV` allowlist that does **not**
include `CLUSTER_PROVIDER`. So provider auto-detection runs, and because
`test_helpers.bash`'s `stub_kubectl_command` routes bare `kubectl` into `_kubectl`, the
probe is logged to `KUBECTL_LOG`. The test then asserts `[ ! -s "$KUBECTL_LOG_PATH" ]`
and fails.

Measured — the log after `--dry-run` contains exactly one line, the probe and nothing else:

```
--context ubuntu-hostinger --request-timeout=5s get --raw=/readyz
```

**Second, more important effect.** `_kubectl` also consumes one entry from
`KUBECTL_EXIT_CODES` per call. So in the two tests that script exit codes —
`errors when namespace missing` (`KUBECTL_EXIT_CODES=(1 0 0 0 0)`) and
`errors when ESO CRDs missing` (`(0 0 1 0 0)`) — the **probe eats the first scripted
code**. Those two tests currently pass, but for the wrong reason: the code intended for
the namespace check is being fed to a reachability probe. Pinning `CLUSTER_PROVIDER`
realigns them with their documented intent.

### Fix — pin `CLUSTER_PROVIDER` in `BASE_ENV`

The suite is pure logic and must not depend on ambient context detection.

In `scripts/tests/plugins/argocd_deploy_keys.bats`, find:

```bash
  BASE_ENV=(
    "PATH=$PATH"
    "BATS_TEST_DIRNAME=$BATS_TEST_DIRNAME"
    "BATS_TEST_TMPDIR=$BATS_TEST_TMPDIR"
    "HOME=$HOME"
    "ARGOCD_NAMESPACE=cicd"
```

Replace with:

```bash
  BASE_ENV=(
    "PATH=$PATH"
    "BATS_TEST_DIRNAME=$BATS_TEST_DIRNAME"
    "BATS_TEST_TMPDIR=$BATS_TEST_TMPDIR"
    "HOME=$HOME"
    "CLUSTER_PROVIDER=k3s-hostinger"
    "ARGOCD_NAMESPACE=cicd"
```

Change nothing else in this file. Verified by Claude: this makes all 8 tests in the
suite pass, tests 4 and 5 included.

## Root cause 2 — frozen whole-line literal in the allowlist test (failure #3)

`workers/slack-relay/index.js:1` gained `/cleanup-stale-sandbox`:

```js
const ALLOWED_COMMANDS = new Set(['/cluster-up', '/cluster-down', '/cluster-status', '/cluster-diagnose', '/cluster-refresh', '/cluster-resume', '/hostinger-status', '/cleanup-stale-sandbox', '/ask', '/claude', '/gemini', '/codex', '/argocd-upgrade'])
```

The test `grep -F`s the **entire previous line**, so any addition to the set breaks it.
The worker and `docs/howto/slack-slash-commands.md` are both already correct and
consistent — only the test is stale.

### Fix — assert membership per command, not the whole line

Do NOT simply paste the new line in; it would break again on the next command added.
Scope the assertion to what the test actually means: every required command is a member.

In `scripts/tests/plugins/slack_slash_commands.bats`, find:

```bash
@test "slack relay allowlist includes cluster-status and hostinger-status" {
  run grep -F -- "const ALLOWED_COMMANDS = new Set(['/cluster-up', '/cluster-down', '/cluster-status', '/cluster-diagnose', '/cluster-refresh', '/cluster-resume', '/hostinger-status', '/ask', '/claude', '/gemini', '/codex', '/argocd-upgrade'])" "${WORKER}"
  [ "${status}" -eq 0 ]
}
```

Replace with:

```bash
@test "slack relay allowlist includes cluster-status and hostinger-status" {
  run grep -F -- 'const ALLOWED_COMMANDS = new Set([' "${WORKER}"
  [ "${status}" -eq 0 ]

  local _allowlist
  _allowlist="$(grep -m1 -F -- 'const ALLOWED_COMMANDS = new Set([' "${WORKER}")"

  local _cmd
  for _cmd in /cluster-up /cluster-down /cluster-status /cluster-diagnose \
              /cluster-refresh /cluster-resume /hostinger-status /ask /claude \
              /gemini /codex /argocd-upgrade; do
    if [[ "${_allowlist}" != *"'${_cmd}'"* ]]; then
      echo "ALLOWED_COMMANDS is missing ${_cmd}: ${_allowlist}"
      return 1
    fi
  done
}
```

Note this is a **narrowing**, not a weakening: each of the 12 commands is still
individually required to be present. Additions to the set no longer break the gate.

## Root cause 3 — frozen whole-line literal in the ack test (failure #4)

`workers/slack-relay/index.js:212` now destructures `conflict` and passes `meta`:

```js
      const { ok, conflict } = await relay('/api/v1/cluster-status', payload, meta)
```

The test `grep -F`s the old form, `const { ok } = await relay('/api/v1/cluster-status', payload)`.

This test was previously mislabeled by Claude as a "load-dependent flake". That was
wrong: it is a `grep` against a static file and fails 3/3 in isolation. Recording the
correction here so nobody re-investigates it as a concurrency problem.

### Fix — assert the relay target, not the destructuring shape

The test's intent is "the ack is returned before the relay call is awaited". The
destructured variable names are incidental.

In `scripts/tests/plugins/slack_relay_ack.bats`, find:

```bash
  run grep -F -- "const { ok } = await relay('/api/v1/cluster-status', payload)" "${WORKER}"
  [ "${status}" -eq 0 ]
```

Replace with:

```bash
  run grep -E -- "await relay\('/api/v1/cluster-status', payload" "${WORKER}"
  [ "${status}" -eq 0 ]
```

Leave the first assertion in that test (the `jsonReply` ack line) untouched — it passes.
