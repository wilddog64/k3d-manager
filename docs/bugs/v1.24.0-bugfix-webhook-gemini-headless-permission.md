# Bugfix: v1.24.0 — webhook `_call_gemini` headless command-permission auto-deny

**Branch:** `k3d-manager-v1.24.0`
**Files:** `bin/k3dm-webhook`

---

## Problem

When a `TrivyCriticalVulnerabilityDetected` (ours) alert reaches the analyze route, the Slack analysis
posts:

> jetski: no output produced — a tool required the command permission that headless mode cannot prompt
> for, so it was auto-denied

instead of an actual CVE analysis. The v1.23.0 alert-noise fix reduced this to ≤1/12h (no longer a
flood), but the surviving analysis is still broken.

**Root cause:** `_call_gemini` (`bin/k3dm-webhook:1162`) runs `agy --model <GEMINI_MODEL> --prompt
<prompt>` headless via `os.posix_spawn` with no TTY. The model attempts a **tool call** (e.g. a shell
command to inspect the cluster), which in headless mode has no interactive approver, so `agy`
auto-denies the tool and returns no output. The webhook already feeds all needed cluster/alert state
*into* the prompt, so the model should not need tools at all for this call.

---

## Reproduction

```bash
agy --model "$GEMINI_MODEL" --prompt "Analyze this alert and run kubectl to inspect the cluster"
# → headless: tool auto-denied, no output
```

Or trigger a `wilddog64/*` TrivyCritical alert and watch the analyze Slack post.

---

## Fix

**Step 0 — flag discovery DONE (2026-08-10, `agy --help`).** `agy` exposes **no** tool-disable /
tool-allowlist / `--approval-mode` flag. The only permission-related flag is
`--dangerously-skip-permissions` (blanket auto-approve — the privilege concern the "What NOT to Do"
section forbids). `--mode plan` exists but plan mode still permits read-only tool calls, so it does not
reliably stop the auto-deny. **Conclusion: the preferred "tool-free flag" path is unavailable → the
prompt-guard fallback below is the authoritative fix.** (Full flag list captured in
`reference_agy_model_id_drift` follow-up.)

**Fix (authoritative) — guard the prompt so the model never attempts a tool call.** All callers route
through `_call_gemini`, so prepend a single tool-suppression guard there; it covers every call site
(analyze-stall, TrivyCritical analysis, hub/app status analysis) uniformly. The webhook already feeds
all needed cluster/alert state *into* the prompt, so no tool is required.

### Change 1 — `bin/k3dm-webhook`: prepend a headless tool-suppression guard

**Exact old block (line 1163):**
```python
        cmd = [resolved, "--model", GEMINI_MODEL, "--prompt", prompt]
```

**Exact new block:**
```python
        guarded = (
            "You are analyzing pre-collected data in a HEADLESS session with no "
            "interactive approver. Do NOT run any commands or call any tools — a tool "
            "call is auto-denied and yields no answer. Answer ONLY from the text below; "
            "if it is insufficient, say so briefly.\n\n" + prompt
        )
        cmd = [resolved, "--model", GEMINI_MODEL, "--prompt", guarded]
```

### Change 2 — `bin/k3dm-webhook`: make the auto-deny case legible

If a tool call still slips through, surface a clear, non-alarming message instead of the raw jetski
string.

**Exact old block (lines 1184–1186):**
```python
        raw = Path(tmp_path).read_text(errors="replace").strip()
        Path(tmp_path).unlink(missing_ok=True)
        raw = raw or "agy returned no output"
```

**Exact new block:**
```python
        raw = Path(tmp_path).read_text(errors="replace").strip()
        Path(tmp_path).unlink(missing_ok=True)
        if "headless mode" in raw and "auto-denied" in raw:
            return "agy analysis skipped — headless tool use disabled"
        raw = raw or "agy returned no output"
```

**Do NOT** add `--dangerously-skip-permissions` — the guard makes it unnecessary and it would grant an
unattended webhook blanket tool execution (privilege concern).
