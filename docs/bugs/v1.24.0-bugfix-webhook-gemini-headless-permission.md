# Bugfix: v1.24.0 — webhook `_call_gemini` headless command-permission auto-deny

**Branch:** `k3d-manager-v1.24.0`
**Files:** `bin/k3dm-webhook`

---

## Problem

When a `TrivyCriticalVulnerabilityDetected` (ours) alert reaches the analyze route, the Slack analysis
posts:

> jetski: no output produced — a tool required the command permission that headless mode cannot prompt
> for, so it was auto-denied

instead of an actual CVE analysis. The v1.23.0 alert-noise fix reduced this to ≤1/12h (no longer a
flood), but the surviving analysis is still broken.

**Root cause:** `_call_gemini` (`bin/k3dm-webhook:1162`) runs `agy --model <GEMINI_MODEL> --prompt
<prompt>` headless via `os.posix_spawn` with no TTY. The model attempts a **tool call** (e.g. a shell
command to inspect the cluster), which in headless mode has no interactive approver, so `agy`
auto-denies the tool and returns no output. The webhook already feeds all needed cluster/alert state
*into* the prompt, so the model should not need tools at all for this call.

---

## Reproduction

```bash
agy --model "$GEMINI_MODEL" --prompt "Analyze this alert and run kubectl to inspect the cluster"
# → headless: tool auto-denied, no output
```

Or trigger a `wilddog64/*` TrivyCritical alert and watch the analyze Slack post.

---

## Fix

**Step 0 — discover the correct flag (`agy` retires flags like it retires model ids, see
`reference_agy_model_id_drift`):**
```bash
agy --help 2>&1 | grep -iE 'tool|approval|permission|yolo|prompt|non-?interactive|dangerous'
```

**Preferred fix — run analysis tool-free.** The webhook supplies the context in the prompt, so disable
tool use for this call. Adjust the `cmd` in `_call_gemini` to pass whatever `agy` exposes for
"analysis only / no tools" (e.g. a `--no-tools` / `--approval-mode=none` / tool-allowlist-empty flag —
confirm the real name from Step 0). Illustrative:

```python
        cmd = [resolved, "--model", GEMINI_MODEL, "--prompt", prompt]
```
→
```python
        cmd = [resolved, "--model", GEMINI_MODEL, <no-tools/approval flag>, "--prompt", prompt]
```

**Fallback if `agy` has no tool-disable flag** — prepend a prompt guard instructing the model to answer
only from the provided text and never call tools, and (only if unavoidable and safe) an auto-approve
flag. Auto-approving tool execution in an unattended webhook is a privilege concern — prefer the
tool-free path; do NOT add a blanket `--yolo`/`--dangerously-skip-permissions` without the user's
explicit sign-off.

**Also:** the empty-output guard already returns `"agy returned no output"` — make the auto-deny case
legible by detecting the permission phrase and returning a clearer, non-alarming message
(`"agy analysis skipped — headless tool use disabled"`) rather than surfacing the raw jetski string.
