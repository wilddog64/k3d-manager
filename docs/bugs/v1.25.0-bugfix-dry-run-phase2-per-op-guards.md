## Problem (recap)

`DRY_RUN=1` is honored in exactly one place today (`_k3s_aws_deregister_cluster`). Everywhere else,
`DRY_RUN=1 make up/down` **provisions/tears down for real** — a "dry run" that destroys is a footgun.
Phase 2 gates every destructive/provisioning side-effect on the two released primitives.

---

## The two forms (memorize this — it is the whole task)

The helpers already exist and are sourced. You only ADD guards; you do not define helpers.

```bash
# _dry_guard: wrap ONE command (single argv, no pipes/redirs/subshells). In DRY_RUN it logs and skips (rc 0).
_dry_guard "delete EC2 stack" acg_teardown --confirm

# _dry_run_active: gate a MULTI-STEP block (pidfile read + kill + rm, launchctl + rm, pipelines, conditionals).
if _dry_run_active; then
  _info "DRY_RUN: would stop Vault port-forward"
else
  <the original multi-step block, unchanged>
fi
```

**Mechanical rule — apply everywhere:** *does this line change cluster or host state?*
(installs, `deploy_*`, `k3d cluster create/start/delete`, `launchctl load/bootout/bootstrap/unload`,
`kill`, `rm` of live state, `docker system prune`, cloud-CLI create/delete, `tunnel_start`/`tunnel_stop`,
`acg_provision`/`acg_teardown`, `_run_command` that writes) → **guard it**. If it only reads state
(`kubectl get`, `k3d cluster list`, `launchctl list`, `aws sts`, `--help`/`--confirm` arg validation) →
**leave it unguarded** (a dry run must still read state and print an accurate plan).

**Preservation rules (do not weaken):**
- Keep every existing `|| true`, `|| return 1`, `|| _info/_warn`, `--ignore-not-found`, rc-capture. In DRY_RUN
  `_dry_guard` returns 0, so a trailing `|| fallback` is simply skipped — correct.
- Never wrap a command whose side-effect already ran (evaluating args is fine; the guarded token must be the
  mutating command itself).
- No secrets in the `_desc` string — human description only, never tokens/keys/argv with credentials.

- `shellcheck -S warning` clean on every changed file (zero new warnings vs. the branch baseline).
- Read-only probes are **never** guarded. `_dry_guard` wraps one command; multi-step blocks use `_dry_run_active`.
- Do not weaken any existing `|| true` / `--ignore-not-found` / rc handling.
- No secrets in the `_desc` strings.
- Do **not** redefine `_dry_run_active`/`_dry_guard` (already synced in `scripts/lib/system.sh`).
- Do **not** touch `_k3s_aws_deregister_cluster` (self-guards; Phase 3, separate).
- Do **not** touch files outside the six listed targets.
