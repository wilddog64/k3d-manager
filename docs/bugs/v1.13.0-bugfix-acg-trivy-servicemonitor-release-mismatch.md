# Bugfix: v1.13.0 — ACG trivy metrics missing (ServiceMonitor `release` label mismatch)

**Branch:** `k3d-manager-v1.13.0`
**Files:** `scripts/etc/helm/observability/trivy-operator-acg-values.yaml` (new), `scripts/etc/argocd/applicationsets/observability-acg.yaml`

---

## Problem

`make status` prints, for the app cluster:

```
INFO: [observability] Trivy infra security summary — ACG (ubuntu-hostinger):
INFO: [observability]   (no cluster compliance metrics found)
```

even though the ACG `ClusterComplianceReport` CRs exist and carry results (CIS fail=4,
NSA fail=3, updated live). So the compliance **data** is present — the **metrics** are not.

**Root cause:** ServiceMonitor `release`-label mismatch. Both the hub `observability` and the
app `observability-acg` ApplicationSets render the trivy-operator chart from the **same**
`scripts/etc/helm/observability/trivy-operator-values.yaml`, which hardcodes:

```yaml
serviceMonitor:
  labels:
    release: kube-prometheus-stack
```

The hub Prometheus selects ServiceMonitors with `release: kube-prometheus-stack` — correct
on the hub. But the **ACG** Prometheus (`acg-kube-prometheus-stack`) has
`serviceMonitorSelector.matchLabels.release: acg-kube-prometheus-stack`, so it never selects
the `acg-trivy-operator` ServiceMonitor. Result: ACG Prometheus scrapes **zero** `trivy_*`
metrics, and `_trivy_prom_query` (which execs into the ACG cluster's own Prometheus) returns
empty for `sum by (title,status) (trivy_cluster_compliance)`.

---

## Reproduction

```
# ACG ServiceMonitor label (wrong for ACG Prometheus):
kubectl --context ubuntu-hostinger -n trivy-system get servicemonitor acg-trivy-operator \
  -o jsonpath='{.metadata.labels.release}'          # -> kube-prometheus-stack

# ACG Prometheus requires a different release label:
kubectl --context ubuntu-hostinger -n monitoring get prometheus \
  -o jsonpath='{.items[0].spec.serviceMonitorSelector.matchLabels.release}'   # -> acg-kube-prometheus-stack

# ACG Prometheus has no trivy metrics:
kubectl --context ubuntu-hostinger -n monitoring exec \
  statefulset/prometheus-acg-kube-prometheus-stack-prometheus -c prometheus -- \
  sh -lc "wget -qO- 'http://localhost:9090/api/v1/query?query=count(%7B__name__%3D~%22trivy_.%2A%22%7D)'"
# -> {"status":"success","data":{"resultType":"vector","result":[]}}
```

Expected: ACG Prometheus scrapes `trivy_*`, and `make status` shows ACG cluster-compliance.
Actual: empty — `(no cluster compliance metrics found)`.

---

## Fix

Give the ACG trivy-operator its own values file whose ServiceMonitor `release` label matches
the ACG Prometheus release, mirroring the existing per-cluster split already used for
kube-prometheus-stack (`kube-prometheus-stack-values.yaml` vs `-acg-values.yaml`). Do **not**
change the shared hub values file, and do **not** broaden the ACG Prometheus selector.

### Change 1 — new file `scripts/etc/helm/observability/trivy-operator-acg-values.yaml`

Create the file with **exactly** this content (identical to
`trivy-operator-values.yaml` except the ServiceMonitor `release` label):

```yaml
image:
  registry: mirror.gcr.io
  repository: aquasec/trivy-operator
  tag: "0.31.2"

trivy:
  ignoreUnfixed: true
  severity: CRITICAL,HIGH
  resources:
    requests:
      memory: 64Mi
      cpu: 50m
    limits:
      memory: 512Mi
      cpu: 500m

operator:
  scanJobTTL: 1h
  vulnerabilityReportsPlugin: Trivy
  configAuditScannerEnabled: true
  resources:
    requests:
      memory: 32Mi
      cpu: 20m
    limits:
      memory: 96Mi
      cpu: 100m

serviceMonitor:
  enabled: true
  labels:
    release: acg-kube-prometheus-stack
```

### Change 2 — `scripts/etc/argocd/applicationsets/observability-acg.yaml`: point ACG trivy at the new values file

**Exact old block:**

```yaml
          - name: acg-trivy-operator
            namespace: trivy-system
            chart: trivy-operator
            repoURL: https://aquasecurity.github.io/helm-charts
            targetRevision: 0.33.2
            valuesFile: scripts/etc/helm/observability/trivy-operator-values.yaml
```

**Exact new block:**

```yaml
          - name: acg-trivy-operator
            namespace: trivy-system
            chart: trivy-operator
            repoURL: https://aquasecurity.github.io/helm-charts
            targetRevision: 0.33.2
            valuesFile: scripts/etc/helm/observability/trivy-operator-acg-values.yaml
```
