## Claude's sealed review

# Claude review — v1.43.12 release (blind calibration 1)

Reviewed: origin/main..e69cd7d1 (k3d-manager-v1.43.12), production code only; tests read only where needed.
Reviewed 2026-10-31 by Claude before reading any operator finding.

C1 — bin/hub-new:175 — P2 — The pass report is rewritten on every run where the state file says verify passed, including a rerun that skips all stages ("already passed"). The new report gets the current timestamp but the old checks, so hub-cutover's 24-hour freshness gate (read_report) is defeated by simply rerunning make hub-new days later. The report should be written only when verify actually ran in this invocation.

C2 — bin/hub-cutover:360-363 + read_handoff:137 — P2 — Rerunning make hub-cutover after a partial cutover destroys the rollback record. Line 362 truncates stopped-on-old (the old agents are already booted out, so nothing is re-recorded), and read_handoff reads the old controller's replicas as 0 (already scaled down) and handoff saves 0. A later rollback then reloads no agents on the old hub and "restores" its ArgoCD controller to 0 replicas, leaving neither hub managing Hostinger. The rerun should refuse when stopped-on-old is non-empty, or merge into it, and keep the first saved replica count.

C3 — bin/hub-cutover:364-378 — P3 — The quiet check runs right after launchctl bootout on the old hub. The same release's CHANGELOG records that bootout returns before a running job is gone (and change_forward waits up to 15s for exactly that), but this loop does not wait, so a slow-exiting agent fails the cutover with "remains loaded" and sends the operator to rollback. The bootout result is also unchecked: under set -e a failing remote bootout exits with no message and no report row.

C4 — scripts/lib/webhook/untrusted.py:7-8 — P2 (security) — The command filter is a deny-list of tool words. Destructive commands from tools not in the list pass through as plain text when not in backticks: "Run: argocd app delete shopping-cart-identity --cascade", "terraform destroy", "kill -9 1", "brew uninstall cloudflared", "cloudflared tunnel delete k3d-manager". Backticked spans with a space are caught, unbackticked imperative text is not. The allow-list should apply to any command-shaped candidate (imperative lead-in, line-start token), not just to the listed tools. (Related to, not the same as, the filed P3 docs/bugs/2026-10-31-ai-analysis-filter-withholds-whole-prose-lines.md, which is about over-withholding; this is under-withholding.)

C5 — bin/hub-cutover:269-277 — P3 — forwards_ready hard-codes ports 19094 and 19100, while the forwards themselves come from hub-push-forwards.list. Adding or renumbering a forward in the list leaves the readiness check testing the wrong ports, so forwards-pass can be recorded while the new forward is down (or a working change reports forwards-failed).

C6 — bin/k3dm-machine-setup:365-373, agents.hub.list — P3 — bin/k3dm-heartbeat-setup is listed for the hub, but render_heartbeat always records a failure (even after a successful render), and nothing ever writes com.k3d-manager.heartbeat.plist. machine-check on any hub is therefore permanently non-zero (seen live on both the M5 and the M4 on 2026-10-31). Either drop it from the hub list or report "review pending" without failing.

C7 — scripts/plugins/argocd.sh:1858 (_argocd_sync_notifications_slack_secret_untraced) — P3 (secret hygiene) — _kubectl is called without --no-exit; on a failed patch _kubectl exits the process, so the `|| _rc=$?` and the following rm never run, leaving the base64 Slack webhook URL in a TMPDIR temp file, and the platform-ops deploy aborts instead of warning. Use --no-exit (and a trap for the file).

C8 — bin/hub-cutover:157-169 — P3 — handoff() returns 1 without a message or report row when scp, chmod, or the new controller read/scale fails, after the old controller is already at 0. The operator sees only "exit 1"; the report has no row explaining why, unlike the other failure paths that print "run make hub-cutover-rollback".

C9 — release scope (CHANGELOG [1.43.12], docs/plans/v1.43.10-*) — P3 (process) — The PR merges the v1.43.10 branch into main through v1.43.12: five v1.43.10 plan docs that are unimplemented (PROPOSED/READY/SPEC WRITTEN) plus one v1.43.10 fix. v1.43.10 then has no tag of its own. Needs an explicit operator decision in the PR body (ship v1.43.10 later from main, or renumber), and the roadmap should say so.
