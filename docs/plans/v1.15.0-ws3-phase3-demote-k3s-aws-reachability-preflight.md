# WS3 Phase 3 — Demote `k3s-aws` default + reachability preflight

**Branch:** `k3d-manager-v1.15.0`
**Files:** `scripts/lib/provider.sh`, `scripts/tests/lib/provider_contract.bats`
**Design doc:** `docs/bugs/2026-07-07-app-cluster-vault-portability.md` (Phase 3, decision #1 — RESOLVED 2026-07-10)

---

## Problem

The AWS ACG cluster (`k3s-aws` → context `ubuntu-k3s`) was migrated to Hostinger, but
its kubeconfig entry outlives the cluster: a **resolvable-but-dead** context at
`https://52.37.60.119:6443` that answers DNS/TCP-connect but never `/readyz`. Two consequences:

1. **`k3s-aws` is still a silent default.** `_acg_resolve_provider` (`provider.sh:130`)
   falls back to `k3s-aws` when nothing is reachable and no active-provider file exists —
   pointing new work at the dead cluster by default.
2. **Selecting a dead context can hang.** The auto-detect loop already uses a 5s
   `/readyz` timeout, but there is no reusable primitive a caller can use to fail fast
   before operating on a context.

Per **decision #1** (signed off 2026-07-10): *keep the `k3s-aws` → `ubuntu-k3s` mapping,
but demote it* — make `k3s-aws` non-default and add a reachability preflight. This is the
**re-scoped** Phase 3: **not** a mass find-replace of `ubuntu-k3s`.

**Scope (confirmed 2026-07-12):** "Primitive + demote" only. Add the reusable
`_acg_context_reachable()` primitive, route the existing auto-detect loop through it
(behavior-preserving extraction — identical `kubectl` invocation), and demote the
`provider.sh:130` fallback default. Do **not** wire the preflight into other call sites
(that is a follow-up), and do **not** touch the `_acg_provider_context` `*)` mapping at
`provider.sh:99` (it is locked by an existing test and decision #1 keeps the mapping).

## Fix

### Change 1 — `scripts/lib/provider.sh`: add the reachability primitive + route the loop through it

**Exact old block (lines 111–116):**

```bash
function _acg_resolve_provider() {
    local provider="${CLUSTER_PROVIDER:-}"
    if [[ -z "${provider}" ]]; then
        local ctx
        for ctx in ubuntu-hostinger ubuntu-k3s ubuntu-azure ubuntu-gcp; do
            if kubectl --context "${ctx}" --request-timeout=5s get --raw=/readyz >/dev/null 2>&1; then
```

**Exact new block:**

```bash
# Reachability preflight: true only if the kube-context answers /readyz within a
# short timeout. Selecting a resolvable-but-dead context (e.g. an expired ACG
# sandbox whose kubeconfig entry outlived the cluster) then fails fast instead of
# hanging against a dead endpoint.
function _acg_context_reachable() {
    local ctx="${1:-}"
    [[ -z "${ctx}" ]] && return 1
    kubectl --context "${ctx}" --request-timeout=5s get --raw=/readyz >/dev/null 2>&1
}

function _acg_resolve_provider() {
    local provider="${CLUSTER_PROVIDER:-}"
    if [[ -z "${provider}" ]]; then
        local ctx
        for ctx in ubuntu-hostinger ubuntu-k3s ubuntu-azure ubuntu-gcp; do
            if _acg_context_reachable "${ctx}"; then
```

> The extracted `kubectl` invocation is byte-for-byte identical to the old inline probe,
> so the 5 existing `_acg_resolve_provider` tests (which mock `kubectl` on that exact
> argument string) keep passing. This is a behavior-preserving extraction, not a change
> to the auto-detect path.

### Change 2 — `scripts/lib/provider.sh`: demote the fallback default

**Exact old block (line 130):**

```bash
    _acg_normalize_provider "${provider:-k3s-aws}"
```

**Exact new block:**

```bash
    _acg_normalize_provider "${provider:-k3s-hostinger}"
```

> Test-safe: every existing `_acg_resolve_provider` test has at least one reachable
> context or an active-provider file, so it resolves before reaching this fallback. Only
> the new test #10 (nothing reachable, no file) exercises this branch.

### Change 3 — `scripts/tests/lib/provider_contract.bats`: add 4 tests

Insert immediately **before** the existing test
`@test "_hostinger_set_active_app_cluster targets the hub context for relabel" {`
(i.e. after the `_acg_resolve_provider honors a live Hostinger active-provider file` test):

```bash
@test "_acg_context_reachable is true when the context answers /readyz" {
  kubectl() {
    case "$*" in
      --context\ ubuntu-hostinger\ --request-timeout=5s\ get\ --raw=/readyz*) return 0 ;;
      *) return 1 ;;
    esac
  }

  run _acg_context_reachable ubuntu-hostinger
  [ "$status" -eq 0 ]
}

@test "_acg_context_reachable is false for an unreachable context" {
  kubectl() {
    return 1
  }

  run _acg_context_reachable ubuntu-k3s
  [ "$status" -eq 1 ]
}

@test "_acg_context_reachable is false for an empty context" {
  run _acg_context_reachable ""
  [ "$status" -eq 1 ]
}

@test "_acg_resolve_provider falls back to k3s-hostinger when nothing is reachable and no file exists" {
  _ACG_ACTIVE_PROVIDER_FILE="${BATS_TEST_TMPDIR}/no-such-active-provider"
  rm -f "${_ACG_ACTIVE_PROVIDER_FILE}"

  kubectl() {
    return 1
  }

  [[ "$(_acg_resolve_provider)" == "k3s-hostinger" ]]
}
```
