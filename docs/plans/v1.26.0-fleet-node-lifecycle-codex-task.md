3. **Do NOT touch the live ACG sandbox.** Do not run `make up`, `make down`, `make fleet-validate`,

6. **Style:** double-quote every expansion; `set -euo pipefail`; `--` to separate options; validate any

### A1 — Generated N-agent CFN template

Today `etc/acg-cluster.yaml` is a static `Server` + `Agent1Instance` + `Agent2Instance` with outputs
`Agent1PublicIP`/`Agent2PublicIP` only. Make the deployed template a function of `ACG_AGENT_COUNT`
(default `2`):

  `aws cloudformation deploy --template-file`, emitting `Server` + `Agent{i}Instance` for
  `i in 1..ACG_AGENT_COUNT` and a matching `Agent{i}PublicIP` output for each. Keep a 2-agent template
  checked in as the documented default/reference.
- The rendered template is the only thing `deploy` sees; its agent count equals `ACG_AGENT_COUNT`.
- Reject `ACG_AGENT_COUNT` that is non-numeric or `< 1` **before** any `aws` call (fail closed, no
  writes).

Replace the hardcoded three-output read (`server_ip`, `agent1_ip`, `agent2_ip` at approx lines
**151–157**) with a loop that collects **every** `Agent*PublicIP` stack output into an ordered array
(e.g. `agent_ips[]`), regardless of count. No `Agent1`/`Agent2` literal may remain.

## Phase B — k3d-manager — only after Claude confirms the subtree pull

Branch: `k3d-manager-v1.26.0`.

### B1 — Leave the checked-in template as the 2-agent reference (do NOT regenerate from upstream)

**Corrected 2026-08-21 after Phase A verification.** Do **not** overwrite `scripts/etc/acg-cluster.yaml`
from the upstream lib-foundation template. The k3d-manager copy is intentionally **ahead** of upstream:
it carries the `EnableSsm` parameter, the `SsmEnabled` condition, and
`IamInstanceProfile: !If [SsmEnabled, !Ref SSMInstanceProfile, !Ref "AWS::NoValue"]` — the
IAM-restricted-sandbox fix (`fef71219`/`40f1d19a`) that the upstream template still lacks. Regenerating
from the bare upstream 2-agent template would **revert that fix and break deploys on IAM-restricted ACG
sandboxes**.

The checked-in k3d-manager template **stays a 2-agent reference** and is *not* replaced. At runtime the
`_acg_render_template` emitter (Phase A) reads the exported `ACG_CLUSTER_TEMPLATE`
(`scripts/plugins/acg.sh:14` → k3d-manager's `scripts/etc/acg-cluster.yaml`) and generates the N-agent
form at deploy time — verified 2026-08-21 to preserve every per-agent property, including the SSM `!If`
conditional and the `Conditions`/`EnableSsm` blocks, when rendered against this drifted template. So B1
is effectively a **no-op**: confirm the template is unchanged and the render works against it; do not
edit it. (Closing the upstream template's missing-SSM-conditional debt is a separate upstream-first task,
not part of this Phase B.)

### B2 — `scripts/lib/providers/k3s-aws.sh`

- **Line 236:** derive `UBUNTU_K3S_AGENT_HOSTS` from `ACG_AGENT_COUNT` (`ubuntu-1,…,ubuntu-N`) instead
  of the hardcoded `export UBUNTU_K3S_AGENT_HOSTS="ubuntu-1,ubuntu-2"`.
- **Line 245:** `local total_nodes=$((1 + ACG_AGENT_COUNT))` instead of the hardcoded `3`. (The other

  — do not leave a stray `3`.)
- **Line 188:** update the stale help text (`ACG_AGENT_COUNT  Number of agent nodes (default: 2)`) so it
  describes the now-wired knob.

### B3 — `scripts/plugins/shopping_cart.sh:deploy_app_cluster()` (starts line 1102)

The join loop consumes `UBUNTU_K3S_AGENT_HOSTS` at approx lines **1215** and **1286**, serially. Make it:

- **parallel** across the host list (background jobs + `wait`), replacing the serial loop;
- **per-node readiness**: each node validated individually (SSH reachable → runtime installed → node
  `Ready`); collect failures into a list and report them all, do **not** abort on the first bad node;
- **idempotent**: skip a node already joined / already `Ready`; never create a duplicate SSH alias or
  re-run a completed join.

Trace where the `Agent*PublicIP` → SSH-alias (`ubuntu-1`…`ubuntu-N`) file is authored and make it
count-driven (the write site is downstream of discovery; confirm and generalize to N).

### B4 — Makefile targets (author all; run only `fleet-render`)

Add provider-aware (`k3s-aws` only) targets to the `Makefile`, each accepting optional
`ACG_AGENT_COUNT=N` (default 2). Each target needs **all** of:
- its name in `.PHONY`;
- a `##` doc comment above the target (the pattern the Makefile uses for `make help`);
- a target line in the `help:` **Targets** section (under the `k3s-aws / k3s-gcp only:` group, matching
  the existing `make provision` / `make observability-acg` entries);
- an entry in the `help:` **Examples** section (alongside `make up # k3s-aws (default)`), showing the
  `ACG_AGENT_COUNT=N` form, e.g. `make fleet-render ACG_AGENT_COUNT=4` and
  `make fleet-up ACG_AGENT_COUNT=4`.

Targets:

| Target | Rung | Command it wraps |
|---|---|---|
| `fleet-render` | 0 | render the generated CFN template to stdout + assert it has `ACG_AGENT_COUNT` agents / outputs (offline) |
| `fleet-validate` | 1 | `aws cloudformation validate-template` on the rendered template |
| `fleet-plan` | 2 | `create-change-set --no-execute`, print planned instance count, no create |
| `fleet-up` | 3 | `scripts/k3d-manager deploy_cluster --confirm` (node-join only — **not** `bin/cluster-up`/`make up`) |

Guard non-`k3s-aws` providers with a clear skip message (mirror the `cleanup-stale-sandbox` pattern in
the Makefile). You author **all four** targets, but you may only **run** `make fleet-render` — the other
three touch the live sandbox and are Claude's to run.

### B5 — k3d-manager BATS (stubbed `aws`/`ssh`/`kubectl`)

- `ACG_AGENT_COUNT` unset → 2 agents / `total_nodes=3` / hosts `ubuntu-1,ubuntu-2` (behavior preserved);
- `ACG_AGENT_COUNT=4` → 4 agents / `total_nodes=5` / hosts `ubuntu-1,…,ubuntu-4`;
- parallel-join fan-out spawns N background jobs and `wait`s;
- a per-node failure is collected, not fatal on the first;
- idempotent re-run adds no duplicate host/join/SSH-alias.
