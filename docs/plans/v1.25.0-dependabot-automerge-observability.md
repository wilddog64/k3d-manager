# v1.25.0 — event-driven Dependabot auto-merge monitoring and Grafana visibility

**Target branch:** `k3d-manager-v1.25.0`
**Status:** SCOPED — implementation not started. Plan doc **#3** for v1.25.0.
**Related:** `docs/plans/v1.19.0-shopping-cart-dependabot-automerge.md`,
`docs/issues/2026-07-28-copilot-dependabot-automerge-review-findings.md`.

## Problem and outcome

The five shopping-cart repositories already create Dependabot pull requests and request GitHub
auto-merge. A PR can nevertheless remain open, become blocked by a review/check/policy, or have its
auto-merge workflow fail without an operator seeing the reason. The existing workflow is the source of
truth for eligibility, but it does not expose a durable operational signal.

This plan adds an event-driven monitor that receives GitHub PR, review, check, and workflow events,
maintains a bounded current-state registry, exports Prometheus metrics, and presents the state in
Grafana. A scheduled reconciliation is a safety net for dropped webhooks; it is not a second merge
implementation. The monitor never merges, closes, approves, or changes branch protection.

## Scope and non-goals

In scope are the five shopping-cart repositories (`shopping-cart-basket`, `shopping-cart-frontend`,
`shopping-cart-order`, `shopping-cart-payment`, and `shopping-cart-product-catalog`), the existing
Dependabot auto-merge workflow, the k3d-manager webhook/exporter seam, Grafana, and Alertmanager.

Out of scope: changing Dependabot update policy, auto-merging major updates, bypassing required
reviews, replacing GitHub's merge queue, deploying a new always-on database, or exposing PR bodies,
tokens, credentials, or arbitrary GitHub API responses as metric labels.

## Event contract

Configure one GitHub App webhook (or the existing repository webhook fan-out) for each repository,
with a single endpoint on `k3dm-webhook`. Subscribe to:

- `pull_request`: `opened`, `reopened`, `edited`, `synchronize`, `labeled`, `unlabeled`, and `closed`;
- `pull_request_review`: `submitted`, `edited`, and `dismissed`;
- `check_run`: `completed`;
- `workflow_run`: `completed`.

The receiver must verify the GitHub HMAC signature before parsing or enqueueing an event, reject
unknown event types with a safe 2xx response, and return quickly after durable in-memory/queue
acceptance. Deduplicate by `X-GitHub-Delivery`; duplicate deliveries must not increment counters.
Only the repository, numeric PR number, Dependabot actor, update class, workflow/check conclusion,
auto-merge state, and a bounded reason code are retained. URLs are constructed at render time from
validated repository and PR values.

The monitor tracks these states: `open`, `ready`, `blocked`, `auto_merge_enabled`, `merged`, and
`closed`. A closed/merged PR is retained for seven days for audit and then evicted. Open PRs are
reconciled every 15 minutes by a least-privilege GitHub Action (`pull-requests: read`, `actions: read`)
that posts signed snapshots to the same endpoint. Reconciliation must be idempotent and must not call
the merge API.

## Prometheus metric contract

Extend the existing k3dm webhook/exporter path; do not add a second exporter process. Metrics use a
fixed repository allowlist and bounded reason/update labels. PR numbers are allowed only on gauges
with the seven-day TTL and are never used on unbounded counters.

| Metric | Type | Labels | Meaning |
|---|---|---|---|
| `k3dm_dependabot_pr_state` | gauge | `repo`, `pr`, `state` | Current PR state; one series is 1 |
| `k3dm_dependabot_pr_automerge_enabled` | gauge | `repo`, `pr` | GitHub reports auto-merge enabled |
| `k3dm_dependabot_pr_age_seconds` | gauge | `repo`, `pr` | Age of the current open PR |
| `k3dm_dependabot_automerge_events_total` | counter | `repo`, `event`, `result` | Accepted, duplicate, rejected, or error event |
| `k3dm_dependabot_workflow_failures_total` | counter | `repo`, `workflow`, `reason` | Failed/ cancelled auto-merge workflow runs |
| `k3dm_dependabot_last_event_timestamp_seconds` | gauge | `repo` | Most recent accepted event |
| `k3dm_dependabot_reconcile_timestamp_seconds` | gauge | `repo` | Most recent successful snapshot |

The exporter must emit HELP/TYPE lines, escape label values, keep the registry bounded, and expose
`/metrics` without GitHub credentials. A missing webhook secret, malformed signature, or GitHub API
failure is an error metric and never a successful event.

## Grafana dashboard

Add a provisioned `Dependabot Auto-Merge` row to the platform-ops dashboard (or a separate dashboard
ConfigMap if that is the established provisioning boundary). Required panels:

1. **Open Dependabot PRs by state** — stacked series from `k3dm_dependabot_pr_state`.
2. **Blocked PRs** — table with repository, PR, state, age, and a generated GitHub link.
3. **Auto-merge enabled vs waiting** — stat/table from the enabled gauge and current state.
4. **Workflow failures** — time series from `k3dm_dependabot_workflow_failures_total`, grouped by
   repository and bounded reason.
5. **Event freshness** — `time() - k3dm_dependabot_last_event_timestamp_seconds` and reconciliation
   age, with a red state when either exceeds 30 minutes.
6. **Merged updates** — daily rate of accepted `pull_request` closed/merged events, grouped by repo.

Dashboard variables are limited to the five repository names and update classes. Panel links must
point to `https://github.com/wilddog64/<repo>/pull/<pr>` and must not contain a token.

## Alertmanager rules and routing

Add owned PrometheusRule alerts to the existing platform-ops rule set and route them to the existing
Slack operations receiver (not the `k3dm-quiet` blackhole):

- `DependabotAutoMergeBlocked`: an open PR is blocked for 30 minutes;
- `DependabotAutoMergeWorkflowFailing`: an auto-merge workflow has failed twice in 30 minutes;
- `DependabotAutoMergeEventStale`: an open PR exists and no accepted event or reconciliation has been
  observed for 30 minutes;
- `DependabotAutoMergeMonitorDown`: the exporter target is absent or its scrape has failed for 10
  minutes.

Alerts include repository, PR (when present), bounded reason, and a token-free PR URL. They must use
`for` durations and `absent()`/freshness checks so a single transient event does not page.

## Security and reliability requirements

- Store the GitHub App webhook secret and installation credentials in Vault/ESO; never commit them,
  place them in command arguments, or log request bodies.
- Grant the App read-only pull-request/check/workflow metadata. The monitor has no `contents: write`
  or merge permission.
- Verify signatures with constant-time comparison, cap request size, reject malformed JSON safely,
  and use delivery-id idempotency.
- Bound event retention and metric cardinality; evict closed PRs after seven days.
- If GitHub or the webhook is unavailable, reconciliation must recover state without changing PRs.

## Implementation files and sequence

Implement in this order, keeping each change reviewable:

1. `bin/k3dm-webhook` plus its BATS suite: signed event endpoint, schema validation, deduplication,
   bounded registry, and metrics handler.
2. The existing exporter/ConfigMap manifest and `scripts/plugins/argocd.sh`: RBAC/secret wiring and
   rollout wiring, preserving least privilege.
3. The five shopping-cart workflow callers and a shared reconciliation workflow (or equivalent
   repository-local workflow if GitHub cannot reuse it): post signed snapshots every 15 minutes.
4. Platform-ops PrometheusRule and Grafana dashboard ConfigMap, with dashboard provisioning tests.
5. Static/live verification after merge: duplicate delivery, invalid signature, blocked PR, workflow
   failure, merged PR, stale webhook, and reconciliation recovery.

## Gates and acceptance criteria

- `python3 -m py_compile` for any embedded/exporter Python and `shellcheck -S warning` for touched
  shell scripts are clean.
- Webhook BATS tests cover valid/invalid signatures, malformed JSON, duplicate delivery, all supported
  event types, bounded eviction, and token-free rendered links.
- YAML/JSON parse checks pass for the PrometheusRule, dashboard, manifests, and workflow files.
- A fixture sequence (open → auto-merge enabled → check failure → retry → merged) produces the exact
  metric contract and expected Grafana states.
- The reconciliation fixture restores a deliberately missing event without creating a merge action.
- Live smoke confirms the dashboard panels, Alertmanager routing, and Slack payloads; no credential or
  PR body is present in metrics/logs.
- `_agent_audit` passes and the implementation touches only the files listed in the implementation
  change set.

## Definition of done

The five repositories' Dependabot PRs are observable end-to-end: an operator can see why an update is
waiting or blocked, receive a routed alert when it remains blocked or the monitor goes stale, and see
successful merges in Grafana. Missed webhook deliveries self-heal through reconciliation, while the
monitor remains strictly read-only with bounded retention and no secret exposure.
