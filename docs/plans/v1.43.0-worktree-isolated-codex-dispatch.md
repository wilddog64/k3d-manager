# v1.43.0 — Worktree-isolated Codex dispatch: one worktree per spec, scope checked at landing

**Filed:** 2026-10-09, Claude
**Branch:** `k3d-manager-v1.43.0` (never `main`)

**Origin:** operator, 2026-10-09, after comparing k3d-manager with the Aithon delivery pipeline. Two

companion spec `v1.45.0-alert-intake-draft-bugs.md`). A per-PR human-review classifier and full

**Implementer:** Codex · **Verifier:** Claude

## Problem

Codex runs in the operator's own checkout, on the shared release branch. That causes three problems
that keep recurring.

1. **Collisions.** Codex has reverted unrelated uncommitted edits in the shared tree
   (`feedback_codex_reverts_unrelated_unstaged_edits`). The standing workaround has two rules:
   "commit before dispatch", and "never edit the tree while Codex or a suite runs from it". So Claude
   and the operator are blocked for the whole run, and only one Codex task can run at a time.
2. **No parallelism.** Two specs in the same release cannot be dispatched together. They would share
   one working tree.
3. **Scope is checked by eye.** Every spec has a `## Files` table and a "do not modify files outside
   the table" rule. The only enforcement is Claude reading `git diff --stat`.

Codex also cannot commit under `--sandbox workspace-write`, because `.git` writes are denied
(`reference_codex_exec_cannot_commit_git_lock`). Claude already commits after verifying. This spec
keeps that boundary and makes it explicit.

## Approach

A new `bin/k3dm-codex-dispatch` script gives each spec its own git worktree, on its own task branch
cut from `origin/<release-branch>`:
- Codex runs with `-C <worktree>`, so its edits cannot reach the operator's checkout or another task.
- Claude verifies in the worktree and commits there. Codex still never commits.
- `land` checks the commit against the spec's `## Files` table, fast-forwards the release branch
  onto it, and removes the worktree.

Nothing here pushes, opens a PR or merges to `main`.

```
operator checkout (k3d-manager-v1.43.0)         untouched while Codex runs
~/.local/share/k3d-manager/worktrees/
  v1.43.0/bug-priority-tracking/                worktree  · branch task/v1.43.0/bug-priority-tracking
  v1.43.0/bug-priority-tracking.run/            prompt.md codex.log last-message.md pid exit state/
  v1.43.0/hermes-r10-delete-superseded-failed-job/  second task, in parallel
```

## Items

### 1. `bin/k3dm-codex-dispatch` (new, bash, `set -euo pipefail`, sources lib-foundation like other `bin/` scripts)

Subcommands:

**`start --spec <path> [--slug <slug>] [--network]`**
- Check the preconditions. Each refusal exits 2 and names the failed check:
  - The current branch matches `^k3d-manager-v[0-9]+\.[0-9]+\.[0-9]+$`. This is the release branch, `<rel>`.
  - `<path>` is tracked (`git ls-files --error-unmatch`) and unchanged against HEAD
    (`git diff --quiet HEAD -- <path>`).
  - HEAD is pushed. Run `git fetch origin "<rel>:refs/remotes/origin/<rel>"`, then compare
    `git rev-parse HEAD` with `origin/<rel>`. A bare `git fetch origin <rel>` updates only
    FETCH_HEAD (`reference_git_fetch_bare_branch_name_skips_refspec`).
  - The spec has a `## Files` section that contains at least one backticked path.
- `<version>` comes from `<rel>`, for example `v1.43.0`. The default `<slug>` is the spec basename
  without its `vX.Y.Z-` prefix and without `.md`.
- The task branch is `task/<version>/<slug>`. Refuse with exit 2 if it already exists locally or on
  origin. `task/` keeps it out of the `k3d-manager-v*` milestone namespace, so `appsets-reapply`
  rejects it.
- `root="${K3DM_WORKTREE_ROOT:-$HOME/.local/share/k3d-manager/worktrees}"`. Create
  `$root/<version>/<slug>` with `git worktree add -b task/<version>/<slug> <dir> origin/<rel>`.
  Create the run dir `$root/<version>/<slug>.run/` with mode 0700. The run dir sits outside the
  worktree, so its files never show up in the task diff.
- Write `prompt.md` from a heredoc template. It must say:
  - Read the spec at `<path>` in full, and implement it in this directory only.
  - Run the spec's Rules gates and paste their output.
  - Do **not** run `git add`, `git commit` or `git push`. `.git` is read-only to you. Leave the
    changes in the working tree.
  - Do not touch `memory-bank/`.
  - Do not unset or override the `K3DM_*` and `TMPDIR` variables you were given. They keep this task's
    state away from the live webhook and from other tasks.
  - Your last message must list every file you changed.
- **Isolate per-task state.** Create `<run>/state/` (mode 0700) with these subdirectories: `jobs`,
  `run`, `state`, `logs`, `tmp` and `port-cache`. Export the following into Codex's environment and
  nowhere else:

  | Variable | Value |
  |---|---|
  | `K3DM_REPO_ROOT` | `<dir>` (the worktree, never the operator checkout) |
  | `K3DM_JOB_DIR` | `<run>/state/jobs` |
  | `K3DM_RUN_DIR` | `<run>/state/run` |
  | `K3DM_STATE_DIR` | `<run>/state/state` |
  | `K3DM_LOG_DIR` | `<run>/state/logs` |
  | `K3DM_TMP_ROOT` | `<run>/state/tmp` |
  | `K3DM_PORT_CACHE_DIR` | `<run>/state/port-cache` |
  | `TMPDIR` | `<run>/state/tmp` |

  - Keep the list in one array, `_dispatch_state_vars`, so that a future override is added in one place.
  - Do **not** change `HOME`. Codex's auth, `gh` and git config live under it.
  - Feature-specific overrides, such as `K3DM_HERMES_STATE` or `K3DM_SANDBOX_REAPER_STATE_DIR`, are
    already set by their own tests and stay out of this list.
- Launch Codex in the background. `--add-dir` makes the state directory writable inside the sandbox,
  since it sits outside `-C`:
  ```bash
  "${K3DM_CODEX_BIN:-codex}" exec --sandbox workspace-write -C "<dir>" --add-dir "<run>/state" \
    -o "<run>/last-message.md" ${network_flag} - < "<run>/prompt.md" > "<run>/codex.log" 2>&1
  ```
  - `network_flag` is empty by default. Only with `--network` is it
    `-c sandbox_workspace_write.network_access=true`.
  - Wrap the launch so that `$?` is written to `<run>/exit` when Codex finishes. Write the PID to
    `<run>/pid`, then return at once.
- Print the worktree path, the run dir and the `status` command.

**`status [<slug>]`**: one block per task under `$root/<version>/`. Each block shows:
- the state: `running` if the PID is alive, `exited <code>`, or `landed`;
- the changed files, from `git -C <dir> status --porcelain` plus the commits ahead of `origin/<rel>`;
- the scope verdict (below).

It is read-only.

**`land --slug <slug> [--allow-out-of-scope]`**: refuse with exit 2 when any of these holds:
- Codex is still running.
- The worktree has uncommitted changes. Claude verifies and commits in the worktree first.
- The task branch has no commits ahead of `origin/<rel>`.
- Any file changed by those commits is out of scope, unless `--allow-out-of-scope` is given.
- The operator's checkout is not on `<rel>`, or is not clean (`git status --porcelain` non-empty).

If none of those holds:
- `git -C <dir> rebase "<rel>"`, then in the operator checkout `git merge --ff-only task/<version>/<slug>`.
- Then `git worktree remove <dir>` and `git branch -d task/<version>/<slug>`. The run dir stays as
  a record, and gets a `landed` marker.
- Print `git push origin <rel>`. It does **not** push.

**`abandon --slug <slug> --yes`**: run `git worktree remove --force <dir>` and
`git branch -D task/<version>/<slug>`. Without `--yes`, it prints what it would remove and exits 2.

**Scope rule.** In scope means every changed path is a backticked path in the spec's `## Files`
section, or matches a backticked glob there. `memory-bank/**` is always out of scope.

### 3. `scripts/tests/bin/codex_dispatch.bats` (new, fully stubbed)

**Fixture.** Each test gets:
- a temp bare origin and a clone on `k3d-manager-v9.9.9`, holding a committed and pushed spec with a
  `## Files` table listing `` `a.txt` ``;
- `K3DM_WORKTREE_ROOT` set to a temp dir;
- `K3DM_CODEX_BIN` set to a stub. The stub records its argv, then edits files under its `-C` dir:
  `a.txt` by default, or the paths in `STUB_EDITS`.

**Tests:**
1. `start` refuses a non-release branch (exit 2).
2. `start` refuses an uncommitted spec, and refuses when HEAD is ahead of origin.
3. `start` creates `$root/v9.9.9/<slug>` on `task/v9.9.9/<slug>`, based on `origin/k3d-manager-v9.9.9`.
   After the stub runs, the operator checkout's `git status --porcelain` is empty and `a.txt` there
   is unchanged. This is the isolation property.
4. Two `start`s with different specs run in parallel. Each worktree has only its own edit.
5. The stub's argv contains `exec`, `--sandbox workspace-write`, `-C <worktree>` and
   `--add-dir <run>/state`. With no `--network`, it does not contain `network_access=true`.
5b. State isolation: the stub dumps its environment. Every variable in the state table points under
   `<run>/state/`, `K3DM_REPO_ROOT` equals the worktree, and `HOME` is unchanged. Two parallel tasks
   get disjoint state directories. Nothing is written under the fixture's `$HOME/.local/share`, so
   point `HOME` at a temp dir in the test and assert that the directory stays empty.
6. `status` marks a change to `memory-bank/x.md` as out of scope.
7. `land` refuses while the PID is alive, refuses an out-of-scope commit, and refuses an uncommitted
   worktree.
8. `land` refuses when the operator checkout is dirty.
9. `land` on an in-scope commit fast-forwards `k3d-manager-v9.9.9`, removes the worktree and task
   branch, and does not push: the bare origin ref is unchanged.
10. `abandon` without `--yes` changes nothing.

**Mutation checks.** Paste the red output for each:
- Change `-C "<dir>"` to the operator checkout. Tests 3 and 4 must fail.
- Skip the scope check in `land`. Test 7 must fail.
- Drop `K3DM_JOB_DIR` from `_dispatch_state_vars`. Test 5b must fail.

## What NOT to Do

- Do NOT let the script run `git commit`, `git push`, `gh pr`, or anything against `main`.
- Do NOT place the worktree or run dir inside the repo checkout.
- Do NOT pass `--dangerously-bypass-approvals-and-sandbox` or `--sandbox danger-full-access`.
  Do NOT enable network by default.
- Do NOT run real `codex` in tests. Every test uses `K3DM_CODEX_BIN`.
- Do NOT edit `.claude/`, the `/handoff` skill or `memory-bank/`.
- Do NOT create a PR or merge. Do NOT use `--no-verify`. Do NOT modify files outside the table.
