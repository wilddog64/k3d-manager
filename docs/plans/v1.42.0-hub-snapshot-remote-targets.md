# v1.42.0 — Hub snapshot targets over Slack `/k3dm` and the cloud bridge

**Filed:** 2026-10-08, Claude (operator request: "can we make these make targets available to k3dm slack commands and cloud-bridge")
**Branch:** `k3d-manager-v1.42.0`
**Status:** SPEC — not started
**Depends on:** `docs/bugs/2026-09-20-no-capture-producer-hub-pvc-data-unrecoverable.md` round 3
(capture's doubled container name). Don't dispatch this until round 3 is verified.

## Why

The DR snapshot is only useful if it is fresh. The teardown guard now refuses `DELETE_HUB=1` without
a verified snapshot under 24h old. Taking or checking one currently needs a terminal on the M4.
Exposing the targets in Slack lets the operator take one from a phone. Exposing the read-only one
to the cloud bridge lets a cloud session check freshness before it proposes a teardown.

## Decision — which target goes where, at which role

| make target | effect | Slack `/k3dm` | cloud bridge | why |
|---|---|---|---|---|
| `snapshot-list` | read-only `ssh` listing on the M2 | `reader` | **yes**, `make-snapshot-list` | Pure read, no secret content. Its output is timestamps, sizes and verified/incomplete state. |
| `snapshot` | copies the 8 hub volumes (Vault storage included) to the M2 and writes the local stamp | `operator` | **no** | Moves the hub's data, so it needs operator rights. The cloud reader token is reader-only, and the cloud-runner token is scoped to e2e and sandbox lifecycle by design (`cloud-session-requests.md`). Widening either for this is out of scope. |
| `hub-retain-pvs` | patches PV reclaim policy to Retain (idempotent, only adds protection) | `operator` | **no** | It mutates the cluster, but only in the safe direction. It needs repeating after every hub rebuild, so Slack access helps. |
| `snapshot-prune` | **deletes** snapshots on the M2 | not exposed | not exposed | Destructive, and it could delete the only good copy. It stays terminal-only. |
| `status` | — | not added | not added | Already reachable as `/cluster-status`. Confirm in the report whether that path prints the new `Hub snapshot:` line. If it does not, say so; do not change it here. |

## Changes

   existing ones:

   ```python
   "snapshot-list": {"min_role": "reader", "timeout": 120, "summary": "list hub snapshots on the M2 (verified/incomplete, age)"},
   "snapshot": {"min_role": "operator", "timeout": 1800, "summary": "capture the hub volumes to the M2 and verify checksums"},
   "hub-retain-pvs": {"min_role": "operator", "timeout": 300, "summary": "set the hub PVs to Retain (idempotent)"},
   ```

   Put the reader entry with the other reader entries and the operator entries with the other
   operator entries.

