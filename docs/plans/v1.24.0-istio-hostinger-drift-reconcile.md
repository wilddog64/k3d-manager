# v1.24.0 (F) — Istio ambient + hostinger GitOps drift reconcile

**Branch:** `k3d-manager-v1.24.0`
**Files:** `scripts/etc/argocd/applicationsets/istio-ambient.yaml`,
`scripts/lib/providers/k3s-hostinger.sh`, `scripts/etc/argocd/projects/shopping-cart.yaml.tmpl`

---

## Problem

Three F-workstream fixes were applied to the **live** hostinger/hub clusters and verified, but were
committed only to `archive/k3d-manager-v1.22.0-integration` (tip `03ed9ad6`) — never onto `main`. Git
is therefore out of sync with the running cluster: a fresh `deploy`/appset-reapply from `main` would
re-introduce the drift these fixes suppress.

**Root cause:** operational fixes made during the integration-branch era were not carried forward when
F was split; they are genuine gaps confirmed by an `archive`-vs-`main` diff.

---

## Fix

### Change 1 — `scripts/etc/argocd/applicationsets/istio-ambient.yaml`: suppress controller-owned drift

**Exact old block:**

```yaml
      namespace: ${ARGOCD_NAMESPACE}
      annotations:
        argocd.argoproj.io/sync-wave: '{{ .wave }}'
      labels:
        managed-by: k3d-manager
        app-type: mesh
    spec:
      project: platform
      destination:
```

**Exact new block:**

```yaml
      namespace: ${ARGOCD_NAMESPACE}
      annotations:
        argocd.argoproj.io/sync-wave: '{{ .wave }}'
        # ServerSideApply otherwise selects ArgoCD's structured-merge diff,
        # which retains Kubernetes default-value false drift for Istio's
        # DaemonSet and Deployment manifests.
        argocd.argoproj.io/compare-options: ServerSideDiff=true
      labels:
        managed-by: k3d-manager
        app-type: mesh
    spec:
      project: platform
      # Istiod changes these bootstrap values once its validation endpoints are
      # ready.  They are controller-owned runtime state, not Git drift.
      ignoreDifferences:
        - group: admissionregistration.k8s.io
          kind: ValidatingWebhookConfiguration
          name: istiod-default-validator
          jsonPointers:
            - /webhooks/0/clientConfig/caBundle
            - /webhooks/0/failurePolicy
        - group: admissionregistration.k8s.io
          kind: ValidatingWebhookConfiguration
          name: istio-validator-istio-system
          jsonPointers:
            - /webhooks/0/clientConfig/caBundle
            - /webhooks/0/failurePolicy
      destination:
```

### Change 2 — `scripts/lib/providers/k3s-hostinger.sh`: point Istio CNI at k3s/flannel paths

In `_hostinger_reapply_gitops_applicationsets`, after the `APP_CLUSTER_NAME` export.

**Exact old block:**

```bash
  export K3D_MANAGER_BRANCH
  APP_CLUSTER_NAME="${APP_CLUSTER_NAME:-${_HOSTINGER_KUBE_CONTEXT}}"
  export APP_CLUSTER_NAME

  local -a hub_kubectl=()
```

**Exact new block:**

```bash
  export K3D_MANAGER_BRANCH
  APP_CLUSTER_NAME="${APP_CLUSTER_NAME:-${_HOSTINGER_KUBE_CONTEXT}}"
  export APP_CLUSTER_NAME
  # Hostinger runs k3s/flannel.  The Istio CNI DaemonSet must mount the k3s
  # CNI directories rather than the generic Cilium defaults.
  AMBIENT_CNI_CONF_DIR="/var/lib/rancher/k3s/agent/etc/cni/net.d"
  AMBIENT_CNI_BIN_DIR="/var/lib/rancher/k3s/data/cni"
  export AMBIENT_CNI_CONF_DIR AMBIENT_CNI_BIN_DIR

  local -a hub_kubectl=()
```

### Change 3 — `scripts/etc/argocd/projects/shopping-cart.yaml.tmpl`: hub-owned destinations

**Exact old block:**

```yaml
  sourceRepos:
    - '*'
  destinations:
    - namespace: shopping-cart-apps
      name: ubuntu-k3s
```

**Exact new block:**

```yaml
  sourceRepos:
    - '*'
  destinations:
    # Hub-owned app-of-apps, identity, and Istio routing resources.
    - namespace: cicd
      server: https://kubernetes.default.svc
    - namespace: identity
      server: https://kubernetes.default.svc
    - namespace: istio-system
      server: https://kubernetes.default.svc
    - namespace: shopping-cart-apps
      name: ubuntu-k3s
```
