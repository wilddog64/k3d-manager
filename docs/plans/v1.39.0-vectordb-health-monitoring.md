# v1.39.0 — vectordb health in Hermes and Grafana

**Target branch:** `k3d-manager-v1.39.0`
**Status:** SPEC. Requested by the operator on 2026-09-26, after WS2/WS3 landed.
**Scope:** a Hermes sensor for the vector store, and the metrics a Grafana panel needs.

## Why

WS1 cost a day of live debugging that no dashboard would have shortened, because nothing watched
the component. The observed failure chain was: Vault path absent → `vectordb-postgres`
`SecretSyncedError` → `pod/vectordb-0` `CreateContainerConfigError`. Every link was visible to
`kubectl` and invisible to everything else.

There is a second failure mode that has not happened yet and is quieter: the index silently stops
being refreshed. `make find-similar-docs` keeps returning plausible results from a stale index, so
the dedup check degrades into confidently recommending the wrong prior art. Nothing about that is
visible from pod health.

## H1 — `bin/k3dm-vectordb-status` (new, Python, stdlib only)

One executable that emits every fact as JSON, so the sensor and the metrics publisher share one
source of truth and the probe can be executed end to end in a test.

```python
#!/usr/bin/env python3
"""Emit vectordb health facts as JSON. Read-only; never raises; always exits 0."""
import argparse
import json
import subprocess
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(ROOT / "scripts" / "lib"))

from hermes.prior_art import (  # noqa: E402
    KUBE_CONTEXT, NAMESPACE, TABLE, RetrievalUnavailable, iter_corpus, run_sql,
)

EXTERNAL_SECRET = "vectordb-postgres"
POD = "vectordb-0"


def kubectl_json_argv(kind, name, context=None, namespace=None):
    """Pure function so a test can assert the real argv without a cluster."""
    return ["kubectl", "--context", context or KUBE_CONTEXT,
            "-n", namespace or NAMESPACE, "get", kind, name, "-o", "json"]
```

Required JSON keys, all always present:

| Key | Type | Meaning |
|---|---|---|
| `available` | bool | the store answered a `SELECT` |
| `external_secret_synced` | bool or `null` | `SecretSynced` condition is `True`; `null` if unreadable |
| `pod_ready` | bool or `null` | `vectordb-0` `Ready` condition is `True`; `null` if unreadable |
| `rows` | int or `null` | `count(*)` from the table |
| `corpus_docs` | int | tracked docs on disk (never `null`; `iter_corpus` is offline) |
| `last_indexed_epoch` | float or `null` | `max(indexed_at)` as a Unix timestamp |

Rules:

- Exit 0 **always**, including when the cluster is unreachable. A probe that exits non-zero is
  indistinguishable from a broken probe.
- `null` means *could not read*, `false` means *read it and it is bad*. Never collapse the two —
  that distinction is what keeps a monitoring gap from reading as health.
- Support `--json` (default) and `--offline` (skip every cluster call; emit `available: false` with
  `corpus_docs` populated). `--offline` is what makes the end-to-end test possible.
- Reach the database only through `prior_art.run_sql`. Do **not** read the Postgres password.

## H2 — sensor `vectordb` in `scripts/lib/hermes/sensors.py`

Append after `kine`. Mirror its structure exactly.

```python
def vectordb(run, state, threshold=2, max_index_age_seconds=7 * 86400, now=None):
    """Report vector-store health from a read-only, injected probe."""
    try:
        code, output = run(["bin/k3dm-vectordb-status", "--json"], {})
        payload = json.loads(output) if code == 0 and output else {}
        required = ("available", "external_secret_synced", "pod_ready", "rows",
                    "corpus_docs", "last_indexed_epoch")
        if not all(name in payload for name in required):
            raise ValueError("invalid vectordb probe")
        ...
    except Exception:
        return record("vectordb", "unknown", "vectordb status source unavailable")
```

Check order — **the ExternalSecret first, because it is upstream of the pod.** The WS1 failure chain
was: Vault path absent → ExternalSecret `SecretSyncedError` → pod `CreateContainerConfigError`. A
sensor that reports the pod is the defect sends the operator to the wrong layer.

1. `external_secret_synced is False` → degraded, evidence names the credential:
   `"ExternalSecret vectordb-postgres not synced — the pod cannot start until it is"`.
   **Do not also report the pod in this branch.**
2. `pod_ready is False` → degraded, evidence names the pod.
3. `available is False` → degraded, evidence says the store did not answer.
4. `last_indexed_epoch` older than `max_index_age_seconds` → degraded, evidence gives the age in
   days and the row count.
5. Otherwise healthy, evidence `"rows=<n>, corpus=<m>, indexed <k>d ago"`.

Every `null` in a required field means the source is unreadable → `record(..., "unknown", ...)`,
never `degraded`. A missing kube context is not a store outage.

Debounce every degraded verdict through `_debounced("vectordb", True, threshold, state)`, and call
`_debounced("vectordb", False, threshold, state)` on the healthy path, exactly as `kine` does.
Attach the numeric facts via `data=`.

`now` is injectable so the staleness branch is testable without sleeping.

## H4 — `bin/k3dm-vectordb-metrics` (new) and the alert rules

The publisher reads `bin/k3dm-vectordb-status --json` and POSTs to
`{PUSHGATEWAY_URL}/metrics/job/k3dm-vectordb`, reusing the `bin/k3dm-webhook` idiom: a `/-/healthy`
precheck, `Content-Type: text/plain; charset=utf-8`, and a bounded retry loop. Default
`PUSHGATEWAY_URL` is `http://localhost:9091` from `K3DM_PUSHGATEWAY_URL`.

```
k3dm_vectordb_rows                          gauge
k3dm_vectordb_corpus_docs                   gauge
k3dm_vectordb_drift_docs                    gauge   corpus_docs - rows
k3dm_vectordb_last_index_timestamp_seconds  gauge
k3dm_vectordb_reachable                     gauge   1/0
k3dm_vectordb_external_secret_synced        gauge   1/0
```

Emit a gauge only when its source is non-`null`. Publishing `0` for "unknown" is what turns a
monitoring gap into a false alarm.

Call it at the end of a successful `make index-docs` and on the Hermes tick.

**The staleness trap is load-bearing and is designed around, not documented around.** Pushgateway
has no staleness: once the publisher stops, every gauge keeps its last value forever, so
`k3dm_vectordb_reachable == 1` would assert a healthy store indefinitely after the publisher dies.

- `k3dm_vectordb_last_index_timestamp_seconds` is the **only** series an alert may be built on,
  because it is the only one whose stale value is itself the alarm: `time() - <ts>` grows without
  bound once publishing stops.
- Alerting on `reachable == 0` is **forbidden** — it cannot fire.

New `scripts/etc/prometheus/rules/vectordb.yaml`:

```yaml
- alert: VectorDBMetricsStale
  expr: absent(k3dm_vectordb_last_index_timestamp_seconds)
  for: 1h
- alert: VectorDBIndexStale
  expr: time() - k3dm_vectordb_last_index_timestamp_seconds > 7 * 86400
  for: 15m
```

Match the file's existing `groups:` structure, labels and annotation style.

## Tests — `scripts/tests/hermes/test_vectordb_sensor.py` (new, pytest)

Stub only the injected `run`. The logic under test is real.

**The half-a-seam trap is explicitly in scope.** The `app-health-delta` suite kept 8 tests green
while its probe never executed, because the tests injected a stubbed `run` and asserted the parsing
of a hypothetical payload. So, in addition to the parsing cases:

1. `kubectl_json_argv` returns the exact expected argv, including context and namespace — so a
   renamed resource fails a test instead of silently returning `unknown` forever.
2. **One test executes `bin/k3dm-vectordb-status --offline` as a subprocess** and asserts it exits 0
   and emits every required key, the way `test_check_doc_links.py` exercises its script.
3. ExternalSecret `False` → degraded, and the evidence does **not** mention the pod.
4. Pod `False` with ExternalSecret `True` → degraded naming the pod.
5. Any required key `null` → `unknown`, **not** `degraded`. Separate test per field.
6. A malformed / empty payload → `unknown`.
7. Stale `last_indexed_epoch` → degraded; fresh → healthy, using injected `now`.
8. Debounce: the first degraded sample below `threshold` reports healthy, and the sample above it
   reports degraded.
9. The sensor never raises, for every payload in 3–7.

Every assertion must be **mutation-proved**: break the specific check, confirm that specific test
goes red, restore. Paste the red output per mutation. A test that cannot fail is not a gate.
