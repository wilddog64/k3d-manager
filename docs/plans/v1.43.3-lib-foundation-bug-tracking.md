## Problem

lib-foundation keeps its own bug docs (26 in `docs/bugs/` today), and none reach the Bug Tracking
dashboard:

- `bug-tally.py` and the bug metrics read only k3d-manager's top-level `docs/bugs/`. The subtree
  copy at `scripts/lib/foundation/docs/bugs/` is skipped by the "no `/` after `docs/bugs/`" filter,
  and it is stale anyway: it changes only on a subtree-pull.
- The docs do not follow k3d-manager's header conventions. With today's parser
  (`hermes.prior_art.doc_status`): 25 of 26 have priority `unset` and 14 have status `unknown`.

Only lib-foundation bugs filed from the k3d-manager side (in k3d-manager's `docs/bugs/`, like the
two `secret-store-data` bugs) are counted today.

## Decisions

- **Source = the lib-foundation clone at `origin/main`, not the subtree copy.** Path from
  `K3DM_LIB_FOUNDATION_DIR`, default `~/src/gitrepo/personal/lib-foundation`. Before reading,
  `git -C <dir> fetch --quiet origin main` (timeout 30 s); a failed fetch is logged and the existing
  `origin/main` is used. A missing directory or ref skips lib-foundation (logged, non-fatal);
  k3d-manager's metrics are unaffected.
- **lib-foundation releases are lib-foundation's own tags (`v0.5.2`, …).** Filed-in and fixed-in
  both come from tag ancestry **in the lib-foundation repo**. A `**Branch:** k3d-manager-v…` line
  in a lib-foundation doc names where it was found, not a lib-foundation release, so it is
  **ignored** for that repo; no branch fallback (lib-foundation branches are `fix/*`). An untagged
  commit gives `unknown`, as in the fixed-in spec.
- **One `repo` label on every bug series**: `repo="k3d-manager"` or `repo="lib-foundation"`.
  k3d-manager keeps its existing Pushgateway groups (`k3dm-bug-docs`, `k3dm-bug-open`,
  `k3dm-bug-releases`); its series gain the label in place. lib-foundation pushes to the same jobs
  with grouping key `/instance/lib-foundation`, so neither repo's push replaces the other's.
- **The dashboard shows one repo at a time**: a `repo` variable (custom, values `k3d-manager`,
  `lib-foundation`, default `k3d-manager`, single-select). Release axes do not mix (v1.x vs v0.x).
- **"Fixed this release" and "Open in later releases" stay k3d-manager concepts.** lib-foundation
  has no release branch, so `k3dm_bug_current_release_info` is never emitted for it and those tiles
  read 0 / no data for lib-foundation. Stated in the guide, not worked around.
- **Verified / Live-verified** for lib-foundation docs: `n/a`, as for k3d-manager releases before
  v1.43.2 (the convention is not used there).

## Fix

### 1. lib-foundation doc headers (Claude, not Codex, before dispatch)

In lib-foundation, branch `docs/bug-headers` from `origin/main`, PR #69 (done 2026-10-16; must merge
before the live proof). For each of the 26 `docs/bugs/*.md`:

- add `**Priority:** P0|P1|P2|P3` directly under Status, judged by the same rule as k3d-manager's
  `CLAUDE.md` (urgency, separate from Severity);
- give every doc a `**Status:**` line whose first word `doc_status` classifies: `OPEN`, `FIXED`,
  `IMPLEMENTED`, `CLOSED`, `DEFERRED`, keeping the existing text after an em dash.

Gate: the classification script in this plan's Verification reports 0 `unset` and 0 `unknown`.
This is judgment work on 26 docs, so Claude does it; the code below must still handle a doc
without the headers (`unset` / `unknown`), as it does for k3d-manager.

### 2. `scripts/bug-tally.py`: a repo directory

- New option `--repo-dir PATH` (default `ROOT`). Every `git` call uses it instead of `ROOT`.
  `_git` takes the directory from a module-level setting that `main()` sets once.
- New option `--repo-name NAME` (default `k3d-manager`). When it is not `k3d-manager`:
  - `BRANCH_RE` fallback is disabled (`_release_of_commit` returns tag or `(None, None)`);
  - `doc_release(text, ...)` is called so that a `branch_line` result is discarded and the
    tag-ancestry release is used instead.
- `--json` output gains `"repo": NAME`. No other output change; default behaviour (no new options)
  is byte-identical to today.

### 3. `bin/k3dm-vectordb-metrics`: publish both repos

- `_bug_texts(root, ref)`, `_tally(root, ref, full)` and `_bug_status_metrics` / `_release_metrics`
  / `_bug_metrics` take a `repo` argument (default `"k3d-manager"`) and put `repo="<repo>"` as the
  **first** label of every series they emit, including the unlabelled ones today
  (`k3dm_bug_docs_scan_timestamp_seconds`, `k3dm_bug_info_skipped`, `k3dm_bug_info_truncated`,
  `k3dm_bug_fixed_in_unknown_docs`).
- `_tally` passes `--repo-dir` and `--repo-name` for lib-foundation; it still runs
  `scripts/bug-tally.py` from k3d-manager's `root`.
- `_push_bug_group(job, payload, method, instance=None)`: with `instance`, the URL is
  `{base}/metrics/job/{job}/instance/{instance}`.
- `publish_bug_metrics(root, ref)`: after the k3d-manager publish (unchanged order and methods),
  call `_publish_lib_foundation_bugs()`, which resolves the directory, fetches, and runs the same
  three publishes for `ref="origin/main"`, `repo="lib-foundation"`, `instance="lib-foundation"`.
  Every failure is logged and non-fatal; it never changes `publish_bug_metrics`' return value.

### 4. Dashboard `grafana-dashboard-bugs.yaml`

- Add the `repo` variable (Decisions). Every panel target adds `repo="$repo"` to each
  `k3dm_bug_*` selector, merged with existing matchers.
- Panel titles unchanged. The guide explains the selector.

### 5. Docs
