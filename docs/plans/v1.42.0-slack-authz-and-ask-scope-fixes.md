## Fix 2 — slash commands must use the Slack caller's mapped role

**Root cause.** The relay sends `X-K3DM-Role: COMMAND_ROLES[command]` (admin for cluster-up/down/
resume, cleanup-stale-sandbox, argocd-upgrade; operator for cluster-refresh) and only `/k3dm` carries
`slack_user_id`. The webhook caps by Slack caller role only for `route["handler"] == "make"`.
The relay is the only sender of `X-K3DM-Role`, which is verified by grep across `bin/`,
`scripts/lib/` and `workers/`. Direct-token and cloud-bridge callers therefore never send it, and
`_effective_make_role` already returns the token role unchanged for them.

### 2a. Relay — carry the caller on every relayed request (`workers/slack-relay/index.js`)

In the slash handler, add the caller ID to `meta`:

```js
  const meta        = { role, actor, sourceCommand: command }
```
→
```js
  const meta        = { role, actor, sourceCommand: command, slackUserId: userId }
```

In `relay()`, inject it into the JSON body so no individual route can forget it:

```js
      body: JSON.stringify(payload)
```
→
```js
      body: JSON.stringify(meta.slackUserId ? { ...payload, slack_user_id: meta.slackUserId } : payload)
```

Leave the `/k3dm` payload's explicit `slack_user_id: userId` in place. It is harmless and keeps
the diff minimal. Do not change `COMMAND_ROLES` because it stays as the route's *ceiling*.
Before editing, check every other `relay(` call site, such as Events/thread forwarding, to see
whether it builds `meta`. If it does and has a user ID, pass `slackUserId` there too. Otherwise,
leave it alone and list it in your report.

### 2b. Webhook — apply the caller cap to every route (`bin/k3dm-webhook` `do_POST`)

```python
        request_role = _request_role(self.headers, token_role)
        if route["handler"] == "make":
            request_role = _effective_make_role(self.headers, body, token_role)
```
→
```python
        request_role = _effective_make_role(self.headers, body, token_role)
```

In `scripts/lib/webhook/policy.py`, update only the docstring of `_effective_make_role` to
`"""Cap a relayed request's role at the caller's mapped Slack role (unknown → reader)."""`.
Do not rename the function, because tests import it.

Expected behaviour:

| Caller | X-K3DM-Role header | Result |
|---|---|---|
| Slack user mapped admin | admin (`/cluster-down`) | admin → allowed |
| Slack user mapped reader | admin | reader → **403 before any worker** |
| Unmapped / empty `slack_user_id` | admin | reader → **403** |
| Slack user mapped admin | reader (`/cluster-status`) | reader (header is the ceiling) |
| Direct token, no header | — | token role, unchanged |
| Cloud-bridge capability token | — | unchanged (non-level role passthrough) |

## Fix 3 — ask-bash filesystem scope (`bin/k3dm-ask-bash`, `scripts/lib/webhook/agent.py`)

Three defects:
- The scope loop checks only argv elements that start with `/`, so `-c "cat /abs"` is never checked.
- The prefix match has no directory boundary.
- Canonicalization falls back to the raw string, so `/tmp/../Users/x` passes. Also, `/tmp` never
  matches its canonical form `/private/tmp`.

The bug doc is explicit that more regex is not a boundary. This fix therefore adds an
**OS-enforced boundary on macOS** (layer B) and closes the concrete wrapper holes as defence in
depth (layer A). The webhook runs on macOS only.

### Layer A — wrapper scope check

Replace the block that starts at the comment
`# Block file access outside allowed repos and diagnosis paths (absolute path arguments only)`
and runs up to, but not including, `exec /bin/bash "$@"` with logic that:

1. Defines `_canon <path>`:
   - first try `realpath -m`;
   - else, if the path exists, try `realpath`;
   - else, if the path contains no `..` component, return it unchanged;
   - **else fail closed**, which means deny.
2. Builds `_ALLOWED` by canonicalizing each existing allowlist entry, so `/tmp` becomes
   `/private/tmp` on macOS.
3. Matches with a directory boundary: `[[ "$real" == "$p" || "$real" == "$p/"* ]]`.
4. Collects candidate tokens from **all** of `"$@"`, including the `-c` string. It splits that
   string on whitespace and the characters `;|&()<>'"=` and checks every token that:
   - starts with `/`;
   - contains a `..` path component, which is denied outright;
   - starts with `~`, which is denied outright.
5. Denies these shell expansions anywhere in `$CMD` before the scope loop:
   - `` ` ``
   - `$(`
   - `${`
   - `$` followed by a letter or underscore

   Positional `$1`, `$2` and similar stay allowed so `awk '{print $1}'` keeps working.
6. Denies `cd`/`pushd` with no argument, `-` or `~`, because a bare `cd` jumps to `$HOME`.
   `cd /allowed/path` passes through the token check.

Keep every existing deny rule above the block unchanged.

### Layer B — macOS `sandbox-exec` read boundary

Replace the final `exec /bin/bash "$@"` with:
- on Darwin, when `K3DM_ASK_OS_SANDBOX` is not `0`, `exec /usr/bin/sandbox-exec -p "$_profile" /bin/bash "$@"`;
- on Darwin with the sandbox enabled but `/usr/bin/sandbox-exec` missing, **deny**, which is fail-closed;
- on non-Darwin, keep the current `exec /bin/bash "$@"`, so Linux CI is unaffected.

`$_profile` is generated in the wrapper and uses canonical paths:

```
(version 1)
(allow default)
(deny file-read* file-write* (subpath "<canon $HOME>"))
(allow file-read* (subpath "<K3DM_REPO>") (subpath "<SHOPPING_CARTS_ROOT>")
                  (subpath "<HOME>/.local/share/k3d-manager") (subpath "<HOME>/.kube")
                  (subpath "<HOME>/.config/argocd") (subpath "<HOME>/.config/helm")
                  (subpath "<HOME>/Library/Preferences/helm") (subpath "<HOME>/Library/Caches/helm")
                  (literal "<HOME>/.gitconfig") (subpath "<HOME>/.config/git"))
(allow file-write* (subpath "<HOME>/.kube/cache") (subpath "<HOME>/Library/Caches/helm"))
```

Escape any `"` or `\` in the substituted paths, or deny when a path contains them.
`~/.ssh`, `~/Library/Keychains`, `~/.aws` and every other path under HOME stay unreadable to agent
commands. **Known, accepted:** `~/.kube` remains readable because kubectl needs it, and that grants
nothing beyond the kubectl access the agent already has.

### Layer C — make sure the wrapper is actually the shell

`scripts/lib/webhook/agent.py` injects `bin/.ask-sandbox/bash` via `PATH` only. Claude Code picks
its shell from `$SHELL`, so on a zsh host the wrapper may never run. In the `env = {...}` dict at
~line 559, add:

```python
                "SHELL": str(Path(sandbox_bin) / "bash"),
```

The operator must verify this live; see below.

### Tests

Extend the existing ask-bash BATS suite. Find it with `grep -rln k3dm-ask-bash scripts/tests`, or
create `scripts/tests/bin/ask_bash_scope.bats`. Use a temp `HOME`, a temp repo root and a canary
file outside both.

Each of these must exit non-zero and must not print the canary:
- `-c "cat $canary"`
- a relative `-c "cat ../../canary"`
- `-c "cat ~/canary"`
- `-c 'cat $HOME/canary'`
- `-c 'cat $(echo /x)'`
- a symlink inside the repo pointing at the canary
- a sibling-prefix dir `<repo>-evil/canary`
- `/tmp/../<outside>/canary`
- `-c "cd; cat canary"`

Each of these must still succeed:
- `-c "cat <repo>/README.md"`
- `-c "git -C <repo> log -1 --oneline"`
- `-c "ls /tmp"`
- `-c "kubectl version --client"`, or skip it if kubectl is absent
- `-c "awk '{print \$1}' <repo>/file"`

Run the Layer B tests only on Darwin, using `skip` elsewhere. With `K3DM_ASK_OS_SANDBOX=1`, a read
of `$HOME/canary` through an **allowed-looking** command such as `-c "cat $HOME/canary"` must fail.
Use a temp `HOME` for this so the real home is never touched.
