## Problem

The current `scripts/lib/hermes/prior_art.py` `CORPUS_GLOBS` covers `docs/bugs/*.md`, `docs/issues/*.md`, `docs/plans/*.md`, `docs/retro/*.md`, and `docs/job-failures/*.md`; it excludes `memory-bank/`. Thus `find-similar-docs` and `/ask-docs` cannot semantically retrieve `memory-bank/activeContext.md` and `memory-bank/progress.md` as corpus documents. Those files are currently readable directly by agents, but contain ongoing context, decisions, implementation status, and pending work not necessarily represented in a dated bug or spec.

On 2026-10-15 an operator-approved note was added to `memory-bank/activeContext.md` proposing Gemini's original red-team role and independent worktrees as a **suggestion only**, not approved implementation. A question about the Gemini proposal should retrieve that note with its actual status and source, without confusing it with an approved plan.

## Goal

Make selected, Git-tracked memory-bank context available for provenance-aware semantic lookup, without compromising current approval authority, security, or the Gemini free tier.

## Selective inclusion

- Index `memory-bank/activeContext.md` and `memory-bank/progress.md`.
- Optionally index existing `memory-bank/projectbrief.md`, `memory-bank/systemPatterns.md`, and `memory-bank/techContext.md` if files exist and pass allowlist/safety checks.
- Do **not** recursively include all of `memory-bank/`. Exclude `memory-bank/archive/` by default (could be a later opt-in with historical status), secrets, credentials, tokens, user-specific private material, generated local-state files and untracked documents.
- Make the allowlist explicit and testable in both Git-ref and local working-tree corpus discovery. Do not inadvertently index files from outside the selected Git ref.

## Chunking, identity and lifecycle

`activeContext.md` and `progress.md` can be long, mutable and frequently edited. Avoid embedding the whole file on every change. Introduce deterministic **section/entry-level chunks** that preserve meaningful context while bounding Gemini token/request use.

- Stable chunk identifiers derived from source path and a deterministic section/entry identity; do not use only a positional index that shifts with every insertion.
- Content-hash changed chunks so unchanged text continues to hit the existing SQLite embedding cache.
- Record original source path, heading/entry label, source Git commit or ref provenance, chunk ID, `source_type=memory`, active vs archived status, and indexed/fetched timestamps where supported.
- Ensure truncation, deletion, rename, reordering and changed chunk content prune/update the correct rows without leaving stale knowledge. Preserve all existing fail-closed mass-prune protections.
- Reuse the current vector-store schema and search APIs where feasible; explicitly design compatibility/migration for existing one-row-per-document assumptions. Do not blindly overwrite other document types or inflate the documented corpus counts without labeling what they count (files vs chunks/rows).

## Retrieval behavior

- Permit `/ask-docs` and `find-similar-docs` to retrieve memory-bank chunks, link to the exact Git file/section, and explain status/freshness.
- Distinguish the current memory-bank from historical bugs/specs using bounded `source_type` metadata and a clearly stated ranking/citation strategy. No unrestricted recursive memory retrieval.
- Retrieved notes remain **advisory**. Current Git source and explicit human approvals are authoritative; a semantic match does not grant implementation authority or override a newer spec or branch.
- Test recency and conflicting context: archived/superseded notes must not silently outrank current explicit decisions.
- Never include secrets, private tokens, raw credentials, or sensitive local runtime state in embedded content, search results or logs; define a content guard and failure behavior before enabling.

## Quota and operational integration

- Reuse existing Git fetch, fingerprint, `index-docs`, SQLite cache, Gemini quota pause/resume, batch commits and pgvector pipeline.
- New/changed chunks, not entire mutable files, should drive API embedding; unchanged chunks should reuse cached vectors.
- Expose separate document-file versus chunk-row counts and current memory-bank backlog where necessary; do not break existing `k3dm_vectordb_drift_docs = corpus_docs - rows` assumptions without updating the metric's contract and dashboard. A mixed-granularity count can otherwise produce misleading drift.
- Integrate with v1.45.2 index provenance and quota telemetry when available; avoid new services or external vector stores.

## Implementation investigation

Review `scripts/lib/hermes/prior_art.py` (`CORPUS_GLOBS`, `iter_corpus`, `corpus_fingerprint`), `scripts/index-docs.py`, pgvector schema, `EmbedCache`, `bin/k3dm-vectordb-status`, `bin/k3dm-vectordb-metrics`, `/ask-docs` and `find-similar-docs` interfaces. Document the minimum schema/search change required before implementation. Avoid scope creep into general memory-bank synchronization or autonomous approval.

## Acceptance and negative tests

1. A new entry in `activeContext.md` is discovered on the configured branch and retrievable with a citation to the correct Git path and heading; semantic QA correctly says the Gemini red-team proposal is **not approved implementation**.
2. Editing only one entry causes only changed chunks to be embedded; unchanged entries hit SQLite cache or retain existing rows. Confirm bounded Gemini usage with mock API.
3. Entire section/file removal prunes only its obsolete chunks; manifest and mass-delete safeguards fail closed.
4. `memory-bank/archive/`, credentials and disallowed paths never enter the corpus, metrics, or retrieval payload.
5. Deterministic chunks survive reordering/insertion without wholesale re-embedding.
6. Search results distinguish authoritative current notes from historical or superseded context; approval state is never inferred from similarity alone.
7. Mixed corpus file/chunk accounting does not break row/corpus/drift/backlog semantics or any existing dashboards.
8. No duplicate results or stale chunks after rerun, quota pause, hub recovery or SQLite-cache reuse; resume without re-embedding completed chunks.
9. Unit tests, mutation/negative tests and canonical `test-all` pass. Verify retrieval relevance on a small labeled evaluation set, not merely that vectors were inserted.

## Exclusions / rollout

No deployment changes or agent permissions from this filing. Pilot only selected memory-bank files; keep the archived corpus and long-term memory redesign out of scope until evaluated. Claude may reprioritize during backlog triage; this doc does not require implementation in the next release.
