# v1.24.0 (D) — Webhook auth.py hardening reconcile

**Branch:** `k3d-manager-v1.24.0`
**Files:** `scripts/lib/webhook/auth.py`, `scripts/tests/lib/webhook.bats`

---

## Problem

`scripts/lib/webhook/auth.py` is **live** — `bin/k3dm-webhook:52` imports `_verify_slack_signature`
from it. The `archive/k3d-manager-v1.22.0-integration` branch (tip `03ed9ad6`) hardened this module
against malformed input, but that hardening was never brought onto `main`; it is a genuine gap, not a
superseded fork.

**Root cause:** the D webhook-hardening workstream was split off the integration branch, and the
`bin/k3dm-webhook` rate-limit/Content-Length hunks shipped in v1.23.0 (`ee32837d`) while the sibling
`auth.py` Slack-signature hardening was left on the archive branch.

Two concrete defects on `main` today:
1. `_verify_slack_signature` calls `int(timestamp)` and `raw_body.decode()` unguarded — a malformed
   timestamp or a non-UTF-8 body raises `ValueError`/`UnicodeDecodeError` instead of failing closed.
2. No `_slack_user_is_allowlisted` helper — callers cannot cheaply ask "is this Slack user explicitly
   mapped?" without reaching into `SLACK_ROLE_MAP` and re-implementing the fail-closed default.

---

## Reproduction

Post to the webhook's Slack endpoint with `X-Slack-Request-Timestamp: not-a-number` (or a body that is
not valid UTF-8). On `main`, `_verify_slack_signature` raises instead of returning `False`.

---

## Fix

### Change 1 — `scripts/lib/webhook/auth.py`: fail closed on malformed timestamp/body

**Exact old block:**

```python
    if not SLACK_SIGNING_SECRET:
        return False
    import time
    if abs(time.time() - int(timestamp)) > 300:
        return False
    base = f"v0:{timestamp}:{raw_body.decode()}"
```

**Exact new block:**

```python
    if not SLACK_SIGNING_SECRET:
        return False
    import time
    try:
        timestamp_value = int(timestamp)
        body_text = raw_body.decode()
    except (AttributeError, TypeError, UnicodeDecodeError, ValueError):
        return False
    if abs(time.time() - timestamp_value) > 300:
        return False
    base = f"v0:{timestamp}:{body_text}"
```

### Change 2 — `scripts/lib/webhook/auth.py`: add `_slack_user_is_allowlisted`

**Exact old block (end of file):**

```python
def _slack_user_role(user_id):
    """Resolve a Slack user ID to reader|operator|admin. Unknown → reader (fail closed)."""
    return SLACK_ROLE_MAP.get((user_id or "").strip(), "reader")
```

**Exact new block:**

```python
def _slack_user_role(user_id):
    """Resolve a Slack user ID to reader|operator|admin. Unknown → reader (fail closed)."""
    return SLACK_ROLE_MAP.get((user_id or "").strip(), "reader")


def _slack_user_is_allowlisted(user_id):
    """Return True only when a non-empty Slack user ID is explicitly mapped."""
    return bool((user_id or "").strip() in SLACK_ROLE_MAP)
```

### Change 3 — `scripts/tests/lib/webhook.bats`: bring the auth-specific tests, DO NOT duplicate

Source: `git show archive/k3d-manager-v1.22.0-integration:scripts/tests/lib/webhook.bats`.

**Bring ONLY the tests that exercise `auth.py` behavior not already covered on `main`:**

- `Slack ignores signed unknown and user-less commands without creating anchors`

- `webhook rejects malformed Content-Length without killing either POST route`

If a brought-in test references a helper (`_wait_cluster_idle`, `setup_file` additions) not on `main`,
