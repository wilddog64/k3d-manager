## Goal

The agent-cost dashboard reads "Ledger coverage 36.3%" and "Outside ledger $76.77" (30d, 2026-11-01). Read
together, they suggest most model use cannot be tied to tracked work, so cost per verified spec looks unreliable.
Replaying the exporter's own functions (`_session_files`, `read_ledger`, `_cost`) over the M4's
`~/.codex/sessions` on 2026-11-01 shows that the panels mislead more than the ledger is missing data:

| 30d, 655 Codex sessions, $103.81 priced | Sessions | Priced cost | Share |
|---|---|---|---|
| Ledgered dispatch (worktree, `codex_usage` in the ledger) | 239 | $27.15 | 26.2% |
| Operator's own interactive Codex in the main checkout (`codex-tui`) | 19 | $61.91 | 59.6% |
| Raw `codex exec` from the main checkout (2026-10-02 to 10-20, before every dispatch went through `make codex-dispatch`) | 135 | $12.88 | 12.4% |
| Codex in other repos (shopping-cart, lib-foundation, rabbitmq-client-java) | 51 | $1.40 | 1.3% |
| Dispatch worktree with no `codex_usage` event (a real ledger gap) | 11 | $0.48 | 0.5% |
| Guardian approval reviews (`thread_source: guardian_review`, model `codex-auto-review`) | 200 | $0.00 shown | — |

In the 7d window, operator interactive sessions are 8 sessions and $48.15 of $64.22 (75%), and raw exec is zero.

Four problems follow:

1. **Coverage counts sessions, not cost.** The 200 guardian reviews (sessions in the ledger's denominator, a few
   cents of output each) pull coverage down to 36.3%. Excluding them, session coverage is 52.5%; by cost, dispatch
   coverage is 27.15 / (27.15 + 12.88 + 1.40 + 0.48) = 64.8%, and 99.8% in 7d (16.03 / 16.07).
2. **"Outside ledger" is one bucket.** Interactive work by the operator is not a ledger gap. It is attributable,
   just not to a dispatched spec. Only the $0.48 in worktree sessions is missing data the dispatch tool should have
   written.
3. **Guardian reviews are unpriced, not free.** The 200 reviews used 117,368,416 input and 184,774 output tokens on
   `codex-auto-review`, which has no row in `scripts/etc/agent/codex-model-prices.json`, so `_cost` returns None and
   the panels count $0. Every review names its parent session in `parent_thread_id` (226 of 226 found on
   2026-11-01: 71 ledgered dispatches, 83 interactive, 69 raw exec, 3 unledgered worktree), so the reviews can be
   assigned exactly.
4. **Cost per verified spec includes only ledgered dispatch cost**, with no statement of how much spend sits outside
   it, so the operator cannot judge whether the number is representative.

## Change

1. **Classify every Codex session** in `bin/k3dm-dispatch-metrics` from its `session_meta` line (fields captured on
   the M4, Codex CLI 0.166.0, 2026-11-01: `originator`, `cwd`, `thread_source`, `parent_thread_id`, `source`),
   into exactly one `category`:
   - `dispatch` — has a `codex_usage` ledger event.
   - `dispatch_unrecorded` — `cwd` under the worktree root (`K3DM_WORKTREE_ROOT`) with no `codex_usage` event.
   - `guardian` — `thread_source` is `guardian_review`. Assigned to its parent's category for cost (see 2); counted
     on its own for sessions.
   - `interactive` — `originator` `codex-tui`, outside the worktree root.
   - `exec_untracked` — `originator` `codex_exec`, outside the worktree root.
   - `other` — anything else, including an unreadable `session_meta`.
2. **Assign guardian cost to the parent.** A guardian session's tokens and cost are added to the session named by
   `parent_thread_id`, and so to that session's category (and to the dispatched task, when the parent is
   ledgered). When the parent is not among the scanned sessions, the review stays `guardian` with
   `parent="missing"`. Following the parent link is one level only: a parent that is itself a guardian session is
   `guardian` with `parent="missing"`.
3. **Unpriced is not zero.** Sum tokens of models with no price row as
   `k3dm_codex_unpriced_tokens{window,model,kind}` (`kind` = `input`, `cached_input` or `output`). The cost panels show
   "+ N unpriced tokens" beside a dollar figure when N > 0. Do not add a `codex-auto-review` price unless the operator
   supplies one; that is a separate edit to the price file with its source.
4. **Metrics.** `k3dm_codex_sessions{window,category}` and `k3dm_codex_api_cost_usd{window,category}` (priced
   cost after step 2). Keep `k3dm_dispatch_codex_sessions{ledgered}` and `k3dm_dispatch_unledgered_api_cost_usd`
   for one release, marked deprecated in the guide, then remove them in the following release.
5. **Dashboard** (`grafana-dashboard-agent-cost.yaml`):
   - Replace "Ledger coverage" with **"Dispatch coverage (by cost)"** =
     `dispatch / (dispatch + dispatch_unrecorded + exec_untracked)` cost: the share of agent-run work that the ledger
     records. Description says interactive work and guardian reviews (assigned to their parents) are not in the
     denominator.
   - Replace "Outside ledger" with **"Codex spend by category"**, a bar gauge of `k3dm_codex_api_cost_usd` by
     category, with the unpriced-token note.
   - Add **"Ledger gaps"**: cost and session count of `dispatch_unrecorded` only. This is the number the dispatch tool
     should drive to zero.
   - Beside cost per verified spec, add **"Spend outside dispatch"** = (interactive + exec_untracked + other) cost / all
     cost, so the per-spec figure is read against how much spend it leaves out.
   - Panels may move or narrow; the grid must stay valid.
6. **Close the gap at its source.** List the 11 `dispatch_unrecorded` sessions (slug, run, exit state) in the
   implementation report. If they share a cause in `bin/k3dm-codex-dispatch` (for example, a resumed or abandoned run
   that never writes `codex_usage`), file it as a bug with its own spec. Do not fix it inside this plan.
7. **Docs.** `docs/guides/grafana-dashboards/k3dm-agent-cost.md`: the categories, how guardian reviews are assigned,
   unpriced tokens, the new panels, and that the old coverage number is not comparable.

- Do not put prompts, `cwd` paths, session IDs or parent IDs into metric labels or the Pushgateway; `category`,
  `window`, `model`, `kind` and `parent="missing"` are the only new label values.
- Do not read message content to classify a session; `session_meta` fields only.
- Do not change `bin/k3dm-codex-dispatch` or the ledger format (see Change 6).
- Do not edit `scripts/tests/fixtures/agent-dispatch-dashboard-pre-split.yaml`.
- Tests use a temp `CODEX_HOME` and ledger (asserted not to be `~/.codex` or the real worktree root) and the
  127.0.0.1:9 Pushgateway pin.
