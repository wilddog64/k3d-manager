## Problem

Grafana sorts the Open bugs table's **Release** column, and the **Release** dropdown, as plain
text. The order comes out as `v1.1.0`, `v1.14.0`, `v1.16.0`, `v1.22.0`, `v1.5.0`. The dropdown's
`sort: 8` (natural descending) has no effect on the hub's Grafana 11.4.0. The table's default
order is priority, then filed date; release plays no part.

## Fix: one order label whose text order is version order

Emit one extra label, `release_order`, on `k3dm_bug_open_info`:

```text
release_order="<inverted key> <release>"
```

- **Inverted key:** each part of `vX.Y.Z` becomes `9999 - part`, zero-padded to 4 digits, joined
  by `.`. For example, `v1.43.2` becomes `9998.9956.9997`.
- **`unassigned`:** the key is `9999.9999.9999`, so the label is `9999.9999.9999 unassigned`.

Ascending text order of this label is newest release first, with `unassigned` last. The
`release` label and its filter are unchanged.

### 1. `bin/k3dm-vectordb-metrics`, `_open_bug_metrics`

Add this helper above `_open_bug_metrics`:

```python
def _release_order(release):
    match = re.fullmatch(r"v(\d+)\.(\d+)\.(\d+)", release)
    if not match:
        return "9999.9999.9999 unassigned"
    return ".".join(f"{9999 - int(part):04d}" for part in match.groups()) + f" {release}"
```

In `_open_bug_metrics`:

- Replace
  `sort_key = f"{priority} {filed or '9999-99-99'} {stem}"`
  with
  `sort_key = f"{_release_order(release)} {priority} {filed or '9999-99-99'} {stem}"`.
  The default table order becomes newest release first, then priority, then filed date.
- Add `release_order="{_release_order(release)}"` as the **last** label of `k3dm_bug_open_info`,
  after `release`. The other labels and their order stay the same.
- Do not change `k3dm_bug_open_release_docs`, `_skipped`, `_truncated`, or the 200-row cap.
  The cap now keeps the newest releases' rows first. That is intended.

### 2. `scripts/etc/argocd/platform-ops/grafana-dashboard-bugs.yaml`

**2a. Table (panel 23, "Open bugs").**

- The visible Release column comes from `release_order`, not `release`.
  - `organize.indexByName`: replace `"release": 1` with `"release_order": 1`.
  - `excludeByName`: add `"release": true`.
  - `renameByName`: replace `"release": "Release"` with `"release_order": "Release"`.
- In the existing `byName` / `Release` override, keep `custom.width` 90 and add:

  ```json
  {"id": "mappings", "value": [{"type": "regex", "options": {"pattern": "^\\S+ (\\S+)$", "result": {"text": "$1", "index": 0}}}]}
  ```

  The cell shows `v1.43.2`. Clicking the header sorts by the raw value, which is version order.
- The `sortBy` transformation on `sort_key` (ascending) is unchanged.

**2b. Release dropdown (`templating.list[0]`).** Change only these keys:

| Key | Before | After |
|---|---|---|
| `query.query` and `definition` | `label_values(k3dm_bug_open_info, release)` | `label_values(k3dm_bug_open_info, release_order)` |
| `regex` | absent | `/^\S+ (?<value>\S+)$/` |
| `sort` | `8` | `0` |

With `sort: 0`, Grafana keeps the order Prometheus returns, which is ascending raw label value,
so newest first. The regex sets the option value and text to the bare release. Every panel still
filters on `release=~"$release"`.

**2c. Descriptions.** Add one sentence to panel 23's description: "Sorted newest release first,
then by priority; click Release to re-sort by version."
