## Problem

Codex runs on the operator's $20/month ChatGPT plan, so a run costs nothing extra. The flat spend is
$64/month: ChatGPT, Claude and Gemini at $20 each, and GitHub at $4. The operator wants to see what
the Codex work would cost at OpenAI API prices, and how efficiently it turns into landed specs.

The ledger can't price a run today. `codex_exit.tokens` is the "tokens used" line Codex prints:
uncached input plus output. It leaves out cached input, which is most of the volume. Measured on run
`hub-apps-settle-wait` (2026-10-17):

- input 611,180, of which cached 561,408;
- output 5,912;
- "tokens used" 55,684.

The full breakdown is in Codex's own session record,
`${CODEX_HOME:-$HOME/.codex}/sessions/YYYY/MM/DD/rollout-*-<session id>.jsonl`. Its last
`"total_token_usage"` object holds `input_tokens`, `cached_input_tokens`, `output_tokens` and
`reasoning_output_tokens`. `codex exec resume` continues the **same** session id, so a session's
last usage is cumulative across resumes. The run log's first `session id: ` line names the session,
as `_dispatch_resume` already parses it.

## Design

The **cost formula**, per session, in USD:

```
(input − cached) × input_rate + cached × cached_input_rate + output × output_rate   (rates per 1M tokens)
```

`reasoning_output_tokens` is already part of `output_tokens`; do not add it again.

**Metrics.** Every scope is a time window or a release from plan 3, unless marked otherwise.

| Metric | Definition |
|---|---|
| API-equivalent cost per spec | The task's priced sessions summed (last usage per session) |
| API-equivalent cost by model | Every session in scope, summed per `model`; unpriced models show tokens only |
| Cost per landed spec | **All** Codex usage in scope (landed, refused, abandoned, still running) ÷ landed tasks in scope |
| Cached-token percentage | Σ cached_input ÷ Σ input over all sessions in scope |
| Subscription cost | The flat monthly plans from the prices file, unscoped |
| Instrumentation coverage | Codex sessions started in the window that appear in the ledger ÷ all Codex sessions started in the window. Time windows only |

Two changes from the suggested list:

- **"Landed", not "verified".** Landing means the land gate passed (tests and scope). It is not a live
  proof, and the dashboard must not claim one.
- **All usage, not landed usage.** The numerator includes refused and abandoned attempts; the ledger
  holds 6 `land_refused` events as of 2026-10-17. Pricing only landed tasks would hide what retries
  cost.

**Which scope a session belongs to.**
- **Time scope:** the `ts` of the session's last `codex_usage` event.
- **Release scope:** its `version`.
- **Coverage:** a session's start time, from the session file's first `session_meta` timestamp.

## Changes

### C1. `scripts/etc/agent/codex-model-prices.json` (new)

```json
{
  "currency": "USD",
  "unit": "per_million_tokens",
  "checked": "2026-10-17",
  "source": "OpenAI API standard short-context rates after the 2026-07-30 cut, via third-party price trackers; not yet confirmed on openai.com/api/pricing",
  "models": {
    "gpt-5.6-luna": {"input": 0.20, "cached_input": 0.02, "output": 1.20}
  },
  "subscriptions_usd_per_month": {"chatgpt": 20, "claude": 20, "gemini": 20, "github": 4}
}
```

A model with no entry is **unpriced**. Never fall back to another model's rates.

### C2. `bin/k3dm-codex-dispatch`: record usage

1. New helper `_dispatch_codex_usage <run-log> <version> <slug>`.
   - Read the first `session id: ` value from the log. Find exactly one file matching
     `${CODEX_HOME:-$HOME/.codex}/sessions/*/*/*/rollout-*-<id>.jsonl`.
   - From it, take the last `total_token_usage` object and the last `"model"` string.
   - Append a ledger event:
     ```
     {"event":"codex_usage","version":…,"slug":…,"session":<id>,"model":<model or null>,
      "input":N,"cached_input":N,"output":N}
     ```
     Use `_dispatch_ledger_event`.
   - If there is no session id, no file or several files, or the JSON can't be parsed, print one
     `[codex-dispatch] WARNING:` line and append nothing. It must never fail the dispatch.
2. Call it in both places that call `_dispatch_codex_exit` (start and resume), right after that call,
   with the same log path.
3. New subcommand `usage-backfill`. It walks every `<root>/<version>/<slug>.run/codex*.log` and calls
   the helper for each log whose `(version, slug, session)` has no `codex_usage` event yet.
   - Idempotent: running it twice appends nothing new.
   - Prints `backfilled: N` and `missing: M`. M counts logs whose session file no longer exists.
   - Add it to the usage text.

### C3. `bin/k3dm-dispatch-metrics`: price it

1. **Prices and session files.**
   - Load the prices from `scripts/etc/agent/codex-model-prices.json`, resolved from the script's
     repo root. A missing or unreadable file means everything is unpriced and no subscriptions are
     emitted. It is not an error.
   - Add `--prices PATH` and `--codex-home PATH` options for tests. The defaults are that file and
     `${CODEX_HOME:-$HOME/.codex}`.
2. **Sessions.** Group `codex_usage` events by `session`, keeping the last by `ts`.
3. **Per task.** Add `api_cost_usd` to `_task_metrics`'s dict: the sum over the task's sessions, or
   `None` if any session is unpriced or there are none. Pass it through `tasks` as the last tuple
   element.
4. **Per scope**, emitted in `_render_scope` after plan 3's existing lines:
   - `k3dm_dispatch_task_api_cost_usd{window,version,slug}`: priced landed tasks only, inside the
     existing `TASK_CAP` loop.
   - `k3dm_dispatch_api_cost_usd{window}`: priced cost of **all** sessions in scope, `0` when none.
   - `k3dm_dispatch_api_cost_per_landed_usd{window}`: the line above ÷ landed count. Omit the line
     when landed is 0.
   - `k3dm_dispatch_api_cost_by_model_usd{window,model}`: priced models only.
   - `k3dm_dispatch_codex_tokens_by_model{window,model,kind}`, with `kind` = `uncached_input`,
     `cached_input` or `output`, for every model including unpriced ones.
   - `k3dm_dispatch_cached_input_ratio{window}`: Σ cached ÷ Σ input. Omit it when Σ input is 0.
   - `k3dm_dispatch_api_cost_unpriced_sessions{window}`.
5. **Coverage, time windows only.**
   - Scan `<codex-home>/sessions/*/*/*/rollout-*.jsonl`. Skip any file whose mtime is older than
     the longest time window (30d) without opening it; there were 593 files on 2026-10-17. For each
     remaining file, read only:
     - the first line, `{"type":"session_meta","payload":{"id":…,"timestamp":…}}`, taking `payload.id`
       and `payload.timestamp`;
     - the last `total_token_usage` and the last `"model"`.
   - Stream each file line by line. Never load or keep anything else.
   - Emit `k3dm_dispatch_codex_sessions{window,ledgered="true|false"}`.
   - Emit `k3dm_dispatch_unledgered_api_cost_usd{window}`, priced from the unledgered sessions only.
   - Release scopes get no coverage series.
   - A missing sessions directory emits nothing.
6. **Subscriptions, global and unlabelled by window.** Emit
   `k3dm_dispatch_subscription_usd_per_month{plan}` once per plan.
7. **Byte-identical guard.** Plan 3's test 1 golden for the time windows may change only by these
   new lines appended at the end of each window's block. Every earlier line stays byte-identical and in
   the same order.

## Tests

`scripts/tests/bin/test_dispatch_metrics.py`. Use synthetic ledgers, and a temporary prices file and
`--codex-home`. Never read the real `~/.codex`.

1. **Cost formula.** One `gpt-5.6-luna` session with input 611180, cached 561408 and output 5912 gives
   `api_cost_usd` = 0.0099544 + 0.01122816 + 0.0070944 = 0.02827696, to within 1e-9.
2. **Resume is not double-counted.** The same session has two `codex_usage` events, the second with
   larger cumulative numbers. Only the second is priced. A second *session* on the same task is added.
3. **Unpriced model.**
   - No `task_api_cost_usd` series for that task.
   - `unpriced_sessions` is 1.
   - The model appears in `codex_tokens_by_model` and not in `api_cost_by_model_usd`.
4. **Per landed counts failures.** Two tasks each cost $1: one landed, one with only `land_refused`.
   `api_cost_usd` = 2 and `api_cost_per_landed_usd` = 2. With no landed tasks, the per-landed line is
   absent.
5. **Cached ratio.** Σcached ÷ Σinput across two sessions, to within 1e-9.
6. **Coverage.**
   - Three fake session files in the window; two of their ids are in the ledger. That gives
     `ledgered="true"` 2 and `"false"` 1.
   - `unledgered_api_cost_usd` prices only the third.
   - A file started outside the window is not counted, and a file whose mtime is older than 30d
     is never opened (patch `open` or check through a counter).
   - No coverage series appears for a release scope.
   - The fake files also contain a user-prompt line holding the string `SECRET-PROMPT`. Assert it
     appears nowhere in the rendered output.
7. **Subscriptions.** Exactly four `subscription_usd_per_month` lines, without a `window` label.
8. **Dashboard.** Parse the ConfigMap. Assert that:
   - the `Per spec` panel has an `API equiv.` target on `k3dm_dispatch_task_api_cost_usd`;
   - the seven cost panels exist by title, and `Projected / month` queries `window="7d"`, not
     `$window`;
   - no `gridPos` rectangles overlap.

`scripts/tests/bin/codex_dispatch.bats`. Use the existing stubbed `K3DM_CODEX_BIN`, and point
`CODEX_HOME` at `$BATS_TEST_TMPDIR` with a fake session file named for the id the stub prints:

10. With no session file present, the start still succeeds, prints the WARNING, and appends no

## What NOT to Do

  timestamp, the `total_token_usage` numbers, and the model name. Session files hold full prompts and
  tool output.
- Do NOT rewrite or delete existing ledger lines; the ledger stays append-only.
- Do NOT change existing series names or plan 3's time-window or release semantics.
- Do NOT modify files outside the Component list.
