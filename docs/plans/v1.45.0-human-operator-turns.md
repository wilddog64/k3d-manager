**Priority:** P3 (a dashboard mislabel plus missing telemetry; nothing is broken and no decision depends on it yet)
**Approval:** operator 2026-11-07: "the truely what I want to know if this a really human intervention or your interaction with sub-agents. can we capture turn human interaction?", then "can we aslo capture agy and codex if I use them occationaly?", then "go ahead to write a plan after v1.43.14 merged". The same conversation approved folding in the correction-cause P3 ("small P3 is fine"). Spec only. Registering the hook in the operator's live Claude Code settings and `make platform-ops` are live steps and need a separate operator go.
**Release:** v1.45.0 (branch `k3d-manager-v1.45.0`), plan 4
**Depends on:** none in code. Lands after `docs/bugs/2026-11-01-dispatch-resume-reason-unrecorded-runs-never-rework-or-progress.md` (verified offline; its live E3 is still pending), which made every `resume` carry a reason; this plan adds a turn origin and a correction cause beside that reason.

## Problem

The Agent Dispatch dashboard panel **Human continuation prompts** (`scripts/etc/argocd/platform-ops/grafana-dashboard-agent-dispatch.yaml`, described in `docs/guides/grafana-dashboards/k3dm-agent-cost.md:67` and `docs/howto/codex-dispatch.md:162`) counts `intervention` events in the dispatch ledger (`bin/k3dm-dispatch-metrics`, ~lines 1530-1541). Those events are written by `bin/k3dm-codex-dispatch resume --reason …` and `intervention --reason …`, and the coordinator (Claude) runs those commands. The panel therefore measures **coordinator → sub-agent turns**, not human effort. Some of them follow an operator instruction ("resume Luna"), most do not, and the ledger cannot tell which.

Ledger on the M4, 2026-11-07: 41 `correction`, 10 `clarification`, 3 `continue_prompt` interventions since tracking began 2026-10-31, against 102 tracked tasks. The 41 corrections fall on 22 tasks (15 with exactly one; one task, `2026-11-02-acg-up-stalls-at-system-keychain-trust`, has 12). Nothing records why a correction happened, so a spec gap written by the coordinator and an agent's mistake land in the same bar.

Real operator turns are recorded today, but in three places no metric reads:

| Tool | Where human turns are | How a human turn is told apart (measured 2026-11-07) |
|---|---|---|
| Claude Code | session transcripts `~/.claude/projects/<repo>/*.jsonl` | typed prompts are `type=user` entries with string or image+text content; background-task notifications are also `type=user` but carry `<task-notification>`; tool results and meta entries are separate types. One session: ~98 typed prompts, 75 notifications, 1,508 tool results. Transcripts are kept ~30 days. |
| Codex | `~/.codex/history.jsonl` (`ts` epoch seconds, `session_id`, `text`) | only interactive sessions write it: of ~400 recent sessions, the 4 in history are all `originator=codex-tui`; none of the 232 `codex_exec/exec` (dispatched) or ~160 Codex sub-agent sessions appear. |
| agy | one SQLite file per conversation, `~/.gemini/antigravity-cli/conversations/*.db`, table `steps` | `steps.step_type` is an undocumented integer (one sample: 4, 14, 15, 23, 101, 132). Which value is a user message must be calibrated. Dispatched agy conversations are known to the dispatcher. |

## Design

### A. Claude Code operator turns (hook)

1. New `bin/k3dm-operator-turn-hook` (`set -euo pipefail`). Registered in the repo's `.claude/settings.json` for `UserPromptSubmit` and `Stop`. It reads the hook JSON on stdin and uses only `session_id`, `cwd` and `hook_event_name`, plus one boolean derived from the prompt: `kind=slash` when it starts with `/`, else `kind=prompt`. It never writes, logs or passes the prompt anywhere.
2. On `UserPromptSubmit` it appends one line to `${K3DM_OPERATOR_TURNS_LEDGER:-$HOME/.local/share/k3d-manager/operator-turns.jsonl}`: `{"ts":<epoch>,"tool":"claude","session":"<id>","branch":"<git branch of cwd or null>","kind":"prompt|slash"}`, and writes the per-session marker `…/operator-turns.d/<session>.open` containing the same `ts`.
3. On `Stop` it removes that session's `.open` marker.
4. It always exits 0 within 1 s and prints nothing to stdout, so a fault can never block or alter a prompt. A write failure goes to stderr only.

### B. Turn origin on coordinator → agent events

`bin/k3dm-codex-dispatch resume` and `intervention` add `turn_origin` to the ledger event, read from the markers, never from an argument:

- exactly one `.open` marker younger than `K3DM_TURN_MARKER_MAX_AGE` (default 6 h) → `operator_turn` (the coordinator acted inside a turn the operator started);
- no live marker → `autonomous_turn` (for example a turn woken by a background-task notification);
- more than one live marker (two Claude sessions) or an unreadable marker directory → `unknown`.

`operator_turn` means "inside a human-started turn", not "the operator asked for this resume". The docs must say so.

### C. Codex operator turns (reader)

`bin/k3dm-dispatch-metrics` reads `${K3DM_CODEX_HISTORY:-$HOME/.codex/history.jsonl}` and counts rows by window, using only `ts` and `session_id`. It never reads `text` into a variable that reaches output. Missing file → the Codex source reports `absent`, not zero.

### D. agy operator turns (reader, separable)

`bin/k3dm-dispatch-metrics` counts user-message steps in `${K3DM_AGY_CONVERSATIONS:-$HOME/.gemini/antigravity-cli/conversations}/*.db`, opened read-only (`?mode=ro`, or a copy in a temp directory), excluding conversation ids the dispatcher recorded for its own agy runs. The user-message `step_type` value comes from a calibration constant set from a conversation with a known number of operator prompts (calibration is part of E3). If a database lacks the `steps` table, or the calibrated value is absent from every conversation that has steps, the agy source reports `unknown_schema`. It never reports zero for an unreadable store. This phase may slip to a later release without blocking A-C or E-F.

### E. Correction cause

`resume --reason correction` and `intervention --reason correction` require `--cause spec_gap|agent_error|test_refusal|scope|other`; other reasons refuse `--cause`. The ledger event carries `cause`. Old correction events export as `cause="unrecorded"`.

### F. Metrics and dashboard

New series (same `window` labels as today):

- `k3dm_operator_turns{window,tool="claude|codex|agy"}`
- `k3dm_operator_turn_source_status{tool,status="ok|absent|unknown_schema"}` (1 for the current status)
- `k3dm_dispatch_coordinator_prompts{window,reason,turn_origin}` (old events: `turn_origin="unrecorded"`)
- `k3dm_dispatch_corrections{window,cause}`
- `k3dm_operator_turns_per_landed_task{window}` (all tools / landed tasks; absent when no task landed)

Dashboard:

- The rename of **Human continuation prompts** to **Coordinator → agent prompts** lands earlier as a P3
  (`docs/bugs/2026-11-10-human-continuation-prompts-panel-counts-coordinator-resumes.md`, Claude 2026-11-10 at the
  operator's "schedule the label fix"). This plan only splits that panel's bars by `turn_origin`.
- Add **Human operator turns**: bars by tool, plus the per-landed-task stat.
- Add **Correction causes**.
- A tool whose source status is not `ok` shows that status, not 0.
- Update the panel descriptions and both docs above to the new meanings.

`k3dm_dispatch_human_continuation_prompts` keeps being exported for one release with its description marked deprecated, then is removed in the next.

## What NOT to Do

- No prompt text, image, file path from a prompt, or Codex `text` / agy step body in any ledger line, metric label, log or argv. Length is not recorded either.
- Do not read, copy or modify the operator's real `~/.claude`, `~/.codex` or `~/.gemini`, the real dispatch ledger, or the Pushgateway. Tests use a scratch `HOME`, fixture files and `127.0.0.1:9`. A fixture first asserts it points at the scratch `HOME`.
- Stubs imitate captured shapes only:
  - Codex rows: `{"ts":1793750880,"session_id":"01a199cf-…","text":"…"}` (M4, 2026-11-07).
  - agy `steps` schema: from `sqlite3 .schema` on an M4 conversation copy, 2026-11-07.
  - Claude hook stdin: from the Claude Code hooks documentation for `UserPromptSubmit`/`Stop`, cited in a comment with the date.
- Do not infer turns from Claude transcripts in the exporter. A one-off backfill is out of scope.
- Do not change the meaning of `reason` values, the `resume` contract other than `--cause`, or any other dashboard panel.
- Write the must_not tests first and show them red on the pre-fix tree.
- Do not edit CLAUDE.md, `memory-bank/` or `docs/roadmap.md`. Do not commit to `main`, create a PR or skip hooks.
