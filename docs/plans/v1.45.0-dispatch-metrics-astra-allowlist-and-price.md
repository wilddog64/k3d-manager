## Problem

The operator is trialling Astra (OpenAI via codex) for spec and bug review against Argon and Fable. The first Astra run
(`lf-v057-review-astra`, 2026-11-18, `model: gpt-6.2-astra`) shows on the Agent Dispatch dashboard as model `other`,
because `MODEL_IDENTITY_ALLOWLIST` (`bin/k3dm-dispatch-metrics:41-47`) has `gpt-6-astra` but not `gpt-6.2-astra`
(`:1865-1866` map any valid name not on the list to `other`; only a missing or malformed name becomes `unknown`). `gpt-6.2-sol`, also in codex's model list, is missing too. No Astra model has
a rate in `scripts/etc/agent/codex-model-prices.json`, so `_cost` (`:718`) returns `None` and the run is counted unpriced.

## Proof of external behaviour

- Model IDs: `~/.codex/models_cache.json` on the M4, 2026-11-18, lists `gpt-6.2-sol`, `gpt-6.2-astra`, `gpt-6-astra`.
- Ledger row (2026-11-18): `"agent":"codex","model":"gpt-6.2-astra","model_source":"explicit"`; usage
  `input 253880, cached_input 226816, output 1291`.
- Rates (web search, 2026-11-18): `gpt-6-astra` $10.00 input / $1.00 cached / $50.00 output per 1M (standard,
  ≤272K input) per eesel.ai, codersera.com, anotherwrapper.com; not confirmed on openai.com. No rate published for
  `gpt-6.2-astra`.

## Spec correction (2026-11-18)

Luna's first run stopped (rightly): the spec said an unlisted model exports as `unknown`; the code exports `other`
(`bin/k3dm-dispatch-metrics:1865-1866`). Corrected the positive control, M3, N1 and E2. Intent unchanged.
