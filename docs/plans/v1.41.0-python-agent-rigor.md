# v1.41.0 — Agent rigor for Python

**Branch:** `k3d-manager-v1.41.0`
**Requested by:** CK, 2026-09-30 ("we have more and more development on python so I wonder if our
agent_rigor protocol can cover those")
**Related:** `scripts/lib/foundation/scripts/lib/agent_rigor.sh` (upstream `lib-foundation`),
`scripts/lib/agent_rigor.sh` (k3d-manager's local copy, which the pre-commit hook actually runs),
the 2026-09-29/30 verifications recorded in `docs/bugs/2026-09-30-*.md`.

## Problem

`agent_rigor` checks shell, BATS and YAML only. Python has no commit-time check, and CI runs
nothing on Python except pytest. The Python code base is now large and growing:

- **74 Python files**, about 11,700 lines: every Hermes module, the webhook, and the vector store.
  **9 of them have no `.py` extension** (`bin/k3dm-hermes`, `bin/k3dm-webhook`,
  `bin/k3dm-vectordb-*`, `bin/k3dm-cloud-*`, `bin/k3dm-test-metrics`, the two auth proxies). A
  `*.py` glob misses them; Python must be recognised by its shebang.
- **417 test functions** in `scripts/tests/**/*.py`, with no guard against deleting or weakening them.
  The BATS suites have one.

What `_agent_audit` checks today:

| Check | Scope |
|---|---|
| Assertions or `@test` blocks removed | `*.bats` |
| `if` count per function (max 8) | `*.sh` |
| Bare `sudo` | `*.sh` |
| Tab indentation | `*.sh` |
| `kubectl exec … env X=…` | any staged diff |
| Hardcoded IPv4 | `*.yaml`/`*.yml` |
| AI lint (opt-in) | `*.sh` (k3d-manager's copy); `*.sh`/`*.js`/`*.md` upstream |

**Measured on 2026-09-30:**
- `ruff check --select F` over the 74 files finds 47 issues: 27 unused imports, 1 f-string without
  placeholders, and 19 undefined names, all in `scripts/lib/webhook/lifecycle.py`. The undefined names
  are false positives: `configure_runtime()` injects them through `globals().update(...)`.
- Python contains **no** `shell=True`, `eval(`, `exec(` or `"sudo"` today, so those checks start at
  zero noise.
- The copies have drifted. The hook sources `scripts/lib/agent_rigor.sh`, which differs from the
  subtree copy in two ways: it excludes `scripts/lib/acg/*` BATS files, and it narrows AI lint to
  `*.sh`. A `git subtree pull` therefore does **not** update what the hook runs.

**The week's Python defects, and what would have caught them:**

| Defect | Caught by |
|---|---|
| A test read the real Keychain and would fail on the M4 (`a92f1f1d`) | M2 hermetic-test guard |
| A test weakened or deleted in a hand-off | M1 test-shrink guard |
| A typo'd name in a rarely run path | M3 pyflakes in CI |
| A PrometheusRule broken by a re-indent (`29b7f55c`) | M4 `make validate-manifests` in CI |
| `git cat-file` deadlock; "paused" substring match; vacuous pager test | Nothing mechanical. These stay in the brief rules: realistic sizes, mutations, review |

## Approach

Four milestones, each shippable alone. M1 lands in `lib-foundation` first, so rigor-cli and
shopping-carts get it too. M2–M4 are k3d-manager only.

### M1 — `_agent_audit` learns Python (lib-foundation)

All checks read **staged** content (`git show :<path>`), like the existing ones. "Staged Python" means
staged `*.py` files **plus** staged files whose first line matches `^#!.*python`.

1. **Test-shrink guard.** Over staged Python files matching `AGENT_AUDIT_PY_TEST_GLOB` (default
   `*/tests/*`, `test_*.py`, `*_test.py`): fail if the staged diff removes more `def test_` lines than
   it adds, or removes any line whose first token is `assert` or `self.assert`. This is a direct port
   of the BATS rule, message included.
2. **Syntax.** `python3 -m py_compile` on each staged Python file, compiling the staged blob from a
   temporary file (not the working tree). If `python3` is missing, warn and skip, never fail.
3. **Dangerous calls,** on added lines of staged Python outside test files:
   - `shell=True`;
   - `\beval\(` or `\bexec\(`;
   - a `"sudo"`/`'sudo'` string literal (the shell rule's Python twin: privilege goes through the
     documented wrappers);
   - `"--password"`, `"--token"` or `"--username"` string literals, which mirror
     `_args_have_sensitive_flag`.

   Each is suppressible per line with `# agent-audit: allow <rule>`, written with a reason, the way
   shellcheck disables are.
4. **Reconcile the copies.** Upstream takes k3d-manager's two local deltas as options:
   `AGENT_AUDIT_BATS_EXCLUDE` (a glob list; k3d-manager sets `scripts/lib/acg/*`) and
   `AGENT_LINT_GLOBS` (default `*.sh *.js *.md`; k3d-manager sets `*.sh`). After the subtree pull,
   k3d-manager's hook sources `scripts/lib/foundation/scripts/lib/agent_rigor.sh`, and
   `scripts/lib/agent_rigor.sh` is deleted. One copy, no silent drift.

Tests (`scripts/tests/lib/agent_rigor.bats` upstream), each in a temporary git repository:
- test shrink: `def test_` removed / `assert` removed → fail; test added → pass;
- an extensionless `#!/usr/bin/env python3` file with a syntax error → fail; the same file with a
  `.txt` name and no shebang → ignored;
- each dangerous pattern → fail; the same line with `# agent-audit: allow …` → pass; a test file →
  pass;
- `python3` absent from `PATH` → warn, exit 0;
- `AGENT_AUDIT_BATS_EXCLUDE` skips a matching BATS file.

Mutations: drop the shebang detection → the extensionless test goes red; compile the working-tree
file instead of the staged blob → a test with a clean working tree and a broken staged blob goes red.

### M2 — hermetic Python tests (k3d-manager)

`scripts/tests/conftest.py` (new) adds an autouse fixture. For the duration of each test, it wraps
`subprocess.Popen` (which `run`, `check_output` and `call` all use) and `socket.socket.connect`:

- **Blocked executables:** `security`, `kubectl`, `argocd`, `gh`, `helm`, `docker`, `launchctl`,
  `curl`, `ssh`. They are blocked only when the executable resolves (`shutil.which` with the call's
  `env["PATH"]`) **outside** the test's `tmp_path` and pytest's base temp. So stubs written into a
  temp dir still run.
- **Blocked git subcommands:** `fetch`, `pull`, `push`, `clone` and `ls-remote`, when a remote is not a
  local path. Git on temporary repositories stays allowed.
- **Blocked connections:** any non-loopback address.
- **The failure message** names the test, the command and the rule: `hermetic: test called real
  'security' — stub _keychain_secret or run it via a temp-dir stub`.
- **Opt-out:** `@pytest.mark.external("reason")`, used sparingly and listed in the guide.

**Roll-out:** the first run uses `K3DM_HERMETIC=report` and lists offenders without failing. Fix them
in the same milestone, then default to enforce. The spec does not guess how many exist; the report
run counts them.

Tests (`scripts/tests/bin/test_hermetic_guard.py`): a real `security` call fails with the message; a
temp-dir stub named `kubectl` runs; `git init` and `git commit` in `tmp_path` run; `git fetch` from
`https://…` fails; a `socket.connect(("192.0.2.1", 80))` fails while `127.0.0.1` passes; the marker
allows a call. Mutation: resolve against the default `PATH` instead of the call's `env` → the stub
test goes red.

### M3 — pyflakes in CI (k3d-manager)

- `ruff` pinned (`ruff==0.15.8`, the version measured here) in the CI install step.
- **`make lint-python`:** `ruff check --select F` over the 74 files, with the shebang-detected ones
  passed explicitly because ruff's discovery also skips extensionless files. Per-file ignore
  `F821` for `scripts/lib/webhook/lifecycle.py` only, with a comment pointing at `configure_runtime`.
  Replacing that injection with explicit parameters is a separate refactor, not this spec.
- One-time `ruff check --select F --fix` for the 28 auto-fixable findings, in its own commit.
- A CI step that runs `make lint-python` after pytest.
- **Style rules stay out on purpose.** Only `F` (pyflakes): correctness, no formatting churn.

Tests: `make lint-python` exits 0 on the branch; a planted `undefined_name()` in a scratch copy
of a Hermes module exits non-zero; an extensionless file with an unused import is reported (proving
the shebang list is passed).

### M4 — manifest validation in CI (k3d-manager)

`make validate-manifests` (added 2026-09-30, `b46c08db`) installs kubeconform when it is missing and
validates custom resources against the Datree CRD catalog pinned to a commit. Today: 72/72 valid, and
it rejects the rule file from `29b7f55c`. Add it as a CI step after the shellcheck step; the runner has
network. No new code.

## Out of scope

- Type checking (mypy/pyright): a later decision, and the noise has not been measured.
- Formatting (black, `ruff format`).
- Refactoring the `lifecycle.py` globals injection.
- AI lint for Python (`_agent_lint`): it follows once `AGENT_LINT_GLOBS` exists, by config only.

## Hand-off

- **Codex brief A (lib-foundation, M1):** the files are `scripts/lib/agent_rigor.sh`,
  `scripts/tests/lib/agent_rigor.bats`, README and CHANGE.md, tagged as a new minor release. Gates: the
  clean-env BATS command from lib-foundation's CLAUDE.md, and shellcheck. Bash 3.2 rules apply (no
  `declare -A`, no `mapfile`).
- **Codex brief B (k3d-manager, M1 adoption + M2–M4):** a subtree pull with `K3DM_SUBTREE_SYNC=1`,
  hook re-pointed, local copy deleted, then M2, M3, M4 as separate commits. Gates: `make test-pytest`,
  `make lint-python`, `make validate-manifests`, BATS, shellcheck, and `git diff --stat` per commit.
- Both briefs carry the standing rules: realistic input sizes, no host Keychain or network in tests,
  a test for every early return, mutations pasted red then green, and no re-indenting of YAML you
  were not asked to touch.

## Done when

- A commit that deletes a Python test, adds `shell=True`, or breaks the syntax of `bin/k3dm-hermes` is
  refused by the pre-commit hook.
- `make test-pytest` fails a test that calls the real `security`, `kubectl` or network, with a message
  that says how to fix it.
- CI fails on a pyflakes error or an invalid manifest.
- k3d-manager's hook runs the subtree copy of `agent_rigor.sh`; there is no second copy.
