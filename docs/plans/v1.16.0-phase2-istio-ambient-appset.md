## Why this differs from the parent plan's Phase 2

Two hard facts, verified against the live hub ArgoCD (`k3d-k3d-cluster`) and the repo on
2026-07-17, changed the shape:

1. **The `platform` AppProject `destinations` are a whitelist, and `istio-system` is allowed only
   on the hub (`server: https://kubernetes.default.svc`), NOT on the named app clusters
   (`ubuntu-k3s`, `ubuntu-hostinger`, …).** Applying the ApplicationSet with
   `destination.name: ubuntu-k3s, namespace: istio-system` would be **refused** by ArgoCD
   ("destination namespace istio-system is not permitted in project platform"). → **Change 2.1**
   adds `istio-system` for the four named clusters. (`sourceRepos: ["*"]` already permits the Istio
   helm repo, and the `clusterResourceWhitelist` already permits CRDs, Mutating/Validating
   WebhookConfiguration, ClusterRole/Binding, and Namespace — so no other AppProject change.)

2. **ArgoCD ApplicationSet structured `goTemplate` renders string leaves only — it cannot emit a
   variable-length `helm.parameters` list per element**, and the per-component Istio params differ
   (base: 1, istiod: 1, cni: 3, ztunnel: 0). The robust expression is a per-element `values:`
   block-scalar injected through the single string leaf `helm.values: '{{ .values }}'` (the
   documented ApplicationSet pattern). → **Change 2.2** uses that, not a `parameters:` range.

Also: every public `deploy_*` function has an explicit wrapper in the dispatcher `scripts/k3d-manager`
for `--help`/usage discoverability. → **Change 2.4** adds it. (Invocation itself also works via the
`_try_load_plugin` fallback, but the wrapper keeps the idiom and help listing consistent.)

## Change 2.2 — NEW `scripts/etc/argocd/applicationsets/istio-ambient.yaml`

Ambient install order: istio-base → istiod → istio-cni → ztunnel. `sync-wave` annotations are
documentary (ApplicationSet does not guarantee cross-Application ordering); ArgoCD `retry` +
`selfHeal` is the real convergence mechanism — istio-cni/ztunnel fail until istiod's webhook is up,
then retry succeeds. The **k3s CNI path override** on istio-cni is the crux: without it istio-cni
writes to the wrong dirs and ambient capture silently never happens.

**Exact new file contents:**

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: istio-ambient
  namespace: ${ARGOCD_NAMESPACE}
  labels:
    managed-by: k3d-manager
    app-type: mesh
spec:
  goTemplate: true
  generators:
    - list:
        elements:
          - name: istio-base
            chart: base
            wave: "0"
            values: |
              defaultRevision: default
          - name: istiod
            chart: istiod
            wave: "1"
            values: |
              profile: ambient
          - name: istio-cni
            chart: cni
            wave: "2"
            values: |
              profile: ambient
              cni:
                cniConfDir: /var/lib/rancher/k3s/agent/etc/cni/net.d
                cniBinDir: /var/lib/rancher/k3s/data/current/bin
          - name: ztunnel
            chart: ztunnel
            wave: "3"
            values: ""
  template:
    metadata:
      name: '{{ .name }}-${APP_CLUSTER_NAME}'
      namespace: ${ARGOCD_NAMESPACE}
      annotations:
        argocd.argoproj.io/sync-wave: '{{ .wave }}'
      labels:
        managed-by: k3d-manager
        app-type: mesh
    spec:
      project: platform
      destination:
        name: ${APP_CLUSTER_NAME}
        namespace: istio-system
      source:
        repoURL: https://istio-release.storage.googleapis.com/charts
        chart: '{{ .chart }}'
        targetRevision: ${AMBIENT_ISTIO_VERSION}
        helm:
          releaseName: '{{ .name }}'
          values: '{{ .values }}'
      syncPolicy:
        automated:
          prune: true
          selfHeal: true
        retry:
          limit: 10
          backoff:
            duration: 15s
            maxDuration: 3m
        syncOptions:
          - CreateNamespace=true
          - ServerSideApply=true
```

> Application names are cluster-suffixed (`{{ .name }}-${APP_CLUSTER_NAME}` →
> `istio-base-ubuntu-k3s`) so the same ApplicationSet can target the sandbox and Hostinger without
> name collisions in the hub `cicd` namespace. Do NOT drop the suffix. Do NOT quote the `values:`
> block scalars differently — `profile: ambient` etc. are plain YAML and must not gain a leading
> `$` (envsubst leaves them untouched).

## Change 2.3 — NEW `scripts/plugins/istio_ambient.sh`: `deploy_istio_ambient`

Mirrors `deploy_observability_acg`. Applies the ApplicationSet to the **hub** ArgoCD explicitly via
`--context "${ARGOCD_CONTEXT}"` (default `k3d-k3d-cluster`) — this avoids the current-context-drift
footgun (a mis-targeted apply is a silent no-op).

**Exact new file contents:**

```bash
#!/usr/bin/env bash
# scripts/plugins/istio_ambient.sh — install Istio ambient mesh on an app cluster via ArgoCD

function deploy_istio_ambient() {
  if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
    cat <<'HELP'
Usage: [APP_CLUSTER_NAME=<ctx>] [ARGOCD_CONTEXT=<hub-ctx>] ./scripts/k3d-manager deploy_istio_ambient

Applies the istio-ambient ApplicationSet to the hub ArgoCD (ARGOCD_CONTEXT, default
k3d-k3d-cluster), targeting APP_CLUSTER_NAME (default ubuntu-k3s). Preconditions:
  - The target cluster is registered with the hub ArgoCD (register_app_cluster).
  - The target cluster's CNI is Cilium with cni.exclusive=false (deploy with K3S_AMBIENT_MESH=true).
  - The platform AppProject permits istio-system as a destination for the target cluster.
HELP
    return 0
  fi

  local _appset="${SCRIPT_DIR}/etc/argocd/applicationsets/istio-ambient.yaml"
  : "${ARGOCD_NAMESPACE:=cicd}"
  : "${ARGOCD_CONTEXT:=k3d-k3d-cluster}"
  : "${APP_CLUSTER_NAME:=${ARGOCD_APP_CLUSTER_NAME:-ubuntu-k3s}}"
  : "${AMBIENT_ISTIO_VERSION:=1.24.2}"
  export ARGOCD_NAMESPACE APP_CLUSTER_NAME AMBIENT_ISTIO_VERSION

  if [[ ! -f "${_appset}" ]]; then
    _err "[istio_ambient] ApplicationSet not found: ${_appset}"
    return 1
  fi

  _info "[istio_ambient] Applying istio-ambient ApplicationSet (hub: ${ARGOCD_CONTEXT}, target: ${APP_CLUSTER_NAME})..."
  # shellcheck disable=SC2016
  if envsubst '$ARGOCD_NAMESPACE $APP_CLUSTER_NAME $AMBIENT_ISTIO_VERSION' < "${_appset}" \
      | _kubectl apply --context "${ARGOCD_CONTEXT}" -f -; then
    _info "[istio_ambient] Applied — ArgoCD will sync istio-system on ${APP_CLUSTER_NAME}"
  else
    _err "[istio_ambient] Failed to apply istio-ambient ApplicationSet"
    return 1
  fi
}
```

## Rules

- `set -euo pipefail` semantics preserved; double-quote every expansion.
- Pin chart version explicitly via `${AMBIENT_ISTIO_VERSION}` (no floating `latest`) — supply-chain rule.
- New service in its own namespace (`istio-system`) — never `default`.
- Route the apply through `_kubectl` — do NOT call `kubectl`/`sudo` directly.
- Minimal patch — do NOT touch the local-dev `_istioctl` path, `istio-operator.yaml.tmpl`, Phase 1
  code, or any Phase 3 (Hostinger) file.
- Keep the envsubst variable whitelist exactly `$ARGOCD_NAMESPACE $APP_CLUSTER_NAME $AMBIENT_ISTIO_VERSION`
  so goTemplate `{{ }}` tokens survive substitution.
