## Problem

The Per spec table shows effort (Codex runs, tokens, Codex time, time to land, API equiv.) but
nothing about how big the work was. A spec that took three reworks could be large or could be
badly written; the table cannot tell. Nor can a release be compared with another by size.

The ledger has no size data. A `land` event carries only `verifier_lines` and `wait_seconds`:
no commit, no diff stats. A `start` event carries the spec path, but nothing about the spec.

## Design

Two measures, recorded when the facts are fixed, shown as separate columns. No combined score:
any weighting would be invented before there is data to justify it. Size buckets (S/M/L) can
come later, from real numbers.

### D1. Spec complexity — recorded at dispatch

`bin/k3dm-dispatch-metrics --spec-stats PATH` (new mode; stdlib Python, no export, no push)
prints one JSON object for a plan or bug doc:

- `files` — entries in the `## Files` section: bullet items, or table rows excluding the header
  and separator.
- `must`, `must_not`, `evidence`, `live_evidence` — item counts in the `## Acceptance` YAML block
  (`live_evidence` = evidence items with `kind: live`).

A missing section gives that key `null`, never `0`. An unreadable file or no Acceptance block
gives `null` for the affected keys; the mode still exits 0.

`bin/k3dm-codex-dispatch` calls it once when it writes the `start` event and stores the result
as `spec_stats`. If the call fails, the event is written without `spec_stats`. The dispatch
itself never fails because of it.

### D2. Change size — recorded at land

In `_dispatch_land`, after the rebase and tests pass and before the fast-forward, compute
`git -C "$task" diff --numstat "$rel" HEAD` and store on the `land` event:

- `commit` — `git -C "$task" rev-parse HEAD` (the landed tip).
- `change` — `{"files": N, "code": L, "tests": L, "docs": L}`, where L is added + deleted lines.
  - `tests`: paths under `scripts/tests/` or named `test_*.py` / `*.bats`.
  - `docs`: paths under `docs/` or `memory-bank/`, and `*.md`.
  - `code`: everything else.
  - Binary files (`-` in numstat) count in `files`, add 0 lines.

A failure to compute leaves `change` out; the land still proceeds. `verifier_lines` and
`wait_seconds` are unchanged.

### D3. Exporter series

For each window and release scope, per landed task (within the existing `TASK_CAP`):

- `k3dm_dispatch_task_spec_files{window,version,slug}`
- `k3dm_dispatch_task_spec_acceptance_items{window,version,slug}` = `must + must_not`
- `k3dm_dispatch_task_change_files{window,version,slug}`
- `k3dm_dispatch_task_change_lines{window,version,slug,kind}`, `kind` = `code|tests|docs`

A task with no `spec_stats` or no `change` emits no series for that measure. Per scope:

- `k3dm_dispatch_change_lines_total{window,kind}` and `k3dm_dispatch_change_files_total{window}`
- `k3dm_dispatch_change_lines_median{window}` (code + tests + docs per task)
- `k3dm_dispatch_spec_acceptance_items_total{window}`
- `k3dm_dispatch_complexity_measured_tasks{window,measure}`, `measure` = `spec|change` — how many
  landed tasks carry the data, so a total is read as "N of M specs measured".

Sums and medians run over every measured landed task in the scope, not just the 50 shown.

### D4. Dashboard

- Per spec table: columns **Spec files**, **Acceptance items**, **Files changed**,
  **Lines changed** (code + tests + docs), and **Test lines**. Blank when unmeasured. The footer
  sums them (add each to `footer.fields`, raw and display names, as the existing footer does).
- A stat row: **Lines changed** total, **Median lines / spec**, **Acceptance items** total, and
  **Measured** shown as `N / M` landed specs.
- Panel descriptions say: change size is measured at land from the rebased task diff; spec size at
  dispatch from the spec as it was then; specs landed before this shipped are blank.

### D5. No backfill

Specs landed before this ships stay blank. Release branches are squash-merged and task branches
are rebased and deleted, so a reconstructed diff would be unreliable.

## What NOT to Do

- Do NOT create a PR, commit to `main`, or skip hooks (`--no-verify`).
- Do NOT add a combined complexity score or size buckets.
- Do NOT backfill size data for specs already landed, or run `usage-backfill`.
- Do NOT change `verifier_lines`, `wait_seconds`, existing series or the 50-task cap.
- Do NOT read the real `~/.codex`, query the live Prometheus or Grafana, or push to the Pushgateway.
- Do NOT modify files outside the Files list.
