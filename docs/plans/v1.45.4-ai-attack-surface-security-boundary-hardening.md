**Filed:** 2026-11-03
**Release:** v1.45.4 (plan 4 of 5, subject to current release-slot reconciliation)
**Branch:** `k3d-manager-v1.43.14` (spec authored here; implement only on the appropriate future release branch)

**Component:** cloud-bridge, webhook/Slack ChatOps, Hermes, ask-docs/find-similar-docs, GitHub Actions, Mac hub and external monitoring
**Dependencies:** existing webhook/cloud-bridge scoped read-only roles, agent-rigor and approval controls; complements v1.48.1 semantic approval, v1.51.0 Falco, and v2.2 agent identity/provenance work

## Problem

AI-assisted adversaries can rapidly iterate against exposed interfaces, automate credential discovery, place malicious instructions in logs/Slack/Git/RAG material, and attempt to turn a lower-trust observation into a privileged tool action. Existing cloud-bridge limits, tests, CVE scans and agent instructions are useful but are not a complete authorization or containment boundary. This plan hardens currently exposed seams without waiting for the larger v2.2 multi-agent gateway.

## Scope and sequencing

1. **Inventory and threat model first (no mutation):** enumerate actual public Cloudflare routes, webhook and bridge ingress, authentication and replay checks, tool allowlists, fixed argument schemas, reader/writer roles, LaunchAgent credentials, GitHub Actions token scopes, Vault access, Mac-to-Hostinger paths, ACG temporary trust, and external watchdog dependencies. Mark verified vs assumed; do not claim compromise from 502/alert spikes.
2. **Deterministic per-tool authorization:** preserve existing read-only diagnostics; require verified caller identity, exact allowlisted verb and target, bounded argv and output, expiry/nonce/replay handling, fail-closed policy loading, and denial audit. Direct tool invocation must not bypass the check. Separate read-only, reversible maintenance, deployment and destructive actions. Do not grant arbitrary shell or wildcard `kubectl`/cloud access.
3. **Untrusted-input boundary:** treat external logs, GitHub issues and files, Slack text, Cloudflare responses, vector chunks, webhook results and agent summaries as data, never executable instructions or approval. Attach immutable source/revision, timestamp, trust category, evidence links and freshness to RAG and incident findings. Sanitization and model-side warnings are defense in depth; tools must refuse unauthorized actions regardless of prompt content.
4. **Privileged change protection:** deny autonomous changes to security policy, bridge/webhook allowlists, secrets, service accounts, admission policy, CI gates, signing configuration and DR destruction until the v1.48.1 SHA-bound operator approval gate is verifiably enforced. Validate the present protection before claiming that a GitHub check is required.
5. **Host and network containment audit:** map which workloads can reach Vault, Argo CD, bridge, hub and other namespaces. Propose staged default-deny Kubernetes ingress/egress policies with audited legitimate flows and safe rollback; never apply a policy that could sever control or emergency access based on AI recommendation alone. Coordinate Mac endpoint controls with the v1.45.3 workstation proposal.
6. **Independent failure detection:** verify off-host heartbeat/blackbox coverage and alert delivery using existing v1.46.0 Hostinger watchdog plan. An attacker or outage on the M5 must not silence all evidence; keep any off-host service read-only and independently credentialed. Validate backup immutability / independently protected copy with existing DR plans.
7. **No autonomous containment in this slice:** publish an evidence-backed containment runbook and approval matrix. Preauthorized reversible isolation is only a later separately reviewed design; no auto-quarantine, auto-delete, token rotation or unrestricted host shell.

## Deliverables

- Security trust-boundary inventory with verified endpoints, privileges, credential locations by *type only* (never values), and residual unknowns.
- Authorization matrix and fixed tool-schema / replay-negative-test specification for cloud-bridge and Slack/webhook paths.
- Adversarial regression fixtures covering prompt injection in logs, RAG chunks and Slack; forged tool results; replayed approvals; cross-agent permission escalation; stolen read-only token; failed policy store; CI self-modification; and fake-green test evidence.
- Proposed network-policy matrix and safe rollback prerequisites; evidence-only GitHub Actions privilege review.
- Read-only Security Effectiveness dashboard contract: denied action count, source freshness, test attack detection numerator/denominator, time-to-detect, alert transport and containment verification (if implemented later), with unknown states rather than fabricated zeros.
- Incident runbook describing isolate / preserve evidence / rotate compromised credentials / trusted rebuild / independent recovery verification, requiring appropriate human authorization.

## Verification / acceptance

- [ ] Every exposed interface and reachable credential-bearing trust boundary has an evidence-backed inventory, owner and unknowns.
- [ ] Crafted logs, docs, Slack messages and tool results cannot cause an unauthorized bridge/tool action in isolated negative fixtures; no model output itself satisfies identity or approval.
- [ ] A read-only identity cannot invoke a write/destructive tool even through direct adapter calls or replay; all denials are auditable without secrets.
- [ ] Security policy outage produces a visible refusal and does not silently grant access.
- [ ] Existing approved diagnostics still work and normal CI remains green.
- [ ] In disposable isolated tests, forged green evidence, stale/duplicate incidents and absent sensor/alert paths cannot be counted as verified success.
- [ ] Live behavior, external watchdog, rollback and real deployment coverage are explicitly **not verified** until separately approved E2 evidence exists.

## Boundaries / related plans

- **v1.45.0:** Autonomous Incident Investigation remains read-only evidence correlation; it does not become an attack-response executor.
- **v1.45.3:** Mac Santa/BlockBlock/LuLu/osquery workstation protections; do not duplicate installation here.
- **v1.46.0:** off-host watchdog and backup verification workstreams.
- **v1.48.1:** trusted semantic change and SHA-bound approval is the authority for high-risk changes.
- **v1.51.0:** Falco Linux runtime detection and alerting, not quarantine.
- **v2.2:** durable identity/capability enforcement and independent provenance throughout multi-agent gateways.
- **v2.6.4 candidate:** read-only AI interpretation of intrusion evidence; do not grant remediation from a model verdict.

## Not authorized

No new inbound exposure, agent privilege increase, deployment, security-tool installation, attack against third-party assets, destructive tests against persistent clusters, or bypass of the five-plan-per-release rule. Implementation is conditional on an exact file audit and subsequent operator approval.
