## Problem

Plan 4 prices Codex. Claude, the lead agent, writes the specs, reviews and verifies Codex's work, and
debugs live, but nothing records what that costs. The "Projected / month" panel therefore leaves out
the largest consumer.

Claude Code already records usage. Each project has a directory,
`~/.claude/projects/<cwd with "/" replaced by "-">/`, and it holds one `<session id>.jsonl` per
session. A line with `"type":"assistant"` carries:

- `message.id`;
- `message.model`;
- `timestamp` (ISO 8601);
- `message.usage`, holding `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`,
  `output_tokens`, and, when present, `cache_creation.ephemeral_5m_input_tokens` and
  `cache_creation.ephemeral_1h_input_tokens`.

Measured on this repo's session `72107bf3` (2026-10-17):

- 6,717 assistant messages, all `claude-opus-5-5`, plus one `<synthetic>`;
- 921M cache-read, 16.3M cache-write, 14K uncached input and 4.25M output tokens.

Cache reads dominate. The directory holds 10 transcripts, 388 MB. Claude Code deletes transcripts
after its retention period, so history must be rolled up before it disappears.

**Streaming duplicates.** One `message.id` can appear on several consecutive lines with the same
usage, one per content block. Count each `message.id` once. Counted per line, the measured session
overstates usage.

## Design

**Cost formula**, per message, in USD (rates per 1M tokens):

```
input × input + cache_5m × cache_write_5m + cache_1h × cache_write_1h + cache_read × cache_read + output × output
```

- `cache_5m` and `cache_1h` come from `usage.cache_creation`.
- When that object is absent, all of `cache_creation_input_tokens` counts as `cache_5m`.
- `model == "<synthetic>"` is not a model call. Skip it entirely.
- **Speed.** `usage.speed` is present on current transcripts. Fast mode bills at different rates.
  - A message whose `speed` is absent or `"standard"` is priced under its `model` key.
  - Any other speed is priced under `<model>@<speed>`, for example `claude-opus-5-5@fast`. If that
    key is missing, the message is unpriced. Never price it at standard rates.
  - Store `speed` in the rollup record.

**Scopes.**

| Scope | Claude usage counted |
|---|---|
| time (`1d`/`7d`/`30d`) | every message whose `timestamp` ≥ cutoff. **Exact.** |
| release `vX.Y.Z` | the sum of the per-task attributions below for that release's tasks. **Approximate.** |
| per task | messages inside the task's interval, from its first `start` `ts` to its latest `land` `ts`. Each message is split evenly among all tasks whose interval contains it. **Approximate.** |

A per-task figure misses the spec written before dispatch and the verification after landing. It also
includes unrelated work done while Codex ran. The dashboard must label it `≈`.

**Rollup cache.** The exporter must not re-read 388 MB on every run, and data must outlive
transcript deletion.

- Keep `~/.local/share/k3d-manager/claude-usage/rollup.json` (option `--claude-cache`).
- Per transcript, store the byte offset read so far.
- Store all `message.id`s seen, globally, because a resumed session can repeat earlier messages in a
  new file.
- Store per-message records `{ts, model, input, cache_5m, cache_1h, cache_read, output}` keyed by
  `message.id`.
- Each run reads only new bytes, appended since the stored offset. Transcripts are append-only. If a
  file shrinks below its stored offset, reread it from 0; ids already seen are skipped.
- Write the cache atomically (temp file plus rename).
- Records stay in the cache after their transcript is deleted.

**Coverage.** Emit the earliest record `ts` in the cache, so the dashboard can show where Claude data
begins, like the Codex ledger beginning at v1.43.0.

## Changes

### D1. `scripts/etc/agent/codex-model-prices.json`

Add a top-level `"claude_models"` object, keyed by model id:

```json
"claude_models": {
  "claude-opus-5-5": {"input": null, "cache_write_5m": null, "cache_write_1h": null, "cache_read": null, "output": null}
}
```

Ship it with `null` rates. **Do not invent rates.** A model whose rates include any `null` is
unpriced. Claude fills in the confirmed rates (DoD). Plan 4's `models`, `subscriptions_usd_per_month`,
`checked` and `source` keys are unchanged. Add `"claude_checked"` and `"claude_source"`, both
initially `null`.

### D2. `bin/k3dm-dispatch-metrics`

1. **Options.**
   - `--claude-projects PATH` defaults to `~/.claude/projects/<repo root with "/" → "-">`.
   - `--claude-cache PATH` defaults to the path above.
   - A missing projects directory emits nothing Claude-related and is not an error.
2. **`_claude_rollup(projects_dir, cache_path)`.**
   - Walk `projects_dir/**/*.jsonl`, recursively, so subagent transcripts are included.
   - Stream each file from its stored offset, line by line.
   - Parse only lines containing `"type":"assistant"`. Ignore any line that fails to parse.
   - Keep only `message.id`, `message.model`, `timestamp` and `message.usage`. Discard everything
     else immediately.
   - Return the records and save the cache as described in Design.
3. **Per scope**, in `_render_scope` after plan 4's lines:
   - `k3dm_dispatch_claude_api_cost_usd{window}`: priced cost in scope, `0` when none.
   - `k3dm_dispatch_claude_api_cost_per_landed_usd{window}`: the line above ÷ landed count. Omit it
     when landed is 0.
   - `k3dm_dispatch_claude_tokens{window,model,kind}`, with `kind` = `input`, `cache_write`,
     `cache_read` or `output`, for every model including unpriced ones.
   - `k3dm_dispatch_claude_unpriced_messages{window}`.
   - `k3dm_dispatch_claude_api_cost_observed_days{window}` (time scopes only): days from the later of
     the window cutoff and the earliest Claude record `ts` to now, the same rule plan 4's
     `k3dm_dispatch_api_cost_observed_days` uses for Codex. Omit it when there are no records in scope.
   - `k3dm_dispatch_task_claude_api_cost_usd{window,version,slug}`: priced, approximate, landed tasks
     only, inside the existing `TASK_CAP` loop.
4. **Global, unlabelled by window:** `k3dm_dispatch_claude_coverage_start_timestamp_seconds`, the
   earliest record `ts`. Omit it when there are no records.
4b. **Per day, global.** `k3dm_dispatch_claude_daily_tokens{date,model}`: the sum of all four token
   kinds per local calendar day (`YYYY-MM-DD`, from the record `ts` in the machine's local time
   zone) and model, for the 30 days ending today, today included. Skip days with no records and
   `<synthetic>` messages, and add no `window` label. This matches the "Tokens per Day" chart in
   Claude Code's `/stats` (added 2026-10-18 at operator request).
5. **Byte-identical guard.** In plan 4's golden, the lines may change only by these new lines appended
   at the end of each block. Every earlier line stays byte-identical and in the same order.

## Tests (`scripts/tests/bin/test_dispatch_metrics.py`)

Use temporary transcript directories, cache and prices file. Never read the real `~/.claude`. Use
only synthetic rates (for example, every rate 1.0 per 1M) and never the shipped file.

1. **Formula.** One message with input 10, cache_5m 100, cache_1h 200, cache_read 1000 and output 50,
   at distinct synthetic rates per kind. Assert the exact sum to within 1e-12.
2. **Dedup.** The same `message.id` appears on three lines of one file and once in a second file. It
   is counted once.
3. **Synthetic skipped.** A `<synthetic>` message adds nothing and is not counted as unpriced.
4a. **Speed.** A `speed: "fast"` message with no `<model>@fast` key is unpriced. With the key, it is
   priced at those rates.
4. **Null rate is unpriced.** With one `null` rate, there is no cost series for that model.
   `claude_unpriced_messages` counts its messages, and `claude_tokens` still lists it.
5. **Incremental.** Run the rollup, append two new messages, and run it again.
   - The second run reads only the new bytes (assert through a counter or a patched `open`/`seek`).
   - The totals equal those of a cold run.
   - A truncated file is reread without double counting.
6. **Survives deletion.** Run the rollup, delete the transcript, and run it again. The totals are
   unchanged.
7. **Attribution.** Task A runs from t0 to t10 and task B from t5 to t15. A message at t7 costs $2:
   each task gets $1. A message at t12 goes to B only. One at t20 goes to neither, but counts in a
   time window that contains it.
8. **Release scope.** A release's Claude cost equals the sum of its tasks' attributions.
9. **Privacy.** Transcripts contain user and assistant text holding `SECRET-PROMPT`. The string is
   absent from the rendered output **and** from the cache file.
10. **Dashboard.**
    - `Per spec` has a `Claude ≈` target on `k3dm_dispatch_task_claude_api_cost_usd`.
    - The new panels exist by title.
    - `Projected / month` sums both cost series on `window="7d"`, each divided by its own
      observed-days series.
12. **Claude observed days.** With Claude records starting 3 days ago, the `7d` scope emits
    `k3dm_dispatch_claude_api_cost_observed_days` ≈ 3; with records older than 7 days, ≈ 7.
    - No `gridPos` rectangles overlap.

11. **Per day.** Messages at 23:59 and 00:01 local time on consecutive days, under two models, and
    one 31 days old. Each lands in its own `date`, the old one is absent, and each value is the sum
    of all four kinds. Run with `TZ=America/Los_Angeles` and with `TZ=UTC`, and assert that the
    date boundary moves with the time zone. The dashboard has the panel by title, and its query
    names `k3dm_dispatch_claude_daily_tokens`.

**Mutations (report each as caught):**
- count per line instead of per `message.id` → test 2 fails;
- charge cache reads at the input rate → test 1 fails;
- give each overlapping task the full cost instead of a share → test 7 fails;
- persist the message text in the cache → test 9 fails;
- always reread from offset 0 → test 5 fails;
- bucket days in UTC instead of local time → test 11 fails.
