# v1.43.4 — Bug Tracking opens on the current release, sorted by priority, showing all fixes

**Status:** SPEC — ready for Codex
**Branch:** `k3d-manager-v1.43.4`
**Release:** v1.43.4 (plan 3 of 5)
**Filed:** 2026-10-16
**Approval:** explicit 2026-10-16 "go for that" (operator), for the three items in
`docs/bugs/2026-10-16-bug-dashboard-release-filter-defaults-to-all.md`
**Fixes:** `docs/bugs/2026-10-16-bug-dashboard-release-filter-defaults-to-all.md` (P3)
**Component:** `scripts/etc/argocd/platform-ops/grafana-dashboard-bugs.yaml`, `bin/k3dm-vectordb-metrics`

## Problem

1. The dashboard opens with **Release (filed in) = All**; the operator wants the release in progress.
2. Within a release the Bugs table orders by status before priority, so an open P3 sits above a
   fixed P1.
3. The dashboard opens with **Verified fixes = Hide live-verified**, which hid 7 of the 8 v1.43.3
   bugs and made the table look broken.

## Decisions

- **Item 1 — pin the saved Release to the branch's own version.** The bug doc proposed saving a
  `current` that matches no option, so Grafana falls back to the first one. That does not work on
  our Grafana (`grafana/grafana:11.4.0`): the Scenes loader builds the variable with
  `defaultToAll: Boolean(variable.includeAll)` (`public/app/features/dashboard-scene/utils/variables.ts`
  at `v11.4.0`), so an unmatched value falls back to **All**. The legacy loader picks option 0, which
  is also All. Dropping `includeAll` would lose All, because the Prometheus datasource regex-escapes
  multi-value selections, so a synthetic `.*` option cannot work either.
  The hub syncs this dashboard from the **release branch**, so the branch knows its own version. Save
  `current` = that version, and enforce it with a test that fails when the branch's version and the
  saved value differ. A new release branch then goes red in CI until the one value is bumped, which
  is part of cutting the branch. Repo = lib-foundation has no such release, so Grafana falls back to
  All there, which is the behaviour the bug doc asks for.
- **Item 2 — priority before status in `sort_key`.**
  `{release_order} {priority} {STATUS_RANK[status]} {filed} {stem}`. `P0` < `P1` < `P2` < `P3` <
  `unset` in byte order, so unset sorts last with no extra rank.
- **Item 3 — Verified fixes defaults to Show all.** Same query and option order; only `current`
  changes.

## Fix

### 1. `scripts/etc/argocd/platform-ops/grafana-dashboard-bugs.yaml`

In `templating.list`, variable `release`:

old:
```json
"current": {"selected": true, "text": ["All"], "value": ["$__all"]}
```
new:
```json
"current": {"selected": true, "text": ["v1.43.4"], "value": ["v1.43.4"]}
```
Keep the existing spacing and key layout of the file; only the values change. Everything else on
the variable (query, regex, `includeAll`, `allValue`, `multi`, `sort`, `refresh`) is unchanged.

Variable `verified`:

old:
```json
"current": {
  "selected": true,
  "text": "Hide live-verified",
  "value": "^(false|-)?$"
}
```
new:
```json
"current": {
  "selected": true,
  "text": "Show all",
  "value": ".*"
}
```
`query` stays `Hide live-verified : ^(false|-)?$,Show all : .*`.

### 2. `bin/k3dm-vectordb-metrics`, `_bug_status_metrics`

old:
```python
        sort_key = f"{_release_order(release)} {STATUS_RANK[status]} {priority} {filed or '9999-99-99'} {stem}"
```
new:
```python
        sort_key = f"{_release_order(release)} {priority} {STATUS_RANK[status]} {filed or '9999-99-99'} {stem}"
```

### 3. Docs

- `docs/guides/grafana-dashboards.md`, Bug Tracking section:
  - the paragraph that says "The **Hide live-verified** toggle is the default" now says the
    dashboard opens on **Show all**, and Hide live-verified is the other option;
  - add one paragraph: the dashboard opens on the release branch's own version (the saved Release
    value), a new release branch must bump it (the BATS test fails until it does), lib-foundation
    falls back to All, and rows sort by release, then priority (P0 first, unset last), then status.
- `CHANGELOG.md` `## [Unreleased]` `### Changed`: one entry covering the three defaults.
