**Branch:** `k3d-manager-v1.45.0`

**Depends on:** Part 2a (the engine and its `Refused`/`Unknown` classes). Dispatch order is 1, 2a, 2d, 2c, 2b. Part 2c imports this

## Problem

Under O2, evaluation and the push must run in the authority principal (Part 2c). This part is that code: a Python module that takes an
approval the engine has validated and evaluates the policy the shell promoter enforces today. It then moves `deploy/hub` and records the tag
in one atomic push. It ports the policy rather than redesigning it, with one stated addition: the `not_newest_green` rule (umbrella open
question Q5).

Round 2 found these problems in v1. Each is fixed below:

- **A witness did not permanently block its id.** If `A -> B` succeeded, finalization failed, and the remote returned to `A`, a second push
  was possible. A competing tag could also be credited as ours (agreed defect; Astra 5).
  - Now any tag that names the id blocks every further push for it (C.3).
  - Our own push is recognized by the exact remote tag object id (C.13).
  - A historical witness is matched on its tag target and every field.
  - Conflicting witnesses fail closed.
- **The move-time recheck was weaker than "newest green at the move"** (agreed defect; Astra 6). The recheck now repeats branch selection
  across every remote branch, the release tip, and the green status of every commit from the tip down to `sha` (C.10).
- **Expiry was checked before the slow path** (agreed defect; Astra 4).
  - The mover now calls the engine's `authorize_push` through an opaque callable as the very last step before `git push` (C.12).
  - The whole pre-push phase runs under one monotonic budget. The push and its observation are never aborted by it (A.5).
- **The containment port lacked the `refs/pull/<n>/head` fetch and pagination** (agreed defect; Fable 20). Both are added (C.8, A.3), and
  `CurlApi` now defines how it reads the status.
- **A bare mirror has no `origin`** (Astra 12). The mirror has no remote at all; every git command names `repo_url` (A.4). This was probed.
- **Two conventions conflicted:** helpers returned tuples while the glue re-raised exceptions (Fable 21). `move` and `witness` now raise,
  and helpers return tuples (B.5).
- **A zero-exit push with an unexpected observation was undefined** (Fable 22). It is now `unknown/push_unknown` and never consumed (C.13).
- **`witness` and the consumed routing were undefined** (Fable 13). See `Mover.witness` (C.14) and the glue (D.15).
- **N2 depended on Part 2c's loader** (Fable 24). The loader check moves to 2c; N2 here is a module property.

**O3:** the remote witness is only as strong as tag-creation protection.
- Before Part 2c's ruleset blocks creation of `hub-promote/*` tags, a same-user process can create a forged tag. That costs a denial of
  service or a false "already" record, never a move. This is residual R2d-1.
- Ruleset setup is a trusted operator step (Part 2c H).

## Behaviour

**A. Construction and isolation**

1. **Module.** The module is `scripts/lib/promote_mover.py`; Part 2c installs it as `/usr/local/libexec/k3dm-promote/promote_mover.py`.
   - Allowed imports: `json`, `os`, `re`, `subprocess`, `tempfile`, `time`, `typing`, `urllib.parse`, and the sibling `hub_approval`.
   - It reads no environment variable: `os.environ` and `os.getenv` are absent, and a test greps for them. It reads no file other than the
     paths it is given.
   - Python 3.9 syntax only. Tests run on Linux Python 3.12 in CI and on macOS `/usr/bin/python3` 3.9.6.
2. **Constructor:** `Mover(repo_url, repo_slug, api, ssh_command, workdir, clock, monotonic=time.monotonic)`.
   - **`repo_url`** is any URL `git` accepts. In production it is the `git@github.com:...git` from `promote.conf`; in tests it is the path
     of a local bare repository.
   - **`api`** is an object with `get(path, timeout) -> (status, body)` and `get_all(path, list_key, timeout) -> (status, items)`. Production
     passes `CurlApi(token_path)`; tests pass a scripted fake.
   - **`ssh_command`** becomes `GIT_SSH_COMMAND`. In production (Part 2c constants) it is: `/usr/bin/ssh -F /dev/null -i
     /var/db/k3dm-promote/deploy_key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o
     UserKnownHostsFile=/var/db/k3dm-promote/known_hosts -o BatchMode=yes`.
   - **`workdir`** holds the bare mirror.
   - **`clock`** has `now() -> int` (Part 2a `FileClock` in tests) and is used for the tag stamp. **`monotonic`** is used for the budget.
3. **`CurlApi(token_path)`**
   - **The call:** `/usr/bin/curl -q -sS --max-time <t> -w '\n%{http_code}' -K -`, run with `env={"PATH": "/usr/bin:/bin"}`.
     - `-q` comes first, so no curlrc is read. With no HOME, `~/.curlrc` is not found either way.
     - The config on stdin holds `url = "https://api.github.com<path>"`, the `Authorization: Bearer` header (read from the root-only token
       file at call time) and `Accept: application/vnd.github+json`.
     - No token appears in argv or the environment.
   - **The status** is the last line of stdout; the body is everything before it.
   - **`get_all`** loops pages with `per_page=100&page=N`. It stops when a page holds fewer than 100 items, or when the running count
     reaches `total_count` where the body has one (check-runs). More than 10 pages is `(0, [])`.
   - **Failures:** a curl failure, a timeout, a non-2xx status, an unparseable body, or a list key missing from an object body returns
     `(0, ...)` or the status. Callers map it to `unknown`.
4. **Git.**
   - Always `/usr/bin/git -c core.hooksPath=/dev/null`, with an environment built from scratch: `PATH=/usr/bin:/bin`, `HOME=<workdir>`,
     `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_SSH_COMMAND=<ssh_command>`.
   - The mirror is `git init --bare <workdir>/mirror.git`, created on first use. It never has a configured remote: every fetch, `ls-remote`
     and push names `repo_url` explicitly, and remote branches are fetched into `refs/remotes/origin/*`.
   - `Mover.prime()` does the first full fetch with a 600 s timeout. Part 2c calls it at enrol, outside any request budget.
5. **Budget** (agreed defect: the 120 s deadline mechanism).
   - `move` and `witness` take `deadline`, an absolute `monotonic()` value. Every git or API call before the push gets the timeout
     `min(own default, deadline - monotonic())`; the defaults are git 60 s and API 20 s.
   - If less than 1 s remains before a step, the call raises `Unknown("deadline")` without starting it.
   - The push (timeout 60 s) and the observation that follows it (timeout 30 s) are outside the budget. They always run to completion or to
     their own timeout, and they are never skipped once the push has started.

**B. Results**

6. **One convention** (Fable 21). Internal helpers return `("ok", data)`, `("refused", code, msg)` or `("unknown", code, msg)`. `Mover.move`
   and `Mover.witness` return a dict on ok and raise `hub_approval.Refused` or `hub_approval.Unknown` otherwise, with the codes of Part 2a
   B.5.
   - The `approval` field of a mover `Refused` is `kept`.
   - Mapping: an answer that means "the thing is absent or false" is `refused` only where Behaviour C says so. Everything else is
     `unknown`: every network error, timeout, 5xx, 403 or 429, malformed body, page cap, and git failure that is not a definite answer.

**C. `move(id, sha, branch, authorize, deadline)` and its order (the contract)**

`authorize` is a zero-argument callable; in production it is `lambda: engine.authorize_push(id, sha)`. It either returns or raises Part 2a's
`Refused` or `Unknown`, which the mover propagates untouched.

1. **Validate.** `id` against `^p[0-9]+-[0-9a-f]{8}$`, `sha` as 40 or 64 lowercase hex, `branch` against
   `^k3d-manager-v[0-9]+\.[0-9]+\.[0-9]+$`. Any failure is refused `bad_input`.
2. **Fetch.** `git fetch --prune <repo_url> '+refs/heads/*:refs/remotes/origin/*'
   '+refs/tags/hub-promote/*:refs/tags/hub-promote/*'`. A failure is `unknown/lookup_failed`.
3. **Witness** (agreed defect). Find every fetched `hub-promote/*` tag whose message has a line exactly `approval: <id>`.
   - **More than one:** refused `witness_conflict`.
   - **Exactly one** that is *authentic for (id, sha)*: return ok `{"outcome": "already", "old", "new", "tag"}`, whatever `deploy/hub`
     holds now (this means "historically moved"). Authentic means all of the following:
     - it is an annotated tag object whose `object` is `sha` and whose `type` is `commit`;
     - its tagger name is `k3dm-promote`;
     - its message has exactly one each of `action: promote`, `old: <40|64 hex>`, `new: <sha>`, `REF: <sha>` and `approval: <id>`.
   - **Exactly one that is not authentic:** refused `already_spent`. The id is blocked permanently.
   - **None:** continue.
4. **Old.** `git ls-remote <repo_url> refs/heads/deploy/hub`.
   - A failure is `unknown`.
   - An absent branch is refused `deploy_moved`, with the message "deploy/hub does not exist; the first promote is the manual bootstrap in
     docs/howto/hub-promote.md" (Part 2c H.17 routes bootstrap).
5. **Already current without a witness.** When old equals `sha`, the result is refused `deploy_moved` ("deploy/hub is at that commit but
   not by this approval").
6. **Newest release branch.**
   - List every `refs/remotes/origin/*` and keep only names matching the branch regex. This is done in Python, never with a git glob such as
     `k3d-manager-v*`, which also matches `k3d-manager-vX` and `k3d-manager-v1.45.0-evil`.
   - Sort by the integer tuple and take the last.
   - The result is refused `not_newest_branch` when `branch` is not that name, or when no name matches. Record the tip `T`.
7. **Containment** (ported from `bin/k3dm-hub-promote:39-50` `uncontained_commits` and `:22-37` `merged_pr_contains`).
   - The candidates are the `+` lines of `git cherry <sha> <old>`.
   - When there are any, `get_all("/repos/<slug>/commits/<old>/pulls", None)` returns the PR rows, and only rows with `merged_at` not null
     are kept. Accept on the first row that passes all of these, in order:
     1. `number` is digits, and `head.sha` and `merge_commit_sha` are 40 or 64 hex;
     2. `git ls-remote <repo_url> refs/pull/<number>/head` equals `head.sha`;
     3. the head object exists, or `git fetch --no-tags <repo_url> refs/pull/<number>/head` (agreed defect, as `:29`) makes it exist;
     4. the merge commit exists in the mirror;
     5. `old` is an ancestor of the head;
     6. the merge commit is an ancestor of `sha`.
   - A row that fails a check is skipped, as in the shell function.
   - **Results.** No accepted row with candidates present is refused `not_contained`, listing at most five short shas. A pulls lookup failure
     while evidence was needed is `unknown`. A failed `ls-remote` or fetch on a row skips that row, as in the original. When every row was
     skipped only because of such failures, the result is `unknown/lookup_failed`, never `not_contained`.
8. **Green walk.** `git rev-list --first-parent -n 20 refs/remotes/origin/<branch>`. For each commit in order, call
   `get_all("/repos/<slug>/commits/<c>/check-runs", "check_runs")` and classify as `bin/k3dm-hub-promote:93-101` (`classify_check_runs`)
   does:
   - no runs is none;
   - any run whose `status` is not `completed` is pending;
   - any `conclusion` outside `success`, `neutral` and `skipped` is failed;
   - otherwise the commit is green.

   A lookup failure is `unknown` at once. Pending, failed and none continue to the next commit. The first green is `g`.
   - None green within 20: refused `not_green`.
   - `sha != g`: refused `not_newest_green`, naming `g`. Record the walked prefix `P` (from `T` down to `sha` inclusive).
9. **Tag pre-flight.**
   - `tag = hub-promote/<UTC %Y%m%dT%H%M%SZ>` from `clock`.
   - A non-empty `git ls-remote --tags <repo_url> refs/tags/<tag>` is refused `tag_exists`; a failure is `unknown`.
   - Delete any local tag of that name, then create the annotated tag in the mirror at `sha`. Use `-c user.name=k3dm-promote -c
     user.email=k3dm-promote@localhost`, and the message lines `action: promote`, `old: <old>`, `new: <sha>`, `REF: <sha>`,
     `approval: <id>`, in that order.
   - Record the local tag object id `O` (`git rev-parse refs/tags/<tag>`).
10. **Move-time recheck** (agreed defect; Astra 6). This runs after step 9, as late as possible:
    1. Repeat step 2's fetch, then step 3's witness search: any tag naming the id now is refused per step 3.
    2. Repeat step 6 on the new fetch. Another newest branch is refused `release_moved`.
    3. The tip of `branch` must still be `T`; otherwise refused `release_moved`.
    4. Re-query the check-runs of every commit in `P`: every commit before `sha` must still be not green, and `sha` must still be green.
       Otherwise refused `release_moved`, which is `not_newest_green` at the move.
    5. `git ls-remote <repo_url> refs/heads/deploy/hub` must still equal old; otherwise refused `deploy_moved`.

    Any lookup failure is `unknown`. The remaining window, from this observation to the push, is the budget's last seconds plus
    `authorize`. A commit turning green inside that window is accepted; this is stated, not closed.
11. **Budget check.** If less than 1 s of `deadline` remains, the result is `Unknown("deadline")` and nothing is pushed.
12. **Authorize.** Call `authorize()`. A `Refused` (for example `expired`) or `Unknown` propagates, and nothing is pushed.
13. **Push and observe.**
    - **Push:** `git push --atomic --force-with-lease=refs/heads/deploy/hub:<old> <repo_url> <sha>:refs/heads/deploy/hub refs/tags/<tag>`.
    - **Observe:** `git ls-remote <repo_url> refs/heads/deploy/hub refs/tags/<tag>`. Let `ours` mean "the remote `refs/tags/<tag>` object
      id equals `O`".
    - **`ours`:** ok `{"outcome": "moved", "old", "new": sha, "tag"}`, whatever the push exit was and whatever the branch now holds. The tag
      and the branch were written atomically.
    - **Non-zero push, not `ours`, branch equal to old:** `unknown/push_unknown`. The move definitely did not happen, the lease binds old,
      and a retry is safe.
    - **Non-zero push, not `ours`, branch at another value:** refused `deploy_moved`. The atomic push applied nothing.
    - **Zero push, not `ours`, any branch value:** `unknown/push_unknown`, with the message "the push reported success but the remote does
      not show this approval's tag; rerun with the same approval" (Fable 22). Never consumed.
    - **Failed observation:** `unknown/push_unknown`.
14. **`witness(id, sha, deadline)`.** Steps C.1-C.3 only, used in recover mode. It returns the `already` dict, or `None` when no tag names
    the id. It raises `Refused` (`witness_conflict`, `already_spent`, `bad_input`) or `Unknown`, and it never pushes.

**D. The glue, tested here with the real Engine**

15. **`promote(engine, mover, id, sha, deadline)`,** in the same module; the daemon calls it.
    1. `r = engine.begin_promote(id, sha)` (Part 2a G.20). Its `Refused` and `Unknown` propagate.
    2. **`mode == "consumed"`:** return `{"outcome": "already", old, new, tag}` from the record. There is no remote call; this is the consumed
       routing.
    3. **`mode == "recover"`:** `w = mover.witness(id, sha, deadline)`.
       - A dict: `engine.commit_moved(id, w.old, w.new, w.tag)`, then return `w`.
       - `None`: `engine.finish_unmoved(id)`, then raise `Refused("expired", ..., "final")`.
    4. **`mode == "fresh"`:** `w = mover.move(id, sha, r.record.branch, lambda: engine.authorize_push(id, sha), deadline)`, then
       `engine.commit_moved(id, w.old, w.new, w.tag)`, then return `w`.
       - An `already` outcome on a record whose `push_at` is null is refused `not_approved` by `commit_moved` (Part 2a G.23). A witness
         without a recorded push is forged or foreign, and this refusal propagates.
    5. **Errors.**
       - A `Refused` raised by the mover with a mover code (Part 2a B.5) calls `engine.note_refusal(id, code)`, then re-raises. That
         includes `witness_conflict` and `already_spent` in recover mode, which are safe: the remote tag still blocks the id.
       - A `Refused` with an engine code (from `authorize` or `commit_moved`) re-raises untouched.
       - An `Unknown` re-raises untouched.
       - If `commit_moved` raises `Unknown` after a moved push, the result is `Unknown("push_unknown")`. The next call finds the witness at
         C.3, or in recover mode.
    6. The mover never imports or calls the engine except through `authorize`, and the engine never calls git.

## Residuals

- **R2d-1: forged witness before the ruleset.** Until Part 2c's ruleset blocks creation of `hub-promote/*` tags (a trusted O3 step), a
  same-user process holding the operator's push credential can create a tag naming a live id.
  - The result is `already_spent`, `witness_conflict` or `tag_exists`, which is a denial of service.
  - Or it is a false `already`, which D.15.4 refuses unless `push_at` is set.
  - It is never a move. It can also poison the shell rollback's tag stack (`bin/k3dm-hub-promote:224-230`); Part 2c routes rollback.
- **R2d-2: who supplies green.** "Policy-valid" means "newest green on the newest release branch". Whoever can push a release branch and get
  CI green can make a commit policy-valid (S4). Release-branch protection is umbrella open question Q6.
- **R2d-3: move-time window.** C.10's observation precedes the push by at most the remaining budget. A commit newer than `sha` that turns
  green inside it is not detected.
- **R2d-4: display versus authority.** `bin/k3dm-repo-sync:83-85` walks `--max-count=10` commits for its promotable display, while the
  authority walks 20 first-parent commits. The display is advisory; the authority decides.

## Proof of external behaviour

Captured locally on m4-air (macOS 26.5.2), `/usr/bin/git` 2.50.1 (Apple Git-155), curl 8.7.1, 2026-11-18:

1. **Stale lease.** Against a bare repository, `git push --atomic --force-with-lease=refs/heads/deploy/hub:<old> <url>
   <new>:refs/heads/deploy/hub refs/tags/<tag>` with a stale lease rejects both refs (`(stale info)`, `(atomic push failed)`) and leaves
   the remote unchanged. With the right lease, both refs move (v1 capture, kept).
2. **Remote-less mirror.** A `git init --bare` mirror with no configured remote (`git remote` prints nothing) fetches `+refs/heads/*` and
   `+refs/tags/hub-promote/*` by path.
3. **Tag object id.** `git ls-remote <url> 'refs/tags/hub-promote/*'` prints the annotated tag object id (`2f771d32...`), which equals the
   pusher's local `git rev-parse refs/tags/<tag>`, plus the peeled `^{}` line with the commit. `git cat-file tag` shows the `object`,
   `type commit` and `tagger k3dm-promote` lines. Probe directory: scratchpad `p1v3/gitprobe`.
4. **curl.** `man curl` (8.7.1): `-q` "If used as the first parameter on the command line, the curlrc config file is not read"; the
   `-w` variable `http_code` exists.
5. **Sorting.** Plain `sort` picks `v1.43.9` over `v1.43.15` (v1 capture).

Proof owed before dispatch (read-only captures or an operator probe; none asserted):

1. **GitHub atomic push.** `git push --atomic` with a lease and an annotated tag is accepted by GitHub, and a ruleset-rejected branch also
   rejects the tag. This is the probe on Part 2c's throwaway branch.
2. **A green check-runs capture from the hub** (`status` and `conclusion` per run, and `total_count`). Until it is taken, the fake API's
   green fixture is synthesized and says so in a comment.
3. **The `commits/<sha>/pulls` row shape** (`number`, `head.sha`, `merge_commit_sha`, `merged_at`), as the shell promoter's `--jq` at
   `bin/k3dm-hub-promote:24` expects.
4. **Deploy-key reads.** A deploy key can `ls-remote` and fetch `refs/pull/<n>/head`.
5. **Pagination.** GitHub's `per_page=100&page=N` on `pulls` and `check-runs` (an array, and an object with `total_count`).

## Worker definition of done

1. **Red first.** Every must and must_not has a test, and each must_not test includes its positive control.
2. **The pre-fix code is "module absent".** Each test is also shown red against a stub mover that pushes `sha` unconditionally with a tag
   and returns moved.
3. **Non-equivalent mutants,** each killed by a named test:
   - drop the `approval:` line;
   - match the witness on `new:` only (the return-to-A case);
   - accept two witnesses;
   - skip the tag pre-flight;
   - skip the recheck walk of commits before `sha`;
   - call `authorize` before the recheck;
   - consume on a zero push without the exact object;
   - take a plain-string branch sort;
   - drop `--atomic`;
   - drop the lease;
   - drop `-q` from curl.

   Reordering the tag message lines is equivalent for the readers and is not a mutant.
4. **Fixtures assert their target first:** a temporary bare repository path, a scripted fake API, a `FileClock` file and an injected
   monotonic. No network, no real HOME, no `/usr/local`.
5. **Walk fixture.** It has 21 first-parent commits. Commit 21 (the oldest) is the only green one in the not-found case, and the
   side-parent green is distinguishable from a first-parent walk.
6. **Synthesized fixtures** (green check-runs, pulls rows, pages) carry a comment saying so until proof owed 2, 3 and 5 are captured.
7. **Checks.** `make lint-python` and `make test-pytest` pass on Linux 3.12. The test file also passes under macOS `/usr/bin/python3` 3.9.6;
   name the interpreter in the hand-off.

## What NOT to do

- No daemon, socket, TOTP or approval logic here. The mover reaches the engine only through `authorize`.
- No environment reads, no test mode, no flag that skips checks.
- Do not edit `bin/k3dm-hub-promote`; the policy is ported, not moved.
