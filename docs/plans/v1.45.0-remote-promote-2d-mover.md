## Problem

Under O2, evaluation and the push must run in the authority principal (Part 2c). This part is that code: a Python module that takes an
approval the engine has validated and evaluates the policy the shell promoter enforces today. It then moves `deploy/hub` and records the tag
in one atomic push. It ports the policy rather than redesigning it, with one stated addition: the `not_newest_green` rule (umbrella
Decisions, Q5).

Round 3 found these problems in v3. Each is fixed below:

- **B1: the recheck pruned the mover's own tag** (Fable B1; Astra blocker 1; probed by both). v3 created `refs/tags/<tag>` in the mirror and
  then repeated `fetch --prune` into the same namespace, which deleted it; the push by ref name then failed. Even without `--prune`, the
  recheck's witness search would have found the mover's own tag.
  - Witness tags are now fetched into `refs/k3dm/witness/*` and branches into `refs/k3dm/remote/heads/*`, with `--no-tags` (C.2).
  - The tag object is built with `git mktag` from stdin, which writes an object and no ref. It is held at `refs/k3dm/pending/<stamp>`, a
    namespace no fetch refspec touches, so neither prune nor gc removes it (C.9).
  - The push names the object id: `<O>:refs/tags/<tag>` (C.13). Proof 1 re-runs the whole sequence with real git.
- **Restart could not compare the exact object** (Astra major). Part 2a now stores `attempt {tag, object, old}` with `push_at` (2a G.23).
  Recover mode compares the remote tag object with `attempt.object` (C.14). Structural matching is used only to block an id, never to
  credit a move.
- **A completed move could be reported as refused** (Fable M3). Any exception from `commit_moved` after an observed move becomes
  `Unknown("push_unknown")` (D.16.5).
- **Credentials pointed one directory too high** (Astra blocker 4). The SSH command now uses `creds/deploy_key` and `creds/known_hosts`,
  as Part 2c enrol writes them (A.2). Part 2c install creates the empty mirror directory; `prime` initializes it (A.4).
- **The budget did not hold across pages** (Astra major). `get_all` asks a budget callable before every page (A.3, A.5).
- **Mixed PR rows** (one definite mismatch, one unresolved lookup) gave `not_contained` (Astra major). Any unresolved row with no accepted
  row is now `unknown/lookup_failed` (C.7).
- **The mover's `Refused` always said `kept`** (Fable minor), including for `already_spent` and `witness_conflict`, which block the id for
  good. The glue now sets the approval field from what the engine and the remote say (B.6, D.16).
- **Smaller fixes:** `witness` takes `branch` (C.14); a leading-zero tie rule (C.6); peeled `^{}` lines are ignored (A.4); curl's `-q` is
  named as the protection, since curl can find a home directory through `getpwuid` without `HOME` (A.3); R2d-2 names the
  higher-branch lockout; cross-references corrected (C.7, B.6, Part 2c H.23).

**O3:** the remote witness is only as strong as tag-creation protection.
- Before Part 2c's ruleset blocks creation of `hub-promote/*` tags, a same-user process can create a forged tag. That costs a denial of
  service, never a move. This is residual R2d-1.
- Ruleset setup is a trusted operator step (Part 2c H), and it waits for Part 2e (umbrella Decisions, K3a).

## Behaviour

**A. Construction and isolation**

1. **Module.** The module is `scripts/lib/promote_mover.py`; Part 2c installs it as `/usr/local/libexec/k3dm-promote/promote_mover.py`.
   - Allowed imports: `json`, `os`, `re`, `subprocess`, `tempfile`, `time`, `typing`, `urllib.parse`, and the sibling `hub_approval`.
   - It reads no environment variable: `os.environ` and `os.getenv` are absent, and a test greps for them. It reads no file other than the
     paths it is given.
   - Python 3.9 syntax only. Tests run on the CI runner's `python3` (Ubuntu 24.04, `.github/workflows/ci.yml`) and on macOS
     `/usr/bin/python3` 3.9.6.
2. **Constructor:** `Mover(repo_url, repo_slug, api, ssh_command, workdir, clock, monotonic=time.monotonic, git=GIT)`.
   - **`git`** is the git binary, an absolute path. The module constant `GIT = "/Library/Developer/CommandLineTools/usr/bin/git"`
     is the default, because `/usr/bin/git` is the Xcode tool shim (Part 2c A.1, probe there). Tests pass the CI runner's or the Mac's
     git by absolute path; the module never searches `PATH` for it.
   - **`repo_url`** is any URL `git` accepts. In production it is the `git@github.com:...git` from `promote.conf`; in tests it is the path
     of a local bare repository.
   - **`api`** is an object with `get(path, timeout) -> (status, body)` and `get_all(path, list_key, budget) -> (status, items)`, where
     `budget` is a zero-argument callable returning the timeout for the next request (A.5). Production passes `CurlApi(token_path)`; tests
     pass a scripted fake.
   - **`ssh_command`** becomes `GIT_SSH_COMMAND`. In production (built by Part 2c) it is: `/usr/bin/ssh -F /dev/null -i
     /var/db/k3dm-promote/creds/deploy_key -o IdentitiesOnly=yes -o UserKnownHostsFile=/var/db/k3dm-promote/creds/known_hosts -o
     StrictHostKeyChecking=yes -o BatchMode=yes` (v4: the `creds/` paths Part 2c enrol writes).
   - **`workdir`** is the bare mirror itself. In production it is `/var/db/k3dm-promote/mirror.git`, which Part 2c install creates empty,
     0700 root.
   - **`clock`** has `now() -> int` (Part 2a `FileClock` in tests) and is used for the tag stamp and the tagger time. **`monotonic`** is
     used for the budget.
3. **`CurlApi(token_path)`**
   - **The call:** `/usr/bin/curl -q -sS --max-time <t> -w '\n%{http_code}' -K -`, run with `env={"PATH": "/usr/bin:/bin"}`.
     - `-q` comes first, so no curlrc is read. This is the protection: without `HOME`, curl can still find a home directory through
       `getpwuid` (Proof 6).
     - The config on stdin holds `url = "https://api.github.com<path>"`, the `Authorization: Bearer` header (read from the root-only token
       file at call time) and `Accept: application/vnd.github+json`.
     - No token appears in argv or the environment.
   - **The status** is the last line of stdout; the body is everything before it.
   - **`get_all(path, list_key, budget)`** loops pages with `per_page=100&page=N`. Before each page it calls `budget()` for that page's
     timeout; `budget()` raises `Unknown("deadline")` when less than 1 s remains, and the loop does not start that page. It stops when a
     page holds fewer than 100 items, or when the running count reaches `total_count` where the body has one (check-runs). More than 10
     pages is `(0, [])`.
   - **Failures:** a curl failure, a timeout, a non-2xx status, an unparseable body, or a list key missing from an object body returns
     `(0, ...)` or the status. Callers map it to `unknown`.
4. **Git.**
   - Always `<git> -c core.hooksPath=/dev/null` (the constructor's `git`), with an environment built from scratch: `PATH=/usr/bin:/bin`, `HOME=<workdir>`,
     `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_SSH_COMMAND=<ssh_command>`.
   - **Initialization.** Any call that finds no `<workdir>/HEAD` first runs `git init --bare -q <workdir>`. The mirror never has a configured
     remote: every fetch, `ls-remote` and push names `repo_url` explicitly.
   - **Ref namespaces (v4, B1).** Branches are fetched into `refs/k3dm/remote/heads/*`, witness tags into `refs/k3dm/witness/*`, and the
     pending tag object is held at `refs/k3dm/pending/<stamp>`. No refspec writes `refs/tags/*` in the mirror.
   - **`ls-remote` parsing.** Lines are `<oid>\t<ref>`. Only lines whose ref equals a requested name exactly are used; every line ending in
     `^{}` is ignored, whether or not git printed one for that pattern (Proof 3).
   - `Mover.prime()` initializes the mirror and does the first full fetch (C.2) with a 600 s timeout. Part 2c calls it at enrol, outside any
     request budget, and marks the daemon configured only after it succeeds.
5. **Budget.**
   - `move` and `witness` take `deadline`, an absolute `monotonic()` value. Every git or API call before the push gets the timeout
     `min(own default, deadline - monotonic())`; the defaults are git 60 s and API 20 s. `get_all` applies this per page through `budget`.
   - If less than 1 s remains before a step, the call raises `Unknown("deadline")` without starting it.
   - The push (timeout 60 s) and the observation that follows it (timeout 30 s) are outside the budget. They always run to completion or to
     their own timeout, and they are never skipped once the push has started. So a `move` returns at most 120 + 60 + 30 = 210 s after its
     `deadline` was set (Part 2c sets the client timeout from this).

**B. Results**

6. **One convention.** Internal helpers return `("ok", data)`, `("refused", code, msg)` or `("unknown", code, msg)`. `Mover.move` and
   `Mover.witness` return a dict on ok and raise `hub_approval.Refused` or `hub_approval.Unknown` otherwise, with the codes of Part 2a B.5.
   - The mover raises its `Refused` with approval `kept`; the glue (D.16.3, D.16.6) replaces that field before anything leaves the module. The
     final value is `final` for `already_spent` and `witness_conflict` (a remote tag blocks the id for good), and otherwise what the engine
     reports.
   - Mapping: an answer that means "the thing is absent or false" is `refused` only where Behaviour C says so. Everything else is
     `unknown`: every network error, timeout, 5xx, 403 or 429, malformed body, page cap, and git failure that is not a definite answer.

**C. `move(id, sha, branch, authorize, deadline)` and its order (the contract)**

`authorize` is a one-argument callable. The mover passes it `attempt = {"tag", "object", "old"}`; in production it is
`lambda attempt: engine.authorize_push(id, sha, attempt)` (2a G.23). It either returns or raises Part 2a's `Refused` or `Unknown`, which
the mover propagates untouched.

1. **Validate.** `id` against `^p[0-9]+-[0-9a-f]{8}$`, `sha` as 40 or 64 lowercase hex, `branch` against
   `^k3d-manager-v[0-9]+\.[0-9]+\.[0-9]+$`. Any failure is refused `bad_input`.
2. **Fetch.** `git fetch -q --prune --no-tags <repo_url> '+refs/heads/*:refs/k3dm/remote/heads/*'
   '+refs/tags/hub-promote/*:refs/k3dm/witness/*'`. A failure is `unknown/lookup_failed`.
3. **Witness block.** Inspect every ref under `refs/k3dm/witness/` whose object is an annotated tag (`git cat-file -t` is `tag`); other
   objects are ignored. A tag *names the id* when its message has a line exactly `approval: <id>`.
   - **Two or more name the id:** refused `witness_conflict`.
   - **Exactly one names the id:** refused `already_spent` ("a hub-promote tag already names this approval; it can never move again"). In
     fresh mode `push_at` is null, so no push of this approval can have landed through the engine; a tag naming it is foreign or
     historical, and it blocks the id permanently (v4: the v3 `already` outcome is gone, because 2a G.25 refused it anyway).
   - **None:** continue.
   - **Authentic** (used by recover mode, C.14, and by the rollback reader): an annotated tag object whose `object` is `sha` and `type` is
     `commit`, whose tagger name is `k3dm-promote`, and whose message is exactly the five lines `action: promote`, `old: <40|64 hex>`,
     `new: <sha>`, `REF: <sha>`, `approval: <id>`, in that order.
4. **Old.** `git ls-remote <repo_url> refs/heads/deploy/hub`.
   - A failure is `unknown`.
   - An absent branch is refused `deploy_moved`, with the message "deploy/hub does not exist; the first promote is the manual bootstrap in
     docs/howto/hub-promote.md" (Part 2c H.23 routes bootstrap).
5. **Already current without a witness.** When old equals `sha`, the result is refused `deploy_moved` ("deploy/hub is at that commit but
   not by this approval").
6. **Newest release branch.**
   - List every `refs/k3dm/remote/heads/*` and keep only names matching the branch regex. This is done in Python, never with a git glob such
     as `k3d-manager-v*`, which also matches `k3d-manager-vX` and `k3d-manager-v1.45.0-evil`.
   - **Tie rule (v4).** A name with a leading zero in any component (for example `k3d-manager-v1.045.0`) is ignored, so every kept name maps
     to a distinct integer tuple and no tie is possible. A requested branch with a leading zero is then refused `not_newest_branch`.
   - Sort by the integer tuple and take the last.
   - The result is refused `not_newest_branch` when `branch` is not that name, or when no name matches. Record the tip `T`.
7. **Containment** (ported from `bin/k3dm-hub-promote:39-50` `uncontained_commits` and `:22-37` `merged_pr_contains`).
   - The candidates are the `+` lines of `git cherry <sha> <old>`.
   - When there are any, `get_all("/repos/<slug>/commits/<old>/pulls", None, budget)` returns the PR rows, and only rows with `merged_at`
     not null are kept. Accept on the first row that passes all of these, in order:
     1. `number` is digits, and `head.sha` and `merge_commit_sha` are 40 or 64 hex;
     2. `git ls-remote <repo_url> refs/pull/<number>/head` equals `head.sha`;
     3. the head object exists, or `git fetch -q --no-tags <repo_url> refs/pull/<number>/head` (as `:29`) makes it exist;
     4. the merge commit exists in the mirror;
     5. `old` is an ancestor of the head;
     6. the merge commit is an ancestor of `sha`.
   - A row is *definitely rejected* when check 1, 4, 5 or 6 fails, or check 2 returns a different value. A row is *unresolved* when its
     `ls-remote` or fetch fails (the shell function skips such rows).
   - **Results.** An accepted row passes. With no accepted row: if any row is unresolved, the result is `unknown/lookup_failed` (v4: mixed
     rows, Astra major); otherwise refused `not_contained`, listing at most five short shas. A pulls lookup failure while evidence was
     needed is `unknown`.
8. **Green walk.** `git rev-list --first-parent -n 20 refs/k3dm/remote/heads/<branch>`. For each commit in order, call
   `get_all("/repos/<slug>/commits/<c>/check-runs", "check_runs", budget)` and classify as `bin/k3dm-hub-promote:93-101`
   (`classify_check_runs`) does:
   - no runs is none;
   - any run whose `status` is not `completed` is pending;
   - any `conclusion` outside `success`, `neutral` and `skipped` is failed;
   - otherwise the commit is green.

   A lookup failure is `unknown` at once. Pending, failed and none continue to the next commit. The first green is `g`.
   - None green within 20: refused `not_green`.
   - `sha != g`: refused `not_newest_green`, naming `g`. Record the walked prefix `P` (from `T` down to `sha` inclusive).
9. **Tag object, no ref (v4, B1).**
   - `stamp` is the UTC `%Y%m%dT%H%M%SZ` of `clock.now()`, and `tag = hub-promote/<stamp>`.
   - A non-empty answer (after A.4 parsing) from `git ls-remote <repo_url> refs/tags/<tag>` is refused `tag_exists`; a failure is
     `unknown`.
   - Build the object with `git mktag` reading stdin: `object <sha>`, `type commit`, `tag <tag>`,
     `tagger k3dm-promote <k3dm-promote@localhost> <clock.now()> +0000`, a blank line, then the five message lines of C.3 in order. `mktag`
     prints `O` and creates no ref (Proof 1).
   - `git update-ref refs/k3dm/pending/<stamp> <O>` holds it.
10. **Move-time recheck.** This runs after step 9, as late as possible:
    1. Repeat step 2's fetch, then step 3's witness block. The pending object is outside `refs/k3dm/witness/`, so it is not seen
       (Proof 1). Any tag naming the id now is refused per step 3.
    2. Repeat step 6 on the new fetch. Another newest branch is refused `release_moved`.
    3. The tip of `branch` must still be `T`; otherwise refused `release_moved`.
    4. Re-query the check-runs of every commit in `P`: every commit before `sha` must still be not green, and `sha` must still be green.
       Otherwise refused `release_moved`, which is `not_newest_green` at the move.
    5. `git ls-remote <repo_url> refs/heads/deploy/hub` must still equal old; otherwise refused `deploy_moved`.

    Any lookup failure is `unknown`. The remaining window, from this observation to the push, is the budget's last seconds plus
    `authorize`. A commit turning green inside that window is accepted; this is stated, not closed (R2d-3).
11. **Budget check.** If less than 1 s of `deadline` remains, the result is `Unknown("deadline")` and nothing is pushed.
12. **Authorize.** Call `authorize({"tag": tag, "object": O, "old": old})`. A `Refused` (for example `expired`) or `Unknown` propagates,
    and nothing is pushed.
13. **Push and observe.**
    - **Push:** `git push --porcelain --atomic --force-with-lease=refs/heads/deploy/hub:<old> <repo_url> <sha>:refs/heads/deploy/hub
      <O>:refs/tags/<tag>`.
    - **Observe:** `git ls-remote <repo_url> refs/heads/deploy/hub refs/tags/<tag>`. Let `ours` mean "the remote `refs/tags/<tag>` object
      id equals `O`".
    - **`ours`:** ok `{"outcome": "moved", "old", "new": sha, "tag"}`, whatever the push exit was and whatever the branch now holds. The tag
      and the branch were written atomically.
    - **Non-zero push, not `ours`, branch equal to old:** `unknown/push_unknown`. The move did not happen, the lease binds old, and a retry
      is safe.
    - **Non-zero push, not `ours`, branch at another value:** refused `deploy_moved`. The atomic push applied nothing.
    - **Zero push, not `ours`, any branch value:** `unknown/push_unknown`, with the message "the push reported success but the remote does
      not show this approval's tag; rerun with the same approval". Never consumed.
    - **Failed observation:** `unknown/push_unknown`.
    - In every `unknown` case `push_at` and `attempt` stay set in the engine, so the next call runs recover mode (C.14).
14. **`witness(id, sha, branch, attempt, deadline)`** (recover mode; v4 takes `branch` and the stored `attempt`).
    - Step C.1, then step C.2.
    - **Exact evidence.** `git ls-remote <repo_url> refs/tags/<attempt.tag>`. When its object id equals `attempt.object`, return
      `{"outcome": "moved", "old": attempt.old, "new": sha, "tag": attempt.tag}`. This is the only way recover mode credits a move.
    - **Otherwise** apply step C.3's block to the fetched witnesses: two or more naming the id raise `witness_conflict`, one raises
      `already_spent`. Structural authenticity is not enough: a legitimate landed push for this id always carries `attempt.object`, because
      `attempt` is cleared only after a read that showed no witness (2a G.26) or a definite non-move (2a G.24).
    - **None:** return `None`.
    - It never pushes.
15. **`drop_pending(tag)`.** Best effort: `git update-ref -d refs/k3dm/pending/<stamp>`. Failures are ignored.

**D. The glue, tested here with the real Engine**

16. **`promote(engine, mover, id, sha, deadline)`,** in the same module; the daemon calls it. The branch comes from the record.
    1. `r = engine.begin_promote(id, sha)` (2a G.22). Its `Refused` and `Unknown` propagate.
    2. **`mode == "consumed"`:** return `{"outcome": "already", old, new, tag}` from the record. There is no remote call.
    3. **`mode == "recover"`:** `w = mover.witness(id, sha, r.record.branch, r.record.attempt, deadline)`.
       - A dict: commit it as in step 5 and return it.
       - `None`: call `engine.finish_unmoved(id)` (2a G.26). If the record is now `expired`, raise `Refused("expired", ..., "final")`.
         Otherwise the record is `approved` with `push_at` null; continue with step 4 in the same call and the same `deadline`.
       - A `Refused` from `witness` is raised with approval `final` and no `note_refusal`: `push_at` stays set, so the record can never
         return to fresh mode while a foreign or conflicting tag names it.
    4. **`mode == "fresh"`:** `w = mover.move(id, sha, r.record.branch, lambda attempt: engine.authorize_push(id, sha, attempt), deadline)`,
       then commit it as in step 5 and return it.
    5. **Commit after a move (v4, Fable M3).** `engine.commit_moved(id, w.old, w.new, w.tag)`, then `mover.drop_pending(w.tag)`. Any
       exception from `commit_moved` (a `Refused` such as `clock_backwards`, `state_lost` or `integrity`, or an `Unknown`) becomes
       `Unknown("push_unknown")`, with a message naming the tag. `push_at` and `attempt` are still set, so the next call finds the exact
       object in recover mode.
    6. **Errors from `move`.**
       - `already_spent` or `witness_conflict`: raised with approval `final`; no `note_refusal`.
       - `bad_input`: raised with approval `kept`; no `note_refusal` (2a G.24 refuses it, and the engine validated the record).
       - Any other mover code: `engine.note_refusal(id, code)` (2a G.24). On success, raise with approval `kept`. If `note_refusal` raises
         `Refused`, raise the mover's code with that refusal's approval value; if it raises `Unknown`, raise that `Unknown`.
       - A `Refused` or `Unknown` that came from `authorize` re-raises untouched (it is the engine's own result).
       - Any other `Unknown` re-raises untouched.
    7. The mover never imports or calls the engine except through `authorize`, and the engine never calls git.

## Residuals

- **R2d-1: forged tag before the ruleset.** Until Part 2c's ruleset blocks creation of `hub-promote/*` tags (a trusted O3 step that waits
  for Part 2e), a same-user process holding the operator's push credential can create a tag naming a live id.
  - The result is `already_spent`, `witness_conflict` or `tag_exists`: a denial of service.
  - It is never a move, and recover mode credits only the exact `attempt.object`. It can also poison the shell rollback's tag stack
    (`bin/k3dm-hub-promote:224-231`); Part 2c routes rollback.
- **R2d-2: who supplies green and which branch is newest.** "Policy-valid" means "newest green on the newest release branch". Whoever can
  push a release branch and get CI green can make a commit policy-valid (S4). The same writer can push a higher-numbered branch such as
  `k3d-manager-v9.0.0` and make every promote `not_newest_branch` until it is deleted: a lockout, never a move. Release-branch protection is
  in the umbrella Decisions (Q6).
- **R2d-3: move-time window.** C.10's observation precedes the push by at most the remaining budget. A commit newer than `sha` that turns
  green inside it is not detected.
- **R2d-4: display versus authority.** `bin/k3dm-repo-sync:85` walks `--max-count=10` commits for its promotable display, while the
  authority walks 20 first-parent commits. The display is advisory; the authority decides.
- **R2d-5: pending objects.** A crash between C.9 and `drop_pending` leaves a ref under `refs/k3dm/pending/`. It is inert (no fetch or push
  refspec names it) and is removed by the next `drop_pending` of that stamp or by `reset-state` (Part 2c).

## Contract readers

All by `grep -n` on one file each, 2026-11-19.

- **The tag format and the ref.**
  - Writers: `bin/k3dm-hub-promote:142-172` (`record_move`; the message at `:150-156`; branch push at `:160`; tag push at `:170`).
  - Readers: `bin/k3dm-hub-promote:174` (`status`; `:178` lists tags and drops `^{}` lines) and `:215` (`rollback`), which parses
    `action:`, `old:` and `new:` by `sed -n` line pattern at `:227-229`.
  - The mover writes the same tag-name pattern and the same three lines, plus `REF:` and one new `approval:` line. Line-pattern readers are
    unaffected. The mover's tagger time comes from `clock`, not the wall clock.
  - After Part 2c's ruleset the shell writer can no longer push. Part 2c H.23 routes rollback (`:215`, `:284`), BREAK_GLASS (`:316`) and
    bootstrap.
- **The rollback reader is a new consumer of the witness.** It treats any `action: promote` tag as a stack entry (`:231-232`), including
  the mover's.
- **`GH_REPO`** (`bin/k3dm-hub-promote:16`) stays the user-side script's own variable; the mover never reads it.
- **Policy sources ported, not changed:** `bin/k3dm-hub-promote:22-37`, `:39-50`, `:93-101`.
- **Ref namespaces in the mirror** (`refs/k3dm/remote/heads/*`, `refs/k3dm/witness/*`, `refs/k3dm/pending/*`): the mover is the only
  reader and writer; the mirror is root-only (Part 2c).
- **Other readers of `hub-promote/` refs:** `bin/k3dm-hub-promote` and its tests. `scripts/lib/hermes/sensors.py:475` only returns the

## Proof of external behaviour

Captured locally on m4-air (macOS 26.5.2), 2026-11-19 about 12:03-12:12 UTC, with PATH git 2.56.1 and `/usr/bin/git` 2.50.1 (Apple
Git-155), curl 8.7.1. Scripts and logs: scratchpad `p1v4/b1/probe.sh`, `probe-path.log`, `probe-apple.log`, `atomic2.sh`, `atomic2.log`.

1. **B1 sequence (both gits).** A remote-less bare mirror fetched with `fetch -q --prune --no-tags <url>
   '+refs/heads/*:refs/k3dm/remote/heads/*' '+refs/tags/hub-promote/*:refs/k3dm/witness/*'`. `git mktag` from stdin printed an object id
   `O` of type `tag` and created no ref. A second identical fetch kept `O`, and the witness list held only the pre-existing tag, not the
   mover's own. `git push --porcelain --atomic --force-with-lease=refs/heads/deploy/hub:<old> <url> <sha>:refs/heads/deploy/hub

   witness. A ref under `refs/k3dm/pending/` survived the prune fetch.
2. **Stale lease.** The same push with a stale lease rejected both refs (`stale info`, `atomic push failed`), exited 1, and left the remote
   unchanged.
3. **`ls-remote` output.** Annotated tags are listed with their tag object id and, for wildcard patterns, a peeled `^{}` line with the

5. **`mktag` strictness.** A tag without a tagger line is rejected (exit 128, strict fsck).
6. **curl.** `man curl` (8.7.1): `-q` "If used as the first parameter on the command line, the curlrc config file is not read"; the `-w`

## Worker definition of done

1. **Red first, two columns.** Every must and must_not has a test, and each must_not test includes its positive control. The hand-off
   reports, per test, the pre-fix result and the mutant result in separate columns.
2. **The pre-fix code is "module absent".** Each test is also run against a stub mover that pushes `sha` unconditionally with a tag and
   returns moved. Tests marked "pre-fix red is impossible" in their must_not text are instead killed by the named mutant.
3. **Non-equivalent mutants,** each killed by a named test:
   - drop the `approval:` line;
   - fetch witnesses into `refs/tags/*` (the B1 shape; killed by E1 and E7's pending-object case);
   - accept a structural witness in recover mode without the exact object (E9, M11);
   - accept two witnesses;
   - skip the tag pre-flight;
   - skip the recheck walk of commits before `sha`;
   - call `authorize` before the recheck;
   - consume on a zero push without the exact object;
   - take a plain-string branch sort;
   - drop `--atomic` (E7's `receive.denyNonFastForwards` fixture: Proof 4 shows the tag lands without it);
   - drop the lease (E7's ancestor fixture: a push without the lease would fast-forward);
   - re-raise a `commit_moved` `Refused` untouched (E9);
   - give `get_all` one timeout for all pages (E10);
   - drop `-q` from curl, pass the token with `-H`, pass `env=None`, drop `core.hooksPath` (E8).

   Reordering the tag message lines is not a mutant: C.3's authenticity rule now fixes the order, so it is killed by the authenticity test.
4. **Fixtures assert their target first:** a temporary bare repository path, a scripted fake API, a `FileClock` file and an injected
   monotonic. No network, no real HOME, no `/usr/local`.
5. **Walk fixture.** It has 21 first-parent commits. Commit 21 (the oldest) is the only green one in the not-found case, and the
   side-parent green is distinguishable from a first-parent walk.
6. **Synthesized fixtures** (green check-runs, pulls rows, pages) carry a comment saying so until proof owed 2, 3 and 5 are captured.
7. **Checks.** `make lint-python` and `make test-pytest` pass on the CI runner. The test file also passes under macOS `/usr/bin/python3`
   3.9.6; name the interpreter in the hand-off.

## What NOT to do

- No daemon, socket, TOTP or approval logic here. The mover reaches the engine only through `authorize`.
- No environment reads, no test mode, no flag that skips checks.
- Do not edit `bin/k3dm-hub-promote`; the policy is ported, not moved.
- Never create a ref under `refs/tags/` in the mirror.
