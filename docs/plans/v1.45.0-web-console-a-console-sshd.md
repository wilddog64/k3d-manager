## Problem

The operator wants a browser SSH path into the M5 and M4 (umbrella). Its origin is an sshd that accepts only Cloudflare Access short-lived certificates and can be reached only from the local `cloudflared`. macOS Remote Login (`com.openssh.sshd`) cannot be that origin: it is socket-activated on `*:22`, and D1 leaves it as it is (the machine-setup flow uses it where it is on: `docs/howto/machine-setup.md:62`, `:74`). The console therefore runs its own sshd. This part builds that sshd, its root-owned installation, a trusted login entry, an emergency stop and a local `check`, with no Cloudflare dependency. Until part C lands, its `ForceCommand` is a stub that refuses every login, so the daemon can be installed and checked without being usable.

### Privilege and tool model (shared library `scripts/lib/web_console_common.sh`)

1. Production `main` of `bin/k3dm-web-console-sshd` starts with `PATH=/usr/bin:/bin:/usr/sbin:/sbin` and `unset -f sudo` (only there: the library sets no `PATH` and unsets nothing when sourced, so a test that sources the library without `main` keeps its own `sudo` function, E3), so the `sudo` word that `_run_command` places in its runner (`scripts/lib/foundation/scripts/lib/system.sh:106-107`) resolves to `/usr/bin/sudo`. Every external command is called by absolute path: `/usr/bin/install`, `/usr/bin/stat`, `/bin/ls`, `/bin/cp`, `/bin/mv`, `/bin/rm`, `/bin/mkdir`, `/usr/bin/touch`, `/usr/bin/tee`, `/usr/bin/mktemp`, `/bin/launchctl`, `/usr/sbin/sshd`, `/usr/bin/ssh-keygen`, `/usr/sbin/netstat`, `/bin/ps`, `/usr/bin/shasum`, `/usr/bin/plutil`, `/usr/bin/id`, `/bin/kill`, `/bin/sleep`, `/usr/bin/true`, `/usr/bin/git`. `yq` is `/opt/homebrew/bin/yq`; missing makes C7 `WARN indeterminate`.
2. `_wc_priv <abs-tool> [args]` is the only privileged call. Production body, exactly: `_run_command --interactive-sudo --soft --quiet -- "$@"`. It returns the command's exit code (`--soft`, `system.sh:148`, `:127-128`) instead of exiting (without `--soft`, `_run_command_handle_failure` calls `_err`, `system.sh:117-132`, which is `exit 1`, `:2114-2117`), and it never prints the failing argv (`--quiet`, `system.sh:122-126`). `--quiet` suppresses only `_run_command`'s own diagnostic; the privileged tool's stderr is the caller's: it is sent to `/dev/null` on every call except `sshd -t` and `sshd -T` in step 13, whose stderr is captured into a variable and printed after the login is replaced by `<login>` and `$HOME` by `~`. Every caller checks the code; an unchecked `_wc_priv` is a source-scan failure (E3).
3. `_wc_priv` runs `sudo -n` whenever stdin or stdout is not a tty (`system.sh:60-65`). So the script first calls `_wc_priv_open`: refuse with exit 10 (`web-console-sshd: an interactive terminal is required for the sudo prompt`) unless `-t 0` and `-t 1`; run `_wc_priv /usr/bin/true` on the tty (the one password prompt); then run `_wc_priv /usr/bin/true </dev/null` (the `sudo -n` path). A failure of the second call is exit 10, `web-console-sshd: sudo ticket not usable from a pipe; sudo timestamp_timeout must be greater than 0`. Every later call, including the piped `tee`, runs inside that ticket. This needs the default ticket (5 minutes); the v2 recommendation of `timestamp_timeout=0` is withdrawn (it made every piped call fail). The ticket window is residual R-SUDO.
4. Payloads go to root on stdin only: `printf '%s' "$payload" | _wc_priv /usr/bin/tee <stage file> >/dev/null`. `tee` output is discarded, so no rendered line, login or key reaches the terminal.
5. `_wc_tool <abs-tool> [args]` runs an unprivileged tool by absolute path.
6. Installer fixture mode needs all three: the directory named by `K3DM_WC_ROOT` holds the file `.k3dm-wc-fixture`, `EUID` is not 0, and the marker is checked first (variable set and marker missing is exit 2). In fixture mode `_wc_priv` and `_wc_tool` never call `_run_command`, `sudo` or the absolute path: they append the argv to `$K3DM_WC_ROOT/calls.log` and run `$K3DM_WC_ROOT/bin/<basename>` with an empty `PATH`. A missing shim is exit 2 before any action. File-touching shims (`install`, `mv`, `rm`, `mkdir`, `touch`, `tee`, `mktemp`, `cp`, `kill`) exit 99 on an absolute path argument outside `$K3DM_WC_ROOT`. Every absolute path resolves under `$K3DM_WC_ROOT` in fixture mode. The fixture rules bind installer fixtures only; the integration tests E1 and E8 run the real `sshd` and `zsh` (Acceptance says which is which).
7. No root-owned artifact (stub, gate, verifier) reads an environment variable for a path.
8. **Argv boundary (N7).** No child process the script starts has an argv that contains the operator login, a home path, a key or certificate body, or a rendered config line. The operator-typed `--ca-file` and `--cloudflared-config` values are opened by bash redirection (`< "$path"`) in the script's own process and never passed to a child; the script's own argv, typed by the operator, is outside N7.

### 1. `bin/k3dm-web-console-sshd install [--ca-file PATH] [--after-revoke] [--dry-run]`

Run by the operator on the machine, as the operator user, watched (O3). Steps stop at the first failure.

1. **Refusals (exit 2).** Non-Darwin; `EUID` 0 (`web-console-sshd: run as the operator user, not root`); a login name (`/usr/bin/id -un`) that is empty, `root`, or does not match `^[a-z_][a-z0-9_-]*$`; a login shell that is not `/bin/zsh`, read as the last field of `/usr/bin/id -P` (no login in argv; probe below); any of `/etc/zshenv`, `/etc/zshenv.zwc`, `/etc/ssh/sshrc` existing (`web-console-sshd: <path> exists; the trusted entry needs it absent`). zsh reads `/etc/zshenv` first and it cannot be overridden (`/usr/share/man/man1/zsh.1:430`); sshd runs `/etc/ssh/sshrc` when it exists and no user rc applies (`/usr/share/man/man8/sshd.8:376-385`). All three are absent on the M4 (probe).
2. **Port** `${WEB_CONSOLE_SSH_PORT-42722}` (an empty value is refused, not defaulted). Refuse (exit 2, `web-console-sshd: refusing port <n>: <reason>`) with these exact reasons: `empty value`; `not a decimal port` (anything but `^[0-9]+$`); `outside 1024-49151`; `reserved SSH alternate` (`2222`, `2200`-`2299`, `2022`, `8022`, `10222`, `22222`, `32222`); `held by another process` (listening and `_wc_listener` does not name this job); and, when it differs from `console_port` in an existing `/etc/k3dm-web-console/totp.conf`, the message `web-console-sshd: part C is installed on port <old>; uninstall part C first`. It never falls back to another port. IPv6 is not offered. Before the lock these checks are advisory when a journal exists (they print what they see and step 9 decides); without a journal a refusal here exits at once, and step 9 decides again either way.
3. **Revoked marker (advisory before the lock).** When `/etc/k3dm-web-console/revoked` exists and `--after-revoke` is not given: exit 2, `web-console-sshd: revoked; rerun with --after-revoke to restore the daemon`. With `--after-revoke` the run reads and prints the marker's id here; step 9 and step 16 use that id.
4. **Sources.** These tracked files must be unchanged from `HEAD` (`/usr/bin/git diff --quiet HEAD -- <paths>` and `git ls-files --error-unmatch`): this script, `scripts/lib/web_console_common.sh`, `scripts/lib/system.sh`, `scripts/lib/foundation/scripts/lib/system.sh`, `scripts/lib/agent_rigor.sh` (sourced by the foundation copy, `system.sh:28-36`), the config template, the plist template and the stub; otherwise exit 9, `web-console-sshd: sources differ from HEAD; commit or discard first`. The installed bytes are the `HEAD` blobs (`git cat-file blob HEAD:<path>`). The run prints each blob id. This is accident prevention, not authentication (R-INSTALL).
5. **Render in memory** with bash parameter expansion, never `sed`, `envsubst` or `eval`; the two placeholders are `{{CONSOLE_USER}}` and `{{CONSOLE_PORT}}`, each validated first. **Exact-line allow-list:** the rendered bytes must equal, byte for byte, the 39 lines of the Acceptance `interface` entry "sshd_config", in that order, each ending in one LF, with no other line, blank or comment. The script holds that list as its own array, so a template edit alone fails install. Any `Match`, `Include`, `Subsystem`, `AcceptEnv`, second `SetEnv` variable, quoted keyword, tab or `=` form is therefore refused by construction (probes below show each is a live bypass of a keyword scan). Failure is exit 4.
6. **Open sudo**: `_wc_priv_open` (model item 3); exit 10 on failure.
7. **Pre-lock trust check, unprivileged, before any privileged write.** `_wc_trust_check` on `/`, `/private`, `/private/etc`, `/Library`, `/Library/LaunchDaemons`, `/Library/PrivilegedHelperTools`, `/private/var`, `/private/var/db`, `/private/var/log`, and on `/etc/k3dm-web-console`, its `zdotdir` and `.prev`, and the helper directory and its `.prev`, each when it exists. Rules: owner uid 0; no group or other write bit (the sticky bit is allowed); no ACL (the `ls -lde` mode string has no trailing `+`); a symlink is allowed only for `/etc`, `/var`, `/tmp` resolving to `/private/...`. An existing `.prev` must also be `0700`. An existing `zdotdir` must also be empty (`/bin/ls -A` prints nothing), else exit 8 (`untrusted path /etc/k3dm-web-console/zdotdir (not empty)`); step 16 checks it again just before `bootstrap`. Then `_wc_dest_check` on every destination file (including the log and the plist): an existing one that is operator-owned, a symlink, group/other writable or has an ACL is exit 8, `web-console-sshd: untrusted path <path> (<reason>); nothing written`.
8. **Lock.** `_wc_priv /bin/mkdir /var/db/k3dm-web-console.lock`, then the holder line through `tee`. When `mkdir` fails: a holder whose pid is alive with the same `lstart` is exit 7 (`web-console-sshd: another install or uninstall holds the lock`); a lock directory with no holder file and an mtime younger than 10 s counts as live (exit 7, closes the creation race). Otherwise the lock looks stale and is reclaimed only under the reclaim guard: `_wc_priv /bin/mkdir /var/db/k3dm-web-console.lock.reclaim` (a failure is exit 7; a guard older than 60 s is reported as `web-console-sshd: stale reclaim guard /var/db/k3dm-web-console.lock.reclaim; remove it after checking that no install runs` and is never removed automatically); holding the guard, the run reads the holder again and removes the lock only when it is still stale by the same rules, takes the lock with `mkdir`, writes its holder, and removes the guard. A reclaimer that finds a live holder on the second read releases the guard and exits 7, so two reclaimers never remove a lock that a third run has just taken.
9. **Recover, then decide, under the lock.** `_wc_txn_recover` (a journal left by a crashed run is rolled back first and reported, `web-console-sshd: rolled back an interrupted install`); `_wc_stage_clean` on both directories. Recovery restores files only and never runs `launchctl bootstrap`. Then steps 2 and 3 are decided again from the recovered state, and these decisions are binding: the busy port and the `totp.conf` port rules (exit 2), and the marker (absent without `--after-revoke`, or present with the id read at step 3 under `--after-revoke`; present with another id is exit 11 after this step, `web-console-sshd: a newer revoke arrived; not loaded`).
10. **Create missing directories as root** (`/usr/bin/install -d -o root -g wheel -m <mode>`): the config directory, `zdotdir`, the helper directory, both `.prev`. Each is recorded `created` in the journal before it is made, then passes `_wc_trust_check` (exit 8 otherwise).
11. **Stage** (`_wc_stage_new` in the config directory and in the helper directory; `0700`): stream with `_wc_stage_put` the rendered `sshd_config`, the plist, the stub as `forced-command.stub`, the stub as `forced-command` (only when `forced-command` is absent or the manifest lists it as part A's stub with a matching hash; any other `forced-command` is kept and, when the manifest does not list it as part C's gate with a matching hash, install refuses with exit 8, `unrecognised forced-command`), the CA (step 12), and the new manifest. Generate the host key in the stage only when no installed key exists (`ssh-keygen -q -t ed25519 -N '' -f <stage>/ssh_host_ed25519_key`). Pre-create the log (`install -m 0600 -o root -g wheel /dev/null <log>`) when absent.
12. **CA.** With `--ca-file`, read once into memory: exactly one non-blank, non-comment line; first token one of `ssh-ed25519`, `ecdsa-sha2-nistp256`, `ecdsa-sha2-nistp384`, `ecdsa-sha2-nistp521`, `ssh-rsa` (an options-prefixed line is refused); `ssh-keygen -l -f -` on stdin prints exactly one line. Without `--ca-file` the installed `access_ca.pub` is kept and checked by the same rule. Failure is exit 2. The run always prints the fingerprint of the CA it will trust, kept or new, as parsed fields only (`<bits> <SHA256:...> <type>`; the comment field is dropped).
13. **Validate in the stage, as root.** `sshd -t -f <stage>/sshd_config -h <host key>` and `sshd -T -C user=nobody,host=localhost,addr=127.0.0.1,laddr=127.0.0.1,lport=<port> -f <stage>/sshd_config -h <host key>`, where `<host key>` is the staged key on a first install and the installed key otherwise (without `-h`, a first install fails with `no hostkeys available`, probe below); the `-T` output must show every value of the allow-list; `plutil -lint` on the staged plist. Failure removes the stage and the directories this run created, leaves every installed file untouched, exit 4, `web-console-sshd: validation failed; nothing loaded`.
14. **Commit** (`_wc_commit`, journaled). Journal format: one line per action, `<seq> <created|moved> <dest> <backup|->`, appended by `printf '%s\n' "<line>" | _wc_priv /usr/bin/tee -a /var/db/k3dm-web-console.txn >/dev/null` before the action runs (`<backup>` is the `.prev` copy, `-` when the destination did not exist; every path is a constant without blanks). Recovery reads the lines from last to first: `moved` with a backup restores the destination from the backup when they differ; `moved` with `-` and `created` remove the destination when present. Each recovery step is idempotent, so a crash during recovery is rolled back again by the next run. A recovery step that fails exits 5 with `web-console-sshd: restore incomplete; journal kept; rerun install`, keeps the journal and releases the lock. Copy each installed destination to `.prev/` (`cp -p` as root into the `0700` directory, replacing the older backup). Then move staged files into place one `mv` at a time, recording each in the journal: CA, `forced-command.stub`, `forced-command` (when allowed), the host key pair (when new), `sshd_config`, `manifest`, and the plist into `/Library/LaunchDaemons` last (only when a CA is installed). All these paths are on one APFS volume (probe: one device id), so each `rename(2)` is atomic. A failed `mv` restores every already-moved destination from `.prev` (or removes it when it was new), exit 5, `web-console-sshd: commit failed; previous generation restored`. A crash during the commit leaves the journal, and the next run's step 9 rolls back the same way.
15. **CA missing:** the plist goes to `/etc/k3dm-web-console/launchd.plist.pending` instead, no load, exit 3, `web-console-sshd: files installed; CA public key missing, daemon not loaded`.
16. **Load.** (a) Under `--after-revoke`, consume the marker: `mv revoked revoked.consumed.<id>` with the id read at step 3, then read the moved file; when its content is not `<id>` (a newer revoke replaced the marker between the read and the move), move it back to `revoked`. (b) Re-check: `zdotdir` empty, and `revoked` absent. If `revoked` exists (a revoke ran meanwhile) or `zdotdir` is not empty: move `/Library/LaunchDaemons/com.k3d-manager.web-console-sshd.plist` to `launchd.plist.revoked` (marker case) or remove it (zdotdir case), do not load, exit 11 (`web-console-sshd: revoked during install; not loaded`) or 8. (c) `launchctl bootout system/<label>` (its code is recorded and ignored: on a first install nothing is loaded), `launchctl bootstrap system <plist>` (code checked), wait up to 10 s for C3 and C4. (d) Immediately after a healthy load the marker is checked again; if it appeared, install runs `bootout` itself, moves the plist to `launchd.plist.revoked` and exits 11. So every exit 11 leaves no console plist in `/Library/LaunchDaemons` (`RunAtLoad` cannot bring it back at boot). (e) A failed load restores the previous generation from `.prev`, runs `bootout`, and runs `bootstrap` of the previous plist only when one existed and `revoked` is absent, exit 5, `web-console-sshd: load failed; previous generation restored`. A first install that fails removes exactly the journal's `created` and new paths. Revoke wins over every recovery or rollback: no path of install, recovery or rollback runs `bootstrap` while `revoked` exists.
17. **End.** Remove the journal and release the lock on every exit path except a failed restore (step 14), which keeps the journal (an `EXIT` trap; the trap never runs a privileged command whose code it ignores except `rm` of the lock).
18. **Idempotence.** When the installed `sshd_config`, plist, CA, stub and manifest hashes equal the staged ones and C3 and C4 hold, nothing is moved and the run exits 0 (`web-console-sshd: already installed`). A run whose only difference is the CA moves `access_ca.pub` and then the manifest (two moves) with no restart (proof owed P5).
19. **`--dry-run`** runs steps 1-5 and 12 unprivileged, prints the rendered config with the login replaced by the literal `<login>`, the file list with owner and mode, and the commands it would run; makes no `_wc_priv` call and no write; exits 0.

### 2. `revoke`, `uninstall [--purge]` and the stop procedure

- **Privilege for `revoke` and `uninstall`.** `uninstall` needs a terminal: `_wc_priv_open`, exit 10 without one. `revoke` must also work for part B's revoke and from a script: when stdin and stdout are ttys it runs `_wc_priv_open`; otherwise it runs `_wc_priv /usr/bin/true </dev/null` and, when that fails (no open ticket), exits 10 with `web-console-sshd: revoke needs an open sudo ticket or a terminal`, having changed nothing.
- **Port for `revoke` and `uninstall`:** `_wc_port_lookup` (installed `sshd_config`, else `.prev/sshd_config`, else the environment, else 42722); the run prints the port and its source.
- **Live socket on the port** (one definition for the stop procedure, the exit codes and E9 and E14): a `netstat -anv -p tcp` row whose local address is `127.0.0.1.<port>`, whose state is `LISTEN`, `SYN_RCVD`, `ESTABLISHED`, `CLOSE_WAIT` or `FIN_WAIT_1`, and whose owner pid exists (`ps -o pid= -p`). `TIME_WAIT`, `FIN_WAIT_2`, `CLOSING`, `LAST_ACK` rows and rows whose owner is gone are not live and are ignored.
- **`revoke`** is the emergency stop. It does not wait for the lock (an emergency stop never blocks); it serialises with install through the per-event marker (install steps 9 and 16). Steps: (1) write a new marker with `_wc_revoke_mark`: create `/etc/k3dm-web-console` (`install -d -o root -g wheel -m 0755`) when absent, write `<UTC>.<pid>` through `tee` into `revoked.tmp.<pid>` and `mv` it over `revoked` (a newer revoke replaces an older id); (2) move `/Library/LaunchDaemons/com.k3d-manager.web-console-sshd.plist` to `launchd.plist.revoked` when it exists (replacing an older parked copy); (3) the stop procedure with step (c) always run; (4) exit 0 when no S pid survives with the same `lstart` and no live socket remains on the port, 1 otherwise (pids printed, never commands). The order (marker, plist, bootout) means an install that commits its plist after step 2 still sees the marker at its step 16. A second `revoke` writes a new marker, finds no plist and no listener, boots out nothing that is loaded, and exits 0.
- **`uninstall [--purge]`** takes the lock, runs the stop procedure, and removes the plist, `launchd.plist.pending`, `launchd.plist.revoked`, `revoked`, every `revoked.consumed.*`, `sshd_config`, `manifest`, both `.prev`, `zdotdir`, `forced-command`, `forced-command.stub`, the log and any journal. Without `--purge` it keeps the host key pair and `access_ca.pub`; with it, it also removes them and both directories. It refuses (exit 6, `web-console-sshd: part C is installed; run uninstall-web-console-totp first`) when the manifest lists a part C row or `/Library/LaunchDaemons/com.k3d-manager.web-console-totp.plist` exists (written as a literal ending in `.plist`, which `agent_classification.bats` skips). It never touches `com.openssh.sshd` or `/etc/ssh`. Exit 0 clean, 1 survivor, 6, 7, 10.
- **Stop procedure** (`_wc_stop <port>`). A `launchctl bootout` of an `sshd -D` job leaves already-forked sessions, and session titles carry no config path, so nothing matches by argv (W1).
  - (a) Listener: `_wc_listener <port>`. Result 0 gives L. Result 1 (no row and no job: after a revoke, an exit-3 install, a crash) gives no L; the procedure continues with the socket set. Result 3 (a row whose pid is not uid 0 or is not the job's pid, or a job pid with no row) gives no L, the row's pid is never signalled (an impostor), and the procedure's result is 1 even when everything else is stopped.
  - (b) Snapshot S, recording `lstart` per pid from `ps -axo pid=,ppid=,uid=,lstart=,command=`: L and its breadth-first descendants; plus the owner pid of every live socket on the port, of any uid (a console session's socket is owned by the user `sshd-session` with the operator's uid, not by uid 0: Fable's round-3 probe, capture owed P7), and, for each such owner, its parent when that parent has uid 0 and its command starts `sshd-session: ` and ends ` [priv]`; plus the breadth-first descendants of each. Excluded from S, with all their descendants: every listener row pid that `_wc_listener` did not accept (an impostor, of any uid, including uid 0) and every owner whose parent chain reaches such a pid.
  - (c) `launchctl bootout system/<label>` (code recorded, never fatal).
  - (d) Wait up to 5 s; recompute descendants of each surviving S member and the owners of live sockets on the port with their `[priv]` parents (new ones join S under the same exclusions); `kill -TERM` each S pid whose `lstart` is unchanged; wait up to 3 s; `kill -KILL` the rest. The waits are multiplied by `K3DM_WC_STOP_WAIT_SCALE` in installer fixture mode only (interface); production ignores it.
  - (e) Confirm no S pid survives with the same `lstart` and no live socket remains on the port other than an excluded impostor's (which makes the result 1 anyway).
  - Never signalled: a pid whose `lstart` changed; an unrelated Remote Login session (`sshd-session` with ppid 1, captured below); the `cloudflared` client (ephemeral local port, foreign `127.0.0.1.<port>`); an impostor listener. The tmux server daemonizes (ppid 1) and is never in S, so the `work` session survives revoke. A process deliberately daemonized from inside a console session before the snapshot also escapes S (residual R-REPARENT).
  - While the console sshd is down, any same-user process can bind `127.0.0.1:<port>` and receive the tunnel's connections; part B's revoke stops the console tunnel first (umbrella; part B outline item 4).

### 5. Named residuals (O3 and runtime)

- **R-INSTALL (O3, accepted).** The installer and its sources are operator-writable. The operator starts and watches the install (O3). Optional out-of-band check: compare the printed blob ids with the remote tree (umbrella decision 5). The same holds for the `/usr/bin/git` Xcode shim the installer runs.
- **R-SUDO (O3, accepted).** For the install's duration plus the sudo ticket (default 5 minutes, per tty), a same-user process on that tty can run commands as root. The operator runs the install from a plain terminal and may run `sudo -k` afterwards (the how-to says so).
- **R-CONFIG (runtime, detective only).** A same-user process can edit the cloudflared files C7 reads; C7 detects, part B owns the routes.
- **R-REPARENT (runtime).** A process that daemonizes itself out of a console session (as tmux does) is not a descendant at snapshot time and survives revoke; it runs as the operator, which O2 already assumes hostile, and holds no console socket (step (e) checks).
- **R-PORT-GAP (runtime, owned by part B).** While the console sshd is down, a same-user process can bind the port; part B's revoke stops the tunnel first.
- **R-REVOKE-CODE (runtime, accepted by K1 = a, umbrella decision 14).** `revoke` is the checkout script acting through the checkout library with the operator's sudo ticket; a same-user change to those files can make a revoke print success while the job or a session survives. ## What NOT to do

- Do not run the install target, `launchctl` or `sshd` against the real `/etc` or `/Library`; never edit `/etc/ssh` or touch `com.openssh.sshd`.
- Do not add Cloudflare, tunnel, Access or TOTP code here; those are parts B and C.
- Do not bind IPv6, `localhost` or any non-loopback address, and do not add a `Port` line.
- Do not put the console in an agents, secrets or hub list, or print the operator login, a home path or key material.
- Do not write rendered bytes to an operator-writable file, a pid file or `/var/run`; do not read a path from the environment in a root-owned artifact.
- Do not build a separate admin account, a root-owned installer verifier or a phone confirmation (O3).
- Do not run `make -n` on the lifecycle targets in a test.
- Do not commit, push, dispatch, or skip pre-commit hooks.
