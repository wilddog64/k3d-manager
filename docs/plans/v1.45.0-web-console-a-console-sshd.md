## Problem

The operator wants a browser SSH path into the M5 and M4 (umbrella). Its origin is an sshd that accepts only Cloudflare Access short-lived certificates and can be reached only from the local `cloudflared`. macOS Remote Login (`com.openssh.sshd`) cannot be that origin: it is socket-activated on `*:22` and the machine-setup flow needs it on (`docs/howto/machine-setup.md:74`). The console therefore runs its own sshd. This part builds that sshd, its root-owned installation, a trusted login entry, an emergency stop and a local `check`, with no Cloudflare dependency. Until part C lands, its `ForceCommand` is a stub that refuses every login, so the daemon can be installed and checked without being usable.

## Behaviour

Constants (fixed in the script; the only environment inputs are `WEB_CONSOLE_SSH_PORT` and, in fixture mode only, `K3DM_WC_ROOT`):

- Label `com.k3d-manager.web-console-sshd`. Plist `/Library/LaunchDaemons/com.k3d-manager.web-console-sshd.plist`, `root:wheel`, `0644`.
- Config directory `/etc/k3dm-web-console`, `root:wheel`, `0755`. In it: `sshd_config`, `ssh_host_ed25519_key` (`0600`), `ssh_host_ed25519_key.pub`, `access_ca.pub`, and the empty directory `zdotdir` (`0755`). Every entry is `root:wheel`, files `0644` unless stated. Generation backups live in `/etc/k3dm-web-console/.prev` (same ownership).
- Helper directory `/Library/PrivilegedHelperTools/k3dm-web-console`, `root:wheel`, `0755` (probe: `/Library/PrivilegedHelperTools` is `root:wheel` and not group or other writable here; `/usr/local` can be operator-owned on other Macs and `/usr/local/libexec` is absent here, so the earlier `/usr/local/libexec` location is dropped). In it: `forced-command` (`0755`), `forced-command.stub` (`0755`) and `.prev/`.
- Log `/var/log/k3dm-web-console-sshd.log`, `root:wheel`, `0600`. There is no pid file: `/var/run` is `root:daemon 0775` (group-writable), so the config says `PidFile none` and the listener pid comes from `netstat` (Behaviour 3, C3).
- Install lock: the directory `/var/db/k3dm-web-console.lock` (`/var/db` is `root:wheel 0755`), created by `mkdir` as root. Holder pid and `ps -o lstart` are written inside. Part C uses the same lock.
- Nothing installed lives in, or points into, the user-writable checkout, `$HOME` or a Homebrew prefix. The plist template has no `{{REPO_ROOT}}`, no `{{HOME}}` and no `/opt/homebrew/bin/python3`.

### The `_wc_priv` and `_wc_tool` model (shims; no fixture runs a real binary)

1. Every external command is called by absolute path (`/usr/bin/install`, `/usr/bin/stat`, `/bin/launchctl`, `/usr/sbin/sshd`, `/usr/bin/ssh-keygen`, `/usr/sbin/netstat`, `/bin/ps`, `/usr/bin/shasum`, `/usr/bin/plutil`, `/usr/bin/dscl`, `/bin/kill`, `/bin/mv`, `/bin/rm`, `/bin/mkdir`, `/usr/bin/tee`, `/usr/bin/mktemp`, `/usr/bin/git`; `yq` is `/opt/homebrew/bin/yq`, missing means C7 fails closed). GNU coreutils come first on this operator's `PATH`; `_run_command` rewrites a bare program name to its `/usr/bin`, `/bin`, `/usr/sbin` or `/sbin` path (`scripts/lib/foundation/scripts/lib/system.sh:67-76`), but only for a bare name, so absolute paths are the rule.
2. All privileged calls go through one function `_wc_priv <abs-tool> [args]`. Production body: exactly `_run_command --interactive-sudo -- "$@"` (`system.sh:152` defines the prompting form; `--require-sudo` needs passwordless sudo, `system.sh:137`). All unprivileged external calls go through `_wc_tool <abs-tool> [args]` which runs the absolute path directly.
3. Fixture mode requires all three: the directory named by `K3DM_WC_ROOT` contains the file `.k3dm-wc-fixture`, `EUID` is not 0, and the marker is checked first, before any other action (missing marker with the variable set is exit 2). In fixture mode `_wc_priv` and `_wc_tool` never call `_run_command`, `sudo` or the absolute path: they append the argv to `$K3DM_WC_ROOT/calls.log` and run `$K3DM_WC_ROOT/bin/<basename>` with an empty `PATH`. A missing shim is exit 2 before any action, so a forgotten shim cannot reach a real binary. Fixture shims for file-touching tools (`install`, `mv`, `rm`, `mkdir`, `tee`, `mktemp`, `kill`) refuse, exit 99, any absolute path argument that is not under `$K3DM_WC_ROOT`. Every absolute path in the script resolves under `$K3DM_WC_ROOT` in fixture mode.
4. `_run_command` is a sourced function, so a `PATH` shim cannot replace it; it appears only inside `_wc_priv` (source scan over the script and the shared library, E2). `sudo` and `command sudo` appear nowhere. `_wc_priv`, `_wc_tool`, the fixture-mode gate, the trust-chain validation, the lock and the stage helpers live in `scripts/lib/web_console_common.sh`, sourced by this script and by part C's `bin/k3dm-web-console-totp`, so both parts share one tested copy.
5. The override does not exist in any root-owned artifact: the gate stub, the (part C) gate and verifier read no environment variable for a path.

### 1. `bin/k3dm-web-console-sshd install [--ca-file PATH] [--dry-run]`

Run by the operator on the machine, as the operator user.

1. Refuse (exit 2) on non-Darwin, on `EUID` 0 (`web-console-sshd: run as the operator user, not root`), when the login name is empty, `root`, or not matching `^[a-z_][a-z0-9_-]*$`, and when `/usr/bin/dscl . -read /Users/<login> UserShell` is not `/bin/zsh` (`web-console-sshd: login shell is not /bin/zsh; the trusted entry is only proven for zsh`; open question 8).
2. The port is `${WEB_CONSOLE_SSH_PORT-42722}` (no colon, so an empty value is refused, not defaulted). Refuse (exit 2, `web-console-sshd: refusing port <n>: <reason>`) when it is not a decimal 1024-49151, is `2222`, `2200`-`2299`, `2022`, `8022`, `10222`, `22222`, `32222`, or is already listening and the listener pid is not this job's own listener (own = the pid the console's `127.0.0.1.<port>` LISTEN row names, and only while `launchctl print system/<label>` reports the same pid). It never falls back to another port. IPv6 is not offered.
3. Sources: the four tracked source files (template, plist template, stub, this script) must be unchanged from `HEAD` (`/usr/bin/git diff --quiet HEAD -- <paths>` and `git ls-files --error-unmatch`); otherwise exit 9, `web-console-sshd: sources differ from HEAD; commit or discard first`. The installed bytes are read from the `HEAD` blobs (`git cat-file blob HEAD:<path>`), not the working tree. The run prints each source's `git rev-parse HEAD:<path>` blob id.
4. Render in memory with bash parameter expansion (`${var//\{\{NAME\}\}/$value}`), never `sed`, `envsubst` or `eval`, so no rendered value appears in any argv. Placeholders: `{{CONSOLE_USER}}`, `{{CONSOLE_PORT}}`, `{{CONF_DIR}}`, `{{HELPER_DIR}}`, `{{ZDOTDIR}}`. Values are validated first (login regex, port rule, constants). Nothing is written to an operator-writable scratch file: rendered bytes are streamed to root through `_wc_priv /usr/bin/tee <stage file>` on stdin (proof owed P3: `tee` through `_run_command --interactive-sudo` passes stdin). The run prints the sha256 of each streamed payload, then root re-hashes the staged file (`_wc_priv /usr/bin/shasum -a 256`) and a mismatch is exit 8.
5. The rendered config contains exactly these effective settings (E1 asserts `sshd -G -f`; install asserts `sshd -T` as root):
   - `ListenAddress 127.0.0.1:<port>` and `AddressFamily inet`; no `Port` line, no other `ListenAddress`;
   - `HostKey` the console key; `PidFile none`; `UsePAM no`;
   - `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitEmptyPasswords no`, `HostbasedAuthentication no`, `GSSAPIAuthentication no`, `PermitRootLogin no`;
   - `PubkeyAuthentication yes`, `AuthenticationMethods publickey`, `TrustedUserCAKeys /etc/k3dm-web-console/access_ca.pub`, `AuthorizedKeysFile none`;
   - `AllowUsers <operator login>`;
   - `DisableForwarding yes`, `AllowTcpForwarding no`, `AllowAgentForwarding no`, `AllowStreamLocalForwarding no`, `GatewayPorts no`, `PermitTunnel no`, `X11Forwarding no`, `PermitUserRC no`, `PermitUserEnvironment no`, `PermitListen none`, `PermitOpen none`; no `Subsystem` line (no sftp);
   - `PermitTTY yes`, `ForceCommand /Library/PrivilegedHelperTools/k3dm-web-console/forced-command`;
   - `SetEnv ZDOTDIR=/etc/k3dm-web-console/zdotdir` (the trusted entry, below);
   - `MaxAuthTries 3`, `MaxSessions 1`, `MaxStartups 3:50:10`, `LoginGraceTime 30`, `LogLevel VERBOSE`, `ClientAliveInterval 300`, `ClientAliveCountMax 3`, `StrictModes yes`, `UseDNS no`.
   - Text scan of the rendered bytes (install, dry-run and `check` all run it): no line begins, after optional blanks, with `Match`, `Include`, `AcceptEnv` or `Subsystem` (case-insensitive); exactly one `SetEnv` line and it is the ZDOTDIR line; exactly one `ListenAddress`; no `Port`. `-G` ignores `Match`, so the scan, not `-G`, is what excludes Match overrides; install additionally runs `_wc_priv /usr/sbin/sshd -T -C user=nobody,host=localhost,addr=127.0.0.1,laddr=127.0.0.1,lport=<port> -f <staged>` (the dummy `user=` keeps the login out of argv).
6. Trusted entry (W2, O2). `sshd` runs `ForceCommand` through the operator's login shell with `-c` (`man sshd_config`, probed 2026-11-18). The operator's `~/.zshenv` is a symlink into the operator's dotfiles checkout (`bin/k3dm-machine-setup:404-405`) and zsh reads it for every invocation, so any agent that can write the operator's dotfiles runs code before any gate. Probe: `env -i HOME=<h> /bin/zsh -c` runs `<h>/.zshenv`, and with `ZDOTDIR` set to a directory (existing empty, or not existing) it does not. The config therefore sets `SetEnv ZDOTDIR=/etc/k3dm-web-console/zdotdir` (`SetEnv` overrides the default environment, `AcceptEnv` and `PermitUserEnvironment`; `sshd -G` prints `setenv ZDOTDIR=...`), `/etc/zshenv` must be absent or root-owned (C10), the target `forced-command` is root-owned in a root-owned directory, and the stub and the part C gate start with `#!/bin/sh` and `#!/usr/bin/python3 -I` (`-I` ignores `PYTHON*` variables and the user site; probe: a plain `/usr/bin/python3` ran a user-site `usercustomize.py`, `-I` did not). No command that can read operator-writable state runs before the stub. The real `sshd` effect of `SetEnv` on the `ForceCommand` environment is proof owed P1.
7. Generation staging and rollback (W3, W6), in this order, stopping at the first failure; every step is a `_wc_priv` call:
   1. Take the lock (`mkdir /var/db/k3dm-web-console.lock`; held by a live holder with the same `lstart` is exit 7 `web-console-sshd: another install or uninstall holds the lock`; a dead holder's lock is removed first).
   2. Validate the trust chain before any privileged write (E2): for each of `/etc`, `/etc/k3dm-web-console`, `/Library/LaunchDaemons`, `/Library/PrivilegedHelperTools`, `/Library/PrivilegedHelperTools/k3dm-web-console`, `/var/db`, `/var/log`, and each ancestor, `stat` shows owner uid 0, no group or other write bit, and no ACL (the `ls -lde` mode string ends in `+`); the only symlinks allowed in a path are `/etc`, `/var` and `/tmp` (resolved to `/private/...`); a destination file that exists must be a regular file, not a symlink. Failure is exit 8, `web-console-sshd: untrusted path <path> (<reason>); nothing written`.
   3. Create the stage directory as root: `mktemp -d /etc/k3dm-web-console/.stage.XXXXXXXX` (mode `0700`, so no pre-existing `.new` or `.prev` file is ever trusted) and, when absent, the two directories and `zdotdir`.
   4. Stream and hash-check into the stage: `sshd_config`, the plist, the stub, also as `forced-command.stub` in the helper directory (`0755`, never executed by sshd; it is the canonical stub copy and part C restores from it); `forced-command` is replaced by the stub only when it does not exist or its sha256 equals the installed `forced-command.stub`'s (any other `forced-command`, i.e. a part C gate, is never replaced), and `access_ca.pub`.
   5. CA (when `--ca-file` is given, else the installed one is kept): read once into memory; exactly one non-blank, non-comment line; the first token is one of `ssh-ed25519`, `ecdsa-sha2-nistp256`, `ecdsa-sha2-nistp384`, `ecdsa-sha2-nistp521`, `ssh-rsa` (so an options-prefixed line such as `command="..." ssh-ed25519` is refused); `ssh-keygen -l -f -` on stdin prints exactly one line (probe: `-f -` accepts stdin); that fingerprint line is printed. Failure is exit 2.
   6. Host key: `ssh-keygen -q -t ed25519 -N '' -f <stage>/ssh_host_ed25519_key` as root, installed only when no host key exists (a changed host key breaks the operator's browser trust).
   7. Validate in the stage as root: the text scan and `sshd -T` of 1.5, `sshd -t -f`, and `/usr/bin/plutil -lint` of the plist. `sshd -t` accepts a missing CA file and a missing `ForceCommand` target (probe), so `check` C5 and C6 test them. Failure removes only the stage directory, leaves every installed file untouched, exit 4, `web-console-sshd: validation failed; nothing loaded`.
   8. Copy the installed generation (config, CA, stub, plist, with `cp -p`) into `.prev` directories, replacing the previous backups, then `mv` the staged files into place (`mv` within one directory is atomic per file). The plist is moved into `/Library/LaunchDaemons` last, and only when the daemon will be loaded.
   9. CA missing after all of the above: the plist stays in the stage's pending name `<plist>.pending`, no load, exit 3, `web-console-sshd: files installed; CA public key missing, daemon not loaded`.
   10. Otherwise `launchctl bootout system/<label>` (soft), `launchctl bootstrap system <plist>`, wait up to 10 s for C3 (one LISTEN row `127.0.0.1.<port>` owned by `sshd`) and C4.
   11. A failed step 10 restores the whole previous generation from `.prev` (config, CA, stub, plist), `bootout` and `bootstrap` again when a previous generation existed, exit 5, `web-console-sshd: load failed; previous generation restored`. A first install that fails removes exactly the inventory of paths this run created and records them in the stage's `created.list` before creating them.
   12. Release the lock on every exit path.
8. Idempotence: when the installed `sshd_config`, plist, `access_ca.pub` and stub hashes equal the rendered ones and C3 and C4 hold, nothing changes and the run exits 0 (`web-console-sshd: already installed`). A run whose only difference is the CA file replaces `access_ca.pub` with one `mv` and no restart (proof owed P5: sshd reads the CA file at each authentication).
9. `--dry-run` prints the rendered config with the login replaced by the literal `<login>` (`AllowUsers <login>`), the file list with owner and mode, and the commands it would run; makes no `_wc_priv` call and no write at all; exits 0.

### 2. `bin/k3dm-web-console-sshd uninstall [--purge]` and `revoke`

- Both run the stop procedure below. `revoke` is the emergency stop: after the stop it also moves the plist to `<plist>.revoked` (so a reboot does not restart it) and keeps every other file; exit 0 only when nothing remains, 1 when a survivor remains (pids printed, never commands).
- `uninstall` runs the stop procedure, removes the plist, `sshd_config`, `.prev`, `zdotdir`, `forced-command` and the log; without `--purge` it keeps the host key and CA. It refuses (exit 6, `web-console-sshd: part C is installed; run uninstall-web-console-totp first`) when `forced-command` is not the stub (sha256 differs from `forced-command.stub`) or the part C plist exists, and takes the same lock. It never touches `com.openssh.sshd` or `/etc/ssh`.
- Stop procedure (W1). A `launchctl bootout` of an `sshd -D` job leaves already-forked session processes, and the session titles carry no config path (captured below), so a `pkill -f <config>` cannot find them. Instead: (a) from `netstat -anv -p tcp` find the LISTEN row `127.0.0.1.<port>`; its `process:pid` is the listener L (only when `launchctl print system/<label>` reports the same pid; a mismatch aborts with exit 1 and no kill); (b) snapshot the set S: breadth-first descendants of L by `ps -axo pid=,ppid=,lstart=,command=` (ppid links), recording `lstart` per pid, plus every pid owning a socket whose local address is `127.0.0.1.<port>`; (c) `launchctl bootout system/<label>`; (d) wait up to 5 s, recompute descendants of any surviving S member (children forked meanwhile join S), `kill -TERM` each S pid whose `lstart` is unchanged, wait up to 3 s, then `kill -KILL` the rest; (e) confirm no S pid survives (same `lstart`) and no socket has local port `<port>`. A pid whose `lstart` changed is never signalled. Unrelated Remote Login sessions are children of launchd (ppid 1), are never in S, and are never signalled. The client side of the tunnel (`cloudflared`, a socket whose local port is ephemeral and foreign port is `<port>`) is never in S.

### 3. `bin/k3dm-web-console-sshd check [--strict] [--cloudflared-config PATH]...`

Read-only, no sudo, never prints the operator login, a home path, a key or a certificate. One line per item, level `PASS`, `FAIL`, `WARN` or `INFO`, then the id and text; exit 0 when no item is `FAIL`, 1 otherwise, 2 on usage error. Items:

- `C1 files`: every constants-list path exists with the stated owner, group and mode; the trust-chain validation of install step 7.2 holds; `zdotdir` is an empty directory; `.prev` content is not checked.
- `C2 config`: `sshd -G -f /etc/k3dm-web-console/sshd_config` shows every effective value of 1.5, including `setenv ZDOTDIR=/etc/k3dm-web-console/zdotdir`, `pidfile none` and exactly one `listenaddress` equal to `127.0.0.1:<port>`; and the text scan of 1.5 passes on the installed file. Because `-G` ignores `Match`, the scan covers it.
- `C3 listener`: from `netstat -anv -p tcp`, exactly one LISTEN socket has local port `<port>`, its address is `127.0.0.1.<port>`, its process is `sshd` and its pid equals `launchctl print system/<label>`'s `pid = <n>` line. Two rows, a `*.<port>` row or another owner is `FAIL C3` (`port <n> is held by another process` for the owner case).
- `C4 launchd`: `launchctl print system/<label>` exits 0, state is running, arguments are `/usr/sbin/sshd -D -e -f /etc/k3dm-web-console/sshd_config`. The `print` shape for a root job is proof owed P2; until it is captured the fixture is marked UNPROVEN and the live E10 is the proof.
- `C5 ca`: `access_ca.pub` is exactly one public-key line (same rule as install step 5), and its fingerprint is printed.
- `C6 forced-command`: the target exists, is `root:wheel`, executable, not group or other writable, and is either the stub or (after part C) a file whose first line is `#!/usr/bin/python3 -I`.
- `C7 system-sshd-not-tunnelled` (D1), strict allow-list, fail closed. Inputs: the repo `scripts/etc/cloudflared/config.yml`, `${HOME}/.cloudflared/config.yml`, every `--cloudflared-config` and every `--config <path>` or `--config=<path>` found in the argv of a running process whose program basename is `cloudflared` (`ps -axo command=`). Each file is parsed with `yq`; an unparsable or unreadable file is `FAIL`. Per file: `warp-routing.enabled: true` is `FAIL`; an ingress rule with `originRequest.bastionMode: true` is `FAIL`; every `service:` must be `http://`, `https://`, `http_status:` or `unix:`, or exactly `ssh://127.0.0.1:<port>`; any `ssh://`, `tcp://` or `rdp://` with another target, any URL ending in `:22`, or `localhost` as an ssh/tcp/rdp target is `FAIL`. A cloudflared process started with `--token` or no readable config (remote-managed ingress) is `WARN` (`effective routes are not inspectable here; part B owns the route inventory`), never `PASS`. `C7` is detective: a same-user process can edit these files (open question 5).
- `C8 system-sshd-password-off` (D1): `sshd -G` with no `-f` shows `passwordauthentication no` and `kbdinteractiveauthentication no`. It is `WARN` (never `FAIL`) while the machine-setup `FROM=` pull still uses password ssh (`bin/k3dm-machine-secrets:103`, `docs/howto/machine-setup.md:74`), because turning both off breaks that pull until the operator moves it to key login (open question 2); `--strict` makes it `FAIL`. It never edits anything and prints the two lines an operator drop-in would need.
- `C9 remote-login-note`: `INFO` only, one fixed format `INFO C9 socket on *.22: yes|no`.
- `C10 login-shell`: the operator's `UserShell` is `/bin/zsh`, and `/etc/zshenv` is absent or `root:wheel` and not group or other writable.

- Do not add Cloudflare, tunnel, Access or TOTP code here; those are parts B and C.
- Do not bind IPv6, `localhost` or any non-loopback address, and do not add a `Port` line.
- Do not put the console in an agents, secrets or hub list, or print the operator login, a home path or key material.
- Do not write rendered bytes to an operator-writable file, a pid file, or `/var/run`; do not read a path from the environment in any root-owned artifact.
- Do not run `make -n` on the lifecycle targets in a test.
- Do not commit, push, dispatch, or skip pre-commit hooks.
