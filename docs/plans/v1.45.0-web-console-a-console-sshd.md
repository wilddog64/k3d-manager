## Problem

The operator wants a browser SSH path into the M5 and M4 (umbrella). Its origin is an sshd that accepts only Cloudflare Access short-lived certificates and can be reached only from the local `cloudflared`. macOS Remote Login (`com.openssh.sshd`) cannot be that origin: it is socket-activated on `*:22` and the machine-setup flow needs it on (`docs/howto/machine-setup.md`). The console therefore runs its own sshd. This part builds that sshd, its root-owned installation and a local `check`, with no Cloudflare dependency. Until part C lands, its `ForceCommand` is a stub that refuses every login, so the daemon can be installed and checked without being usable.

## Behaviour

Constants (fixed in the script; none read from the environment except where stated):

- Label `com.k3d-manager.web-console-sshd`. Plist `/Library/LaunchDaemons/com.k3d-manager.web-console-sshd.plist`, `root:wheel`, mode `0644`.
- Config directory `/etc/k3dm-web-console`, `root:wheel`, `0755`. In it: `sshd_config` (`0644`), `ssh_host_ed25519_key` (`0600`), `ssh_host_ed25519_key.pub` (`0644`), `access_ca.pub` (`0644`). All `root:wheel`.
- Helper directory `/usr/local/libexec/k3dm-web-console`, `root:wheel`, `0755`. In it: `forced-command` (`0755`, `root:wheel`).
- Log `/var/log/k3dm-web-console-sshd.log`, `root:wheel`, `0600`. Pid file `/var/run/k3dm-web-console-sshd.pid`.
- Nothing installed lives in, or points into, the user-writable checkout or `$HOME`. The plist template has no `{{REPO_ROOT}}` and no `{{HOME}}` placeholder.

1. `bin/k3dm-web-console-sshd install [--ca-file PATH] [--dry-run]`, run by the operator on the machine, as the operator user.
   1. Refuse on non-Darwin, on `EUID` 0 (exit 2, message `web-console-sshd: run as the operator user, not root`), and when the login name is empty, `root`, or not matching `^[a-z_][a-z0-9_-]*$`.
   2. The port is `${WEB_CONSOLE_SSH_PORT:-42722}`. Refuse (exit 2, message `web-console-sshd: refusing port <n>: <reason>`) when it is not a decimal 1024-49151, or is `2222`, `2200`-`2299`, `2022`, `8022`, `10222`, `22222`, `32222`, or is already listening and the listener is not this job's own sshd (own = the `sshd` pid that `launchctl print system/<label>` reports). It never falls back to another port. IPv6 is not offered: the daemon binds `127.0.0.1` only (this closes the umbrella contradiction between N1 and the optional `[::1]`).
   3. Render `scripts/etc/ssh/k3dm-web-console_sshd_config.tmpl` into a scratch directory (`mktemp -d`, mode `0700`) with exactly four placeholders: `{{CONSOLE_USER}}`, `{{CONSOLE_PORT}}`, `{{CONF_DIR}}`, `{{LIBEXEC_DIR}}`. Values are validated first (user regex above, port rule above, the two directories are the constants). Substitution is a fixed `sed` replacement, never `eval` or `envsubst`.
   4. The rendered config contains exactly these effective settings (asserted with `sshd -G -f` in the tests and, as root at install time, `sshd -T -f`):
      - `ListenAddress 127.0.0.1:<port>` and `AddressFamily inet`; no `Port` line, no other `ListenAddress`;
      - `HostKey` the console key; `PidFile` as above; `UsePAM no`;
      - `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitEmptyPasswords no`, `HostbasedAuthentication no`, `GSSAPIAuthentication no`, `PermitRootLogin no`;
      - `PubkeyAuthentication yes`, `AuthenticationMethods publickey`, `TrustedUserCAKeys /etc/k3dm-web-console/access_ca.pub`, `AuthorizedKeysFile none`;
      - `AllowUsers <operator login>`;
      - `DisableForwarding yes`, `AllowTcpForwarding no`, `AllowAgentForwarding no`, `AllowStreamLocalForwarding no`, `GatewayPorts no`, `PermitTunnel no`, `X11Forwarding no`, `PermitUserRC no`, `PermitUserEnvironment no`; no `Subsystem` line at all (no sftp);
      - `PermitTTY yes`, `ForceCommand /usr/local/libexec/k3dm-web-console/forced-command`;
      - `MaxAuthTries 3`, `MaxSessions 1`, `MaxStartups 3:50:10`, `LoginGraceTime 30`, `LogLevel VERBOSE`, `ClientAliveInterval 300`, `ClientAliveCountMax 3`, `StrictModes yes`, `UseDNS no`.
   5. Install through `_run_command --interactive-sudo` only (see the sudo note under Contract readers), in this order, stopping at the first failure:
      1. `install -d -o root -g wheel -m 0755` for the two directories;
      2. generate the host key with `ssh-keygen -q -t ed25519 -N '' -f` only when `ssh_host_ed25519_key` does not exist (never regenerate: a changed key breaks the operator's browser trust);
      3. when `--ca-file` is given: validate it as a single public key with `ssh-keygen -l -f` (exit 2 on failure) and install it as `access_ca.pub`; otherwise keep an installed one;
      4. stage `sshd_config.new` and the plist as `*.new`, then run `sshd -t -f` on the staged config as root. When `-t` fails: remove only the `*.new` files, leave every previous file untouched, exit 4, message `web-console-sshd: sshd -t failed; nothing loaded`. `sshd -t` does not check the `TrustedUserCAKeys` or `ForceCommand` paths (probe below), so `check` items C5 and C6 do;
      5. keep the previous `sshd_config` as `sshd_config.prev`, move the staged files into place (`mv` within one directory), then install the stub from `scripts/libexec/k3dm-console-forced-command` as `forced-command` only when none exists or the installed one is byte-identical to a previous stub (a part C gate is never overwritten);
      6. when `access_ca.pub` is absent: do not load the daemon, exit 3, message `web-console-sshd: files installed; CA public key missing, daemon not loaded`. Otherwise `launchctl bootout system/<label>` (soft), `launchctl bootstrap system <plist>`, then wait up to 10 s for the listener check C3;
      7. when the load or C3 fails: restore `sshd_config.prev` (when one exists), `bootout` and `bootstrap` again, exit 5, message `web-console-sshd: load failed; previous config restored`. A first install that fails removes only the files this run created.
   6. A run whose rendered config and plist are byte-identical to the installed ones and whose daemon is healthy changes nothing and exits 0 (`web-console-sshd: already installed`).
   7. `--dry-run` prints the rendered config, the file list with owner and mode, and the commands it would run; makes no `_run_command` call and no write outside its scratch directory; exits 0.
2. `bin/k3dm-web-console-sshd uninstall [--purge]`: `launchctl bootout system/<label>`, remove the plist, then remove `sshd_config`, `sshd_config.prev`, `forced-command` and the log. Without `--purge` it keeps the host key and CA key. After the bootout it waits up to 5 s; when any process whose argument list contains `/etc/k3dm-web-console/sshd_config` survives (this includes `sshd-session` children), it ends them through `_run_command --interactive-sudo -- pkill -f`. Exit 0 only when no listener on the port and no such process remain. It never touches `com.openssh.sshd` or `/etc/ssh`.
3. `bin/k3dm-web-console-sshd check`: read-only, needs no sudo, never prints the operator login, a home path, a key or a certificate. One line per item, `PASS <id> <text>` or `FAIL <id> <text>`; exit 0 only when C1-C8 all pass, 1 when any fails, 2 on usage error. Items:
   - `C1 files`: every file in the constants list exists with the stated owner, group and mode, and no ancestor directory up to `/` is writable by group or other (`stat -f '%Su:%Sg %Lp'`).
   - `C2 config`: `sshd -G -f /etc/k3dm-web-console/sshd_config` (works unprivileged, probe below) shows every effective value of 1.4, no `subsystem` line, and exactly one `listenaddress`, equal to `127.0.0.1:<port>`.
   - `C3 listener`: from `netstat -anv -p tcp` (lists every user's sockets without root, probe below), every LISTEN socket on the port is `127.0.0.1.<port>`, at least one exists, and its process is `sshd` with the pid that `launchctl print system/<label>` reports. Any other owner on the port is `FAIL C3 port <n> is held by another process`.
   - `C4 launchd`: `launchctl print system/<label>` exits 0, state running, program arguments `/usr/sbin/sshd -D -e -f /etc/k3dm-web-console/sshd_config`.
   - `C5 ca`: `access_ca.pub` is a single public key (`ssh-keygen -l -f`).
   - `C6 forced-command`: the target exists, is `root:wheel`, executable, not writable by group or other.
   - `C7 system-sshd-not-tunnelled` (D1): in the repo cloudflared config (`scripts/etc/cloudflared/config.yml`), in `${HOME}/.cloudflared/config.yml`, and in any file named by `--cloudflared-config` (part B passes the console tunnel config), every `service:` value is `http://`, `https://`, `http_status:` or `unix:`, or is exactly `ssh://127.0.0.1:<port>`. A `service:` of `ssh://`, `tcp://` or `rdp://` with another target, any URL ending in `:22`, or `localhost` is `FAIL`.
   - `C8 system-sshd-password-off` (D1): `sshd -G` with no `-f` (effective system configuration including `/etc/ssh/sshd_config.d/*`) shows `passwordauthentication no` and `kbdinteractiveauthentication no`. It never edits anything. On `FAIL` it prints the two lines an operator drop-in would need and says the script changed nothing. Probe result below: this item fails on the M4 today.
   - `C9 remote-login-note`: prints whether a socket listens on `*.22` as `INFO` only, never `FAIL`: Remote Login stays on for machine-setup.
4. `Makefile` targets `install-web-console-sshd`, `uninstall-web-console-sshd`, `web-console-sshd-check`, each a one-line call to the script, each in `.PHONY` and in the help text. The install target carries that name because `scripts/tests/bin/machine_setup.bats` derives the action from the plist template name.
5. `scripts/etc/machine/not-installed.list` gains `install-web-console-sshd|not installed by setup: operator-run once with a password; adds a root LaunchDaemon (docs/plans/v1.45.0-web-console-a-console-sshd.md)` and `web-console-sshd|system LaunchDaemon installed once by make install-web-console-sshd`. The console is in no `agents.*.list` and no `secrets.*.list` (host key, CA key and later the TOTP secret are machine-local and never copied between Macs by `bin/k3dm-machine-secrets`).
6. `scripts/libexec/k3dm-console-forced-command` is a `/bin/sh` stub: writes `console gate not installed` to stderr and exits 1, with no `exec`, no shell fallback and no `-i`.
7. `docs/howto/web-console-sshd.md`: what the daemon is, why Remote Login stays on, the port and refusal rules, install, check, uninstall, the stub, and that Cloudflare (part B) and the gate (part C) are separate. States plainly that this part alone gives no remote access.
8. Test overrides: when `EUID` is not 0 and the directory named by `K3DM_WC_ROOT` contains a file `.k3dm-wc-fixture`, every absolute path above resolves under that directory. The marker is checked first, before any other action; a missing marker is exit 2. No override exists for any executable (tests put shims for `launchctl`, `sshd`, `netstat`, `ssh-keygen` and the sudo router on `PATH`, asserted first by name). The override is rejected when `EUID` is 0.
