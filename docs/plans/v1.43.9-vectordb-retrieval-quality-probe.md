## Problem

The VectorDB dashboard answers the first two questions: reachability, rows and age for health, and
(after plan 3) drift by kind for consistency. Nothing answers the third.

Retrieval quality was measured once, by hand, in v1.40.0. The live case in
`scripts/tests/bin/test_find_similar_docs.py` runs only with `K3DM_RETRIEVAL_EVAL_LIVE=1`. It
scores recall@5 and hard-negative intrusion@5 over `scripts/tests/fixtures/doc-dedup/pairs.jsonl`
(27 positive pairs, 25 or more hard negatives). The 2026-10-01 result is in
`docs/guides/vector-store.md`. Since then, retrieval could have degraded with no signal. This can
come from a re-index, a model change, a schema change, or a corpus that grew.

"Correct" is covered by recall. "Current" is not covered by anything. A retrieved row can carry a
hash from an older version of the doc, or point at a doc that was deleted.

## Change

### C1. One evaluation, two callers

Move `_pairs`, `_evaluate` and the live `rank` (`search(text, k=6)`, drop the query's own path,
keep 5) from the test file into `scripts/lib/hermes/retrieval_eval.py`.

The live pytest and the probe both import it, and the live pytest keeps its behaviour and floors.
Move `LIVE_RECALL_FLOOR` into the module as the single source.

### C2. "Current" check

For every result the probe returns, compare the result's indexed `content_hash` with the corpus
hash from `iter_corpus(ROOT, ref)`. Use the same ref Hermes indexes.

- `stale_hits`: a result whose hash differs.
- `deleted_hits`: a result whose path is not in the corpus.

Read hashes with the existing `fetch_hashes()`, once per run — not once per query.

### C3. Run it from Hermes, at most once a day

Hermes already holds the embedding credential when it runs `index-docs.py`. The metrics
LaunchAgent may not hold it, and its Keychain fallback prompts.

After `_refresh_index` finishes with result `success` or `noop`, run the probe if the last probe is
more than 24 hours old. Record that time in Hermes' existing `state` dict. A probe failure
(`RetrievalUnavailable` or any exception) is logged as one line. It must never change the index
result or stop the Hermes tick.

Cost: about 52 query embeddings a day. Do not add a timeout path that retries the embeddings.

### C4. Metrics

Push the metrics with the same Pushgateway helper as `_push_index_metrics`, under job
`k3dm-vectordb-retrieval`.

| metric | meaning |
|---|---|
| `k3dm_vectordb_retrieval_recall_at5{directory}` | share of positive pairs found in the top 5 |
| `k3dm_vectordb_retrieval_recall_floor{directory}` | `LIVE_RECALL_FLOOR`, so the alert does not repeat the numbers |
| `k3dm_vectordb_retrieval_intrusion_at5{directory}` | share of hard-negative pairs in the top 5 |
| `k3dm_vectordb_retrieval_stale_hits` / `_deleted_hits` | counts from C2 over all returned results |
| `k3dm_vectordb_retrieval_results` | total results returned (the denominator) |
| `k3dm_vectordb_retrieval_probe_last_success_timestamp_seconds` | the end of the last completed probe |

No query text, path or title appears in any label.

### C5. Alerts (`scripts/etc/prometheus/rules/vectordb.yaml`)

| alert | expr | for |
|---|---|---|
| `VectorDBRetrievalRecallBelowFloor` | `k3dm_vectordb_retrieval_recall_at5 < on(directory) k3dm_vectordb_retrieval_recall_floor` | `1h` |
| `VectorDBRetrievalReturnsOutdatedDocs` | `(k3dm_vectordb_retrieval_stale_hits + k3dm_vectordb_retrieval_deleted_hits) > 0` | `1h` |
| `VectorDBRetrievalProbeStale` | `time() - k3dm_vectordb_retrieval_probe_last_success_timestamp_seconds > 172800` | `30m` |

All are `severity: warning` with `cluster: hub`, like the existing rules. Each description says what
to run: `K3DM_RETRIEVAL_EVAL_LIVE=1 pytest scripts/tests/bin/test_find_similar_docs.py -k live`.
The outdated-docs description also says to run `make index-docs DRY_RUN=1`.

### C6. Dashboard: three rows, one per question

Reorganise `grafana-dashboard-vectordb.yaml` into four rows. Keep every existing panel's `id`,
`targets`, `fieldConfig` and `options`; change only `gridPos`.

1. Row `Infrastructure health — is pgvector available and accepting queries?`: panels 4 and 3.
2. Row `Data consistency — are indexed documents synchronized with the repository?`: panels 1, 2 and 5 (from plan 3), and 14.
3. Row `Retrieval quality — do agents retrieve the correct, current documents?`: new panels.
   - 20: stat, recall@5 by directory, with thresholds from the floor.
   - 21: stat, intrusion@5 by directory.
   - 22: stat, `stale_hits + deleted_hits`, green at 0 and red above.
   - 23: stat, time since the last probe.
4. The existing `Ingestion` row with 11, 12, 16, 13 and 15, unchanged in order.

There is no overlap and no vertical gap. Each new panel has a description.

## Tests

`scripts/tests/bin/test_retrieval_probe.py`, with a fake `search`, `iter_corpus` and
`fetch_hashes`. It uses no store, no embeddings API and no Pushgateway (URL `http://127.0.0.1:9`).

1. A fake `search` that returns the expected doc for 3 of 4 positives gives recall 0.75 for that directory.
2. A result whose indexed hash differs from the corpus counts in `stale_hits`. A result for a path not in the corpus counts in `deleted_hits`. Both are red on a copy where C2 is removed.
3. `fetch_hashes` is called once per probe, whatever the number of queries.
4. Hermes: the probe is skipped when the last probe was under 24h ago, and runs when it was over 24h ago.
5. Hermes: a probe that raises `RetrievalUnavailable` leaves the index result and the tick's return value unchanged.
6. No pushed line carries a path, title or query label.

The existing pytest in `test_find_similar_docs.py` passes unchanged in count. Its live case still
skips without `K3DM_RETRIEVAL_EVAL_LIVE=1`.

BATS `vectordb_rules.bats`:

7. Four rows in the C6 order. Every pre-existing panel has the same `targets`/`fieldConfig`/`options` as before. There are no overlaps and ids are unique.
8. The three alerts exist with the C5 exprs.

Also run `make validate-manifests`.
