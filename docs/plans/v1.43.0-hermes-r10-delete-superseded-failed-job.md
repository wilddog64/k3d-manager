## Problem

When a CronJob's Job fails and the CronJob spec is then fixed (new image, command or args), the
failed Job stays behind. `KubeJobFailed` keeps firing for a failure that the current spec can no
longer produce, until someone runs `kubectl delete job` by hand. Today Hermes can only report it.
R10 makes it an approval-gated repair: Hermes proposes it, and a human approves it in Slack.

## Definitions

A Job is **superseded** only when **all** of the following hold:
1. Its namespace is in `R10_NAMESPACES = ("identity", "monitoring", "cicd")`.
2. It has a `Failed` condition with status `"True"`, and `status.active` is absent or 0.
3. It has an `ownerReferences` entry with `kind: CronJob` and `controller: true`, and that CronJob
   exists in the same namespace.
4. `template_fingerprint(job.spec.template.spec)` is not equal to
   `template_fingerprint(cronjob.spec.jobTemplate.spec.template.spec)`.
5. Its name matches `^[a-z0-9]([-a-z0-9]*[a-z0-9])?$` and is at most 63 characters.

`template_fingerprint(pod_spec)` is the SHA-256 of canonical JSON (`sort_keys=True`, compact
separators) of
`[[c.name, c.image, c.command or [], c.args or []] for c in initContainers + containers]`.
Env, resources and labels are deliberately excluded. Only a change to what *runs* counts as
superseding.

A failed Job whose fingerprint still matches the CronJob is **not** superseded. That failure
could happen again, so it stays a report or a bug, never a deletion.

## Fix

### 1. `scripts/lib/hermes/sensors.py`: new sensor `superseded_jobs(run, state, context=None, threshold=2)`
- `context` defaults to `os.environ.get("K3DM_HERMES_JOB_CONTEXT", "k3d-k3d-cluster")`.
- For each namespace in `R10_NAMESPACES` (import it from `repairs`, so there is one source of truth):
  - `kubectl --context <ctx> -n <ns> get jobs -o json --request-timeout=10s`
  - `kubectl --context <ctx> -n <ns> get cronjobs -o json --request-timeout=10s`
  - parse the output and apply the definition above.
- `data = {"context": ctx, "jobs": [{"namespace", "name", "cronjob", "failed_at"}...], "unreadable": [ns...]}`,
  sorted by namespace, then name.
- Status follows `node_pressure`:
  - `"unknown"` when every namespace is unreadable;
  - `"degraded"` (debounced through `_debounced("superseded_jobs", ..., threshold, state)`) when
    any job is superseded;
  - `"healthy"` otherwise.
- Evidence reads `N superseded failed Jobs: ns/name (cronjob X), ...`, with the first 3 listed.
- Read-only. It never runs a verb other than `get`, and never touches a Secret.

### 2. `bin/k3dm-hermes`
Register the sensor next to `hostnet_drift(_probe_run, state)` (around line 184), as
`superseded_jobs(_probe_run, state)`.

### 3. `scripts/lib/hermes/repairs.py`
- `R10_NAMESPACES = ("identity", "monitoring", "cicd")` at module level.
- `_r10_targets(records)` returns `(context, namespace, [names])` for the **first namespace**, in
  sorted order, that has superseded jobs. It applies items 1 and 5 of the definition again on the
  record data, as defence in depth. It returns `None` if nothing qualifies.
- `_r10_precondition(records, _history, _state)`: `_status(records, "superseded_jobs") == "degraded"`
  **and** `_r10_targets(records)` is not `None`.
- `_r10_command(records)` returns
  `["kubectl", "--context", ctx, "-n", ns, "delete", "job", "--wait=false", "--", *names]`
  with `{}` as env. The `--context` is always explicit, and the names come after `--`.
- `REPAIRS["r10"] = {"key": "r10", "name": "Delete failed Jobs superseded by a newer CronJob spec",
  "precondition": _r10_precondition, "build_command": _r10_command, "cwd": None,
  "blast_radius": "named failed Job objects (and their finished pods) in one allowlisted namespace; CronJobs untouched",
  "reversible": False, "needs_scope": "local hub kubeconfig"}`
- `_evidence`: add `"r10": ("superseded_jobs",)`.
- **`approve()` target pinning:** after the precondition re-check, `r10` only. Rebuild the command
  from `records_now`; if `shlex.join(argv) != proposal["command"]`, return
  `{"outcome": "refused: target set changed since proposal", "action_id": action_id}` and
  execute nothing. Never delete a set the human did not see.
- **Never auto-executed.** R10 is not added to any auto-remediation path.

## Tests (each new test is shown failing against the pre-change code, on a temp copy)
- `scripts/tests/hermes/test_superseded_jobs.py`, with a fake `run` returning fixture JSON:
  - a failed CronJob-owned Job whose image differs from the CronJob's: superseded, and degraded
    only after the 2nd cycle;
  - the same Job with a matching image: not superseded;
  - an image-identical Job whose only difference is env: not superseded;
  - an active Job (`active: 1`): not superseded;
  - a Job with no CronJob owner, or whose CronJob is missing: not superseded;
  - `default` and `kube-system`: never queried (assert on the argv the fake `run` received);
  - every namespace failing with rc≠0: `unknown`;
  - an assertion that no argv contains `delete`, `patch` or `secret`.
- `scripts/tests/hermes/test_repairs.py`, extended:
  - `r10` precondition and command for two Jobs in `monitoring`: the exact argv, with
    `--context` and `--`;
  - a name containing `;` or uppercase is dropped by `_r10_targets`;
  - `approve()`:
    - with the target set unchanged: executes once, writes the audit, and adds `r10` to
      `repairs_attempted_this_incident`;
    - with one more Job in `records_now`: refused, and the runner is never called;
    - when the precondition no longer holds: refused;
  - `auto_remediate_kine` never runs `r10`.
