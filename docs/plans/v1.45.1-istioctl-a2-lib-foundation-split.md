## Problem

Part B's Step 0 (`git subtree pull ... v0.5.8 --squash`) is refused by k3d-manager's pre-commit `_agent_audit`
(`scripts/lib/foundation/scripts/lib/agent_rigor.sh:124-155`): "core.sh exceeds if-count threshold in:
_install_istioctl:17". The audit counts lines matching `^[[:space:]]*if[[:space:](]` (not `elif`) per `function` and
refuses any function above `AGENT_AUDIT_MAX_IF` (default 8) unless listed in `scripts/etc/agent/if-count-allowlist`.
lib-foundation's own hooks do not run `_agent_audit`, so v0.5.8 passed review there. Observed on m4, 2026-11-23; an awk
copy of the rule on lib-foundation main `ac67873` prints exactly `_install_istioctl:17` and nothing else in `core.sh`.

## Behaviour

Split `_install_istioctl` (`scripts/lib/core.sh:472-576`) into private helpers so that **every** function in `core.sh` has
at most 8 counted `if` lines. Observable behaviour is unchanged: same signature and default, same env vars, same stdout
and stderr text byte for byte, same return/exit status, same external commands with the same arguments in the same
order, same temp-dir cleanup on every failure path.

Suggested split (the worker may choose another that meets the rules):

- `_istioctl_find_existing <install_dir>` — prints the install_dir or PATH istioctl, or nothing.
- `_istioctl_client_version <path>` — prints `X.Y.Z` from the first line `client version: X.Y.Z`, else `unknown`.
- `_istioctl_platform` — the two `uname` cases.
- `_istioctl_fetch_verified <version> <os> <arch> <checksum> <base_url> <tmp_dir>` — curl, sha256, compare, extract.
- `_istioctl_copy_into <tmp_dir> <install_dir>` — mkdir (plain, then `_run_command --soft --prefer-sudo`) and cp.

Rules for the split:

1. **`_err` and subshells.** `_err` exits. A helper that can reach `_err` must not be called inside `$(...)`, a pipeline
   or any other subshell, where `exit` would only end the subshell and `_install_istioctl` would carry on. Either call it
   directly and pass results back through variables the caller declared `local` (bash dynamic scope), or make the helper
   return non-zero and keep the `_err` call in the caller. The existing `checksum="$(_istioctl_pinned_sha256 …)" || _err`
   form (no `_err` inside the helper) is fine.
2. **Cleanup.** Every path that reached `mktemp -d` removes `$tmp_dir` before `_err` and before success, as today. No
   `trap`, `cd` or `pushd` (v0.5.8 N4).
3. **Names.** New helpers are `_istioctl_*`, declared with `function name() {` like the rest of `core.sh` (the audit only
   sees the `function` keyword; a helper declared without it would be folded into the previous function's count).
4. **No gate change.** Do not raise `AGENT_AUDIT_MAX_IF`, add an allowlist line, or edit `agent_rigor.sh`.

## Contract readers

`_install_istioctl` callers are unchanged (same signature). k3d-manager reads it through the subtree after part B's pull:
`grep -rn '_install_istioctl' scripts/ bin/` in k3d-manager — part B owns that list. New helper names are private and must
not collide: `grep -rn '_istioctl_' scripts/` in lib-foundation and k3d-manager shows only `_istioctl_pinned_sha256` today.
