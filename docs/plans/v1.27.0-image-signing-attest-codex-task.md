## The change (one file)

**File:** `.github/workflows/build-push-deploy.yml`

Insert **three new steps** immediately **after** the `Sign image by digest` step
(the one whose `run:` is `cosign sign --yes --key env://COSIGN_KEY "${IMAGE_REF}@${DIGEST}"`)
and **before** the `Update image tag in k8s/base/kustomization.yaml` step (`id: promote`).

All three steps carry the **same guard** as the existing sign step:
`if: env.COSIGN_KEY != ''`.

### Exact YAML to insert

```yaml
      - name: Generate vuln attestation predicate (Trivy)
        if: env.COSIGN_KEY != ''
        uses: aquasecurity/trivy-action@v0.35.0
        with:
          image-ref: ${{ inputs.image-name }}@${{ steps.push.outputs.digest }}
          format: cosign-vuln
          output: trivy-vuln.json
          severity: CRITICAL,HIGH
          ignore-unfixed: true
          exit-code: '0'

      - name: Generate SBOM predicate (Trivy SPDX)
        if: env.COSIGN_KEY != ''
        uses: aquasecurity/trivy-action@v0.35.0
        with:
          image-ref: ${{ inputs.image-name }}@${{ steps.push.outputs.digest }}
          format: spdx-json
          output: sbom.spdx.json
          exit-code: '0'

      - name: Attest vuln + SBOM by digest
        if: env.COSIGN_KEY != ''
        env:
          COSIGN_KEY: ${{ secrets.COSIGN_KEY }}
          COSIGN_PASSWORD: ${{ secrets.COSIGN_PASSWORD }}
          IMAGE_REF: ${{ inputs.image-name }}
          DIGEST: ${{ steps.push.outputs.digest }}
        run: |
          cosign attest --yes --key env://COSIGN_KEY \
            --type vuln --predicate trivy-vuln.json "${IMAGE_REF}@${DIGEST}"
          cosign attest --yes --key env://COSIGN_KEY \
            --type spdxjson --predicate sbom.spdx.json "${IMAGE_REF}@${DIGEST}"
```

### Why this shape

- **`--type vuln` + trivy `cosign-vuln`** is the format cosign expects for a vuln
  attestation; **`--type spdxjson` + trivy `spdx-json`** for the SBOM. They pair 1:1.
- Reuses `aquasecurity/trivy-action@v0.35.0` (already pinned in this file) and the
  cosign already installed by `Install cosign` — **no new tool versions** (A08).
- Scans the **pushed digest** (`inputs.image-name@steps.push.outputs.digest`), the
  exact artifact that was signed; registry auth comes from the `Login to ghcr.io`
  step's docker config already on the runner.
- `exit-code: '0'` on both trivy steps: CVE *findings* must not fail predicate
  generation. A genuine trivy failure still surfaces (no `continue-on-error`).
- Same `if: env.COSIGN_KEY != ''` guard as sign: when the key secret is absent
  (forks, key-less callers) the whole attest path no-ops, exactly like signing.
- Key never on argv: `env://COSIGN_KEY` + `COSIGN_PASSWORD` env — unchanged from sign.
