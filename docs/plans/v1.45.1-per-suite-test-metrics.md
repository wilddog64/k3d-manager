# v1.45.1 — Per-suite offline test metrics and parent-run correlation

**Status:** PROPOSED — specification only; not dispatched
**Requested:** 2026-10-14, operator
**Milestone:** v1.45.1 — fifth and final planned slot
**Implementation branch:** `k3d-manager-v1.45.1` after v1.45.0 merges
**Priority:** P3 enhancement, not a confirmed defect
**Depends on:** Existing `bin/k3dm-test-metrics`, Test Execution Grafana dashboard and current `make test-all` publisher.

## Problem and observed contract

On the v1.43.2 Makefile, `make test` runs the dispatcher BATS suites; `make test-bin` runs the additional BATS suites under `scripts/tests/bin`; `make test-python-unit` executes standalone Python scripts; `make test-pytest` runs pytest from `scripts/tests/hermes` and `scripts/tests/bin/test_*.py`. `make test-python` is an aggregate dependency target for Python unit and pytest. Only `make test-all` explicitly captures full output and invokes `bin/k3dm-test-metrics` with target `test-all`. Therefore independent test target runs by developers or agents do not publish first-class suite-level results.

## Requirements

1. **Preserve targets and semantics.** Keep existing CLI and test discovery behavior unchanged. Add non-invasive capture/publication for independently invoked leaf targets: `test`, `test-bin`, `test-python-unit`, and `test-pytest`. `test-python` and `test-all` remain aggregates, not additional independent copies of constituent tests.
2. **Parent/child correlation.** Assign a stable run ID to each top-level Make invocation; propagate a `parent_run_id` and leaf `suite_id` for invocations within `test-python` or `test-all`. Use an existing common environment variable where available, otherwise document a bounded new one. Correlate without inflating total test counts. IDs should not become high-cardinality Prometheus labels.
3. **Metrics.** Capture start/completion UTC times, elapsed wall time, target, machine/runner, pass/fail/skip counts *when reliably parsed*, overall exit code and run classification. Report unavailable counts as unknown/N/A; do not count a zero-test run as a pass. Preserve parser-specific BATS, unittest, pytest conventions and add guard tests against misleading or vacuous output.
4. **Publication.** Reuse existing `bin/k3dm-test-metrics` and Pushgateway/exporter interfaces, extending their event schema compatibly. Report publication errors without masking the original test exit code. Do not make tests succeed when they fail. A single `test-all` run should publish one parent summary plus linked leaf results; no duplicate tests in the aggregate.
5. **Nested target behavior.** `test-python` may publish an aggregate summary only if it can be reliably computed from its two leaves; otherwise display the child suites without invented rollup counts. `test-all` remains authoritative for complete offline regression. Respect short-circuit behavior when a child fails and mark unexecuted children as `not_run`, not passing.
6. **Historical comparability.** Existing `test-all` metrics and dashboards continue to display accurately. Historical records lacking parent IDs/leaf details remain readable and are not retroactively attributed.
7. **Grafana.** Extend the existing Test Execution dashboard with a run-group/parent selector, per-suite latest status, duration trends, counts, failure reason if available, and a table identifying independent versus nested executions. Ensure visual totals distinguish leaf counts from aggregate test-all counts; preserve existing panels and sensible retention. Show data-freshness and no-data distinctly from zero failures.
8. **Privacy and operational safety.** Sanitize console output and metric labels, avoid secrets, file paths/user data in metric labels, bound retained logs and series cardinality. No new database or periodic LLM invocation; deterministic collection only.

## Acceptance tests

- [ ] Standalone `make test`, `make test-bin`, `make test-python-unit` and `make test-pytest` each produce independent correctly attributed metrics (when run) while preserving exact execution exit codes.
- [ ] `make test-python` groups both Python suites under one parent; leaf test counts are not counted twice.
- [ ] `make test-all` emits one authoritative parent and correctly linked child records; the displayed total agrees with the actual executed test count, without counting nested summaries again.
- [ ] When a leaf fails and subsequent suites are skipped, skipped execution is recorded as `not_run` while the parent fails.
- [ ] Parsing failures, zero collected tests, missing tools, publisher downtime and interrupted runs are not reported as successful green tests; metrics failures do not override a real test failure.
- [ ] Repeated publication retries do not duplicate runs/counts.
- [ ] Existing test-all-only historical records remain visible and correct.
- [ ] Mocked stdout fixtures verify BATS, unittest, pytest and mixed-suite parsing; offline tests cover failures, skips, missing values, and all ancestry cases.
- [ ] Dashboard render/PromQL checks and one controlled live suite execution prove separate suite results appear and totals are not inflated.
- [ ] Updated help and docs clearly distinguish `test-pytest` (pytest only) from `test-python` (unittest-style + pytest).
