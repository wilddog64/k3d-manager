## Part 1 — ArgoCD admin credential rotator (in-cluster CronJob)

### Discovery (live-confirmed 2026-08-10)

- Auth secret: `argocd-secret` in `cicd`, `admin.password` = bcrypt (`$2y$10$…`), `admin.passwordMtime` RFC3339.
  **This is what argocd-server authenticates against** — the rotator's authoritative target.
- Plaintext/ESO display secret `argocd-admin-secret` (`externalsecret-admin.yaml.tmpl`, Vault
  `secret/argocd/admin` key `password`) is **NOT currently deployed on the hub** → the rotator updates
  Vault + force-syncs that ESO **best-effort/guarded**, but success does not depend on it.
- Image `quay.io/argoproj/argocd:v3.4.5` ships `argocd account bcrypt`, which **reads the password from
  stdin** (`echo pw | argocd account bcrypt`). So the bcrypt step needs **no secret in `argv`** — reuse
  ArgoCD's own hasher (decision 2b), no new deps.
- Vars: `ARGOCD_NAMESPACE=cicd`, `ARGOCD_VAULT_KV_MOUNT=secret`, `ARGOCD_ADMIN_VAULT_PATH=argocd/admin`,
  `ARGOCD_ADMIN_PASSWORD_KEY=password`, `ARGOCD_ADMIN_SECRET_NAME=argocd-admin-secret`.

### The application step (the ArgoCD-specific part)

Unlike Grafana (`grafana cli … reset-admin-password`), there is **no repo precedent** for setting
`argocd-secret` bcrypt. Mechanism:

```sh
# capture current auth state FIRST so restore is exact (Vault plaintext may be absent)
old_bcrypt="$(kubectl -n cicd get secret argocd-secret -o jsonpath='{.data.admin\.password}' | base64 -d)"
old_mtime="$(kubectl -n cicd get secret argocd-secret -o jsonpath='{.data.admin\.passwordMtime}' | base64 -d || true)"
new="$(head -c 24 /dev/urandom | od -An -tx1 | tr -d ' \n')"
# reuse argocd's own bcrypt via stdin — no secret in the kubectl exec command string
new_bcrypt="$(printf '%s' "$new" | kubectl exec -i -n cicd deploy/argocd-server -- argocd account bcrypt)"
mtime="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
kubectl -n cicd patch secret argocd-secret --type merge \
  -p "$(jq -nc --arg p "$new_bcrypt" --arg m "$mtime" '{stringData:{"admin.password":$p,"admin.passwordMtime":$m}}')"
```

Restore-on-failure re-patches `argocd-secret` back to `old_bcrypt`/`old_mtime` (exact prior state),
writes the old plaintext back to Vault, and force-syncs the ESO if present.

### Rotator manifest — `scripts/etc/argocd/platform-ops/argocd-credential-rotator.yaml` (new)

Mirror `grafana-credential-rotator.yaml` (same securityContext, schedule `0 0 1 * *`, `Forbid`,
`alpine/k8s:1.31.4`, TTL, notifier ClusterRole for `platform-ops-notifications`). Differences:

- **Namespace `cicd`** (co-located with argocd-server + `argocd-secret`).
- **Role (cicd)** — least privilege:
  ```yaml
  rules:
    - apiGroups: [""]
      resources: ["secrets"]
      resourceNames: ["argocd-secret"]
      verbs: ["get", "patch"]
    - apiGroups: ["external-secrets.io"]
      resources: ["externalsecrets"]
      resourceNames: ["argocd-admin-secret"]
      verbs: ["get", "patch"]         # best-effort; guarded (ESO may be absent)
    - apiGroups: [""]
      resources: ["pods"]
      verbs: ["get", "list"]
    - apiGroups: [""]
      resources: ["pods/exec"]
      verbs: ["create"]               # exec argocd account bcrypt
    - apiGroups: ["apps"]
      resources: ["deployments"]
      resourceNames: ["argocd-server"]
      verbs: ["get"]
  ```
- **CronJob args** — Grafana skeleton (Vault k8s login role `argocd-rotation`, `trap restore EXIT`,
  Slack value-free notify) with the ArgoCD application step above. Guard the ESO force-sync:
  `kubectl -n cicd get externalsecret argocd-admin-secret >/dev/null 2>&1 && kubectl -n cicd annotate externalsecret argocd-admin-secret force-sync="$(date +%s)" --overwrite || true`.

### Vault role — reuse `_vault_configure_secret_writer_role`

```bash
_vault_configure_secret_writer_role "secrets" "vault" \
  "argocd-credential-rotator" "cicd" "secret" "argocd/admin" \
  "argocd-rotation" "argocd-rotation"
```
(create/read/update on `secret/data/argocd/admin` only; k8s-auth role bound to SA
`argocd-credential-rotator`/`cicd`.)

### Apply function — `scripts/plugins/argocd.sh`

Add `_argocd_apply_credential_rotator` mirroring `_observability_apply_grafana_rotator`
(apply the manifest, then call `_vault_configure_secret_writer_role` as above), and invoke it from
`deploy_argocd_platform_ops` next to the other secret-sync calls.

### Tests — `scripts/tests/lib/argocd.bats`

Structural check mirroring any Grafana-rotator test: manifest parses; SA/Role/RoleBinding/CronJob present;
Role is namespaced to `cicd` and scoped to `argocd-secret` (no `cluster-admin`, no wildcard verbs);

## Part 2 — Prometheus basic-auth recurring rotation (host-side monthly timer)

**Why host-side, not a CronJob:** hub Prometheus enforces no basic-auth; the only consumer is the ACG
sandbox path, which runs **on the laptop** where `htpasswd` exists. The `alpine/k8s` rotator image has
no `htpasswd`/`openssl`/bcrypt module, so an in-cluster CronJob cannot generate the bcrypt. Reuse the
bugfix generator on the host.

### Change 1 — `observability.sh`: `observability_rotate_prometheus_basic_auth`

A public function that force-regenerates the credential (ignores the existing Vault value), writes it to
Vault, re-applies the ACG web-config secret, and Slack-notifies (value-free). Reuses
`_observability_generate_prometheus_basic_auth` from the bugfix and the existing
`_observability_prometheus_vault_payload` + `_prometheus_acg_web_config_secret` apply path.

### Change 2 — `scripts/etc/launchd/com.k3d-manager.prometheus-credential-rotator.plist.tmpl` (new)

A `StartCalendarInterval` monthly agent (`Day=1 Hour=0`) that runs
`k3d-manager observability_rotate_prometheus_basic_auth`, mirroring the existing
`com.k3d-manager.alertmanager-port-forward.plist.tmpl` templating (`{{KUBECTL_PATH}}`/`{{HOME}}`).
Install via an `_observability_install_prometheus_rotator` function guarded by `_is_mac` +
`command -v launchctl`, mirroring `_observability_install_alertmanager_port_forward`.

### Tests — `observability.bats`

`observability_rotate_prometheus_basic_auth` is defined and public (no leading `_`); the plist template
exists and references the rotate entrypoint; no plaintext password in the plist.

## Rules

- Least privilege: ArgoCD rotator Role namespaced to `cicd`, `resourceNames` pinned; Vault policy scoped
  to `secret/data/argocd/admin` only. No `cluster-admin`, no wildcard verbs (CLAUDE.md OWASP A01).
- Pin `alpine/k8s:1.31.4`; `runAsNonRoot`/`runAsUser: 65534`; `concurrencyPolicy: Forbid`;
  `ttlSecondsAfterFinished`.
- No plaintext credential in Slack messages (value-free notify).
- No secret in any `kubectl exec` command string — ArgoCD bcrypt is fed via stdin; Prometheus bcrypt via
  `htpasswd -i` (stdin). (CLAUDE.md OWASP A02.)
- `shellcheck -S warning` clean on `argocd.sh`/`observability.sh`; `bats` green.
- Do NOT re-implement the Grafana rotator (shipped v1.23.0). Do NOT rotate Alertmanager here.

## Follow-up note — Grafana Vault `user` key gap (NOT in this batch)

**Not part of the ArgoCD/Prometheus commit above — do not touch `grafana-credential-rotator.yaml`
in this batch.** Recorded here so the decision is not lost.

Live discovery 2026-08-10: Vault `secret/observability/grafana` stores only `password` — the `user`
key is **empty**. The password matches the live `grafana-admin-credentials` secret exactly (verified
by SHA-256), so Grafana login is unaffected (username is always `admin`), but Vault is not a
*self-describing* credential record. Root cause: the Grafana rotator (`grafana-credential-rotator.yaml`,
shipped v1.23.0) writes only `password` back to `secret/data/observability/grafana`; nothing seeds
`user`.

**When addressed** (a later focused pass, or the next time the Grafana rotator YAML is edited): have
the rotator's Vault `PUT` payload also carry `"user":"admin"` so `secret/observability/grafana` holds
the full pair. Mirror the same completeness for the new ArgoCD/Prometheus Vault payloads if they omit
`user`. No live impact today — this is hygiene, not an outage fix.
