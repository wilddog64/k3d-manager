## Behaviour

### 1. `docs/howto/tailscale/policy.hujson`

Exactly the JSON in the parent's § The policy, byte for byte apart from indentation (2-space, keys in the order shown,
trailing newline). Plain JSON (valid HuJSON, no comments).

### 2. `scripts/tests/bin/test_tailscale_policy.py`

- Locate the file as `Path(__file__).resolve().parents[3] / "docs/howto/tailscale/policy.hujson"` and assert it exists
  before anything else.
- A function `validate(policy: dict) -> list[str]` returns the list of violations (empty = valid). It checks:
  1. top-level keys are exactly `{"groups", "tagOwners", "grants", "tests"}`;
  2. `groups == {"group:operator": ["operator@example.com"]}`;
  3. `tagOwners == {"tag:k3dm-mac": ["group:operator"]}`;
  4. `grants`, compared order-insensitively, equal the two literal grants; each grant's keys are exactly
     `{"src", "dst", "ip"}`;
  5. `tests` equal the three literal test entries (order-insensitive), so every accept and deny, including `proto`,
     is present;
  6. no string anywhere in the policy contains `*`, `autogroup:`, `/` (CIDR), `tskey-`, `.ts.net`, or matches
     `100\.\d+\.\d+\.\d+`, and the only string containing `@` is `operator@example.com`.
- `test_shipped_policy_is_valid`: `validate(load())` is empty (the positive control).
- One test per red fixture, each a deep copy of the shipped policy with one change, asserting `validate()` is non-empty:
  `dst ["*"]`; `ip ["tcp:*"]`; a third port `tcp:443` on grant 1; `tcp:5900` added to the Mac↔Mac grant; a third grant
  `tag:k3dm-mac → group:operator tcp:22`; grant 1 `src ["group:operator", "tag:k3dm-mac"]`; an `app` key on grant 1;
  a CIDR source `["100.64.0.0/10"]`; `tagOwners` gaining `autogroup:member`; a second member in `group:operator`; a
  real-looking login `someone@gmail.com` replacing the placeholder; top-level `ssh`, `acls`, `autoApprovers` and
  `nodeAttrs` keys (one fixture each); a test entry with its `deny` list removed; a test entry without `proto`.
