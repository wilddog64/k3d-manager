# v1.45.0 — Alert intake: a long-firing or recurring alert drafts a bug doc for operator approval

**Filed:** 2026-10-09, Claude
**Branch:** `k3d-manager-v1.45.0` (do not start until that branch exists; never `main`)
**Status:** QUEUED for v1.45.0. Dispatch to Codex when the branch opens.
**Origin:** operator, 2026-10-09, from the Aithon comparison: automate "issues → intake → specs" but
keep the human approval boundary. The companion spec is `v1.43.0-worktree-isolated-codex-dispatch.md` (moved forward to v1.43.0).
**Implementer:** Codex · **Verifier:** Claude · **Restart after landing:** operator runs
`make restart-webhook`

## Problem

Most of the loop already exists, but its last step is manual.
- Alertmanager posts every firing alert to `/api/v1/analyze` (AlertmanagerConfig `k3dm-analyze`).
- `_run_analyze` in `bin/k3dm-webhook` gathers `kubectl` diagnostics, asks the model for a diagnosis
  and posts it to Slack.
- After that, nothing is kept. The diagnosis scrolls away in Slack. Whether a bug doc gets written
  depends on the operator noticing and Claude being in session.

Two recent examples:
- istio-cni was stuck `Progressing` for six days before anyone filed it.
- The `appsets-reapply` false failure on 2026-10-09 was filed only because the operator pasted the
  output.

## Approach

When an alert has fired long enough, or keeps coming back, the webhook writes a **draft** bug doc
**outside the repo**. The draft holds:
- the alert evidence;
- redacted diagnostics;
- the model's diagnosis, labelled as unverified;
- the top prior-art matches from `find-similar-docs`;
- the result of the exact-slug dedup check.

The webhook then posts one Slack line. Only `make intake-promote` copies a draft into `docs/bugs/`.
That command is the operator's approval, and it never runs git.

```
Alertmanager → /api/v1/analyze → diagnostics + model diagnosis → Slack (unchanged)
                                   └─ eligible? → ~/.local/share/k3d-manager/intake/drafts/<id>.md
                                                  + one Slack line
operator: make intake-show ID=… → make intake-promote ID=… → docs/bugs/<date>-<slug>.md (untracked)
          → Claude reviews, sets priority, commits → spec / Codex as usual
```

Drafts never land in the working tree on their own. Codex, test suites and the operator all work
from that tree, so an unattended writer there would recreate the collision problem the companion
spec removes.

## Items

### 1. `scripts/lib/webhook/intake.py` (new, pure, no module-level side effects)

Every function takes its collaborators as arguments: `redact`, `now`, `prior_art`, `intake_dir`.
There is **no module-global redactor with an identity default**. CodeQL flagged exactly that pattern
in `status.py` (#31 and #32, dismissed 2026-10-09). Here the redactor is a required parameter.

- `eligible(alert, ledger, now, min_firing_minutes, repeat_episodes) -> (bool, reason)`
  - Never eligible:
    - `status != "firing"`;
    - label `tier == "upstream"`;
    - a `remediation` label (the CVE loop owns these);
    - `alertname` in `{"Watchdog", "InfoInhibitor"}`;
    - `severity` in `{"none", "info"}`.
  - Eligible when **either** of these holds:
    - `now - startsAt >= min_firing_minutes` (default 30); or
    - the ledger holds `>= repeat_episodes` distinct `startsAt` values (default 3) for this
      fingerprint in the last 7 days, counting the current one.
  - The fingerprint is the alert's `fingerprint` field. If that is missing, use the sha256 of its
    sorted labels.
- `record(alert, ledger, now)`: adds this `startsAt` to the fingerprint's episodes and prunes
  episodes older than 7 days.
- `draft(alert, diagnostics, diagnosis, *, redact, prior_art, now, intake_dir, repo_root) -> draft_id | None`
  - There is **one draft per fingerprint per episode**.
  - When the ledger already maps this episode to a draft, append `- seen again <UTC ISO>` to that
    draft and return `None`.
  - Otherwise write `drafts/<YYYY-MM-DD>-<slug>.md`. `slug` is the kebab case of
    `alertname-display_name`, at most 60 characters.
  - The draft follows the `docs/bugs/` header shape:
    - Title.
    - `**Filed:**`.
    - `**Status:** DRAFT — intake <id>, not filed`.
    - `**Priority:** TBD (operator)`.
    - `## Symptom`: alertname, labels, `startsAt`, and the summary and description annotations.
    - `## Diagnostics`: capped at 4000 characters.
    - `## Model diagnosis (unverified)`.
    - `## Prior art (advisory)`: the top 3 lines from `prior_art`, or `prior-art search unavailable`.
    - `## Dedup pass 1`: the existing `docs/bugs/*-<slug>.md` path, or `none`.
  - **Every** string written (diagnostics, diagnosis, annotations and labels) passes through
    `redact` first.
  - Directories are created with mode 0700, and files with mode 0600. Every write goes to a
    temporary file first, then `os.replace`. That covers the ledger (`ledger.json`) as well as drafts.
- `default_prior_art(query, repo_root)`
  - Runs `python3 scripts/find-similar-docs.py --k 3 -- <query>` with `cwd=repo_root` and
    `timeout=30`.
  - Returns its stdout lines. Any error or timeout returns `[]`, so it never blocks.

### 2. `bin/k3dm-webhook`: call intake from `_run_analyze`

- After the per-alert `analysis = _call_gemini(prompt)` and the existing Slack post, call a small
  `_intake_alert(alert, diagnostics, analysis, display_name)`. The call is wrapped in
  `try/except Exception` and logs `intake skipped: <exc>`. Intake must never fail the analyze job or
  change its Slack message.
  - It loads the ledger, runs `record` and `eligible`, and on eligible calls `draft` with
    `redact=_redact_secrets` (the real one in this file), `repo_root` (the same `Path(__file__)`
    derivation as `_publish_test_metrics`), and `intake_dir`.
  - On a new draft it posts `📝 intake draft <id>: <alertname> \`<display_name>\` → make intake-show ID=<id>`
    to the same `notify_url`.
- Also call it on the `No diagnostics gathered` path, with `diagnostics=""` and `analysis=""`. A
  stuck alert with nothing to describe is still worth a draft.
- `intake_dir = Path(os.environ.get("K3DM_INTAKE_DIR", Path.home() / ".local/share/k3d-manager/intake"))`.
  `K3DM_INTAKE_MIN_FIRING_MINUTES` and `K3DM_INTAKE_REPEAT_EPISODES` are integers that fall back to
  30 and 3 when invalid.
  `K3DM_INTAKE_DISABLED=1` turns intake off.

### 3. `bin/k3dm-intake` (new, Python CLI)

- `list` prints id, status (`draft`, `promoted` or `discarded`), alertname, first seen and
  last seen.
- `show <id>` prints the draft.
- `promote <id> [--slug <slug>] [--append-recurrence]`
  - Runs dedup pass 1 against `docs/bugs/*-<slug>.md`.
  - When it matches, it refuses with exit 2, prints the existing path, and suggests
    `--append-recurrence`. That flag appends `## Recurrence (<date>, intake <id>)` with the Symptom
    and Diagnostics sections to the existing doc.
  - Otherwise it writes `docs/bugs/<YYYY-MM-DD>-<slug>.md` with
    `**Status:** OPEN — promoted from intake <id>`. Priority stays TBD.
  - Then it prints `make find-similar-docs Q="…"` as the pass-2 reminder, and marks the draft
    promoted in the ledger.
  - **It never runs git.**
- `discard <id>` marks the draft discarded. The file is kept.
- The repo root comes from `K3DM_REPO_ROOT`, defaulting to `Path(__file__).resolve().parents[1]`.

### 5. Tests

**`scripts/tests/bin/test_webhook_intake.py`** (new; the webhook package's tests live in
`scripts/tests/bin/`, beside `test_redact.py`). Cover:
1. Eligibility exclusions: upstream, remediation, Watchdog, info, and resolved alerts.
2. The 29-minute vs 30-minute boundary.

5. A redactor that maps `SECRET` to `[R]`: the `SECRET` planted in the diagnostics, diagnosis and an

  - `scripts/lib/webhook/status.py`, for the `configure_runtime` injection pattern you are **not**

## What NOT to Do

- Do NOT write drafts, or anything else, into the repo tree from the webhook. Only `bin/k3dm-intake
  promote` writes to `docs/bugs/`, and only when the operator runs it.
- Do NOT run `git` from either the webhook or `bin/k3dm-intake`.
- Do NOT dispatch Codex, write specs or file GitHub issues from intake.
- Do NOT change the existing analyze Slack message, the Alertmanager routes or the AlertmanagerConfig.
- Do NOT add a module-global redactor with an identity default.
- Do NOT read, print or log Secret values, the Slack webhook URL or the webhook token.
- Do NOT create a PR or merge. Do NOT use `--no-verify`. Do NOT modify files outside the table.
