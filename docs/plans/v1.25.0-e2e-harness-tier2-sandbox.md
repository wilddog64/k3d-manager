## The cleanup invariant (why this design exists)

Hub-orphan risk comes entirely from `register_app_cluster` writing `cluster-ubuntu-k3s` into the hub and
its ApplicationSets generating Applications onto the sandbox. **Registration is opt-in** — `deploy_app_cluster`
does NOT auto-register (it only prints "Then run: register_app_cluster", shopping_cart.sh:1119). Therefore:

> **INVARIANT: `e2e_verify_sandbox` MUST NOT call `register_app_cluster`.** The sandbox stays a self-contained
> island; the hub never learns it exists; TTL expiry orphans nothing.

The `v1.25.0-bugfix-k3s-aws-hub-deregister` change is the safety net for the case where a human *did* register
manually — it is not required by this harness path.

## Design — `e2e_verify_sandbox` (public, `scripts/plugins/e2e.sh`)

Assumes an ACG sandbox is up (or brings it up via `CLUSTER_PROVIDER=k3s-aws deploy_cluster`). All work targets
the sandbox `ubuntu-k3s` kube context; the hub is never touched.

1. **Pre-flight:** extend sandbox TTL (`acg_extend_playwright`) so the run isn't killed mid-flight; verify
   `kubectl --context ubuntu-k3s get nodes` Ready. Dead `ubuntu-*` contexts are normal
   (`reference_acg_sandbox_lifetime`).
2. **Full stack in-sandbox** (real topology): Istio ambient ingress, Vault, ESO, Keycloak (real OIDC),
   shopping-cart services + datastores + seed. `OAUTH2_ENABLED=true`.
3. **Deploy mechanism** — see **D1**. Whichever is chosen, it is **local to the sandbox**; no hub ArgoCD.
4. **Stripe live E2E:** run the authenticated checkout flow against **real ingress + real Keycloak** with
   Stripe **test** keys resolved from Vault / Keychain backup (`reference_stripe_sk_keychain_backup`), never
   in argv/logs (A02). Handle the OIDC issuer-mismatch trap by **fetching the JWT in-cluster** so the issuer
   matches (`reference_local_go_and_oauth_testing`).
5. **Report:** emit the **same flat JSON summary** as Tier 1 (`tier:"sandbox"`, `project:"stripe"`) to
   `$E2E_REPORT_DIR/<run_id>.json` and ship raw logs to `$E2E_REPORT_DIR/<run_id>.log` (Path B). Exit code
   faithful. This is what moves the G acceptance from 2/4 toward 4/4.
6. **Do NOT tear down the sandbox** — it self-expires (4h + 4h). Tier 2 is best-effort / opt-in / periodic,
   **never a blocking per-candidate gate** (browser-automation credential fragility + short lifetime).

## Deploy architecture (resolved 2026-08-14)

Grounding of the actual bring-up surface (argocd.sh / shopping_cart.sh / vault.sh / keycloak.sh / the
appsets). The **architecture is locked**; three deploy-orchestration paths are still undesigned and are

### Reusable building blocks (exist today)
- `deploy_app_cluster --confirm` (shopping_cart.sh:1109) — installs k3s on the sandbox via k3sup + merges
  the `ubuntu-k3s` kubecontext. **Only provisions the cluster — does NOT deploy the app stack.**

  kubecontext (the `_into_context` portability pattern; ties to `project_app_cluster_vault_auth_portability`).

- ApplicationSets (`scripts/etc/argocd/applicationsets/{istio-ambient,eso,data-git,services-git}.yaml`) —
  the stack, keyed on `k3d-manager/role: app-cluster` clusters / `destination.name|.server`.
- Keycloak realm/user helpers (`keycloak_seed_smoke_user`, `_keycloak_reconcile_realm_client`, …) — seed

- Tier 1's e2e image (`ghcr.io/wilddog64/shopping-cart-e2e-tests`) + `_e2e_write_summary` JSON contract —
  **Tier 2 creates the shared `scripts/plugins/e2e.sh` scaffolding (`E2E_REPORT_DIR`, `_e2e_write_summary`)
  carved so Tier 1 later drops `e2e_verify_vcluster` into the same file without collision.**

### Intended sequence (`e2e_verify_sandbox`) — 2B (shared hub identity)
1. `acg_extend_playwright` pre-flight; assert `kubectl --context ubuntu-k3s get nodes` Ready.
2. Install a **disposable ArgoCD inside the sandbox** (context `ubuntu-k3s`, ns `argocd`); label its
   `in-cluster` secret `k3d-manager/role: app-cluster`.  **[GAP 1 — CLOSED, exact command below]**
3. Stand up the **Vault bridge** to the hub Vault and create the sandbox's Vault k8s-auth mount with
   **TokenReview** (not local-CA) so ESO in the sandbox can read hub secrets.  **[recipe below]**
4. Apply the four appsets into the in-sandbox ArgoCD (substitute `${K3D_MANAGER_BRANCH}`/`${ARGOCD_NAMESPACE}`

5. **Identity (2B):** reach **hub Keycloak** from the sandbox via the existing ssh-reverse-tunnel + iptables

6. Expose the frontend ingress reachably for the e2e Job (Istio gateway → NodePort/tunnel).  **[GAP 3 — open]**

8. `_e2e_write_summary` (`tier:"sandbox"`, `project:"stripe"`) → `$E2E_REPORT_DIR`; faithful exit code.

## Proven 2B recipe (live, 2026-08-14/15)

On a live app-role ACG sandbox, in-sandbox ArgoCD + the four appsets delivered the **full shopping-cart
stack**: all 7 databases (postgres orders/payment/products, redis cart/orders, rabbitmq, minio) Running and
**7/8 apps Healthy** (basket, frontend, order, product-catalog, namespace, eso, data-layer). Only **payment**
lagged, and the Stripe E2E was not reached before TTL. The durable wiring that made it work:

- **Substrate provisioning:** SSH/k3sup, **NOT SSM.** Codex's SSM-agent bug means the agent never registers
  on ACG (`InstanceInformationList` empty, `docs/bugs/2026-08-14-k3s-aws-ssm-agent-cannot-register.md`), so
  provision the k3s app cluster over SSH (`K3S_AWS_SSM_ENABLED=false`, invoke `deploy_app_cluster --confirm`
  through a lib-sourcing wrapper). Dead `ubuntu-*` contexts are normal (`reference_acg_sandbox_lifetime`).
- **ArgoCD namespace/name wiring (load-bearing):**
  - ArgoCD ns = **`argocd`** (`ARGOCD_NAMESPACE=argocd`).
  - The local app-cluster secret **MUST be named `ubuntu-k3s`** — the AppProjects whitelist destinations by
    cluster **name**, so a mismatched name silently yields zero synced apps.
- **Secrets path (vault bridge, hub Vault):**
  `vault-bridge` Service+Endpoints → node `socat:8201` → node `:8200` → `ssh -R` → laptop `:18200` → hub Vault.
  The sandbox Vault mount **`kubernetes-ubuntu-k3s` MUST use TokenReview**
  (`disable_local_ca_jwt=true` + `token_reviewer_jwt`), **NOT** local-CA JWT validation — local-CA fails for a
  remote k3s cluster. This is the ⭐ auth-portability seam; full detail in
  `project_app_cluster_vault_auth_portability`.
- **Known payment gap (fix before/with the Stripe run):** payment stalled on a namespace pull-secret
  propagation detail — a manual ghcr secret copy got **pruned by `services-git` (`prune: true`)**. Durable fix
  = a **git/ESO-owned ghcr `ExternalSecret` in `shopping-cart-payment`** so the pull secret is reconciled, not
  hand-copied. Without this, payment stays not-Healthy and the Stripe checkout can't complete.
- **Still required for the Stripe E2E (the fresh-sandbox run):** hub-Keycloak identity reach from the sandbox
  (DNAT/CoreDNS/ssh-R + Cloudflare issuer, per D6/2B) + GAP 3 ingress exposure, then the Playwright run.
  → **RESOLVED 2026-08-15, simpler than designed:** see codification below.

## Implementation — `e2e_verify_sandbox` (codified from the live run, 2026-08-15)

The fresh-sandbox run drove the full path end-to-end (add-to-cart → authenticated order, amount
$39.98, cart consistency correct → payment attempted at the **live Stripe API**). Everything the run
did by hand is codified here so Codex can write `scripts/plugins/e2e.sh::e2e_verify_sandbox` verbatim.

### Identity is simpler than D6 assumed — no tunnel/DNAT for OIDC
GAP 2/3 collapsed: hub Keycloak is already public at `keycloak.3ai-talk.org` (returns 200), so sandbox
services validate JWTs against the **public issuer over ordinary internet egress**. There is **no** need
for ssh-reverse-tunnel + iptables DNAT + CoreDNS rewrite for identity. Get a JWT via password grant
(client `order-service`, secret from Vault `secret/keycloak/clients` key `order_service_client_secret`;
user `developer`, pw from `secret/keycloak/users/developer`), and point every service's OIDC config at
the public issuer. The tunnel/DNAT machinery stays **only** for the Vault bridge (secrets), not identity.

### Substrate config overrides the harness MUST apply (do NOT change the app-repo defaults)
These five defaults are **correct for the production hub** (Istio ambient localhost/waypoint routing +
hub-internal Keycloak DNS) and break **only** on a self-contained non-Istio Cilium sandbox. The harness
overrides them at deploy time (kustomize patch / ConfigMap env) — the app repos stay untouched:

| # | Service | Default (production-correct) | Sandbox override the harness applies |
|---|---------|------------------------------|--------------------------------------|
| a | order | `BASKET_URL`/`PAYMENT_URL` = `http://localhost:8083`/`:8084` (ambient localhost) | in-cluster svc DNS: `http://basket-service.shopping-cart-apps:8083`, `http://payment-service.shopping-cart-payment:8084` |
| d | payment | `payment.gateway.default=mock`, `mock.gateway.enabled=true` | `stripe` + `mock.gateway.enabled=false` (mock declines Stripe test cards) |
| e | payment | `oauth2.jwk-set-uri=http://keycloak.identity.svc.cluster.local/.../certs` (unresolvable in sandbox) | **public** `https://keycloak.3ai-talk.org/realms/shopping-cart/protocol/openid-connect/certs` — this was the 401→403 fix |

Note the payment ConfigMap already sets `oauth2.issuer-uri` to the **public** host while
`oauth2.jwk-set-uri` is the **in-cluster** host — an inconsistency the harness papers over for the sandbox.
Flag to the payment owner (out of scope here): prefer letting `issuer-uri` auto-discover the JWK URI, or
set both to the public host, so the two never diverge.

### Namespace-label precondition — fixed at source, not by the harness
Items (b)/(c) from the live cascade (data ns needs `component=data`; apps ns needs
`component=application`+`name=shopping-cart`, or payment NetworkPolicies deny all traffic under Cilium) are
**substrate-independent bugs**, fixed in k3d-manager by
`docs/bugs/2026-08-15-namespace-labels-missing-for-payment-netpol.md` (namespace app + `data-git`
`managedNamespaceMetadata`). `e2e_verify_sandbox` **depends on** that fix landing first; it does not
re-label namespaces imperatively (imperative labels get pruned by `services-git prune:true`).

### e2e Job wiring (GAP 3 answer)
The in-cluster Playwright Job reaches services by **ClusterIP DNS** (`--project=flows --no-deps
tests/flows/stripe-checkout-orchestrator.spec.ts`; `flows` depends on `api`, so `--no-deps` isolates it).
Env: `OAUTH2_ENABLED=true`, `STRIPE_E2E=true`, `KEYCLOAK_URL=`public issuer. Service ports are
**non-obvious** — order `8081` (not 8080), product-catalog `8082` (not 8000), basket `8083`, payment
`8084`. Stripe `sk_test` key resolved from Vault (restored from Keychain `k3dm-stripe-sk-test`,
`reference_stripe_sk_keychain_backup`), delivered via env/stdin — never in argv or logs (A02).

### Codified sequence
1. Pre-flight: `acg_extend_playwright`; assert `kubectl --context ubuntu-k3s get nodes` Ready.
2. In-sandbox ArgoCD (GAP 1 command block above); label `in-cluster` secret `k3d-manager/role=app-cluster`;
   name the local cluster secret **`ubuntu-k3s`** (AppProjects whitelist by name).
3. Vault bridge + `kubernetes-ubuntu-k3s` mount with **TokenReview** (recipe above); ClusterSecretStore
   `vault-backend` Ready → ExternalSecrets SecretSynced (incl. `ghcr-pull-secret`).
4. Apply the four appsets; **apply the three substrate overrides (a)/(d)/(e)** as a kustomize patch layer
   or post-sync ConfigMap edit + rollout; wait Synced/Healthy (expect 8/8 with the label fix in place).
   **INVARIANT: never `register_app_cluster` (D2).**
5. Mint a JWT via password grant against the **public** issuer; run the Playwright `flows` Job with the env
   above; Stripe test key from Vault/Keychain.
6. `_e2e_write_summary` (`tier:"sandbox"`, `project:"stripe"`) → `$E2E_REPORT_DIR`; faithful exit code.
   **Do NOT tear down** (TTL self-expiry).

### Known app-level boundaries (NOT platform gaps — do not chase in the harness)
- **payment→Stripe 403** on the PaymentIntent/`pm_card_visa` flow: the `sk_test` key is valid
  (`curl api.stripe.com/v1/balance` = 200; Vault == Keychain, pod env matches). Root-caused to the Java
  payment service dropping Keycloak `realm_access`/`resource_access` roles → no `ROLE_*` authorities → 403;
  fix pushed shopping-cart-payment `aeb89e8` on `origin/fix/keycloak-role-authority-mapping`
  (`KeycloakRealmRoleConverter`, 133 tests green). Follow-up after merge: confirm the `shopping-cart` realm
  grants the test principal a `PAYMENT_*` role.
- **e2e X-User-ID keying:** the Playwright orchestrator sends `X-User-ID=TEST_USER_ID` while order resolves
  the cart by JWT `sub` → basket-key mismatch (empty cart). The manual JWT-only path is consistent. This is
  an e2e-suite fix in `shopping-cart-e2e-tests`, not a platform gap.

### BATS contract (structural, no live cloud)
- `register_app_cluster` is **never** invoked on this path (grep the call graph / spy the function).
- `OAUTH2_ENABLED=true` and `STRIPE_E2E=true` are exported before the Job.
- The three substrate overrides resolve to **in-cluster svc DNS** (a), **stripe** (d), and the **public**
  JWK host (e) — assert the rendered patch/ConfigMap, not hard-coded literals in code.
- `_e2e_write_summary` emits `tier:"sandbox"` with a faithful exit code.
- `shellcheck -S warning` clean; `set -euo pipefail`.

## Why Tier 2 (not Tier 1) unblocks G

- G's acceptance criterion is the **Stripe live E2E** passing 4/4 — an **authenticated** checkout flow needing
  real OIDC + ingress. Tier 1's nested vCluster deliberately runs `OAUTH2_ENABLED=false` and cannot reproduce
  Istio ambient mesh, real ingress TLS, or the OIDC issuer. So the Stripe cases can only be validated on Tier 2.
- The order schema blocker (`order_items.total_price NOT NULL`) is already resolved on `main` (`cb58e8b`, #67)
  and the order image promoted (`df35ea8`). What remains is **re-running** the Stripe E2E on a real substrate —
  exactly this harness path.
