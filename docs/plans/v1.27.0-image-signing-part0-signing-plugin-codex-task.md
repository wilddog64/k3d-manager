## Deliverables

### 1. `scripts/plugins/signing.sh`

Header + `set -euo pipefail`. Public (no underscore), private (`_signing_` prefix). Use
`_kubectl` / `_run_command` — never bare `sudo`.

**Public functions:**

- `signing_init` — idempotent Stage-0 key material setup:
  - If Vault `secret/cosign/signing` already holds `cosign.key` → log and return 0 (no-op).
  - Else: `cosign generate-key-pair` (in a trap-guarded `mktemp -d`, cleaned on exit), with a
    **strong generated** `COSIGN_PASSWORD` (never a literal — generate via the repo's existing
    password-gen helper if one exists, else `openssl rand`/`head -c` of `/dev/urandom` base64).
  - Write `cosign.key`, `cosign.password`, `cosign.pub` to Vault `secret/cosign/signing`
    (idempotent `vault kv get` guard before `vault kv put`, mirroring vault.sh).
  - **Back up** `cosign.key` + `cosign.password` to macOS Keychain via `_secret_store_data`
    (accounts `k3dm-cosign-key`, `k3dm-cosign-password`).
  - Apply the ESO ExternalSecret (deliverable 2) and the Vault policy (deliverable 3).
  - **Secret hygiene:** the private key and password must NEVER appear in `argv` or logs — pass
    to cosign via `--key env://COSIGN_KEY` and `COSIGN_PASSWORD` env, and wrap key-bearing
    commands so they are not traced (`_no_trace` if present, as `_secret_store_data` does).
- `signing_rotate_key` — generate a NEW key pair, write to Vault (overwrite), re-backup to
  Keychain, re-apply the ESO pub secret. Emit a clear note that old signatures need dual-key
  overlap or re-sign (per parent plan risk #1). Do NOT delete the old public key automatically.
- `signing_status` — report, without printing secret material: whether Vault holds the key,
  whether the Keychain backup exists, and whether the ESO-projected pub Secret is present.

**Private helpers** as needed, e.g. `_signing_seed_vault_key`, `_signing_apply_pub_externalsecret`,
`_signing_apply_vault_policy`, `_signing_backup_keychain`.

If the plugin adds any CLI flag carrying key/password material, register it in
`_args_have_sensitive_flag` in `scripts/lib/system.sh`.

### 2. ESO ExternalSecret template

New `scripts/etc/signing/externalsecret-cosign-pub.yaml.tmpl` (mirror the grafana-admin one):
projects **`cosign.pub` only** from Vault `secret/cosign/signing` into a Secret (name e.g.
`cosign-public-key`) in the admission-engine namespace (default `kyverno`; parameterize the
namespace via an env/`envsubst` var, do not hardcode if the mirror templates parameterize it).
Only the public key — never the private key or password — is projected.

### 3. Vault policy (least privilege — OWASP A01)

New `scripts/etc/signing/cosign-verify-policy.hcl` (or the repo's existing policy-file convention if
one exists — check `scripts/etc/` first): **read-only** on `secret/data/cosign/signing` ONLY.
No `create`/`update`/`delete`, no other paths. `_signing_apply_vault_policy` writes it via
`_vault_exec`.

### 4. BATS — `scripts/tests/plugins/signing.bats` (STRUCTURAL only)

Mock `cosign`, `vault`/`_vault_exec`, `_kubectl`, `_run_command`, `security`/`_secret_store_data`.
Assert:
- `signing_init` is **idempotent** — when the Vault-get mock reports the key exists, no
  `generate-key-pair` and no `kv put` are issued.
- On a fresh path, it issues `cosign generate-key-pair`, a `vault kv put` to
  `secret/cosign/signing`, a Keychain backup for both accounts, and applies the ESO + policy.
- The private key/password are passed via `env://` / env — assert the built cosign command string
  contains `--key env://COSIGN_KEY` and does NOT contain the raw key/password value.
- The Vault policy grants only `read` (and/or `list`) on `secret/data/cosign/signing` and no
  write verbs — assert against the rendered policy content.
- The ESO template projects `cosign.pub` and NOT `cosign.key`/`cosign.password`.
- `signing_status` returns non-zero / reports "absent" cleanly when mocks report nothing present.
