## Problem

The Per spec table's **Claude ≈** column charges a spec with every Claude message sent between its
first dispatch and its land, split across overlapping specs. That is time overlap: Claude's design
work, discussion and other specs written in that time are charged to it, and the spec's own
writing, before dispatch, is left out. The operator wants what Claude actually spent on each spec.

Claude Code transcripts (`~/.claude/projects/<repo>/*.jsonl`) show what each message did. Work on a
spec leaves its name in the tool calls: the spec file is written and read (`docs/plans/…`,
`docs/bugs/…`), its worktree is used (`worktrees/<version>/<slug>`), and the dispatcher is called
with `SLUG=<slug>` or `SPEC=<path>`. That is evidence per message, not a time window.

## Fix

### F1. Rollup: record references and turns

In `_claude_rollup`, for each assistant record also store:

- `session`: the line's `sessionId`.
- `turn`: the `uuid` of the latest preceding line in the same file with `type: "user"` whose
  `message.content` is a string (a typed prompt, not a tool result). Empty when there is none.
- `refs`: a sorted list of reference strings found in the message's `tool_use` blocks, from the
  JSON text of each block's `input`:
  - spec paths matching `docs/(plans|bugs)/[A-Za-z0-9._-]+\.md`;
  - worktree slugs from `worktrees/v[0-9.]+/([a-z0-9-]+)`, stored as `slug:<slug>`;
  - `SLUG=([a-z0-9-]+)`, stored as `slug:<slug>`.

One API message is written as several transcript lines (one per content block) with the same
`message.id`. Union the refs from all of its lines; usage is still counted once.

Add `"version": 2` to the cache. A cache with another or no version is discarded and rebuilt from
offset 0, so old records gain the new fields. Records, refs and turns stay offline: no network.

### F2. Attribute by turn

In `_render_claude`, map refs to ledger specs: a spec path matches a task whose ledger `start`
event has that `spec`; `slug:<slug>` matches a task with that slug. A ref that matches no task is
ignored.

A turn's references are the union of the refs of all its assistant messages. Each assistant
message in a turn with at least one matched spec is charged to those specs, split equally. This
covers the thinking and text messages of a turn that also wrote, read, dispatched or landed the
spec. A message in a turn with no matched spec is **unattributed**.

Turns and refs ignore time: spec writing before dispatch counts toward the spec.

New series:

- `k3dm_dispatch_task_claude_attributed_usd{window,version,slug}`: per spec, for the same rows as
  `k3dm_dispatch_task_claude_api_cost_usd` (the `shown_keys` set), every scope.
- `k3dm_dispatch_claude_attributed_usd{window}`: for a release, the sum over all of the release's
  landed specs (not only shown rows); for a time window, the attributed cost of messages in the
  window.
- `k3dm_dispatch_claude_attributed_per_landed_usd{window}`: release scope only, attributed ÷ landed.
- `k3dm_dispatch_claude_unattributed_usd{window}`: time windows only.

Keep the existing time-overlap series unchanged.

### F3. Dashboard

- Per spec table: a **Claude (by reference)** column next to **Claude ≈**, currency, footer summed.
  Its description: charged from turns whose tool calls named the spec, including spec writing;
  turns that named nothing are not charged to any spec.
- In the Claude row, replace the **Claude tokens per landed spec** stat with **Claude attributed
  per spec** (`k3dm_dispatch_claude_attributed_per_landed_usd`, release only) and add
  **Claude attributed share** (`attributed / claude_api_cost_usd`, time windows; percent). Keep
  every panel inside the existing layout with no overlaps.

### F4. Docs

`docs/guides/grafana-dashboards/k3dm-agent-dispatch.md`: one paragraph on attribution by reference,
the turn rule, what stays unattributed, and how it differs from **Claude ≈**.

## Tests

ledgers only:

1. Rollup: an assistant line whose `Bash` input contains `make codex-land SLUG=foo` gets ref
   `slug:foo`; an `Edit` with `file_path` `…/docs/plans/v1.0.0-foo.md` gets that path.
2. Rollup: two lines with one `message.id`, a text block then a tool_use block, give one record whose
   refs come from the second line and whose usage is counted once.
3. Rollup: `turn` is the uuid of the latest string-content user line; a tool-result user line does
   not start a turn.
4. Rollup: a cache without `"version": 2` is rebuilt (records gain `refs`).
5. Render: a turn with a thinking-only message and a message that edits spec A's file charges both
   messages to A.
6. Render: a turn naming A and B splits each message 50/50.
7. Render: a message sent while A is dispatched, in a turn naming nothing, is unattributed and
   adds nothing to A's attributed cost (it does still count in A's **Claude ≈**).
8. Render: spec-writing messages dated before A's first dispatch count toward A's attributed cost.
9. Render: `attributed_per_landed` and `unattributed` follow their scope rules (release only / time
   windows only).
10. Dashboard JSON: the new column and stats exist with the right expressions; no panel overlaps.
