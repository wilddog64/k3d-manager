## Context

The relay Worker (`workers/slack-relay/index.js`) records an operator's Approve press for an action id matching
`HERMES_ACTION_ID_RE = /^[rd][0-9]+-[0-9a-f]{8}$/` (`:4`): `r` for Hermes repairs, `d` for dispatch-recover. The cloud bridge will post
cards with ids `c<n>-<8 hex>`. Allow `c`, and give `c` presses reply text that fits a cloud request.

## Files

`workers/slack-relay/index.js`, `workers/slack-relay/test/relay.test.mjs`. Nothing else. Do not deploy.

## Change

- `HERMES_ACTION_ID_RE` -> `/^[rdc][0-9]+-[0-9a-f]{8}$/`. The drain DELETE path pattern (`/^\/hermes\/approvals\/([A-Za-z0-9-]{1,64})$/`)
  already admits it; leave it.
- Reply texts in the interactivity handler (`:263-289`), for ids starting with `c` only (`r` and `d` texts stay byte-identical):
  - approve: `✅ <id> approved by <@user> — the cloud bridge runs it on its next poll (up to ~1 min)`;
  - deny: `🚫 <id> denied by <@user> — the request will expire without running`;
  - not authorized: `⛔ Your <Decision> of <id> was NOT recorded: you are not authorized to approve or deny cloud requests`.
- Everything else (signature check, allowlist, re-auth, KV TTL, drain) unchanged.
