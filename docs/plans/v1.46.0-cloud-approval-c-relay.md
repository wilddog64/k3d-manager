## Context

The relay Worker (`workers/slack-relay/index.js`) records an operator's Approve press for an action id matching
`HERMES_ACTION_ID_RE = /^[rd][0-9]+-[0-9a-f]{8}$/` (`:4`) in KV `approval:<id>` (`:282`) and lists them at `GET /hermes/approvals`
(`:205-232`). Deny stores nothing (`:285`). The cloud bridge will post cards with ids `c<n>-<8 hex>` and needs to see both decisions,
so a Deny frees a waiting slot.

## Files

`workers/slack-relay/index.js`, `workers/slack-relay/test/relay.test.mjs`. Nothing else. Do not deploy.

## Change

- `HERMES_ACTION_ID_RE` -> `/^[rdc][0-9]+-[0-9a-f]{8}$/`.
- In the interactivity handler, for ids starting with `c` only, after the existing allowlist and re-auth checks pass:
  - if `approval:<id>` already exists, store nothing and reply `ℹ️ <id> was already decided; this press was not recorded`;
  - Approve: store `{approved_by, approved_at, nonce, decision: "approve"}`; reply
    `✅ <id> approved by <@user> — the cloud bridge runs it on its next poll (up to ~1 min)`;
  - Deny: store `{approved_by, approved_at, nonce, decision: "deny"}` (same TTL); reply `🚫 <id> denied by <@user> — it will not run`;
  - not authorized: `⛔ Your <Decision> of <id> was NOT recorded: you are not authorized to approve or deny cloud requests`.
- `GET /hermes/approvals`: each item also carries `decision: String(value.decision || 'approve')`.
- `r` and `d`: stored values, reply texts and Deny behaviour byte-identical to today (their items gain only the `decision: "approve"`
  field in the listing, which their consumers ignore).
