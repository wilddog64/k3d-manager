## Context — the `publish` job as it stands

The `publish` job already has, in order:

- `Build, scan, and push frontend image` — `id: push`, exposes `steps.push.outputs.digest`,
  image `ghcr.io/wilddog64/shopping-cart-frontend`.
- `Install cosign` — `if: env.COSIGN_KEY != ''`, `sigstore/cosign-installer@v3.7.0`.
- `Sign image by digest` — `if: env.COSIGN_KEY != ''`, `cosign sign --yes --key env://COSIGN_KEY "${IMAGE_REF}@${DIGEST}"`.
- `Scan frontend image (Trivy)` — `aquasecurity/trivy-action@v0.36.0`, table format, `continue-on-error: true`.
- `Open PR to update Kubernetes manifest to the new image tag` — the deploy step.

`COSIGN_KEY` and `COSIGN_PASSWORD` secrets already flow into the sign step; reuse them.
The trivy-action is already pinned at **`v0.36.0`** in this file — the new predicate
steps MUST use that same pin (do NOT introduce `v0.35.0`; keep one trivy-action version
in the file).

## The change (one file: `.github/workflows/ci.yml`)

Insert the **three** steps below into the `publish` job, **immediately after the
`Sign image by digest` step** (i.e. after its `cosign sign …` `run:` line) and
**before the `Scan frontend image (Trivy)` step**. This mirrors the infra reusable
workflow's step order (sign → vuln predicate → SBOM predicate → attest).

Match the existing indentation of the sibling steps exactly (steps are indented 6
spaces for `- name:`, keys under a step at 8 spaces, `with:`/`env:` children at 10).
LF endings only. Do not change any other step, env, input, or action pin.

**Insert this block (byte-for-byte, indentation as shown):**

```yaml
      - name: Generate vuln attestation predicate (Trivy)
        if: env.COSIGN_KEY != ''
        uses: aquasecurity/trivy-action@v0.36.0
        with:
          image-ref: ghcr.io/wilddog64/shopping-cart-frontend@${{ steps.push.outputs.digest }}
          format: cosign-vuln
          output: trivy-vuln.json
          severity: CRITICAL,HIGH
          ignore-unfixed: true
          exit-code: '0'

      - name: Generate SBOM predicate (Trivy SPDX)
        if: env.COSIGN_KEY != ''
        uses: aquasecurity/trivy-action@v0.36.0
        with:
          image-ref: ghcr.io/wilddog64/shopping-cart-frontend@${{ steps.push.outputs.digest }}
          format: spdx-json
          output: sbom.spdx.json
          exit-code: '0'

      - name: Attest vuln + SBOM by digest
        if: env.COSIGN_KEY != ''
        env:
          COSIGN_KEY: ${{ secrets.COSIGN_KEY }}
          COSIGN_PASSWORD: ${{ secrets.COSIGN_PASSWORD }}
          IMAGE_REF: ghcr.io/wilddog64/shopping-cart-frontend
          DIGEST: ${{ steps.push.outputs.digest }}
        run: |
          cosign attest --yes --key env://COSIGN_KEY \
            --type vuln --predicate trivy-vuln.json "${IMAGE_REF}@${DIGEST}"
          cosign attest --yes --key env://COSIGN_KEY \
            --type spdxjson --predicate sbom.spdx.json "${IMAGE_REF}@${DIGEST}"
```

> Why by digest, not `:sha-` tag: attestations must bind to the exact pushed digest
> (`steps.push.outputs.digest`) — the same reference the sign step used — so verify
> matches. The existing table-format `Scan frontend image (Trivy)` step (tag-based,
> informational) stays unchanged.
