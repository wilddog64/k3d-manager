# v1.27.0 — Foundation-managed vCluster CLI

**Milestone:** v1.27.0 (promoted from v1.26.0 — deferred at the v1.26.0 cut, now the leading load-split prerequisite)  
**Status:** Scoped — ready for implementation on the v1.27.0 branch.  
**Owners:** `lib-foundation` owns acquisition and verification; `k3d-manager` owns vCluster lifecycle orchestration.  
**Consumer:** `k3d-manager`, via its `scripts/lib/foundation` subtree.

## Problem

`make e2e` requires the vCluster CLI. Today `k3d-manager/scripts/plugins/vcluster.sh` detects a missing binary and installs it itself:

- macOS: `brew install loft-sh/tap/vcluster`
- Linux: downloads a release binary and moves it into a system install directory

That makes the consumer responsible for a shared CLI dependency, makes the installed version depend on the host package-manager state, and fails on a machine without Homebrew. It also conflicts with the rule that dependencies must be installed through the upstream `lib-foundation` contract, never by manual host setup or a consumer-local installer.

## Goal

Provide one versioned, integrity-checked vCluster CLI contract in `lib-foundation`. `k3d-manager` must request that contract and use the returned executable path; it must not invoke Homebrew, `curl`, `mv`, `chmod`, or a package manager to obtain vCluster.

This is a CLI binary-management change only. It does not change vCluster manifests, Helm chart versions, E2E substrate behavior, Grafana publishing, or add an npm, Python, Homebrew, or OS-package dependency to `k3d-manager`.

## Locked design

1. **Single owner.** Add a public `foundation_ensure_vcluster_cli <version>` API in `lib-foundation/scripts/lib/system.sh`. The function is the only supported installer/verifier for vCluster in all consumers.
2. **Version input.** The caller supplies the exact version without a `v` prefix. Reject malformed versions. The function must verify that an existing binary identifies as that requested version; a different version is not silently accepted.
3. **Managed location.** Store the executable below `${XDG_DATA_HOME:-$HOME/.local/share}/lib-foundation/vcluster/<version>/vcluster`, never in `/usr/local/bin`, `/opt/homebrew/bin`, or a repository directory. The function prints the absolute executable path on stdout and sends diagnostics only to stderr.
4. **Supported hosts.** Resolve `darwin|linux` and `arm64|amd64` to the official Loft release asset. Fail clearly before any write for unsupported OS/architecture combinations.
5. **Integrity before activation.** Download the release checksum manifest and the matching asset to a temporary directory. Verify SHA-256 before marking the binary executable or replacing a managed binary. Remove temporary files on success and failure. Never execute an unverified download.
6. **Atomic, bounded behavior.** Use a per-version lock to serialize concurrent calls. Install into a temporary file in the managed directory and rename atomically only after verification. A failed update must leave an already verified managed binary usable.
7. **No implicit package manager.** The foundation API must not call `brew`, `apt`, `dnf`, `npm`, or `pip`. `curl` is the existing host prerequisite; when unavailable, report the exact missing prerequisite and return non-zero without modifying the host.
8. **Offline behavior.** If the requested verified binary is already present, return it without network access. If it is absent and the release cannot be fetched, return non-zero with an actionable message; do not fall back to an arbitrary `vcluster` on PATH.

## Implementation

### Part A — `wilddog64/lib-foundation`

1. In `scripts/lib/system.sh`, add the public `foundation_ensure_vcluster_cli <version>` entry point and private helpers for version validation, platform/architecture resolution, managed-path construction, lock handling, download, checksum verification, and installed-binary verification. Keep each helper within the repository's `if`-count budget.
2. Reuse `_detect_platform` and `_run_command` where appropriate. All filesystem writes must be confined to the managed vCluster directory or `mktemp` output.
3. Add focused BATS coverage in `scripts/tests/lib/system.bats` using stubbed `curl`, `uname`, and `vcluster` binaries. The suite must prove:

   - a verified existing exact-version binary is reused without download;
   - a version mismatch is rejected/replaced through the verified acquisition path;
   - malformed versions and unsupported platform/architecture fail without writes;
   - a checksum mismatch never activates the binary;
   - a failed download preserves a prior verified binary;
   - concurrent callers leave one valid executable and no stale lock/temp files;
   - no package-manager command is invoked.

4. Document the public function, managed location, host prerequisites, supported architectures, and offline behavior in `lib-foundation/README.md` and `docs/api/functions.md`.
5. Release the foundation change and record its commit SHA/tag.

### Part B — `wilddog64/k3d-manager`

1. Pull the released `lib-foundation` change into `scripts/lib/foundation` using the repository's normal subtree workflow. Record the upstream SHA in the subtree merge commit.
2. In `scripts/plugins/vcluster.sh`:

   - delete `_vcluster_install_cli` and the `vcluster_install_cli` dispatcher wrapper;
   - remove `VCLUSTER_INSTALL_DIR` and every Homebrew/download/system-directory installation path;
   - in `_vcluster_check_prerequisites`, call `foundation_ensure_vcluster_cli "$VCLUSTER_VERSION"`, retain the returned absolute path in a private executable variable, and fail before lifecycle work if the contract fails;
   - replace every direct `vcluster` invocation in this plugin with that verified executable path;
   - keep the existing namespace, chart version, pinned proxy port, cleanup, and dry-run semantics unchanged.

3. Update `scripts/lib/help/utils.sh` so the user-facing vCluster help describes the foundation-managed prerequisite instead of a local install command.
4. Update `scripts/tests/plugins/vcluster.bats` and `scripts/tests/plugins/e2e.bats` to stub the foundation contract. Assert the consumer never contains `brew install loft-sh/tap/vcluster`, release download URLs, or `VCLUSTER_INSTALL_DIR`; assert its lifecycle commands use the contract-returned executable path.
5. Update `docs/guides/vcluster-e2e-harness.md` (or create it if it has not landed) with a short prerequisite section: run `make e2e`; the foundation contract resolves the pinned vCluster CLI; no manual install is supported.

## Non-goals

- Do not install vCluster manually on developer machines.
- Do not add an npm, Python, Homebrew, apt, dnf, or pip dependency.
- Do not change the E2E test image, vCluster chart/runtime configuration, Grafana E2E event schema, or E2E dashboard.
- Do not make the consumer accept an arbitrary vCluster binary found on PATH.
- Do not modify shopping-cart repositories.

## Verification gates

### `lib-foundation`

```bash
env -i HOME="$HOME" PATH="/usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin" TMPDIR="$TMPDIR" \
  bash --norc --noprofile -c 'bats scripts/tests/lib/system.bats'
shellcheck scripts/lib/system.sh
```

### `k3d-manager`

```bash
bats scripts/tests/plugins/vcluster.bats scripts/tests/plugins/e2e.bats
shellcheck scripts/plugins/vcluster.sh scripts/plugins/e2e.sh
rg -n 'brew install loft-sh/tap/vcluster|VCLUSTER_INSTALL_DIR|vcluster-linux-' scripts/plugins/vcluster.sh
```

The final `rg` command must return no matches. After the foundation subtree is updated, run one real `make e2e` only when the hub is healthy. Confirm that the run creates a `k3dm.k3d.io/e2e-result=true` ConfigMap, the exporter exposes `e2e_last_run_pass`, and the Grafana E2E dashboard renders that result.

## Definition of done

- `lib-foundation` is the sole owner of the verified vCluster CLI lifecycle.
- `k3d-manager` contains no local vCluster installer or package-manager dependency.
- Existing exact-version binaries work offline; absent or invalid binaries fail safely and clearly.
- Both repositories' focused BATS and shellcheck gates pass.
- A live E2E run records its result from ConfigMap through Prometheus to Grafana.
