## Problem

The operator wants to reach the M5 and M4 from anywhere: from a browser-only office machine, from the
phone, or from the M2 while away from home. From there they want to attach to tmux `work` or start
Claude Code. Today there is no remote path into either laptop. It must be interactive and for the
operator only: no agent, token or automation may use it.

## Review 2026-11-18

Fable (Agent) and Astra (codex `gpt-6.2-astra`, read-only) reviewed this spec blind at `00220305`; both said **not ready**.
Claude checked the findings against the tree; none refuted. Trial log: Pair 9 in `docs/reviews/reviewer-trial-fable-vs-argon.md`.

Confirmed blockers (both reviewers unless noted):

1. The Acceptance YAML does not parse (E4 `text:`, colon-space inside an unquoted scalar).
2. There is no `## Files` section, so `bin/k3dm-codex-dispatch` refuses to dispatch. The Component line names `scripts/etc/machine/hosts.conf`, which does not exist.
3. There is no `## Contract readers` section. Missed readers and writers include:
   - `bin/cluster-up:1872-1876` re-renders `~/.cloudflared/config.yml` from the repo on every run, which undoes a revoke.
   - `Makefile` `cloudflared-config` and `cloudflared-backup`.
   - `bin/public-endpoint-probe` and Hermes would probe `ssh-<host>`.
   - `bin/k3dm-cloudflare-posture`, `bin/cluster-down` (boots out the tunnel), `bin/hub-cutover` and the machine-setup bats.
4. "Remote Login stays off, and `check` fails if it is on" contradicts current workflows:
   - `docs/howto/machine-setup.md:62,74` requires Remote Login for `FROM=` pulls.
   - `scripts/plugins/e2e_remote.sh` publishes back over ssh.
   - `docs/plans/service-password-tailnet-read.md:30` needs the hub's sshd.
5. The console rides the hub tunnel. That means split-brain routing, `make down` and cutover cut the console, and it depends on a GUI login. It needs its own tunnel per machine.
6. The idle TOTP lock can be bypassed. Fable proved this on tmux 3.8 with scratch probes:
   - a reconnecting client is unlocked, because the lock is per client;
   - Ctrl-C at the lock prompt unlocks;
   - a lock command that exits non-zero unlocks;
   - `lock-after-time` does not follow a session switch.
7. `ForceCommand` does not cover forwarding. `cloudflared access ssh -L` could reach Vault and ArgoCD on loopback without passing the lock (Astra; Fable listed it as major).
8. No external behaviour is proven: the Cloudflare Access API, whether an app can be disabled, the certificate principal mapping, browser-rendered SSH with a PTY, `sshd -D -f` under a LaunchDaemon, and Keychain reads from an SSH session.
9. Revoke does not cut established sessions and is only stub-proven (M5).

Major: sshd hardening options, and validating the Access JWT at the origin; root ownership of the daemon files (N6 cannot fail as written); machine lists run bare `make` targets and the secrets lists copy items between Macs (console goes in `not-installed.list`); acceptance gaps (M6 has no evidence); scope is too broad for one dispatch.

**Operator decisions (2026-11-18, operator: "all as recommended"; recorded below as chosen).** Originally: **Operator decisions owed before the rewrite** (Claude's recommendation first):

- D1 Remote Login coexistence: leave system sshd as it is (machine-setup needs it). The console runs a separate sshd bound to loopback only, and `check` asserts system sshd is not reachable through any tunnel ingress and has password auth off.
- D2 One dedicated console tunnel per machine (own tunnel id, config file, launchd label and credentials item), independent of `cluster-up`, `cluster-down` and cutover.
- D3 TOTP at login: ForceCommand runs a root-owned gate that loops until a valid code before it attaches. The idle lock becomes a second layer that fails closed, with lock options set globally.
- D4 Split into three dispatches: A, the console sshd plus LaunchDaemon plus a local `check`; B, the Access and tunnel setup and revoke, after captures; C, the TOTP login gate and lock.
- D5 Captures first: the operator (or Claude with a go) captures the Cloudflare Access API responses, browser-SSH behaviour and `sshd -T` on each Mac. The rewritten spec embeds them.

## Re-review 2026-11-18 (Fable + Astra blind, at 861221e5; Claude adjudicates)

Verdicts: both reviewers — A not ready, C not ready. Operator decision O2 (2026-11-18, recorded in the plan 1 umbrella): a process running as the operator's user is in the threat model, so same-user findings below are required fixes, not residuals.

Agreed by both:
- W1 BLOCKER: revoke cannot find live sessions — `sshd-session: <user>@ttysN` titles drop the config path (verified by Claude on the M4, `ps -axo command`), so `pkill -f` matches nothing; no test holds a session open across revoke. Fix: pid set from the listener's descendants plus `netstat -anv` rows on the port; operator drill with one console session and one unrelated Remote Login session.
- W2 BLOCKER: code runs before the gate — `ForceCommand` goes through the login shell (`.zshenv`), Python reads `PYTHONPATH`/`PYTHONINSPECT`/user site. Fix: `#!/usr/bin/python3 -I`, a trusted entry independent of operator startup files; E2 case launched through `/bin/zsh -c`; marker proves startup code absent before auth (or state the `.zshenv` residual explicitly — operator-writable, so under O2 it must be closed).
- W3 BLOCKER: root ownership checked late and incompletely — install writes and loads before C1; ancestors checked for group/other write but not owner; symlinks, ACLs, pre-existing `.new`/`.prev`; installed files copied from an operator-writable checkout. Fix: validate the resolved chain (owner root) before any privileged write; refuse when sources differ from HEAD; print sha256.
- W4 BLOCKER: idle layer fails open — no timeout on tmux calls or child wait, SIGTERM does not kill the child, uncaught exception path, daemon has no read timeout (one stalled same-user connection blocks every login). Fix: try/finally kills the child; bounded tmux calls; SIGKILL fallback; per-connection timeouts; tests after attachment.
- W5 BLOCKER: TOTP state has two writers (daemon vs enrol/rotate), non-atomic secret+state generation, `status` has no source. Fix: one writer (enrol/rotate through the daemon), single commit boundary, `STATUS` verb; E4 asserts rotation through the running daemon.
- W6: CA lifecycle — CA installed before `sshd -t`, rollback omits it, E8/E9 leave a throwaway CA trusted (no `--purge` via make), `ssh-keygen -l` accepts multi-key files (Fable probe). Fix: stage and roll back the whole generation; exactly one key line; `uninstall --purge` in E8/E9; print CA fingerprint.
- W7: C7/C8 do not prove D1 — `sshd -G` ignores `Match` (Fable probe: `-T -C` shows forwarding/password on), C7 misses warp-routing/bastion/other config paths; C8 conflicts with `docs/howto/machine-setup.md:74` (FROM= pull uses the M4 password). Fix: assert no Match/Include/AcceptEnv/SetEnv/Subsystem in file text; `-T -C`; strict cloudflared allow-list; C8 = WARN until the operator moves FROM= to key login (machine-setup how-to listed as a reader).
- W8: verifier socket has no peer-UID check and no bounds. Fix: LOCAL_PEERCRED both directions, bounded reads, distinct UNAVAILABLE reply.
- W9: tmux `-t work` prefix-matches (Fable probe: matches `work-console`); attach changes session environment. Fix: `=work` everywhere; preserve session environment; handle concurrent creation.
- W10: E9 can pass without a forwarding request; needs authenticated session, real channel requests, wrong CA / principal / expired cert cases.

One reviewer only, accepted (Fable): C lockout rule ambiguous (second cycle; state the guess rate); E1 asserts a code is accepted 300 s later (cannot pass); `K3DM_WC_ROOT` override live in the production gate (ignore when `SSH_CONNECTION` set or file root-owned); socket dir under `/var/run` needs the daemon to recreate it at start; N7 argv leaks (dry-run prints AllowUsers, sed argv, `_run_command` failure argv); E4 empty-port contradiction; GNU coreutils first on PATH and `_run_command` sudo path rewriting (`system.sh:67-76`) break shims — use absolute paths; C1 file list (pid file under `root:daemon 775`); plist keys unspecified; uncited readers (`agent_classification.bats:8-25`, `launchd_plist_path.bats:83-91`, `machine_setup_acceptance.bats:97`, `bin/k3dm-hub-sync:85`); `make lint-python` only sees tracked files; use `/usr/bin/python3` for py_compile.
Astra only, accepted: B captures must not replace the production helper/label; A↔C ownership of the live gate serialized.
