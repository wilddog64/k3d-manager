## Motivation

The Gemini free-tier embedding API can be exhausted during mass indexing or disaster recovery, even though ordinary Git-driven incremental updates require few embeddings. The present VectorDB Grafana dashboard shows documents embedded via API per **last run**, cache hits, backlog, pause-until and run result; none is a reliable *daily API request count*, especially across retries and multiple indexer invocations. During the 2026-10-15 review, a 2,013→2,016 corpus increase was indexed and backlog cleared, but the operator could not tell daily request consumption or how much the SQLite cache saved.

Current code facts:
- `scripts/lib/hermes/prior_art.py`: `EMBED_BATCH=100` is a commit chunk, **not a network batch**; `embedContent` is invoked once per uncached text and retried when appropriate.
- `scripts/index-docs.py`: changed docs are resolved through `EmbedCache` (`~/.cache/k3dm/embeddings.sqlite`), then API misses are embedded. Per-run `embedded` and `from_cache` do not represent all actual attempted HTTP requests (e.g. retries).
- `bin/k3dm-hermes` calls the indexer with `--limit 100` **per invocation**, not per day, and handles pause/resume after quota-related failures.

## Goal

Give the operator a truthful, low-cost view of **actual Gemini embedding HTTP requests consumed today**, cached vectors reused, rate-limit responses and proximity to the effective daily budget. Do not imply that fixed historical free-tier limits apply universally.

## Proposed telemetry contract

Instrument the **HTTP request boundary** used by Gemini `embedContent` (not only `embed_batch` returns). Account for:
- All attempted requests, including retries; distinguish succeeded HTTP 2xx, 429 responses (minute throttle vs daily quota when error payload identifies it), other HTTP errors and transport failures.
- Separately count **unique text embeddings completed** and **SQLite cache hits**. Never conflate these with request attempts, tokens consumed or billable units.
- Aggregate into a durable, local **Pacific-day** summary, using an explicit timezone and day boundary consistent with the actual provider reset observed/configured; avoid inventing universal quota reset times. Persist atomically so individual indexing runs and Hermes restarts do not zero the count.
- Include failure-safe handling of process interruption: count at issuance or record an explicit uncertainty/unknown outcome. Idempotent event IDs if journaling; no double count across exporter restarts or retry accounting.
- Provide metrics or a fixed-summary exporter for `requests_today`, `successful_requests_today`, `rate_limited_today`, `daily_quota_rejections_today`, `cache_hits_today`, `embeddings_created_today`, `day_start_timestamp`, and last updated timestamp. Choose bounded fixed-label metrics and guard cardinality, no document paths, prompts, API keys, user inputs or unbounded error messages as labels.
- Daily quota **limit** is an optional configured value, not assumed from historic documentation. If absent, display `unknown` rather than percentage or `safe`; only provide used/limit percentages and threshold alerts when a valid configured limit is available. Clarify the counter covers **this k3d-manager installation/key usage observed here**, not all usage from other applications sharing the Gemini project or key.
- If provider response reports quota metric/type or reset hint, classify with bounds and sanitization; ambiguous HTTP 429 stays `unknown rate/quota type` rather than automatically declaring daily exhaustion.
- If a durable count or metrics publication becomes stale, show unavailable/stale rather than resetting to an apparently healthy zero.

## Grafana presentation

Extend the existing VectorDB **Ingestion** section:
1. **Gemini embedding requests today:** integer count, with source/timezone and last updated timestamp.
2. **SQLite cache hits today:** integer count, plus optional reuse ratio based on actual cache hits and successful new embeddings.
3. **Daily quota usage:** count/limit and utilization only with operator-verified limit; otherwise explicitly “limit not configured.”
4. **429 / daily quota rejection trend:** diagnostic distinction and recent rate-limit behavior.
5. **Requests over time (today):** bounded timeline separating attempted API requests, successful embeddings and cache-served texts.

Show the last-run metrics separately from the daily accumulated metrics. Do not add duplicate dashboard panels already planned under the provenance enhancement. Ensure counts are integer-formatted (avoid fractional Y-axis ticks).

## Tests / acceptance criteria

1. No-op unchanged fingerprint => zero new API requests; no artificial increment from ordinary polling.
2. Cache hit => counts reuse; no API request. Cache miss with 2xx => one attempted and one successful request plus one new embedding.
3. 429 then retry with 2xx => two attempted requests, one 429, one success; do not count two embedded documents.
4. Exhausted daily quota response => classified if supported by provider evidence; indexer pause unchanged, no fabricated successful embed.
5. Per-minute throttle or ambiguous 429 => not mislabeled as daily quota.
6. Multiple indexer runs, Hermes restarts and Pacific-day rollover => totals persist, reset only at defined day boundary, and never double count completed events.
7. Missing/quota-limit override, changed provider limits or other applications sharing key => utilization is `unknown` or explicitly partial, never incorrectly 100%-accurate.
8. Crash, missing cache, telemetry write failure or stale exporter => no silent success/zero; preserve embedding and existing fail-closed quota behavior.
9. Tests use mock HTTP and temporary local ledgers. No live Gemini API, no secrets in metrics/logs, no external network calls.
10. Validate the dashboard's integer display and run existing VectorDB/index tests plus canonical `test-all`.

## Non-goals

No paid Gemini tier, new network polling of Google quota APIs, new persistent database server, quota bypass, changes to indexing prioritization, or altered default embedding model. Keep the SQLite cache and per-batch resume behavior intact.
