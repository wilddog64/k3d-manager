# v1.43.2 — Separate VERIFIED from LIVE-VERIFIED on the Bug Tracking dashboard

**Filed:** 2026-10-16

**Status:** OPEN — spec ready

## Problem

The dashboard's `verified` label is `true` for both `VERIFIED` and `LIVE-VERIFIED`, so the
two steps of the ladder look the same. The operator's ladder is:

```text
OPEN → IMPLEMENTED → VERIFIED → LIVE-VERIFIED
```

- **VERIFIED:** someone other than the implementer checked the fix offline: tests run, the
  new tests shown red on the old code, mutations red.
- **LIVE-VERIFIED:** the fix was proven on the real system (hub, cluster, Slack, email).

The ladder is cumulative: a LIVE-VERIFIED doc is also verified.

## Fix

### 1. `scripts/lib/hermes/prior_art.py`

Add after `doc_status`, leaving `doc_status` and its return value unchanged:

```python
_LIVE_VERIFIED_RE = re.compile(r"^LIVE-VERIFIED\b", re.IGNORECASE)


def doc_verification(text):
    """Return ``"live"``, ``"verified"`` or ``""`` from the doc's Status value."""
    value = _status_value(text) or ""
    if _LIVE_VERIFIED_RE.search(value):
        return "live"
    if _VERIFIED_RE.search(value):
        return "verified"
    return ""
```

### 2. `bin/k3dm-vectordb-metrics`, `_bug_status_metrics`

- Import `doc_verification` the same way `doc_status` is imported.
- For a `fixed` doc, set the `verified` label from `doc_verification(text) in ("verified", "live")`,
  so its values do not change, and add a `live_verified` label: `"true"` when it returns `"live"`,
  else `"false"`. Docs from before v1.43.2 get `"n/a"` for both, like today. A doc that is not
  fixed gets neither label, like `verified` today.
- Add `live_verified` as the **last** label on `k3dm_bug_info` and on `k3dm_bug_status_docs`.
  Add it to the aggregation key and to the row tuple, after `verified`.
- Do not change the push group, the push method, the 1000-row cap, or the sort key.
