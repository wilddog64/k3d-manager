## Goal

The operator asked to "select between releases" on the k3dm Bug Tracking dashboard. Add a
**Release** dropdown. It filters the Open bugs table and the Open P0–P3 stats to the bugs
**filed in** the chosen releases.

"Filed in" means exactly what `scripts/bug-tally.py` already uses, through
`hermes.prior_art.doc_release`:

1. the doc's `**Branch:** k3d-manager-vX.Y.Z` line;
2. otherwise the first tag that contains the commit that added the file;
3. otherwise the current release branch.

Do not write a second attribution rule.

## Fix

### 1. `bin/k3dm-vectordb-metrics`

**1a. Run the tally once.** Move the `bug-tally.py` subprocess call out of `_release_metrics`
into a new function:

```python
def _tally(root, ref=None):
    root = Path(root)
    result = subprocess.run([sys.executable, str(root / "scripts" / "bug-tally.py"), "--json", "--ref", ref or "HEAD"],
                            cwd=root, capture_output=True, text=True, check=True, timeout=90)
    return json.loads(result.stdout)["releases"]
```

Then change `_release_metrics` as follows.

- Signature: `def _release_metrics(root, ref=None, tally=None):`
- Replace its two subprocess lines with:
  `tally = tally if tally is not None else _tally(root, ref)`

Everything else in `_release_metrics` stays the same.

**1b. A release label on the open-bug series.**

- Signature: `def _open_bug_metrics(root, ref=None, now=None, tally=None):`
- Build a map from the tally:

  ```python
  release_of = {item["path"]: release
                for release, data in (tally or {}).items()
                for item in data.get("open_paths", [])}
  ```

- For each open row, set `release = release_of.get(path, "unassigned")`. If the value does not
  match `^v\d+\.\d+\.\d+$`, use `"unassigned"` instead. This covers the tally's `unknown` bucket,
  a `None` key, and a doc the tally did not see.
- Add `release="<release>"` as the **last** label of `k3dm_bug_open_info`. The other labels and
  their order stay the same.
- Add a new uncapped aggregate to the same payload. It counts every open row **before** the
  200-row cap, so the stats stay exact when the table is truncated:

  ```text
  k3dm_bug_open_release_docs{release="<release>",priority="<P0..P3|unset>"} <count>
  ```

  - Emit only nonzero pairs.
  - Sort by release, then priority.
  - Rows skipped by the stem check are not counted.
- The two counters (`_skipped`, `_truncated`) are unchanged.

**1c. `publish_bug_metrics`.** Keep the current inventory scan and its `k3dm-bug-docs` push
first. Then:

```python
    try:
        tally = _tally(root, ref)
    except Exception as exc:
        print(f"bug tally skipped (non-fatal): {exc}", file=sys.stderr)
        tally = None
    try:
        open_bugs = _open_bug_metrics(root, ref, tally=tally)
        _push_bug_group("k3dm-bug-open", open_bugs, method="PUT")
    except Exception as exc:
        print(f"open bug metrics skipped (non-fatal): {exc}", file=sys.stderr)
    if tally is None:
        print("bug release metrics skipped (non-fatal): no tally", file=sys.stderr)
        return pushed
    try:
        releases = _release_metrics(root, ref, tally=tally)
    except Exception as exc:
        print(f"bug release metrics skipped (non-fatal): {exc}", file=sys.stderr)
        return pushed
    _push_bug_group("k3dm-bug-releases", releases)
    return pushed
```

A failed tally still publishes the open table, with every row `unassigned`. It skips only the
release group, as before.

### 2. `scripts/etc/argocd/platform-ops/grafana-dashboard-bugs.yaml`

**2a. A dashboard variable.** Add a top-level `"templating"` key. It must stay valid JSON inside
the ConfigMap.

```json
"templating": {
  "list": [
    {
      "name": "release",
      "label": "Release (filed in)",
      "type": "query",
      "datasource": {"type": "prometheus", "uid": "prometheus"},
      "query": {"query": "label_values(k3dm_bug_open_info, release)", "refId": "PrometheusVariableQueryEditor-VariableQuery"},
      "definition": "label_values(k3dm_bug_open_info, release)",
      "refresh": 2,
      "sort": 8,
      "multi": true,
      "includeAll": true,
      "allValue": ".*",
      "current": {"selected": true, "text": ["All"], "value": ["$__all"]},
      "hide": 0
    }
  ]
}
```

`sort: 8` is natural descending (Grafana 11.4 on the hub), so `v1.43.2` lists above `v1.9.0`
and `unassigned` sorts last.

**2b. The panels the variable filters.**

| Panel | Before | After |
|---|---|---|
| 9–12 Open P0..P3 | `sum(k3dm_bug_docs{state="open",priority="Px"})` | `sum(k3dm_bug_open_release_docs{priority="Px",release=~"$release"}) or vector(0)` |
| 23 Open bugs (table) | `k3dm_bug_open_info` | `k3dm_bug_open_info{release=~"$release"}` |
| 22 row title | `All open bugs` | `Open bugs — filed in $release` |

**2c. A Release column in the table.**

- Every other column and override is unchanged.

## Tests (each new one shown failing against the pre-change code, on a temp copy)

### pytest (`test_vectordb_bug_metrics.py`)

1. `_open_bug_metrics(..., tally=...)` uses a hand-built tally dict, not a subprocess. A path in
   `v1.43.1`'s `open_paths` gets `release="v1.43.1"`. A path in the `unknown` bucket, and a path
   absent from the tally, both get `release="unassigned"`. `tally=None` makes every row
   `unassigned`.
2. `release` is the last label on every `k3dm_bug_open_info` line.
3. `k3dm_bug_open_release_docs` gives exact counts per (release, priority) with no zero lines.
   With 201 open docs the aggregates still sum to 201, while the info series are capped at 200.
4. In `publish_bug_metrics`, `_tally` is called **once**. Monkeypatch it with a counter and
   monkeypatch `urlopen`. `k3dm-bug-open` is still `PUT`, and the other two groups are still `POST`.
5. When `_tally` raises, `k3dm-bug-docs` and `k3dm-bug-open` are still pushed and
   `k3dm-bug-releases` is not.
6. The existing tests stay green. Update the existing `_fake_git` / tally fakes only where they
   stubbed the subprocess that moved into `_tally`.
