# v1.43.13 — AGENTS.md and GEMINI.md: match how agents are dispatched, drop stale facts and the persona, guard against drift

**Status:** PROPOSED — not dispatched
**Approval:** pending. Operator asked for the plan 2026-10-31 ("can you evaluate AGENTS.md and GEMINI.md then write up an plan in v1.43.13"); no dispatch go yet.
**Branch:** `k3d-manager-v1.43.13`
**Related:** `bin/k3dm-codex-dispatch` (the prompt every dispatched agent gets); `CLAUDE.md` (Docs Conventions: Acceptance block, Test controls); memory `feedback_gemini_verify_tasks.md` (no live-cluster verification by Gemini)

## Goal

Codex reads `AGENTS.md`, and the Gemini/agy path reads `GEMINI.md`. Both were written in early 2026 and have
not tracked how the project works now. Three kinds of problem were found on 2026-10-31:

1. **They contradict the dispatch prompt.** An agent gets two sets of orders and has to guess which wins.
2. **They state stale or unsafe facts.** An agent that follows them does the wrong thing on today's fleet.
3. **They miss the rules that matter most for dispatched work.** The Acceptance and test-control rules live
   only in `CLAUDE.md`, which Codex and agy never read, although those agents write most of the tests.

The fix is a rewrite of both files into short, direct contracts, plus a check that keeps them from drifting
again. This applies the "direct objective framing, full context, fewer rigid incident rules" points from the
operator's 2026-10-31 review.

### Persona and incident rules

- `GEMINI.md` line 14 opens with "You are the **SDET + Red Team agent**". The useful part is the scope list
  under it. The label adds nothing an agent can act on.
- `GEMINI.md` "Known Failure Modes" is a list of dated incidents ("2026-03-18", "2026-03-27") written as
  "You do X". Each one hides a principle. Stated as principles, they apply to cases the incident did not cover.
- `AGENTS.md` has no persona. Its "Repository Guidelines" header and generic sections read as a template.

### What is missing from both

- The Acceptance-block contract: implement to `must`/`must_not`; every `must_not` test is shown red on the
  pre-fix code; never weaken or delete a test.
- The three test controls from CLAUDE.md (2026-10-30): a paired positive control for every "has no effect"
  test; stubs taken from a real read-only capture with host and date beside them; a fixture asserts its
  target (scratch HOME, stub endpoint, fake repo root) before it asserts the result.
- Test isolation that has actually bitten: tests that leak to the live Pushgateway on `:19094`, observability
  tests that clobber the real `$HOME`, and deny-tests that pass falsely inside the Codex seatbelt sandbox.

### Duplication

The security rules, bug priorities and 5-plan cap are copied into `CLAUDE.md`, `AGENTS.md` and `GEMINI.md`,
each worded differently. The copies have already drifted, as the sensitive-flag location above shows.

## Change

### 1. `AGENTS.md` — the contract for a dispatched agent

Rewrite to at most about 120 lines, in this order:

1. **What you are given and what you hand back.** It must match the dispatch prompt: a worktree and a spec;
   no git writes, no `memory-bank/`; finish by listing every changed file and pasting the spec's gate output.
2. **How to read a spec.** The `## Acceptance` block is the contract. `must_not` tests run red on the pre-fix
   code. If a spec is ambiguous or contradicts the code, stop and say so in the last message. Do not guess.
3. **Test rules.** The three test controls, the isolation rules (scratch HOME, Pushgateway pointed at
   `127.0.0.1:9`, no real Keychain or `~/Library/LaunchAgents`), and the note that sandbox deny-tests need a
   run outside the sandbox. Never weaken, skip or delete a test.
4. **Gates.** `make test`, `make test-pytest`, `shellcheck` on touched shell files, `_agent_audit`; read
   per-suite counts, not only the exit code.
5. **Code rules.** Bash and Python, `_run_command`, lib-foundation edits upstream only, scope limits.
6. **Shared rules block** (see 3).

Remove: commit/push/PR/memory-bank instructions, the `yolo` rule (moves to `GEMINI.md`), the stale command list.

### 2. `GEMINI.md` — the same shape, Gemini's scope

- Replace "You are the SDET + Red Team agent" with a plain **Scope** list: BATS and pytest authoring, offline
  security review, pre-commit hook smoke tests. Remove cluster verification. Say in one line that live
  evidence is run by the operator or Claude.
- Delete the Cluster Context section and the cluster parts of the completion report. Gemini needs no
  cluster access for its scope.
- Rewrite "Known Failure Modes" as principles, keeping each one's lesson. Examples: read the spec and
  memory-bank before acting; a confirmed plan is not a checkpoint, the output is; stop at stop gates; never
  reference an unreleased dependency.
- Keep the `--approval-mode yolo` rule (moved here from `AGENTS.md`).
- Same hand-back contract as `AGENTS.md` §1. The implementer first checks which file agy actually loads
  (`GEMINI.md`, `AGENTS.md` or neither), records the answer in the commit message, and tells Claude if agy
  loads `AGENTS.md`.

### 3. Shared rules, one source

Security rules, bug priority and the 5-plan cap go between markers
`<!-- shared:begin rules -->` / `<!-- shared:end rules -->`, byte-identical in `CLAUDE.md`, `AGENTS.md`
and `GEMINI.md`. The text is the current `CLAUDE.md` wording. `CLAUDE.md` changes only by gaining the markers.

### 4. `make check-agent-docs`

A small Python check (`bin/k3dm-check-agent-docs`), run in `make test-pytest`'s CI job:

- the shared block is present and byte-identical in all three files;
- every repo path in backticks in `AGENTS.md` and `GEMINI.md` (anything starting `scripts/`, `bin/`,
  `docs/`, `memory-bank/` or `Makefile`) exists, ignoring `<placeholder>` paths;
- neither file contains an instruction token the dispatch prompt forbids: `git commit`, `git push`,
  `gh pr create` outside a "do not" sentence, or a `0.0.0.0:` bind, or `config use-context`.
