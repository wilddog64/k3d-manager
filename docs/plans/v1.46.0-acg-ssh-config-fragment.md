## Problem

Cloud sandbox code edits the operator's main SSH config, which on m4 and m5 is a symlink into the `zshdotfiles` repo:

- ACG (AWS): lib-foundation `scripts/lib/acg/acg.sh:18,71-117` (fixed upstream in lib-foundation v0.5.12).
- GCP: `scripts/lib/providers/k3s-gcp.sh:84-105` `_gcp_update_ssh_config` (removes then appends `Host ubuntu-gcp` with
  `StrictHostKeyChecking no`, `UserKnownHostsFile /dev/null`), and teardown `:286-296`.
- Azure: `scripts/lib/providers/k3s-az.sh:86-107` `_az_update_ssh_config` (`Host ${AZ_SSH_CONFIG_HOST:-ubuntu-azure}`),
  teardown `:287-297`.
- The GCP/Azure rewrite does `mv "$tmp" "$ssh_config"`: on a symlinked `~/.ssh/config` that **replaces the symlink with
  a regular file**, silently detaching the operator's config from the dotfiles repo.

## Proven facts (read-only, Claude, 2026-11-27)

- m4-air and m5-air: `~/.ssh/config` and `~/.ssh/config.d` are both symlinks into `zshdotfiles/ssh/<host>/`; `~/.ssh` is
  a real `drwx------` directory. m2-air: neither is linked.
- `git -C zshdotfiles check-ignore ssh/m4-air/config.d/k3dm-sandbox` prints nothing: a file in `~/.ssh/config.d/` would
  land, unignored, in the dotfiles repo. Hence the default fragment `$HOME/.ssh/k3dm-sandbox.conf`, shared with
  lib-foundation via `K3DM_SSH_SANDBOX_FRAGMENT`.
- `zshdotfiles` `HEAD:ssh/m4-air/config` still carries `Host ubuntu-1`, `Host ubuntu-2`, `Host ubuntu` (lines 3, 8, 13;
  Host lines only read) — committed leftovers from an earlier sandbox.
- `Include` lines (`grep -n '^Include'` only): m4 and m5 line 1 `Include ~/.ssh/config.d/operator`; m5 line 5
  `Include ~/.orbstack/ssh/config`; m2 lines 4 and 9 (colima, orbstack).
- k3d-manager's `scripts/plugins/acg.sh:18` sources the subtree `acg.sh`, so after the pull ACG uses the fragment.

## What NOT to Do

- Never write, `touch`, chmod or `mv` `~/.ssh/config`; never write through a symlink; never touch `~/.ssh/config.d/`.
- Do not change the Host block contents, kube context names, firewall or cloud API calls.
- Do not edit `scripts/lib/foundation/` (only Claude's subtree pull changes it).
- Do not edit the operator's dotfiles (`zshdotfiles`): adding the Include line and deleting the committed stale
  `ubuntu*` blocks on m4 are the operator's change.
- Tests: no real `gcloud`, `az`, `ssh`, network; never read the real `~/.ssh`.
