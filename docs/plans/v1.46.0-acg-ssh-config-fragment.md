## Problem

Cloud sandbox code edits the operator's main SSH config, which on m4 and m5 is a symlink into the `zshdotfiles` repo:

- ACG (AWS): lib-foundation `scripts/lib/acg/acg.sh:18,71-117` (fixed upstream in lib-foundation v0.5.12).
- GCP: `scripts/lib/providers/k3s-gcp.sh:84-106` `_gcp_update_ssh_config` (removes then appends `Host ubuntu-gcp` with
  `StrictHostKeyChecking no`, `UserKnownHostsFile /dev/null`), and inline teardown `:286-295`.
- Azure: `scripts/lib/providers/k3s-az.sh:86-106` `_az_update_ssh_config` (`Host ${_AZ_SSH_CONFIG_HOST}`, bound at source
  time `:17`; the alias is interpolated into an `awk` regex at `:92`), inline teardown `:287-296`.
- The GCP/Azure rewrite does `mv "$tmp" "$ssh_config"` when the block already exists: on a symlinked `~/.ssh/config`
  that **replaces the symlink with a regular file**, silently detaching the operator's config from the dotfiles repo.
  Teardown does the same, and runs even under `DRY_RUN=1`.
- `scripts/plugins/shopping_cart.sh` reads AWS node IPs by `awk` over `${HOME}/.ssh/config` (`:1224-1231`,
  `:1246-1255`, `:1464-1469`) and passes them to `ssh-keyscan` and `k3sup` (Go SSH, which ignores `~/.ssh/config`).

## Proven facts (read-only, Claude, 2026-11-27)

- m4-air and m5-air: `~/.ssh/config` and `~/.ssh/config.d` are both symlinks into `zshdotfiles/ssh/<host>/`; `~/.ssh` is
  a real `drwx------` directory. m2-air: neither is linked.
- `git -C zshdotfiles check-ignore ssh/m4-air/config.d/k3dm-sandbox` prints nothing: a file in `~/.ssh/config.d/` would
  land, unignored, in the dotfiles repo. Hence the default fragment `$HOME/.ssh/k3dm-sandbox.conf`, shared with
  lib-foundation via `K3DM_SSH_SANDBOX_FRAGMENT`.
- m4 `~/.ssh/config` (`grep -n '^Include\|^Host'` only): `1: Include ~/.ssh/config.d/operator`, `3: Host ubuntu-1`,
  `8: Host ubuntu-2`, `13: Host ubuntu` — committed leftovers. A sandbox Include added after line 1 still precedes them,
  so the fragment wins; deleting them is D3.
- `scripts/plugins/acg.sh:18` sources the subtree `acg.sh`, which (v0.5.12) sources `ssh_fragment.sh`.
  `k3s-gcp.sh:15,17` / `k3s-az.sh:9,11` source `${SCRIPT_DIR}/plugins/{gcp,azure,shopping_cart}.sh` at source time.
- `scripts/tests/plugins/shopping_cart.bats:408-525` seeds `${HOME}/.ssh/config` directly (`:489`, `:525` with
  `Host ubuntu`).
- `bin/cluster-down:138-152` skips `acg_teardown` when AWS credentials are expired: stale stanzas then stay until the
  next `make up` overwrites them (expected, not a teardown failure).

## Operator decisions (asked once, with the intent)

**Decided 2026-11-27 (operator): D1, D2, D3 accepted as the defaults below.**

  `ssh/m4-air/config` — before the next sandbox run (the D2 pre-flight would otherwise stop it).

## What NOT to Do

- Never write, `touch`, chmod or `mv` `~/.ssh/config`; never write or delete through a symlink; never touch
  `~/.ssh/config.d/`.
- Never call `_err` (it exits); use `printf 'ERROR: %s\n' "[k3s-gcp] …" >&2; return 1` where an error is needed.
- Do not change the Host block contents, kube context names, firewall or cloud API calls.
- Do not edit `scripts/lib/foundation/` (only Claude's subtree pull changes it); do not copy helper logic out of it.
- No new `if` line in `_provider_k3s_gcp_destroy_cluster` (7/8) or `_provider_k3s_az_destroy_cluster` (8/8); every new
  helper uses the `function` keyword and has ≤ 8 `if` lines (pre-commit `_agent_audit`).
- Do not edit the operator's dotfiles (`zshdotfiles`) — that is D3.
- Tests: no real `gcloud`, `az`, `ssh` (except `ssh -G -F <fixture>`), `k3sup`, network; never read the real `~/.ssh`.
