# v1.29.0 — Hermes Phase-1 implementation plan (read-only ops monitoring, off-hub)

**Milestone:** v1.29.0 — Hermes Phase-1 (the "hermes-agent").
**Scope authority:** `docs/architecture/hermes-phase1-monitoring-scope.md` (the roadmap-required scope
doc; this is the implementation plan that executes it). Roadmap theme: Hermes event-driven ops
automation, Phase 1 = read-only observe/correlate/report only.
**Gate satisfied:** scope §9 — Hermes runs **off-hub** (on the laptop, same tier as `bin/k3dm-webhook`),
which satisfies "don't monitor from inside the failure domain" **without** waiting for the Mac Mini M5.
So this milestone is NOT hardware-gated.

## Non-negotiable constraints (carry into every workstream)

1. **Read-only, reports-and-stops.** No `kubectl apply/patch/delete`, no ArgoCD sync, no pod restarts,
   no edge refresh, no Git writes, no branch-protection changes. There must be **no mutation code path
   in the Hermes codebase at all** (grep-assertable). Phases 2/3 are explicitly deferred, each needs its
   own scope doc.
2. **Webhook is authoritative** (scope §4). Hermes consumes the k3d-manager webhook status via the
   existing contract — `bin/cluster-status-summary` → `GET /api/v1/health?provider=<p>` (Bearer token
   from Keychain `k3dm-webhook-token`, port 7443), which returns
   `{overall, provider, context, errors, warnings, checks, counts}` and degrades to `overall:"unknown"`
   when the webhook is unreachable. Hermes does NOT run a second cluster-health model; on `unknown` it
   reports "status source unavailable", never invents a verdict.
3. **Least privilege** (scope §6). Read-only only: namespaced K8s Role (ExternalSecrets conditions,
   pods/nodes via webhook, ArgoCD app status), ArgoCD read-only API account (app get/list), GitHub
   read-only Actions/status. No write verbs, no `cluster-admin`, no cloud/Git write, no secret *values*.
4. **Least-resort LLM routing** (scope §10). Deterministic sensing in code; an LLM is called ONLY on
   sustained multi-signal degradation; the default LLM is **non-Claude** (Codex/Gemini), Claude only for
   verification; a **per-day call budget** is enforced from day one.
5. **Bounded polling.** Config-driven intervals, no tight loops, jittered; safe to run unattended.

## Already shipped (Phase-1 first deliverable, v1.28.0)

`bin/public-endpoint-probe` + `make status-public` — multi-sample public-endpoint probe with
`--json`, edge-vs-single-service discrimination (exit 0/1/2/3). Becomes Hermes's reachability sensor
for free (WS1 consumes its `--json`). Do not reimplement it.

## Workstreams

Each workstream is a separate Codex/Claude task with its own handoff spec written at execution time.
Sequenced by dependency. Kept within the ≤5 plan-doc milestone cap (see "Plan-doc structure" below).

### WS0 — Access model (scope §6) — FIRST, gates everything
- **Goal:** provision the read-only identities Hermes uses, verified to hold no write verbs.
- **Deliverables:** a namespaced K8s `Role`+`RoleBinding`/`ServiceAccount` (or read-only kubeconfig)
  scoped to ExternalSecrets (get/list/watch conditions), pods/nodes read; an ArgoCD read-only local
  account/project scoped to app get/list; a GitHub fine-grained read-only token (Actions/checks read).
- **DoD:** `kubectl auth can-i --list` for the SA shows only read verbs (no create/update/patch/delete);
  ArgoCD account cannot sync (`argocd app sync` denied); GH token has no `contents:write`/branch scopes.
- **Owner:** Claude (k3d-manager manifests) + user for the GH token issuance.

### WS1 — Sensor set (scope §3), read-only
- **Goal:** deterministic, bounded pollers emitting a normalized signal record each cycle.
- **Sensors:** (a) ExternalSecret sync — `SecretSyncedError` sustained > 2 cycles; (b) ArgoCD app
  health — `Degraded`/`OutOfSync` sustained > N cycles (read-only API); (c) public reachability —
  wrap `bin/public-endpoint-probe --json` (already shipped); (d) node/control-plane pressure — from the
  **webhook** payload (§4), never a direct probe; (e) CI health — GitHub Actions read API, required
  check failing/stuck.
- **DoD:** each sensor emits `{sensor, status, evidence, sampled_at}`; unit-tested against stubbed
  inputs (BATS/py); no mutation calls; webhook-unknown handled per constraint 2.
- **Owner:** Claude/Codex (k3d-manager `bin/` + `scripts/`).

### WS2 — Correlator + Slack summary (scope §8)
- **Goal:** combine sensor records; fire ONE Slack summary only on **sustained multi-signal**
  degradation (not any single flap); include the incident-shaped correlation (e.g. ESO-error +
  node-CPU-pressure + public-502 → the 2026-09-02/03 signature).
- **Slack:** reuse the existing relay path (webhook Slack integration / `make update-webhook-slack*`),
  read-only post to the ops channel. No command surface (Phase 1 is advisory).
- **LLM routing:** deterministic correlation in code; call an LLM ONLY when the multi-signal threshold
  trips, default non-Claude, Claude verify-only, per-day budget (constraint 4). Budget + provider are
  config with safe defaults.
- **DoD:** correlator emits a summary on a simulated multi-signal incident and stays silent on single
  flaps; grep proves no mutation path; budget enforced (call count capped, tested).
- **Owner:** Claude/Codex.

### WS3 — `_install_hermes_agent` (scope §10), lib-foundation, off-hub
- **Goal:** install + supervise the Hermes agent on the laptop (launchd LaunchAgent, like
  `bin/k3dm-webhook`), off-hub. Provisions ONLY the WS0 read-only access; no privilege at install time.
- **Subtree discipline:** the helper lives in **lib-foundation** — edit lib-foundation upstream, PR,
  tag, `git subtree pull` into `scripts/lib/foundation/`. NEVER edit the subtree copy directly.
- **DoD:** `_install_hermes_agent` stands up the launchd job off-hub, wires the read-only creds, and a
  fresh install creates no write verbs (re-run WS0 DoD checks post-install). Uninstall path included.
- **Owner:** Claude (lib-foundation upstream) → subtree pull.

### WS4 — Guide (scope §8, per-major-tech convention)
- **Goal:** `docs/guides/hermes.md` (or `docs/howto/`) grounded in the real WS0–WS3 code: what Hermes
  senses, how the webhook is authoritative, the access model, how to install/uninstall, and an explicit
  statement that Phases 2/3 are NOT implemented and require their own scope docs.
- **DoD:** guide references real file paths/functions; passes `scripts/check-doc-links.sh`.
- **Owner:** Claude.

## Sequencing

WS0 (access) → WS1 (sensors) → WS2 (correlator+Slack) in parallel-ish with WS3 (installer) once WS0/WS1
interfaces are fixed → WS4 (guide) last. WS0 is the hard prerequisite (nothing runs without read-only
creds) and proves the least-privilege posture before any agent code observes the cluster.

## Phase-1 Definition of Done (from scope §8 — the release exit)

- [ ] Sustained multi-sample public-endpoint probe in `make status` (DONE v1.28.0).
- [ ] Read-only sensor set (WS1) against the authoritative webhook status.
- [ ] Least-privilege access model (WS0) provisioned + verified to hold no write verbs.
- [ ] Correlator emits a Slack summary on sustained multi-signal degradation, bounded polling, **no
      mutation path in the codebase** (WS2).
- [ ] `_install_hermes_agent` installs/supervises off-hub via lib-foundation subtree (WS3).
- [ ] `docs/guides/` Hermes Phase-1 guide grounded in real code (WS4).
- [ ] Explicit statement in code + docs that Phases 2/3 are not implemented and require their own scope docs.

## Plan-doc structure (≤5 cap)

This master plan = 1 doc. Per-workstream Codex/Claude handoff specs are written at execution time as
`docs/bugs/`-style task specs (exempt from the plan cap) OR as at most 3 additional `docs/plans/` specs
(WS0+WS3 access/installer, WS1+WS2 sensors/correlator, WS4 guide) — staying within the 5-plan limit.
If the breakdown would need a 6th plan doc, split the milestone.

## What NOT to do

- Do NOT add any mutation capability "for later" — Phase 1 has zero write paths by design.
- Do NOT let Hermes run a second health model — always defer to the webhook (§4).
- Do NOT default the LLM to Claude, and do NOT ship without a per-day call budget.
- Do NOT run Hermes in-cluster — off-hub only (scope §9).
- Do NOT edit `scripts/lib/foundation/` directly — lib-foundation upstream + subtree pull.

## Verification (milestone close)

- Read-only proof: `kubectl auth can-i --list` (SA), ArgoCD sync denied, GH token scope check.
- Correlator behavior: simulated multi-signal incident → one Slack summary; single flaps → silent.
- No-mutation proof: grep the Hermes codebase for `apply|patch|delete|sync|restart` write paths → none.
- Off-hub proof: agent runs on the laptop (launchd), survives a hub outage, reports "status source
  unavailable" when the webhook is down rather than a false verdict.
