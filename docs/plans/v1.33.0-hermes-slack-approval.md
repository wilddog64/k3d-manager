## 1. Goal

Today Hermes proposes allowlisted repairs (R1–R4) but the operator must approve them at a **shell**
(`bin/k3dm-hermes approve <action-id>`). Option A adds **interactive Approve / Deny buttons in Slack**
so an approver can authorize a proposed repair from their phone — **without weakening the off-hub,
no-public-inbound posture** that Phase 1/2 were built around.

The chosen mechanism is a **PULL model**: Hermes never exposes a listener. Approvals are captured at the
Cloudflare edge (the existing `k3dm-slack-relay` worker) into Cloudflare **KV**, and Hermes **drains** that
KV on its normal poll cycle and feeds each approved `action_id` into the **unchanged** `repairs.approve()`
path — which still re-validates the precondition and enforces one-attempt-per-incident.

## 1a. Non-goals (explicit)

- **No auto-execution.** The `repairs.approve()` invariant (no repair runs outside `approve()`; poll cycle
  only proposes) is preserved verbatim. Grep-invariant-1 must still hold.
- **No new privilege for R1–R3.** R4 keeps its existing `actions:write` PAT. No repair gains scope.
- **This does NOT widen the `/ask` audience.** The approver allowlist (§5.2) is a small admin set, wholly
  separate from the slash-command role map. The audit's F2-Phase-2 gate is about the general `/ask` reader
  surface and is unrelated to this feature; do not conflate them.
- **No inbound listener on the laptop.** Hermes remains outbound-only (post to Slack; GET/DELETE the edge KV).

---

## 2. Trust model / why pull, not push

A push model (Slack → worker → **laptop webhook** → execute repair) would turn the webhook into a
remotely-triggerable repair executor, exactly the escalation the security audit warns about. The pull model
keeps the laptop's only inbound surface the existing loopback webhook and does not add a repair-execution
route to it. The edge worker can only **record intent** into KV; the laptop decides, on its own schedule,
whether that intent still maps to a valid precondition. Compromising the worker/KV yields at most a
**queued approval**, which `repairs.approve()` will still reject if the precondition no longer holds or the
repair was already attempted this incident.

## 3. Data flow

```
Hermes poll (incident + proposals)
  └─ post_interactive() ──▶ Slack incoming webhook (k3dm-slack-webhook)
                             message = summary + Block Kit Approve/Deny buttons
                             button value = {action_id, key, nonce}

Approver taps [Approve]
  └─ Slack ──▶ k3dm-slack-relay  POST /slack/interactivity   (payload=<urlenc json>)
                 worker:
                   1. verifySlack() signature + 5-min window            (exists)
                   2. approver ∈ APPROVER_ALLOWLIST                      (new)
                   3. reauth:<user> present in KV (24h TTL)              (new; §5.3)
                   4. KV put  approval:<action_id> = {approved_by, at}   (new)
                   5. update the Slack message via payload.response_url  ("✅ Approved by @u")

Hermes next poll
  └─ drain_approvals() ──▶ GET  https://<relay>/hermes/approvals   (Bearer drain-token)   (new; §5.4)
       for each {action_id, approved_by}:
         repairs.approve(action_id, state, records_now, _repair_runner)  (UNCHANGED)
         DELETE https://<relay>/hermes/approvals/<action_id>            (new)
```

Hermes' poll cadence is its existing launchd `StartInterval` — approvals apply on the next tick (bounded
latency, acceptable for repairs; note it in the guide). No new timer.

## 5. Detailed design

### 5.1 Hermes posts an interactive proposal

Extend `slack.py` with `post_interactive(relay_url, text, blocks, opener=urllib.request.urlopen)` that POSTs
`{"text": text, "blocks": blocks, "response_type": "in_channel"}` to the incoming webhook. Incoming-webhook
messages support Block Kit; button clicks reach the app's Interactivity Request URL as long as interactivity
is enabled on the Slack app.

In `bin/k3dm-hermes._run_cycle`, when `event["kind"] == "incident"` and `proposals` is non-empty, build one
`actions` block per proposal with two buttons:

```
{ "type": "actions", "block_id": "<action_id>", "elements": [
  { "type": "button", "action_id": "hermes_approve", "style": "primary",
    "text": {"type":"plain_text","text":"Approve"}, "value": "<action_id>",
    "confirm": { … "Approve <name>? Blast radius: <blast_radius>" } },
  { "type": "button", "action_id": "hermes_deny", "style": "danger",
    "text": {"type":"plain_text","text":"Deny"}, "value": "<action_id>" }
]}
```

The human-readable `command` / `blast_radius` / `evidence` already exist on each proposal (`repairs.propose`).
Keep the existing "Approve with: bin/k3dm-hermes approve …" CLI line as a fallback in the text body.

**Nonce/anti-stale:** include the proposal `proposed_at` (or a short random nonce persisted in
`state["pending_repairs"][action_id]`) in the button `value` as `"<action_id>|<nonce>"`; the worker echoes it
and Hermes ignores a drained approval whose nonce no longer matches the current pending proposal. This stops a
tapped button from a previous, superseded incident from applying. (`action_id` is already a stable sha1 of
key+command, so it is stable across identical re-proposals; the nonce guards the *incident*, not the command.)

### 5.2 Worker: `/slack/interactivity`

Add a branch in `handle()` for `pathname === '/slack/interactivity'`:
- Read raw body, `verifySlack(req, body)` (reuse — same signing secret, same 5-min window). Reject 401 otherwise.
- Parse `payload = JSON.parse(new URLSearchParams(body).get('payload'))`. Expect `payload.type === 'block_actions'`.
- `user = payload.user.id` / `payload.user.username`. **Approver allowlist:** require `user.id ∈ APPROVER_ALLOWLIST`
  (a new worker secret, comma-separated Slack user IDs — NOT the slash-command role map; approvers are a small
  admin set). Reject with an ephemeral "not authorized to approve" via `payload.response_url` otherwise, and
  do not write KV.
- **24h re-auth gate (§5.3):** require `await APPROVALS_KV.get('reauth:' + user.id)` to be non-null. If absent
  (expired or never done), respond via `response_url`: "Re-authenticate first: run `/hermes-auth`" and stop.
- Read `action = payload.actions[0]`. If `action.action_id === 'hermes_approve'`:
  `await APPROVALS_KV.put('approval:' + actionId, JSON.stringify({approved_by:user.id, approved_at:Date.now(), nonce}), {expirationTtl: 3600})`
  then update the message via `payload.response_url` → "✅ Approved by <@user> — applying on next Hermes poll".
  If `hermes_deny`: write `deny:<action_id>` (short TTL, informational) and update message → "🚫 Denied by <@user>".
- Always return `200` quickly (Slack requires <3s); heavy work via `event.waitUntil`.

### 5.3 Worker: `/hermes-auth` slash command (the 24h re-auth)

Slack does not expose MFA state to the worker, so "re-authenticate every 24h" is implemented as a **short-lived
re-auth stamp**. Add `/hermes-auth` to `ALLOWED_COMMANDS` (role admin) and a handler:
- Verify signature (already done for the slash-command path).
- Require `user_id ∈ APPROVER_ALLOWLIST`.
- `await APPROVALS_KV.put('reauth:' + userId, '1', {expirationTtl: 86400})`.
- Ephemeral reply: "🔐 Re-authenticated for 24h — you can now approve Hermes repairs."

The channel-level **MFA** the user enabled means the act of issuing `/hermes-auth` (and tapping Approve) already
happens behind Slack's MFA challenge; the KV TTL enforces the *24h* recurrence. After 24h the stamp expires and
the next Approve tap is refused until `/hermes-auth` is run again. Document this clearly in the guide.

### 5.4 Worker: authenticated drain API for Hermes

- `GET /hermes/approvals` — require `Authorization: Bearer <APPROVAL_DRAIN_TOKEN>` (new worker secret),
  compared in constant time. List `approval:*` keys (KV `list({prefix:'approval:'})`), return the JSON array
  (each item: `action_id`, `approved_by`, `approved_at`, `nonce`). No Slack signature here — this is the
  Hermes↔worker channel, guarded by the drain bearer only.
- `DELETE /hermes/approvals/:action_id` — same bearer; `APPROVALS_KV.delete('approval:'+id)`. Hermes deletes
  after applying (whether executed, skipped, or refused) so a stale approval is not retried forever.
- Rate-limit / cap the list size defensively (KV list is bounded; approvals TTL is 1h).

### 5.5 Hermes: drain on poll

New `scripts/lib/hermes/approvals.py`:
- `fetch_approvals(get_json, drain_url, token)` → GET the worker, return list (fail-closed to `[]` on any error).
- `delete_approval(opener, drain_url, token, action_id)` → DELETE, best-effort.

In `bin/k3dm-hermes.main()` **default (no-arg) poll branch**, after `_run_cycle` and before/after posting the
summary:
```
drain_url = os.environ.get("K3DM_HERMES_APPROVAL_DRAIN_URL", "")   # https://<relay>/hermes/approvals
token     = _keychain_secret("k3dm-hermes-approval-drain-token")
for appr in fetch_approvals(_http_get_json, drain_url, token):
    action_id, nonce = appr["action_id"], appr.get("nonce")
    pending = state.get("pending_repairs", {}).get(action_id)
    if not pending or (nonce and pending.get("nonce") != nonce):
        delete_approval(...)                    # stale/superseded — drop
        continue
    records_now, _ = _run_cycle(state)          # fresh sample (approve() re-checks precondition anyway)
    outcome = repairs.approve(action_id, state, records_now, _repair_runner)
    post_summary(relay, f"Hermes repair {action_id} ({pending['name']}) approved by {appr['approved_by']}: {outcome['outcome']}")
    delete_approval(...)
_save_state(...)
```
`repairs.approve()` is called **exactly as the CLI path calls it** — no behavior fork. If the drain URL/token
are unset, the block is a no-op and Hermes behaves exactly as today (safe default; feature is opt-in).

## 6. KV schema (namespace `APPROVALS_KV`)

| Key | Value | TTL | Written by |
|-----|-------|-----|------------|
| `reauth:<slack_user_id>` | `"1"` | 86400s (24h) | worker `/hermes-auth` |
| `approval:<action_id>` | `{approved_by, approved_at, nonce}` | 3600s | worker `/slack/interactivity` (approve) |

All keys expire on their own; Hermes also deletes `approval:*` after processing.

## 7. Security requirements (checklist for the implementation)

- [ ] Slack signature verified on `/slack/interactivity` and `/hermes-auth` (reuse `verifySlack`, 5-min window).
- [ ] Approver allowlist enforced by **Slack user ID** (not username — usernames are mutable), separate secret.
- [ ] 24h re-auth stamp required before any approval is written to KV.
- [ ] Drain endpoints require a dedicated bearer (`APPROVAL_DRAIN_TOKEN`), constant-time compared; never logged.
- [ ] `repairs.approve()` unchanged — precondition re-validation + one-attempt-per-incident still the last word.
- [ ] Nonce guards against a stale button from a superseded incident applying.
- [ ] No secret in argv/logs (Hermes drain token via Keychain; worker secrets via `wrangler secret put`).
- [ ] Approval/deny actions are audited: the worker updates the Slack message with the approver; Hermes appends
      to `state["repair_audit"]` (already done by `approve()`) and posts the outcome + approver to Slack.
- [ ] Worker still returns within Slack's 3s budget (KV ops + `event.waitUntil`).

## 11. Open decisions (resolve at review, before slice 1)

- **Drain transport:** worker drain endpoint (this spec) vs. Hermes reading KV via the Cloudflare API with a
  scoped API token. Spec chooses the worker endpoint — one fewer credential class on the laptop, outbound-only.
- **Approval latency:** apply on next poll (this spec) vs. shortening Hermes `StartInterval` when a proposal is
  outstanding. Spec keeps the fixed interval; note the latency in the guide.
- **Deny semantics:** does a Deny mark the incident's repair attempted (suppress re-proposal until resolve) or
  just dismiss the message? Spec leans "dismiss only"; confirm.

## 13. Implementation spec (resolved 2026-09-13 — this section supersedes §3–§6 where they differ)

### 13.0 Resolved decisions

| §11 question | Decision |
|---|---|
| Drain transport | Worker endpoint `GET/DELETE /hermes/approvals` guarded by a dedicated bearer. No Cloudflare API token on the laptop. |
| Approval latency | Next normal poll (launchd `StartInterval` 300s). No interval change. Documented in the guide. |
| Deny semantics | **Dismiss only.** Deny updates the Slack message with the denier and writes **nothing** to KV; Hermes may re-propose. |
| Scope | All 5 code slices land in v1.33.0 **switched off**. With `K3DM_HERMES_APPROVAL_DRAIN_URL` unset, Hermes behaves exactly as today (no buttons, no drain). KV namespace, worker secrets, Slack interactivity and the live E2E are operator steps (§13.6). |

Deviations from §5, each with a reason:
- **Nonce = per-incident random**, stored as `state["incident_nonce"]` by `bin/k3dm-hermes` (not `proposed_at`). `repairs.propose()` rewrites `proposed_at` every poll, so a `proposed_at` nonce would expire every 5 minutes. `repairs.py` stays unchanged.
- **Buttons are posted only when the drain URL is set.** Otherwise the buttons would lead nowhere.
- **`wrangler.toml` gets a commented-out KV binding template only.** `deploy-worker.yml` deploys on merge to `main`, and an `[[kv_namespaces]]` block without a real namespace `id` breaks that deploy. Every worker code path checks `typeof APPROVALS_KV === 'undefined'` and answers "not configured".
- **Deny requires the allowlist and the 24h re-auth**, the same as Approve, so a non-approver cannot dismiss a proposal.

**W3.** Insert these functions immediately **before** `async function relay(`:

```js
function constantTimeEqual(a, b) {
  if (typeof a !== 'string' || typeof b !== 'string' || a.length !== b.length) return false
  let diff = 0
  for (let i = 0; i < a.length; i++) diff |= a.charCodeAt(i) ^ b.charCodeAt(i)
  return diff === 0
}

function approvalsKv() {
  return typeof APPROVALS_KV === 'undefined' ? null : APPROVALS_KV
}

function approverAllowed(userId) {
  const raw = typeof APPROVER_ALLOWLIST === 'undefined' ? '' : String(APPROVER_ALLOWLIST)
  return !!userId && raw.split(',').map(s => s.trim()).filter(Boolean).includes(userId)
}

function drainAuthorized(req) {
  const token = typeof APPROVAL_DRAIN_TOKEN === 'undefined' ? '' : String(APPROVAL_DRAIN_TOKEN)
  if (token.length < 32) return false
  return constantTimeEqual(req.headers.get('Authorization') || '', `Bearer ${token}`)
}

async function handleDrain(req, pathname) {
  if (!drainAuthorized(req)) return new Response('Unauthorized', { status: 401 })
  const kv = approvalsKv()
  if (!kv) return new Response('Approvals not configured', { status: 503 })
  if (req.method === 'GET' && pathname === '/hermes/approvals') {
    const listed = await kv.list({ prefix: 'approval:', limit: 50 })
    const items = []
    for (const key of listed.keys || []) {
      const raw = await kv.get(key.name)
      if (!raw) continue
      let value
      try { value = JSON.parse(raw) } catch (_) { continue }
      items.push({
        action_id: key.name.slice('approval:'.length),
        approved_by: String(value.approved_by || ''),
        approved_at: Number(value.approved_at || 0),
        nonce: String(value.nonce || ''),
      })
    }
    return new Response(JSON.stringify(items), { status: 200, headers: { 'Content-Type': 'application/json' } })
  }
  const match = pathname.match(/^\/hermes\/approvals\/([A-Za-z0-9-]{1,64})$/)
  if (req.method === 'DELETE' && match) {
    await kv.delete(`approval:${match[1]}`)
    return new Response(null, { status: 204 })
  }
  return new Response('Not Found', { status: 404 })
}

async function handleInteractivity(req, event) {
  const body = await req.text()
  if (!await verifySlack(req, body)) return new Response('Unauthorized', { status: 401 })
  let payload
  try { payload = JSON.parse(new URLSearchParams(body).get('payload') || '') } catch (_) {
    return new Response('Bad Request', { status: 400 })
  }
  if (!payload || payload.type !== 'block_actions') return new Response('', { status: 200 })
  const action      = (payload.actions || [])[0] || {}
  const userId      = (payload.user && payload.user.id) || ''
  const responseUrl = payload.response_url || ''
  const [actionId, nonce] = String(action.value || '').split('|')
  if (!['hermes_approve', 'hermes_deny'].includes(action.action_id) ||
      !HERMES_ACTION_ID_RE.test(actionId || '') || !HERMES_NONCE_RE.test(nonce || '')) {
    return new Response('', { status: 200 })
  }
  event.waitUntil((async () => {
    const kv = approvalsKv()
    if (!kv) return postResponseUrl(responseUrl, '⚠️ Hermes approvals are not configured on the relay')
    if (!approverAllowed(userId)) return postResponseUrl(responseUrl, '⛔ You are not authorized to approve Hermes repairs')
    if (!await kv.get(`reauth:${userId}`)) {
      return postResponseUrl(responseUrl, '🔐 Re-authenticate first: run `/hermes-auth` (valid for 24h)')
    }
    if (action.action_id === 'hermes_approve') {
      await kv.put(`approval:${actionId}`,
        JSON.stringify({ approved_by: userId, approved_at: Date.now(), nonce }),
        { expirationTtl: APPROVAL_TTL_SECONDS })
      return replaceResponseUrl(responseUrl, `✅ ${actionId} approved by <@${userId}> — applying on the next Hermes poll (up to ~5 min)`)
    }
    return replaceResponseUrl(responseUrl, `🚫 ${actionId} denied by <@${userId}> — dismissed; Hermes may propose it again`)
  })())
  return new Response('', { status: 200 })
}
```

```python
"""Hermes pull-model Slack approvals: drain approved action-ids from the relay worker.

The worker only records intent. Every drained approval still goes through the
unchanged repairs.approve(), which re-validates the precondition and enforces
one attempt per incident.
"""

import json
import re
import urllib.parse
import urllib.request

APPROVAL_DRAIN_SERVICE = "k3dm-hermes-approval-drain-token"
ACTION_ID_RE = re.compile(r"^r[0-9]+-[0-9a-f]{8}$")
NONCE_RE = re.compile(r"^[0-9a-f]{16}$")
SLACK_USER_RE = re.compile(r"^[A-Z0-9]{2,32}$")


def _usable(drain_url, token):
    return bool(token) and str(drain_url).startswith("https://")


def fetch_approvals(drain_url, token, opener=urllib.request.urlopen, timeout=10):
    """Return well-formed approvals from the relay; fail closed to [] on any error."""
    if not _usable(drain_url, token):
        return []
    request = urllib.request.Request(drain_url, method="GET",
                                     headers={"Authorization": f"Bearer {token}"})
    try:
        with opener(request, timeout=timeout) as response:
            items = json.loads(response.read())
    except Exception:
        return []
    if not isinstance(items, list):
        return []
    return [item for item in items
            if isinstance(item, dict)
            and ACTION_ID_RE.match(str(item.get("action_id", "")))
            and NONCE_RE.match(str(item.get("nonce", "")))
            and SLACK_USER_RE.match(str(item.get("approved_by", "")))]


def delete_approval(drain_url, token, action_id, opener=urllib.request.urlopen, timeout=10):
    """Best-effort removal of a processed approval; return success."""
    if not _usable(drain_url, token) or not ACTION_ID_RE.match(str(action_id)):
        return False
    url = f"{drain_url.rstrip('/')}/{urllib.parse.quote(action_id)}"
    request = urllib.request.Request(url, method="DELETE",
                                     headers={"Authorization": f"Bearer {token}"})
    try:
        with opener(request, timeout=timeout):
            return True
    except Exception:
        return False


def interactive_blocks(message, proposals, nonce):
    """Block Kit: the summary plus Approve/Deny buttons carrying '<action_id>|<nonce>'."""
    blocks = [{"type": "section", "text": {"type": "mrkdwn", "text": message[:2900]}}]
    for item in proposals:
        value = f"{item['action_id']}|{nonce}"
        detail = f"*{item['name']}* (`{item['action_id']}`)\nBlast radius: {item['blast_radius']}"
        blocks.append({"type": "section", "text": {"type": "mrkdwn", "text": detail[:2900]}})
        blocks.append({"type": "actions", "block_id": item["action_id"], "elements": [
            {"type": "button", "action_id": "hermes_approve", "style": "primary",
             "text": {"type": "plain_text", "text": "Approve"}, "value": value,
             "confirm": {"title": {"type": "plain_text", "text": "Approve repair?"},
                         "text": {"type": "plain_text",
                                  "text": f"Run {item['name']}? Blast radius: {item['blast_radius']}"[:300]},
                         "confirm": {"type": "plain_text", "text": "Approve"},
                         "deny": {"type": "plain_text", "text": "Cancel"}}},
            {"type": "button", "action_id": "hermes_deny", "style": "danger",
             "text": {"type": "plain_text", "text": "Deny"}, "value": value},
        ]})
    return blocks
```
