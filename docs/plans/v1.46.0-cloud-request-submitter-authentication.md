## Why rev 1 was replaced

Rev 1 proposed Ed25519 request signing with a key per agent. A cloud session holds no credential by policy
(`docs/howto/cloud-session-requests.md`, "The short version"), so a cloud agent's signing key would have to live in its cloud
environment next to its GitHub token: a stolen session would get both. Signing would stop other connectors, not a compromised session.
The operator chose an approval gate instead (2026-11-25).

A GitHub ruleset limiting who can push `cloud-requests` was considered and dropped. `git log origin/cloud-requests -200` (2026-11-25,
M4) shows every commit authored as the operator (`chengkai liang` 118, `chengkai` 58, `t` 24; none signed): cloud sessions push with the
operator's own GitHub identity, so a ruleset cannot tell them apart.

## Threat model

- **Attacker:** anyone who can push to `cloud-requests` (a cloud session, a leaked token with repo write, a misbehaving agent). The repo
  is public, so everything on the branch is public.
- **Asset:** the cloud-runner set. Today these run on push alone: `sandbox-up` and `sandbox-down` (provider fixed to `aws`; cost money),
  `make-e2e` and `make-e2e-remote` (`scripts/lib/webhook/cloud_actions.py:21-22,38-39`; token choice `bin/k3dm-cloud-bridge:332`).
- **Not in scope:** reader actions (read-only, unchanged and never delayed), the webhook's own auth, Slack account takeover (the relay
  already requires the approver allowlist and a fresh `/hermes-auth` re-auth per press, `workers/slack-relay/index.js:267-275`).
- **Goal:** no cloud-runner request reaches the webhook, or reads the cloud-runner token, without an operator pressing Approve on a
  card that shows that exact request, before the request expires.

## Design

1. **Gate.** The bridge has one predicate, `gated(action)`, true exactly when the action uses the cloud-runner token. The token choice at
   `bin/k3dm-cloud-bridge:332` and the gate both call it, so they cannot drift. A gated request that passes `prepare_request` is not sent;
   it becomes a pending approval.
2. **Pending approval.** Stored in `STATE_DIR/approvals.json` (mode 0600, atomic replace), so it survives a bridge restart. Each record:
   the request id, an approval id `c1-<8 hex>`, a 16-hex nonce, the validated request as the bridge parsed it, `created_at` and
   `expires_at` (the request's own `expires_at`, at most `REQUEST_TTL_SECONDS` = 30 min ahead; `bin/k3dm-cloud-bridge:34`). Caps: at
   most 3 pending at once and 10 cards per rolling hour; a request over a cap is rejected, so a pusher cannot flood Slack.
3. **Card.** Posted with the existing Hermes helpers: `interactive_blocks` and `post_interactive` (`scripts/lib/hermes/approvals.py:62`,
   `scripts/lib/hermes/slack.py:47`), to the relay URL in Keychain `k3dm-slack-webhook` (as `bin/k3dm-dispatch-recover:149` does). It
   shows the request id, action, arguments, a fixed blast-radius line per action, the expiry, and `requested_by` labelled as not verified.
   Buttons carry `<approval id>|<nonce>`.
4. **Approval.** The operator presses Approve; the relay (already deployed) checks the Slack signature, the allowlist and the re-auth, and
   stores the approval for 1 h. Each tick, while any request is pending, the bridge drains approvals matching `^c[0-9]+-[0-9a-f]{8}$`
   from `K3DM_HERMES_APPROVAL_DRAIN_URL` with the Keychain drain token `k3dm-hermes-approval-drain-token`
   (`fetch_approvals`/`delete_approval`, `approvals.py:26,47`). Hermes (`r`) and dispatch-recover (`d`) filter by their own prefixes and
   delete only their own ids, so a third prefix does not interfere.
5. **Decision.** An approval whose id and nonce match a pending record that has not expired runs the **stored** request through the
   existing path (webhook call, artifacts, watch, response commit), so a request file changed on the branch after the card is posted does
   not change what runs. A wrong nonce, an unknown id or an expired record never runs anything; the approval is deleted. Deny writes
   nothing on the relay (`index.js:288`), so a denied or ignored request expires and is answered `rejected`.
6. **Responses.** While pending, the bridge commits `responses/<id>.pending.json` (status `ok`, body `{"status": "approval-pending",
   "approval_id", "expires_at"}`; no nonce) without recording the id as processed. The final answer is the normal
   `responses/<id>.json`: the webhook result after approval, or `rejected` with a stable reason. Status values stay `ok`, `rejected`,
   `error`, so an old helper keeps working (it waits for `responses/<id>.json` and times out after its default 300 s).
7. **Fail closed.** Missing drain URL, drain token or relay URL: a gated request is rejected at once; reader actions are unaffected.

## Contract between the children

| Name | Owner | Readers |
|---|---|---|
| `scripts/lib/webhook/cloud_approval.py` API (below) | a | b |
| `responses/<id>.pending.json` shape | b | d, e |
| Approval id `^c[0-9]+-[0-9a-f]{8}$`, nonce `^[0-9a-f]{16}$` | a | b, c |
| Rejection reasons (below) | b | d (prints them), e |
| `K3DM_HERMES_APPROVAL_DRAIN_URL` in the bridge plist | b | e |

`cloud_approval.py` API (child a writes it; b only calls it):
- `CLOUD_ACTION_ID_RE`, `NONCE_RE`, `MAX_PENDING = 3`, `MAX_CARDS_PER_HOUR = 10`.
- `load(path) -> Store` (missing file: empty store; unreadable or malformed: raise `StoreError`, never an empty store),
  `save(path, store)` (0600, temp file + `os.replace`).
- `admit(store, request_id, request, now, rand=secrets) -> Pending | Refusal`: applies both caps, makes the ids, adds the record and the
  card time. `Refusal.reason` is one of the reasons below.
- `card(pending) -> (text, blocks)`.
- `decide(store, approvals, now) -> list[Decision]` and removes decided records from `store`: `Decision.kind` is `execute` (with the
  stored request), `expire` (with the request id), or `drop` (with the approval id to delete). Pure: no I/O, no clock.

Rejection reasons (exact text, in `responses/<id>.json` `reason`):
`operator approval is not configured on the bridge`, `too many requests awaiting approval; try again later`,
`approval card not delivered; file a new request`, `not approved before the request expired`.
