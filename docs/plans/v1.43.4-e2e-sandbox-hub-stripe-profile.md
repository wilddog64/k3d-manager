**Status:** IMPLEMENTED — 2026-10-16 by Codex, Claude-verified (overlay location corrected; see item 1); live proof pending

**Release:** v1.43.4 (plan 4 of 5)

**Fixes:** `docs/bugs/2026-10-16-e2e-sandbox-rebuilds-platform-hub-already-deploys.md` (P2)
**Component:** `scripts/plugins/e2e.sh`, `scripts/plugins/argocd.sh`,
`scripts/etc/argocd/applicationsets/services-git.yaml`, `services/shopping-cart-{order,payment}/`

## Problem

`e2e_verify_sandbox` (Tier 2) still sets the sandbox up as if it were bare. `cluster-up` now
registers the sandbox with the hub (`cicd/cluster-ubuntu-k3s` on `k3d-k3d-cluster`), and the hub's
app-cluster ApplicationSets deploy the whole platform to it. The run fails at `configuring-vault`
(`env: 'vault': No such file or directory`, exit 127), and the `applying-appsets` step after it would
start a second Argo CD fighting the hub over the same resources. See the bug doc for the evidence.

## Decisions (design a′, approved)

- **Remove** from Tier 2: the in-cluster registration Secret, the whole `configuring-vault` phase
  (`shopping_cart_create_vault_bridge`, `_e2e_sandbox_configure_vault_token_review`, the
  `vault-backend` store apply and wait), the `applying-appsets` loop, and the direct
  ConfigMap overrides with their manual apply. The hub already runs ESO, the store and the services.
- **Stripe mode is a per-cluster profile chosen by a label on the hub's registration Secret**,
  `k3dm.k3d.io/e2e-profile`, value `none` or `stripe`. The `services-git` ApplicationSet points the
  order and payment Applications at an `e2e-stripe` kustomize overlay when the label is `stripe`.
  The same Applications keep their names, so Argo CD updates them in place.
- **`cluster-up` always writes `k3dm.k3d.io/e2e-profile: "none"`** in the registration it renders.
  `kubectl apply` does not remove a label that `kubectl label` added, so writing the value
  explicitly is what keeps a label left by a crashed run from carrying into a rebuilt sandbox.
- **The overlay carries all four settings the old overrides set.** The bug doc suggested moving the
  order URLs and `oauth2.jwk-set-uri` into the base for `ubuntu-k3s`. The base is shared with
  `ubuntu-hostinger` (also `k3d-manager/shopping-cart: "true"`), so a base change would need yet
  another per-cluster switch. That fix stays a follow-up; this spec keeps parity with today's run.
- **Hub coupling.** The run needs the hub to set the label. Context `E2E_HUB_CONTEXT`, default
  `k3d-k3d-cluster`; namespace `E2E_HUB_ARGOCD_NAMESPACE`, default `cicd`. A hub that does not
  answer `/readyz` fails the run before the sandbox extension.
- **Clean-up runs on success and on failure.** It sets the label back to `none`, waits (bounded,
  best effort) for `payment.gateway.default` to read `mock`, and restarts order and payment so the
  idle sandbox runs mock. Failures here are logged and never change the run's exit code.

```yaml
  - ../../services/shopping-cart-payment
patches:

      apiVersion: v1

    target:

```
**Correction (Claude, 2026-10-16, at verification):** the first draft put each overlay under its
base (`services/<svc>/e2e-stripe/` with `resources: [..]`). Kustomize rejects that as a cycle
(`candidate root … contains visited root …`), and Argo CD's repo-server would too. The overlays
live in a top-level `services-e2e-stripe/<svc>/` directory and reference `../../services/<svc>`.
They sit outside the `services/*` directory generator, so neither becomes an Application of its own.

### 2. `scripts/etc/argocd/applicationsets/services-git.yaml`

old:
```yaml
        path: '{{.path.path}}'
```
new:
```yaml
        path: '{{ if and (eq (index .metadata.labels "k3dm.k3d.io/e2e-profile") "stripe") (has .path.basename (list "shopping-cart-order" "shopping-cart-payment")) }}services-e2e-stripe/{{.path.basename}}{{ else }}{{.path.path}}{{ end }}'
```

### 4. `scripts/plugins/e2e.sh`

Delete `_e2e_sandbox_argocd_ready`, `_e2e_sandbox_argocd_cluster_manifest`,
`_e2e_sandbox_render_overrides`, `_e2e_sandbox_vault_store_manifest` and
`_e2e_sandbox_configure_vault_token_review`. Add:

```bash
function _e2e_hub_kc() {
  _run_command -- kubectl --context "${E2E_HUB_CONTEXT:-k3d-k3d-cluster}" "$@"
}

function _e2e_sandbox_preflight_hub() {
  local ctx="${E2E_HUB_CONTEXT:-k3d-k3d-cluster}" timeout="${E2E_SANDBOX_PROBE_TIMEOUT:-15}"
  if ! kubectl --context "$ctx" get --raw=/readyz --request-timeout="${timeout}s" >/dev/null 2>&1; then
    _err "[e2e] hub preflight: kubecontext ${ctx} did not answer /readyz within ${timeout}s; Tier 2 switches the sandbox to Stripe through the hub's ubuntu-k3s registration, so the hub must be up — start it (make up) and rerun Tier 2"
    return 1
  fi
  _info "[e2e] hub preflight: context=${ctx} readyz=ok"
}

function _e2e_sandbox_hub_apps_ready() {
  local ns="${E2E_HUB_ARGOCD_NAMESPACE:-cicd}" listing bad
  listing="$(_e2e_hub_kc -n "$ns" get applications.argoproj.io \
    -o 'jsonpath={range .items[?(@.spec.destination.name=="ubuntu-k3s")]}{.metadata.name}{" "}{.status.sync.status}{" "}{.status.health.status}{"\n"}{end}')"
  if [[ -z "$listing" ]]; then
    _err "[e2e] hub Applications: none target ubuntu-k3s in ${ns}; cluster-up registers the sandbox with the hub — rerun make up with the k3s-aws provider"
    return 1
  fi
  bad="$(awk '$2 != "Synced" || $3 != "Healthy"' <<< "$listing")"
  if [[ -n "$bad" ]]; then
    _err "[e2e] hub Applications for ubuntu-k3s are not all Synced and Healthy: $(tr '\n' ';' <<< "$bad")"
    return 1
  fi
  _info "[e2e] hub Applications for ubuntu-k3s: $(wc -l <<< "$listing" | tr -d ' ') Synced and Healthy"
}

function _e2e_sandbox_set_profile() {
  local profile="${1:?profile required}" ns="${E2E_HUB_ARGOCD_NAMESPACE:-cicd}" app
  _e2e_hub_kc -n "$ns" label secret -l argocd.argoproj.io/cluster-name=ubuntu-k3s \
    "k3dm.k3d.io/e2e-profile=${profile}" --overwrite
  for app in ubuntu-k3s-shopping-cart-order ubuntu-k3s-shopping-cart-payment; do
    _run_command --soft -- kubectl --context "${E2E_HUB_CONTEXT:-k3d-k3d-cluster}" -n "$ns" \
      annotate "application.argoproj.io/${app}" argocd.argoproj.io/refresh=normal --overwrite || true
  done
}

function _e2e_sandbox_wait_gateway() {
  local want="${1:?gateway required}" timeout="${E2E_PROFILE_SYNC_TIMEOUT:-300}" deadline got
  deadline=$(( $(date +%s) + timeout ))
  while :; do
    got="$(_run_command --soft --quiet -- kubectl --context ubuntu-k3s -n shopping-cart-payment \
      get configmap payment-service-config -o 'jsonpath={.data.payment\.gateway\.default}' 2>/dev/null || true)"
    [[ "$got" == "$want" ]] && return 0
    (( $(date +%s) < deadline )) || {
      _warn "[e2e] payment.gateway.default is '${got}', not '${want}', after ${timeout}s"
      return 1
    }
    sleep 5
  done
}

function _e2e_sandbox_enable_stripe() {
  _E2E_PROFILE_SET=1
  _e2e_sandbox_set_profile stripe
  _e2e_sandbox_wait_gateway stripe
  _e2e_sandbox_kc -n shopping-cart-apps rollout restart deployment/order-service
  _e2e_sandbox_kc -n shopping-cart-payment rollout restart deployment/payment-service
  _e2e_sandbox_kc -n shopping-cart-apps rollout status deployment/order-service --timeout="${E2E_ROLLOUT_TIMEOUT}s"
  _e2e_sandbox_kc -n shopping-cart-payment rollout status deployment/payment-service --timeout="${E2E_ROLLOUT_TIMEOUT}s"
}

function _e2e_sandbox_clear_profile() {
  [[ "${_E2E_PROFILE_SET:-0}" == "1" ]] || return 0
  _E2E_PROFILE_SET=0
  _e2e_sandbox_set_profile none || _warn "[e2e] could not reset k3dm.k3d.io/e2e-profile to none on the hub"
  _e2e_sandbox_wait_gateway mock || true
  _run_command --soft -- kubectl --context ubuntu-k3s -n shopping-cart-apps rollout restart deployment/order-service || true
  _run_command --soft -- kubectl --context ubuntu-k3s -n shopping-cart-payment rollout restart deployment/payment-service || true
  _info "[e2e] sandbox profile reset to none"
}
```
Use `_run_command --soft` only if that flag exists in this tree; `_e2e_sandbox_argocd_ready`
already uses it, so it does. If `awk` or `wc` use trips the repo's lint, keep behaviour identical.

In `e2e_verify_sandbox`:
- after `_e2e_sandbox_preflight_cluster`, add `_E2E_ACTIVE_PHASE="preflight-hub"` and
  `_e2e_sandbox_preflight_hub` (before `extending-sandbox`);
- replace everything from `_E2E_ACTIVE_PHASE="checking-argocd"` up to, not including,
  `_E2E_ACTIVE_PHASE="running-playwright"` with:
  ```bash

  _e2e_sandbox_hub_apps_ready

  _E2E_ACTIVE_PHASE="enabling-stripe"
  _e2e_sandbox_enable_stripe
  ```
- set `_E2E_PROFILE_SET=0` next to `_E2E_SUMMARY_WRITTEN=0` at the start;

## Operational Requirements

| Item | Requirement |
|---|---|
| Resources | One label write and two refresh annotations on the hub per run; one ConfigMap poll every 5 s for ≤ 300 s. |
| Security | No new credentials. Removes a path that wrote a ServiceAccount token to `$TMPDIR`. The Stripe key stays in the run-scoped `stripe-e2e` Secret. |
| Failure mode | A crashed run can leave `stripe` on the hub registration; the next `cluster-up` resets it to `none`, and the next Tier 2 run resets it on exit. |
| Rollout | Live only after `make appsets-reapply` on the release branch (the ApplicationSet changes) and a `cluster-up` that re-renders the registration (or the label is absent, which renders the base). |
| Proof it works | `make e2e-sandbox` passes `checking-hub-apps` and `enabling-stripe`, the Playwright job runs, and afterwards the hub registration reads `e2e-profile=none` and the sandbox `payment.gateway.default` reads `mock`. |
