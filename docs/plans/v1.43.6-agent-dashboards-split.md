## Problem

The Agent Dispatch dashboard has 64 panels in seven sections. It covers dispatch throughput, cost,
Claude context, all Codex and agy activity, quota efficiency, and run outcomes. The operator finds it
too hard to navigate. Half its sections also only work for 1d/7d/30d, so choosing a release in
**Window** shows No data for them.

## Change

Move panels into three dashboards. Keep every panel's `id`, `title`, `type`, `targets`,
`fieldConfig` and `options` unchanged. Change only `gridPos`, plus the row titles listed below. No
exporter change.

| Dashboard | File | uid | Window variable | Panels (by id) |
|---|---|---|---|---|
| k3dm Agent Dispatch | `grafana-dashboard-agent-dispatch.yaml` (existing) | `k3dm-agent-dispatch` | unchanged (query over `k3dm_dispatch_landed`, default 7d) | 1–13; 40, 41; row 42 and 43–48 |
| k3dm Agent Cost | `grafana-dashboard-agent-cost.yaml` (new) | `k3dm-agent-cost` | same query variable as Agent Dispatch | row 19 and 20–27; 28–32; 34 |
| k3dm Agent Activity | `grafana-dashboard-agent-activity.yaml` (new) | `k3dm-agent-activity` | `custom`, values `1d,7d,30d`, default `7d`, label `Window` | row 33 and 35–39; row 49 and 50–58; row 59 and 60–63; row 64 and 66–71 |

Layout rules:

- On each dashboard, panels keep their current relative order, and rows keep their current order.
- No panel rectangles overlap, and there are no vertical gaps between sections.
- Row 33 becomes `Claude context and compaction`. It no longer holds 34, 40 or 41.
- On Agent Activity, the row titles drop `; 1d/7d/30d only`, because the Window variable only offers time windows there.
  - Row 49: `All Codex activity (including outside the dispatcher)`.
  - Row 64: `All agy activity (including outside the dispatcher)`.

New dashboards copy these from Agent Dispatch:
- `ConfigMap` metadata: namespace `monitoring`, labels `grafana_dashboard: "1"` and `release: kube-prometheus-stack`. The ConfigMap name is the file name without `.yaml`.
- The data key: `agent-cost.json` or `agent-activity.json`.
- The 4-space JSON indentation inside the block scalar.
- `schemaVersion`, `graphTooltip`, `time`, `refresh` and `editable`.
- The `k3d-manager` tag.

Each new dashboard gets a one-sentence `description`. Agent Activity's description says its numbers cover time windows only.

Links. All three dashboards carry the tag `k3dm-agents`. Each has these `links`, in this order:

1. `{"type": "dashboards", "tags": ["k3dm-agents"], "asDropdown": false, "includeVars": true, "keepTime": true, "title": "Agents"}`
2. The existing `Bug Tracking` link, unchanged.

`includeVars` carries `window` between dashboards. A release value passed to Agent Activity is not one of its options, so Grafana falls back to its default, 7d. That is acceptable.

Deployment: the hub ApplicationSet `grafana-dashboards-hub` already includes
`scripts/etc/argocd/platform-ops/grafana-dashboard-*.yaml`, so the new files deploy with no
ApplicationSet change. Do not add them to `deploy_argocd_platform_ops`.
