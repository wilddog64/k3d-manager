## API (exact; the bridge task codes against it)

- Constants: `CLOUD_ACTION_ID_RE = re.compile(r"^c[0-9]+-[0-9a-f]{8}$")`, `NONCE_RE = re.compile(r"^[0-9a-f]{16}$")`,
  `MAX_PENDING = 3`, `MAX_CARDS_PER_HOUR = 10`.
- `class StoreError(Exception)`.
- `Store`: a dataclass with `pending: dict[str, Pending]` keyed by request id and `cards: list[float]` (card post times, epoch).
- `Pending`: a dataclass with `request_id: str`, `approval_id: str`, `nonce: str`, `request: dict`, `created_at: float`,
  `expires_at: float`.
- `Refusal`: a dataclass with `reason: str`.
- `Decision`: a dataclass with `kind` (`"execute"`, `"expire"` or `"drop"`), `request_id: str | None`, `request: dict | None`,
  `approval_id: str | None`.
- `load(path) -> Store`: a missing file gives an empty store. A file that is not valid JSON, has the wrong `v`, or has a record that fails
  the field checks (ids and nonce match their patterns, times are numbers) raises `StoreError`. Never return an empty store for a bad
  file: an empty store would let the bridge forget a pending request.
- `save(path, store)`: JSON `{"v": 1, "pending": {...}, "cards": [...]}`; write a temp file in the same directory with mode 0600, then
  `os.replace`. Create the directory if missing with mode 0700.
- `admit(store, request_id, request, now, rand=secrets) -> Pending | Refusal`:
  - drop `cards` entries older than `now - 3600`;
  - `len(store.pending) >= MAX_PENDING` -> `Refusal("too many requests awaiting approval; try again later")`;
  - `len(store.cards) >= MAX_CARDS_PER_HOUR` -> the same refusal;
  - `request_id` already pending -> return that `Pending` unchanged (idempotent);
  - else approval id `"c1-" + rand.token_hex(4)`, nonce `rand.token_hex(8)`, `expires_at` = the request's `expires_at` (ISO 8601 `Z`)
    as epoch, but never later than `now + 1800`; append `now` to `cards`; add and return the record. `admit` does not save.
- `card(pending) -> (text, blocks)`: `blocks = hermes.approvals.interactive_blocks(text, [item], pending.nonce)` with
  `item = {"action_id": pending.approval_id, "name": f"Run cloud request {action}", "blast_radius": BLAST[action]}`.
  - `BLAST`: `sandbox-up` "creates an AWS sandbox; it costs money until sandbox-down", `sandbox-down` "destroys the AWS sandbox and
    everything on it", `make-e2e` "runs the e2e suite on the hub", `make-e2e-remote` "runs the e2e suite on runner <RUNNER arg>". An
    action not in `BLAST` raises `ValueError`.
  - `text`: `Cloud request <request_id> asks to run <action> <args as key=value, space separated>. Submitter not verified
    (requested_by: <value>). Expires <HH:MM> UTC. Deny or ignore to do nothing.` Every value taken from the request (`args` values,
    `requested_by`) has `&`, `<`, `>` replaced by `&amp;`, `&lt;`, `&gt;` and is cut to 120 characters, so text such as `<!channel>`
    cannot ping. The nonce never appears in `text`.
- `decide(store, approvals, now) -> list[Decision]`: `approvals` is the list `fetch_approvals` returns (dicts with `action_id`, `nonce`,
  `approved_by`). For each approval, in order:
  - no pending record has that `approval_id` -> `drop`;
  - nonce differs -> `drop` (the record stays pending);
  - `now >= expires_at` -> `drop`, plus `expire` for that request (record removed);
  - else `execute` with the stored `request` (record removed), plus `drop` for the approval id.
  Then every remaining record with `now >= expires_at` -> `expire` (removed). Two approvals for one record: the first decides, the second
  is `drop`. Pure: no I/O, no clock, no randomness.

## Tests (`scripts/tests/bin/test_cloud_approval.py`, pytest, stdlib only)

Cover each API rule, including: missing vs malformed store file (malformed raises); save mode 0600 and atomic replace (the temp file is
gone; a crash before `os.replace` leaves the old file intact, simulated by patching `os.replace` to raise); caps at exactly 3 pending and
10 cards, and the hourly window sliding; idempotent re-admit; `expires_at` clamped to `now + 1800`; card escaping of `<!channel>` and
`&`; nonce absent from text but present in the button values; every `decide` branch, including wrong nonce keeping the record and the
double-approval case; `decide` making no calls (pass objects whose methods raise).
