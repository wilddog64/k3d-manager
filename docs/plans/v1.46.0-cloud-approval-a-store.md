## Context

The cloud bridge (`bin/k3dm-cloud-bridge`) will hold four action types (`sandbox-up`, `sandbox-down`, `make-e2e`, `make-e2e-remote`)
until the operator presses Approve or Deny on a Slack card. You write the pure module that stores pending requests, builds the card
and decides what each drained decision means. A sibling wires it into the bridge; do not edit the bridge. Everything on the request
except `action` and `args` (which the bridge validated against fixed regexes) is attacker-controlled text.

## API (exact; the bridge task codes against it)

- Constants: `CLOUD_ACTION_ID_RE = re.compile(r"^c[0-9]+-[0-9a-f]{8}$")`, `NONCE_RE = re.compile(r"^[0-9a-f]{16}$")`,
  `REQUESTED_BY_RE = re.compile(r"^[A-Za-z0-9._@:-]{1,64}$")`, `MAX_PENDING = 3`, `MAX_CARDS_PER_HOUR = 10`,
  `MIN_LIFETIME = 300`, `MAX_LIFETIME = 1800`, `DRAIN_INTERVAL = 30`.
- `class StoreError(Exception)`.
- `Store` dataclass: `pending: dict[str, Pending]` (keyed by request id), `cards: list[float]`, `last_drain: float` (0 if never).
- `Pending` dataclass: `request_id`, `approval_id`, `nonce`, `request: dict`, `created_at: float`, `expires_at: float`,
  `notice_published: bool`.
- `Refusal` dataclass: `reason: str`.
- `Decision` dataclass: `kind` (`"execute"`, `"deny"`, `"expire"`, `"drop"`), `request_id: str | None`, `request: dict | None`,
  `approval_id: str | None`, `expires_at: float | None`.
- `load(path) -> Store`: missing file -> empty store. Invalid JSON, wrong `v`, or any record failing the field checks (ids and nonce
  match their patterns, times are finite numbers, `request` is a dict, `notice_published` is a bool) -> raise `StoreError`. Never return
  an empty store for a bad file.
- `save(path, store)`: JSON `{"v": 1, "pending": {...}, "cards": [...], "last_drain": ...}`; temp file in the same directory, mode 0600,
  `os.replace`; create a missing directory with mode 0700.
- `admit(store, request_id, request, now, rand=secrets) -> Pending | Refusal`, in this order:
  1. `request_id` already pending -> return that `Pending` unchanged (idempotent; no cap check);
  2. `expires_at` = the request's `expires_at` parsed with `datetime.fromisoformat` (accept `Z` and any offset), as epoch, then
     `min(expires_at, now + MAX_LIFETIME)`; if `expires_at - now < MIN_LIFETIME` ->
     `Refusal("request expires too soon for approval; file it with at least 5 minutes left")`;
  3. drop `cards` entries older than `now - 3600`; `len(pending) >= MAX_PENDING` or `len(cards) >= MAX_CARDS_PER_HOUR` ->
     `Refusal("too many requests awaiting approval; try again later")`;
  4. approval id `"c1-" + rand.token_hex(4)`, nonce `rand.token_hex(8)`, `notice_published=False`; append `now` to `cards`; add and
     return the record. `admit` does not save.
- `remove(store, request_id)`: drop a record (used when the card post fails); no-op if absent.
- `card(pending) -> (text, blocks)`: `blocks = hermes.approvals.interactive_blocks(text, [item], pending.nonce)` with
  `item = {"action_id": pending.approval_id, "name": f"Run cloud request {action}", "blast_radius": BLAST[action]}`.
  - `BLAST`: `sandbox-up` "creates an AWS sandbox; it costs money until sandbox-down", `sandbox-down` "destroys the AWS sandbox and
    everything on it", `make-e2e` "runs the e2e suite on the hub", `make-e2e-remote` "runs the e2e suite on runner <RUNNER arg>".
    Another action raises `ValueError`.
  - `text`: `` Cloud request `<request_id>` asks to run `<action>` with <args>. Submitter not verified (requested_by: `<rb>`). Expires
    <HH:MM> UTC. Deny or ignore to do nothing. `` where `<args>` is `key=value` pairs (each in a code span; `none` if empty) and `<rb>` is
    `str(requested_by)` if it matches `REQUESTED_BY_RE`, else `(invalid)`. Every value from the request is converted with `str()`,
    has `&`, `<`, `>` replaced by `&amp;`, `&lt;`, `&gt;`, has backticks and control characters (including newlines) removed, and is cut
    to 120 characters. The nonce never appears in `text`.
- `due_for_drain(store, now) -> bool`: `bool(store.pending) and now - store.last_drain >= DRAIN_INTERVAL`.
- `decide(store, items, now) -> list[Decision]`: `items` are drain items (dicts with `action_id`, `nonce`, `approved_by`, and optional
  `decision`, `"approve"` when missing). Sets `store.last_drain = now`. For each item, in order:
  - no pending record has that `approval_id` -> `drop`;
  - nonce differs -> `drop` (record stays);
  - record's `now >= expires_at` -> `drop` plus `expire` (record removed);
  - `decision == "deny"` -> `drop` plus `deny` (record removed);
  - `decision == "approve"` -> `drop` plus `execute` with the stored `request` and `expires_at` (record removed);
  - any other `decision` value -> `drop` (record stays).
  An item whose record a previous item already removed -> `drop`. If both a deny and an approve for one record are present, deny wins
  regardless of order. Then each remaining record with `now >= expires_at` -> `expire` (removed). Pure: no I/O, no clock, no randomness.

## Tests (`scripts/tests/bin/test_cloud_approval.py`, pytest, stdlib only, tmp paths only)

A named test per rule above, including: malformed store raises (bad JSON, wrong `v`, bad nonce, non-bool flag); 0600 mode; atomic replace
(patch `os.replace` to raise: old file intact, no temp file left); idempotent re-admit with a full store; offset expiry
`2026-11-25T13:30:00-08:00`; 5-minute minimum; 30-minute clamp; caps at exactly 3 and 10 with the hour sliding; card escaping of
`<!channel>`, `&`, backticks and a newline; `requested_by` as `{"x": 1}`, `7`, and `"op\n*Verified*"` all render `(invalid)` without
raising; nonce in button values only; every `decide` branch, deny-wins in both orders, double approve, unknown `decision`, drain throttle.
