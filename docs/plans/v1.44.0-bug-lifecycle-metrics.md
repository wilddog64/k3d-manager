## Problem

The k3dm Bug Tracking dashboard (v1.43.0) answers "how many bugs, at what priority, in which
release". The operator asked three questions it cannot answer:

1. **Bug age:** how long has each open P1/P2 been open?
2. **Reopen rate:** how often does a supposedly fixed bug come back?
3. **Fix verification:** was the bug closed after its regression test passed?

What the docs hold today (measured 2026-10-10, 707 docs in `docs/bugs/`):

| Question | Data today | Gap |
|---|---|---|
| Age | 560 file names start `YYYY-MM-DD-`; 308 docs have `**Filed:**` | Nothing publishes it |
| Recurrence | 23 docs have a `## Recurrence` section (the dedup rule appends one instead of filing again) | No date or count per recurrence; a closed→open Status edit leaves no trace |
| Verification | about 524 closed docs have a date in Status; 144 cite a SHA; 196 mention a regression or mutation test in prose | No structured test reference, and no evidence that the test ran green before close |

## Definitions (the contract every item uses)

Three new header lines. They sit with the other header lines, under `**Priority:**`.

| Line | Form | Meaning |
|---|---|---|
| `**Filed:**` | `**Filed:** YYYY-MM-DD` (free text may follow after ` — ` or `, `) | Date the bug was filed. Already the convention; now required on new docs. |
| `**Recurred:**` | `**Recurred:** YYYY-MM-DD — <sha or one-line note>` | One line per recurrence. Several lines are allowed. |
| `**Verified by:**` | `**Verified by:** <test ref> — passed YYYY-MM-DDTHH:MM:SSZ at <12-hex sha>` or `**Verified by:** none — <reason>` | The regression test that proves the fix and when it passed. `none` is allowed only for P3. |

`<test ref>` is either:
- `path/to/test_file.py::test_name`, where `path` exists and `test_name` occurs in the file; or
- `path/to/file.bats::<exact @test title>`, where the title occurs in the file as `@test "<title>"`.

`doc_lifecycle(text, path) -> dict` in `scripts/lib/hermes/prior_art.py` is the single parser:

| Key | Value |
|---|---|
| `filed` | the first `^\*\*Filed:\*\*\s*(\d{4}-\d{2}-\d{2})`; else the `YYYY-MM-DD` prefix of the basename; else `None` |
| `closed_on` | when `doc_meta` says `closed`: the first `\d{4}-\d{2}-\d{2}` in the Status value; else `None` |
| `recurred` | sorted list of dates from every `^\*\*Recurred:\*\*\s*(\d{4}-\d{2}-\d{2})` |
| `verified` | `"passed"` when a `**Verified by:**` line has a test ref and a `passed <timestamp>`; `"none"` for `none — `; `"unrecorded"` when the line is absent or malformed |
| `verified_before_close` | `True` when `verified == "passed"` and the passed date is on or before `closed_on`; `False` when it is after; `None` when either is missing |

`doc_lifecycle` never raises on content. A malformed line counts as absent.

## Fix

### 1. `scripts/lib/hermes/prior_art.py`
Add `doc_lifecycle` as defined, with the regexes compiled at module level next to `_PRIORITY_RE`.
`doc_meta` and `doc_release` do not change.

### 2. `scripts/bug-tally.py`
- Each release bucket gains `"lifecycle": {"recurred_docs": n, "recurrences": n,
  "closed_dated": n, "verified_passed": n, "verified_none": n, "verified_unrecorded": n,
  "verified_after_close": n}`, counted over that release's docs. `closed_dated` counts closed docs
  with a `closed_on`. Existing keys keep their shape.
- New flag `--age`: prints every open doc with priority P0–P2 as
  `  P1  23d  docs/bugs/<file>.md`, oldest first, after the per-release lines. Age is in whole days
  from `filed` to today (UTC). A doc with no `filed` prints `?d` and sorts last.
- `--json` adds a top-level `"open_age": [{"path", "priority", "age_days"}]` for open P0–P2.
- `Makefile` `bug-tally` passes `$(if $(AGE),--age,)`.

### 3. `bin/k3dm-vectordb-metrics`
Into the existing `k3dm-bug-docs` group (computed from the same texts as `_bug_metrics`):
- `k3dm_bug_open_by_age{priority,bucket}`: open docs per priority (P0–P3) in buckets `0-7d`,
  `8-30d`, `31-90d`, `90d+`, `unknown`. Always all 25 series, zeros included.
- `k3dm_bug_open_age_days_max{priority}`: the oldest open doc's age per priority, `0` when none.

Into the existing `k3dm-bug-releases` group, per release already published:
- `k3dm_bug_release_lifecycle{release,order,kind}` with `kind` in `recurred_docs`, `recurrences`,
  `closed_dated`, `verified_passed`, `verified_none`, `verified_unrecorded`, `verified_after_close`.

No doc path, file name or title in any label.

### 4. `bin/k3dm-bug-close` (new) and `make bug-close`
`make bug-close DOC=docs/bugs/<file>.md TEST='<test ref>'` closes a bug only after its test
passes:
1. Refuses unless `DOC` exists under `docs/bugs/` (not `archive/`) and `doc_meta` says `open` or
   `unknown`.
2. Validates `TEST` as defined (path exists; name or `@test` title occurs in the file).
3. Runs only that test: `python3 -m pytest -q <path>::<name>` or `bats -f '^<escaped title>$' <path>`.
   On failure it prints the test output and exits 1, and the doc is untouched.
4. On success it rewrites the doc in place:
   - the Status value becomes `FIXED YYYY-MM-DD` (today, UTC), and any existing value is kept after ` — `;
   - inserts or replaces `**Verified by:** <test ref> — passed <UTC timestamp> at <git rev-parse --short=12 HEAD>`
     directly under `**Priority:**`.
5. It never commits, stages or pushes.
6. For a P3 with no test: `make bug-close DOC=... NO_TEST='<reason>'` writes
   `**Verified by:** none — <reason>`. It refuses for P0–P2.

Bash, `set -euo pipefail`, sources lib-foundation like the other `bin/` scripts. The doc rewrite
runs in Python, through `python3 -c` or a small helper function in `prior_art.py`; no `sed -i`.

### 5. `.githooks/pre-commit`
These rules extend the existing new-bug-doc block and apply only to staged `docs/bugs/*.md`
outside `archive/`. They compare the staged blob (`git show :<path>`) with `HEAD:<path>`.
- **Added doc:** `**Filed:** YYYY-MM-DD` is also required, alongside `**Priority:**`.
- **Closing transition** (HEAD state `open`/`unknown` → staged `closed`, or an added doc that is
  already closed): needs a `**Verified by:**` line with a test ref, or `none — ` when the priority
  is P3. For a test ref, the path must exist in the index (`git cat-file -e :<path>`) and the name
  or title must occur in the staged blob.
- **Reopen transition** (HEAD `closed` → staged `open`): the `**Recurred:**` count must go up.
- **Recurrence added** (the count of `^## Recurrence` headings goes up): the `**Recurred:**` count
  must go up too.
- Each message names the doc, the rule and the fix (`make bug-close ...`, or add a line `**Recurred:** <date> — <sha>`).
  The hook stays read-only. Use the same parser: `python3 -c` importing `prior_art.doc_meta` and
  `doc_lifecycle` from `scripts/lib/hermes`.

Existing docs that are not edited are never checked. No backfill.

### 6. `scripts/etc/argocd/platform-ops/grafana-dashboard-bugs.yaml`
Add one row, "Lifecycle", below "Last five releases and the current one". Move the "All open bugs"
row down by the new height. Panels:
- **Open P1/P2 by age** (stacked bar chart, buckets on x, P1 and P2 series) from `k3dm_bug_open_by_age{priority=~"P1|P2"}`.
- **Oldest open P1** and **Oldest open P2** (stat, unit `d`, thresholds: green, orange ≥ 14, red ≥ 30).
- **Recurrence per release** (bar chart): `recurred_docs / closed`, per release. Name the series
  "docs that recurred" and give the panel a description of the ratio.
- **Fix verification per release** (stacked bar chart): `verified_passed`, `verified_none`,
  `verified_unrecorded` over closed docs. The description says "unrecorded" means the doc was closed
  before this field existed, or without `make bug-close`.
- **Verified after close** (stat): sum for the current release; orange ≥ 1.

Keep the existing layout BATS test green: no overlap, 24 columns, every queried metric emitted.

## Tests (each shown failing against the pre-change code, on a temp copy)

- `doc_lifecycle`:
  - `Filed` line wins over the file name, and the file name is the fallback.
  - `closed_on` comes from `FIXED 2026-10-01 (abc123)` and is `None` for an open doc.
  - `**Recurred:**` lines: several are sorted, and a malformed date is ignored.
  - `verified` is `passed`, `none` or `unrecorded`.
  - `verified_before_close` is True, False or None.
- `bug-tally`:
  - lifecycle counts for a fixture repo with one doc of each kind;
  - `--age` order, the `?d` case, and that P3 is excluded;
  - the `--json` `open_age` shape.
- Producer:
  - exactly 25 `open_by_age` series and 4 `age_days_max` series;
  - a 10-day-old P1 lands in `8-30d`;
  - the lifecycle kinds per release;
  - no label value contains `docs/` or `.md`.
- `bug-close` (stubbed `pytest`/`bats` on `PATH`):
  - failing test: exit 1 and the doc is byte-identical;
  - passing test: Status is `FIXED <today>` with the old value kept, and `Verified by` is placed under `Priority`;
  - refuses: a closed doc, an archive path, a missing test path, a name not in the file;
  - `NO_TEST` works for P3 and is refused for P2;
  - never runs `git add` or `git commit` (a `git` shim records its calls).
- Pre-commit (temp repo with the real hook):
  - added doc without `Filed`: refused;
  - open → FIXED without `Verified by`: refused;
  - with a test ref that does not exist: refused;
  - with a valid ref: accepted;
  - P3 `none — reason`: accepted, and P2 `none`: refused;
  - closed → open without a new `Recurred`: refused, and with one: accepted;
  - new `## Recurrence` without a new `Recurred`: refused;
  - editing an unrelated line of an old closed doc: accepted;
  - `archive/` is ignored.
- Mutation (Claude at verification):
  - drop the reopen rule;
  - let P2 use `none`;
  - make `bug-close` write before the test runs.

  Each must turn a test red.

## What NOT to Do
- Do NOT create a PR, commit to `main`, or use `--no-verify`.
- Do NOT backfill or edit existing bug docs, and do NOT infer recurrence or verification from prose.
- Do NOT put doc paths, file names or titles in metric labels.
- Do NOT change `doc_meta`, `doc_release`, or the existing `k3dm_bug_docs` and
  `k3dm_bug_release_docs` series.
- Do NOT run `make test`, `make e2e`, or push to a real Pushgateway; tests point the exporter at a
  closed local port.
- Do NOT let `bug-close` stage, commit or push, or run anything but the one named test.
