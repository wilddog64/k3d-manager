## Decision

The operator wants to see, from v2.0.0 to v3.0.0, how much they had to intervene per release. v3.0.0
(multi-agent product team, `docs/roadmap.md`) must push this number down; v1.48 through v2.x are the
baseline, so collection starts here.

One point per **verified release**: a release whose merge commit has a passing `hub-e2e` record.
Releases without one are reported with `verified="false"` and excluded from the headline trend.

What counts as one intervention:

| `kind` | Source | Automatic? |
|---|---|---|
| `approval` | `**Approval:** explicit` headers on plan/bug docs added in the release, plus explicit `Approval:` commit trailers (Decision Digest) | yes, git |
| `operator_commit` | commits in the release with no agent `Co-Authored-By:` trailer (Claude, Codex, Gemini, Copilot) | yes, git |
| `operator_step` | a command only the operator may run (rebuild, secret, merge, apply to the live hub, protection change) | ledger |
| `agent_correction` | the operator rejected or redirected agent work ("that's wrong", rework, reverted result) | ledger |
| `manual_fix` | the operator fixed something by hand outside git (cluster, keychain, launchd) | ledger |

Minutes are optional and self-reported; the count is the headline, minutes are context.
Branch-cut-to-merge hours come from git/GitHub as context, not as effort.

## Changes

### 1. Ledger — `make log-intervention`

New Makefile target calling new `bin/k3dm-log-intervention`:

```
make log-intervention KIND=operator_step NOTE="ran make hub-recover-all" [MINUTES=20] [RELEASE=v1.48.0]
```

- Appends `{"ts", "release", "kind", "note", "minutes"}` to
  `${K3DM_LEDGER_DIR:-$HOME/.k3dm/ledger}/interventions.jsonl` (dir `0700`, file `0600`).
- `release` defaults from the current branch `k3d-manager-vX.Y.Z`; on any other branch, require
  `RELEASE=`.
- `KIND` must be one of the three ledger kinds; `NOTE` ≤ 200 characters.
- Refuse (exit 2, write nothing) a `NOTE` that looks like a secret: `hvs.`, `eyJ`, `ghp_`, `gho_`,
  `github_pat_`, `sk_`, `AGE-SECRET-KEY`, `BEGIN .*PRIVATE KEY`, or any 32+ character base64/hex run.
- `make log-intervention-list [RELEASE=…]` prints the release's rows.

### 2. Claude logs its own corrections

`CLAUDE.md`, Claude Session Rules: when the operator corrects or rejects Claude's or an agent's work,
or runs an operator-only command Claude handed them, Claude runs `make log-intervention` with the
matching kind and a short neutral note, in the same turn. This keeps the ledger from depending on
the operator's memory. Claude never logs `approval` (git has it).

### 3. Collector — new `bin/k3dm-effort-metrics` (Python 3, stdlib)

- Releases: every `vX.Y.Z` tag ≥ `v1.40.0`; the range is previous tag → tag.
- `approval`: call `scripts/decision-digest.py --json --ref <tag>` scoped to the range if it exists;
  otherwise count `**Approval:** explicit` in `docs/plans/` and `docs/bugs/` files **added** in the
  range (`git diff --diff-filter=A --name-only`).
- `operator_commit`: `git log <range> --format=%H%x00%B` without an agent co-author trailer.
- Ledger kinds: rows whose `release` matches.
- `verified`: the v1.47.0 hub-e2e pass record for the tag's commit; absent → `false`.
- Releases before v1.48.0 have no ledger, so they carry `ledger="absent"`; the panel shows only the
  git kinds for them.

Push to `${K3DM_EFFORT_PUSHGATEWAY_URL:-http://localhost:19094}/metrics/job/k3dm-effort` (same retry
and skip as `bin/k3dm-disk-metrics`):

```
k3dm_release_human_effort{release="v1.48.0",kind="operator_step",verified="true"} 7
k3dm_release_human_effort_total{release="v1.48.0",verified="true",ledger="present"} 23
k3dm_release_human_minutes{release="v1.48.0"} 140
k3dm_release_lead_hours{release="v1.48.0"} 96
```

`--dry-run` and `--now` as in the quality aggregator. Hermes runs it daily
(`state["effort_last_run"]`, 86400 s).

## Tests

Python, a temp git repo with fixture tags and commits, temp ledger, injected `now`, `--dry-run`,
autouse fixture pointing the Pushgateway at `http://127.0.0.1:9`.

1. Range with 3 commits, 1 without an agent trailer → `operator_commit 1`.
2. Two plan docs added with `**Approval:** explicit`, one with `pending` → `approval 2`; a doc only
   *modified* in the range is not counted.
3. Ledger rows for two releases → each counted only in its own release.
4. No hub-e2e record → `verified="false"`; excluded from the `verified="true"` total.
5. Release before v1.48.0 → `ledger="absent"`.
6. `log-intervention` with `NOTE="token hvs.abc"` → exit 2, ledger unchanged; a 201-char note →
   exit 2; unknown `KIND` → exit 2.
7. `log-intervention` on a non-release branch without `RELEASE` → exit 2.
8. Versions sort `v1.9.0 < v1.10.0 < v1.48.0`.
9. Hermes: effort step skipped at 23 h, runs at 25 h.

Mutations (each must turn a test red; restore with `cmp`): count modified docs as approvals
(test 2); drop the secret check (test 6); sort releases as strings (test 8).

Gates: `pytest` on the new files, `make test-pytest`, `make test` (per-suite counts),
`make validate-manifests`, `shellcheck` on any shell touched.
