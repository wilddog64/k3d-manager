## Behaviour

### 1. `docs/guides/operator-acceptance.md` (new)

Sections, in this order:

1. **What it checks** — the offline scenarios by id (from child A's table), what each proves in one sentence, and the
   `known_failing` scenarios with links to their four bug docs (parent § Decisions 2).
2. **Run it** — `make test-operator-acceptance`; where the run directory is (`K3DM_ACCEPTANCE_RUN_ROOT`, default),
   retention (`K3DM_ACCEPTANCE_RETENTION_DAYS`, `K3DM_ACCEPTANCE_MAX_MB`); that it also runs inside `make test-pytest`;
   what `inconclusive` means (promtool missing: `make machine-setup` installs it).
3. **Reading the report** — outcome and cause values, `known_failing` vs `failed`, `report.json` schema 1 fields.
4. **Isolation guarantees** — refused ports and hosts, allowlisted environment (CONFIRM and Slack variables never pass
   through), stub PATH, scratch HOME; what it never does (no Slack, no git push, no hub, no containers).
5. **Live profile** — `K3DM_ACCEPTANCE_LIVE=1 make test-operator-acceptance-live PROFILE=k3dm-tests`, the closed action
   list, `--with-test-all` (about 15 minutes), the Grafana Viewer token in Keychain `k3dm-grafana-viewer-token` (how
   the operator creates a Viewer service account; never the admin password; the token expires — the current one on
   2027-01-26 — and an expired token makes the Grafana leg fail with 401: rotate by adding a new token on the same
   service account and re-running the `security add-generic-password -U ... -w` prompt), the lock, local-only drafts and
   `--with-prior-art`.
6. **Known limits** — a Pushgateway restart loses the `-last-success` group (no persistence); panels 1-2 take max()
   across targets (bug link); rendered-Grafana checks and the document-index canary are not part of this harness (ideas
   rows dated 2026-11-26).
