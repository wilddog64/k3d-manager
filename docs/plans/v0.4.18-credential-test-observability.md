## Why this spec exists

`acg_session_check.js` writes the string `ACG_SESSION_OK` from **three** different places, and a
caller cannot tell them apart (a fourth producer lives in a sibling script, covered in item 1):

| Line | How it got there | Credentials exercised? |
|---|---|---|
| 58 | the existing browser session was already authenticated | **no** |
| 73 | headless auto-login succeeded | yes |
| 95 | a human signed in at the interactive prompt | no |

`make credential-test` is the live gate that `k3d-manager` treats as proof that ACG auto-login
works. Because line 58 short-circuits before credentials are ever read, a green run proves only
that *something* is authenticated. It does not prove the Keychain store is populated, correct, or
even non-empty.

This is not hypothetical. Measured on the operator's machine 2026-09-24: the Keychain item
`k3dm-acg-pluralsight` was **absent for weeks** while the live `pw-profile` session stayed valid.
Every `credential-test` run in that period printed `ACG_SESSION_OK`. The absence was diagnosed only
by reading `cdp.sh:184-185` by hand, and it was repeatedly mistaken for "auto-login was never
wired". The gate had the information and threw it away.

A second failure mode was measured the same day: `security add-generic-password -w` with stdin not a
TTY reads EOF and stores an **empty** value at exit 0. So "the Keychain item exists" does not imply
"the item has a value", and today nothing downstream distinguishes those two states — an empty
credential takes the same silent path as an absent one.

### 2. Always report credential-store health, on every run

Add this helper next to the other module-level declarations, after `LOGIN_TIMEOUT_MS`:

```js
function _credentialState(value) {
  if (value === undefined || value === null) {
    return 'absent';
  }
  if (value === '') {
    return 'empty';
  }
  return 'present';
}

function _reportCredentialState() {
  const user = _credentialState(process.env.ACG_USERNAME);
  const pass = _credentialState(process.env.ACG_PASSWORD);
  console.error(`ACG_CREDENTIALS: username=${user} password=${pass}`);
  return user === 'present' && pass === 'present';
}
```

`_reportCredentialState` must be called **once**, in `_main`, before the sandbox navigation — so the
line is emitted even when the session short-circuits at line 58, which is the whole point. Capture
its return value; item 3 uses it.

It writes to **stderr**, like every other diagnostic in this file, so nothing parsing stdout for
markers is affected.

**It must never print, log, hash, or echo a credential value, or its length.** `absent`, `empty` and
`present` are the only three words it may emit about a value. A length is a disclosure and is also
useless here — the operator already knows what they typed.

### 3. `K3DM_ACG_REQUIRE_CREDENTIALS=1`

When set to exactly `1`, a run whose credential state is not `present`/`present` must fail, **even
when the session is authenticated**. Without it the default stays exactly as today.

The rationale: a live-but-expiring session masks a broken credential store. Tier 2 in `k3d-manager`
wants to assert "this will still work unattended tomorrow", which is a different question from "is it
working right now".

Emit a distinct marker so this is never confused with an expired session:

```js
ACG_CREDENTIALS_REQUIRED: credential store is not usable (username=<state> password=<state>) and K3DM_ACG_REQUIRE_CREDENTIALS=1
```

and exit non-zero. Do **not** reuse `ACG_SESSION_EXPIRED` — that marker means the browser is not
authenticated, which may well be false here, and `k3d-manager`'s preflight triage table keys off it.

Order of operations in `_main`, exactly:

1. connect over CDP
2. `_reportCredentialState()` → keep the boolean
3. if `K3DM_ACG_REQUIRE_CREDENTIALS === '1'` and the boolean is false → print the marker, throw
4. everything else, unchanged

Checking before the browser work means the failure is fast and cannot be attributed to a navigation
timeout. The CDP connection stays first so that a dead browser is still reported as a dead browser.

## What NOT to build

- **Do NOT add a mode that forces a login while already authenticated.** Repeated sign-ins from a
  profile Pluralsight does not recognise are what trigger new-device verification — the MFA path
  this module refuses by design (`k3d-manager` `docs/bugs/v1.14.0-bugfix-acg-pluralsight-autologin.md:394`).
  Testing a code path must not risk the account it authenticates.
- Do NOT touch `LOGGED_IN_SELECTORS` or `SIGNED_OUT_SELECTORS`. The 2026-09-12 false-green fix is
  already in `main` and is out of scope.
- Do NOT change `SANDBOX_URL`, `SIGNIN_URL`, `LOGIN_TIMEOUT_MS`, `POLL_INTERVAL_MS`, or any
  Playwright timeout.
- Do NOT read the Keychain from this file. It receives credentials via env only; `cdp.sh` owns the
  loading.
