# v1.43.10 — Compare context-handling cost and quality across releases

**Status:** READY — dispatch once `k3d-manager-v1.43.10` is cut (from `main` after v1.43.9 merges)
**Approval:** explicit 2026-10-25 ("go for v1.43.9", after Claude listed what exists and what is missing for the three measures). v1.43.9 was already full (5 plans), so Claude moved it to v1.43.10 under the release cap and told the operator.
**Release:** v1.43.10
**Owner:** Claude (spec, review, live check); Luna (implementation)
**Related:** `docs/plans/v1.43.6-claude-context-compaction-metrics.md` (the 400K compaction trial and its measures)

## Why

Before the auto-compaction threshold is changed again, three measures have to be compared release by
release:

1. API-equivalent cost per **independently verified** spec, coordinator (Claude) and worker (Codex)
   together;
2. the share of file reads that re-read a file after a compaction (context reconstruction overhead);
3. first-pass verification and human interventions, so cheaper context handling is not bought with
   worse delivery.

Today none of them can be read per release:

- `k3dm_claude_verified_specs` exists only for 1d/7d/30d, and its count is wrong: on 2026-10-25 it
  read 125 for both 1d and 7d. `_verified_specs` counts any file whose added `**Status:**` matches
  `_CLOSED_RE` (so `FIXED`, which only means landed, counts), and dates it by committer time (`%ct`),
  which a rebase or `commit --amend` resets for every rewritten commit.
- `k3dm_claude_reads` counts only the `Read` tool. Claude reads most files through Bash (`cat`,
  `sed -n`, `head`, `tail`), so 30d showed 51 reads, a small fraction of the real number.
- Release scope exists for cost per landed spec, first pass (`k3dm_dispatch_live_verified_bug_first_pass`)
  and continuation prompts (`k3dm_dispatch_human_continuation_prompts`), but nothing sets them side by
  side.

## Changes

All in `bin/k3dm-dispatch-metrics` unless stated.

### C1. Verified means live-verified, dated by author time

Change `_verified_specs`:

- A spec counts as verified in a commit when that commit's patch adds a `**Status:**` line starting
  `LIVE-VERIFIED` (case-sensitive), or adds a `**Live evidence:**` line, to a file under `docs/bugs/` or
  `docs/plans/`. `FIXED`, `DONE`, `CLOSED` and other values no longer count.
- Use the author time (`%at`) for the window check.
- Each file counts once per window.
- Keep the series name `k3dm_claude_verified_specs{window}` for 1d/7d/30d.

### C2. Verified specs per release

Emit `k3dm_claude_verified_specs{window="<release>"}` for each release the exporter already scopes
(the same list `_releases(events)` returns). A file belongs to a release when:

- its name starts `v<release>-` (plans), or
- its `**Release:**` line in the current tree starts with `v<release>`, ignoring the leading `v` when
  matching `<release>` (bugs).

It counts if the file's current Status starts `LIVE-VERIFIED`, or the file contains a `**Live evidence:**`
line. No time window applies to release scope.

### C3. Shell reads count as reads

In the Claude session reader (the block around the `block.get("name") == "Read"` check), also treat a
`Bash` `tool_use` as reads:

- Split `input.command` into segments on `;`, `&&`, `||`, `|` and newlines (use `shlex` with
  `punctuation_chars=True`; on a parse error, skip the command).
- A segment is a read when its first word is `cat`, `head`, `tail`, `nl` or `less`, or it is `sed` with
  `-n` among its options. Each non-option argument that is not a number and not a `sed` script
  (the first non-option argument to `sed`) is a file path read once.
- Resolve a relative path against the record's `cwd`, when present; otherwise keep it as written.
- Feed each path into the same read list and re-read detection that `Read` uses.

`grep`, `rg`, `find`, `ls` and `git` are not reads. Do not record paths in any metric label.

### C4. Compactions and reads per release

Emit `k3dm_claude_compactions{window="<release>",trigger}` and `k3dm_claude_reads{window="<release>",kind}`
for each release. A compaction or read belongs to a release when its timestamp falls inside any task
interval of that release, using the same task intervals `_render_claude` uses for that release's Claude
cost. Count each event once per release, even where intervals overlap.

### C5. Combined cost per verified spec

For each release, emit `k3dm_dispatch_api_cost_per_verified_spec_usd{window="<release>",agent}` with
`agent` in `claude`, `codex` and `total`:

- `claude` = `k3dm_dispatch_claude_api_cost_usd` for that release ÷ C2's count;
- `codex` = `k3dm_dispatch_api_cost_usd` for that release ÷ C2's count;
- `total` = their sum.

Skip the series for a release whose verified count is 0.

### C6. Release comparison table on Agent Cost

`scripts/etc/argocd/platform-ops/grafana-dashboard-agent-cost.yaml`: a new row **Context threshold
comparison** (id 89) with a table panel (id 90), full width, below the existing panels. One row per
release (label `window`, releases only: `window=~"v.*"`), columns in this order:

| Column | Query | Unit |
|---|---|---|
| Verified specs | `k3dm_claude_verified_specs` | short |
| Total $ / verified | `k3dm_dispatch_api_cost_per_verified_spec_usd{agent="total"}` | currencyUSD |
| Claude $ / verified | `...{agent="claude"}` | currencyUSD |
| Codex $ / verified | `...{agent="codex"}` | currencyUSD |
| Re-read share | `k3dm_claude_reads{kind="reread_after_compaction"} / ignoring(kind) k3dm_claude_reads{kind="all"}` | percentunit |
| Compactions | `sum by (window) (k3dm_claude_compactions)` | short |
| First pass | `k3dm_dispatch_live_verified_bug_first_pass{result="pass"} / ignoring(result) sum without(result) (k3dm_dispatch_live_verified_bug_first_pass)` | percentunit |
| Continuation prompts | `sum by (window) (k3dm_dispatch_human_continuation_prompts)` | short |

Instant queries, formatted as table, joined on `window` (outer join), sorted by release descending. An
empty cell means no data for that release. The panel description names each column's meaning and says
that releases before v1.43.7 have no prompt tracking and few live-verified specs.

### C7. Docs

`docs/guides/grafana-dashboards.md`, Agent Cost: the comparison table, what "verified" now means, and
that shell reads count as reads. `docs/plans/v1.43.6-claude-context-compaction-metrics.md` is not edited.

## Tests

In `scripts/tests/bin/test_dispatch_metrics.py`, with a temp git repo and a temp Claude projects dir:

1. A commit adding `**Status:** FIXED` does not count; one adding `**Status:** LIVE-VERIFIED` does; one
   adding `**Live evidence:**` does; a file counts once.
2. A commit with author time 10 days ago and committer time now counts in 30d but not in 7d.
3. Release scope: a plan `v1.2.3-x.md` and a bug with `**Release:** v1.2.3 (bug)`, both live-verified,
   give `k3dm_claude_verified_specs{window="v1.2.3"} 2`; a `FIXED` bug of the same release is not counted.
4. Bash reads: `cat a.md`, `sed -n 1,20p b.md`, `head -5 c.md | tail -1`, `git -C x log && cat d.md` each
   record the right paths; `grep foo e.md`, `ls`, an unparseable command record none. A shell read of a
   file read before a compaction counts as a re-read.
5. Compactions and reads inside a release's task interval appear under that release; ones outside do
   not; overlapping intervals count an event once.
6. `k3dm_dispatch_api_cost_per_verified_spec_usd` values for a fixture release, and no series for a
   release with 0 verified specs.
7. No metric line contains a file path, home directory or username.

In `scripts/tests/plugins/agent_dispatch_dashboard.bats`:

8. Row 89 and table 90 exist with the eight queries, units, outer join on `window` and `window=~"v.*"`;
   update the panel-id set assertions for 89 and 90.

Tests 1, 2, 3, 4 and 8 must be red on a temp copy of the pre-change files.
