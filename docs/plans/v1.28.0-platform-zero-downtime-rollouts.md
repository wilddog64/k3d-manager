# v1.28.0 — platform zero-downtime rollouts

> **Status: QUEUED — hardware-gated (deferred 2026-09-04).** The current M4 Air 24GB
> hub has no CPU headroom for 2+ replicas of the stateless tier — it already
> CPU-starves at single replicas (see `reference_one_second_probes_cpu_starvation_kill_loop`,
> `reference_hostinger_maxsurge_rollout_deadlock`). Zero-downtime is a hardware story;
> do NOT implement until the Mac Mini M5 upgrade (Oct 2026 target). The design below
> stands — only the execution is gated.

## Goal

Use the hub's existing capacity to make platform image and configuration updates
safe to roll without planned downtime. This milestone changes deployment
topology and rollout policy; it does not patch live workloads directly.

## Scope

### Stateless platform tier

Move these services to at least two replicas where supported: ArgoCD server,
repo-server, application-set controller, notifications, Grafana, Loki gateway,
Istio ingress gateway, Istiod, External Secrets controllers, and the CVE
inventory exporter. For each service:

- add readiness/startup probes where absent;
- set `maxUnavailable: 0` and a bounded `maxSurge`;
- add a PodDisruptionBudget with one available replica;
- verify session, cache, and leader-election behavior with multiple replicas;
- preserve resource requests/limits and validate scheduling headroom.

### Stateful tier design

Do not claim zero downtime for LDAP, Keycloak PostgreSQL, or other single-writer
stateful components until replication/failover is designed and tested. Produce
a separate decision record for each stateful service covering storage,
replication, failover, backups, and rollback.

## Rollout order

1. Observability and exporters.
2. ArgoCD control-plane components.
3. Istio ingress/control-plane components.
4. Grafana/Loki and External Secrets.
5. Stateful services only after their failover design is approved.

Each step must pass readiness, PDB, ArgoCD sync/health, endpoint smoke tests,
and a rollback rehearsal before the next tier.

## Capacity gates

Before rollout, record node allocatable resources, current usage, and pod
requests. A tier may proceed only when one additional replica for every service
in that tier fits with a documented safety margin (minimum 25% CPU and memory
headroom). Abort on Pending pods, failed scheduling, or degraded health.

## Definition of done

- Stateless services run with two healthy replicas and PDB coverage.
- A controlled image update preserves endpoint availability during rollout.
- ArgoCD reports all platform Applications Synced/Healthy afterward.
- `make status` and focused service checks remain healthy throughout.
- Stateful availability decisions are documented; no unsupported live patching
  or forced failover is performed.

## Out of scope

Image signing/admission (v1.27.0), shopping-cart application rollouts, and
stateful database/LDAP replication implementation are separate workstreams.
