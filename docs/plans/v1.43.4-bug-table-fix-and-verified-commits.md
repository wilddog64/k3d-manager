## Problem

The Bugs table says a bug was fixed in `v1.43.3` and verified at `2026-10-16`, but not which commit
did either. The operator wants both commits, as two columns right after **Fixed in**.

## Decisions

- **Two new labels on `k3dm_bug_info` only:** `fix_sha` and `verified_sha`. Value: the first 8
  characters of the commit SHA, lowercase hex; `-` when there is none. `k3dm_bug_status_docs` gets
  **no** new label.
- **`fix_sha`** = the commit `bug-tally` already uses for **Fixed in**: `_fixed_commits(ref)[path][0]`
  (the commit at which the doc's Status last became fixed). Only for docs in `fixed_in` (fixed
  docs). A `status_backfill` source still has a commit; show it. `-` for open, deferred and unknown
  docs, and for a fixed doc with no transition (`no_transition`).
- **`verified_sha`** = the commit `_verification_times` already finds with the verified pattern
  `^\*\*Status:\*\* (LIVE-)?VERIFIED` (the earliest one). `-` when the doc is not verified, when git
  finds nothing, or on any git failure. It is git-only: a date in the Status line does not change it.
- **Guard:** every value must `re.fullmatch(r"[0-9a-f]{8}|-", value)`, else `-`.
- **Table:** **Fix commit** and **Verified commit** sit right after **Fixed in**; the four
  verification columns move two places right. `-` renders as `—`. No links (lib-foundation rows
  would need another repo's URL; out of scope).

## Fix

### 1. `scripts/bug-tally.py`, `_scan`

In the `fixed_in[path] = (...)` assignment, add the commit to the transition case:

old:
```python
        fixed_in[path] = ({"release": commit_info[0], "source": commit_info[1]}
                          if commit_info else {"release": "unknown", "source": "no_transition"})
```
new:
```python
        commit = fixed_commits.get(path, (None,))[0] if commit_info else None
        fixed_in[path] = ({"release": commit_info[0], "source": commit_info[1], "commit": commit}
                          if commit_info else {"release": "unknown", "source": "no_transition", "commit": None})
```
`--json` output carries the new key; `tally()` / the `releases` payload are unchanged.

### 2. `bin/k3dm-vectordb-metrics`

- `_verification_times`: return a third element, the verified commit SHA or `None`:
  `times[path] = (verified_at or "true", live_at, verified_commit[0] if verified_commit else None)`.
  Update every reader of the tuple (the `values = verification_times.get(path) or (None, None)`
  default becomes `(None, None, None)`; index 0/1 keep their meaning).
- `_bug_status_metrics`: after the `live_verified_at` label append
  ```python
  labels += f',fix_sha="{...}",verified_sha="{...}"'
  ```
  - `fix_sha`: `((fixed_in or {}).get(path) or {}).get("commit")`, first 8 chars, only in the
    branch that already sets a real `fixed_in` release label; else `-`.
  - `verified_sha`: `values[2]` first 8 chars when the existing `verified` label is `true`; else `-`.
  - Apply the guard from Decisions to both.
- lib-foundation path: no change in behaviour beyond the two labels reading `-`.

### 3. `scripts/etc/argocd/platform-ops/grafana-dashboard-bugs.yaml`, Bugs table panel

- `organize.indexByName`: `"fixed_in": 6, "fix_sha": 7, "verified_sha": 8, "verified": 9,
  "verified_at": 10, "live_verified": 11, "live_verified_at": 12` (0–5 unchanged).
- `organize.renameByName`: add `"fix_sha": "Fix commit"`, `"verified_sha": "Verified commit"`.
  Neither is in `excludeByName`.
- Overrides: one per new column, matcher `byName` on the renamed name, `custom.width` 100, and a
  value mapping `{"-": {"text": "—", "color": "#8e8e8e", "index": 0}}`.
- Panel description: add "Fix commit is the commit that marked it fixed (the one Fixed in comes
  from); Verified commit is the one that first marked it verified."
