## Decision

The operator's severity scale (2026-10-12):

| Level | Example | Measured by |
|---|---|---|
| SEV1 | Hub unavailable, unrecoverable data loss | frequency, recovery time |
| SEV2 | Argo CD unavailable, production-like app outage | frequency, duration |
| SEV3 | Agent task fails, monitoring panel misleading | frequency, recurrence |
| SEV4 | Minor defect without operational impact | backlog, resolution time |

Bug docs already carry `**Severity:** low|medium|high`, the technical impact. It is left alone: the
existing docs are not migrated. The incident level is a **new** line, `**Incident:**`, because it
answers a different question (how bad was it for the platform) and it is the one the dashboard
counts. `**Priority:**` (urgency) is also unchanged.

## Format

Directly under `**Priority:**` in every new `docs/bugs/` file:

```
**Incident:** SEV2 — started 2026-10-12T11:35Z, resolved 2026-10-12T11:41Z
**Detected by:** alert (VaultSealed)
```

- `**Incident:**` — `SEV1`…`SEV4`. For SEV1 and SEV2, `started` and `resolved` are required
  (ISO-8601 UTC, minute precision); `resolved` may be `open` while it lasts. SEV3/SEV4 take the level
  only.
- `**Detected by:**` — exactly one of `alert`, `sensor`, `test`, `human`, optionally followed by the
  alert, sensor or test name in parentheses. `alert` = an Alertmanager notification; `sensor` = a
  Hermes sensor; `test` = CI, e2e or a drill; `human` = someone noticed it first (including Claude in
  conversation, or the operator on a dashboard).
- A doc without the lines is `unclassified`. Old docs stay `unclassified` unless someone adds the
  lines by hand.

## Changes

### 1. `bin/k3dm-vectordb-metrics`

Parse both lines next to the existing `**Priority:**` parsing. Emit:

```
k3dm_incident_docs{level="SEV2",state="open|closed"} N            # unclassified included as level="unclassified"
k3dm_incident_detected_docs{level="SEV2",detected_by="alert"} N   # last 30 days by Filed date
k3dm_incident_duration_seconds_sum{level="SEV1|SEV2"} S           # resolved incidents started in the last 30 days
k3dm_incident_duration_seconds_count{level="SEV1|SEV2"} N
k3dm_incident_open_duration_seconds{level="SEV1|SEV2"} S          # longest unresolved, 0 when none
k3dm_incident_recurred_docs{level="SEV3"} N                       # docs with a v1.44.0 Recurred line, last 30 days
k3dm_incident_sev4_backlog_age_seconds{quantile="0.5|0.9"} S      # open SEV4 docs, age from Filed
k3dm_incident_sev4_resolution_seconds{quantile="0.5|0.9"} S       # SEV4 closed in the last 30 days, Filed → closed
```

The 30-day windows are computed here, from the docs, because hub Prometheus keeps 3 days
(`scripts/etc/helm/observability/kube-prometheus-stack-values.yaml`). The window uses an injectable
`now` for tests. An unparseable `**Incident:**` line → `unclassified`, plus one stderr warning naming
the file. Never fail the run.

### 2. Filing convention

- `CLAUDE.md`, **Docs Conventions**: one rule next to the Priority rule. Every new `docs/bugs/`
  file carries `**Incident:**` and `**Detected by:**` under Priority, with the four-level table as a
  one-line reference to `docs/guides/incident-severity.md`.
- `AGENTS.md`: the same sentence, if it repeats the Priority rule.

### 3. Docs

- New `docs/guides/incident-severity.md`: the table above, how to choose a level (pick the highest
  that applies; data loss is always SEV1), what each `Detected by` value means, two worked examples
  from real docs (the 2026-10-12 OrbStack-upgrade Vault seal: SEV2, detected by `human`; the
  2026-10-12 hostnet drift recurrence: SEV3, detected by `sensor (hostnet_drift)`).
- `docs/guides/grafana-dashboards.md`: the new series under k3dm Bug Tracking.
- `CHANGELOG.md` `[Unreleased]` → `### Added`.

## Tests

Python, temp `docs/bugs/` fixtures, injected `now`, autouse fixture pointing the Pushgateway at
`http://127.0.0.1:9`.

1. SEV2 with started/resolved 6 minutes apart → `duration_seconds_sum{level="SEV2"} 360`, count 1.
2. SEV1 `resolved open` → `open_duration_seconds{level="SEV1"}` = now − started; not in sum/count.
3. `Detected by: sensor (hostnet_drift)` → `detected_by="sensor"`; the parenthesised name is not a label.
4. A doc with no lines → `level="unclassified"`; `Detected by: pager` → excluded from
   `detected_docs`, warning printed, exit 0.
5. A SEV2 doc filed 31 days ago is excluded from every 30-day series but counted in
   `k3dm_incident_docs`.
6. SEV4 resolution quantiles from three fixtures with known Filed/closed dates.
7. The existing bug-metrics tests stay green.

Mutations (each must turn a test red; restore with `cmp` against a snapshot): use `Filed` instead of
`started` for duration (test 1); drop the 30-day filter (test 5); keep the parenthesised name in the
label (test 3).

Gates: `pytest scripts/tests/bin/test_vectordb_bug_metrics.py`, `make test-pytest`, `make test`
(per-suite counts).
