## Context

`bin/k3dm-cloud-bridge` answers requests filed on the public `cloud-requests` branch. For long jobs it adds an entry to
`ledger/watching.txt` on that branch and polls the job until it ends. Anyone who can push the branch can write that file. Two defects:

1. `_watch_entry` (`:492-501`) computes `LIFECYCLE_TIMEOUTS.get(action, MAKE_TARGETS.get(target, {}).get("timeout", 300))`. The default
   is evaluated eagerly; for `sandbox-up`/`sandbox-down` `target` is a dict (`scripts/lib/webhook/cloud_actions.py:21-22`), so
   `MAKE_TARGETS.get(target, {})` raises `TypeError` after the webhook already started the job, and the response is lost.
2. `_read_watching` (`:477-490`) checks only that four keys exist. The watch loop (`:603-624`) calls `float(entry["created_at"])` and
   `float(entry["timeout"])`; a non-numeric value raises `ValueError`, `main` (`:706`) catches it, and every tick aborts there, before the
   new-request scan (`:625`), so no request is answered. `entry["job_id"]` reaches the webhook without the `JOB_ID_RE` check. The watch
   loop's terminal response is committed without the `scrub_credentials` pass the direct `job-status` path applies (`:646`).

## Files

`bin/k3dm-cloud-bridge`, `scripts/tests/bin/test_cloud_bridge.py`. Nothing else.

## Change

- `_watch_entry`: `timeout = LIFECYCLE_TIMEOUTS[action] if action in LIFECYCLE_TIMEOUTS else MAKE_TARGETS.get(target, {}).get("timeout",
  300)`, evaluating the `MAKE_TARGETS` lookup only for string targets.
- `_read_watching`: keep an entry only if `request_id` matches `ID_RE` (fullmatch), `job_id` matches `JOB_ID_RE` (fullmatch), and
  `created_at` and `timeout` are `int` or `float` (not `bool`), finite, `created_at` > 0 and `0 < timeout <= 86400`. Skip any other line;
  log one warning per tick naming how many lines were skipped (no line content).
- Watch loop: when the terminal response body has a string `output`, apply `scrub_credentials` to it before `job_artifacts` and the
  commit, as the direct path does at `:646`.
- Keep every existing call signature (tests fake `_call_webhook`, `_write_commit` and `job_artifacts` positionally).

## Tests (extend `scripts/tests/bin/test_cloud_bridge.py`; reuse its fixtures, tmp `STATE_DIR` and fakes)

- `_watch_entry` with a queued response returns an entry with timeout 3600 for `sandbox-up` and 1800 for `sandbox-down`, and the make
  target's timeout for `make-e2e`.
- A watching.txt holding one line each with `created_at: "x"`, `timeout: true`, `timeout: 1e9`, `job_id: "../x"`, `request_id: "bad"`,
  plus one valid entry: the valid entry is polled, the bad ones are skipped, and a reader request filed in the same tick is answered.
- A watched terminal response whose output contains a credential-shaped string (use a sentinel the existing scrub tests use) is committed
  scrubbed.
- All existing tests pass unchanged.
