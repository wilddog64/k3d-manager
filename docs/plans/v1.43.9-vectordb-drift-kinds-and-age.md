## Problem

`k3dm_vectordb_drift_docs` is `corpus_docs - rows`, a net count. It has two gaps.

1. **It cancels out.** Three corpus docs missing from the index plus three deleted docs still in it
   gives 0. The panel reads "in sync" and `VectorDBIndexDrift` (`!= 0`) never fires. A doc whose
   content changed but was not re-embedded (a stale hash) is not counted at all, because the row
   count does not move.
2. **It has no age.** A drift of 4 that appeared five minutes ago, during a normal index cycle,
   looks the same as a drift of 4 that has lasted three days.

The data to fix both already exists. Each index row stores `path`, `content_hash` and
`indexed_at`. `iter_corpus(ROOT, ref)` returns `(path, title, text, hash)` with the same hash that
`scripts/index-docs.py` stores, and `fetch_hashes()` returns `{path: content_hash}`.
`index-docs.py` already uses these to decide what to embed and what to prune.

## Change

### C1. Classify drift (in `bin/k3dm-vectordb-status`)

Use the same corpus source as today: `iter_corpus(ROOT, K3DM_INDEX_REF or None)`. With `fetch_hashes()`:

| kind | rule |
|---|---|
| `missing` | the path is in the corpus, not in the index |
| `stale` | the path is in both, and the hashes differ |
| `deleted` | the path is in the index, not in the corpus |

`status()` adds `drift: {"missing": [paths], "stale": [paths], "deleted": [paths]}` when the store
is reachable. When it is offline or unavailable, add `drift: null`. `--json` prints it. One extra
`run_sql` round trip at most; reuse `fetch_hashes()` instead of a new query.

### C2. First-seen state (in `bin/k3dm-vectordb-metrics`)

Keep a JSON file `{path: first_seen_epoch}` at `K3DM_VECTORDB_DRIFT_STATE`. It defaults to
`~/.local/share/k3d-manager/state/vectordb-drift-first-seen.json` (create the directory, mode 0700).

On each run where `drift` is not null:

- A drifted path not in the file gets the current time.
- A path still drifted keeps its time, even if its kind changes (for example `missing` → `stale`).
- A path no longer drifted is removed.
- Write atomically (temp file + `os.replace`).

When `drift` is null (store unreachable), leave the file unchanged and do not emit C3's metrics.
The file holds paths and epochs only — no content, no hashes.

The age is measured from the first run that saw the drift. So it is accurate to the exporter's run
interval, and a lost state file restarts every age at 0. Say both in the guide.

### C3. Metrics

- `k3dm_vectordb_drift_docs_by_kind{kind="missing|stale|deleted"}` — always all three, 0 when empty.
- `k3dm_vectordb_oldest_drift_age_seconds{kind=...}` — now minus the oldest first-seen epoch for
  that kind. 0 when that kind has no drift.
- Keep `k3dm_vectordb_drift_docs` unchanged; panel 14 and older notes use it.

No path label on any metric.

### C4. Alert (`scripts/etc/prometheus/rules/vectordb.yaml`)

Change `VectorDBIndexDrift` to
`expr: sum(k3dm_vectordb_drift_docs_by_kind) > 0 and max(k3dm_vectordb_oldest_drift_age_seconds) > 7200`.
Drop the `for: 2h`, because the age replaces it. The description names the three kinds and says to
run `make index-docs DRY_RUN=1`. Keep the labels.

### C5. Dashboard (`grafana-dashboard-vectordb.yaml`)

Replace panel 2 (x12 y0 w12 h8) with two panels in the same rectangle:

- Panel 2, `Drift docs by kind (last published)`. Timeseries at x12 y0 w8 h8, query
  `k3dm_vectordb_drift_docs_by_kind`, legend `{{kind}}`, unit none, decimals 0.
  Fixed colours: missing orange, stale yellow, deleted red. Its description gives the three rules from C1.
- New panel 5, `Oldest drift (last published)`. Stat at x20 y0 w4 h8, query
  `max(k3dm_vectordb_oldest_drift_age_seconds)`, unit `s`.
  Thresholds: green below 7200, orange from 7200, red from 86400. Its description says the age
  counts from the first exporter run that saw the drift.

No other panel moves. There is no overlap.

## Tests

pytest `scripts/tests/bin/test_vectordb_drift.py`. Use a fake `iter_corpus`/`fetch_hashes` and a
temp state file. Use no real store, no git ref and no Pushgateway
(`K3DM_DISPATCH_PUSHGATEWAY_URL` / the exporter's URL env set to `http://127.0.0.1:9`).

1. Corpus {a:h1, b:h2, c:h3} vs index {a:h1, b:hX, d:h4} gives missing [c], stale [b], deleted [d].
2. 3 missing + 3 deleted: `drift_docs` is 0, but `drift_docs_by_kind` has missing 3, deleted 3.
3. First-seen: run 1 at t=1000 records b; run 2 at t=5000 gives b age 4000. If b is fixed in run 3, the state no longer has b and the age is 0.
4. Kind change keeps first-seen (missing at t=1000, stale at t=3000, age measured from 1000).
5. Store unavailable: the state file is byte-identical before and after, and no `drift_docs_by_kind` line is printed.
6. The state file contains no hash and no content.

BATS `vectordb_rules.bats`:

7. Panel 2 queries `k3dm_vectordb_drift_docs_by_kind`. Panel 5 exists with unit `s`. There are no overlaps and ids are unique.
8. `VectorDBIndexDrift` uses `drift_docs_by_kind` and `oldest_drift_age_seconds`, not `drift_docs != 0`.
