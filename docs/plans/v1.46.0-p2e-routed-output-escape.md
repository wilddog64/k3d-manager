## Context

Plan 2 lets a cloud request route a job's Slack messages to an aliased channel (`notify_route`). The bot token has
`chat:write.public`, so it can post to any public channel. One mitigation the operator accepted for that risk is that **request
text cannot form a Slack mention** (`<!channel>`, `<!here>`, `<@U…>`) in a routed channel.

p2b escapes only the make **label** for routed jobs (`scripts/lib/webhook/lifecycle.py` `_run_make_target`, the
`notify_routes.escape_label(label)` call guarded by `(job_dir / "notify_route").exists()`). The same messages also append the
raw **output tail** inside a triple-backtick block:

- progress: `_post_progress` → `` f"…\n```{tail}```" ``
- final: `` f"{icon} *make {label}* {verdict} — job `{job_id}`\n```{tail or '(no output)'}```" ``

`_sanitize_cluster_output` redacts secrets but does not escape `&`, `<`, `>` or backticks. `make-find-similar-docs` is routable
and ungated, its `Q` argument allows any printable ASCII (`scripts/lib/webhook/cloud_actions.py:9`), and
`scripts/find-similar-docs.py` prints `Prior art for: "{query}"` into make's output. A `Q` of three backticks followed by
`<!channel>` closes the code block and puts a live mention in the aliased channel with no approval.

`notify_routes.escape_label(text)` (`scripts/lib/webhook/notify_routes.py:69`) replaces `&`→`&amp;`, `<`→`&lt;`, `>`→`&gt;`.

## Behaviour

1. Add `notify_routes.escape_code_block(text: str) -> str`: `escape_label(text)`, then replace every backtick `` ` `` with
   `ˋ` (U+02CB MODIFIER LETTER GRAVE ACCENT), so the text can neither form a mention nor close the surrounding code block.
2. In `_run_make_target`, when the job is routed (the same `notify_route` file check p2b uses), pass the progress tail and the
   final tail through `escape_code_block` after `_sanitize_cluster_output` and after truncation. Unrouted jobs: unchanged.
3. No other message, endpoint, or file changes.
