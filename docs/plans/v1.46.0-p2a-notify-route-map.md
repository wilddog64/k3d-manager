## Context

Later children let a cloud request name a Slack channel **alias** (for example `testing`) for its job notices. This child adds
only the map of allowed aliases and its parser. The map is configuration, not a secret, but it lives in the Keychain (with an env
override) like the Slack role map, because webhook plist values are dropped on re-render.

## Behaviour

### 1. `scripts/lib/webhook/notify_routes.py` (new)

- Constants: `ALIAS_RE = re.compile(r"[a-z][a-z0-9-]{0,31}")`, `CHANNEL_RE = re.compile(r"[CG][A-Z0-9]{8,11}")` (both used with
  `fullmatch`), `MAX_ALIASES = 8`, `MAX_RAW_BYTES = 512`, `RESERVED = {"default"}`, `ENV_VAR = "K3DM_SLACK_NOTIFICATION_ROUTES"`,
  `KEYCHAIN_SERVICE = "k3dm-slack-notification-routes"`, `INVALID_REASON = "invalid notification route"`,
  `UNSUPPORTED_REASON = "notification route not supported for this action"`.
- `parse_routes(raw: str) -> dict[str, str]`: format `alias:CHANNEL_ID[,alias:CHANNEL_ID...]`, whitespace around items and
  around `:` stripped. Empty or whitespace-only `raw` returns `{}`. Raises `RouteMapError` (a `ValueError`, message always
  exactly `invalid notification route map`, never containing input text) when: raw is over 512 bytes UTF-8; an item lacks one
  `:`; an alias fails `ALIAS_RE` or is reserved; a channel ID fails `CHANNEL_RE`; an alias or a channel ID repeats; more than 8
  aliases.
- `load_routes() -> tuple[dict[str, str], str]`: raw from `os.environ.get(ENV_VAR)` or else
  `webhook.auth._keychain_secret(KEYCHAIN_SERVICE)`; returns `(routes, "ok")`, `({}, "absent")` when raw is empty, or
  `({}, "invalid")` on `RouteMapError`. Reads the Keychain only when called; nothing at import. Never logs or prints values.
- `route_names() -> frozenset[str]`: alias names from `load_routes()` (empty when absent or invalid).
- `routable(action: str) -> bool`: true exactly when `ACTION_ALLOWLIST[action][1] == "/api/v1/make"` or action is
  `sandbox-up` or `sandbox-down` (import `ACTION_ALLOWLIST` from `webhook.cloud_actions`); false for unknown actions.
- `escape_label(text: str) -> str`: replaces `&` → `&amp;`, then `<` → `&lt;`, `>` → `&gt;`.

### 2. `scripts/etc/machine/secrets.hub.list`

Add, after the `k3dm-slack-role-map` row:
`k3dm-slack-notification-routes|k3dm|Slack notification route aliases (alias:C…,…)|operator: see docs/howto/webhook-operations.md`

### 3. `bin/k3dm-webhook-doctor`

Add `_slack_notification_routes_status()` returning `"configured"`, `"absent"` or `"invalid"`, modelled on
`_slack_role_map_status()` (`bin/k3dm-webhook-doctor:244`), using `notify_routes.parse_routes` on the env value or the Keychain
read; add key `"slack_notification_routes"` to the check result (`:281`). Absent is not a failure. Never print the value.

### 4. `Makefile`

New target `update-webhook-slack-routes`, modelled on `update-webhook-slack-roles` (`Makefile:969-974`): refuses when
`K3DM_SLACK_NOTIFICATION_ROUTES` is empty; validates it with `python3 -c` calling `parse_routes` (refuse on error, no value
echoed); then `security add-generic-password -U -s k3dm-slack-notification-routes -a k3dm -w "$(K3DM_SLACK_NOTIFICATION_ROUTES)"`
and `$(MAKE) restart-webhook`. Add one help line next to the roles target's.

### 5. Tests: `scripts/tests/bin/test_notify_routes.py` (new), `scripts/tests/bin/test_webhook_doctor.py` (extend)

Every rejection case of `parse_routes` (each rule above, one test each, including `default`, 9 aliases, 513 bytes, duplicate
alias, duplicate ID, lowercase ID, missing colon); a valid 8-alias map at exactly 512 bytes; the error message equals the fixed
string and does not contain the input; `load_routes` env-over-Keychain precedence with `_keychain_secret` patched (a test asserts
the patch is the one called; no real Keychain); `load_routes` reads nothing at import (patched helper call count 0 after
import); `routable` true for every `/api/v1/make` action and both sandbox actions, false for `cluster-status`,
`hostinger-status`, `job-status`, `health` and every `diagnose-*`; `escape_label` on `<!channel> & x>`; doctor reports
`configured`, `absent`, `invalid` with a patched runner, and its output never contains a channel ID from the fixture.
