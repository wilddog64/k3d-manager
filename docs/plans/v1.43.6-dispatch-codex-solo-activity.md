## Problem

The dispatch dashboard reads the ledger that `bin/k3dm-codex-dispatch` writes. A bare `codex exec` or
an interactive `codex` session writes no ledger event, so it never appears. When Claude's weekly cap
runs out, the operator drives Codex directly. Then the dashboard goes flat while work continues.

Plan 4 of v1.43.5 scans the session files and emits two numbers for work outside the ledger:
`k3dm_dispatch_codex_sessions{window,ledgered}` and `k3dm_dispatch_unledgered_api_cost_usd{window}`.
Those show that unledgered work exists, but not:

- **Where:** which repo the work was in.
- **How:** headless `codex exec` or an interactive session.
- **How long:** Codex's active time.
- **Quota:** how close Codex is to its own limits. Codex has a 5-hour and a weekly limit. Once Claude
  is out, the Codex weekly limit is the one that stops work.

Sessions on 2026-10-01 to 2026-10-17, by `session_meta.payload.originator` and cwd basename:

- `codex_exec` in k3d-manager: 203.
- `codex-tui` in k3d-manager: 22.
- `codex_exec` in other repos: at least 43. These included lib-foundation (11), shopping-cart-payment (11),
  hub-dr-drill (7), shopping-cart-e2e-tests (5), shopping-cart-infra (5) and shopping-cart-order (4).

## Findings

A rollout file, `${CODEX_HOME:-$HOME/.codex}/sessions/YYYY/MM/DD/rollout-*.jsonl`, carries everything
this plan needs. These shapes were read from CLI 0.162.1 on 2026-10-18:

- **First line:**
  `{"type":"session_meta","payload":{"id","timestamp","cwd","originator",…}}`. `originator` is
  `codex_exec` (headless) or `codex-tui` (interactive).
- **`{"type":"event_msg","payload":{"type":"token_count","info":{…},"rate_limits":{…}}}`:**
  - `info.total_token_usage` holds `input_tokens`, `cached_input_tokens` and `output_tokens`.
  - `rate_limits.primary` and `rate_limits.secondary` each hold `used_percent`, `window_minutes` and
    `resets_at` (epoch seconds). `window_minutes` was 300 for primary and 10080 for secondary.
  - `rate_limits.plan_type` is a string, for example `"plus"`.
- **`{"type":"event_msg","payload":{"type":"task_complete","duration_ms":N,…}}`:** one per turn. An
  interactive session has several.

The file also holds prompts, tool output, `base_instructions` and account ids. None of these may be
read into a metric.

## Fix

### C1. `bin/k3dm-dispatch-metrics`: extend plan 4's session scan

Plan 4 already streams the files modified within the last 30 days. In the same pass, also keep:

- **Mode:** from `payload.originator`. `codex_exec` maps to `exec`, `codex-tui` maps to
  `interactive`, and anything else, including a missing field, maps to `other`.
- **Repo:** the basename of `payload.cwd`.
  - Keep it only if it matches `^[A-Za-z0-9._-]{1,64}$`; otherwise use `other`.
  - Keep the 10 repos with the most sessions in the 30d window. Fold the rest into `other` in every
    window, so the label set is bounded.
- **Active seconds:** the sum of `task_complete.duration_ms` ÷ 1000. A missing value counts as 0.
- **Quota sample:** the last `rate_limits` object in the file, with that line's `timestamp`. If the
  line has none, use the session's `payload.timestamp`.

Read only these fields. Never keep prompts, tool input or output, `base_instructions`, `cwd` beyond its
basename, or any account, user or creator id.

### C2. New series

These go on the time windows (1d, 7d, 30d) only. Release scopes get none, as in plan 4.

- `k3dm_codex_sessions{window,mode,repo}`: every session, ledgered or not.
- `k3dm_codex_untracked_sessions{window,mode,repo}`: **Codex sessions detected − Codex sessions
  associated with dispatch records** (operator, 2026-10-18). Computed per session id, not by
  subtracting two totals:
  - *Detected* is the set counted by `k3dm_codex_sessions` (the `session_meta.payload.id` of each
    session file in the window).
  - *Associated* means that id appears as `session` in any `codex_usage` ledger event (plan 4,
    including events written by `usage-backfill`), in any window.
  - A resumed dispatch keeps one session id, so it is one associated session.
  - Always emit the line, with value 0, for each `(window, mode, repo)` that has detected sessions,
    so "no untracked work" reads 0, not "no data".
  - Invariant per `(window, mode, repo)`: `0 <= untracked <= sessions`.
- `k3dm_codex_tokens{window,mode,repo,kind}`. `kind` is `uncached_input`, `cached_input` or `output`,
  using plan 4's arithmetic.
- `k3dm_codex_active_seconds{window,mode}`.
- `k3dm_codex_api_cost_usd{window,mode}`: priced with plan 4's price file. Omit a mode's line when
  any of its sessions is unpriced.

The quota series are global, with no `window` label:

- They come from the newest quota sample across all scanned files.
- For each of `primary` and `secondary`, emit:
  - `k3dm_codex_quota_used_ratio{limit,window_minutes}` = `used_percent` ÷ 100, where `limit` is
    `primary` or `secondary`;
  - `k3dm_codex_quota_resets_at_seconds{limit,window_minutes}`.
- Also emit `k3dm_codex_quota_sample_timestamp_seconds`.
- Omit all quota lines when no sample exists. Omit a limit's lines when `used_percent` is missing
  or not a number.

The label is `limit`, not `window`, because `window` already means the dashboard's spec window.

### C5. Quota efficiency against verified outcomes (2026-10-22 amendment)

Purpose: quantify how many independently **verified deliverables** the Codex workflow produces per percentage point of its own subscription weekly quota, while keeping token price, raw quota percentages, and human involvement distinct. This is an efficiency/coverage statistic, **not** proof of bug-fix accuracy or monetary cost equivalence with Claude.

- **Data source:** use C1/C2's observed secondary quota `used_percent`, `resets_at`, sample timestamp and the v1.43.6 verified-delivery-cost plan's `delivered` definition. Capture and retain bounded, timestamped quota observations (or use existing Prometheus observations with equivalent retention) so interval deltas can be computed. The single newest sample by itself cannot establish quota spent over an interval. Do not read additional session content or secrets.
- **Cycle boundary:** treat `secondary.resets_at` as the identifier of the reported weekly cycle, not a hard-coded Tuesday or a guessed 7-day boundary. Compute a nonnegative **percentage-point** consumption delta only between chronological valid observations in the *same* reset cycle. If the reset identity changes, `used_percent` falls unexpectedly, timestamps reverse, or coverage is insufficient, mark the interval unavailable instead of calculating a negative or invented delta. A rate_limit `resets_at` update may reflect a service-side adjustment: never silently join different reset identities.
- **Counting outcomes:** count each distinct task/spec once when it becomes independently verified within the exact measured quota interval, based on plan 2's events/evidence. Report *verified specs*, and *verified bugs* separately **only when** there is a trustworthy bug-doc-to-task association. Exclude merely started, exited, landed-but-unverified, and reopened-not-yet-reverified items. Do not claim a live check was performed simply because the controlled landing tests passed.
- **Metric:** `verified_deliverables / weekly_quota_percentage_points_consumed` with an explicitly displayed covered interval and denominator. If the delta is zero, missing, too small to measure reliably, crosses a reset, or verified delivery cannot be joined to the interval, show **N/A**. For an interval with incomplete observation coverage, show the raw readings and a coverage warning, not a confident efficiency ratio. Display separate readouts for **verified outputs**, **observed quota delta (percentage points)**, and **outputs per percentage point**.
- **Model attribution:** when actual coordinator/worker model and reasoning effort are reliably recorded (by a separately approved attribution mechanism), segment by them; otherwise show `unknown`. Do not derive actual GPT-6-Luna or GPT-5-Luna identity from a current CLI default or retroactively label old dispatches. Do not attribute global Codex quota use solely to dispatched workers: it also includes interactive/untracked Codex use.
- **Cross-provider comparison:** Claude's session quota telemetry is not available under this spec. Do not manufacture Claude quota values or directly compare a Codex quota percentage point with a Claude percentage point as if they represented equivalent spending. A future separately scoped source may extend the dashboard when trustworthy Claude quota readings, matched verified outcomes and human-intervention evidence exist.
- **Observed example, not fixture/backfill:** the operator reported 81% remaining (19% used) with reset expected on 2026-10-27 at 4 PM Pacific. This establishes one anecdotal reading, not a verified consumption delta, per-bug cost, or reset policy. Do not seed historical values from this conversation.

Add a separate **Quota efficiency (verified outcomes)** panel group to the existing C3 row or directly below it without moving existing panels, with measurement-interval text, raw readings, delivery count, ratio and coverage status. The implementation may choose a bounded retrospective interval supported by actual sampled timestamps and verified events; it must not imply that the dashboard's arbitrary rolling 1d/7d/30d selections necessarily coincide with a Codex reset cycle. Update C4 guide with denominator semantics and missing-data rules.

### C6. `bin/k3dm-agy`: a pass-through wrapper that records agy runs (2026-10-24 amendment)

agy keeps its conversations under `~/.gemini/antigravity/`, next to account and credential files. That
tree is never read, by the exporter or by anyone else. Instead, the operator puts a wrapper on `PATH`
ahead of the real `agy`, and the wrapper writes one line per run to a ledger of its own.

- **Finding the real binary:** `K3DM_AGY_REAL` if set; otherwise the first `agy` on `PATH` whose
  resolved path is not the wrapper's own resolved path. If none is found, print
  `k3dm-agy: real agy not found on PATH` to stderr and exit 127. The wrapper must never call itself.
- **Pass-through:** argv, stdin, stdout, stderr and the exit code are exactly the real agy's. The wrapper
  never adds, removes or reorders an argument. A ledger write that fails prints one stderr warning and
  never changes the exit code.
- **Interactive mode** (no `--print`/`--prompt`): run the real agy as a child process attached to the
  same terminal, ignore `SIGINT` in the wrapper while it runs, and record the run when it exits. Never
  capture its output.
- **Print mode** (`--print` or `--prompt` present): stream stdout to the terminal unchanged while a copy
  goes to a `mktemp` file under `${TMPDIR}`. If `--output-format json` was given, read usage from the copy
  as in C6a. Delete the copy on exit, including on a signal.
- **Not recorded:** the subcommands `models`, `changelog`, `help`, and any run with `--help`, `-h` or
  `--version`. These still pass through.
- **Ledger:** `${K3DM_AGENT_LEDGER_DIR:-$HOME/.local/share/k3d-manager/agent-sessions}/agy.jsonl`,
  created with mode 0700 for the directory and 0600 for the file. One JSON object per run:
  `{"agent":"agy","id":<uuid>,"start":<epoch>,"end":<epoch>,"duration_s":<n>,"exit":<n>,
  "mode":"print"|"interactive","model":<id or null>,"repo":<basename>,"dispatch_slug":<slug or null>,
  "usage":<object or null>}`.
  - `model` is the value after `--model`, kept only if it matches `^[A-Za-z0-9._-]{1,64}$`; otherwise
    `null`. Never guess agy's default model.
  - `repo` is the basename of the working directory, under the same `^[A-Za-z0-9._-]{1,64}$` rule;
    otherwise `other`.
  - `dispatch_slug` is `K3DM_DISPATCH_SLUG` when set and valid; otherwise `null`.
  - Never record argv, the prompt, output text, the environment, or any path beyond the basename.

#### C6a. Usage from print-mode JSON

Observed 2026-10-24 (agy E2 run): stdout is a plain status line (`root agent idle; waiting …`)
followed by one JSON object, `{"conversation_id", "status", "response", "usage": {"input_tokens",
"output_tokens", "thinking_tokens", "cache_read_tokens", "total_tokens"}}`. So:

- Use the last line of the copy that parses as a JSON object. Never parse the whole copy as one value,
  because the status line would make every run read as having no usage. If no line parses, `usage` is
  `null`.
- Take the object under its top-level `usage` key. Keep only keys whose value is a non-negative integer
  and whose name matches `(?i)token` and `^[A-Za-z0-9_]{1,48}$`, at most 12 keys. If none survive,
  `usage` is `null`.
- Never record `response` or `conversation_id`, and never invent a count.
- E5's fixture must reproduce the status-line-then-JSON shape.

### C7. The dispatcher marks its own agy runs

`bin/k3dm-codex-dispatch` adds `K3DM_DISPATCH_SLUG=<slug>` to the `state_vars` it passes to the agy worker.
A dispatched run that goes through the wrapper is then recorded with its slug and is never counted as
untracked. The Codex worker's command line and environment do not change.

### C8. agy series, dashboard and docs

On the time windows (1d, 7d, 30d) only, from the wrapper ledger by `start`:

- `k3dm_agy_sessions{window,mode,repo}`: every recorded run. `repo` uses C1's top-10 rule, computed
  over agy runs.
- `k3dm_agy_untracked_sessions{window,mode,repo}`: runs with `dispatch_slug` `null`. Emitted as 0 where
  every run is dispatched.
- `k3dm_agy_active_seconds{window,mode}`: the sum of `duration_s`.
- `k3dm_agy_tokens{window,mode,kind}`: `kind` is the usage key from C6a, lowercased. Summed only over
  runs that have usage.
- `k3dm_agy_runs_without_usage{window,mode}`.

No agy cost series: there is no agy price in the price file, and none is invented. A missing or
unreadable wrapper ledger exports no agy lines and does not fail the export. A ledger line that does not
parse is skipped.

Dashboard: a new row "All agy activity (including outside the dispatcher)" below C3's row, with stats for
sessions, untracked sessions and active hours, and bar gauges for sessions by mode and untracked by repo.
A tokens panel shows "No data" when no run reported usage. Its description says why.

Docs:

- `docs/howto/codex-dispatch.md` gains a subsection under the agy section covering:
  - `make agy-wrapper-install`, which symlinks `${AGY_WRAPPER_DIR:-$HOME/.local/bin}/agy` to `bin/k3dm-agy`
    and then prints `type -a agy`, so the operator can confirm the wrapper comes first;
  - `make agy-wrapper-uninstall`, which removes that symlink only if it points at `bin/k3dm-agy`;
  - what is and is not recorded.
- The C4 guide paragraph also covers the agy row. Only runs made through the wrapper are counted, and
  interactive runs never carry usage.
