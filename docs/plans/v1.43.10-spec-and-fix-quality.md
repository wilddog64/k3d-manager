## Problem

The dashboards show what a spec cost (runs, tokens, time to land) and, after v1.43.9, how big it
was. Nothing shows whether it was **right**. The operator's question has two halves:

1. **Spec quality** — did the spec produce the right change the first time?
2. **Fix quality** — did the change stay right after it landed?

Most of the evidence is already recorded and unused at the per-spec level:

| Signal | Recorded today | Gap |
|---|---|---|
| Worker reran (`codex_exit` > 1) | ledger | exported only as a window total (`k3dm_dispatch_rework_landed{cause="rerun"}`) |
| Land refused for failing tests | ledger `land_refused reason=tests` | window total only |
| Claude edited the work before land | `land.verifier_lines` | window total only |
| Review failed | ledger `verify result=fail` | `verify` has 4 records in 168 dispatches (all `pass`); reviews are not recorded |
| Human continuation prompts | ledger `intervention` (since v1.43.7) | not per spec on Per spec |
| Spec edited after dispatch | git history of the spec file | not measured |
| Independent verifier disagreed | nowhere | not recorded |
| A later bug was caused by this change | prose only, if at all | no structured link |

A real example from 2026-10-25: two changes on `k3d-manager-v1.43.7` broke CI and were not seen
until the release PR. A dashboard refresh change broke the Host Disk test, and a roadmap edit broke
the milestones drift test. Neither is recorded against the change that caused it.

## Scope and design

Separate columns and counts. **No combined quality score** (same decision as the v1.43.9
complexity plan: a single number hides the reason and invites gaming).

### Q1. Per-spec spec-quality signals (Agent Dispatch)

For each landed task, export the signals the exporter already computes per task in the rework
calculation (`rerun`, `tests`, `claude_edit`, `review`) plus:

- `interventions` — count of `intervention` events for the task (coverage rules from v1.43.7 apply:
  before the coverage marker the value is unknown, not 0).
- `spec_edits_after_start` — commits that changed the spec file between the task's first `start`
  and its `land`, in the repository holding the spec. Commits whose diff only changes header lines
  (`**Status:**`, `**Fix commit:**` and other `**Name:**` lines before the first `## ` heading) do
  not count; those are bookkeeping.
- `verifier` — `pass`, `fail` or unknown, from the latest `verify --verifier independent` record.

Per spec gains a **Clean land** column (yes when none of `rerun`, `tests`, `claude_edit`,
`review`, `spec_edits_after_start` hit) and the individual signal columns beside it. It is named
Clean land, not First pass, because **First pass** already means the first *live* verification
passed (`k3dm_dispatch_live_verified_bug_first_pass`, used by plan 1); the two answer different questions.

### Q2. Make review and verifier results recordable

- `k3dm-codex-dispatch verify` gains `--defects <n>` (count of defects the review found, 0 for a
  clean pass) and accepts `--verifier independent` for the independent verifier's result. Existing
  `verify` records stay valid; a record without `--defects` reads as unknown.
- The dispatch how-to states that Claude records `verify` after every review of a landed task.
  Coverage starts with a marker event, as interventions did; tasks landed before it show unknown.

### Q3. Fix quality: escapes linked by a header

- New optional bug-doc header `**Caused by:** <sha>[, <sha>…] — <one-line note>`, naming the commit
  (or commits) that introduced the defect. It is different from v1.44.0's `**Recurred:**`, which
  records the *same* bug returning.
- The bug-doc scan resolves each cited SHA to the dispatched task that landed it (ledger
  `land.commit`) and to the release whose branch first contained it. Unresolvable SHAs are counted
  as `unattributed`, never guessed.
- Per spec gains an **Escapes** column; Bug Tracking gains a per-release **Escaped defects**
  count (bugs whose `Caused by` commit belongs to that release), next to the release's bug totals.
- Filing guidance in `CLAUDE.md`-referenced docs: add `Caused by` when the cause is known; leave it
  out when it is not. No backfill beyond what the operator asks for.

### Q4. Per-release roll-up

Bug Tracking's release row shows, per release: specs landed, clean-land count, review-fail count,
verifier-fail count, escaped defects. Values with incomplete coverage show **Unknown**, not 0.

## What NOT to Do

- Do not build a combined quality score.
- Do not reimplement v1.44.0's `**Recurred:**` or `**Verified by:**` parsing; read them only if present.
- Do not infer an escape from timing, file overlap or commit messages.
- Do not backfill `Caused by` across old bug docs unless the operator asks.
- Do not create a PR, commit to `main`, or skip pre-commit hooks.
