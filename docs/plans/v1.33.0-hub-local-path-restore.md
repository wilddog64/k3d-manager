# v1.33.0 — Hub local-path restore-mapped rebuild

**Status:** planned; execution waits for `COPY_CHECKSUM_VERIFIED`

## Objective

Rebuild the hub K3s/Kine control plane without losing data stored by the
`local-path` provisioner. The stable identity is `(namespace, claim name)`, not
the old PVC UID or the old Docker volume name.

## Preconditions

1. The M2 monitor writes `COPY_CHECKSUM_VERIFIED`; any other result stops the
   process.
2. The source and M2 recovery copies remain immutable through acceptance.
3. Generate a machine-readable mapping from the captured PV/PVC export. Reject
   missing, duplicate, or unexpected claim names before any restore action.
4. Export current workload images and scale the stateful consumers down before
   copying into their target local-path directories.
5. Never use `k3d cluster delete`, wildcard Docker volume removal, or raw
   SQLite deletion in this procedure.

## Execution sequence

1. **Preflight.** Verify M2 checksums, the seven mapped source trees, and all
   expected claim names. Record source ownership and modes. Fail closed on any
   mismatch.
2. **Recreate control plane.** Stop the resolved server node, replace only its
   K3s datastore volume, and recreate/rejoin nodes with the same logical node
   indexes. Preserve all captured source data independently of Docker volumes.
3. **Bootstrap desired state.** Bring up only the GitOps/Vault prerequisites
   until the new PVCs are provisioned. Do not start a consumer that can write a
   target claim before its restore completes.
4. **Resolve new targets.** Query the new PVs by namespace and claim name and
   derive their new `local.path`. A target must resolve to exactly one path on
   the expected logical node.
5. **Restore in dependency order.** Scale down the owning workload; copy data
   via tar streams into the resolved target directory; restore mode and
   ownership; then start it. Order: Vault, PostgreSQL, LDAP data/config,
   Keycloak, Trivy, then Prometheus. Prometheus may be explicitly skipped only
   if the owner accepts losing historical metrics.
6. **Verify.** Confirm Vault unseals and its expected KV/policies exist;
   Keycloak login and LDAP federation work; Trivy becomes ready; Prometheus
   loads expected blocks when selected. Finally restore normal GitOps
   reconciliation and require `/readyz` plus `make status` with no
   control-plane error.

## Implementation and offline gates

- Add a narrow recovery helper with `plan`, `validate`, and `restore` modes.
  `plan` and `validate` are read-only; `restore` requires explicit confirmation
  and consumes only the captured claim map.
- Add BATS coverage for duplicate/missing claim rejection, logical-node
  mismatch, restore order, and the no-wildcard/no-raw-delete invariant.
- Run BATS, shellcheck, `bash -n`, and `_agent_audit` before the live rung.

## Acceptance

- The helper records every old claim identity and exactly one new target.
- No source or M2 recovery file changes during the live rebuild.
- Every selected durable workload passes its service-level verification.
- Hub `/readyz` and `make status` pass before the temporary tmux copy/monitor
  sessions or recovery data are retired.
