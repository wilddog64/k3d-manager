## Why

The first M5 `make machine-setup ROLE=hub` run found all 14 hub Keychain items missing. The M4 has every one of them. They do not sync through iCloud: `security add-generic-password` writes the file-based login keychain, which is local to each Mac.

Re-creating them by hand is impossible or harmful:
- Some values are shown only once at creation (the Cloudflare API token).
- Some setup commands change live systems. The manifest offered `bin/k3dm-worker-setup` for `k3dm-cloudflare-api-token`, and that script pushes GitHub secrets and redeploys the live Slack relay Worker. The operator answered y and had to interrupt it.

A second machine should copy the items, not mint them again.

## Design

New script `bin/k3dm-machine-secrets`, run by the operator in a normal terminal on each Mac (login keychain unlocked; never over SSH), with two subcommands.

### `export --role <role> [--out FILE]` (on the old machine)

1. For each service in `scripts/etc/machine/secrets.<role>.list`, export **every** generic-password item with that service, whatever its account. Enumerate accounts from `security dump-keychain` attributes only; never pass `-d`. This covers `*`, `USER` and services with several accounts (`k3dm-vault-unseal-dr` has `secrets/vault:count` and `secrets/vault:shard1`).
2. Read each value with `security find-generic-password -s S -a A -g` and parse stderr:
   - `password: 0x<HEX>  ...`: use the hex;
   - `password: "<text>"`: hex-encode the text between the first and last quote.
   - Do not use `-w`, which hex-encodes multi-line values ambiguously.
   - A missing or empty value is reported `skipped (empty)` and not exported.
3. Build records `service<TAB>account<TAB>hexvalue`, one per line, and pipe them straight into `openssl enc -aes-256-cbc -pbkdf2 -iter 200000 -salt -out FILE`. Use `umask 077`, so the file is mode 600.
   - The plaintext exists only in pipes and shell variables: never on disk, never in argv.
   - Default FILE: `${XDG_STATE_HOME:-$HOME/.local/state}/k3d-manager/machine-secrets-<role>.enc`.
   - Refuse to overwrite an existing FILE.
4. Passphrase: prompt twice with `read -rs` from `/dev/tty`, require them to match, and pass it as `-pass fd:N`, never `-pass pass:`.
   - Tests only: `K3DM_SECRETS_PASSPHRASE_FILE` names a file read with `-pass file:`.
5. Print one line per item, `exported <service> <account>`, then the FILE path with `$HOME` shown as `~`, and the next step.

### `import --in FILE [--force]` (on the new machine)

1. Decrypt with the same openssl options, passphrase prompted once (or the test file), into a pipe.
2. For each record:
   - If the item exists (`security find-generic-password -s S -a A`, no value flags) and `--force` is not given, report `skipped (present)`.
   - Otherwise add it by writing `add-generic-password -U -s S -a A -X <hex>` to `security -i` on **stdin**, so the value never appears in argv.
   - Validate service and account against `^[A-Za-z0-9._:/@+-]+$` before use. A record that fails is reported `rejected (bad name)` and not added.
3. A record with an empty hex value is rejected, never stored.
4. After all records:
   - Delete FILE only if every record was `copied` or `skipped (present)`. Otherwise keep it and say so.
   - Exit 1 if any record failed.
5. Print one line per item (`copied`, `skipped (present)`, `rejected (...)`, `failed`), never a value.
6. A wrong passphrase reports `could not decrypt` and exits 1 without touching the keychain.
7. When `security` reports `User interaction is not allowed`, print: "the login keychain is locked; run this in a terminal on the Mac itself, not over SSH".

**Goal:** on a new Mac, `make machine-setup ROLE=hub FROM=m4-air.local` copies the missing Keychain items from the old Mac with no file, no transfer passphrase, and no separate command to remember.

### Proven building blocks (Claude, 2026-10-30)

- **The M5 can reach the M4 by SSH with password auth.** Remote Login is on and the M4 offers `publickey,password,keyboard-interactive`. `ssh` prompts for the password on the terminal itself, so stdin stays free for data. No SSH key is needed.
- **`security unlock-keychain <keychain>` reads the password from stdin when there is no terminal.** Tested on a throwaway keychain: rc 0, then unlocked. The password never appears in argv.
- **A non-login SSH session runs `/bin/bash` 3.2**, and `PATH` lacks `/opt/homebrew/bin`. The remote command must run `/opt/homebrew/bin/bash` explicitly, since the script needs bash 4+.

### `bin/k3dm-machine-secrets`

- **`export --role R --stream [--unlock] [--keychain PATH]`** writes plain records (`service<TAB>account<TAB>hex`) to stdout instead of encrypting to a file. The SSH channel is the encryption.
  - `--stream` refuses to run when stdout is a terminal (`[[ -t 1 ]]`), so records can never be printed to a screen.
  - The per-item `exported`/`skipped` lines stay on stderr.
  - With `--unlock`, it first reads one line from stdin and pipes it to `security unlock-keychain <login keychain, or --keychain>` on stdin. A failed unlock exits 1 with "could not unlock the keychain", before any record is written. The password variable is unset after use.
  - An item whose read fails with `User interaction is not allowed` (an ACL that wants a GUI approval) is reported on stderr as `skipped (needs approval on the old Mac) <service> <account>`. Export continues.
- **`import --in -`** reads records from stdin. It applies the same validation, skip-present rule, `--force` and per-item lines as a file import, but there is nothing to delete. Zero records exits 1.
- **`pull --from HOST --role R [--repo PATH] [--force] [--keychain PATH]`** runs on the new Mac:
  1. `HOST` must match `^[A-Za-z0-9.-]+$`, else exit 2. `--repo` defaults to `src/gitrepo/personal/k3d-manager` relative to the remote home and must match `^[A-Za-z0-9._/-]+$`.
  2. It prompts `Login password for the keychain on HOST: ` with `read -rs` from `/dev/tty`. Empty input aborts.
  3. It runs `ssh -o ConnectTimeout=10 HOST "cd REPO && /opt/homebrew/bin/bash bin/k3dm-machine-secrets export --role R --stream --unlock"`, feeding the password as the only stdin line via `printf '%s\n'` (a builtin). The remote stdout is piped straight into `import --in -` (plus `--force`/`--keychain`), and the remote stderr passes through.
  4. It exits non-zero when ssh, the remote export or the import fails. On failure it prints the fallback: `make machine-secrets-export ROLE=R` on HOST, then `make machine-secrets-import FILE=…` here.
  - The pipeline holds records only in pipes and variables, never on disk.

### Setup integration (`bin/k3dm-machine-setup`)

- New option `--from HOST`. `make machine-setup ROLE=<role> FROM=<host>` passes it through; `FROM` is optional. `machine-check` ignores `FROM`.
- In setup mode with `--from`, the secrets phase first runs `bin/k3dm-machine-secrets pull --from HOST --role R`, and only when at least one manifest item is missing and stdin is a terminal. Then it checks every item as today. Items the pull copied report `ok`; items still missing fall through to today's per-item prompt.
- A pull failure is recorded as `secret-pull missing (see output above)`. Setup still continues with the per-item checks.
- Without `--from`, setup is unchanged, except that the hint line becomes: `Moving from another Mac? Rerun with FROM=<old Mac hostname> to copy these items (docs/howto/machine-setup.md).`
- `--check` and `--dry-run` never run a pull. `--dry-run` prints `would pull secrets from HOST` when `--from` is set.

### Docs

`docs/howto/machine-setup.md`:
- The M5 cut-over step becomes `make machine-setup ROLE=hub FROM=m4-air.local`. It notes the two password prompts: ssh login, then keychain unlock, normally the same password.

## What NOT to do

- Do not read, print or copy any item from the real login keychain. Tests use `--keychain` throwaway files or the stub only.
- Do not make a real ssh connection in any test. Do not run `security unlock-keychain` on the login keychain in tests.
- Do not add an SSH key, `ssh-copy-id`, `sshpass`, `SSH_ASKPASS`, or `-o StrictHostKeyChecking=no`.
- Do not use `security ... -w VALUE`, `-X` in argv, `openssl -pass pass:`, or `echo "$value"` into a log.
- Do not create a PR, commit to `main`, or use `--no-verify`.
- Do not touch files outside the list above.
- `set -euo pipefail`; shellcheck clean.
