**Status:** QUEUED for v1.45.0. Dispatch to Codex when the branch opens.

**Implementer:** Codex · **Verifier:** Claude

## Problem

Standing docs go stale silently, and nothing notices until someone asks. On 2026-10-09 the
operator asked whether four docs were current. All four were stale. The worst case was
`docs/architecture/webhook-server.md`, which went untouched for about 30 webhook commits (see
`docs/bugs/2026-10-09-webhook-server-architecture-doc-stale.md`). It had:
- two contradictory line counts for `bin/k3dm-webhook`, both wrong;
- 6 missing modules;
- 17 make targets where there are 29;
- a missing route;
- line ranges from a file 1,400 lines longer than today's.

Most of those facts can be derived from the code. The rest depends on judgment ("does this
section still describe the behaviour?"), and the only check for it is an ad-hoc audit.

`make check-doc-links` already catches broken links and anchors. Nothing catches wrong facts or
stale prose.

## Design: three layers

| Layer | What it catches | Who acts | Model involved |
|---|---|---|---|
| 1. Generated doc blocks + `make docs-check` | Facts derivable from code (module tables, routes, targets, line counts) | CI / pre-commit fails; author runs `make docs-regen` | none |
| 2. Hermes weekly drift digest | Prose that is probably stale: covered code changed a lot since the doc was last edited | Hermes posts to Slack (read-only) | none (git only) |
| 3. Drift → bug-doc draft | A doc over the threshold gets a bug doc listing its drift evidence | Hermes drafts; Codex rewrites; Claude verifies; operator merges | optional, advisory |

Hermes **never edits a doc**. It detects drift and reports it, and that matches its Phase 1
read-only scope (`docs/architecture/hermes-phase1-monitoring-scope.md`).

## Fix

### 1. Generated blocks: `scripts/docs-regen.py` (new)

A Markdown doc marks a generated region with a matching marker pair:

```markdown
<!-- generated:webhook-routes -->
...body owned by the generator; do not edit by hand...
<!-- /generated:webhook-routes -->
```

`scripts/docs-regen.py` has a registry `GENERATORS: dict[str, Callable[[Path], str]]`, keyed by
block name. Each generator takes the repo root and returns the block body. In the default
(write) mode the script finds every marker pair in tracked `docs/**/*.md` and replaces each body
with its generator's output. In `--check` mode it writes nothing; for every block whose current
body differs from the generated body, it prints `path: block <name> is stale` and exits 1.

Error handling:
- An unknown block name, or an unclosed or nested marker, is an error (exit 2) in both modes. It
  must never be silently skipped.
- Generators are pure reads of the tree: no network, no subprocess except `git ls-files`, and no
  imports of the code under description. Parse it with `ast`/regex, so a broken module cannot
  break the check.

Output must be deterministic: sorted rows, no timestamps. Line counts are the exception, since
they are facts of the tree; give them in the form "N lines" with no date (the commit dates them).

**Initial generators**, all for `docs/architecture/webhook-server.md`, to replace the hand-written
tables Codex rewrote in `d1f66a98`:

| Block | Source | Columns |
|---|---|---|
| `webhook-modules` | `scripts/lib/webhook/*.py` except `__init__.py` | module, `wc -l`, first line of module docstring, intra-package imports (`from webhook.X` / `from .X`) |
| `webhook-routes` | `_POST_ROUTES` and `_GET_ROUTES` dict keys in `bin/k3dm-webhook` (via `ast`) | method, path, handler name |
| `webhook-confirm-targets` | `MAKE_TARGETS` entries with `confirm` in `scripts/lib/webhook/make_targets.py` | target, tier |
| `webhook-monolith-size` | `bin/k3dm-webhook` | one sentence: "`bin/k3dm-webhook` is N lines." |

Keep the hand-written responsibility prose outside the blocks. Where a generated column
duplicates prose (the module docstring), the docstring is the source of truth. Fix the
docstring, not the doc.

### 2. Make targets and gates

- `make docs-regen`: `python3 scripts/docs-regen.py`.
- `make docs-check`: `python3 scripts/docs-regen.py --check`.
- **CI:** add a `docs-check` step to `.github/workflows/ci.yml`, next to the existing doc-link
  check if there is one; otherwise in the lint job. It needs `permissions: contents: read` only.
- **Pre-commit:** in `.githooks/pre-commit`, run `scripts/docs-regen.py --check`. Run it when
  any staged path is a generator source (`bin/k3dm-webhook`, `scripts/lib/webhook/**`) or a doc
  containing a `generated:` marker. Copy the existing `K3DM_SKIP_DOC_LINKS` block, and give it
  its own skip variable, `K3DM_SKIP_DOCS_CHECK`. On failure, print
  `run: make docs-regen`.

### 3. Coverage front-matter for drift detection

Standing docs under `docs/architecture/` and `docs/guides/` may declare the code they describe on
the line after the H1:

```markdown
# Architecture: Webhook Server

<!-- covers: bin/k3dm-webhook scripts/lib/webhook/** -->
```

The globs are space-separated and use git pathspec syntax. A doc with no `covers:` line is ignored
by layer 2. Add `covers:` lines to these four docs, which are the ones audited on 2026-10-09:

| Doc | covers |
|---|---|
| `docs/architecture/webhook-server.md` | `bin/k3dm-webhook scripts/lib/webhook/**` |
| `docs/architecture/cloud-bridge.md` | `bin/k3dm-cloud-bridge scripts/lib/webhook/cloud_actions.py scripts/lib/webhook/policy.py` |
| `docs/architecture/vector-store.md` | `scripts/index-docs.py scripts/find-similar-docs.py scripts/lib/hermes/prior_art.py scripts/lib/hermes/embed_cache.py scripts/etc/argocd/vectordb/**` |
| `docs/architecture/hermes-phase1-monitoring-scope.md` | `bin/k3dm-hermes scripts/lib/hermes/sensors.py scripts/lib/hermes/pager.py` |

Before writing each glob, confirm with `git ls-files -- <glob>` that it matches at least one file.
`docs-regen.py --check` must also fail (exit 2) on a `covers:` glob that matches nothing, so a
renamed file cannot make a doc look fresh forever.

### 4. Hermes sensor: `scripts/lib/hermes/docs_drift.py` (new)

```python
def drift_report(git, repo_root, threshold=10) -> list[dict]:
    """For each tracked doc with a covers: line, count commits to its covered paths since the
    doc's own last commit. git is an injected callable(args) -> str for testability."""

def weekly_docs_drift_advisory(git, repo_root, state, this_week, threshold=10) -> str | None:
    """Once-per-ISO-week gate (mirrors audit.monthly_audit_advisory). Returns the digest the
    first time this_week (YYYY-Www) is seen, then stamps state["last_docs_drift_week"]."""
```

For each doc:
- `last_doc = git log -1 --format=%H -- <doc>`.
- `commits = git log --format='%h %s' <last_doc>..HEAD -- <covers globs>`. Exclude merge commits
  and commits that touch only `memory-bank/`.
- Record `{doc, last_edited (date), commits: N, subjects: first 5}`.

The digest lists only docs with `N >= threshold`, sorted by N descending:

```
Hermes docs drift (2026-W41) — 2 docs behind their code
• docs/architecture/webhook-server.md — 31 commits to covered paths since 2026-09-25
    8aa14053 fix(webhook): cap every relayed slash command at the caller's role
    ...
```

If no doc is over the threshold, return `None`, so nothing is posted. A quiet week is silent.

Wire it into `bin/k3dm-hermes` right after the `monthly_audit_advisory` call, with the same
pattern: compute, then `post_summary(relay, digest)` if truthy. Settings:
- The threshold comes from `K3DM_HERMES_DOCS_DRIFT_THRESHOLD` (default 10).
- The feature is enabled unless `K3DM_HERMES_DOCS_DRIFT_ENABLED=0`.
- The git callable runs `git -C <repo_root>` with a fixed argv, never through a shell.

Read-only: no `git fetch`, and no writes to the repo. The digest reflects the checkout's `HEAD`.
If `git` fails (not a repo, detached), post nothing and record a warning in state.

### 5. Drift → bug-doc draft (layer 3, advisory)

For each doc in the digest with `N >= 2 * threshold`, Hermes drafts a bug doc. It reuses the
existing bug-filing path that `_file_app_health_bugs` uses: its own worktree and branch, with
dedup through the exact-slug glob plus the `prior_art` similarity pass.

- **Slug:** `<doc-stem>-doc-stale`.
- **Body:** the Symptom section lists the doc, its last edit, and every covering commit subject.
- **Fix:** points at `docs/bugs/2026-10-09-webhook-server-architecture-doc-stale.md` as the
  template.
- **Priority:** P3 (field from `v1.43.0-bug-priority-tracking.md`).

If that path cannot be reused unchanged, skip layer 3 and record why in the PR. Layers 1 and 2
stand on their own.

## Tests (each new test is shown failing against the pre-change code, on a temp copy)

Pytest, under `scripts/tests/hermes/` beside `test_audit.py`:

1. `docs-regen --check` exits 1 when a `webhook-routes` block lacks a route added to a fixture
   `_POST_ROUTES`. It exits 0 after a regen, and that second regen produces no diff (idempotent).
2. Unknown block name, unclosed marker, nested marker: each exits 2 with the file and line.
3. A `covers:` glob matching nothing exits 2.
4. Generators never import the code they describe. Run them on a fixture module that raises on
   import, and assert the output is still produced.
5. `drift_report` with a stub `git`:
   - counts commits after the doc's last commit;
   - ignores docs with no `covers:` line;
   - excludes merges and commits that touch only memory-bank.
6. `weekly_docs_drift_advisory`:
   - returns a digest once per ISO week, then `None` on a second poll in the same week;
   - returns `None` when nothing is over the threshold;
   - returns `None` when disabled by env.
7. The digest goes through the existing Slack redaction path. Feed it a commit subject that
   contains a token-shaped string, and assert the string is redacted.

BATS: one test in `scripts/tests/lib/` asserting `.githooks/pre-commit` invokes
`docs-regen.py --check` and honours `K3DM_SKIP_DOCS_CHECK`.

## What NOT to Do

- Do NOT let Hermes edit, commit or open a PR for any doc. Layer 3 drafts a bug doc only, through
  the existing bug-filing path.
- Do NOT call a model to decide drift in layers 1 or 2. Use git and the AST only.
- Do NOT `git fetch` or `pull` from Hermes.
- Do NOT generate prose. Generators emit tables and counts, and prose stays hand-written.
- Do NOT create a PR or merge, do NOT commit to `main`, and do NOT use `--no-verify`.
- Do NOT touch `scripts/lib/foundation/`.
