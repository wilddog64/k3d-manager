**Branch:** `k3d-manager-v1.45.0`
**Filed:** 2026-11-18
**Intent approved:** no
**Risk:** critical. This part is the second factor in front of an interactive shell on the operator's Mac, and adds a second root LaunchDaemon. Dispatch needs the operator's go. The operator runs every live step; the worker runs none.
**Depends on:** part A ([`v1.45.0-web-console-a-console-sshd.md`](v1.45.0-web-console-a-console-sshd.md)): its `ForceCommand` path, its config directory and its install pattern. Independent of part B.
**Operator decisions applied:** D3 (TOTP at every login through a root-owned gate that traps INT/TSTP/QUIT/HUP, loops until a valid code, never exits into a shell, rate-limits, keeps replay state root-owned, then attaches; idle layer fails closed), D4 (this is part C).
**Deviation to confirm (open question 1):** D3 says the idle lock sets tmux lock options globally. The four tmux 3.8 bypasses Fable proved (per-client lock, Ctrl-C at the prompt, non-zero `lock-command`, `lock-after-time` not following a session switch) all live inside tmux's lock. This spec therefore does not use tmux locking at all: the idle layer is the gate detaching an idle client and asking for a code again. It sets no tmux option, so the operator's local tmux clients are untouched by construction.

## Problem

Cloudflare Access and GitHub 2FA decide who may open the console. They do not decide that the person at the browser right now is the operator: an unattended or borrowed browser session, or a stolen Access session within its 6 hours, would reach a shell. The operator chose a TOTP code at every login (D3) and after 2 idle minutes. Part A's sshd runs a `ForceCommand`; this part replaces its refusing stub with the gate.

## Behaviour

Components, all root-owned, none inside the checkout or `$HOME`:

- Gate `/usr/local/libexec/k3dm-web-console/forced-command` (`root:wheel`, `0755`), Python 3 stdlib only, `#!/usr/bin/python3` (Apple's 3.9.6 on the M4; no syntax newer than 3.9). Runs as the operator user, because sshd drops privileges before `ForceCommand`.
- Verifier daemon `/usr/local/libexec/k3dm-web-console/totpd` (`root:wheel`, `0755`), same interpreter, run by the LaunchDaemon `com.k3d-manager.web-console-totp` (`/Library/LaunchDaemons/com.k3d-manager.web-console-totp.plist`, `root:wheel`, `0644`).
- Config `/etc/k3dm-web-console/totp.conf` (`root:wheel`, `0644`), `key=value` lines: `uid=<operator uid>`, `tmux=<absolute path>`, `idle_seconds=120` (accepted 5-600), `poll_seconds=5` (accepted 1-10), `window=1`.
- State directory `/var/db/k3dm-web-console` (`root:wheel`, `0700`): `totp.secret` (`0600`, base32, 160 bits from `os.urandom(20)`), `state.json` (`0600`: `last_counter`, `failures`, `locked_until`, `enrolled`). Written by write-temp, `fsync`, `rename`. This is the defined root-owned place for secret and replay state; the login Keychain is not used, because every process of the operator's user can read it.
- Socket `/var/run/k3dm-web-console/totp.sock`: directory `root:wheel` `0755`, socket owned by the operator uid, mode `0600`, so only that uid (and root) can connect.
- Log `/var/log/k3dm-web-console-totp.log` (`root:wheel`, `0600`): event names and counters only; never a code, a secret or a login name.

1. **Verifier protocol.** One request line `VERIFY <6 digits>\n`; one reply line: `OK`, `NO` or `WAIT <seconds>`. Anything else gets `NO` and closes. Requests are handled one at a time, so two simultaneous connections presenting the same code yield exactly one `OK`.
   1. Algorithm: RFC 6238, HMAC-SHA1, 30 s step, 6 digits, accepted counters `now/30 +- window`. Comparison with `hmac.compare_digest`.
   2. Replay: a code is accepted only when its counter is greater than `last_counter`; on acceptance `last_counter` is set to that counter before `OK` is sent. A reused code gets `NO`.
   3. Rate limit: the 5th consecutive failure sets `locked_until = now + 300`; until then every request gets `WAIT <remaining>` with no verification (a valid code during lockout is refused). A success resets `failures`. State survives a daemon restart.
   4. Missing, unreadable or malformed secret or state, or `enrolled` false: reply `NO` and log `not-enrolled`; the gate treats that as unavailable.
2. **Gate flow** (`forced-command`), exit codes: 0 only when the tmux client the gate started exits by the operator's own detach or exit; 1 for every other end:
   1. Before anything else: ignore `SIGINT`, `SIGTSTP`, `SIGQUIT` and `SIGTERM` handling is `exit(1)`; `SIGHUP` is `exit(1)` after killing any tmux client child. Set `umask 077`. Ignore `SSH_ORIGINAL_COMMAND` (never run it; log nothing from it). Run tmux with an environment rebuilt from `PATH=/usr/bin:/bin:/usr/sbin:/sbin:<dirname of tmux>`, `HOME`, `USER`, `LOGNAME`, `TERM`, `LANG` only.
   2. Require stdin to be a tty (`os.isatty(0)`); otherwise print `console: an interactive terminal is required` to stderr, exit 1.
   3. Prompt `Code: ` with echo off (`termios`, restored in a `finally`). Wrong code: print `Invalid code`, sleep 2 s, re-prompt. `WAIT n`: print `Too many attempts; try again later`, sleep 2 s, re-prompt. Input that is not exactly 6 digits counts as a wrong code without calling the verifier. After 10 failed prompts in one connection, or 60 s without input at the prompt, exit 1.
   4. Daemon unreachable, a reply other than `OK`/`NO`/`WAIT n`, a socket error, or a missing or non-`0644` config: print `console login unavailable`, exit 1. A failure never falls through to attaching.
   5. On `OK`: if `tmux has-session -t work` fails, run `tmux new-session -d -s work` (the session is created when absent, as the operator, on the operator's default tmux server). Then start `tmux attach-session -t work` as a child on the gate's tty (no `-d`, so a local client at home is not detached). The gate never creates a grouped session and never names `work-console`.
   6. Idle layer, running while the child lives: every `poll_seconds`, read `tmux list-clients -F '#{client_tty} #{client_activity}'`, take the entry whose tty equals this gate's tty (`os.ttyname(0)`); when `now - client_activity > idle_seconds`, run `tmux detach-client -t <tty>`, wait for the child, then go back to 2.3 (prompt again, then attach again). Work in the panes keeps running behind the detach. When `list-clients` fails, or the client is not found, three times in a row, kill the child and exit 1 (fail closed). Pane output does not count as activity; only the operator's input does.
   7. When the child ends and the gate did not start that detach: exit with status 0 if the child exited 0, else 1. The gate never `exec`s a shell, never starts `$SHELL`, and has no code path that runs an interactive shell.
3. **tmux is not modified.** The gate runs no `set-option`, `set-hook`, `source-file`, `new-session -t` or `lock-*` command. The only tmux commands it runs are `has-session`, `new-session -d -s work`, `attach-session -t work`, `list-clients` and `detach-client -t <its own tty>`.
4. **Enrolment.** `bin/k3dm-web-console-totp enroll` (operator, at the machine).
   1. Refuse with exit 2 and `web-console-totp: refusing to show a secret here: <reason>` when: `$TMUX` or `$TMUX_PANE` or `$STY` is set; stdin or stdout is not a tty; `/dev/tty` cannot be opened; `$SSH_CONNECTION` or `$SSH_TTY` is set; the effective uid is 0.
   2. Run `_run_command --interactive-sudo -- /usr/local/libexec/k3dm-web-console/totpd --enroll`. In that root process: refuse when a secret already exists (use `rotate`), create `totp.secret` with `O_CREAT|O_EXCL`, mode `0600`, generate the secret, then open `/dev/tty` itself and print the base32 secret and the `otpauth://totp/` URI to it only. Neither goes to stdout, stderr, argv, the environment or any log. `enrolled` stays false.
   3. The same process asks on `/dev/tty` for one current code and verifies it; on success sets `enrolled` true, `last_counter` to that counter, prints `enrolled`, then clears the screen and scrollback with `ESC[3J ESC[H ESC[2J`. When no valid code arrives within 5 minutes, or on any error, it deletes the new secret and exits non-zero.
   4. `rotate` is the same flow after `--interactive-sudo` (the operator's password is the recovery factor for a lost phone), replaces the secret atomically only after the new code verifies, and the old secret stays valid until then. `status` prints `enrolled` or `not enrolled` and never a secret. `uninstall [--purge-secret]` removes the daemon, the gate (restoring part A's refusing stub) and, with the flag, `/var/db/k3dm-web-console`.
   5. Each Mac has its own secret; nothing copies it, and it is in no `secrets.*.list`. Enrol both Macs under different account labels (`k3dm-console-<hostname>`).
5. **Install.** `bin/k3dm-web-console-totp install` (staged like part A: render to scratch, validate, `install -o root -g wheel`, keep the previous gate as `forced-command.prev`, bootstrap the daemon, check the socket, restore on failure with exit 5). The tmux path is found with `command -v tmux` as the operator and written to `totp.conf` after checking it is an absolute path to an executable. Without `enrolled`, install still places the files but prints `not enrolled: logins stay refused` (the gate refuses when the verifier says `NO`).
6. **Makefile.** `install-web-console-totp`, `uninstall-web-console-totp`, `web-console-totp-enroll`, `web-console-totp-status`. `not-installed.list` gains `install-web-console-totp|not installed by setup: operator-run once with a password and an authenticator app (docs/plans/v1.45.0-web-console-c-totp-gate.md)` and `web-console-totp|system LaunchDaemon installed once by make install-web-console-totp`. No agents list, no secrets list.
7. **Honest residual, stated in the how-to.** The secret is root-readable only: a program running as the operator cannot read it (it is not in the Keychain). It can still ask the verifier whether a guessed code is valid, and is limited to 5 failures per 300 s, which also lets it lock the operator out for 5 minutes. A valid `OK` is not a credential; reaching a shell needs the Access session and an sshd certificate as well. Anything already running as the operator inside the console can end the gate's process and keep its tmux client: the idle layer protects an unattended screen, not the authenticated operator.
8. **Test overrides.** As in part A: `K3DM_WC_ROOT` plus a `.k3dm-wc-fixture` marker, checked first, rejected for uid 0. In a fixture the daemon reads its clock from `$K3DM_WC_ROOT/clock` and the gate finds tmux from the fixture `totp.conf` (a shim that adds `-S <scratch socket>`). No environment variable selects an executable, a socket or a socket path outside the fixture.

## Proof of external behaviour

Local read-only probes, 2026-11-18, `m4-air`, tmux 3.8, `/usr/bin/python3` 3.9.6 (private tmux socket by relative path under the scratchpad, because the full path exceeds the 104-byte socket limit):

- A client attached through `script -q /dev/null tmux attach` is listed by `tmux list-clients -F '#{client_tty} #{client_activity} #{client_session}'` as `/dev/ttys007`, an epoch `client_activity` and its session. `tmux detach-client -t /dev/ttys007` returned 0, `list-clients` was then empty and `has-session -t work` still succeeded (the session and its pane survive the detach). `show -gv lock-after-time` was `0` on a fresh server.
- Not installed on this Mac: `oathtool`, Python `pyotp`. The gate and daemon therefore use `hmac`, `hashlib`, `struct` only.
- Fable's tmux 3.8 scratch probes (per-client lock, Ctrl-C unlock, non-zero `lock-command` unlock, `lock-after-time` not following a switch, `new-session -A -s work-console -t work` with no `work` leaving split groups) are taken as given from the review; they are the reason this spec does not use tmux locking.

Proof owed: (a) `LOCAL`/peer behaviour of a unix socket created by a root LaunchDaemon with `chown` to the operator uid and mode `0600` on macOS 26; (b) `/dev/tty` availability inside a `sudo`-run process on macOS; (c) that `sshd` under the part A LaunchDaemon runs the gate with a usable pty and that an SSH disconnect delivers `SIGHUP` to it; (d) the browser-rendered SSH terminal passing `Ctrl-C`, `Ctrl-Z` and `Ctrl-\` as characters (part B captures). The offline tests below use real `pty` and a scratch tmux, so (c)-(d) are the only live gaps.
