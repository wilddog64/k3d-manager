**Operator decisions applied:** D3 (TOTP at every login through a root-owned gate, loop until a valid code, never exit into a shell, rate-limit, replay state root-owned, idle layer fails closed), D4 (this is part C), O2 (a process running as the operator is an adversary), O3 (O2 binds the runtime path: the login, the verifier, the idle layer; `install`, `enroll` and `rotate`, which the operator starts and watches, are trusted and their exposures are the named residuals R-INSTALL, R-SUDO and R-ENROL).
**Deviation to confirm (umbrella open question 1):** D3 says the idle lock sets tmux lock options globally. Every tmux 3.8 bypass Fable proved (per-client lock, Ctrl-C at the prompt, non-zero `lock-command`, `lock-after-time` not following a session switch) lives inside tmux's lock. This spec uses no tmux locking: the gate owns the pty of the tmux client (a pty proxy), so the idle layer is the gate ending its own client and asking for a code again. It sets no tmux option, so the operator's local clients are untouched by construction.

## Problem

Cloudflare Access and GitHub 2FA decide who may open the console. They do not decide that the person at the browser right now is the operator: an unattended or borrowed browser session, or a stolen Access session within its 6 hours, would reach a shell. The operator chose a TOTP code at every login (D3) and after 2 idle minutes. Part A's sshd runs a `ForceCommand`; this part replaces its refusing stub with the gate. Under O2 at runtime, a hostile process running as the operator must not run code before the gate, read the secret, learn a code, put the verifier into the lockout state, or keep a tmux client after the gate dies. It can always deny service (it can `kill -9` the gate, which runs as the operator); that is not claimed against.

## Behaviour

Components, all root-owned, none inside the checkout, `$HOME` or a Homebrew prefix. Paths below are constants; no root-owned artifact reads a path from the environment (the importable modules take every path as a parameter and only `main()` binds the constants; a source scan allows `os.environ` reads of `HOME`, `USER`, `LOGNAME`, `TERM` and `LANG` only, in the gate only).

- **Interpreter.** `PY=/Library/Developer/CommandLineTools/usr/bin/python3`, run with `-IS`. Not `/usr/bin/python3`: that is the Xcode tool shim (codesign identifier `com.apple.dt.xcode_select.tool-shim-public`), which resolves the real tool through an operator-owned lookup cache (Fable C2); the shim is on no runtime path. `-I` ignores `PYTHON*` variables and the user site; `-S` skips `site`, so no `.pth` file in `/Library/Python/3.9/site-packages` runs (Astra 2). Install trust-checks the interpreter's whole chain, including its resolved target (probe: `.../Python3.framework/Versions/3.9/bin/python3.9`, Mach-O, 3.9.6, every component `root:wheel 0755`); a chain through `/Applications` (`root:admin 0775`) fails. No syntax newer than 3.9.
- **Gate** `/Library/PrivilegedHelperTools/k3dm-web-console/forced-command` (`root:wheel`, `0755`), source `scripts/libexec/k3dm-console-gate.py`, first line exactly `#!/Library/Developer/CommandLineTools/usr/bin/python3 -IS`. Runs as the operator user (sshd drops privileges before `ForceCommand`), reached through part A's trusted entry (`SetEnv ZDOTDIR` to a root-owned empty directory; `/etc/zshenv`, `/etc/zshenv.zwc`, `/etc/ssh/sshrc` absent). zsh runs a single `-c` command with `exec`, so the gate's pid is the shell's pid (probe).
- **Verifier daemon** `/Library/PrivilegedHelperTools/k3dm-web-console/totpd`, source `scripts/libexec/k3dm-console-totpd.py`, and root admin client `totpctl`, source `scripts/libexec/k3dm-console-totpctl.py` (`root:wheel`, `0755`, same first line). `totpd` runs under the LaunchDaemon `com.k3d-manager.web-console-totp` (`/Library/LaunchDaemons/com.k3d-manager.web-console-totp.plist`, `root:wheel`, `0644`; `ProgramArguments` `PY`, `-IS`, the `totpd` path; `Umask` 63; `StandardErrorPath` the log; no `ProcessType`, no placeholder).
- **Config** `/etc/k3dm-web-console/totp.conf` (`root:wheel`, `0644`), strict `key=value` lines and no others: `uid=<operator uid>`, `tmux=<absolute path>`, `idle_seconds=120` (accepted 5-600), `console_port=<n>`. Install takes `console_port` from the installed `/etc/k3dm-web-console/sshd_config` first line (`^ListenAddress 127\.0\.0\.1:([0-9]+)$`; no match is exit 2), never from the environment; part A refuses a port change while this file exists. The gate and the daemon refuse a config that is not `root:wheel`, is group or other writable, has an unknown key, or has a value outside its range.
- **State directory** `/var/db/k3dm-web-console` (`root:wheel`, `0700`). One file `state.json` (`0600`) holds `secret` (base32, 160 bits from `os.urandom(20)`), `last_counter`, `failures`, `locked_until` and `enrolled`. The daemon is the only writer. A commit: open `state.json.tmp` with `O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW` mode `0600`, write, `fsync`, `rename` over `state.json`, `fsync` the directory. At start the daemon removes a leftover `state.json.tmp` unread. A crash leaves the old or the new `state.json`, never a mix. The login Keychain is not used.
- **Run directory** `/var/db/k3dm-web-console-run` (`root:wheel`, `0755`), a sibling of the state directory, not inside it: the operator needs search permission on every path component to reach the socket (`connect(2)` `EACCES`, `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/share/man/man2/connect.2:190-191`; Fable C1, Astra 3). Created by install; at every start the daemon checks it is a real directory (not a symlink), owner 0, mode `0755`, no ACL (else it exits and launchd's `ThrottleInterval` retries), and unlinks `totp.sock` and `admin.sock` by name before binding. `totp.sock` is `0666` (authority comes from the peer checks, not the mode); `admin.sock` is `0600`.
- **Log** `/var/log/k3dm-web-console-totp.log` (`root:wheel`, `0600`, pre-created by install; plist `Umask` 63): event names and counters only; never a code, a secret or a login name.
- **Shared with part A:** the lock `/var/db/k3dm-web-console.lock`, the journal `/var/db/k3dm-web-console.txn`, the manifest `/etc/k3dm-web-console/manifest` (this part writes its own `C` rows), and the library.

1. **Verifier protocol (`totp.sock`).**
   1. **Peer identity at accept, before any byte is read (Fable C3, C4; Astra 4).** The daemon reads the peer with `getsockopt(SOL_LOCAL=0, LOCAL_PEERCRED=1, 76)` (xucred: version, uid; `/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/share/man/man4/unix.4:156`) and `LOCAL_PEERPID=2`. It admits the connection only when all hold, in this order, cheapest first:
      - (a) the peer uid equals `uid` from `totp.conf`;
      - (b) the console listener is genuine: exactly one `127.0.0.1.<console_port>` LISTEN row in `/usr/sbin/netstat -anv -p tcp`, its pid has uid 0 (`/bin/ps -o uid= -p`) and equals the `pid =` of `/bin/launchctl print system/com.k3d-manager.web-console-sshd` (part A's C3 rule); cached for at most 1 s;
      - (c) the peer is a gate itself: its parent chain from the listener is the exact shape captured in P4 (expected: listener, then `sshd-session: <login> [priv]` with uid 0, then `sshd-session: <login>@<tty>` with the operator uid, then the peer), its executable (`ps -o comm=`) is `PY`'s resolved target, and its arguments (`ps -o args=`) are `PY -IS /Library/PrivilegedHelperTools/k3dm-web-console/forced-command`. A tmux client (the gate's child), a tmux server (ppid 1) and anything in a pane (a descendant of the tmux server) all fail (c), so a replaced `tmux` cannot submit codes (Fable C5);
      - (d) the peer's `lstart` is the same before and after the `ps` reads (pid reuse).
      Each subprocess has a 1 s timeout; any failure, timeout or ambiguity rejects. A rejected connection is closed at once with no read and no reply, and changes no state. An outside process therefore cannot submit a code, learn whether one is right, or reach the lockout.
   2. **Admission.** A `selectors` loop with nonblocking sockets; listen backlog 16; at most 4 admitted connections at a time (a fifth admitted peer is closed); each admitted connection has a 5 s deadline for one request line of at most 32 bytes. Verification and state commits are serialised inside the loop. A test holds 20 stalled outside connections open and a gate's login still gets its reply within the gate's 5 s deadline.
   3. **Framing.** The only request is `VERIFY <6 ASCII digits>\n`. A longer line, a timeout, a non-ASCII byte, a missing newline, another verb or a payload that is not exactly six digits is a wire rejection: the connection is closed with no reply and nothing is counted. (The gate sends only six digits; its own local check counts a malformed line as a wrong code without contacting the daemon.)
   4. **Algorithm:** RFC 6238, HMAC-SHA1, 30 s step, 6 digits, accepted counters `now//30` plus -1, 0, +1 (fixed). Every candidate is compared with `hmac.compare_digest`, with no early exit between candidates.
   5. **Replies:** `OK`, `NO`, `WAIT <seconds>`, `UNAVAILABLE`.
   6. **Replay:** a code is accepted only when its counter is greater than `last_counter`; on acceptance `last_counter` and `failures: 0` are committed before `OK` is sent. If the commit fails, the reply is `UNAVAILABLE` and the in-memory state does not advance. A reused code gets `NO` and counts as a failure, also after a daemon restart.
   7. **Lockout (exact rule).** `failures` counts consecutive `NO` replies. The 5th commits `locked_until = now + 300`. While `now < locked_until` every well-formed request gets `WAIT <remaining>` with no verification and no increment. At the first request with `now >= locked_until` the daemon commits `failures = 0`, `locked_until = 0`, then verifies normally (a wrong code then leaves `failures = 1`). A success sets `failures = 0`. State survives a restart. Guess rate for a gate: at most 5 guesses per about 300 s, under 1,440 per day, against 3 valid codes in 10^6 (about 0.43 percent per day of sustained guessing, only through a real gate, so only past Access and the certificate).
   8. **Unavailable:** not enrolled; `state.json` missing, unreadable or malformed; an unreadable or invalid config; an unreadable clock; a failed commit; a listener check that fails while the peer passed (a): reply `UNAVAILABLE` (for an admitted peer) and log the event. The daemon never repairs or rewrites a malformed state file.
   9. **Clock:** if the wall clock moves backward past `last_counter`, valid codes are refused until it catches up (fails closed).
2. **Admin protocol (`admin.sock`, root only).** The daemon admits only a peer whose `LOCAL_PEERCRED` uid is 0. Verbs, one line each, bounded as above:
   - `STATUS` → `ENROLLED`, `NOT_ENROLLED` (no `state.json`) or `UNAVAILABLE` (present but unreadable or malformed, or the config is invalid).
   - `ENROLL_BEGIN` → `ENROLLED` (refused) when enrolled; `UNAVAILABLE` (refused) when damaged; otherwise a secret in memory only, expiry 300 s, one pending secret at a time, reply `SECRET <base32>`.
   - `ENROLL_COMMIT <code>` → verifies against the pending secret; on success one commit writes `secret`, `last_counter` (the matched counter), `failures` 0, `locked_until` 0, `enrolled` true, reply `OK`; commit failure is `UNAVAILABLE` and the pending secret stays.
   - `ROTATE_BEGIN` (refused unless enrolled and undamaged; the current secret stays valid), `ROTATE_COMMIT <code>` (one commit replaces `secret` and `last_counter`), `ABORT`.
   - A wrong commit code leaves the pending secret for the rest of its 300 s and counts toward a separate in-memory limit of 5, after which the pending secret is dropped. The pending secret is never on disk; a secret reaches disk only inside the commit of `ENROLL_COMMIT` or `ROTATE_COMMIT`, as `state.json.tmp` then `state.json` in the `0700` directory.
   - Repair of a damaged state is `uninstall --purge-secret`, then install and enrol again (the how-to says so).
3. **Gate flow** (`forced-command`, a pty proxy). Exit codes: 0 only when the tmux client the gate started ends by the operator's own detach or exit; 1 for every other end.
   1. Before anything else: `SIGPIPE` ignored; `SIGHUP` and `SIGTERM` raise a handler that ends the connection with exit 1 after the cleanup below; `SIGINT`, `SIGTSTP`, `SIGQUIT` ignored; `umask 077`. `SSH_ORIGINAL_COMMAND` is never read. tmux runs with an environment rebuilt from `PATH=/usr/bin:/bin:/usr/sbin:/sbin:<dirname of tmux>`, `HOME`, `USER`, `LOGNAME`, `TERM`, `LANG` only (so `TMUX_TMPDIR` is dropped; the how-to says a non-default `TMUX_TMPDIR` would give the console a different, empty server). The run is inside `try`/`finally` that restores the terminal and ends the child.
   2. Require stdin to be a tty; otherwise print `console: an interactive terminal is required` to stderr, exit 1. Load and validate `totp.conf`; failure is `console login unavailable`, exit 1.
   3. Clear the screen (`ESC[H ESC[2J ESC[3J`), prompt `Code: ` with the terminal in non-canonical mode, `ECHO` and `ISIG` off (restored in the `finally`), reading one byte at a time with a monotonic deadline, so Ctrl-C, Ctrl-Z, Ctrl-\ and Ctrl-D arrive as data: each discards the typed line and re-prompts; a read of zero bytes is a disconnect and exits 1. A line that is not exactly 6 digits counts as a wrong code locally. Wrong code: print `Invalid code`, sleep 2 s, re-prompt. `WAIT n`: print `Too many attempts; try again later`, sleep 2 s, re-prompt. After 10 failed prompts in one connection, or 60 s without a byte at the prompt, exit 1.
   4. **Verifier I/O, bounded.** Connect within 3 s, reply within 5 s, one line of at most 32 bytes. After connect, the gate reads the server's `LOCAL_PEERCRED` and requires uid 0. Daemon unreachable, a reply other than the four, a server uid other than 0, a socket error or a timeout, or `UNAVAILABLE`: print `console login unavailable`, exit 1. The verifier socket is non-inheritable (Python's default, PEP 446) and is closed before step 5. A failure never falls through to attaching.
   5. **On `OK`:** `tmux has-session -t =work` (exact; plain `-t work` prefix-matches `work-console`, probed), each tmux control command run with a 5 s timeout (killed and exit 1 on expiry). When it fails, `tmux new-session -d -s work`; a `duplicate session: work` error counts as success when `has-session -t =work` then passes, otherwise exit 1. Then the gate makes the outer terminal raw and starts, on a new pty it owns (`pty.fork()`), the child `tmux attach-session -E -t =work` (no `-d`, so a local client is not detached; with `-E` the session environment is unchanged by the attach, probed; without `-E` the attach marks `DISPLAY` and `SSH_AUTH_SOCK` removed in the session environment; the global environment is unchanged either way, probed). The gate never creates a grouped session and never names `work-console`.
   6. **Relay and idle layer (Astra 8).** Both fds nonblocking; one `select` loop whose timeout is the smaller of 1 s and the time to the idle deadline; a 64 KiB buffer per direction; when a buffer is full the gate stops reading that direction's source (backpressure) but keeps running the loop, so the idle deadline (`time.monotonic`) is evaluated even when the outer terminal does not drain. It propagates window-size changes (`TIOCSWINSZ` on `SIGWINCH`). Activity is a byte from the outer tty that is not part of a terminal reply sequence: cursor position reports (`ESC [ <n> ; <n> R`), device attributes (`ESC [ ? ... c`, `ESC [ > ... c`), mode reports (`ESC [ ? ... $ y`), focus events (`ESC [ I`, `ESC [ O`), OSC replies (`ESC ] ... BEL` or `ESC ] ... ESC \`) and DCS replies (`ESC P ... ESC \`) are relayed but do not reset the idle timer (umbrella open question 8; this is the recommended default). Pane output never counts. When `now - last_activity > idle_seconds`: `SIGTERM` the child, wait up to 2 s, `SIGKILL`, reap, restore the terminal, go back to 3.3 (clear, prompt, verify, attach). The tmux server, session and panes keep running (probed).
   7. **Fail-closed cleanup.** The gate holds the only master of the child's pty. On any exit path (`SIGHUP`, `SIGTERM`, an exception, a relay error, disconnect) the `finally` sends `SIGTERM` to the child, waits up to 2 s, sends `SIGKILL`, closes the master and exits 1; if the child cannot be reaped within a further 2 s the gate closes the master and calls `os._exit(1)`. When the gate is killed with `SIGKILL` the kernel closes the master and the tmux client receives `SIGHUP` and exits (probed with a prototype). No `list-clients` polling or tty-name matching exists.
   8. When the child ends and the gate did not end it: exit 0 if the child exited 0, else 1. The gate never `exec`s a shell, never starts `$SHELL`, and has no code path that runs an interactive shell.
   9. **Failure classes kept separate** (Astra 8): before attach (verifier, config, tmux control command) → exit 1, no client ever started; after attach (relay error, signal, disconnect) → cleanup above, exit 1; at re-authentication after idle (the client is already gone) → the 3.4 rules, exit 1.
4. **tmux is not modified.** The gate runs no `set-option`, `set-hook`, `source-file`, `new-session -t`, `list-clients`, `detach-client` or `lock-*` command. The only tmux commands it runs are `has-session -t =work`, `new-session -d -s work` and `attach-session -E -t =work`.
5. **Enrolment** (`bin/k3dm-web-console-totp enroll`, operator, at the machine; trusted step under O3, residual R-ENROL).
   1. The wrapper refuses with exit 2 and `web-console-totp: refusing to show a secret here: <reason>` when `$TMUX`, `$TMUX_PANE` or `$STY` is set, stdin or stdout is not a tty, `/dev/tty` cannot be opened, `$SSH_CONNECTION` or `$SSH_TTY` is set, or the effective uid is 0. These refusals prevent accidents only.
   2. It runs `_wc_priv_open`, then `_wc_priv /Library/Developer/CommandLineTools/usr/bin/python3 -IS /Library/PrivilegedHelperTools/k3dm-web-console/totpctl enroll` (code checked). In that root process: `ENROLL_BEGIN`, open `/dev/tty` itself (proof owed P6) and print the base32 secret and the `otpauth://totp/` URI to it only; neither goes to stdout, stderr, argv, the environment or any log.
   3. It asks on `/dev/tty` for one current code (`ENROLL_COMMIT`); on success it prints `enrolled` and clears the screen and scrollback (`ESC[3J ESC[H ESC[2J`). No valid code within 300 s, or any error, leaves nothing on disk.
   4. `rotate` is the same flow with `ROTATE_BEGIN` and `ROTATE_COMMIT` (the operator's password is the recovery factor for a lost phone). `status` runs `STATUS` and prints `enrolled`, `not enrolled` or `state damaged`, never a secret. Each Mac has its own secret under the account label `k3dm-console-<hostname>`; nothing copies it and it is in no `secrets.*.list`.
6. **Install** (`bin/k3dm-web-console-totp install [--tmux PATH] [--dry-run]`, operator, watched; through the library, same transaction as part A).
   1. Refusals (exit 2): part A not installed (no A manifest rows or no `forced-command.stub`); the `sshd_config` first line does not parse; `PY` missing or not executable.
   2. Sources unchanged from `HEAD` (exit 9): this script, the three Python files, the plist template, `scripts/lib/web_console_common.sh`, both `system.sh` copies, `scripts/lib/agent_rigor.sh`. Installed bytes are the `HEAD` blobs (R-INSTALL).
   3. `tmux` is `command -v tmux` as the operator; the run prints the resolved path and refuses a path outside `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, `/bin`, `/opt/local/bin` unless `--tmux PATH` is given; absolute and executable either way (exit 2).
   4. `_wc_priv_open` (exit 10). `_wc_trust_check` on the helper directory, `/etc/k3dm-web-console`, `/Library/LaunchDaemons`, `/private/var/db`, `/private/var/log`, the state and run directories when they exist, and on every component of `PY` and of its resolved target (exit 8); `_wc_dest_check` on every destination file, the log and the plist (exit 8).
   5. `_wc_lock_take` (exit 7); `_wc_txn_recover`; `_wc_stage_clean`.
   6. Create missing directories (state `0700`, run `0755`) journaled and re-verified. Stage `totpd`, `totpctl`, the gate, `totp.conf`, the plist and the manifest with the `C` rows; pre-create the log `0600`. Validate in the stage (exit 4, nothing moved): `PY -IS -c 'import ast,sys; ast.parse(open(sys.argv[1]).read())'` on each Python file, the gate's first line exact, `plutil -lint`, the `totp.conf` rules.
   7. `forced-command` custody: replace it only when its hash equals the manifest row for A's stub, or for a part C gate (an upgrade); any other content is exit 8, nothing moved.
   8. Commit (`_wc_commit`, journaled, `.prev` first): `totpd`, `totpctl`, `totp.conf`, the manifest, the plist last of these. Then `launchctl bootout` (soft, code recorded), `bootstrap` (code checked), wait up to 10 s for `totpctl status` to answer `ENROLLED` or `NOT_ENROLLED`. Only then move the staged gate over `forced-command`. A failed step restores the whole previous generation from `.prev` (the previous gate on an upgrade, the stub on a first install), re-bootstraps the previous daemon plist when there was one, exit 5.
   9. Without `enrolled`, the run prints `not enrolled: logins stay refused` and exits 0.
   10. `--dry-run`: steps 1-3 unprivileged, prints the file list and commands, no `_wc_priv` call.
7. **Uninstall** (`uninstall [--purge-secret]`): lock; `launchctl bootout` the daemon (soft); stage the stub and `mv` it over `forced-command` first (so new logins are refused before the verifier goes); remove the plist, `totpd`, `totpctl`, `totp.conf`, the run directory, the log and the `C` manifest rows; with the flag remove the state directory. Sessions already attached continue; new logins meet the stub. Afterwards part A may change the port.
8. **Part A interplay (Astra 15).** A's install with C present keeps the gate (manifest `C` row) and refuses a port change (A step 2). A's `revoke` with C present stops the sshd only; `totpd` keeps running and answers nothing useful (check (b) fails, so every admitted request is `UNAVAILABLE`). A's `uninstall` refuses while C is installed. C's uninstall restores the stub.
9. **Makefile.** `install-web-console-totp`, `uninstall-web-console-totp` (`PURGE_SECRET=1` adds `--purge-secret`, with the same `case` value check as part A's `PURGE`), `web-console-totp-enroll`, `web-console-totp-rotate`, `web-console-totp-status`, added to `.PHONY` (`Makefile:163`) and the help text near `:2382`. `scripts/etc/machine/not-installed.list` gains `install-web-console-totp|not installed by setup: operator-run once with a password and an authenticator app (docs/plans/v1.45.0-web-console-c-totp-gate.md)` and `web-console-totp|system LaunchDaemon installed once by make install-web-console-totp`. No agents list, no secrets list, no hub list. Tests do not run `make -n` on these targets.
10. **Named residuals, in the how-to, each separate.**
    - (a) **R-INSIDER (runtime).** An authenticated operator inside the console is trusted: the idle layer protects an unattended screen, not the person who logged in.
    - (b) **R-ACTIVITY (runtime).** A terminal reply sequence the filter does not know, provoked by pane output, keeps the session active.
    - (c) **R-DENIAL (runtime).** A same-user process outside the console cannot read the secret, learn a code or reach the lockout, but it can always deny service (kill the gate, flood connections, fill the disk).
    - (d) **R-TMUX (runtime).** `tmux` lives in an operator-writable prefix (`/opt/homebrew/bin` is operator-owned). A replaced `tmux` runs as the operator after each valid code and can draw a fake `Code:` prompt; it cannot submit codes (peer rule (c)) and gains nothing the operator's user did not have.
    - (e) **R-ENROL (O3, accepted).** Enrolment and rotation show the secret on the operator's terminal from a root process; a same-user process that controls or records that terminal sees it. The operator enrols from a plain terminal window, watched.
    - (f) **R-INSTALL and R-SUDO (O3, accepted)** as in part A.
11. **Test overrides.** None in a root-owned artifact. The gate and daemon modules are importable (`importlib` from the file path) and expose `run(...)` taking every path, the clock, the tmux argv prefix (production `[tmux]`; tests `[tmux, "-S", <scratch socket>]`), the peer-identity function, the connect function, the listener lookup and the idle/prompt limits as parameters; `main()` takes none and binds the constants. The installer script uses part A's `K3DM_WC_ROOT` fixture mode.

## What NOT to do

- Do not use tmux `lock-after-time`, `lock-command`, `lock-server`, grouped sessions, `list-clients` polling or any `set-option` in the gate.
- Do not store the TOTP secret in the Keychain, the checkout, `$HOME`, an environment variable, an argument, a temporary file outside the commit, or any log, and do not print it to stdout or stderr.
- Do not add a shell, `$SHELL`, `exec sh` or any fallback path on error; every error ends the connection.
- Do not name `/usr/bin/python3` or `/usr/bin/env` in a shebang or `ProgramArguments`.
- Do not read any path, socket or executable from the environment in a root-owned artifact.
- Do not run any test against the operator's real tmux server, real `/etc`, `/var` or `/Library`.
- Do not build a separate admin account, a root-owned installer verifier or a phone confirmation (O3).
- Do not add Cloudflare code, change part A's sshd settings, or put the console in an agents or secrets list.
- Do not commit, push, dispatch, or skip pre-commit hooks.
