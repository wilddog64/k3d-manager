## Goal

Getting a change onto the hub after `deploy/hub` was introduced takes five commands in a fixed order:
`make hub-promote REF=…`, `make appsets-check`, `make appsets-reapply` only when ApplicationSet manifests changed,
`make platform-ops`, and `kubectl -n platform-ops rollout status deploy/vulnerability-inventory-exporter`. On
2026-11-08 the operator needed Claude to say which of them to run and when. One target runs them in order on the hub,
skips the reapply when it is not needed, stops at the first failure, and says what it did.

The typed `promote` confirmation stays. Nothing here promotes automatically.

## Design

`make hub-deploy REF=<commit-ish>` calls a new `bin/k3dm-hub-deploy`:

1. `bin/k3dm-require-role hub`.
2. Record `old` = the current `origin/deploy/hub` SHA (`bin/k3dm-hub-promote` already resolves it).
3. Run `bin/k3dm-hub-promote promote "$REF"`. It keeps its TTY confirmation and CI check. If it reports
   `deploy/hub is already at <sha>; nothing to promote`, continue: a rerun after a later step failed must finish the
   remaining steps without promoting again.
4. Record `new` = `origin/deploy/hub` after the promote.
5. If `git diff --name-only old new -- scripts/etc/argocd/applicationsets/` is non-empty, run
   `make appsets-reapply`; otherwise print `appsets unchanged between <old> and <new>; skipping reapply`.
   On the first run after the bootstrap, where `old == new`, nothing is reapplied.
6. `make appsets-check`.
7. `make platform-ops`.
8. `kubectl -n platform-ops rollout status deploy/vulnerability-inventory-exporter --timeout=180s`, using the
   hub context the other steps use.
9. Print one summary line: `hub-deploy: deploy/hub <old7>..<new7>; reapply <ran|skipped>; appsets-check ok;
   platform-ops ok; exporter rolled out`.

Each step runs only if the previous one exited 0. On a failure, print `hub-deploy: stopped at <step>: rerun
make hub-deploy REF=<same ref> after fixing it` and exit with the step's code. Steps call the existing make
targets rather than copying their bodies, so a later change to a target applies here too.

## Contract readers

`hub-deploy` reads contracts and changes none of them: it calls existing targets.

| Contract | Reader | Changes? |
|---|---|---|
| `deploy/hub` ref | `bin/k3dm-hub-promote` (resolve, promote, status) | no: called as is |
| `deploy/hub` ref | `Makefile` `appsets-reapply`, `appsets-check`, `platform-ops` | no: called as is |
| `deploy/hub` ref | `scripts/lib/hermes/sensors.py:114` `_values_branch_expected` | no: not touched (its own P2 bug) |
| `scripts/etc/argocd/applicationsets/` path | `deploy_argocd_applicationsets` (`scripts/plugins/argocd.sh:1310`) | no: only read for the diff |
