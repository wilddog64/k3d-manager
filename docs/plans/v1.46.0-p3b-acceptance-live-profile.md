## Behaviour

### 1. Live profile (`scripts/lib/acceptance/live.py`, `bin/k3dm-operator-acceptance --live`)

- Entry: `make test-operator-acceptance-live PROFILE=k3dm-tests`. Refuses unless `K3DM_ACCEPTANCE_LIVE=1` is set in
  the invoking shell and the terminal is interactive, and prints the actions it will submit before submitting any.
- Closed action list, in code, not configurable: `cluster-status`, `job-status`, `make-test-python-unit`,
  `make-test-all`. Before each submission the profile asserts the action is in that list **and** that
  `gated(action)` from `bin/k3dm-cloud-bridge` is false; otherwise it stops with `harness_error`.
- Submission only through `bin/k3dm-cloud-request <action> --wait-final` with a fixed argv (`shell=False`). That
  helper's own request commit to `cloud-requests` is the only git write the profile causes; the profile itself never
  runs `git`.
- Serialized: a lock file in the run root; a second live run refuses while one holds it.
- Legs for `PROFILE=k3dm-tests`:
  1. `cluster-status` returns a terminal response (deadline 120 s).
  2. `make-test-python-unit` returns terminal status, the original exit code and bounded output (deadline 600 s); no
     metric leg (this target publishes none, `bin/k3dm-test-metrics:273`).
  3. Only with `--with-test-all` (about 15 minutes): `make-test-all` terminal, then the Grafana leg.
  4. Grafana leg (needs P1): with the Viewer token from Keychain `k3dm-grafana-viewer-token`, `GET` the `k3dm-tests`
     dashboard and evaluate panels 1, 3 and 9 through `POST /api/ds/query`; oracle: the last-run time is not older than
     the `make-test-all` submission, and panel 3 equals the job's failed count. The token is read by name, passed in a
     header from memory, never in argv, logs or the report.
- Every response, header and body written to the run directory passes child A's redaction.

### 2. Local bug drafts (`scripts/lib/acceptance/drafts.py`)

- For each `failed` scenario with cause `product_contract`, write one draft under `<run dir>/drafts/` (`0600`), named
  by a stable fingerprint (`sha256` of scenario id + assertion id + normalised expected/actual, first 12 hex).
- Draft header is the canonical block: `**Status:** OPEN — captured, not triaged`, `**Priority:** P3` (placeholder,
  "proposed"), `**Introduced by:** unknown`, `**Should have been caught by:** live check`,
  `**Introducing change reviewed:** unknown`, `**Waiting on:** operator decision — since <date>`,
  `**Classified:** pending`, `**Prior art:** ...`, `**Filed:** <date>, operator-acceptance run <id>`.
- Dedup: exact fingerprint match against earlier runs' drafts and against `docs/bugs/*.md` containing the
  fingerprint; a match updates nothing and is listed in `report.md` as "seen before: <path>". `prior_art.search` is
  called only when `--with-prior-art` is given, its top 3 are listed as advisory candidates, and
  `RetrievalUnavailable` is recorded, not fatal.
- Drafts never leave the run directory: no copy into `docs/bugs/`, no commit, no push, no Slack post, no reopen of an
  existing bug.
