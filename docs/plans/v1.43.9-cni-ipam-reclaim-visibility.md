## Problem

The **k3dm Host Pod IP Pool** dashboard shows how full the pool is and how many stale reservations
each sweep removed. A reviewer pointed out on 2026-10-18 that this does not prove the cleanup is
working: a 254-address pool can hide orphaned reservations for a long time while **Pool used %**
stays low.

The sweep sorts every reservation file into one of four outcomes, but only two reach Prometheus:

| Outcome (sweep loop) | Meaning | Published today |
|---|---|---|
| pod sandbox is live | in use | no — counted in `kept`, never pushed |
| no sandbox, but a pod reports the IP (`SKIP` line) | the sweep refuses to touch it; a real orphan if it persists | no — folded into `kept`, only logged |
| no sandbox, file younger than the grace period (10 min) | probably a pod still starting | no — `young` is in the state file, never pushed |
| no sandbox, older than the grace period | leaked; removed with `--apply` | yes — `k3dm_cni_ipam_stale_last_run` |

The `SKIP` case is the one that matters. The sweep never reclaims it by design, so if it persists
the cleanup is not keeping up, and nothing measures it today.

The reviewer's suggestion, the oldest active reservation's age, would alarm on healthy pods:
`vault-0` legitimately holds a reservation for weeks. This plan measures how long a `SKIP`
reservation has been held instead.

## Fix

### 1. `scripts/etc/hostinger/k3dm-cni-ipam-sweep.sh`

In the reservation loop, count the `SKIP` case separately and record its oldest file age. `kept`
keeps its current meaning (it still includes `SKIP`), so existing readers do not change.

Declare the new counters next to the existing ones:

```bash
kept=0
stale=0
young=0
skipped=0
skipped_oldest_age_s=0
now_s="$(date +%s)"
```

In the `SKIP` branch, after the existing `printf 'SKIP …'` and before `kept=$((kept + 1))`:

```bash
    skipped=$((skipped + 1))
    mtime_s="$(stat -c %Y -- "${f}" 2>/dev/null || stat -f %m -- "${f}")"
    if (( now_s - mtime_s > skipped_oldest_age_s )); then
      skipped_oldest_age_s=$((now_s - mtime_s))
    fi
```

The grep line in that branch is rewritten by the SIGPIPE bug; leave whatever form is on the branch.

Append the two keys to the state file and the summary line, keeping the existing keys and order:
`skipped=%s` and `skipped_oldest_age_s=%s` go after `alloc_errors_1h` in both `printf` calls.

### 2. `bin/k3dm-cni-ipam-metrics`

- Keep `INTEGER_KEYS` as it is (all still required).
- Add `OPTIONAL_INTEGER_KEYS = ("skipped", "skipped_oldest_age_s")`. `_read_state` validates
  them as digits when present and does not fail when they are absent.
- `_metrics` adds, all with `host="hostinger"`:
  - `k3dm_cni_ipam_kept` from `kept`, and `k3dm_cni_ipam_young` from `young` (always present).
  - `k3dm_cni_ipam_skipped` and `k3dm_cni_ipam_skipped_oldest_age_seconds`, only when the state
    file has those keys.

The optional keys matter because of ordering. The hub collector deploys with `make platform-ops`,
but the sweep reaches the host only with `make refresh CLUSTER_PROVIDER=k3s-hostinger`. Until the
host is refreshed, its state file has no `skipped` key. A collector that required the key would
report `probe_success 0` and fire `HostCniIpamSweepStale`.

### 3. `scripts/etc/prometheus/rules/host-cni-ipam.yaml`

Add one rule to group `host.cni-ipam`:

```yaml
        - alert: HostCniIpamOrphanNotReclaimed
          expr: k3dm_cni_ipam_skipped > 0 and k3dm_cni_ipam_skipped_oldest_age_seconds > 3600
          for: 30m
          labels:
            severity: warning
            cluster: hub
          annotations:
            summary: "A pod IP on {{ $labels.host }} has had no sandbox for over an hour"
            description: "{{ $value }} reservation(s) on {{ $labels.host }} have no pod sandbox but a pod still reports the IP, so the sweep will not reclaim them. ssh in; sudo /usr/local/sbin/k3dm-cni-ipam-sweep --dry-run lists them as SKIP lines; find the pod with kubectl get pods -A -o wide."
```

The `for: 30m` plus the 1-hour age means two sweeps in a row confirm it. A pod restarting
across a single sweep never fires.

### 4. `scripts/etc/argocd/platform-ops/grafana-dashboard-host-cni-ipam.yaml`

Add a third row at `y: 20`. Keep panels 1–8 byte-identical:

- id 9, stat **In use** (`k3dm_cni_ipam_kept - k3dm_cni_ipam_skipped or k3dm_cni_ipam_kept`):
  `unit none`, thresholds `[green null]`.
- id 10, stat **Starting (grace period)** (`k3dm_cni_ipam_young`): thresholds
  `[green null, orange 10]`.
- id 11, stat **Held without a sandbox** (`k3dm_cni_ipam_skipped`): thresholds `[green null, orange 1]`,
  `noValue` `"needs host refresh"`.
- id 12, stat **Oldest held without a sandbox** (`k3dm_cni_ipam_skipped_oldest_age_seconds`):
  `unit s`, thresholds `[green null, orange 1800, red 3600]`, `noValue` `"needs host refresh"`.
- id 13, timeseries **Reservations by outcome**, `h 8, w 24, y 26`: legends `in use`,
  `starting`, `held without a sandbox` and `removed last sweep`, from the four series above.

Every stat panel sets its own thresholds; `test_every_stat_panel_sets_its_own_thresholds_or_mappings`
must keep passing.

### 5. `docs/guides/grafana-dashboards.md`

In the **k3dm Host Pod IP Pool** section, explain the third row: what each outcome means,
