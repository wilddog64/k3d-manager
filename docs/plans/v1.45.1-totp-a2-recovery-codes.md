## Problem

After A1 a locked-out operator away from home waits up to 24 h, because the only immediate unlock (`totpctl unlock`)
needs root on the hub. The operator asked for an unlock from the console that does not need root (parent, operator
decisions). The gate also drops any input that is not exactly 6 digits (`k3dm-console-gate.py:332`) and buffers at
most 7 bytes (`:329-330`), and totpd's VERIFY check does the same (`:724`), so nothing longer can reach the daemon.

## Behaviour

Parent **B8** in full, plus the recovery events of **B5**. The parent's text wins where they differ. Summary for the
worker:

1. **Generation.** Ten 16-character base32 codes (80 bits each, `os.urandom(10)`) are pended beside the pending secret
   at `ENROLL_BEGIN`, `ROTATE_BEGIN` and a new admin `RECOVERY_BEGIN`. The pending window is 600 s for `RECOVERY_BEGIN`
   only; enrol and rotate keep 300 s (`:586`, `:630`).
2. **Pending lifecycle (Fable S-1).** Every path that ends a pending operation (commit, `ABORT`, expiry, the fifth wrong
   commit code) also clears `pending_recovery_codes`. `ENROLL_BEGIN` / `ROTATE_BEGIN` reply `REFUSED` while a recovery
   set is pending and unexpired (checked on `pending_operation` and expiry, not on the list alone).
3. **Display.** `RECOVERY_GET <i>` matches `re.fullmatch(r"RECOVERY_GET [0-9]", line)` and replies `CODE XXXX-XXXX-XXXX-XXXX`
   only while a set is pending; anything else `UNAVAILABLE` (N13).
4. **totpctl.** `recovery-status` and `recovery-regen` (regen asks the operator to type `yes`, 600 s select timeout,
   `ABORT` otherwise). After a non-OK enrol or rotate reply other than `UNAVAILABLE`, send `ABORT` and print one fixed
   line saying the recovery codes shown are void (Fable S-2). Clear the scrollback (`\x1b[3J\x1b[H\x1b[2J`, as at
   `totpctl.py:127`) on every exit after codes were printed.
5. **Storage.** `<state_dir>/recovery.json`, root 0600, `{"v": 1, "codes": [{"s": <32 hex>, "h": <64 hex>}]}`, hash
   `sha256(bytes.fromhex(s) + code)` over the ungrouped uppercase code; load requires `type(v) is int and v == 1`. The
   commit fault seam is keyed by file name (`{"recovery.json": <fault>}`); a bare string still means `state.json`, so
   the existing tests at `:943`, `:1442`, `:2410` are unchanged. Startup cleanup (`:380-385`) also removes
   `recovery.json.tmp`, using `os.path.lexists` so a dangling symlink goes too.
6. **Load.** `lstat` ENOENT → no codes; otherwise open with `O_NOFOLLOW`, `fstat` owner root and mode 0600. Damage
   logs `totp-recovery-damaged` and means no codes, never state-unavailable (N12). Loaded only at start, on a
   recovery-format VERIFY and on `RECOVERY_STATUS`, never on the TOTP path.
7. **Wire.** The gate buffers up to 20 bytes with an overflow flag (overflow → local "Invalid code", never a truncated
   prefix), handles backspace (0x7f and 0x08), drops spaces, accepts hyphens anywhere and any case, and sends the
   canonical `VERIFY XXXX-XXXX-XXXX-XXXX` when the 16 remaining characters are `[A-Z2-7]`. 6-digit input is unchanged.
   The WAIT message becomes `Too many attempts; try again later (<n> s)`. totpd accepts exactly the 6-digit form and
   `^VERIFY [A-Z2-7]{4}(-[A-Z2-7]{4}){3}$`. Strict 4-4-4-4 grouping at the gate is **not** required (Argon 3, partly
   rejected): the gate regroups.
8. **No rate limit (rev 4, operator decision).** Every recovery-format attempt is evaluated, locked or not. A wrong
   code replies `NO` and changes nothing: not `failures`, not the lock (Argon 7). Only the log line
   `totp-recovery-failure count=<n>` is throttled, at most once per 60 s of `monotonic()`; `<n>` is the number of wrong
   recovery attempts since the last line.
9. **Verify.** A matching unused code is burned (recovery.json committed without it) **before** the state reset and the
   reply. Burn fails before the rename → `UNAVAILABLE`, the code stays valid. Burn renamed but the state commit fails →
   `UNAVAILABLE`, code gone. recovery.json post-rename fault → `UNAVAILABLE`, no reset, fatal exit (as `:604-614`).
   Success resets `failures`, `locked_until`, `lock_level` to 0 and logs `totp-unlock source=recovery`,
   `totp-recovery-used remaining=<n>`, and `totp-recovery-low remaining=<n>` when n ≤ 2. Two connections with the same
   code get exactly one `OK` (single-threaded loop; burn before reply).
10. **Commands.** `RECOVERY_COMMIT` needs `pending_operation == "RECOVERY"`, an unexpired window and an enrolled state.
    All recovery admin verbs are peer uid 0 only.
11. **Never** put a code in argv, the environment, a log line or `state.json`.

The guessing bound without a limiter is about 7×10^-17 per day even at 100 attempts/s (parent B8 "No rate limit").
B8 "Exhaustion under sustained attack" (a certificate holder cannot burn an unknown code, but can re-lock TOTP after
each recovery, so each lockout spends one of the operator's codes; remedy: revoke the certificate and `recovery-regen`)
is documented by part C, not coded here.

## Why the gate is in A2

Three source files plus tests is one over the usual three. The gate change is about twenty lines and cannot be split
off: a gate-only child has no daemon that accepts the recovery form, and a daemon-only child cannot prove N8 end to end.
