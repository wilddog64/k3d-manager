# v1.36.0 — Deterministic E2E triage: one classifier, one routing table, one labelled corpus

**Status:** SPEC — ready for implementation
**Branch:** `k3d-manager-v1.36.0`
**Owner:** Codex
**Filed:** 2026-09-21

---

## Why

E2E failure classification already exists — **twice**, in two copies that disagree. Neither
copy is authoritative, one of them leaks unredacted third-party error text into a hub
ConfigMap, and the taxonomy is missing a class the operator needs (`auth`). There is also no
service→repo routing table anywhere in the repo, so a classified failure cannot be turned
into "which repo owns this" without a human.

This spec collapses the two copies into one, adds the missing class and the routing table,
closes the redaction gap, and builds a small labelled corpus that pins the classifier's
behaviour as a regression test.

**This work is self-contained and has no dependency on any external model or service.**
It is deterministic Python and Bash only. (It happens to also produce the offline evaluation
set that any future probabilistic triage layer would need in order to be assessed at all —
but nothing here calls out to anything, and nothing here is a prerequisite for adopting such
a layer. See "Non-goals".)

### The two existing copies

| | `scripts/plugins/e2e.sh:711-760` (inline heredoc) | `scripts/lib/hermes/e2e_triage.py` |
|---|---|---|
| Port→service map | **6 entries** — 8000, 8080, 8081, 8082, 8083, 8084 | **4 entries** — 8000, 8080, 8083, 8084 |
| Unknown port | `"unknown"` | `host-<port>` |
| Timeout match | `timeout\|timedOut\|Timeout \d+ms exceeded` (broad — matches the word "timeout" anywhere) | `status == "timedOut"` or `Timeout \d+ms exceeded` (precise) |
| Contract match | 5 alternatives | 6 — adds `Expected: "number".*Received: "string"` |
| Redaction | **none** | `redact()` — Bearer / JWT / password-secret-token-apikey |
| `service` routing | substring chain, duplicated twice (groups + details) | none |
| `auth` class | absent | absent |

### Which copy is right about ports — verified, and not the obvious answer

The two port maps are not "one stale, one current". They describe **different tiers**:

| Service | Tier 1 (vcluster) — `scripts/etc/e2e/*.yaml` | Tier 2 (sandbox) — `_e2e_sandbox_job_manifest` |
|---|---|---|
| product-catalog | **8000** | **8082** |
| order | **8080** | **8081** |
| basket | 8083 | 8083 |
| payment | 8084 | 8084 |

The union has **no collisions**, so a single 6-entry map is correct for both tiers.

- `e2e.sh`'s 6-entry map is the correct union. It is pinned by
  `scripts/tests/plugins/e2e.bats:240-258` (`sandbox-ports`), which asserts 8081→order and
  8082→product-catalog. **That test is correct and must keep passing.**
- `hermes/e2e_triage.py`'s 4-entry map is **Tier-1-only**. Against a Tier 2 run it classifies
  a connection failure as `("service-unreachable", "host-8081")` instead of
  `("service-unreachable", "order")`.

**Consequence:** Hermes is the consumer that files bug docs (`e2e_bugs.py`) and pages. So
today every Tier 2 connection failure is filed against a target of `host-8081` / `host-8082`,
with no service attribution and therefore no possible repo routing. Tier 2 is the tier that
was just implemented (`v1.36.0-e2e-tier2-sandbox-impl.md`), so this is live, not theoretical.

### The redaction gap (security)

`_e2e_write_summary` builds `failure_details` — up to 200 entries of raw Playwright error
text, 300 chars each — and applies **no redaction**. That payload then goes to two places:

1. `${HOME}/.k3dm/e2e/<run_id>.json` and `<run_id>.failures.json` on disk.
2. A hub ConfigMap in `platform-ops` via `_e2e_write_result_event` (`event.json`), read by the
   vulnerability-inventory-exporter and surfaced in Grafana.

`e2e_remote.sh:583-591` validates the shape and length of those strings but likewise does not
redact them.

Playwright assertion output for an auth-flow test routinely embeds the token or header that
failed. A Keycloak or Stripe bearer token appearing in an assertion diff would be copied
verbatim into a cluster ConfigMap and a dashboard. `hermes/e2e_triage.redact()` already exists
for exactly this and is already applied on the Hermes side (`sensors.py`, `e2e_bugs.py`,
`status_triage.py`) — the `e2e.sh` writer path simply never adopted it.

This is the same failure class as
`docs/bugs/2026-09-21-show-service-passwords-keycloak-block-defeats-redaction.md`: a
redaction convention that one code path does not follow.

### The corpus, and its honest size

Labelled data available in-repo today:

- **5** machine-filed bug docs with a `## Sample errors` section
  (`docs/bugs/2026-09-16-e2e-{assertion-api-payments,contract-drift-api-cart,contract-drift-api-cross-service,contract-drift-api-orders,contract-drift-api-products}.md`),
  carrying **11** sample error lines total. The doc slug supplies the label
  (`kind` and `target`) because `e2e_bugs.py` generated it from `classify()`.
- **Zero** usable local run artifacts. `~/.k3dm/e2e/` holds 9 summaries; the 4 with real
  Playwright stats (`passed=26/45/48/48`, `total=102`) are from 2026-08-29/30 and predate the
  `failure_details` feature (added `978ea60f`, 2026-09-17), so they legitimately carry no
  details; the only post-feature run (2026-09-21) died at `deploying-substrate` before
  Playwright started.

**11 labelled samples is enough to pin a rule-based classifier against regression. It is
nowhere near enough to validate a probabilistic one.** State this in the corpus README so the
number is not later mistaken for a calibration set.

## Non-goals

- **No external service, model, or network call.** Not in the implementation, not in the
  tests, not optionally, not behind a flag.
- **No renaming of existing kind strings.** `service-unreachable`, `timeout`,
  `contract-drift`, `assertion`, `harness` keep their exact spellings. They are baked into
  `e2e_bugs.py`'s hint table, `diff_groups` slugs, the `e2e_remote.sh` group schema, and the
  Grafana E2E dashboards. Renaming them would silently empty panels and churn Hermes'
  new/ongoing/resolved diff. Map the operator's vocabulary to the existing strings in docs
  instead (see M6).
- **No change to `_e2e_write_result_event`'s event schema keys**, and no change to the
  `e2e_remote.sh` validator's required key sets. Only the *values* become redacted.
- **No auto-remediation, no auto-filing changes, no thresholds, no confidence scores.**
  `classify()` returns a kind and a target. It does not return a probability and must not
  grow one.
- **Do not seed, write, rotate or repair any credential.**
- **Do not add `keycloak/users/*` to the Vault allowlist** (out of scope, not approved).

## M1 — Canonicalize the classifier in `scripts/lib/hermes/e2e_triage.py`

This module becomes the single source of truth. `e2e.sh` will import it (M3).

### M1.1 — Adopt the 6-port union map

Replace:

```python
_PORT = re.compile(r":(8000|8083|8080|8084)(?:\D|$)")
_PORTS = {"8000": "product-catalog", "8083": "basket", "8080": "order", "8084": "payment"}
```

with:

```python
_PORT = re.compile(r":(8000|8080|8081|8082|8083|8084)(?:\D|$)")
_PORTS = {
    "8000": "product-catalog",
    "8080": "order",
    "8081": "order",
    "8082": "product-catalog",
    "8083": "basket",
    "8084": "payment",
}
```

Keep `_unreachable_target`'s `host-<port>` / `host-unknown` fallback exactly as it is — it is
strictly better than `e2e.sh`'s `"unknown"` because it preserves the port for a human.

### M1.2 — Add the routing table

Add these two functions. `_SERVICE_PATTERNS` is ordered and the first match wins; order
matters because a cross-service spec may mention several nouns.

```python
_SERVICE_PATTERNS = (
    ("cross-service", re.compile(r"cross-service|cross_service")),
    ("basket", re.compile(r"cart|basket")),
    ("order", re.compile(r"order")),
    ("payment", re.compile(r"payment|stripe")),
    ("product-catalog", re.compile(r"product")),
)

_SERVICE_REPOS = {
    "basket": "wilddog64/shopping-cart-basket",
    "order": "wilddog64/shopping-cart-order",
    "payment": "wilddog64/shopping-cart-payment",
    "product-catalog": "wilddog64/shopping-cart-product-catalog",
    "frontend": "wilddog64/shopping-cart-frontend",
    "cross-service": "wilddog64/shopping-cart-e2e-tests",
}


def service_for(target):
    """Attribute a classified target to one owning service.

    `target` is either a service name already (from a port attribution) or a spec slug.
    Returns "cross-service" when no single service owns it.
    """
    text = str(target or "").lower()
    if text in _SERVICE_REPOS:
        return text
    for service, pattern in _SERVICE_PATTERNS:
        if pattern.search(text):
            return service
    return "cross-service"


def repo_for(service):
    """Map an owning service to the repo that must carry the fix.

    Returns None when there is no single owning repo, so callers must decide rather than
    silently routing to a default.
    """
    return _SERVICE_REPOS.get(str(service or "").lower())
```

The `_SERVICE_REPOS` membership check must come **first**, before the substring patterns, so
that an already-resolved service name from a port attribution (`"order"`,
`"product-catalog"`) short-circuits. Without it, a known value would be re-derived by
substring match, which is fragile: `"cross-service"` contains no service noun and would fall
through to the `cross-service` pattern by luck rather than by intent. The membership check
makes every known value order-independent, and leaves the patterns to handle only spec slugs.

### M1.3 — Add the missing `auth` kind

`classify()` currently returns one of `service-unreachable`, `timeout`, `contract-drift`,
`assertion`. Add `auth` **between timeout and contract-drift**: an HTTP 401/403 body is often
empty or an error envelope, which would otherwise be misread as contract drift.

Add the pattern:

```python
_AUTH = re.compile(
    r"\b(401|403)\b|Unauthorized|Forbidden|invalid_grant|invalid_token|"
    r"token (?:is )?expired|no bearer token|authentication failed",
    re.I,
)
```

and in `classify()`, after the `timeout` branch and before the `_CONTRACT` branch:

```python
    if _AUTH.search(combined):
        return "auth", spec_slug(failure)
```

Keep the existing docstring note that ordering is deliberately the public policy.

**Deliberate narrowness:** `\b(401|403)\b` will not match `1401` or `403x`. Do not broaden
this to bare `4\d\d` — a test asserting `expect(res.status).toBe(404)` is an assertion
failure, not an auth failure.

### M1.4 — Register the new kind's triage hint

`scripts/lib/hermes/e2e_bugs.py` has a `KIND`-keyed hint table (line ~12). A missing key
would put an empty "Triage hint" section in a filed bug doc. Add:

```python
    "auth": "the request was rejected by authn/authz, not by the service's business logic; check the Keycloak realm client, the token audience, and whether `secret/keycloak/clients` matches what the test requests.",
```

Place it adjacent to the existing entries, matching their wording style.

In `scripts/plugins/e2e.sh`, `_e2e_write_summary` runs `python3 -` with a heredoc. Give it the

### M2.1 — Export the lib dir

The function already exports a block of `E2E_*` env vars before the heredoc. Add one more,

```bash
  E2E_LIB_DIR="${SCRIPT_DIR}/lib" \
```

Confirm `SCRIPT_DIR` resolves to `scripts/` in this context — the function already uses
`"${SCRIPT_DIR}/.."` for `git rev-parse`, so `${SCRIPT_DIR}/lib` is `scripts/lib`. Verify

### M2.2 — Import, with an explicit failure

At the top of the heredoc, after the existing imports:

```python
sys.path.insert(0, os.environ["E2E_LIB_DIR"])
from hermes.e2e_triage import classify, redact, service_for
```

Do **not** wrap this in a `try`/`except` fallback to the old inline regexes. Two
implementations is the defect being fixed; a silent fallback would reintroduce it. If the

### M2.3 — Delete the inline classifier and both routing chains

Replace the whole block from `groups = {}` through the end of the second
`for failure in failures:` routing loop (currently ending at the `failure["service"] = (...)`
assignment, immediately before `summary = {`) with:

```python
groups = {}
for failure in failures:
    kind, target = classify(failure)
    groups[(kind, target)] = groups.get((kind, target), 0) + 1
failure_groups = [
    {"kind": kind, "target": target, "count": count, "service": service_for(target)}
    for (kind, target), count in sorted(groups.items())
]
for failure in failures:
    failure["service"] = service_for(failure.get("file", ""))
```

This deletes: `_UNREACHABLE`-equivalent inline regexes, the inline `targets` port dict, the
broad `timeout` regex, the inline contract regex, and both copies of the substring routing
chain.

**Behaviour changes this introduces, all intended:**

| Change | Before | After |
|---|---|---|
| `target` for non-port kinds | raw spec path, e.g. `api/cart.spec.ts` | spec slug, e.g. `api-cart` |
| Unknown port | `unknown` | `host-<port>` |
| Broad "timeout" word match | classified `timeout` | falls through to `assertion` (unless `status == "timedOut"` or `Timeout \d+ms exceeded`) |
| `auth` failures | classified `assertion` or `contract-drift` | classified `auth` |

The `target` shape change is what makes `e2e.sh` and Hermes agree — Hermes has always used
slugs, and `failure_groups` targets now match the slugs in Hermes-filed bug doc names.

## M3 — Close the redaction gap

### M3.1 — Redact at the point of capture

In the `walk_suites` closure in `_e2e_write_summary`, the `failures.append({...})` call
(currently `scripts/plugins/e2e.sh:700-705`) writes `title` and `error` raw. Wrap both:

```python
                        failures.append({
                            "file": spec_file or "",
                            "title": redact(spec.get("title") or ""),
                            "status": last["status"],
                            "error": redact(" / ".join(lines[:3]))[:300],
                        })
```

Redact **before** truncating to 300, so a token cannot survive by being cut in half across the
boundary and thereby escaping the pattern on a later re-read. `file` is a spec path and is not
redacted (redacting it would corrupt routing); spec paths do not carry credentials.

### M3.2 — Redact the run's own log tail is NOT in scope

`<run_id>.log` is the raw Playwright log and stays raw — it is local-only, is not published to
the cluster, and redacting it would break debugging. Only the JSON summary, the failures file,
and the published event carry redacted text. Note this explicitly in the CHANGELOG entry so
the asymmetry is deliberate and documented, like the Prometheus/ArgoCD asymmetry before it.

### M3.3 — Defence in depth in the remote validator

`scripts/plugins/e2e_remote.sh`'s validator (`details` loop, ~line 586) receives a summary
produced by a runner that may be running older code. Redact there too, rather than trusting
the producer. Add near the top of that heredoc's imports:

```python
sys.path.insert(0, os.environ["E2E_REMOTE_LIB_DIR"])
from hermes.e2e_triage import redact
```

export `E2E_REMOTE_LIB_DIR` the same way M2.1 does for the other function, and in the
validation loop, after the existing type/length checks pass, rewrite the two free-text fields:

```python
    detail["title"] = redact(detail["title"])
    detail["error"] = redact(detail["error"])
```

Keep the existing length checks **before** this, unchanged — `redact` can only shorten or
keep length, so the checks stay valid.

## M4 — The labelled corpus

### M4.1 — Corpus file

Create `scripts/tests/fixtures/e2e-corpus/corpus.jsonl` — one JSON object per line, no
trailing comma, LF endings. Each entry:

```json
{"id": "2026-09-16-cart-01", "source": "docs/bugs/2026-09-16-e2e-contract-drift-api-cart.md", "file": "api/cart.spec.ts", "status": "failed", "error": "Error: expect(received).toHaveProperty(path) / Expected path: \"id\" / Received path: []", "expected_kind": "contract-drift", "expected_target": "api-cart", "expected_service": "basket"}
```

Populate it from the 11 `## Sample errors` bullets across the 5 machine-filed docs listed in
"Why". Rules for transcription:

- `error` is the bullet text verbatim, minus the leading `- `.
- `file` comes from the doc's "Failing tests" section (the `` `path` `` before the em dash).
- `expected_kind` and `expected_target` come from the doc slug
  (`e2e-<kind>-<target>` → e.g. `e2e-contract-drift-api-cart` → `contract-drift` / `api-cart`).
- `expected_service` is what `service_for(expected_target)` must return — derive it by hand
  from the routing table and hard-code it, so the test cannot pass by agreeing with a bug.
- `status` is `"failed"` unless the doc says the test timed out.

**Do not invent entries.** If a doc's sample bullet cannot be attributed to a spec file with
certainty, omit it and say so in the README. A corpus that is smaller and correct is the
deliverable; a corpus padded with guesses is worse than none.

### M4.2 — Synthetic entries for the classes the corpus lacks

The 5 docs cover only `assertion` and `contract-drift`. Add clearly-marked synthetic entries
covering the other classes, with `"source": "synthetic"`:

- `service-unreachable` — Tier 1 port: `connect ECONNREFUSED 10.43.0.2:8080` → `order`
- `service-unreachable` — **Tier 2 port**: `connect ECONNREFUSED 10.0.0.1:8081` → `order`
- `service-unreachable` — Tier 2 port: `connect ECONNREFUSED 10.0.0.2:8082` → `product-catalog`
- `service-unreachable` — unknown port: `connect ECONNREFUSED 10.0.0.9:9999` → target `host-9999`

- `assertion` — `expect(res.status).toBe(404) / Received: 500`, pinning that `404`/`4xx` in an

The two Tier 2 port entries are the regression pin for the M1.1 bug. The last two are the pins
