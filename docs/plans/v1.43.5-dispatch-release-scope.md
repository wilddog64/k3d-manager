## Problem

The Agent dispatch dashboard can only scope by time (`$window` = 1d / 7d / 30d). The operator wants to
pick a release and see that release's specs, tokens and time-to-land. The `Per spec` table already has
a Release column, but the tiles have no release label, and a 30-day window both mixes releases and
cuts off older ones.

**Coverage floor is v1.43.0, not v1.40.0.** The ledger
(`~/.local/share/k3d-manager/worktrees/ledger.jsonl`) begins at v1.43.0, the first release dispatched
through `bin/k3dm-codex-dispatch`. On 2026-10-17 it holds v1.43.0, v1.43.2, v1.43.3 and v1.43.4. Codex
runs for v1.40–v1.42 were launched by hand and recorded no spec or release, so there is nothing
truthful to backfill. The selector lists only releases present in the ledger. Do NOT synthesize
entries for earlier releases.

## Design

Releases become extra values of the existing `window` label. The exporter already renders every
series per window. It will also render the same series for each release in the ledger, with
`window="<release>"`. Every panel already filters on `window="$window"`, so every panel follows the
selection without a query change.

Release scope differs from time scope in only one place: event selection.

| Scope | Landed tasks | Land attempts |
|---|---|---|
| time (`1d`/`7d`/`30d`) | latest `land` per task with `ts >= cutoff` (unchanged) | `land` / `land_refused` with `ts >= cutoff` (unchanged) |
| release `vX.Y.Z` | latest `land` per task whose `version` normalizes to `vX.Y.Z`, any `ts` | `land` / `land_refused` whose `version` normalizes to `vX.Y.Z`, any `ts` |

- **Normalization.** `version` must match `VERSION_RE`. Prefix `v` if it is missing, so `1.43.3` and
  `v1.43.3` are one release. An event with a missing or invalid version is in no release scope; it
  still counts in the time scopes, as today.
- **Release list.** Normalized versions seen on any `start` event, sorted by numeric tuple. A release
  with starts but no lands still renders `k3dm_dispatch_landed{window="vX.Y.Z"} 0`, so it appears in
  the selector.
- **Task cap.** `TASK_CAP` (50) and `k3dm_dispatch_task_truncated` apply per scope, unchanged.
- **Not scoped.** `k3dm_dispatch_running`, `k3dm_dispatch_awaiting_land`,
  `k3dm_dispatch_ledger_timestamp_seconds` and `k3dm_dispatch_ledger_bad_lines` stay global and
  unlabelled. They describe "now", not a period.

### E1. `bin/k3dm-dispatch-metrics`

1. Split `_window_metrics(events, now, seconds)` into a selection step and a shared computation:
   - `_scope_metrics(events, selected, landed_selected)` computes the dict `_window_metrics` returns
     today (`landed`, `attempts`, `tokens`, `verifier`, `wait`, `elapsed`, `codex_minutes`, `tasks`).
     It takes the attempt events (`selected`) and the chosen latest-land events per task key
     (`landed_selected`).
   - `_window_metrics` keeps its name and signature. It selects by cutoff exactly as now and calls
     `_scope_metrics`.
   - New `_release_metrics(events, release)` selects by normalized version and calls `_scope_metrics`.
   - `_task_metrics` still receives **all** events of a task (`_task_states(events)[key]`), never a
     filtered list, so a task whose `start` predates a window still computes `elapsed` as today.
2. New `_normalize_version(value)`: returns `"v" + value.lstrip("v")` when `VERSION_RE` matches,
   else `None`. New `_releases(events)` returns the sorted list described above.
3. In `render`, move the per-scope body of the `for window, seconds in WINDOWS.items()` loop into
   `_render_scope(lines, window, metrics)`. Call it for each time window, then for each release from
   `_releases(events)`, passing `window=<release>`. Output for the three time windows must be
   byte-identical to today's. Test 1 pins this.

### E2. `grafana-dashboard-agent-dispatch.yaml`

Replace the `custom` `window` variable with a query variable over the same label. Keep `name`,
`label` and the `7d` default:

```json
{
  "name": "window", "label": "Window", "type": "query",
  "datasource": {"type": "prometheus", "uid": "prometheus"},
  "query": {"query": "label_values(k3dm_dispatch_landed, window)", "refId": "window"},
  "definition": "label_values(k3dm_dispatch_landed, window)",
  "refresh": 2, "sort": 7, "includeAll": false, "multi": false,

}
```

- `sort: 7` is natural ascending, which Grafana 11.4 (hub image `grafana/grafana:11.4.0`) supports.
  The intended order is `1d`, `7d`, `30d`, `v1.43.0`, `v1.43.2`, … Confirm it live (DoD). If
  Grafana orders differently, report it; do not hand-maintain a custom list.
- Update the dashboard description and the `Per spec` panel description. "in the window" becomes "in
  the selected window or release". Add one sentence: "Release scope covers v1.43.0 onward; earlier
  releases were dispatched before the ledger existed."
- Leave the Running, Awaiting land and Time since last dispatch update panels unchanged. Append
  "(not release-scoped)" to their descriptions.

## API-equivalent cost

Codex runs on the operator's $20/month ChatGPT plan, so a run costs nothing extra. The operator
wants to see what the same work would cost at OpenAI API prices. The ledger can't price a run
today. `codex_exit.tokens` is the "tokens used" line Codex prints: uncached input plus output. It
leaves out cached input, which is most of the volume. Measured on run `hub-apps-settle-wait`
(2026-10-17):

- input 611,180, of which cached 561,408;
- output 5,912;
- "tokens used" 55,684.

The full breakdown is in Codex's own session record,
`${CODEX_HOME:-$HOME/.codex}/sessions/YYYY/MM/DD/rollout-*-<session id>.jsonl`. Its last
`"total_token_usage"` object holds `input_tokens`, `cached_input_tokens`, `output_tokens` and
`reasoning_output_tokens`. `codex exec resume` continues the **same** session id, so a session's
last usage is cumulative across resumes. The run log's first `session id: ` line names the session,
as `_dispatch_resume` already parses it.

Formula, per session, in USD:

```
(input − cached) × input_rate + cached × cached_input_rate + output × output_rate   (rates per 1M tokens)
```

`reasoning_output_tokens` is already part of `output_tokens`; do not add it again.

### E3. `scripts/etc/agent/codex-model-prices.json` (new)

```json
{
  "currency": "USD",
  "unit": "per_million_tokens",
  "checked": "2026-10-17",
  "source": "OpenAI API standard short-context rates after the 2026-07-30 cut, via third-party price trackers; not yet confirmed on openai.com/api/pricing",
  "models": {
    "gpt-5.6-luna": {"input": 0.20, "cached_input": 0.02, "output": 1.20}
  }
}
```

A model with no entry is **unpriced**. Never fall back to another model's rates.

### E4. `bin/k3dm-codex-dispatch`: record usage

1. New helper `_dispatch_codex_usage <run-log> <version> <slug>`.
   - Read the first `session id: ` value from the log. Find exactly one file matching
     `${CODEX_HOME:-$HOME/.codex}/sessions/*/*/*/rollout-*-<id>.jsonl`.
   - From it, take the last `total_token_usage` object and the last `"model"` string.
   - Append a ledger event:
     ```
     {"event":"codex_usage","version":…,"slug":…,"session":<id>,"model":<model or null>,
      "input":N,"cached_input":N,"output":N}
     ```
     Use `_dispatch_ledger_event`.
   - If there is no session id, no file or several files, or the JSON can't be parsed, print one
     `[codex-dispatch] WARNING:` line and append nothing. It must never fail the dispatch.
2. Call it in both places that call `_dispatch_codex_exit` (start and resume), right after that call,
   with the same log path.
3. New subcommand `usage-backfill`. It walks every `<root>/<version>/<slug>.run/codex*.log` and calls
   the helper for each log whose `(version, slug, session)` has no `codex_usage` event yet.
   - Idempotent: running it twice appends nothing new.
   - Prints `backfilled: N` and `missing: M`. M counts logs whose session file no longer exists.
   - Add it to the usage text.

### E5. `bin/k3dm-dispatch-metrics`: price it

1. Load the prices from `scripts/etc/agent/codex-model-prices.json`, resolved from the script's repo
   root. Add a `--prices PATH` option so tests can override it. A missing or unreadable file means
   every task is unpriced. It is not an error.
2. **Per-task cost.**
   - Group the task's `codex_usage` events by `session`, and keep the last event of each session by
     `ts`, since usage is cumulative.
   - Price each session and sum them.
   - If any session's model is unpriced, or the task has no `codex_usage`, the task's cost is
     `None`.
   - Add the result as `api_cost_usd` in `_task_metrics`'s dict. Pass `api_cost_usd` through
     `tasks` as the last tuple element.
3. **Series.** In `_render_scope`, add these for every scope, time windows and releases alike:
   - `k3dm_dispatch_task_api_cost_usd{window,version,slug}`, only for priced tasks, inside the
     existing `TASK_CAP` loop;
   - `k3dm_dispatch_api_cost_usd{window}`: the sum over priced landed tasks in scope, `0` when none;
   - `k3dm_dispatch_api_cost_priced_tasks{window}` and
     `k3dm_dispatch_api_cost_unpriced_tasks{window}`: counts of landed tasks in scope.
4. **Test 1 still pins the time-window output.** Its golden must change only by these new lines
   added at the end of each window's block. Assert that every other line is byte-identical and in
   the same order.

### E6. Dashboard

1. **Per spec.** Add target `E`, `sum by (version, slug) (k3dm_dispatch_task_api_cost_usd{window="$window"})`,
   renamed **API equiv.**, with unit `currencyUSD` and 2 decimals. An empty cell means unpriced. Add
   to the panel description: "API equiv. prices Codex's session tokens, cached input included, at the
   rates in scripts/etc/agent/codex-model-prices.json. It is not a bill: Codex runs on a $20/month
   ChatGPT plan."
2. **New stat panel** "Codex at API prices", next to "Codex tokens per accepted spec":
   - expr `k3dm_dispatch_api_cost_usd{window="$window"}`, unit `currencyUSD`;
   - description: "What this window's or release's landed Codex specs would cost at API rates,
     compared with the flat $20/month ChatGPT plan. Specs dispatched before usage recording show up
     as unpriced (see the subtitle)."
   - a second target, `k3dm_dispatch_api_cost_unpriced_tasks{window="$window"}`, shown as a small
     "unpriced" value.

   Move panels only as much as needed to fit it, with no overlapping `gridPos`.
3. **"Codex tokens per accepted spec".** Replace the sentence "tokens are not converted to dollars
   because price per token is not stable" with "see Codex at API prices for a dollar estimate".

## Tests (`scripts/tests/bin/test_dispatch_metrics.py`)

Use synthetic ledgers only. No Pushgateway and no network: reuse the existing `--dry-run` / `render`
pattern.

1. **Time windows unchanged.** For the existing `test_windows_latest_resume_and_malformed_lines`
   fixture, the lines whose `window` is `1d`/`7d`/`30d` equal a golden captured from the pre-change
   `render`. Store the golden as a literal in the test.
2. **Release scope includes old lands.** A task with `version: v1.43.0` landed 60 days before `now`
   appears in `window="v1.43.0"` with its `slug`, and is absent from `window="30d"`.
3. **Normalization.** Two tasks, `version: "1.43.3"` and `version: "v1.43.3"`, both land in
   `window="v1.43.3"`, and no `window="1.43.3"` series exists.
4. **Invalid version.** A task with `version: "main"` lands in `7d` but in no release scope, and no
   `window="main"` series is emitted.
5. **Started, never landed.** A release with only `start` events renders
   `k3dm_dispatch_landed{window="vX.Y.Z"} 0`.
6. **Elapsed uses all task events.** A start 40 days ago and a land 1 day ago give `elapsed_seconds`
   ≈ 39 days in both `7d` and the release scope.
7. **Globals stay global.** `k3dm_dispatch_running` appears exactly once, with no `window` label.
8. **Dashboard.** Parse the ConfigMap JSON and assert:
   - the `window` variable has `type == "query"`, query `label_values(k3dm_dispatch_landed, window)`,
     and `sort == 7`;
   - every panel `expr` that referenced `$window` still does.
9. **Cost formula.** A task with one `codex_usage` (`gpt-5.6-luna`, input 611180, cached 561408,
   output 5912) and a prices file given with `--prices` has `api_cost_usd` = 0.0099544 + 0.01122816 +
   0.0070944 = 0.02827696, to within 1e-9.
10. **Resume is not double-counted.** The same session has two `codex_usage` events, the second with
    larger cumulative numbers. Only the second is priced. A second *session* on the same task is
    added.
11. **Unpriced model.** One session's model has no price entry. The task gets no
    `k3dm_dispatch_task_api_cost_usd` series, `unpriced_tasks` is 1, and `api_cost_usd` for the scope
    excludes it.
12. **Scope total.** `k3dm_dispatch_api_cost_usd{window="v1.43.4"}` equals the sum of that release's
    per-task costs.
13. **Dashboard.** The `Per spec` panel has a target whose expr contains `k3dm_dispatch_task_api_cost_usd`,
    renamed `API equiv.`. A stat panel titled `Codex at API prices` exists. No two panels' `gridPos`
    rectangles overlap.

BATS (`scripts/tests/bin/codex_dispatch.bats`). Use the existing stubbed `K3DM_CODEX_BIN`. Point
`CODEX_HOME` at `$BATS_TEST_TMPDIR`, and write a fake session file whose name ends in the session id
the stub prints:

14. A start appends one `codex_usage` event with the fake file's `input`/`cached_input`/`output` and
    `model`.
15. With no session file present, the start still succeeds, prints the WARNING, and appends no
    `codex_usage`.
16. `usage-backfill` run twice appends exactly one event per `(version, slug, session)` in total.

**Mutations (report each as caught):**
- drop the `v` normalization → test 3 fails;
- pass filtered events to `_task_metrics` → test 6 fails;
- emit release scopes before time windows, or alter time-window output → test 1 fails;
- price every `codex_usage` event instead of the last per session → test 10 fails;
