## Problem

The operator wants to compare Gemini 4 Argon (`agy`) with Luna (Codex) on k3d-manager specs, and
needs the comparison recorded ("please don't by pass tool. I need data for research purpose").
`bin/k3dm-codex-dispatch` runs only `codex exec`, so an `agy` run today records nothing.

The full agy plan sits in v1.44.1 behind two other plans, because it also changes the dispatch
dashboard. The data does not need the dashboard: the ledger keeps raw events, so anything recorded
from now on can be shown once v1.44.1 lands. This plan does the dispatcher and ledger part only.

## Fix

### F1. An `--agent` option on `start`

- `bin/k3dm-codex-dispatch start --spec PATH [--agent codex|agy] [--model ID]`. The default stays
  `codex`, and a Codex run without `--agent` keeps its exact command line.
- `--model` with `--agent codex` passes `-m "$model"` to `codex exec`. Without `--model`, Codex
  runs as today.
- The `agy` worker runs from the task worktree (`agy` has no `-C`), in a subshell:
  `(builtin cd "$worktree" && "${K3DM_AGY_BIN:-agy}" --print "$(<"$run/prompt.md")" --output-format json --model "$model" --sandbox --add-dir "$worktree" --add-dir "$run/state" --dangerously-skip-permissions) >"$run/agy.log" 2>&1`.
  `agy --help` on 2026-10-24 shows `--print`/`--prompt` take the prompt and `--output-format json`
  is valid in print mode. Pass the same state env vars the Codex worker gets.
- The default `agy` model is `gemini-4-argon-medium`.
- Before any worktree is created, `--model` (or the default) is checked against the output of
  `"${K3DM_AGY_BIN:-agy}" models`. An unknown ID fails with `unknown agy model: <id>` followed by
  the list. Never hardcode a fallback list. If `agy models` itself fails, `start` fails.
- The prompt is the same one Codex gets.
- `agy` has no read-only `.git`. After the worker exits, compare the task branch `HEAD` with
  `"$run/base"`:
  - **Different (the agent committed):** write a `scope_violation` ledger event with
    `reason: "agent committed"`. `status` shows `VIOLATION: agent committed`, and `land` refuses
    the task.
  - **Same:** `land` works from the working tree, exactly as for Codex.
- `resume` on an `agy` task uses `--conversation <id>` when the first run's JSON output carried a
  conversation ID (store it in `"$run/session"` as Codex does). Without one, `resume` fails with
  `agy run returned no conversation id; start a new task`. Never use `--continue`: it picks the most
  recent conversation, which may not be this task's.
- `--network` is refused with `--agent agy`.

### F2. The ledger and the exporter carry the agent

- The `start` event gains `"agent"` (`codex` or `agy`), `"model"`, and `"model_source"`:
  `explicit` when `--model` was given, `default` for the `agy` default, and `inherited` for a Codex
  run without `--model`, where `model` is `null`. Do not infer a Codex model from config or today's
  default. This matches the identity contract in
  `docs/plans/v1.43.7-dispatch-vendor-coordinator-model-telemetry.md`, which later adds vendor and
  coordinator fields on top.
- `codex_exit` and `codex_usage` keep their names for Codex. `agy` writes `agent_exit` and
  `agent_usage`. `usage` comes from the JSON output's usage fields when present and is `null`
  otherwise. Do not invent a token count.
- `bin/k3dm-dispatch-metrics` adds an `agent` label to every per-spec series, limited to `codex`
  and `agy` (anything else exports as `other`). An event with no `agent` field means `codex`, so the
  existing history exports the same values under `agent="codex"`. `agy` usage never adds to a
  Codex token series.

### F3. Side-by-side runs of one spec

- The same spec may be dispatched to both agents under different slugs, for example
  `--slug <slug>-agy`.
- `land` refuses a second slug for a spec that already has a landed slug, unless
  `--superseding <slug>` names the landed one. Only one implementation reaches the release branch.
- The landed task's `land` event records `"chosen": true`.

### F4. Make target and how-to

- `make codex-dispatch SPEC=... AGENT=agy MODEL=...`. `AGENT` and `MODEL` are optional, and with
  neither the target runs the same command as today.
- `docs/howto/codex-dispatch.md` gains an "agy (Gemini 4 Argon)" section: the options, the commit
  check, resume behaviour, and the side-by-side workflow.
