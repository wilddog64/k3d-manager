## Problem

The console sshd (`scripts/etc/ssh/k3dm-web-console_sshd_config.tmpl`) has no `RevokedKeys`. The only way to cut off a
lost device's certificate is the whole-console revoke marker `/etc/k3dm-web-console/revoked`, which parks the daemon for
everyone. If certificates are long-lived (parent open question 1), there is no per-certificate cut-off at all.

## Behaviour

Parent **B7**, in full:

1. The template gains `RevokedKeys /etc/k3dm-web-console/revoked_keys` directly after `TrustedUserCAKeys` (`tmpl:14`),
   and `_wc_render`'s expected-lines list (`bin/k3dm-web-console-sshd:25-75`, `TrustedUserCAKeys` at `:41`) gains the same
   line in the same position. C2 (`_wc_check_config` `:158-163`) compares the two.
2. The name must differ from the whole-console marker `/etc/k3dm-web-console/revoked`: `_wc_files_healthy` requires that
   marker to be absent (`:220-222`) and `web_console_common.sh:129,212,217` parks the daemon when it exists. The marker's
   handling does not change.
3. Install creates the file only if absent, as an empty KRL (`ssh-keygen -k -f <stage>/revoked_keys`), root:wheel 0644,
   staged beside `_wc_stage_keys` (`:464-474`), through `_wc_priv` like every write under `_WC_CONF_DIR`. It is operator
   data like the host key: never overwritten on reinstall (an overwrite would un-revoke) and not a manifest part-A row.
4. `_wc_dest_check` (`:149-151`), `_wc_files_healthy` (`:217-240`) and the dry-run plan (`:693`) know the file.
   `_wc_files_healthy` fails if it is missing, a symlink, not a regular file, or not `0:0:644` through `_wc_file_mode`
   (`:132-137`).
5. The installer refuses to activate a config while the file is missing (the existing `sshd -t` gate cannot catch it).
6. Uninstall: the non-purge list (`:739`) is **not changed**; it names `revoked`, not `revoked_keys`, so the KRL stays.
   `PURGE=1` removes it with the rest of `_WC_CONF_DIR` (`:740`). A test pins both.
7. Operator revoke command, for the guide (part C): `ssh-keygen -k -u -f /etc/k3dm-web-console/revoked_keys <cert or spec>`
   (root).
