# Cloud bridge: let a cloud session bring the ACG sandbox up and down

**Branch:** `k3d-manager-v1.41.0`
**Filed:** 2026-10-03, Claude
**Status:** DONE `9d527cec` (Claude-verified 2026-10-03)

## What the operator asked for

> "can we allow bring up ACG sandbox and down as this is not our primary cluster"

Operator decision, 2026-10-03: the ACG sandbox (`CLUSTER_PROVIDER=k3s-aws`, a disposable 4-hour
Pluralsight sandbox) may be brought up and down by a cloud session. This narrows the earlier rule
in `v1.41.0-cloud-bridge-e2e-dispatch.md` ("Do NOT expose … any target that brings a cluster up or
down"). The rule still holds for every other cluster. The local hub and the Hostinger app cluster
are the primary clusters, and a cloud session must never reach their lifecycle.

Why (operator, 2026-10-03): *"the sandbox last at least 4 hours which is good for agent to debug.
doing this way, we avoid working on live hostinger directly"*. A sandbox lasts at least 4 hours,
which is long enough for a cloud agent to reproduce and debug a problem on its own disposable
cluster. That keeps agent debugging off live Hostinger.

## Findings that shape the design

1. **The webhook's cluster route trusts `provider` and defaults it to `aws`.** `bin/k3dm-webhook`
   (`route["handler"] == "cluster"`) maps a missing or unknown `provider` to `"aws"`, and accepts
   `hostinger`. `_run_cluster` (`scripts/lib/webhook/lifecycle.py`) then runs
   `make down CLUSTER_PROVIDER=k3s-hostinger` for `hostinger`, which **destroys the app cluster**.
   The policy name is just `cluster-up` / `cluster-down` with no provider in it, so a capability set
   keyed on the name alone would grant Hostinger teardown too. The capability must bind the provider,
   and it must check the **raw** request value, before the webhook's fallback.
2. **`down` for `aws` already keeps the hub.** `_run_cluster` runs `make down KEEP_LOCAL=1` for every
   non-Hostinger provider, which passes `--keep-hub` to `bin/cluster-down`. Keep it that way.
3. **One cluster job at a time is already enforced.** `_running_cluster_job()` makes the route return
   409 while an up or down is running. Nothing new is needed for concurrency between jobs.
4. **`up` needs a live ACG login.** `bin/cluster-up` drives the ACG console through the Chrome CDP
   session. If that login has expired, `up` fails with `ACG_SESSION_EXPIRED` and the operator must
   log in by hand. This fails safely. Document it, don't work around it.
5. **`make up` also runs `observability` and `platform-ops`** after the sandbox is up. This is the
   existing `/cluster-up` behaviour from Slack, so it is accepted here unchanged.
6. **Job state `killed` is not terminal for the bridge.** The cluster `kill` route writes
   `status: killed`, but `TERMINAL_JOB_STATES` in `bin/k3dm-cloud-bridge` is `("success", "failed")`.
   A killed job that the bridge is following (M8 of the e2e spec) is therefore watched until its
   timeout plus ten minutes, and then answered with "watch expired". Fold the fix in here.

## Design

- **Two new bridge actions, provider fixed by the bridge:**
  - `sandbox-up` → `POST /api/v1/cluster` with body `{"action": "up", "provider": "aws"}`;
  - `sandbox-down` → `POST /api/v1/cluster` with body `{"action": "down", "provider": "aws"}`.
  
  Neither takes an argument. The provider is a constant in `ACTION_ALLOWLIST`, so no request can name
  `hostinger` or anything else.
- **Both use the `cloud-runner` token.** Do not add a fourth token. The capability set gains two
  entries that bind the provider: `cluster-up@aws` and `cluster-down@aws`.
- **The webhook enforces the provider too (defence in depth).** In `scripts/lib/webhook/policy.py`:
  - `_action_policy` adds `"provider": <raw body provider string, or "">` to the policy it returns for
    `/api/v1/cluster` up and down. Leave `name` and `min_role` unchanged, so audit names and
    existing behaviour don't change.
  - `_policy_allows`, capability branch:
    - grant a `make:<target>` policy iff `<target>` is in the set (unchanged);
    - grant `cluster-up` / `cluster-down` iff `f"{name}@{policy.get('provider')}"` is in the set;
    - refuse everything else.
    
    Because a missing provider becomes `""`, it yields `cluster-up@`, which is refused. The fallback
    to `aws` happens only after authorization, so it can never widen the grant.
  - Check how `effective_policy` merges the route policy with the dynamic policy, and make sure the
    `provider` key reaches `_policy_allows`.
- **Not included:**
  - `cluster-kill`;
  - `cluster-resume` (its route has its own provider parsing, defaulting to `hostinger`);
  - `cleanup-stale-sandbox`;
  - `e2e-sandbox`;
  - any `make up` / `make down` make target.
  
  These are a later decision.
- **M8 job following** already covers the new actions: the cluster route answers 202
  `{"job_id", "status": "queued"}`. In `_watch_entry`, extend the timeout lookup so `sandbox-up` /
  `sandbox-down` get `timeout: 3600` (cluster jobs have no `MAKE_TARGETS` entry). Use a small
  constant next to `SLOW_ACTIONS`, e.g. `LIFECYCLE_TIMEOUTS = {"sandbox-up": 3600, "sandbox-down": 1800}`.
- **`killed` becomes terminal:** `TERMINAL_JOB_STATES = ("success", "failed", "killed")`.

## Gates (offline; paste actual output)

1. **The capability is not provider-agnostic.** `cloud-runner` is refused for `/api/v1/cluster`:
   - up with `provider: "hostinger"`;
   - down with `provider: "hostinger"`;
   - up with no provider;
   - up with `provider: "AWS"` (case matters);
   - down with `provider: "gcp"`;
   - the `kill` action.
   
   It is allowed for up and for down with `provider: "aws"`. Test at the `_policy_allows` /
   `effective_policy` level, in `scripts/tests/bin/webhook_policy.py`.
2. **The reader token is refused** for `sandbox-up` and `sandbox-down` (policy level), and the bridge
   presents the cloud-runner token for exactly `make-e2e`, `make-e2e-remote`, `sandbox-up` and
   `sandbox-down`, and the reader token for every other action. Assert this over the whole
   `ACTION_ALLOWLIST`, not a sample.
3. **No request can change the provider.** A `sandbox-down` request carrying extra args is rejected by
   `validate_request`, and the body the bridge sends is exactly `{"action": "down", "provider": "aws"}`.
4. **Hostinger is unreachable.** No `ACTION_ALLOWLIST` entry's fixed body contains `hostinger`, and no
   entry targets `/api/v1/cluster` with a provider other than `aws`. Assert this by iterating the
   table.
5. **Killed jobs finish.** A watched job whose stubbed `job-status` returns `killed` produces exactly
   one `.final.json` and clears the watch entry.
6. **Mutations.** For each one, `cp` a snapshot, mutate, show the test red, restore from the snapshot,
   and show `cmp` byte equality. Never restore with `git checkout`.
   - (a) the capability check ignores provider (`name in {"cluster-up","cluster-down"}`) → gate 1 red;
   - (b) drop `killed` from `TERMINAL_JOB_STATES` → gate 5 red;
   - (c) the token selection always returns the reader token → gate 2 red.
7. The bare suite `pytest scripts/tests/bin/test_cloud_bridge.py -q`, then `make test-pytest`,
   `make test-python-unit` and `python3 scripts/check-doc-links.py`.
8. `git diff --stat`: only the files named above, plus tests.
