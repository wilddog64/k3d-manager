# v1.33.0 — Controlled hub Kine datastore rebuild

**Status:** EXECUTED (2026-09-11); acceptance partially verified 2026-09-13 — see
"Close-out (2026-09-13)" below

## Objective

Replace the oversized local hub K3s/Kine datastore without raw SQLite deletion.
The result removes transient Kubernetes revision history while preserving durable
application data and recoverable desired state.

## Inventory (2026-09-10)

The hub server state database is 8.3 GiB. Persistent claims use `local-path`
with `Delete` reclaim policy, so an unplanned k3d rebuild can delete them.

| Durable workload | Claim capacity | Measured node storage |
|---|---:|---:|
| Keycloak PostgreSQL / LDAP | 5 + 2 + 1 + 8 GiB | included in agent-0 3.4 GiB |
| Vault | 1 GiB | included in agent-2 1.3 GiB |
| Trivy | 5 GiB | included in agent-1 67 MiB |
| Prometheus | 25 GiB | included in agent-0 3.4 GiB |

Host free space: 186 GiB. The recovery archive therefore fits locally, but must
be copied to a second location before any destructive teardown.

## Rungs

1. **Capture desired state.** Export non-secret manifests, ArgoCD Applications,
   and a protected Secret export; record PV/PVC inventory and image references.
2. **Capture durable data consistently.** Take a Vault Raft snapshot, then
   quiesce stateful writers and archive each k3d node's
   `/var/lib/rancher/k3s/storage`. Copy the complete
   `/var/lib/rancher/k3s/server/db/` directory **and** the server token; K3s
   requires the same token to restore encrypted datastore content. Record
   SHA-256 checksums and verify each archive can be listed.
3. **External-copy gate.** Copy the verified archive to a second disk/location.
   Do not proceed while there is only one local copy.
4. **Rebuild.** Stop the hub, remove only the K3s server datastore volume, and
   recreate/rejoin the control plane without deleting agent storage volumes.
   This rung is separately confirmed after the external-copy gate.
5. **Restore and verify.** Restore Vault first, reapply GitOps/desired state,
   confirm PVC binding/data, then run control-plane readiness and `make status`.
   Resume ArgoCD reconciliation only after stale ACG generated applications are
   removed.

## Boundaries

- No raw Kine `DELETE`, no time-based retention job, and no automatic rebuild.
- Never remove a Docker volume by wildcard; resolved server-datastore volume
  only, after a second backup copy exists.
- Prometheus data may be intentionally discarded only after the owner accepts
  losing historical metrics; it is not required for application recovery.
- Any manual cluster change absent from Git/Vault must be captured in the
  protected manifest archive before rung 4.

## Acceptance

- Archive inventory, checksums, and Vault snapshot are present and readable.
- At least two independent copies exist before destructive work.
- The recreated hub reaches `/readyz`, all durable claims bind, Vault restores,
  and `make status` reports no control-plane error.
- The old state database is retained only as an offline rollback artifact until
  acceptance completes.

## Execution finding

An initial online Kine tar stream was truncated and is invalid; see
`docs/issues/2026-09-09-hub-rebuild-online-kine-backup-truncated.md`. The plan
therefore requires an offline Kine capture after quiesce, not an online stream.
The first offline attempt captured raw inputs but did not complete the combined
archive verification gate; destructive rung 4 remains blocked.

## External-copy execution note

M2 is the designated independent recovery location. The copy uses the raw,
offline-consistent inputs rather than either invalid tarball, is resumable, and
must be checksum-verified after completion. Retain the M4 source and verified
M2 copy through acceptance plus a seven-day rollback window; retain the M2 copy
for 30 days thereafter unless the owner selects a different retention period.

The owner authorized the controlled rebuild after the checksum gate succeeds on
2026-09-09. That authorization does not waive the gate: no node, volume, PVC,
or datastore is removed until the M2 content comparison completes successfully.

## Blocking design finding

The current k3d create path replaces all agents, but durable `local-path` data
lives in their storage volumes. A standard recreate cannot adopt those agents or
map old PVC UIDs to new ones. The rebuild therefore also requires a tested
claim-to-new-local-path restore procedure before any live destructive step; see
`docs/issues/2026-09-10-hub-rebuild-agent-volume-restore-gap.md`.
