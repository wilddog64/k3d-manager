## Why

Asked for on 2026-09-25: the smoke gate should be reachable from Slack if it is not already.

Current state, verified:

| surface | exists? |
|---|---|
| `make smoke` (`Makefile:797` → `./scripts/k3d-manager smoke_run $(SMOKE_ONLY)`, `SMOKE_ONLY=offline\|cluster`) | **yes** |
| `/k3dm smoke` | **no** — `smoke` is absent from `MAKE_TARGETS` |

So only the Slack half is missing. This spec adds it and nothing else.

## Ordering constraint — do the gate fixes first

`make smoke` currently reports `0 passed, 2 failed` on a healthy cluster, from two defects inside the
gate rather than in the product:

- `docs/bugs/2026-09-25-smoke-cluster-health-app-context-decoupled-from-app-prefix.md`
- `docs/bugs/2026-09-25-smoke-webhook-gate-unbounded-sweep-and-unreachable-probes.md`

**Both must land before `/k3dm smoke` is enabled.** Exposing it first would put two false reds into
Slack on every invocation, which trains the operator to ignore the channel — the opposite of the
gate's purpose. This ordering is the whole risk in this change.

## S1 — `_ARG_PATTERNS`

Add to the dict in `scripts/lib/webhook/make_targets.py` (line 6), keeping the existing style:

```python
    "SMOKE_ONLY": re.compile(r"offline|cluster"),
```

`parse_make_request` calls `.fullmatch`, so the bare alternation is already anchored — do not add
`^`/`$` (no other pattern in the dict has them).

## S2 — `MAKE_TARGETS`

Add one entry. Place it with the other `operator` rows, after `"sync-apps"`:

```python
    "smoke": {"min_role": "operator", "optional": ("SMOKE_ONLY",), "timeout": 900, "summary": "run the smoke gate (offline always; cluster when reachable)"},
```

Two deliberate choices:

- **`min_role: operator`, not `reader`.** The cluster half of the sweep reads Vault secrets and
  performs real Keycloak/ArgoCD/frontend logins. It redacts via `_register_secret`, but a gate that
  exercises live credentials should not be triggerable by every `reader`. `status-public` and
  `observability-status` stay `reader` because they only probe endpoints. If the owner prefers
  `reader`, the narrower option is a `reader`-level `SMOKE_ONLY=offline` — but that needs a
  per-argument role check, which `parse_make_request` does not support today, so it is out of scope
  here.
- **`timeout: 900`, not the `MAKE_JOB_TIMEOUT_DEFAULT` of 300.** The full sweep runs endpoints
  concurrently but Vault/ESO/Kubernetes/logins serially, with `_SMOKE_RETRIES = 3` and
  `_SMOKE_RETRY_SLEEP = 10`. 300s is not enough whenever one stage retries.

No `confirm` key — the gate is read-only and must not prompt.

## S3 — tests in `scripts/tests/bin/webhook_make_targets.py`

Follow the file's existing style. Add cases asserting:

1. `parse_make_request("smoke", {}, None)` → `(["smoke"], None)`.
2. `parse_make_request("smoke", {"SMOKE_ONLY": "offline"}, None)` → `(["smoke", "SMOKE_ONLY=offline"], None)`.
3. `SMOKE_ONLY="cluster"` likewise.
4. `SMOKE_ONLY="both"` → error `invalid value for SMOKE_ONLY`. **This is the case that proves the
   pattern is anchored** — without `fullmatch` it would pass, so assert the error, not just a truthy
   result.
5. `SMOKE_ONLY="offline; rm -rf /"` → error (same anchoring guarantee, injection shape).
6. `parse_make_request("smoke", {"APP": "x"}, None)` → error `smoke does not accept APP`.
7. `make_target_help` for a `reader` role does **not** list `smoke`; for `operator` it does.

Assert on meaningful tokens, never a whole source line.
