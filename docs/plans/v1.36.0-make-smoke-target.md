# v1.36.0 — Unified `make smoke` target

**Status:** ASSIGNED (Codex, 2026-09-22)
**Branch:** `k3d-manager-v1.36.0`

## Objective

There is no `make smoke` target today. Three smoke scripts exist in `bin/` and are
invoked ad hoc, so "did the smoke test pass?" has no single answer:

| Script | Lines | Needs a cluster? | Notes |
|---|---|---|---|
| `bin/smoke-test-cluster-health` | 99 | yes | ghcr-pull-secret, ArgoCD app sync, app pods |
| `bin/smoke-test-webhook` | 132 | **no** | boots an isolated webhook on `SMOKE_WEBHOOK_PORT` (default 27443) |
| `bin/smoke-test-jenkins` | 709 | yes | **Jenkins is DEPRECATED — excluded, see below** |

Add one target that runs the supported smoke surface, reports a per-check table,
and exits non-zero if any selected check fails.

## Scope

**In scope:** a `smoke` target in `Makefile`, a `smoke_run` dispatcher function in a
new `scripts/plugins/smoke.sh`, and a BATS suite.

**Out of scope:** modifying any existing `bin/smoke-test-*` script; Jenkins.

## Design

### Tiering

`make smoke` must be useful on a laptop with no cluster. Split by requirement:

- `OFFLINE` checks — run always. Today: `bin/smoke-test-webhook`.
- `CLUSTER` checks — run only when the target context is reachable. Today:
  `bin/smoke-test-cluster-health`.

A `CLUSTER` check whose context is unreachable is reported `SKIP`, not `FAIL`.
An unreachable cluster is not a smoke failure; a failing check is.

### Jenkins is excluded

`bin/smoke-test-jenkins` is NOT wired in. Jenkins is a deprecated demo feature,
disabled by default and not deployed (see `CLAUDE.md`). Wiring a 709-line
deprecated smoke script into the default gate would make `make smoke` fail on
every box that correctly does not run Jenkins. Retain the script; do not call it.

### Makefile target

Add next to the other test targets. Do **not** put logic in the recipe — the
recipe delegates, exactly like `e2e`:

```make
## Run the smoke gate (offline checks always; cluster checks when reachable). SMOKE_ONLY=offline|cluster optional.
smoke:
	./scripts/k3d-manager smoke_run $(SMOKE_ONLY)
```

### `scripts/plugins/smoke.sh`

New plugin. Public entry point `smoke_run`, everything else `_smoke_*`.

```bash
#!/usr/bin/env bash
# scripts/plugins/smoke.sh

set -euo pipefail

SMOKE_INFRA_CONTEXT="${SMOKE_INFRA_CONTEXT:-${INFRA_CONTEXT:-k3d-k3d-cluster}}"

function _smoke_records() {
  cat <<'EOF'
offline|webhook|bin/smoke-test-webhook
cluster|cluster-health|bin/smoke-test-cluster-health
EOF
}
```

Required behaviour:

1. `smoke_run` accepts an optional filter: empty (all), `offline`, or `cluster`.
   Any other value is an error with a usage line and a non-zero exit.
2. `_smoke_context_reachable` decides whether `CLUSTER` checks run. It must be a
   bounded probe, not an unbounded `kubectl get nodes`:
   ```bash
   function _smoke_context_reachable() {
     local _ctx="$1"
     _kubectl --context "$_ctx" --request-timeout=10s get --raw='/readyz' >/dev/null 2>&1
   }
   ```
3. Each check runs in a subshell so one failing check cannot abort the loop via
   `set -e`. Use the verified-reliable neutraliser — `if ! cmd` does **not**
   reliably suppress `errexit` inside nested function bodies:
   ```bash
   if (set +e; "$_script" >"$_log" 2>&1); then
     _status=PASS
   else
     _status=FAIL
   fi
   ```
4. Every check's output goes to a per-check log under a run directory; the
   summary table prints the log path for any non-`PASS` check.
5. Final line is a table, then an explicit verdict. Exit `0` only if no check
   is `FAIL`:
   ```
   check           tier      status
   webhook         offline   PASS
   cluster-health  cluster   SKIP    (context k3d-k3d-cluster unreachable)
   smoke: 1 passed, 0 failed, 1 skipped
   ```
6. `SKIP` must state the reason. A silent skip is a failure of this spec.

## Tests — `scripts/tests/plugins/smoke.bats`

Stub `bin/` scripts and `_kubectl` on `PATH`; never touch a real cluster.

Required cases:

1. All checks pass → exit 0, table shows two `PASS`.
2. A failing offline check → exit non-zero, that row is `FAIL`, and the summary
   counts one failure.
3. Unreachable context → cluster row is `SKIP` with a reason, exit stays 0.
4. A failing cluster check with a reachable context → exit non-zero.
5. `SMOKE_ONLY=offline` → the cluster script is never invoked. Assert by having
   the stub append to a calls log and asserting the log has no cluster entry.
6. Invalid filter (`smoke_run bogus`) → non-zero with a usage line.
7. One failing check does **not** prevent later checks from running — assert the
   later check still appears in the table. This is the `set -e` regression guard.

**No bare `!` in BATS.** Use `run <cmd>` then `[ "$status" -ne 0 ]`.
**No whole-line `grep -F`** against source lines — assert meaningful tokens.

Mutation check (mandatory, paste evidence): remove the `(set +e; …)` subshell and
confirm case 7 fails. A guard that cannot fail is not a guard.

## Rules

- `set -euo pipefail` in the new plugin; double-quote every expansion; LF only.
- No inline comments in shell blocks.
- Route privileged/external commands through `_run_command`; use `_kubectl`.
- `shellcheck` must pass with **zero new warnings** on `scripts/plugins/smoke.sh`.
- `make test` must stay green. Also run `bats scripts/tests/plugins/smoke.bats`
  and paste the full output — not a `tail`.
- Report the BATS pass count as `grep -cE '^ok '` plus a `grep 'not ok'` check.
  A `tail -3` is not evidence of green.
