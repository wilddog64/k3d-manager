## Problem

The v1 store kept HMAC-signed records in the operator's home with the key in the operator's Keychain, plus a test-mode sentinel. Under O2 the
operator account is the attacker, so a store the operator can read or write, a Keychain item the operator can read, and an environment or
sentinel switch the operator can set are all forgeable. This part is therefore only the engine: the state machine, the TOTP check, the
throttles and the clock rules, as a pure Python library that is handed its state directory, clock and secrets by its caller. It holds no
authority by itself. Part 2c runs it as root, where the state directory is unreadable to the operator. The HMAC and the Keychain are gone:
the directory permission is the protection, and a plain checksum only detects corruption.

Findings fixed here:

- (R1) there is no test mode. The engine reads no environment variable and no sentinel; a test builds an `Engine` with a temporary
  directory and a file-backed clock. Nothing a test can do exists in the production entry point (Part 2c), because the production entry point
  never constructs a fake.
- (R2) restore and rollback of state: a missing state file with records present is refused (`state_lost`), a clock that moved backwards beyond
  5 seconds is refused on every mutating call including consume, and the spent marker is durable (Part 2d writes the remote tag; this engine
  records `moved` and refuses a second consume).
- (R3) there is no `--detail` and no consume/refuse/outcome CLI: those are internal steps of Part 2c's single `promote` call.
- (R5 shape) every engine call ends in one of three results: `ok`, `refused` (definitive, with a code), `unknown` (could not decide, with a
  code), and the wire contract below maps `unknown` to exit 75 for every call site.
- (Astra) `busy` is `unknown` (75), not exit 4; `show` returns `reason`.
- (Fable) file-backed test clock, secrets never in argv (the engine runs no subprocess), vector derivations kept.

## Behaviour

"Now" is whole UTC seconds from the injected clock. All paths are exact.

**A. Construction (no environment)**

1. Module `scripts/lib/hub_approval.py`. Imports allowed: `hashlib`, `hmac`, `json`, `os`, `re`, `secrets`, `struct`, `time`, `fcntl`, `base64`,
   `dataclasses`, `typing`. It contains no `subprocess`, no `os.environ`, no `os.getenv`, no `socket`: a test greps the source for them (N2, N6).
2. `Engine(state_dir, clock, totp_secret, operator_ids)`. `state_dir` must exist, be a directory owned by `os.geteuid()` with mode `0700`
   (`os.stat`); otherwise `Unknown("state_dir_unsafe")` on every call. `clock` is any object with `now() -> int`; the library ships
   `SystemClock` and `FileClock(path)` (reads one integer from the file each call; this is the test clock, and being a file it can be moved
   backwards by a test). `totp_secret` is the decoded bytes (at least 20). `operator_ids` is a frozenset of approver ids; each is
   `^[A-Z0-9]{2,32}$` (the Slack user id shape of `scripts/lib/hermes/approvals.py:16`) or the literal `cli`.
3. Files in `state_dir`, mode 0600: `<id>.json`, `serial`, `totp-state.json`, `clock-hw`, `rate.json`, `audit.jsonl` (append only), `.lock`.
   Each JSON file carries a `sum` key, the lowercase hex SHA-256 of the canonical JSON of the object without `sum`
   (`json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=True)`). A wrong or missing `sum`, extra keys, or a value outside the
   shapes below is `Refused("integrity")` for that file. This is corruption detection, not authentication; the directory permission is the
   protection and the spec says so.
4. Every write is `<name>.tmp` mode 0600, `fsync`, `os.replace`. Every read-modify-write holds `fcntl.flock(LOCK_EX | LOCK_NB)` on `.lock`,
   retried for at most 5 seconds; failing that `Unknown("busy")`.

**B. Results and the wire contract (one place, used by Parts 2c and 2b)**

5. Engine calls return a `dict` on ok and raise `Refused(code, message)` or `Unknown(code, message)`. `to_wire(call_result_or_exception)`
   produces one JSON object, one line, keys exactly: `v` (1), `result` (`ok`|`refused`|`unknown`), `code` (string, `ok` when ok), `message`
   (string, no secrets), `data` (object, possibly empty). The refusal codes are the closed set:
   `malformed_id`, `not_found`, `integrity`, `not_pending`, `not_approved`, `expired`, `clock_backwards`, `locked`, `nonce`, `approver`,
   `totp`, `too_many_codes`, `sha_mismatch`, `state_lost`, `rate_limited`, `bad_input`, and the mover codes owned by Part 2d which this
   engine only records: `not_contained`, `not_newest_branch`, `not_green`, `not_newest_green`, `release_moved`, `tag_exists`, `already_spent`, `deploy_moved`.
   The unknown codes are: `busy`, `state_dir_unsafe`, `lookup_failed`, `push_unknown`, `deadline`, `unreachable`, `protocol`.
6. Exit map, identical at every call site (the table below is the contract; Part 2c's client and Part 2b implement it, tests assert it):

   | result | client exit | meaning for the caller |
   |---|---|---|
   | `ok` | 0 | proceed |
   | `refused` | 1 | definitive no; do not retry the same request; the message says whether the approval is kept or spent |
   | usage / `bad_input` | 2 | caller error |
   | `unknown` (any code) or unreachable or protocol error | 75 | could not decide; the approval is kept; retry is safe |

**C. Record**

7. `<id>.json` keys exactly: `schema` (1), `id`, `sha` (40 or 64 lowercase hex), `branch` (`^k3d-manager-v[0-9]+\.[0-9]+\.[0-9]+$`),
   `nonce_sha256`, `channel` (`cloud-session`|`slack-alert`|`cli`), `requested_by` (1-64 chars of `[A-Za-z0-9._:@-]`), `created`, `expires`
   (`created + 900`), `state`, `approver` (null or string), `approved_at` (null or int), `totp_step` (null or int), `failed_attempts` (0-5),
   `reason` (null or a refusal code), `refusals` (int, count of recorded mover refusals), `old` (null or sha), `new` (null or sha), `tag`
   (null or string), `consumed_at` (null or int), `sum`.
8. `id` is `p<serial>-<8 lowercase hex>` where `<serial>` is the decimal value read and incremented under the lock from `serial` (starts at
   1) and the hex is `secrets.token_hex(4)`; the regex is `^p[0-9]+-[0-9a-f]{8}$`. It satisfies the relay's `^[rp][0-9]+-[0-9a-f]{8}$` once
   Part 3 widens the relay (`workers/slack-relay/index.js:4`, `scripts/lib/hermes/approvals.py:14`); today both accept only `r`. A malformed
   id, or one with `/`, `..` or NUL, is `Refused("malformed_id")` before any path is built. The nonce is `secrets.token_hex(8)`, 16 hex,
   matching `HERMES_NONCE_RE` (`workers/slack-relay/index.js:5`, `scripts/lib/hermes/approvals.py:15`); only its SHA-256 is stored.

**D. States**

9. States: `pending`, `approved`, `denied`, `expired`, `refused`, `consumed`. Legal moves: `pending -> approved|denied|expired|refused`;
   `approved -> consumed|refused|expired`; `consumed`, `denied`, `expired`, `refused` are final. A refusal from the mover (Part 2d) keeps the
   record `approved`: `note_refusal(id, code)` increments `refusals` and sets `reason`; it does not change state. Only a verified move
   consumes (`commit_moved`). Expiry is lazy: the first read at `now >= expires` of a non-final record writes `expired`.

**E. Clock and state-loss rules (R2, Astra)**

10. `clock-hw` stores the highest `now` ever seen. Every mutating call (`request`, `approve`, `deny`, `begin_promote`, `note_refusal`,
    `commit_moved`) first reads it under the lock: `now < hw - 5` is `Refused("clock_backwards")` and writes nothing; otherwise
    `hw = max(hw, now)`. This includes consume. A call inside the 5-second tolerance proceeds with `now` unchanged.
11. If any `<id>.json` exists but `serial`, `totp-state.json` or `clock-hw` is missing or fails its sum, every call except `show`
    returns `Refused("state_lost")` with the message `approval state was lost; re-enrol (Part 2c) before approving`. A fresh empty directory
    is initialised (`serial` 1, `hw` = now, `totp-state` zeroed) only when it holds no `<id>.json`.

**F. Calls**

12. `request(sha, branch, channel, requested_by) -> {id, nonce, expires}`. Rate limits under the lock, from `rate.json`: at most one
    non-final record per `sha` (a second returns `Refused("rate_limited")` naming the existing id), at most 3 requests per rolling hour,
    at most 5 non-final records in total. Validates every field (`bad_input`).
13. `show(id) -> {id, state, sha, branch, channel, requested_by, created, expires, approver, approved_at, reason, refusals, old, new, tag}`.
    It never returns `nonce_sha256`, `totp_step`, `sum`. A record that fails integrity returns `Refused("integrity")`.
14. `approve(id, nonce, approver, totp)` checks in this order, first failure wins, and the order is the contract: (1) id, read, sum;
    (2) state is `pending` (`not_pending`); (3) `now < expires`, else the record becomes `expired` and `expired`; (4) clock rule (E.10);
    (5) global lock `now < locked_until` is `locked`, counts nothing; (6) nonce equals (`hmac.compare_digest` of SHA-256), mismatch is
    `nonce` and counts toward the global throttle only; (7) `approver` is in `operator_ids`, else `approver`, global throttle only;
    (8) code: exactly six digits, RFC 6238 SHA-1, 30-second step, steps `t-1`, `t`, `t+1` with `t = now // 30`, matched step strictly
    greater than `last_step`; wrong, replayed or malformed is `totp`, adds 1 to `failed_attempts` and to the global count; the fifth
    failed code writes the record `refused` with `too_many_codes`.
15. Global throttle in `totp-state.json` (`last_step`, `fail_count`, `window_start`, `locked_until`): a counted failure first resets the
    count to 0 and `window_start` to `now` when `now - window_start >= 900`, then adds 1; reaching 10 sets `locked_until = now + 900`. A
    success clears the count. Success writes `totp-state` (`last_step` = the matched step) first and the record second, so a crash between
    them burns the code and leaves the record pending.
16. `deny(id, nonce, approver)`: checks 1-7 of `approve`, no code; writes `denied`.
17. `begin_promote(id, sha) -> {record}`: no state change except lazy expiry and the clock high-water. Refuses `not_approved` unless state is
    `approved`; `expired` when `now >= expires`; `sha_mismatch` when the given full sha differs from the record sha (nothing burned, so a
    same-user caller cannot spend an approval by sending a wrong sha); `integrity`; `state_lost`.
18. `note_refusal(id, code)`: `code` must be a mover refusal code from B.5, else `bad_input`; allowed only in `approved`.
19. `commit_moved(id, old, new, tag)`: allowed only in `approved` (or `consumed` with the same `old`, `new`, `tag`, which returns ok: idempotent
    repeat); writes `consumed`, `old`, `new`, `tag`, `consumed_at = now`. A second `commit_moved` with different values is
    `Refused("already_spent")`.
20. `rerun_view(id, sha) -> {record}` returns the record when it is `consumed`, `sha` equals the record `new`, and `now - approved_at <= 86400`;
    otherwise `Refused("not_approved")`. Part 2d uses it for the rerun path (R4).
21. Audit: every call appends one JSON line to `audit.jsonl` (`ts` ISO UTC, `event`, `id`, `sha7`, `channel`, `actor`, `result`, `code`),
    never a nonce, code, secret or message free text.

**G. TOTP**

22. `totp_code(secret, now)` is RFC 6238 SHA-1, 6 digits, 30-second step. Vectors (secret `12345678901234567890`; the RFC Appendix B 8-digit
    values, whose last six digits are the 6-digit codes): t=59 gives 287082; t=1111111109 gives 081804; t=1111111111 gives 050471;
    t=1234567890 gives 005924; t=2000000000 gives 279037; t=20000000000 gives 353130. (Re-derived with `hmac` and `hashlib` on m4-air,
    2026-11-18, Python 3.13.6: the 8-digit values are 94287082, 07081804, 14050471, 89005924, 69279037, 65353130.)
