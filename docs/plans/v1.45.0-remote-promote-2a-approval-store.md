## Problem

Under O2, any process running as the operator is an attacker at runtime. So the operator account cannot hold the approval store, its
key or a test switch. This part is only the engine: the state machine, the TOTP check, the check value, the throttles and the clock
rules. It is a pure Python library whose caller hands it the state directory, the clock and the secrets, and it holds no authority by
itself. Part 2c runs it as root, where the operator cannot read the state directory. The directory permission is the protection; a
plain checksum only detects corruption.

**O3** (umbrella): O2 applies at runtime only. Enrolment, reset and install are trusted operator-watched steps owned by Part 2c and
listed there as named residuals. This engine adds the residuals R2a-1 to R2a-5 below.

**K2a** (operator, 2026-11-19): the card shows a 4-character check value derived from the record id and sha. `approve` needs the TOTP
code and that value, and the matched TOTP step must be later than the step the record was created in. Behaviour F.16 and G.20 specify
it. v3's claim that one pending record limits a diverted code to "the record the operator was shown" was false (Fable M1) and is
removed; R2a-2 states what K2a does and does not bind.

**K4** (operator, after round 4, 2026-11-19): the Slack relay Worker signs the approval it received, HMAC-SHA256 over the canonical
`{id, nonce, approver, check, totp, at}`, with a key that exists only as a Worker secret and in a root-only file on the hub (Part 2c
provisions it and passes its bytes as `relay_key`). Hermes and the client forward the signed envelope unchanged. This engine refuses an
approval whose signature does not verify, before TOTP, the check value and the nonce (F.16a, G.20 steps 0a and 0b). It closes R4-B2 /
Astra round-4 blocker 1: a same-user process that reads the code in transit cannot resubmit it with another record's id or public
check. R2a-5 states what the signature gives and what it does not.

## Behaviour

"Now" is whole UTC seconds from the injected clock. All paths are exact.

**A. Construction (no environment)**

1. **Module.** The module is `scripts/lib/hub_approval.py`. Allowed imports: `base64`, `dataclasses`, `fcntl`, `hashlib`, `hmac`, `json`,
   `os`, `re`, `secrets`, `struct`, `time`, `typing`.
   - `hmac` and `hashlib` serve the TOTP (F.15), the check value (F.16) and, from v5, the envelope signature (`approval_mac`, F.16a,
     with `hmac.compare_digest` for the compare). No other import is added for K4.
   - It contains no `subprocess`, no `os.environ`, no `os.getenv` and no `socket`. A test greps the source for them (N6).
   - It runs on Python 3.9: no `X | Y` annotations evaluated at runtime, no `match`, no `str.removeprefix`. The hub's `/usr/bin/python3`
     is 3.9.6 (m4-air probe below); CI runs Linux Python 3.12 (`.github/workflows/ci.yml:163-217`). Every test runs on both.
2. **Constructor:** `Engine(state_dir, clock, totp_secret, operator_ids, relay_key)` (v5: `relay_key` added, K4).
   - **`state_dir`** must exist and be a directory owned by `os.geteuid()` with mode `0700` (`os.stat`). Otherwise every call raises
     `Unknown("state_dir_unsafe")`.
   - **`clock`** is any object with `now() -> int`. The library ships `SystemClock` and `FileClock(path)`. `FileClock` reads one integer
     from the file on each call; it is the test clock, and a test can move it backwards.
   - **`totp_secret`** is the decoded bytes, at least 20 of them, or `None`. With `None` the engine serves `show` only; every other call
     raises `Unknown("unconfigured")`. This is the state Part 2c runs before enrol (2c C.9); it replaces v3's "the engine never raises
     it".
   - **`operator_ids`** is a frozenset. Each id matches `^[A-Z0-9]{2,32}$` (the Slack user id shape at
     `scripts/lib/hermes/approvals.py:16`) or is the literal `cli`.
   - **`relay_key`** (v5, K4) is `bytes` or `None`. Part 2c passes the 32 bytes decoded from its root-only key file (2c C.10) and reads
     the file on every request. With `None` the engine is unconfigured exactly as with `totp_secret` `None`: it serves `show` only and
     every other call raises `Unknown("unconfigured")` (E.2).
3. **Files in `state_dir`.** All are mode 0600. The per-file contract (v4, Astra major; Fable minor):

   | file | content, exact keys | created | written by | write method |
   |---|---|---|---|---|
   | `<id>.json` | the record, C.7 | `request` | `request`, `approve`, `deny`, lazy expiry, `authorize_push`, `note_refusal`, `commit_moved`, `finish_unmoved` | replace |
   | `serial.json` | `{"next": int >= 1, "sum": hex}` | initialisation | `request` | replace |
   | `totp-state.json` | `{"last_step": int >= 0, "fail_count": 0-10, "window_start": int >= 0, "locked_until": int >= 0, "sum": hex}` | initialisation (all zero) | `approve` | replace |
   | `clock-hw.json` | `{"hw": int >= 0, "sum": hex}` | initialisation (`hw` = now) | any call that writes another state file, first | replace |
   | `audit.jsonl` | one JSON object per line, E.14 | first audited call | every locked call | append |
   | `audit.1.jsonl` | the previous audit file | first rotation | rotation only | rename |
   | `.lock` | empty | first locked call | never written | `open(O_CREAT)` |

   - **State files** are the four JSON kinds above. `audit.jsonl`, `audit.1.jsonl` and `.lock` are not state files: no `sum`, never read
     for a decision, and a rule that says "no state file is written" still allows the one audit line.
   - Each state file carries a `sum` key: the lowercase hex SHA-256 of the canonical JSON of the object without `sum`
     (`json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=True)`).
   - Any of these makes that file `Refused("integrity")`: a wrong or missing `sum`, extra or missing keys, a value outside the shapes in
     the table or in C.7 (checked after the sum, so a file with a recomputed sum and a bad value still fails), or a record whose `id`
     differs from its filename stem.
   - This is corruption detection, not authentication. The directory permission (Part 2c) is the protection.
   - **Initialisation.** A locked call that finds no `<id>.json` and any of the three singletons missing treats them as their initial
     values (`serial.json` `next` 1, `totp-state.json` all zero, `clock-hw.json` `hw` = now) and writes the missing ones only if the call
     writes state: they are the first replaces of its write phase, after its audit append (A.4). A call refused before it writes state
     (`bad_input`, `signature`, `envelope_stale`, or any other refusal that leaves state unchanged, M18) initialises nothing, so a forged or
     stale first approval leaves the directory without singletons. (Clarified 2026-11-19 after the worker stopped on the conflict.) With any record present, a
     missing or corrupt singleton is E.12 state loss, never re-initialised.
4. **Writes.**
   - **Replace:** write `<name>.tmp` (mode 0600), `fsync`, `os.replace`, then `fsync` of the directory file descriptor.
   - **Append:** `os.open(audit.jsonl, O_WRONLY|O_APPEND|O_CREAT, 0o600)`, one `write` of the whole line, `fsync`. Before the append, if
     `audit.jsonl` is larger than 1 048 576 bytes, it is renamed over `audit.1.jsonl` first. Total audit size is therefore at most about
     2 MiB (Astra major, retention).
   - **Order inside one call:** the call computes its whole outcome, appends its audit line, then performs its replaces in the order the
     call states. An `OSError` on the append raises `Unknown("io")` with no state written. An `OSError` on a replace raises
     `Unknown("io")`; the audit line then records a decision that may not be in state, and `show` is authoritative.
   - **Lock:** every call except `show` takes `fcntl.flock(LOCK_EX | LOCK_NB)` on `.lock`, retried every 50 ms for at most 5 seconds; if
     the lock is still unavailable the call raises `Unknown("busy")`.

**B. Results and the wire contract (one place, used by Parts 2c, 2d and 2b)**

5. **Results.** Engine calls return a `dict` on ok, or raise `Refused(code, message, approval)` or `Unknown(code, message)`.
   - `approval` is `kept` when the record is `pending` or `approved` after the call. It is `final` when the record is in a final state
     after the call, or there is no record. The engine computes it from the record it just wrote or read; callers never infer it from the
     code.
   - **Exception (v5, K4):** `signature` and `envelope_stale` are decided before the record is read (E, step 6a), so they always carry
     `approval` `kept`, whether or not the id exists: the refusal changed nothing, and the reply tells an unsigned caller nothing about
     records.
   - `to_wire(result_or_exception)` produces one JSON object on one line, with exactly these keys: `v` (1), `result`
     (`ok`|`refused`|`unknown`), `code` (`ok` when ok), `message` (no secrets), `data` (an object; on `refused` it holds exactly
     `{"approval": "kept"|"final"}`; on `unknown` it is `{}`; on ok it is the call's return value).
   - Closed set of refusal codes:
     - engine codes: `malformed_id`, `not_found`, `integrity`, `not_pending`, `not_approved`, `expired`, `clock_backwards`, `locked`,
       `nonce`, `approver`, `check`, `early_code`, `totp`, `too_many_codes`, `sha_mismatch`, `already_spent`, `state_lost`,
       `rate_limited`, `bad_input`, `signature`, `envelope_stale` (the last two new in v5, raised only by `approve`, G.20 steps 0a and
       0b; both exit 1 under B.6, both uncounted);
     - mover codes owned by Part 2d, which this engine only records through `note_refusal`: `not_contained`, `not_newest_branch`,
       `not_green`, `not_newest_green`, `release_moved`, `tag_exists`, `deploy_moved`, `witness_conflict`. `already_spent` is an engine
       code raised by `commit_moved` (G.25) that the mover may also report (2d B.6); it is not accepted by `note_refusal`.
   - Unknown codes: `busy`, `io`, `state_dir_unsafe`, `unconfigured`, and the transport and mover codes `lookup_failed`, `push_unknown`,
     `deadline`, `unreachable`, `protocol`, which the engine never raises.
6. **Exit map.** This table is the contract. Every call site uses it; Part 2c's client and Part 2b implement it, and tests assert it.

   | result | client exit | meaning for the caller |
   |---|---|---|
   | `ok` | 0 | proceed |
   | `refused`, code `bad_input` | 2 | caller error (also every usage error) |
   | `refused`, any other code | 1 | definitive no; do not retry the same request; `data.approval` says `kept` or `final` |
   | `unknown` (any code), unreachable, or protocol error | 75 | the caller does not know the outcome: the call may not have run, or it ran and the reply was lost. A retry is safe (repeats are refused or idempotent, never a second move); `show` reports the current state. |

   v3 said "the approval is kept" for 75. That was false after a lost reply that followed a commit (Astra major); the row now says what
   is known.

**C. Record**

7. **`<id>.json` keys, exactly:**
   - **identity and request:** `schema` (1); `id`; `sha` (40 or 64 lowercase hex); `branch`
     (`^k3d-manager-v[0-9]+\.[0-9]+\.[0-9]+$`); `nonce_sha256` (64 hex); `channel` (`cloud-session`|`slack-alert`|`cli`);
     `requested_by` (1-64 chars of `[A-Za-z0-9._:@-]`); `created` (int); `expires` (`created + 900`); `state`;
   - **approval:** `approver` (null or an `operator_ids` shape); `approved_at` (null or int); `totp_step` (null or int);
     `failed_attempts` (0-5);
   - **mover outcome:** `reason` (null or a refusal code); `refusals` (int >= 0); `push_at` (null or int); `old`, `new` (null or 40/64
     hex); `tag` (null or `^hub-promote/[0-9]{8}T[0-9]{6}Z$`); `consumed_at` (null or int); `attempt` (null, or exactly
     `{"tag", "object", "old"}` with the tag regex and 40/64 hex, written by G.23 and cleared with `push_at`);
   - **checksum:** `sum`.
8. **Id and nonce format.**
   - **Id:** `p<serial>-<8 lowercase hex>`. `<serial>` is `serial.json` `next`, read and incremented under the lock. The hex is
     `secrets.token_hex(4)`. The id regex is `^p[0-9]+-[0-9a-f]{8}$`.
   - **Relay compatibility:** the id satisfies the relay's `^[rp][0-9]+-[0-9a-f]{8}$` once Part 3 widens the relay
     (`workers/slack-relay/index.js:4`, `scripts/lib/hermes/approvals.py:14`); today both accept only `r`.
   - **Path safety:** a malformed id, or one containing `/`, `..` or NUL, is `Refused("malformed_id")` before any path is built.
   - **Nonce:** `secrets.token_hex(8)`, 16 hex, matching `HERMES_NONCE_RE` (`workers/slack-relay/index.js:5`,
     `scripts/lib/hermes/approvals.py:15`). Only its SHA-256 is stored.

**D. States**

9. **States:** `pending`, `approved`, `denied`, `expired`, `refused`, `consumed`.
   - Legal moves: `pending -> approved|denied|expired|refused`; `approved -> consumed|refused|expired|denied`. `consumed`, `denied`,
     `expired` and `refused` are final.
   - `approved -> denied` is new in v4 (Fable minor): `deny` revokes an approval given by mistake, only while `push_at` is null.
   - A refusal from the mover keeps the record `approved` (G.24).
   - **Effective state.** A non-final record with `push_at` null and `now >= expires` is effectively `expired`. Every locked call that
     reads a record, including every record `request` counts (G.18), writes `expired` for it (lazy expiry). `show` reports the effective
     state and writes nothing.
   - **Refusals that write nothing win over lazy expiry** (clarified 2026-11-19). A call whose refusal must leave every state file
     byte-identical writes no lazy expiry either. Those refusals are `sha_mismatch` from `begin_promote` and `commit_moved` (N4), and
     `bad_input`, `signature` and `envelope_stale` (M18). The `sha_mismatch` check therefore runs before lazy expiry, and a due record
     read by such a call stays as it is on disk until the next locked call that does not end in one of those refusals. A refusal of
     `expired` itself still writes `expired` (as below).
   - **Expiry with a recorded push.** A record whose `push_at` is set is never expired lazily. It leaves `approved` only through
     `commit_moved`, `note_refusal` (which clears `push_at`, after which expiry applies again) or `finish_unmoved`.

**E. One precedence for every call**

Every call except `show` runs these steps in this order, and the first failure wins:

1. `state_dir` check, else `Unknown("state_dir_unsafe")`. No write, no audit.
2. Configured check (`totp_secret` and, from v5, `relay_key` both not `None`), else `Unknown("unconfigured")`. No write, no audit.
3. Input shapes (`malformed_id`, `bad_input`). No write, no audit. For `approve` (v5, K4) every one of the seven arguments must be a
   `str` and: `id` the C.8 id regex (`malformed_id` otherwise, as for every call); `nonce` `^[0-9a-f]{16}$`; `approver`
   `^[A-Z0-9]{2,32}$` or `cli`; `check` `^[0-9A-Za-z]{4}$`; `totp` 1 to 16 printable ASCII characters without space (so a code that is
   merely not six digits passes this step and is refused, counted, at G.20 step 7 only after the signature verified); `at`
   `^[0-9]{10}$`; `sig` any string (a `sig` that is not 64 lowercase hex is refused `signature` at step 6a, not `bad_input`). Any other
   failure is `bad_input`, uncounted.
4. Lock, else `Unknown("busy")`. No write, no audit. From here on, every call appends exactly one audit line before it returns (E.14).
5. Initialisation or state loss (A.3, E.12), else `Refused("state_lost")`.
6. Clock rule (E.11), else `Refused("clock_backwards")`. No state file is written.
6a. **`approve` only (v5, K4):** the envelope signature, then its freshness (G.20 steps 0a and 0b), else `Refused("signature")` or
   `Refused("envelope_stale")`. No state file is written, nothing is counted, `data.approval` is `kept` (B.5 exception), and the audit
   line carries `sha7` null because no record has been read. This step runs before the record read so the reply is the same whether or
   not the id exists.
7. Record read: `not_found`, then `integrity` (including the id and filename binding).
8. The call's own checks (Behaviour G), in the order listed there. Lazy expiry is applied here, never earlier, so a rolled-back clock is
   always refused at step 6 before expiry can be decided.

`show` runs steps 1, 3 and 7 only, takes no lock and writes nothing, not even an audit line (v4: Astra and Fable found v3's "show never
writes" contradicted by "every locked call audits"; `show` is no longer a locked call).

11. **Clock high-water.** `clock-hw.json` `hw` is the highest `now` ever recorded. A call refuses with `clock_backwards` when
    `now < hw - 5`. Otherwise it proceeds with `now` as given, and writes `hw = max(hw, now)` only when its outcome writes another state
    file (and then as its first replace). A refused call that writes no state, such as `sha_mismatch`, leaves `clock-hw.json`
    byte-identical (v4: Astra major).
12. **State loss.** If any `<id>.json` exists but `serial.json`, `totp-state.json` or `clock-hw.json` is missing or fails A.3, every call
    except `show` returns `Refused("state_lost")`, with the message `approval state was lost; re-enrol (Part 2c) before approving`.
13. **Rate limits** are computed under the lock from the records' effective state (D.9); there is no separate rate file. Records are
    never deleted by the engine.
14. **Audit.** Each locked call appends one JSON line with exactly the keys `ts` (ISO UTC, `YYYY-MM-DDTHH:MM:SSZ`), `event` (the call
    name), `id` (the id or null), `sha7` (first 7 hex of the record sha, or of the `sha` argument when there is no record, or null),
    `channel` (or null), `actor` (`approver` or `requested_by` argument, or null), `result` and `code`. It never holds a nonce, a code, a
    check value, the secret, the relay key, the `sig` (v5), or message free text. A refusal is audited like a success.

**F. TOTP and the check value**

15. **`totp_code(secret, now)`.** RFC 6238 SHA-1, 6 digits, 30-second step.
    - Vectors, for secret `12345678901234567890` (the RFC Appendix B 8-digit values; the last six digits are the 6-digit codes):

      | t | code |
      |---|---|
      | 59 | 287082 |
      | 1111111109 | 081804 |
      | 1111111111 | 050471 |
      | 1234567890 | 005924 |
      | 2000000000 | 279037 |
      | 20000000000 | 353130 |

    - Re-derived with `hmac` and `hashlib` on m4-air, 2026-11-18, Python 3.13.6 and `/usr/bin/python3` 3.9.6; re-confirmed by Fable's
      round-3 probe 10.
    - **Delivery deadline (v5, Astra round-4 finding 12).** The deadline is measured from the matched step, not a flat 60 s. With steps
      `t-1`, `t` and `t+1` accepted (G.20 step 7), a code generated in step `s` is accepted while `now // 30 <= s + 1`, that is until
      `30 * (s + 2)` seconds; at `now = 30 * (s + 2)` it is refused `totp` (counted). If the phone and hub clocks agree, that is between
      30 s (code typed in the last second of its step) and 60 s (typed in the first second) after it was typed. The operator is told to
      wait for the next code when fewer than 10 s remain on the current one (the instruction text is Part 3's card only; the
      engine only enforces the window). A code typed during the record's creation step (`created // 30`) is refused `early_code`
      and counts as a failure (G.20 step 8), so the card also tells the operator not to use the code shown while the request was
      being created. The envelope freshness window (G.20 step 0b, 300 s back) is wider than any code's life, so the
      code window is the binding deadline. M17 and E8 test a code typed in the last second of its step.
16. **`check_value(id, sha)` (K2a).**
    - `d = sha256(("k3dm-promote-check:v1\n" + id + "\n" + sha).encode("ascii")).digest()`; `n = int.from_bytes(d[:3], "big") >> 4`
      (the first 20 bits); the value is four characters, most significant first, each `ALPHABET[(n >> (15 - 5*k)) & 31]` for k = 0..3,
      with `ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"` (Crockford base32: no I, L, O, U).
    - Vectors (m4-air, 2026-11-19, Python 3.13.6 and `/usr/bin/python3 -I` 3.9.6 agree on the first):

      | id | sha | check |
      |---|---|---|
      | `p1-0123abcd` | `a` x 40 | `03Q1` |
      | `p1-0123abcd` | `b` x 40 | `KTR0` |
      | `p2-0123abcd` | `a` x 40 | `CJ9W` |
      | `p7-deadbeef` | `0123456789abcdef0123456789abcdef01234567` | `N4ES` |

    - **Input form.** `approve` accepts the value case-insensitively, after stripping nothing: it must match `^[0-9A-Za-z]{4}$`
      (otherwise `bad_input`), is upper-cased, and is compared with `hmac.compare_digest`.
    - **What it is.** It is not a secret: anyone who knows the id and sha can compute it, and `show` returns it (G.19) so the card can show
      it. It makes the operator's typed entry name one (id, sha) pair, so an entry made from one card cannot approve a different record
      or a different sha, and a stale or swapped card is refused. R2a-2 states the limit. From v5 the value the operator typed is also
      inside the relay signature (F.16a), so a same-user process cannot replace it in transit.
16a. **`approval_mac(key, id, nonce, approver, check, totp, at) -> str` (v5, K4).** A pure module-level helper used by `approve` and by
    the tests.
    - **Canonical bytes:** `b"k3dm-promote-approve:v1\n" + id + b"\n" + nonce + b"\n" + approver + b"\n" + check + b"\n" + totp + b"\n" + at + b"\n"`,
      ASCII, fields in exactly that order, each field the exact string carried in the envelope (no case folding, no trimming). The
      result is the lowercase hex of HMAC-SHA256(key, canonical bytes), 64 characters.
    - **Test vector** (key = the 32 bytes 0x00..0x1f; nonce `00112233aabbccdd`; approver `U0123ABCD`; totp `287082`; at
      `1700000059`):

      | id | check | key | sig |
      |---|---|---|---|
      | `p1-0123abcd` | `03Q1` | 0x00..0x1f | `5f45ca7b5b3724c6b0d50e0600af206effbb5669d2fb86b530d9ba913d5d572e` |
      | `p2-0123abcd` | `03Q1` | 0x00..0x1f | `799b39e7ee50769fe1347bd35435fb5fb31f40f696d1b2ca7ea149a6ad21c2ce` |
      | `p1-0123abcd` | `KTR0` | 0x00..0x1f | `4f306c720a47babf86b68f8123e0ef11c3801dd9b25852a4a33987ea7ca54d87` |
      | `p1-0123abcd` | `03Q1` | 32 zero bytes | `88c6897a91018fc0411e238afab1caca540e211888c55d6a3bb72c0bdf905626` |

    - Probed on m4-air, 2026-11-19, with Python 3.13.6, `/usr/bin/python3 -I` 3.9.6 and node v26.13.1 WebCrypto (the Worker's
      `crypto.subtle.sign('HMAC')`, `workers/slack-relay/index.js:183-187`); all three agree. Re-run for this spec with
      `/usr/bin/python3 -I` 3.9.6 on 2026-11-19: same four values.
    - The signer (the Worker, Part 3b) upper-cases `check` before signing. The engine MACs the bytes it received, and afterwards compares
      `check` case-insensitively as in F.16.
17. **Global throttle.** `totp-state.json` holds `last_step`, `fail_count`, `window_start` and `locked_until`. Only a wrong check value, an
    early code, or a wrong, replayed or malformed code counts. Nonce and approver mismatches do not count: a 64-bit nonce cannot be
    guessed within the request rate, and not counting them removes an easy lockout. `signature` and `envelope_stale` (v5) do not count
    either: an unsigned caller must not be able to spend the operator's failure budget, and a code is only ever counted after the
    signature over it verified.
    - A counted failure first resets `fail_count` to 0 and `window_start` to `now` when `now - window_start >= 900`, then adds 1.
    - Reaching 10 sets `locked_until = now + 900`.
    - A success clears `fail_count` (to 0) and leaves `window_start`.
    - Success replaces `clock-hw.json`, then `totp-state.json` (`last_step` = the matched step), then the record. A crash after
      `totp-state.json` burns the code and leaves the record pending (N7).
    - A counted failure replaces `clock-hw.json`, `totp-state.json`, then the record (`failed_attempts`).

**G. Calls** (each runs the E precedence first)

18. **`request(sha, branch, channel, requested_by) -> {id, nonce, expires, check}`.** It validates every field (`bad_input`). It applies
    lazy expiry to every record it counts and writes those records (Fable M2), then the rate limits:
    - at most one `pending` record in total; a second request returns `Refused("rate_limited")` naming the existing id;
    - at most one non-final record per `sha`;
    - at most 3 records created in the last 3600 s;
    - at most 5 non-final records in total. Records stuck with `push_at` set count as non-final, which makes this limit reachable.

    On success it replaces `clock-hw.json`, any lazily expired records, `serial.json`, then the new record.
19. **`show(id)`.** Returns exactly `{id, state, sha, branch, channel, requested_by, created, expires, check, approver, approved_at,
    reason, refusals, push_at, old, new, tag}` with `state` the effective state and `check` = `check_value(id, sha)`. It never returns
    `nonce_sha256`, `totp_step`, `failed_attempts` or `sum`.
20. **`approve(id, nonce, approver, totp, check, at, sig)`** (v5: `at` and `sig` added, K4). The seven arguments are the signed envelope
    exactly as Part 2c's daemon received it (2c F.17 wire; Part 3b signs). After E.1-E.6 and before the record read (E step 6a):
    0a. `sig` is 64 lowercase hex (`^[0-9a-f]{64}$`) and `hmac.compare_digest(sig, approval_mac(relay_key, id, nonce, approver, check,
        totp, at))` is true, else `signature`. The shape test comes first because `hmac.compare_digest` raises `TypeError` on a non-ASCII
        `str` (probe below). Uncounted: `failed_attempts`, `fail_count`, `window_start` and `locked_until` are unchanged and no state
        file is written; `data.approval` is `kept`; exit 1.
    0b. `now - 300 <= int(at) <= now + 120`, else `envelope_stale`. Uncounted, no state file, `kept`, exit 1.

    So the signature is verified before TOTP, the check value and the nonce. Then, after E.7, these checks in this order (unchanged from
    v4):
    1. state is `pending` (`not_pending`);
    2. `now < expires` (otherwise the record is lazily expired and the call refuses `expired`);
    3. `now < locked_until` refuses `locked`, counting nothing;
    4. the nonce is checked with `hmac.compare_digest` on the SHA-256 (`nonce`);
    5. `approver` is in `operator_ids` (`approver`);
    6. `check` equals `check_value(id, sha)` (`check`, counted);
    7. the code is exactly six digits and matches step `t-1`, `t` or `t+1` with `t = now // 30`, else `totp` (counted). The delivery
       deadline this implies is stated in F.15: a code of step `s` is accepted until `now = 30 * (s + 2) - 1`;
    8. the matched step `s` satisfies `s > created // 30`, else `early_code` (counted). A code generated in or before the step the record
       was created in can never approve it (K2a; Fable M1);
    9. `s > last_step`, else `totp` (replay, counted).

    A counted failure adds 1 to `failed_attempts` and to the global count; the fifth on one record writes it `refused` with
    `too_many_codes`. On success the record becomes `approved` with `approver`, `approved_at = now`, `totp_step = s`.
21. **`deny(id, nonce, approver)`.** Checks G.20.1 widened to `pending`, or `approved` with `push_at` null (`not_pending` otherwise), then
    G.20.2 for a pending record, then G.20.4 and G.20.5; then writes `denied`. It does not check `locked_until`: a deny can never move
    anything, and the operator must be able to clear a record during a lockout (Astra major, lockout breadth).
22. **`begin_promote(id, sha) -> {mode, record}`.** `sha` must equal the record's `sha` first; otherwise `sha_mismatch`, with no state file
    written. Then:
    - **`consumed`**: ok, with `mode: "consumed"` and the recorded `old`, `new`, `tag`. There is no time limit (v4: Astra major; the
      86 400 s limit cut off retries of pending Part 1 work, and a replay only reports recorded facts, never moves). Since
      `new == sha` always holds for a consumed record (G.25), no further sha check exists.
    - **`approved`** with `push_at` null: if `now >= expires`, the record is lazily expired and the call refuses `expired`. Otherwise ok,
      `mode: "fresh"`.
    - **`approved`** with `push_at` set: ok, `mode: "recover"` (v4: always recover, whether or not the TTL has passed; a set `push_at`
      means a push may have landed, so the mover must look for the witness first, 2d C.14 and D.16).
    - **Any other state:** `not_approved`.
23. **`authorize_push(id, sha, attempt) -> {push_at}`.** This is the authorization instant. The mover calls it through an opaque callable
    immediately before `git push` (Part 2d C.12).
    - It requires state `approved`, `push_at` null, `sha` equal to the record's `sha`, and `now < expires`.
    - `attempt` is `{"tag": str, "object": hex, "old": hex}` (tag regex C.7, object 40 or 64 hex, old 40 or 64 hex). It writes
      `push_at = now` and stores `attempt` in the record under the new key `attempt` (C.7 gains `attempt`: null or that object), so a
      restart can compare the exact tag object (2d C.14; Astra major).
    - When `now >= expires`, it refuses `expired` and lazily expires the record.
24. **`note_refusal(id, code)`.** `code` must be a mover refusal code from B.5 (not `already_spent`, not `bad_input`); otherwise
    `bad_input`. It is allowed only in `approved`. It increments `refusals`, sets `reason`, clears `push_at` and `attempt`, because a mover
    refusal is a definite non-move.
25. **`commit_moved(id, old, new, tag)`.**
    - It checks, in order: `new` equals the record's `sha` (`sha_mismatch`); then the state.
    - On `approved` with `push_at` set, whether or not the TTL has passed: writes `consumed`, `old`, `new`, `tag`, `consumed_at = now`.
    - On `consumed`: the same `old` and `tag` return ok (an idempotent repeat); a different `old` or `tag` returns
      `Refused("already_spent")`. A different `new` never reaches this branch: it is `sha_mismatch` (v4: Astra major, one code per case).
    - On `approved` with `push_at` null: `not_approved` (no witness can legitimately exist without a recorded push).
    - Any other state: `not_approved`.
26. **`finish_unmoved(id)`.** Allowed only in `approved` with `push_at` set. It writes `expired` when `now >= expires`, and otherwise
    clears `push_at` and `attempt` (the record stays `approved`, and a fresh attempt may follow). Part 2d's glue calls it in recover mode
    after a successful remote read shows no witness for the id.

## Residuals

- **R2a-1: lockout and request starvation.** A same-user process can make its own request, receive the nonce and send ten wrong codes
  across two records, which locks `approve` for 900 s. It can also hold the single `pending` slot (the operator cannot deny it without
  its nonce; it expires after 900 s) and use the 3-per-hour budget, so a determined process can keep the operator from approving for
  most of each hour. This is a denial of service, never a promote. It is stated, not fixed; the card names the unexpected pending id.
- **R2a-2: what K2a binds.** The check value and the step-after-created rule are verified by the engine; the check value is not a
  secret. Before v5 a same-user process that diverted the operator's whole approve message could recompute the check value for a record
  it created and replace it (R4-B2). From v5 the id, check and code are inside the relay signature (R2a-5), so that replacement is
  refused `signature`; K2a remains the defence against a mistyped or stale card. The step rule bounds when the record can have been
  created relative to the code: its record must exist no later than the step of the operator's code. Because step `t+1` is accepted
  (G.20 step 7), a phone up to one step (30 s) ahead of the hub produces a code whose step is one above the hub's own; a record created on
  the hub up to about 30 s after the operator generated the code (hub time) can then still satisfy `s > created // 30` (Fable round-4
  minor 6). The rule is therefore "created no later than one step after the code was generated", not "created before it". The operator's
  card (which shows the record id, the sha and the check value) is the swapped one only if the process denied and replaced the record
  before the card was shown. Part 3 sends the card from the record `show` returns, so the card and the record agree. A commit the
  attacker pushed to the newest release branch is approved if the operator approves its card without reading the sha (R2d-2 in Part 2d).
- **R2a-3: state reset.** After a reset (Part 2c, a trusted O3 step) the clock high-water restarts at `now`, and serials restart at 1. A
  reused id that collides with an old remote witness fails closed in Part 2d (`witness_conflict`).
- **R2a-4: the approver is asserted.** `approver` is a caller-supplied string checked against `operator_ids`; the TOTP code and the
  check value are the only factors (Fable minor). The audit records the asserted id. From v5 `approver` is inside the relay signature
  (R2a-5): the Worker signs the Slack user who pressed the button and typed `/hermes-totp`, so a hub process cannot change it in transit.
- **R2a-5: what the relay signature gives (v5, K4; replaces the R4-B2 gap).** A same-user hub process can read a genuine envelope in
  transit but cannot produce a valid `sig` for another id, check, nonce, approver, code or time. Swapping the id or the check of a
  genuine envelope is refused `signature`. A stale card: the envelope names the id on the card the operator read; if that record was
  denied, expired or replaced by a new record, the genuine envelope is refused `not_pending` (or `expired`) and the newer record is never
  approved by it. Residuals:
  - (a) Replaying a genuine envelope whose code was wrong adds counted failures to that one record. This is denial of service only,
    bounded by the 5-failure refusal per record and the global lockout already accepted after round 4 (R2a-1). Replaying a genuine
    successful envelope is refused `not_pending`.
  - (b) The key is as strong as the Worker secret store and the root-only key file (Part 2c). A leak of either reduces the path to v4
    strength (TOTP plus check value).
  - (c) `deny` is unchanged and unsigned (`id, nonce, approver`). A forged deny can only stop a promote, a denial of service that a
    same-user process already has (R2a-1).
  - (d) Channel `cli` (TTY promote, Part 2c H.23 follow-up spec): an `approve` without a valid `sig` is refused whatever the channel.
    Until the follow-up spec defines a locally authenticated path, a `cli` record is approved through the same Slack card and
    `/hermes-totp` path. This is not a new operator question: the follow-up spec is already decided (umbrella Decision 8).

## Worker definition of done

1. **Red first, reported in two columns.** Every must and must_not has a pytest test.
   - Column 1, pre-fix: the named pre-fix command at the head of Acceptance, run on the pre-fix base, exits 2 (collection error on the
     missing module). Report the base sha, the exact command and the rc as the `pre_fix_*` triple; it proves nothing about a protection.
     The test file must import `hub_approval` at module level so this red is a collection error, not a skipped test.
   - Column 2, mutants: for each must_not, apply every mutant named in the `N<k>: mutant` list at the head of Acceptance to the finished
     module, show the named test red, then revert.
   - Each must_not test includes its positive control, and the control passes on the finished module.
2. **Fixtures assert their target first:** a `tmp_path` directory chmod 0700, a `FileClock` file, no real HOME.
3. **Both Pythons.** `make test-pytest` passes, and the test file also passes under `/usr/bin/python3` 3.9 on macOS. Name the
   interpreter in the hand-off.
4. **Module limits.** No network, no subprocess, no Keychain, no environment reads in the module.

## What NOT to do

- No CLI, no daemon, no socket, no Git, no GitHub. Those are Parts 2c and 2d.
- No test mode, no sentinel, no environment variable of any kind.
- Do not print or log the nonce, the code, the check value or the secret.
- Do not delete records.
