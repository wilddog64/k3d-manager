## Problem

Under O2, any process running as the operator is an attacker at runtime. So the operator account cannot hold the approval store, its
key or a test switch. This part is only the engine: the state machine, the TOTP check, the throttles and the clock rules. It is a pure
Python library whose caller hands it the state directory, the clock and the secrets, and it holds no authority by itself. Part 2c runs it
as root, where the operator cannot read the state directory. The directory permission is the protection; a plain checksum only detects
corruption.

**O3** (umbrella): O2 applies at runtime only. Enrolment, reset and install are trusted operator-watched steps owned by Part 2c and listed
there as named residuals. This engine adds one residual of its own, R2a-1 below.

Round 2 found these problems in v2. Each is fixed below:

- **Expiry was checked too early, and a passed promote could not commit after the TTL** (umbrella agreed defect; Astra 4; Fable 15).
  - The authorization instant is now `authorize_push`, called by the mover immediately before the push (G.21).
  - The attempted push is persisted as `push_at`.
  - A record with `push_at` set never expires lazily. It can only be committed, refused, or closed by `finish_unmoved` after the remote
    shows no move.
- **The check order conflicted:** E.10 put the clock first, F.14 put it fourth. There is now one precedence for every call (Behaviour E).
- **The audit rules conflicted:** "every call audits" against N4's "audit unchanged". The rule is now one line per locked call, refusals
  included (E.13), and N4 is rewritten.
- **Routing for a consumed record was undefined.** `begin_promote` now returns `mode: consumed` with the recorded move (G.20). Part 2d's
  glue serves that without a remote call.
- **Forgery cannot be denied inside a writable fixture** (Astra 10). N1 is now corruption detection only. Forgery denial is an OS-boundary
  test in Part 2c.
- **Smaller fixes:**
  - the record id is bound to its filename, and the move sha to the record sha;
  - directory fsync;
  - rate limits are derived from the records, so `rate.json` is gone;
  - `bad_input` exits 2;
  - Python 3.9 syntax;
  - Risk is now high.
- **S4 mitigation (Astra 3, Fable 4).** At most one `pending` record exists at a time. A code diverted in transit can then only approve
  the single record whose sha the operator was shown. It can no longer approve a parallel record the attacker created. The rest is
  residual R2a-2.

## Behaviour

"Now" is whole UTC seconds from the injected clock. All paths are exact.

**A. Construction (no environment)**

1. **Module.** The module is `scripts/lib/hub_approval.py`. Allowed imports: `base64`, `dataclasses`, `fcntl`, `hashlib`, `hmac`, `json`,
   `os`, `re`, `secrets`, `struct`, `time`, `typing`.
   - It contains no `subprocess`, no `os.environ`, no `os.getenv` and no `socket`. A test greps the source for them (N2, N6).
   - It runs on Python 3.9: no `X | Y` annotations evaluated at runtime, no `match`, no `str.removeprefix`-era assumptions beyond 3.9.
     The hub's `/usr/bin/python3` is 3.9.6; CI runs Linux Python 3.12 (`.github/workflows/ci.yml:163-217`).
   - Every test runs on both.
2. **Constructor:** `Engine(state_dir, clock, totp_secret, operator_ids)`.
   - **`state_dir`** must exist and be a directory owned by `os.geteuid()` with mode `0700` (`os.stat`). Otherwise every call raises
     `Unknown("state_dir_unsafe")`.
   - **`clock`** is any object with `now() -> int`. The library ships `SystemClock` and `FileClock(path)`. `FileClock` reads one integer
     from the file on each call; it is the test clock, and a test can move it backwards.
   - **`totp_secret`** is the decoded bytes, at least 20 of them.
   - **`operator_ids`** is a frozenset. Each id matches `^[A-Z0-9]{2,32}$` (the Slack user id shape at
     `scripts/lib/hermes/approvals.py:16`) or is the literal `cli`.
3. **Files in `state_dir`.** All are mode 0600: `<id>.json`, `serial`, `totp-state.json`, `clock-hw`, `audit.jsonl` (append only), `.lock`.
   - Each JSON file carries a `sum` key: the lowercase hex SHA-256 of the canonical JSON of the object without `sum`
     (`json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=True)`).
   - Any of these makes that file `Refused("integrity")`: a wrong or missing `sum`, extra or missing keys, a value outside the shapes below,
     or a record whose `id` differs from its filename stem.
   - This is corruption detection, not authentication. The directory permission (Part 2c) is the protection.
4. **Writes.** Every write goes to `<name>.tmp` (mode 0600), then `fsync`, then `os.replace`, then `fsync` of the directory file
   descriptor. Every call that reaches step E.3 holds `fcntl.flock(LOCK_EX | LOCK_NB)` on `.lock`, retried for at most 5 seconds; if the
   lock is still unavailable, the call raises `Unknown("busy")`.

**B. Results and the wire contract (one place, used by Parts 2c, 2d and 2b)**

5. **Results.** Engine calls return a `dict` on ok, or raise `Refused(code, message, approval)` or `Unknown(code, message)`.
   - `approval` is `kept` when the record is still `pending` or `approved` after the call. It is `final` when the record is in a final
     state or there is no record.
   - `to_wire(result_or_exception)` produces one JSON object on one line, with exactly these keys: `v` (1), `result`
     (`ok`|`refused`|`unknown`), `code` (`ok` when ok), `message` (no secrets), `data` (an object; on `refused` it holds
     `{"approval": "kept"|"final"}`).
   - Closed set of refusal codes:
     - engine codes: `malformed_id`, `not_found`, `integrity`, `not_pending`, `not_approved`, `expired`, `clock_backwards`, `locked`,
       `nonce`, `approver`, `totp`, `too_many_codes`, `sha_mismatch`, `state_lost`, `rate_limited`, `bad_input`;
     - mover codes owned by Part 2d, which this engine only records: `not_contained`, `not_newest_branch`, `not_green`,
       `not_newest_green`, `release_moved`, `tag_exists`, `already_spent`, `deploy_moved`, `witness_conflict`.
   - Unknown codes: `busy`, `state_dir_unsafe`, `lookup_failed`, `push_unknown`, `deadline`, `unreachable`, `protocol`, `unconfigured`
     (raised only by the Part 2c daemon before enrol, C.9; the engine never raises it).
6. **Exit map.** This table is the contract. Every call site uses it; Part 2c's client and Part 2b implement it, and tests assert it.

   | result | client exit | meaning for the caller |
   |---|---|---|
   | `ok` | 0 | proceed |
   | `refused`, code `bad_input` | 2 | caller error (also every usage error) |
   | `refused`, any other code | 1 | definitive no; do not retry the same request; `data.approval` says `kept` or `final` |
   | `unknown` (any code), unreachable, or protocol error | 75 | could not decide; the approval is kept; a retry is safe |

**C. Record**

7. **`<id>.json` keys, exactly:**
   - **identity and request:** `schema` (1); `id`; `sha` (40 or 64 lowercase hex); `branch`
     (`^k3d-manager-v[0-9]+\.[0-9]+\.[0-9]+$`); `nonce_sha256`; `channel` (`cloud-session`|`slack-alert`|`cli`); `requested_by` (1-64
     chars of `[A-Za-z0-9._:@-]`); `created`; `expires` (`created + 900`); `state`;
   - **approval:** `approver` (null or string); `approved_at` (null or int); `totp_step` (null or int); `failed_attempts` (0-5);
   - **mover outcome:** `reason` (null or a refusal code); `refusals` (int); `push_at` (null or int); `old`, `new` (null or sha); `tag`
     (null or string); `consumed_at` (null or int);
   - **checksum:** `sum`.
8. **Id and nonce format.**
   - **Id:** `p<serial>-<8 lowercase hex>`. `<serial>` is the decimal value read and incremented under the lock from `serial`, which
     starts at 1. The hex is `secrets.token_hex(4)`. The id regex is `^p[0-9]+-[0-9a-f]{8}$`.
   - **Relay compatibility:** the id satisfies the relay's `^[rp][0-9]+-[0-9a-f]{8}$` once Part 3 widens the relay
     (`workers/slack-relay/index.js:4`, `scripts/lib/hermes/approvals.py:14`); today both accept only `r`.
   - **Path safety:** a malformed id, or one containing `/`, `..` or NUL, is `Refused("malformed_id")` before any path is built.
   - **Nonce:** `secrets.token_hex(8)`, 16 hex, matching `HERMES_NONCE_RE` (`workers/slack-relay/index.js:5`,
     `scripts/lib/hermes/approvals.py:15`). Only its SHA-256 is stored.

**D. States**

9. **States:** `pending`, `approved`, `denied`, `expired`, `refused`, `consumed`.
   - Legal moves: `pending -> approved|denied|expired|refused` and `approved -> consumed|refused|expired`. `consumed`, `denied`, `expired`
     and `refused` are final.
   - A refusal from the mover keeps the record `approved` (G.22).
   - **Lazy expiry.** A mutating call that reads a non-final record writes `expired` when `now >= expires` and `push_at` is null.
   - **Expiry with a recorded push.** A record whose `push_at` is set is never expired lazily. It leaves `approved` only through
     `commit_moved`, `note_refusal` (which clears `push_at`, after which expiry applies again) or `finish_unmoved`.
   - `show` never writes: it reports `state: "expired"` when the lazy rule would apply.

**E. One precedence for every call (agreed defect; Fable 14; Astra 10)**

Every call runs these steps in this order, and the first failure wins:

1. `state_dir` check, else `Unknown("state_dir_unsafe")`. No write, no audit.
2. Input shapes (`malformed_id`, `bad_input`). No write, no audit.
3. Lock, else `Unknown("busy")`. No write, no audit. From here on, every call appends exactly one audit line before it returns (E.13).
4. State loss (E.11), else `Refused("state_lost")`. `show` skips this step.
5. Clock rule (E.10), else `Refused("clock_backwards")`. No state file is written. `show` skips this step.
6. Record read: `not_found`, then `integrity` (including the id and filename binding).
7. The call's own checks (Behaviour G), in the order listed there. Lazy expiry is applied here, never earlier, so a rolled-back clock is
   always refused at step 5 before expiry can be decided.

10. **Clock high-water.** `clock-hw` stores the highest `now` ever seen. A mutating call refuses with `clock_backwards` when
    `now < hw - 5`. Otherwise it sets `hw = max(hw, now)` and proceeds with `now` as given.
11. **State loss.** If any `<id>.json` exists but `serial`, `totp-state.json` or `clock-hw` is missing or fails its sum, every call except
    `show` returns `Refused("state_lost")`, with the message `approval state was lost; re-enrol (Part 2c) before approving`. A directory
    is initialised (`serial` 1, `hw` = now, `totp-state` zeroed) only when it holds no `<id>.json`.
12. **Rate limits.** Rate limits are computed from the records under the lock; there is no separate rate file to lose. Records are never
    deleted by the engine.
13. **Audit.** Each call appends one JSON line to `audit.jsonl`, with keys `ts` (ISO UTC), `event`, `id`, `sha7`, `channel`, `actor`,
    `result` and `code`. It never holds a nonce, a code, the secret, or message free text. A refusal is audited like a success; only
    steps 1-3 skip the audit.

**F. TOTP**

14. **`totp_code(secret, now)`.** RFC 6238 SHA-1, 6 digits, 30-second step.
    - Vectors, for secret `12345678901234567890`. They are the RFC Appendix B 8-digit values; the last six digits are the 6-digit codes.
      | t | code |
      |---|---|
      | 59 | 287082 |
      | 1111111109 | 081804 |
      | 1111111111 | 050471 |
      | 1234567890 | 005924 |
      | 2000000000 | 279037 |
      | 20000000000 | 353130 |
    - Re-derived with `hmac` and `hashlib` on m4-air, 2026-11-18, Python 3.13.6 and `/usr/bin/python3` 3.9.6. The 8-digit values are
      94287082, 07081804, 14050471, 89005924, 69279037 and 65353130.
15. **Global throttle.** It lives in `totp-state.json` as `last_step`, `fail_count`, `window_start` and `locked_until`. Only a wrong,
    replayed or malformed code counts. Nonce and approver mismatches do not count: a 64-bit nonce cannot be guessed within the request
    rate, and not counting them removes an easy lockout.
    - A counted failure first resets `fail_count` to 0 and `window_start` to `now` when `now - window_start >= 900`, then adds 1.
    - Reaching 10 sets `locked_until = now + 900`.
    - A success clears the count.
    - Success writes `totp-state` (`last_step` = the matched step) first and the record second. A crash between the two burns the code and
      leaves the record pending.

**G. Calls** (each runs the E precedence first)

16. **`request(sha, branch, channel, requested_by) -> {id, nonce, expires}`.** It validates every field (`bad_input`). Rate limits:
    - at most one `pending` record in total; a second request returns `Refused("rate_limited")` naming the existing id (S4 mitigation);
    - at most one non-final record per `sha`;
    - at most 3 records created in the last 3600 s;
    - at most 5 non-final records in total.

    Records stuck with `push_at` set count as non-final, which makes the total limit reachable.
17. **`show(id)`.** Returns `{id, state, sha, branch, channel, requested_by, created, expires, approver, approved_at, reason, refusals,
    push_at, old, new, tag}`. It never returns `nonce_sha256`, `totp_step` or `sum`.
18. **`approve(id, nonce, approver, totp)`.** Runs these checks after E.1-E.6, in this order:
    1. state is `pending` (`not_pending`);
    2. `now < expires` (otherwise the record is lazily expired and the call refuses `expired`);
    3. `now < locked_until` refuses `locked`, counting nothing;
    4. the nonce is checked with `hmac.compare_digest` on the SHA-256 (`nonce`);
    5. `approver` is in `operator_ids` (`approver`);
    6. the code is exactly six digits, matches step `t-1`, `t` or `t+1` with `t = now // 30`, and the matched step is strictly greater
       than `last_step`. Otherwise the call refuses `totp`, adds 1 to `failed_attempts` and to the global count. The fifth failure on one
       record writes it `refused` with `too_many_codes`.
19. **`deny(id, nonce, approver)`.** Checks 1-5 of G.18, then writes `denied`.
20. **`begin_promote(id, sha) -> {mode, record}`.** `sha` must equal the record's `sha`; otherwise `sha_mismatch`, with nothing written
    except the audit line. Then:
    - **`consumed`** and `sha == new` and `now - consumed_at <= 86400`: ok, with `mode: "consumed"` and the recorded `old`, `new`, `tag`.
      This is the consumed routing. Otherwise a consumed record refuses `not_approved`.
    - **`approved`** with `push_at` null: if `now >= expires`, the record is lazily expired and the call refuses `expired`. Otherwise ok,
      `mode: "fresh"`.
    - **`approved`** with `push_at` set: ok. The mode is `"fresh"` when `now < expires`, and `"recover"` otherwise. In recover mode the
      caller may only look for a witness; `authorize_push` will refuse.
    - **Any other state:** `not_approved`.
21. **`authorize_push(id, sha) -> {push_at}`.** This is the authorization instant. The mover calls it through an opaque callable
    immediately before `git push` (Part 2d C.12).
    - It requires state `approved`, `sha` equal to the record's `sha`, and `now < expires`.
    - It writes `push_at = now`, then returns.
    - When `now >= expires`, it refuses `expired`; the record is lazily expired only when `push_at` is null.
22. **`note_refusal(id, code)`.** `code` must be a mover refusal code from B.5; otherwise `bad_input`. It is allowed only in `approved`.
    It increments `refusals`, sets `reason` and clears `push_at`, because a mover refusal is a definite non-move.
23. **`commit_moved(id, old, new, tag)`.**
    - It requires `new` to equal the record's `sha` (`sha_mismatch`).
    - It is allowed in `approved` with `push_at` set, whether or not the TTL has passed. It writes `consumed`, `old`, `new`, `tag` and
      `consumed_at = now`.
    - On a `consumed` record, the same `old`, `new` and `tag` return ok (an idempotent repeat), and different values return
      `Refused("already_spent")`.
    - On `approved` with `push_at` null, it refuses `not_approved`: no witness can legitimately exist without a recorded push.
24. **`finish_unmoved(id)`.** It is allowed only in `approved` with `push_at` set and `now >= expires`. It writes `expired`. Part 2d's glue
    calls it in recover mode, after a successful remote read shows no witness for the id.

## Residuals

- **R2a-1: lockout and request starvation.** A same-user process can make its own request, receive the nonce and send ten wrong codes
  across two records, which locks approvals for 900 s. It can also hold the single `pending` slot or the 3-per-hour budget. This is a
  denial of service, never a promote. It is stated, not fixed; the operator sees an unexpected pending id on the card.
- **R2a-2: the code is not cryptographically bound to (id, sha) (S4).** With one pending record at a time, a diverted code can approve
  only the record the operator was shown. It is still not cryptographically bound. A policy-valid commit an attacker pushed to the newest
  release branch is approved if the operator approves its card without reading the sha. Part 3 shows the full sha on the card. Branch
  protection on release branches is umbrella open question Q6.
- **R2a-3: state reset.** After a reset (Part 2c, a trusted O3 step) the clock high-water restarts at `now`, and serials restart at 1. A
  reused id that collides with an old remote witness fails closed in Part 2d (`already_spent`).

## Worker definition of done

1. **Red first.** Every must and must_not has a pytest test.
   - Each must_not test includes its positive control.
   - Each test is shown red against a stub `hub_approval.py` that returns success for every call. The pre-fix state is "module absent",
     which is trivially red, so the stub provides the real red.
2. **Fixtures assert their target first:** a `tmp_path` directory chmod 0700, a `FileClock` file, no real HOME.
3. **Both Pythons.** `make test-pytest` passes, and the test file also passes under `/usr/bin/python3` 3.9 on macOS. Name the
   interpreter in the hand-off.
4. **Module limits.** No network, no subprocess, no Keychain, no environment reads in the module.

## What NOT to do

- No CLI, no daemon, no socket, no Git, no GitHub. Those are Parts 2c and 2d.
- No test mode, no sentinel, no environment variable of any kind.
- Do not print or log the nonce, the code or the secret.
- Do not delete records.
