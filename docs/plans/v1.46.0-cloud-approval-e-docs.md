## Change

- `docs/howto/cloud-session-requests.md`: a section "Requests that need operator approval": which four actions; what the cloud session
  sees (`responses/<id>.pending.json`, the stderr notice from `--wait`, the longer wait); the four rejection reasons, exact text, each
  with what to do (`operator approval is not configured on the bridge`, `too many requests awaiting approval; try again later`,
  `approval card not delivered; file a new request`, `not approved before the request expired`); that Deny and ignoring both end in the
  last one. Add `.pending.json` to the response-file list near `:242`, keep the status list `ok`/`rejected`/`error` (`:263`) and the exit
  codes (`:289`) as they are.
- `docs/architecture/cloud-bridge.md`: a trust-boundary row "Operator approval" in the table at `:82-92`: gated actions, card, drain by
  prefix, stored request runs, expiry; update the sequence diagram so a gated action goes through approval before the token read.
- `docs/guides/hermes.md`: the relay now accepts three prefixes (`r` Hermes repairs, `d` dispatch-recover, `c` cloud requests); each
  consumer drains and deletes only its own; the relay lists at most 50 approvals at a time.
- Operator setup (in the howto): after this release, `make deploy-worker` (relay `c` prefix) and `make install-cloud-bridge` (plist gains
  `K3DM_HERMES_APPROVAL_DRAIN_URL`); the drain token and relay URL Keychain items are the ones Hermes already uses.
- `CHANGELOG.md` `[Unreleased]`: one bullet.
