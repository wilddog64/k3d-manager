# WS3 Phase 2 — per-context hub-Vault CSS connectivity

**Branch:** `k3d-manager-v1.15.0`
**Files:** `scripts/etc/vault/vars.sh`, `scripts/tests/etc/hub_vault_profile.bats`
**Design doc:** `docs/bugs/2026-07-07-app-cluster-vault-portability.md` (Phase 2, sub-bug #2)

---

## Context — read before implementing

WS3 sub-bug #2 ("one global hub-Vault profile, last `make up` wins") is **partly already
shipped**. Commit `e7fc432e` made the profile *state file* per-context: `vars.sh` resolves the
app context (`_hub_vault_profile_context`) and keys `HUB_VAULT_PROFILE_STATE_FILE` on it, and the
failover driver `vault_failover_hub_into_context` (`scripts/plugins/vault.sh:1240,1269-1283`)
persists the flipped profile to that same per-context file. So the **profile name** is already
per-context.

The **one** piece still derived from a single global is the CSS *connectivity triple* —
`HUB_VAULT_CSS_SERVER`, `HUB_VAULT_USE_BRIDGE`, `HUB_VAULT_CSS_AUTH` (`vars.sh:66-77`). Today these
are computed from the single resolved profile name each run, so two app clusters cannot hold
distinct connectivity values simultaneously. This spec closes that gap by adding a **per-context
override convention** — `<BASE_VAR>__<sanitized-context>` — resolved with a three-tier precedence.
Per design-doc decision #3 this is known-future-need hardening; the default single-cluster
behavior is preserved exactly.

**Precedence for each of the three CSS values (highest first):**
1. Explicit base env (`HUB_VAULT_CSS_SERVER`) — the existing operator escape hatch, unchanged.
2. Per-context override (`HUB_VAULT_CSS_SERVER__<sanitized-context>`) — coexisting multi-cluster.
3. Profile-derived default — today's behavior.

The context sanitizer for a **shell variable name** maps any char outside `[A-Za-z0-9_]` to `_`
(so `ubuntu-hostinger` → `ubuntu_hostinger`, `k3s-gcp` → `k3s_gcp`). Note this differs from the
existing *state-file* key sanitizer at `vars.sh:42` which keeps `.` and `-` (legal in a filename,
illegal in a variable name) — do NOT reuse that one for the variable name.

```bash
# Resolve a hub-Vault CSS connectivity value with per-context precedence:
#   1. explicit base env (e.g. HUB_VAULT_CSS_SERVER)          — operator escape hatch, unchanged
#   2. per-context override (HUB_VAULT_CSS_SERVER__<context>) — coexisting multi-cluster connectivity
#   3. profile-derived default                                — today's single-cluster behavior
# The context is sanitized to a shell-variable-safe key (any char outside [A-Za-z0-9_] -> _).
function _hub_vault_css_resolve() {
  local _base_var="$1" _default="$2" _ctx="${3:-}"
  local _base_val="${!_base_var:-}"
  if [[ -n "${_base_val}" ]]; then
    printf '%s\n' "${_base_val}"
    return 0
  fi
  if [[ -n "${_ctx}" ]]; then
    local _ctx_key _ctx_var
    _ctx_key="$(printf '%s' "${_ctx}" | tr -c 'A-Za-z0-9_' '_')"
    _ctx_var="${_base_var}__${_ctx_key}"
    if [[ -n "${!_ctx_var:-}" ]]; then
      printf '%s\n' "${!_ctx_var}"
      return 0
    fi
  fi
  printf '%s\n' "${_default}"
}

_hub_profile_context="$(_hub_vault_profile_context)"

if [[ -z "${HUB_VAULT_PROFILE_STATE_FILE:-}" ]]; then
  _hub_state_dir="${K3DM_STATE_DIR:-${HOME}/.local/share/k3d-manager}"
  _hub_legacy_state_file="${_hub_state_dir}/hub-vault-profile"
```

> Rationale: `_hub_profile_context` is hoisted **out** of the `if` block so it is always resolved
> (the block is skipped when `HUB_VAULT_PROFILE_STATE_FILE` is pre-set) and survives to the CSS
> derivation below.

**Exact new block:**

```bash
case "${HUB_VAULT_PROFILE}" in
  hostinger)
    _hub_css_server_default="http://vault.${VAULT_NS}.svc:8200"
    _hub_use_bridge_default="0"
    _hub_css_auth_default="kubernetes"
    ;;
  *)
    _hub_css_server_default="http://vault-bridge.secrets.svc.cluster.local:8201"
    _hub_use_bridge_default="1"
    _hub_css_auth_default="token"
    ;;
esac
HUB_VAULT_CSS_SERVER="$(_hub_vault_css_resolve HUB_VAULT_CSS_SERVER "${_hub_css_server_default}" "${_hub_profile_context}")"
HUB_VAULT_USE_BRIDGE="$(_hub_vault_css_resolve HUB_VAULT_USE_BRIDGE "${_hub_use_bridge_default}" "${_hub_profile_context}")"
HUB_VAULT_CSS_AUTH="$(_hub_vault_css_resolve HUB_VAULT_CSS_AUTH "${_hub_css_auth_default}" "${_hub_profile_context}")"
export HUB_VAULT_CSS_SERVER HUB_VAULT_USE_BRIDGE HUB_VAULT_CSS_AUTH
unset _hub_css_server_default _hub_use_bridge_default _hub_css_auth_default _hub_profile_context
```

> Note: assign first, then `export` on a separate line — `export VAR="$(...)"` trips shellcheck
> SC2155 (masks the command-substitution return value), and `vars.sh` is warning-clean today.

```bash

@test "per-context CSS override applies when base env is unset" {
  unset HUB_VAULT_PROFILE HUB_VAULT_CSS_SERVER HUB_VAULT_USE_BRIDGE HUB_VAULT_CSS_AUTH HUB_VAULT_PROFILE_STATE_FILE
  export K3DM_STATE_DIR="${BATS_TEST_TMPDIR}"

  # shellcheck disable=SC1090
  source "${VARS_SH}"
  [ "${HUB_VAULT_CSS_SERVER}" = "http://percontext:8200" ]
}

@test "explicit base env CSS wins over a per-context override" {
  unset HUB_VAULT_PROFILE HUB_VAULT_USE_BRIDGE HUB_VAULT_CSS_AUTH HUB_VAULT_PROFILE_STATE_FILE
  export K3DM_STATE_DIR="${BATS_TEST_TMPDIR}"
  export APP_CONTEXT="ubuntu-hostinger"
  export HUB_VAULT_CSS_SERVER="http://baseenv:8200"
  export HUB_VAULT_CSS_SERVER__ubuntu_hostinger="http://percontext:8200"
  # shellcheck disable=SC1090
  source "${VARS_SH}"
  [ "${HUB_VAULT_CSS_SERVER}" = "http://baseenv:8200" ]
}

@test "without a per-context override the profile default is used" {
  unset HUB_VAULT_PROFILE HUB_VAULT_CSS_SERVER HUB_VAULT_USE_BRIDGE HUB_VAULT_CSS_AUTH HUB_VAULT_PROFILE_STATE_FILE
  export K3DM_STATE_DIR="${BATS_TEST_TMPDIR}"
  export APP_CONTEXT="ubuntu-hostinger"
  export VAULT_NS="secrets"
  # shellcheck disable=SC1090
  source "${VARS_SH}"
  [ "${HUB_VAULT_CSS_SERVER}" = "http://vault-bridge.secrets.svc.cluster.local:8201" ]
}

@test "per-context overrides apply to bridge and auth with a sanitized context key" {
  unset HUB_VAULT_PROFILE HUB_VAULT_CSS_SERVER HUB_VAULT_USE_BRIDGE HUB_VAULT_CSS_AUTH HUB_VAULT_PROFILE_STATE_FILE
  export K3DM_STATE_DIR="${BATS_TEST_TMPDIR}"
  export APP_CONTEXT="k3s-gcp"
  export HUB_VAULT_USE_BRIDGE__k3s_gcp="0"
  export HUB_VAULT_CSS_AUTH__k3s_gcp="kubernetes"
  # shellcheck disable=SC1090
  source "${VARS_SH}"
  [ "${HUB_VAULT_USE_BRIDGE}" = "0" ]
  [ "${HUB_VAULT_CSS_AUTH}" = "kubernetes" ]
}
```
