## Problem

`make hub-deploy REF=<sha>` (`Makefile:546` → `bin/k3dm-hub-deploy`) moves `deploy/hub`, catches the hub checkout up,
reapplies appsets and platform-ops, and reinstalls only launchd agents whose
`scripts/etc/launchd/com.k3d-manager.*.plist.tmpl` changed (`bin/k3dm-hub-deploy:216-300`). The webhook
(`com.k3d-manager.webhook`, `KeepAlive`, `bin/k3dm-webhook`) and the cloud bridge (`com.k3d-manager.cloud-bridge`,
`KeepAlive`, `bin/k3dm-cloud-bridge`) import their Python once at start, so a promote that changes their code reports
success while the hub keeps serving the old code. Seen 2026-11-22 and 2026-11-27 (`35d42bc8` not live until
`make restart-webhook`).

  gui/<uid>/com.k3d-manager.webhook` → `pid = 2505`; `ps -o lstart=` → `Thu Nov 26 19:51:32 2026` (03:51:32Z);
  `~/Library/Logs/k3dm-webhook.log:5264` → `2026-11-27T03:51:32Z INFO webhook listening on 127.0.0.1:7443` (same
  second; also `:4593`, `:4693`). Cloud bridge `pid = 2511`.
- **`launchctl print` shows `pid = <n>` and no start time** (`bin/k3dm-webhook-doctor:98`); it prints the job's
  environment, including `K3DM_WEBHOOK_PORT => <n>` when set (`bin/k3dm-webhook-doctor:83-91`). Default port 7443
  (`scripts/lib/webhook/config.py:14`).
- **An unauthenticated `GET /api/v1/health` answers 401 with no side effects**: `do_GET` calls `self._auth()` before
  routing and before the rate limiter (`bin/k3dm-webhook:2967-2970`; `_auth` `:2405-2409` returns False with no header
  before any token lookup). The authenticated form runs the full smoke test (`scripts/lib/webhook/smoke.py:566-741`)
  and needs a Keychain token — never use it here.
- **Active jobs are `queued` or `running`.** `ask`, `cluster-refresh` and `cluster-diagnostics` stay `queued` for their
  whole run (up to 400 s); make jobs start `queued` (`bin/k3dm-webhook:2888`). `bin/k3dm-hub-sync:27-39` refuses on a
  `queued`/`running` status file whose mtime is under 10800 s old.
- **On startup the webhook marks leftover `running` jobs `failed` and posts an orphan notice**
  (`_clear_stale_jobs`, `bin/k3dm-webhook:1767-1792`); it does not clear `queued`.
- **The only caller of `bin/k3dm-hub-deploy` is `make hub-deploy`** (`Makefile:546`, operator; make reports
  `Error <n>` and exits 2 on any non-zero exit) plus the operator's manual `--approval` runs. `hub-deploy` is not in
  `MAKE_TARGETS` (`scripts/lib/webhook/make_targets.py:23-57`) nor `ACTION_ALLOWLIST`
  (`scripts/lib/webhook/cloud_actions.py:17-52`). `make hub-rollback` runs only `bin/k3dm-hub-promote rollback`.
- **`make restart-webhook` and `restart-cloud-bridge`** (`Makefile:695-712`, `:734-739`) touch neither the repo-sync
  lock nor the checkout; `restart-cloud-bridge` uses `launchctl kickstart -k` and fails if the bridge plist exists but
  is not loaded.

## Behaviour

1. **State field.** Optional `agents <sha>` line in `$HOME/.local/share/k3d-manager/hub-deploy/state` (`STATE_DIR`,
   `bin/k3dm-hub-deploy:33`). Variable `agents`; empty means "restart owed".
   - `valid_state` (`:61-82`): parse into locals and assign the globals (`appsets`, `launchd`, `pending`, `agents`) only
     when the whole file is valid; on any failure the globals are `''`/`()`. Accept at most one `agents` line, in any
     position, whose value matches `^[0-9a-f]{40}([0-9a-f]{24})?$` and resolves with `git cat-file -e "$v^{commit}"`.
     `agents full`, a duplicate, a non-hex or unresolvable value fails `valid_state`. No `agents` line → valid,
     `agents=''`.
   - Every reset path sets `agents=''` alongside `appsets`/`launchd`/`pending` (`:90`, `:93`, `:97`, `:141`).
   - `write_state` (`:54-60`) writes `agents <sha>` after the `launchd` line and before `pending` lines, **only when
     `agents` is non-empty**. So the first-run `--approval` snapshot at `scripts/tests/bin/hub_deploy.bats:912` stays
     exactly two lines, and the make-stub check at `:99` (counts `appsets`/`launchd` lines) is unaffected.
2. **Where.** A new block after the launchd section (after `:300`) and before the summary (`:301-305`), in whichever
   copy reaches it (the promoted copy after the stage2 handoff at `:176-182`).
3. **Decide** (first match wins). "Watched paths" = `bin/k3dm-webhook bin/k3dm-cloud-bridge scripts/lib/webhook/
   scripts/lib/hermes/`. `changed(a)` = `git diff --quiet --no-renames "$a" "$new" -- <watched>` exits 1 (exit 0 =
   unchanged; any other exit → `stop agent-diff <code>`).
   - **not installed** — `$HOME/Library/LaunchAgents/com.k3d-manager.webhook.plist` absent: print
     `hub-deploy: agents: webhook not installed on this host; skipping`; `agents=$new`; `write_state || stop state-write 1`;
     result `not installed`.
   - **unchanged** — `agents` non-empty, `changed "$agents"` false, **and** (`old` empty, or `old == agents`, or
     `changed "$old"` false): print `agents unchanged between <a7> and <n7>`; `agents=$new`;
     `write_state || stop state-write 1`; result `unchanged`. (The `old` check covers rollback: deploy N → `make
     hub-rollback` to R → `make restart-webhook` runs R → re-promote N; `agents..new` is empty but `old..new` is not,
     so it restarts.)
   - **deferred: agent load disabled** — `K3DM_AGENT_LOAD=0`. Reason `agent load disabled (K3DM_AGENT_LOAD=0)`.
   - **deferred: checkout** — reuse the bounded `take_lock && checkout_ok` retry loop of `:258-269` with
     `K3DM_HUB_DEPLOY_CHECKOUT_WAIT` (one attempt when it is 0, as in tests); on failure `release_lock`. Reason
     `hub checkout is not at <n7> with a clean tracked tree`. On success the lock is held through restart and confirm.
   - **deferred: active job** — checked last, immediately before the restart, with the lock held. For each
     `${K3DM_JOB_DIR:-$HOME/.local/share/k3d-manager/webhook-jobs}/*/status` (find `-mindepth 2 -maxdepth 2`):
     content with all whitespace stripped is `queued` or `running`, and mtime (via the existing `lock_stamp`) is ≥ now −
     10800. External commands get `9>&-`. On a hit `release_lock`; reason `webhook job <id> is <state>`.
   - otherwise **restart**.
   Deferred cases: result `pending`; `agents` unchanged; no `make` call.
4. **Restart.** Read `old_w`/`old_b` from `launchctl print gui/<uid>/com.k3d-manager.webhook` / `…cloud-bridge`
   (bridge only if `$HOME/Library/LaunchAgents/com.k3d-manager.cloud-bridge.plist` exists), matching
   `^[[:space:]]*pid[[:space:]]*=[[:space:]]*([1-9][0-9]*)$`; empty if not loaded or no match. Then run, directly (not
   in a subshell, so the stub sees hub-deploy as `$PPID`):
   `_run_command --soft -- env -u K3DM_AGENT_LOAD make --no-print-directory -C "$REPO_ROOT" restart-webhook 9>&-`,
   exactly once. Do not call `restart-cloud-bridge` or `launchctl` (other than `print`) yourself; do not edit `Makefile`.
5. **Confirm**: `wait=${K3DM_HUB_DEPLOY_AGENT_WAIT:-30}` (non-negative integer, else 30); check immediately, then once a
   second until `now ≥ start + wait` (0 = exactly one check); sleep via `_run_command --soft -- sleep 1 9>&-`. A check
   passes when:
   - the webhook `pid` (anchored regex above, from a fresh `launchctl print`) is non-empty and `!= old_w`;
   - if the bridge plist exists, the bridge `pid` is non-empty and `!= old_b`;
   - `_run_command --soft --quiet -- curl -s -o /dev/null -w '%{http_code}' --max-time 2
     "http://127.0.0.1:<port>/api/v1/health" 9>&- 2>/dev/null` prints `401` or `200`. `<port>`: `K3DM_WEBHOOK_PORT =>
     <n>` from that same fresh `launchctl print`, else env `K3DM_WEBHOOK_PORT`, each accepted only if it matches
     `^[1-9][0-9]{0,4}$` and `(( 10#$p <= 65535 ))`; else `7443`. Never pass `-H`/`Authorization`.
   On success print `hub-deploy: restarted webhook (pid <n>) and cloud-bridge (pid <m>) for <a7|full>..<n7>` (omit the
   bridge part without its plist), `agents=$new`, `write_state || stop state-write 1`, `release_lock`, result
   `restarted`.
6. **Failure** (make non-zero, or confirm timed out): `agents` unchanged; print to stderr
   `hub-deploy: webhook is <loaded (pid <n>)|not loaded>; cloud-bridge is <loaded (pid <m>)|not loaded|not installed>;
   restore with make restart-webhook (bridge: make install-cloud-bridge) on the hub`; then `stop agent-restart 1`.
7. **Deferred exit.** Print the summary (8), then on stderr `hub-deploy: agents pending: <reason>; rerun make hub-deploy
   REF=<ref> after it clears (or make restart-webhook)` — `bin/k3dm-hub-deploy <new> --approval <id>` when
   `approval_id` is set — and **exit 3** ("deployed; webhook still runs older code"). The stderr line, not the code
   alone, is the signal (a child's exit 3 can pass through `stop`). Exit 75 stays reserved (`:11`).
8. **Summary.** Store the result in `agents_result` (do not reuse `result`, `:301-303`) and print `; agents
   <agents_result>` after the optional `; launchd unwired N` (`:304`) and before the newline (`:305`). Existing
   assertions on the line are substring matches (`hub_deploy.bats:243,314,436,542`).

## Test design (concrete; the implementer cannot ask)

- **Existing tests.** All except `hub_deploy.bats:530-546` lack the webhook plist and take "not installed". Test `:530`
  writes `com.k3d-manager.webhook.plist` (`:533-535`), has first-run state (`agents` empty), so it **restarts** and
  must pass unedited — the defaults below make it pass.
- **`launchctl` stub** (`:154-159`): append every invocation (`launchctl $*`) to `$CALLS`. Keep `print` exit 113 when
  `$HOME/.test-launchctl/<label>` is absent and for non-`print` verbs. When present, print `pid = <n>` from
  `$HOME/.test-launchctl/<label>.pid` if that file exists, and `K3DM_WEBHOOK_PORT => <n>` from `<label>.port` if it
  exists (shape from the m5 capture above; add a comment with host and date).
- **`make` stub**, target `restart-webhook`: append `restart-webhook` to `$CALLS`; exit 96 if `-e /dev/fd/9`; exit 97
  unless `$K3DM_REPO_SYNC_STATE_DIR/lock/pid` equals `$PPID`; exit 95 if `K3DM_AGENT_LOAD` is set; exit 94 unless the
  checkout HEAD equals the promoted sha and is clean (as `:111-113`); `FAIL_STEP=restart-webhook` already exits via
  `:105`. Unless `NO_PID_BUMP=1`: create `$HOME/.test-launchctl/com.k3d-manager.webhook`, write a new pid (previous + 1,
  start 1000) to its `.pid`; same for `com.k3d-manager.cloud-bridge` only when its plist exists.
- **`curl` stub**: append its arguments to `$BATS_TEST_TMPDIR/curl.args`; print `${CURL_CODE:-401}`; exit 0.
- **Setup** sets `K3DM_JOB_DIR=$BATS_TEST_TMPDIR/jobs` and `K3DM_HUB_DEPLOY_AGENT_WAIT=0`, and asserts `curl`,
  `launchctl`, `make` resolve to the stubs and `K3DM_JOB_DIR` is under `$BATS_TEST_TMPDIR`.
- **Knobs per test:** non-empty `agents` = hand-write a 3-line state (`appsets <sha>`, `launchd <sha>`,
  `agents <sha>`) on a commit that already carries the handoff copy (`$CHANGED_SHA`), then promote a descendant;
  checkout deferral = `install_fixture` + `MOVE_HEAD=1 MOVE_TO=$BASE_SHA` (`:136`); confirm timeout = `NO_PID_BUMP=1` or
  `CURL_CODE=000`; red-on-current = `TEST_HUB_DEPLOY=<pre-fix copy>` (`:18`).

**Accepted residual risks (in writing):** a job submitted in the second between the active-job check and `bootout` is
lost (the startup sweep reports it); a bridge request mid-call becomes "bridge restarted before the request completed"
(`_recover_orphaned_claims`, `bin/k3dm-cloud-bridge:273-290`); an orphaned `queued` file defers restarts up to 3 h
(override `make restart-webhook`); `9>&-` on the restart (unlike the installer at `:287`) means a killed hub-deploy can
be followed by a second run while a restart is in progress; a changed bridge template restarts the bridge twice
(install, then restart) — harmless; a bridge-only host (no webhook plist) never restarts the bridge; a repo-sync run
colliding with the checkout step defers with exit 3 (rerun).
