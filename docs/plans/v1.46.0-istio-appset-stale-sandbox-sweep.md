## Problem

The hub's ArgoCD still holds the `istio-ambient` ApplicationSet rendered for an ACG AWS sandbox (`ubuntu-k3s`) that is
gone. It has shown `ErrorOccurred=True` for four weeks ("there are no clusters with this name: ubuntu-k3s"), which hides
any new ApplicationSet error. `bin/cleanup-stale-sandbox` (also `make cleanup-stale-sandbox`, Slack
`/cleanup-stale-sandbox`) removes the sandbox's launchd forwards and kube context only (`bin/cleanup-stale-sandbox:18-22`);
it never looks at ArgoCD, so sandbox ArgoCD objects outlive every sandbox.

  - ApplicationSets in `cicd`: 14. Template `spec.template.spec.destination.name` is the literal `ubuntu-k3s` only for
    `istio-ambient` (its only one with `ErrorOccurred=True`). Others use `{{.name}}`, `{{.server}}`, or

    `ubuntu-k3s`.

## Behaviour

1. **New section** in `bin/cleanup-stale-sandbox`, after the kube-context section (`:54-67`) and before the summary
   (`:69-74`). Keep the script standalone (it does not source `system.sh`); call `kubectl` directly as the script
   does today, always with `--context "$hub_ctx" -n "$argocd_ns" --request-timeout=10s`.
   - `hub_ctx="${INFRA_CONTEXT:-k3d-k3d-cluster}"`, `argocd_ns="${ARGOCD_NAMESPACE:-cicd}"`,
     `sandbox_name="${ARGOCD_APP_CLUSTER_NAME:-ubuntu-k3s}"`. Do not source `scripts/etc/argocd/vars.sh`.
   - **Guard:** if `sandbox_name` is empty, `in-cluster`, `k3d-cluster`, `ubuntu-hostinger`, or contains anything but
     `[a-z0-9-]`, print `  - skipped ArgoCD sweep: refusing sandbox name '<n>'` and treat it as a failure.
2. **Discover** (dry run and confirm alike):
   - ApplicationSets: `get applicationsets -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.template.spec.destination.name}{"\n"}{end}'`;
     a candidate is a line whose second field equals `sandbox_name` exactly (templated values like `{{.name}}` never
     match).
   - Applications: same with `get applications` and `{.spec.destination.name}`.
   - Cluster secrets: `get secrets -l argocd.argoproj.io/secret-type=cluster -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.data.name}{"\n"}{end}'`;
     a candidate is a line whose second field equals `printf %s "$sandbox_name" | base64` (compare encoded values; no
     decode, so it is portable). Match on the data `name`, never on the secret's own name (the hub's registration is
     called `ubuntu-k3s-app-cluster`).
   - Print one line per candidate: `  - ArgoCD <kind> targeting <sandbox_name>: <name>` and, if none of a kind,
     `  - no ArgoCD <kind> targets <sandbox_name>`.
   - If any discovery call fails (non-zero), print `  - could not inspect ArgoCD <kind> on <hub_ctx>: <first line>`
     — in dry run as information only, in confirm via `report_failure`.
   - The dry-run listing must therefore run **before** the existing `DRY RUN` early exit (`:23-26`): move the exit
     below the discovery, or print the plan lines then discover; the existing plan lines and the `DRY RUN: no changes
     made` line stay as they are.
3. **Delete** (confirm only), in this order: Applications, then ApplicationSets, then cluster secrets, each with
   `kubectl … delete <kind> <name> --wait=false`. Success prints `  - deleted ArgoCD <kind>: <name>`; failure goes to
   `report_failure "could not delete ArgoCD <kind>: <name>"`. Never delete anything that was not listed as a candidate
   in this same run.
4. The existing launchd and kube-context behaviour, messages, exit codes and the `k3s-aws` provider gate (`:14-17`)
   are unchanged.

## What NOT to Do

- Never delete an object whose destination is `ubuntu-hostinger`, `in-cluster`, `k3d-cluster` or a `server` URL;
  never match by secret name; never delete without `--confirm`/`--apply`/`CONFIRM=1`.
- Do not patch or strip ArgoCD finalizers; do not touch Hostinger's running Istio; do not edit ApplicationSet templates.
- Out of scope (follow-ups): distinct ApplicationSet names per target cluster (`istio-ambient-${APP_CLUSTER_NAME}`);
  re-adopting Hostinger Istio under ArgoCD (live mesh, its own spec); an alert for an ApplicationSet with
  `ErrorOccurred=True` for more than a day.
- Tests: no real `kubectl`, `launchctl` or network; do not edit or delete existing assertions in
  `cleanup_stale_sandbox.bats`.

## Test design (concrete; the implementer cannot ask)

- Extend the `kubectl` stub in `setup()` (`cleanup_stale_sandbox.bats:13-26`); keep its existing `config` branches and
  `FAIL_KUBECTL`. Append every invocation to `$BATS_TEST_TMPDIR/kubectl.log`. For calls containing `get
  applicationsets` / `get applications` / `get secrets`, print `$BATS_TEST_TMPDIR/fx/<appsets|apps|secrets>.tsv` if it
  exists (else nothing), exit 0; exit 1 if `FAIL_ARGO_GET=<appsets|apps|secrets>` names that kind. For `delete`, exit 1
  if `FAIL_ARGO_DELETE` equals the object name, else 0. Default fixtures are empty, so every existing test passes
  unedited.
- Fixtures (comment: shape from m5 `k3d-k3d-cluster`, 2026-11-27): appsets `istio-ambient\tubuntu-k3s`,
  `data-git\t{{.name}}`, `observability\t` (server-only); apps `istio-base\tubuntu-k3s`, `frontend\tubuntu-hostinger`,
  `hub-app\tk3d-cluster`; secrets `cluster-ubuntu-hostinger\t<base64 ubuntu-hostinger>`,
  `ubuntu-k3s-app-cluster\t<base64 k3d-cluster>`, `cluster-ubuntu-k3s\t<base64 ubuntu-k3s>`.
- Setup asserts `command -v kubectl` and `launchctl` resolve under `$BATS_TEST_TMPDIR`.
- Required tests: dry run lists the three `ubuntu-k3s` candidates and logs no `delete`; confirm deletes exactly those
  three in the order apps → appsets → secrets; with the full fixture set, no `delete` line names
  `frontend`, `hub-app`, `data-git`, `observability`, `cluster-ubuntu-hostinger` or `ubuntu-k3s-app-cluster` (and a
  positive control in the same test shows `istio-ambient` deleted); `ARGOCD_APP_CLUSTER_NAME=ubuntu-hostinger` (and
  `k3d-cluster`, empty) is refused with no `delete` and exit 1 in confirm; `FAIL_ARGO_GET=apps` in dry run exits 0 with
  the "could not inspect" line, in confirm exits 1 with `Cleanup incomplete`; `FAIL_ARGO_DELETE=istio-ambient` exits 1
  and still deletes the other candidates; context/namespace come from `INFRA_CONTEXT`/`ARGOCD_NAMESPACE` when set
  (checked in `kubectl.log`).
