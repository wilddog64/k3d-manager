## Problem

The hub's ArgoCD holds the `istio-ambient` ApplicationSet rendered for an ACG AWS sandbox (`ubuntu-k3s`) that is gone.
It has shown `ErrorOccurred=True` for four weeks, which hides any new ApplicationSet error. `bin/cleanup-stale-sandbox`
removes only the sandbox's launchd forwards and kube context (`bin/cleanup-stale-sandbox:18-22`).

Deleting the set alone does not stick: every `make hub-deploy` that reapplies appsets
(`bin/k3dm-hub-deploy:191-202` → `Makefile:521-533`) runs `_argocd_deploy_applicationsets`
(`scripts/plugins/argocd.sh:1510-1594`) over every `applicationsets/*.yaml`. Today `istio-ambient` stays on
`ubuntu-k3s` only because `_argocd_appset_live_overrides` (`:1424-1444`) copies the live destination. With no live set,
`_argocd_prepare_applicationsets` (`:1288-1308`) resolves `APP_CLUSTER_NAME` from the active provider
(`:1299-1303`) — `ubuntu-hostinger` on the hub — and the apply (`:1575-1576`) creates four Applications with
`automated: prune: true, selfHeal: true` and `ServerSideApply=true`
(`scripts/etc/argocd/applicationsets/istio-ambient.yaml:93-104`) over Hostinger's running, unmanaged mesh; or, with the
`ubuntu-k3s` fallback, the red set returns. The Hostinger refresh path applies it unconditionally with
`APP_CLUSTER_NAME=ubuntu-hostinger` (`scripts/lib/providers/k3s-hostinger.sh:906-951`, list at `:926`).

## Behaviour

### Part A — `bin/cleanup-stale-sandbox`: ApplicationSet sweep

1. **Argument parsing.** `--confirm|--apply` sets `confirm=1`; `--dry-run` sets `confirm=0` even when `CONFIRM=1` is in
   the environment (as `bin/cleanup-stale-clusters:11`); no argument keeps today's `confirm="${CONFIRM:-0}"` for the
   local steps. New variable `argo_confirm=1` **only** when `--confirm`/`--apply` was passed; the env `CONFIRM` never
   authorizes an ArgoCD delete.
2. **Layout** (one prescribed order): usage/provider gate (unchanged) → move `failed=0` and `report_failure()` to just
   after the plan lines → name guard → ArgoCD discovery (results in arrays; Bash 3.2 compatible, no `mapfile`) → print
   candidates → existing `DRY RUN` exit (unchanged text, exit 0) → existing launchd and kube-context steps (unchanged)
   → ArgoCD deletes (only if `argo_confirm=1`; otherwise print `  - ArgoCD deletes need --confirm (CONFIRM env is not
   enough)`) → summary (unchanged lines; append nothing to them).
3. **Inputs.** `hub_ctx="${ARGOCD_HUB_CONTEXT:-${INFRA_CONTEXT:-k3d-k3d-cluster}}"`,
   `argocd_ns="${ARGOCD_NAMESPACE:-cicd}"`, `sandbox_name="${ARGOCD_APP_CLUSTER_NAME-ubuntu-k3s}"` (no colon: set-but-
   empty reaches the guard). `ARGOCD_APP_CLUSTER_NAME` is the sandbox registration name (`scripts/etc/argocd/vars.sh:68`);
   `APP_CLUSTER_NAME` is the template's per-render variable and is not read here.
4. **Name guard.** Refuse unless `sandbox_name` matches `^[a-z0-9]([a-z0-9-]*[a-z0-9])?$` and is none of
   `ubuntu-hostinger`, `k3d-cluster`, `in-cluster`, `ubuntu-gcp`, `ubuntu-azure`, `k3s-oci`. On refusal print
   `  - skipped ArgoCD sweep: refusing sandbox name '<n>'`, skip all ArgoCD calls, and exit 1 at the summary in both
   dry run and confirm (local steps still behave as today).
5. **Discovery** — every call `kubectl --context "$hub_ctx" -n "$argocd_ns" --request-timeout=5s …`; stop discovery at the
   first failed call and print `  - could not inspect ArgoCD <kind> on <hub_ctx>: <first line>` (first line via
   `${err%%$'\n'*}`); in dry run that is information only, in confirm it is `report_failure` and no ArgoCD delete runs.
   | step | `get` resource | output label |
   |---|---|---|
   | 1 | `applicationsets.argoproj.io -o json` | `ApplicationSet` |
   | 2 | `applications.argoproj.io -o json` | `Application` |
   | 3 | `secrets -l argocd.argoproj.io/secret-type=cluster -o json` | `cluster secret` |
   Parse with `jq`. An ApplicationSet is a **candidate** when `.spec.template.spec.destination.name == sandbox_name`
   exactly **and** `.spec.template.spec.destination.server` is empty or absent, and its name does not start with `-`.
   For each candidate, count owned Applications (`.metadata.ownerReferences[]? | select(.kind=="ApplicationSet" and
   .name==<set>)`, the pattern at `scripts/plugins/argocd.sh:1460`) whose `.spec.destination.name` differs from
   `sandbox_name` or whose `.spec.destination.server` is non-empty: if > 0 the set is **blocked** (`  - ArgoCD
   ApplicationSet <set> owns Applications on other clusters; not deleting`) and counts as a failure in confirm.
   Applications whose destination name equals `sandbox_name`, and cluster secrets whose data `name` equals
   `printf '%s' "$sandbox_name" | base64 | tr -d '\r\n'` (never matched by secret name; never one whose data `server`
   is the base64 of `https://kubernetes.default.svc`), are **listed only**: `  - ArgoCD <label> targeting <n>: <name>
   (remove with make cleanup-stale-clusters / cleanup-stale-registration)`. Print `  - no ArgoCD <label> targets <n>`
   for an empty kind.
6. **Dead-sandbox check** (confirm only, before any delete): `kubectl --context "$context" --request-timeout=5s get
   --raw=/readyz` (as `bin/cleanup-stale-clusters:96`, `context` = the existing `ACG_KUBE_CONTEXT` value) — run it
   **before** the kube-context step removes that context. If it succeeds, print `  - sandbox API is reachable; not
   deleting ArgoCD objects` and delete nothing in ArgoCD (not a failure). A missing context or any error = unreachable.
7. **Delete** (confirm, `argo_confirm=1`, unreachable, discovery succeeded): for each unblocked candidate
   ApplicationSet only: `kubectl --context "$hub_ctx" -n "$argocd_ns" --request-timeout=5s delete
   applicationset.argoproj.io --wait=false -- "<name>"`. Success `  - deleted ArgoCD ApplicationSet: <name>`; failure
   `report_failure "could not delete ArgoCD ApplicationSet: <name>"`. Never delete an object not listed as a candidate in
   this run; never delete Applications or secrets; never patch finalizers.
8. Budget: at most 3 discovery + 1 readyz + N deletes at 5 s each; with one candidate the worst case is ~25 s, under the
   webhook's 30 s. `bin/k3dm-webhook` is unchanged.

### Part B — the reapply paths do not recreate `istio-ambient` (default of D1)

9. `scripts/plugins/argocd.sh` `_argocd_deploy_applicationsets`: before applying `istio-ambient.yaml`, unless
   `ISTIO_AMBIENT_APPSET_ENABLE=1`, run `_kubectl --no-exit get applicationset istio-ambient -n "${ARGOCD_NAMESPACE:-cicd}"
   -o name 2>&1`. Present → today's path (live overrides keep the live destination). Output contains `NotFound` → skip
   the file with `_info "[argocd] skipping istio-ambient.yaml: no live ApplicationSet and ISTIO_AMBIENT_APPSET_ENABLE
   unset (Hostinger Istio adoption needs its own spec)"`. Any other error → skip with `_warn` naming the error. A skip is
   neither deployed nor failed: subtract it from `selected_count` so the summary stays `N/N`.
10. `scripts/lib/providers/k3s-hostinger.sh` `_hostinger_reapply_gitops_applicationsets` (`:906-951`): apply
    `istio-ambient.yaml` only when `ISTIO_AMBIENT_APPSET_ENABLE=1`; otherwise skip with `_info "[k3s-hostinger] skipping
    istio-ambient.yaml (ISTIO_AMBIENT_APPSET_ENABLE unset; Hostinger Istio adoption needs its own spec)"`. (This path
    always targets Hostinger, so a live-set check would not prevent adoption.)
11. `Makefile:348-349`: pass `ARGOCD_HUB_CONTEXT="$(INFRA_CONTEXT)" ARGOCD_NAMESPACE="$(ARGOCD_NS)"` and append
    `--confirm` when `CONFIRM` is `1|true|yes` (same pattern as `:352-353`), so `make cleanup-stale-sandbox CONFIRM=1`
    still deletes the ApplicationSet. Help text `:2417` and `docs/howto/makefile.md:20` gain "and the dead sandbox's
    ArgoCD ApplicationSet".
