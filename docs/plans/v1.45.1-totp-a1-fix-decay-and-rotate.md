## Problem

Two defects in A1 as landed (`scripts/libexec/k3dm-console-totpd.py`), both against the A1 spec
([`v1.45.1-totp-a-lock-and-recovery.md`](v1.45.1-totp-a-lock-and-recovery.md)):

1. **Decay collapses** (A1 spec `:36`, `:161`: "-1 level per full 86400 s since the last lock expired"). `decay_state`
   (`:497-512`) computes `elapsed_levels = (now - locked_until) // 86400`, commits the lower level, but leaves
   `locked_until` unchanged unless the level reaches 0. The next request recomputes the same `elapsed_levels` and
   subtracts again. Reproduced by Claude 2026-11-23: level 4, one day after expiry, start + three `VERIFY 000000` →
   levels `[3, 2, 1, 0]`.
2. **Rotate keeps `lock_level`** (A1 spec `:49`: "enrol and rotate also reset `failures`, `locked_until` and
   `lock_level` to 0"). The rotate commit (`:929-935`) copies `cur_state` and resets only `failures` and
   `locked_until`, so `lock_level` survives; with `locked_until = 0`, `decay_state` returns early and the level never
   decays. Enrol (`:860-866`) is correct.

## Behaviour

1. In `decay_state`, when the level drops but stays above 0, advance `locked_until` by the days consumed:
   `result["locked_until"] = until + elapsed_levels * 86400`. This stays `<= now` (because
   `elapsed_levels = floor((now - until) / 86400)`), so no lock is imposed; `sync_lock_deadline` then sees a changed
   `locked_until` in the past and sets a zero remaining deadline. When the level reaches 0 keep today's behaviour
   (`locked_until = 0`, deadline cleared, `totp-unlock source=decay`). Do not add a state key (rollback to v1.45.0 needs
   the 5-key form at level 0, and `state.json` readers below expect the current key set).
2. In the rotate commit, set `nstate["lock_level"] = 0` before `state_for_commit` (which then drops the key).
3. No migration: A1 is not released or installed anywhere (hub runs v1.45.0 part C), so no on-disk state carries
   `locked_until = 0` with `lock_level > 0`.

## Contract readers

`state.json` key set (writer: `totpd.py` `commit_state` via `state_for_commit`): unchanged — 5 keys, plus
`lock_level` 1..4 only while non-zero. Readers: `load_state` (`totpd.py:141-160`), v1.45.0 `load_state` on rollback
(5 keys exactly), test fixtures in `scripts/tests/bin/test_web_console_totp.py`. The value of `locked_until` while
`lock_level > 0` and no lock is active changes from "last expiry" to "last expiry plus whole decayed days"; the only
reader that interprets it is `decay_state` / `sync_lock_deadline` in the same file (grep `locked_until` in
`scripts/libexec/`, `scripts/lib/` and `bin/`: the only other hits are `scripts/lib/hub_approval.py:134,255,349,372`,
which use their own `totp-state.json` for hub approvals — a separate file and contract, unaffected).
