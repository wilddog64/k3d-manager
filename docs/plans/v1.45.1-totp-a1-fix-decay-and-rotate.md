## Problem

Two defects in A1 as landed (`scripts/libexec/k3dm-console-totpd.py`), both against the A1 spec
([`v1.45.1-totp-a-lock-and-recovery.md`](v1.45.1-totp-a-lock-and-recovery.md)):

1. **Decay collapses** (A1 spec `:36`, `:161`: "-1 level per full 86400 s since the last lock expired"). `decay_state`
   (`:497-512`) computes `elapsed_levels = (now - locked_until) // 86400`, commits the lower level, but leaves
   `locked_until` unchanged unless the level reaches 0, so the next request subtracts again. Reproduced by Claude
   2026-11-23: level 4, one day after expiry, start + three `VERIFY 000000` → levels `[3, 2, 1, 0]`. On the request
   path the failure counter is also inconsistent with startup decay (Rev 2 table, B1).
2. **Rotate keeps `lock_level`** (A1 spec `:49`: "enrol and rotate also reset `failures`, `locked_until` and
   `lock_level` to 0"). The rotate commit (`:929-935`) copies `cur_state` and resets only `failures` and
   `locked_until`; with `locked_until = 0`, `decay_state` returns early (`:502`) and the level never decays. Enrol
   (`:861-867`) is correct.

## Behaviour

1. **Decay anchor.** In `decay_state`, when the level drops but stays above 0, set
   `result["locked_until"] = until + elapsed_levels * 86400` (stays `<= now`, keeps the part-day remainder). At level 0
   keep today's behaviour (`locked_until = 0`, deadline cleared, `totp-unlock source=decay`). No new state key.
2. **Rotate.** In the rotate commit set `nstate["lock_level"] = 0` before `state_for_commit`.
3. **Decay resets failures on both paths.** `decay_state` already sets `failures = 0` (`:508`). On the request path,
   read `failures` from `cur_state` after the `decay_state` call (today it is read at `:1119`, before decay at `:1122`),
   so a request that decays the level starts counting from 0, as startup decay does.
4. **No phantom lock.** `sync_lock_deadline` (`:484-495`) arms a deadline only when `locked_until > now` is plausible
   for a real lock: require `state.get("failures", 0) >= 5`; otherwise clear the deadline as for `locked_until <= 0`.
   A real lock is committed with `failures >= 5` (`:1196-1201`) and keeps it until the expiry reset (`:1146-1148`).
5. No migration: A1 is not released or installed anywhere (hub runs v1.45.0 part C).
