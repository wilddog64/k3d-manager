## Problem

k3d-manager wants CPU/GPU temperature from its fleet Macs. On Apple Silicon no built-in command reports degrees
without sudo (`powermetrics` needs sudo; `pmset -g therm` reports only warning levels). `macmon` (Homebrew formula,
0.10.0 on 2026-11-01) reads the sensors without sudo. Consumers should install it through one library function, like
`_install_helm` and `_install_orbstack`, rather than each listing a brew formula.

Captured on the k3d-manager M4 (`m4-air`), 2026-11-01 ~22:25Z: `uname -m` → `arm64`, `sw_vers -productVersion` →
`26.5.2`, `command -v macmon` → nothing (exit 1), `brew info macmon` → `macmon 0.10.0`.

## Fix spec

Add to `scripts/lib/system.sh`, next to `_install_helm`:

```bash
function _install_macmon() {
  ...
}
```

Behaviour, in order:

1. Not macOS (`_is_mac` false): `_info` that macmon is macOS-only, return 0. No other call.
2. Not Apple Silicon (`uname -m` is not `arm64`): `_info` that macmon needs Apple Silicon, return 0. No brew call.
3. `_command_exist macmon`: return 0 quietly (idempotent). No brew call.
4. `brew` missing: `_warn` "Homebrew is required to install macmon", return 1.
5. Otherwise `_run_command -- brew install macmon`; return its exit status. On success, `_info` "macmon installed".

It never uses sudo, never starts a service or LaunchAgent, and never runs `macmon` itself.

## Rules

- Tests stub `uname`, `brew` and `macmon` on a scratch `PATH` and record argv to a log; the fixture first asserts the
  stub `brew` is the one on `PATH` (not `/opt/homebrew/bin/brew`). The `uname -m` stub output is `arm64`, captured above.
- No real `brew install` in tests.
