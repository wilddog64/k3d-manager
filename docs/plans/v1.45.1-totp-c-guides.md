## Problem

After v1.45.1 the console TOTP lock escalates (5 min, 30 min, 4 h, 24 h, with decay), the sshd checks a revocation list,
and the upgrade needs two at-home root installs in a set order. None of this is in the guides, and a rollback without the
unlock step leaves the console saying "unavailable" (parent "Rollback").

## Behaviour

Edit the two guides only. Each section is short, states commands exactly as the landed code accepts them, and links the
parent.

`docs/howto/web-console-totp.md`:
1. **Lock levels.** The schedule as landed by part A (parent B1 with operator decisions Q3 = 24 h final level reusing
   `WAIT <n>`, Q4 = decay), what the console shows while locked ("Too many attempts; try again later"), and that decay
   lowers the level over time.
2. **Unlock.** Every unlock path part A ships: root `totpctl unlock` (`sudo /Library/PrivilegedHelperTools/k3dm-web-console/totpctl unlock`)
   and the console-side, no-root path: recovery codes (parent B8) — type one at the `Code:` prompt (dashes and case
   optional), single use, one try per minute; `totpctl recovery-status` and `totpctl recovery-regen` (root, at home);
   keep the ten codes off the travel device; regenerate when two or fewer remain. Also: a correct code, enrol and rotate
   reset the lock.
3. **Log lines.** The structured `event=totp-failure|totp-lock|totp-locked-reply|totp-unlock|totp-recovery-*` lines in
   `/var/log/k3dm-web-console-totp.log` (parent B5), and that they carry no code or secret.
4. **macOS sleep note.** A lock imposed before sleep runs its full awake duration after wake (parent B2); it never
   shortens.
5. **Rollback.** Parent "Rollback": run `totpctl unlock` as root **before** reinstalling the old part C; if the old
   version already shows "console login unavailable", either the in-place key removal described in the parent (never
   printing `state.json`, which holds the TOTP secret) or `make uninstall-web-console-totp PURGE_SECRET=1` and re-enrol.

`docs/howto/web-console-sshd.md`:
6. **Revoke one certificate.** `ssh-keygen -k -u -f /etc/k3dm-web-console/revoked_keys <cert or spec>` as root; check with
   `ssh-keygen -Q -f /etc/k3dm-web-console/revoked_keys <cert>`; listing the CA key revokes every cert. Contrast with the
   whole-console `revoked` marker. The file survives reinstall and non-purge uninstall; `PURGE=1` removes it.
7. **Upgrade order.** Parent "Upgrade order" steps 1–4: promote; C1/C2 FAIL until step 2 while login keeps working;
   `make install-web-console-sshd` then `make install-web-console-totp`, both at home, then `totpctl recovery-regen`.
