## Problem
One agent's conjecture, retrieved document, failed probe or self-reported test can be mistakenly treated by subsequent agents as proven fact or operating authority. Poisoned retrieval and repeated AI summaries can launder bad assertions into apparently independent evidence. Existing operational logs alone cannot connect proposal, authorization, tool result, verified artifact and handoff.

## Design
- Separate **instruction authority** from **data evidence**. RAG results, Slack messages, generated docs, source comments, web pages, logs and other agents' reports are untrusted data, never permissions.
- Use a small typed provenance envelope for evidence: source kind, source URI/ref and immutable revision when available, observation timestamp, actor, artifact digest, validation method and uncertainty. Preserve the original source and deduplicate repeated summaries rather than counting them as independent corroboration.
- Status semantics: hypothesis; reported/unverified; independently test-verified; live-observed; operator-approved. Approval is permission, not proof of correctness. Commits prove code changes, not deployments.
- Landing verifies SHA, file scope, exit status, test artifacts and required approval independently of worker claims. Ingestion cannot alter the policy schema or elevate an agent's role.
- Reuse Hermes/Loki/Grafana: record bounded security events such as denied capability, unsupported evidence promotion, repeated poisoned retrieval, unusual tool fan-out and source freshness gaps. Correlate by task/run IDs in durable local records, not high-cardinality metric labels.
- Keep secret-bearing worker transcripts local. Ship only redacted, structured reason codes and safe evidence links; empty Loki links must explicitly report local-only or unavailable evidence.
- Provide a targeted adversarial fixture suite including forged system instructions in VectorDB documents, fabricated green tests, contradictory webhook health probes (e.g., wrong configured port), cross-agent task scope escalation and stale index results.

## Files
- Evidence-envelope schema and validators in existing gateway/dispatch interfaces.
- VectorDB result provenance and independent test/landing evidence adapter.
- Existing Hermes/Loki/Grafana exporter panels and offline adversarial tests.

## Acceptance
1. A poisoned VectorDB chunk cannot grant tool permissions or override operator approval.
2. Two agent summaries citing the same stale log do not count as two independent confirmations.
3. Missing test artifacts, altered SHA or incorrect live health port never yield verified status.
4. Redacted audit can reconstruct coordinator → worker → tool → test → approval → land without transmitting private transcripts.
5. The security dashboard shows denominators and explicit unknown/missing-evidence states; no unsupported live-verification claims.
6. Existing valid read-only retrieval and normal tests continue working.

## Out of scope
Logging hidden model reasoning, storing full prompts by default, a separate SIEM, auto-remediating detected malicious activity or a new agent reviewer whose opinion substitutes for validation.

## AI-driven attack investigation amendment (2026-11-03)

Extend the provenance and poisoning-resistance fixtures to include AI-generated attack strings in Falco/Cloudflare logs, forged Slack and GitHub instructions, manipulated vector-search results and repeated model summaries that share a single root source. Preserve the distinction between observed attack behavior, a hypothesis about AI authorship, a validated exploit and an actual compromised system.

- Correlate runtime evidence from v1.62.0, public-path observations, cloud-bridge authorization denies and protected CI results with explicit source freshness and independent origins. Unknown or lost telemetry is not a negative finding.
- Add a security-case evidence graph using the existing durable incident record, not a second database or metric-label cardinality explosion: incident ID, source/digest, policy decision, tool request, execution outcome, notification result, analyst hypothesis, independent verification and disposition.
- Reject promotion of an agent's incident classification into tool execution rights. AI may recommend a response, but a separate deterministic authorization engine and operator-approval policy control high-impact actions.
- Measure detection coverage on predefined, harmless scenarios and provenance-validation failures; include simulated alert loss, time skew, replay, fabricated test PASS, source duplication and compromised-agent narrative.
- Keep redacted incident and denial evidence available to an independent off-hub watchdog when feasible under existing v1.55.0 scope; never send raw secret-bearing transcripts off host.

**Additional acceptance:** two AI agents agreeing on a poisoned event does not count as corroboration; a missing runtime sensor or stale GitHub evidence cannot yield a green security verdict; replaying a forged event cannot authorize containment.
