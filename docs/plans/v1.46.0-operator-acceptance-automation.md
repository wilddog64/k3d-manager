## Problem

Manual operator testing found failures across cloud job submission, log retrieval, metric publication, Grafana state
transitions and Slack cleanup help that source assertions and a green terminal suite had not caught. Today's tests check
dashboard JSON shape (`scripts/tests/bin/test_k3dm_tests_dashboard.py:32-149`) and push to a throwaway HTTP server
(`scripts/tests/bin/test_k3dm_test_metrics.py:180`); nothing replays a pass/fail sequence through a Pushgateway's
replace semantics and evaluates the panel queries over the result. This plan turns those checks into repeatable
scenarios with explicit oracles and evidence, piloted on the k3dm Tests dashboard.

The three bugs the 2026-11-12 draft called "pending" are all live-verified (2026-10-09) and become regression oracles:
[k3dm Tests history](../bugs/2026-10-07-k3dm-tests-failure-history-missing.md),
[last-success retention](../bugs/2026-10-07-test-metrics-last-success-lost-on-failure.md),
[cleanup reporting](../bugs/2026-10-07-slack-stale-sandbox-cleanup-misleading-reporting.md).

## Decisions (operator, 2026-11-26)

1. **Scope** — "Also opt-in live check": child A (offline runner and pilot), child B (opt-in live profile and local bug
   drafts), child C (docs). Rendered Grafana with Playwright, the document-index canary and git-branch bug filing move
   to `docs/ideas.md` (rows added 2026-11-26).
2. **Gaps the scenarios hit** — "File as bugs (Recommended)": the four gaps are captured, not fixed here. Children report
   them as `known_failing` contracts linked to the bug, never as passed and never by weakening an assertion:
   - [exporter exits 0 when the push fails](../bugs/2026-11-26-test-metrics-exporter-exits-zero-when-push-fails.md) (P3)
   - [summary panels take max() across targets](../bugs/2026-11-26-k3dm-tests-summary-panels-max-across-targets-hide-stale-test-all.md) (P3)
   - [stale-sandbox cleanup inherits an ambient CONFIRM](../bugs/2026-11-26-stale-sandbox-cleanup-inherits-ambient-confirm.md) (P2 proposed)
   - [`apply` accepted by the slash command, refused in a thread](../bugs/2026-11-26-cleanup-stale-sandbox-apply-accepted-by-slash-command-refused-in-thread.md) (P3)
3. **Panel evaluation without containers** (Claude, from Neon's split; Fable M5 shows `docker` is blocked by
   `scripts/tests/conftest.py:15-26` and `scripts/tests/tripwire.sh`): every k3dm Tests panel query is evaluated with
   `promtool test rules` over series built from the exporter's real output. promtool is already installed in CI
   (`.github/workflows/ci.yml:32-37`) and resolved locally by `scripts/tests/promtool.bash`.
4. **Where A runs** (Claude): A's scenarios run inside `make test-pytest` (so inside `test-all` and CI) through one
   pytest file, with a budget of 30 s wall time on the M4; `make test-operator-acceptance` runs the same runner and keeps
   the report directory. Reason: a harness outside the gate rots (the 2026-10-05 offline-test rot); 30 s is under 2 % of
   the ~15-minute `test-all`. promtool-backed scenarios report `inconclusive` (never `passed`) when promtool is absent,
   and the pytest wrapper skips them with that reason; CI always has promtool.
