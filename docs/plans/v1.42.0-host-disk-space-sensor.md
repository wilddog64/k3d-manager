This is the 5th v1.42.0 plan doc — the release cap. Anything further goes to v1.44.0.

## Why

Hub snapshots (~3.3 GB each) now land on the M2, which is also the e2e runner. The M4 runs the
hub's k3d nodes. Neither host's free space is measured anywhere. A full M2 breaks snapshot uploads
and e2e; a full M4 takes the hub down. Kube-prometheus-stack's node-exporter only sees the k3d
node containers, not the macOS data volumes.

## Design — reuse what exists

| Piece | Existing pattern to copy |
|---|---|
| collector | `bin/k3dm-vectordb-metrics` (pushes to Pushgateway, retries, non-fatal) |
| schedule | Hermes tick, every 300s (`bin/k3dm-hermes` `_poll` already calls `_publish_health_metrics`) |
| transport | hub Pushgateway via the existing port-forward, `http://localhost:19094` |
| rules | `scripts/etc/prometheus/rules/*.yaml` (applied by `observability.sh` line ~98) |
| SMS | Alertmanager: `severity=critical`, cluster not `acg|ubuntu-k3s` → `sms-critical`; `warning` → email |
| dashboard | `scripts/etc/argocd/platform-ops/grafana-dashboard-*.yaml` (auto-included by `grafana-dashboards-hub` AppSet) |

No new launchd job, no new port-forward, no new receiver.

## Changes

### 1. `bin/k3dm-disk-metrics` (new, Python 3, executable)

Mirror `bin/k3dm-vectordb-metrics`'s structure (retries, `PUSH_RETRIES`, non-fatal push failure,
exit 0 when the push is skipped).

- Targets from `K3DM_DISK_TARGETS`, default
  `m4=local:/System/Volumes/Data m2=m2jump:k3dm-snapshots`. Each entry is
  `<host-label>=<local|ssh-host>:<path>`.
- Probe: `df -Pk <path>` — locally via `subprocess.run([...])` (argv list, no shell), remotely via
  `ssh -o BatchMode=yes -o ConnectTimeout=10 -- <ssh-host> df -Pk <path>`. Timeout 30s each.
  Parse line 2: size = column 2 × 1024, avail = column 4 × 1024. Validate both are integers.
- Pushgateway URL: `K3DM_DISK_PUSHGATEWAY_URL`, default `http://localhost:19094`. Push to
  `/metrics/job/k3dm-disk` (one group; PUT so dropped targets disappear).
- Metrics (gauge), one series per target, labels `host`, `path`:
  - `k3dm_disk_size_bytes`
  - `k3dm_disk_avail_bytes`
  - `k3dm_disk_probe_success` (1/0). A failed probe emits only this series at 0 for that host.
- `--dry-run` prints the exposition text instead of pushing. Used by tests.
- No credentials involved. Do not read `~/.ssh` or pass `-i`.

### 2. Hermes calls it each tick

In `bin/k3dm-hermes`, next to `_publish_health_metrics`, add `_publish_disk_metrics()` that runs
`bin/k3dm-disk-metrics` with `capture_output=True, timeout=120, check=False`, swallowing
exceptions (same shape as `_publish_health_metrics`). Call it once per `_poll`.

### 3. `scripts/etc/prometheus/rules/host-disk.yaml` (new PrometheusRule)

Labels `release: kube-prometheus-stack`, namespace `monitoring`, group `host.disk`, interval 60s.
Used fraction = `1 - k3dm_disk_avail_bytes / k3dm_disk_size_bytes`.

| alert | expr | for | severity | route |
|---|---|---|---|---|
| `HostDiskSpaceLow` | used > `0.80` | 15m | `warning` | email |
| `HostDiskSpaceCritical` | used > `0.90` **or** avail < 20 GiB | 10m | `critical` | **SMS** |
| `HostDiskMetricsStale` | `k3dm_disk_probe_success == 0` for a host, or `time() - max(push_time_seconds{job="k3dm-disk"}) > 1800`, or `absent(k3dm_disk_size_bytes)` | 30m | `warning` | email |

All three carry `cluster: hub` (so critical routes to `sms-critical`, not `platform-warning`) and
`host` from the series. Descriptions name the host, the path, and the first action:
`m2` → "run make snapshot-prune / lower K3DM_SNAPSHOT_KEEP"; `m4` → "docker system df; prune
images". Keep descriptions short enough for an SMS gateway (one sentence each).

### 4. Grafana dashboard `scripts/etc/argocd/platform-ops/grafana-dashboard-host-disk.yaml`

ConfigMap in the style of `grafana-dashboard-alertmanager-delivery`, uid `k3dm-host-disk`, title
`k3dm Host Disk`:
- stat per host: used %, thresholds green < 80, orange 80–90, red > 90;
- stat per host: free GiB;
- time series: used % per host over the range, with 80/90 threshold lines;
- stat: probe status per host (up/down), and "last push" age.

  what is measured, the producer (Hermes tick → `k3dm-disk-metrics`), thresholds, what pages SMS.

### Change 1 — `bin/k3dm-disk-metrics`

**OLD:**
```python
DEFAULT_TARGETS = "m4=local:/System/Volumes/Data m2=m2jump:k3dm-snapshots"
```
**NEW:**
```python
DEFAULT_TARGETS = "m4=local:/System/Volumes/Data m2=m2jump:k3dm-snapshots hostinger=hostinger:/"


def _ssh_destination(host):
    if host != "hostinger":
        return [host]
    user = os.environ.get("HOSTINGER_SSH_USER", "ubuntu")
    address = os.environ.get("HOSTINGER_HOST", "srv1754834.hstgr.cloud")
    key = os.environ.get("HOSTINGER_SSH_KEY", str(Path.home() / ".ssh" / "hostinger"))
    return ["-i", key, "-o", "IdentitiesOnly=yes", f"{user}@{address}"]
```

**OLD:**
```python
        command = ["ssh", "-o", "BatchMode=yes", "-o", "ConnectTimeout=10", "--",
                   host, "df", "-Pk", path]
```
**NEW:**
```python
        destination = _ssh_destination(host)
        command = ["ssh", "-o", "BatchMode=yes", "-o", "ConnectTimeout=10",
                   *destination[:-1], "--", destination[-1], "df", "-Pk", path]
```
(For a plain alias `destination[:-1]` is empty, so the m2 command is byte-for-byte unchanged.)
