# v2.0.0 (scoping) — Ambient-only mesh: retire sidecar istio

**Status:** SCOPING ONLY — not scheduled. This is the reserved home for the one genuine
backward-incompatible break in the mesh story. Do NOT start implementation without an explicit
owner go-ahead and a follow-on task spec per touchpoint.

**Branch (when scheduled):** `k3d-manager-v2.0.0`

---

## Why this is 2.0.0 (and why the v1.16.0 ambient work was NOT)

The v1.16.0 milestone *added* ambient on the hostinger GitOps path. Sidecar istio still ships and
still runs for every local-dev provider and for Jenkins — nothing an existing user runs broke. That
is additive → minor bump. Correct semver for v1.16.0.

**This** milestone is the opposite: it *removes* sidecar mode and makes ambient the only mesh.
Anyone whose workload relied on `istio-injection=enabled` sidecar injection must re-onboard to
ambient (namespace `istio.io/dataplane-mode=ambient` labeling, no more sidecar containers). That is
a backward-incompatible break → major bump. This is the clean number for that break; do not spend
it earlier.

"Breakthrough" (impressive) ≠ "breaking" (existing invocation stops working). 2.0.0 signals the
latter.

## Scope of the pivot (each becomes its own task spec at schedule time)

1. Replace `_provider_*_configure_istio` sidecar install with ambient enrollment for k3d / k3s /
   orbstack local-dev providers (istio-cni + ztunnel + `istio.io/dataplane-mode=ambient` labeling),
   OR make mesh installation opt-in and default-off for local dev.
2. Remove `istio-injection=enabled` labeling of `default` ns from every provider.
3. Migrate Jenkins to ambient (drop `istio-injection: enabled` from `jenkins-namespace.yaml.tmpl`,
   ambient-label the Jenkins ns) or explicitly document Jenkins as mesh-exempt.
4. Retire `istio-operator.yaml.tmpl` + `istio_var.sh` if no longer referenced after (1)–(3).
5. Update BATS fixtures (`scripts/lib/test.sh:145`) to the ambient expectation.
6. Solve the single-appset design limit if v2.0.0 is meant to run ambient on more than one cluster
   (`istio-ambient.yaml` is keyed to one `${APP_CLUSTER_NAME}`).

## What NOT to do here / open decisions for the owner

- Do NOT start any of the above without owner go-ahead — this doc is a placeholder, not a work order.
- **Decision — local dev mesh:** do local k3d/orbstack clusters get ambient by default, or does
  mesh become opt-in for local dev? (Ambient's istio-cni + ztunnel is heavier than nothing on a
  laptop.)
- **Decision — Jenkins:** ambient-enroll vs mesh-exempt.
- **Migration note (MUST ship with the release):** document the sidecar→ambient re-onboarding steps
  for any existing user, since this is the breaking change 2.0.0 announces.
