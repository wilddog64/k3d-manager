## Problem

- E2E runs only when someone triggers it from Slack.
- The 2026-09-15 run failed 45/102 tests, and nobody would have known without looking. The 2026-08-27 run had also failed, 31 tests, unnoticed.
- The failures are grouped causes (a missing service, contract drift per spec file), but no one turns them into tracked bugs.

## Decisions (operator, 2026-09-15)

- **Schedule:** Wednesday and Saturday, 02:00 local time, on the M2 runner (`e2e_runner_dispatch m2`).
- **Triage:** rule-based. No LLM.
- **Bugs:** a `docs/bugs/` markdown file per new failure group, committed and pushed to the current release branch, plus a Slack triage summary. No GitHub Issues.

## Design

### Scheduling — inside the existing 5-minute poll

The Hermes LaunchAgent is installed by lib-foundation, which must not be edited here, so no second plist.

- `e2e_schedule.due_slot(now_local, claims_dir, schedule)` returns a slot id `YYYY-MM-DD`, or `None`.
  - **Due when:** today's weekday is in the schedule, `now.hour:minute >= 02:00`, and no final marker `<slot>.json` exists.
  - **Retry gating:** if a claim `<slot>.claim` exists, the slot is due again only when `attempts < 6` and `now >= next_try`.
  - **Catch-up:** a laptop asleep at 02:00 runs on wake, the same day.
- **Schedule config:** `K3DM_HERMES_E2E_SCHEDULE`, default `wed,sat@02:00`; strict parse, invalid → disabled plus one Slack notice per day. `K3DM_HERMES_E2E_ENABLED=0` disables.
- **State location:** claims and results live in `~/.k3dm/hermes/e2e/` (not `state.json`, so the detached child never races the poll's state writes).
- **In `_poll`, after paging:** if a slot is due, atomically create or refresh `<slot>.claim` (`os.open(O_CREAT|O_EXCL)` on first attempt; JSON `{attempts, next_try, pid}`). Then spawn:

  ```python
  subprocess.Popen([sys.executable, hermes_bin, "e2e", slot],
                   start_new_session=True, stdin=DEVNULL,
                   stdout=log, stderr=log)
  ```

  `log` is `~/Library/Logs/k3dm-hermes-e2e.log`. The poll never waits.
- **Stale runs:** a claim whose `pid` is still alive is never re-spawned. A claim older than 3h with a dead pid counts as a failed attempt.

### `k3dm-hermes e2e <slot|now>` subcommand

1. **Runner preflight:** run `scripts/k3d-manager e2e_runner_preflight m2` (argv list, `cwd=K3DM_REPO_ROOT`, timeout 120).
   - Non-zero → `attempts += 1`, `next_try = now + 30min`, and exit 0 (the poll retries).
   - At `attempts == 6`: write the final `<slot>.json` `{"outcome": "runner-unavailable"}` and post Slack `Hermes e2e <slot>: skipped — M2 runner unavailable after 6 attempts`.
2. **Dispatch:** `scripts/k3d-manager e2e_runner_dispatch m2` with timeout 5400s. Record `rc` and the start time.
3. **Result files:** read the newest `~/.k3dm/e2e/dispatch/m2-*.summary.json` and matching `.failures.json` with mtime ≥ the start time.
   - Summary missing → one `harness` group, target `dispatch`, carrying rc and the last 5 transcript lines, redacted.
4. **Triage:** `e2e_triage.triage(summary, failures)` → list of groups.
5. **Diff:** compare with the previous final marker's groups → `new`, `ongoing`, `resolved`.
6. **File bugs:** `e2e_bugs.file_bugs(repo_root, groups, run, slot)` → per group: `created` / `ongoing` / `reopened`, plus push status.
7. **Slack:** post via the existing `post_summary(_keychain_secret("k3dm-slack-webhook"), text)`, ≤ 3500 chars:
   - `Hermes e2e <slot> (run <run_id>, M2): PASS 102/102` or `FAIL — 12 passed, 45 failed, 45 skipped`;
   - one line per group: `[new|ongoing|reopened] <kind> <target> (<n> tests) → docs/bugs/<file>`;
   - `resolved: …`;
   - push status.
8. **Final marker:** write `<slot>.json` `{outcome, run_id, counts, groups:[{slug, kind, target, count}]}` and delete the claim.

`e2e now` runs steps 1–7 immediately with slot `manual-<UTC timestamp>` and no retries, for operator testing.

### Rule-based triage (`e2e_triage.py`, pure functions, stdlib only)

**`classify(failure)`** — first match wins, applied to `failure["error"]` and `failure["status"]`:

| # | Match | kind | target |
|---|---|---|---|
| 1 | `ECONNREFUSED\|ENOTFOUND\|EAI_AGAIN\|connect ETIMEDOUT` | `service-unreachable` | service from the port: `{8000: product-catalog, 8083: basket, 8080: order, 8084: payment}`, else `host-<port>` |
| 2 | status `timedOut` or `Timeout \d+ms exceeded` | `timeout` | spec slug |
| 3 | `Received: undefined`, `Cannot read properties of undefined`, `must have a length property`, `received value must be a number`, `toHaveProperty`, or `Expected: "number"` with `Received: "string"` | `contract-drift` | spec slug |
| 4 | anything else | `assertion` | spec slug |

- **Spec slug:** `api/cart.spec.ts` → `api-cart`.
- **`triage(summary, failures)`:**
  - group by `(kind, target)`;
  - if `summary["result"] == "fail"` and `failures == []` → one `harness` group with target = `summary["phase"]`;
  - `result == "pass"` → `[]`.
- **Each group keeps:** `count`, up to 10 test titles, and up to 3 distinct sample errors.
- **Slug:** `e2e-<kind>-<target>`, lowercased, only `[a-z0-9-]`, dashes collapsed, ≤ 60 chars.
- **Redaction, before anything is written or posted:** precompiled `re.sub` for `Bearer\s+\S+`, JWTs `eyJ[\w-]+\.[\w-]+\.[\w-]+`, and `(?i)(password|secret|token|api[_-]?key)["'=:\s]+\S+` → `<redacted>`.

Regression fixture — the real 2026-09-15 error strings — must yield:
- `service-unreachable/payment`;
- `contract-drift` for `api-cart`, `api-orders`, `api-cross-service`, and `api-products`.

### Bug filing (`e2e_bugs.py`)

**Where commits happen — a Hermes-owned worktree only, never the operator's tree:**
- `~/.k3dm/hermes/bugs-worktree`, created if missing with `git -C <repo> worktree add --detach <path>`.
- **Branch** = `git -C <repo> branch --show-current`, which must match `^k3d-manager-v\d+\.\d+\.\d+$`. Otherwise file nothing and report `bugs not filed: repo not on a release branch`.
- **Before writing:** `git -C wt fetch origin <branch>` then `git -C wt checkout --force --detach origin/<branch>`.

**Dedup** (CLAUDE.md rule), against the fetched tree: `glob docs/bugs/*-<slug>.md`.
- **None →** create `docs/bugs/<slot date>-<slug>.md`.
- **Match with a `**Status:**` not starting with `FIXED` or `CLOSED` →** `ongoing`; write nothing.
- **Match that is `FIXED`/`CLOSED` →** `reopened`:
  - append `## Recurrence <date> (run <run_id>)` with count, titles, and samples;
  - set its Status line to `REOPENED <date> — recurred in Hermes e2e run <run_id>`;
  - never create a second file.

**Bug doc template:**

```
# Bug: e2e <kind> — <target>

**Branch:** `<branch>`
**Filed:** <date> by k3dm-hermes
**Status:** OPEN — Hermes rule-based triage; unverified
**Run:** `<run_id>`, runner `m2`, tier `vcluster`, <passed> passed / <failed> failed / <total> total
**Runner commit:** `<summary.commit>`

## Failing tests (<count>)
- `<file>` — <title>          (max 10, then "…and N more")

## Sample errors
- <redacted sample>           (max 3)

## Triage hint
<static text per kind>

## Next step
A human (or Claude) verifies the root cause, then writes the fix spec here before any code change.
```

Static triage hints:
- `service-unreachable`: the service is not in the Tier 1 substrate or never became ready; check `scripts/etc/e2e/kustomization.yaml` and the rollout wait list.
- `contract-drift`: the response shape differs from the test's expectation; compare the substrate image pin with the `shopping-cart-e2e-tests` image and the service's API.
- `timeout`: check substrate readiness and runner load (`make e2e-runner-health RUNNER=m2`).
- `assertion`: a behaviour change; read the failing test.
- `harness`: the run did not reach Playwright; read the dispatch transcript.

**Commit and push:**
- `git add -- <each changed docs/bugs path>`, then `git commit -m "docs(bugs): Hermes e2e triage <slot> (run <run_id>)" -m "Filed-By: k3dm-hermes"`.
- Then `git push origin HEAD:refs/heads/<branch>`.
- **Push rejected (non-fast-forward):** one `fetch` + `git rebase origin/<branch>`, then retry the push once. Still failing → leave the commit in the worktree and report `push failed: <first stderr line, redacted>`.
- **Pre-commit hook failure:** report `commit blocked by pre-commit: <first line>`, and leave the files uncommitted in the worktree.
- **No changed files:** no commit.
- **Subprocess rules:** all git calls are argv lists with a timeout of 120s. Never `--force` on push, never `--no-verify`, never `main`, never the operator checkout.

## Tests

**`test_e2e_schedule.py`:**
- Wed 01:59 → not due; Wed 02:00 → due; Thu → not due; Sat 23:30 with no marker → due (catch-up).
- Final marker present → not due.
- Claim with `attempts=6` → not due; `next_try` in the future → not due.
- Live-pid claim → not re-spawned; dead-pid claim >3h → counts as an attempt.
- Invalid schedule string → disabled.
- `K3DM_HERMES_E2E_ENABLED=0` → disabled.
- `_poll` spawns via `Popen(..., start_new_session=True)` (monkeypatched) and returns without waiting.

**`test_e2e_triage.py`:**
- Each rule, using the real 2026-09-15 strings.
- Port → service map.
- Grouping of the regression fixture into the 5 expected groups.
- Pass → `[]`; fail with no failures → `harness/<phase>`.
- Slug sanitisation, including `../` and spaces.
- Redaction of Bearer, JWT, and `password=`.
- The diff reports new/ongoing/resolved.

**`test_e2e_bugs.py`**, using a temp bare origin + clone on branch `k3d-manager-v9.9.9`:
- New group → file created, committed, pushed to that branch, and only `docs/bugs/` touched.
- Existing OPEN slug → `ongoing`, no commit.
- Existing FIXED slug → recurrence appended, Status `REOPENED`, same path.
- Repo on `main` → nothing filed, reason reported.
- Diverged origin → rebase once, push succeeds.
- The worktree path is not the repo path.
- The template contains no sentinel secret from a failure's error text.

**`test_hermes.py`** (or a new test): the `e2e now` subcommand with preflight, dispatch, triage, filing, and Slack monkeypatched posts one summary and writes the final marker. Preflight failure increments attempts and posts nothing until attempt 6.

## What NOT to do

- Do not run a real dispatch, preflight, `ssh`, `git push` to GitHub, or Slack post in tests. Use temp repos and fakes only.
- Do not commit from or modify the operator's checkout.
- Do not push to `main`; do not `--force` or `--no-verify`.
- Do not open GitHub Issues.
- Do not call an LLM.
- Do not put credentials, tokens, or unredacted error text in bug docs, Slack, or logs.
- Do not edit `scripts/lib/foundation/` or `scripts/lib/acg/`, or the Hermes plist template.
- No PR, no merge. No `git add -A`, no `git stash`.
