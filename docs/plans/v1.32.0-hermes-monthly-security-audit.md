## 1. Goal

Give Hermes a **once-a-month, read-only security posture audit** that posts a single digest to Slack:
open code-scanning / Dependabot alerts, branch-protection posture, credential expiry, and (optionally) the
in-repo security regression status. It is a **report, not an actuator** — it changes nothing, proposes
nothing, and never touches the repair path. It closes the loop the one-off 2026-09-07 webhook audit opened:
posture drifts silently between manual reviews; a monthly nudge surfaces regressions (a re-opened alert, a
weakened protection rule, a token nearing expiry) while they are cheap to fix.

## 2. Cadence — reuse the advisory pattern, no new timer

Hermes already fires a **once-per-day** token-expiry advisory that is deduped via `state` and runs inside the
existing poll cycle (not a correlator sensor). The monthly audit uses the **same mechanism at monthly
granularity**:

- On each poll, compute `this_month = timestamp()[:7]` (`YYYY-MM`).
- If `state.get("last_security_audit_month") != this_month`, run the audit, post the digest via
  `post_summary(relay, digest)`, then set `state["last_security_audit_month"] = this_month`.
- Deterministic, no extra launchd job, survives restarts (state is persisted). First poll of each calendar
  month fires it once; every later poll that month is a no-op.

A manual trigger is also added: **`bin/k3dm-hermes audit`** runs the audit immediately and prints the digest
(JSON + human text), without touching the monthly dedup stamp — for on-demand checks and testing.

**Alternative considered (documented, not chosen):** a dedicated `StartCalendarInterval` launchd job. Rejected
for v1 — it adds a second agent + plist to maintain and duplicates the poll's credential loading. Revisit only
if the audit must run independently of the monitoring cadence.

## 3. What it audits (checks)

All checks are **read-only**. Group A is API-only (no repo/host coupling) and is the core; Group B is optional
and repo-local.

**Group A — GitHub API (read-only):**
1. **Code-scanning (CodeQL) alerts** — `GET /repos/{owner}/{repo}/code-scanning/alerts?state=open`, count by
   severity (critical/high/medium/low). Flag any open critical/high.
2. **Dependabot alerts** — `GET /repos/{owner}/{repo}/dependabot/alerts?state=open`, count by severity. (The
   push output already shows "1 high" on dependabot/9 — exactly the kind of thing this should surface monthly.)
3. **Branch-protection posture** — `GET /repos/{owner}/{repo}/branches/main/protection`: assert
   `enforce_admins.enabled == true`, `required_pull_request_reviews.required_approving_review_count >= 1`, and
   the "main" ruleset still enforces `deletion` + `non_fast_forward`. Report any drift from the expected posture.
4. **Credential expiry sweep** — extend the existing `token_expiry_advisory` logic to report days-to-expiry for
   every Hermes-held credential that exposes an expiry (the `k3dm-hermes-gh-token` PAT via the
   `github-authentication-token-expiration` header; note which are classic no-expiry). Purely informational in
   the monthly digest (the daily advisory still handles the urgent within-window warning).

**Group B — repo-local regression status (OPTIONAL, phase 2):**
5. **Security regression tests** — run the webhook security BATS subset (the F1/F3/F2 sandbox/role/host tests
   in `scripts/tests/lib/webhook.bats`) and report pass/fail. Couples Hermes to repo layout + `bats`, so gate
   it behind `K3DM_HERMES_AUDIT_RUN_BATS=1` and ship it after Group A. Report "skipped" when disabled.

## 4. Credentials / scopes — the key prerequisite (resolve before slice 1)

Hermes today holds a **read-only** posture: a GET-only webhook bearer, a get-only ArgoCD account, and the
`k3dm-hermes-gh-token` PAT which carries **`actions:write` only** (for R4). Group-A checks need scopes that PAT
likely does **not** have:

- code-scanning + dependabot alerts → `security_events: read` (or `repo` on a classic PAT).
- branch-protection read → `administration: read` (repo admin).

**Decision needed:** either (a) add a **separate, dedicated read-only audit PAT**
(`k3dm-hermes-audit-token`, `security_events:read` + `administration:read`, no write anywhere) — the
least-privilege, cleanest option, keeps the R4 token single-purpose; or (b) widen the existing token (rejected —
mixes read-audit with write-repair scope on one credential). **Spec recommends (a).** Whichever check lacks a
scope must **degrade gracefully** — report "unavailable: token lacks `security_events:read`" rather than
crashing the poll (fail-open on availability, never fabricate a clean bill of health). See
`reference_hermes_r4_github_app_rejected` for the personal-repo scope constraints that killed the R4 App path —
verify the audit scopes are actually obtainable on a fine-grained PAT before committing to (a).

## 5. Report format (Slack digest)

One message, posted via the existing `post_summary`. Example shape:

```
🛡️ Hermes monthly security audit — 2026-09 (wilddog64/k3d-manager)
Code scanning: 0 critical, 0 high, 2 medium open
Dependabot:    0 critical, 1 high open  ⚠️  (#9)
Branch protection: enforce_admins=on, reviews=1, ruleset ok  ✅
Credentials: k3dm-hermes-gh-token expires in 88d; webhook/argocd = no expiry
Security regressions (bats): skipped (K3DM_HERMES_AUDIT_RUN_BATS unset)
Overall: 1 item needs attention → dependabot #9
```

Include a one-line "needs attention" verdict so a clean month is a glance. Keep it bounded (no raw alert
bodies — link by number). Redact nothing sensitive is present, but never echo token values.

## 7. Testing

- **pytest** `scripts/tests/hermes/test_audit.py` — inject a stub `github_get` returning canned alert lists +
  protection JSON; assert severity counts, protection-drift detection, graceful "unavailable" on a 403/404
  scope error, and that the digest text renders the verdict. Follow `test_preflight.py` DI style.
- **Monthly dedup** — unit test the `main` gate: same month → no second post; month rollover → one post; state
  persisted.
- **Manual subcommand** — `bin/k3dm-hermes audit` returns the report without mutating `last_security_audit_month`.
- **Invariant** — audit performs no writes: assert `run_audit` makes only GET/HEAD calls (stub raises on any
  non-GET) and never imports or calls `repairs`.

## 8. Non-goals

- No remediation, no proposals, no repair-path involvement (report only).
- No new inbound surface (Hermes stays outbound-only).
- Not a replacement for CI CodeQL/Dependabot — it **summarizes** their state on a monthly beat, it does not
  re-scan.

## 9. Phasing

1. **Group-A audit module + manual `bin/k3dm-hermes audit`** + pytest (stubbed). No poll wiring yet.
2. **Monthly poll wiring** (state dedup) + Slack digest + dedup tests.
3. **Credential scope** — provision the read-only audit token (decision §4a), wire the real calls, live check.
4. **Group-B (optional)** — bats regression status behind `K3DM_HERMES_AUDIT_RUN_BATS=1`.
5. **Docs + setup.**

- **Cadence mechanism:** monthly state-dedup in the poll (recommended) vs. a dedicated launchd calendar job.
