## Problem

Operators upgrading to v1.45.1 must know that a deploy now refuses an istioctl of another minor (Homebrew 1.32.0 on
m2-air, 1.30.0 on m4-air) and how to fix it before their next `hub-up`, `make dr-drill` or cluster deploy.

`### Fixed` subsection, matching the file's heading and bullet style. If another v1.45.1 child already added it, reuse
it. The entry says:

1. istioctl is now pinned to 1.31.4 (lib-foundation v0.5.8, split into helpers in v0.5.9), downloaded from the Istio release archive and checked
   against its SHA-256; the master `downloadIstioCandidate.sh` path is gone.
2. An existing istioctl of another minor is refused with an ERROR naming its version and path. Fix: `brew unlink istioctl`
   (or remove it from PATH) and rerun, or set `ISTIOCTL_VERSION` deliberately.
3. Operator action before the next deploy on m4-air (istioctl 1.30.0) and m2-air (Homebrew 1.32.0): see the parent's
   Rollout survey.
4. A link to the parent bug doc.
