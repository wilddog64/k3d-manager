## Why

`make up` hides the sandbox, cluster, tunnel, hub, Vault, ESO, ArgoCD and observability steps behind one command, and the operator wants to keep it. This plan adds a switch that builds the same platform without the shopping-cart app. The later plug-in plan turns the switch into `APP=<name>`, and the interface the operator types stays the same.

## Behaviour

### 1. Interface and the Makefile

- `make up APP=none` builds the platform without shopping-cart. `make up` (APP not given on the command line) and `make up APP=shopping-cart` behave exactly as today.
- New script `bin/k3dm-up-app-check` (`set -euo pipefail`, under 40 lines). It is called as the **first** line of `up:` with `"$(CLUSTER_PROVIDER)" "$(origin APP)" "$(APP)"`.
  - It only looks at APP when `$(origin APP)` is `command line`. A stray exported `APP` in the environment is ignored, so `make up` never breaks because of it.
  - Allowed command-line values: `shopping-cart` and `none`. Anything else exits 2 with `APP must be 'shopping-cart' or 'none'`.
  - With `APP=none` and a provider whose `up:` branch does not run `bin/cluster-up` (`k3d`, `k3s-oci`, `k3s-hostinger`; `Makefile:173-176`), it exits 2 with `APP=none applies only to the ACG cluster-up providers (k3s-aws, k3s-gcp, k3s-az)`.
  - Otherwise it prints the value to pass as `K3DM_APP`: the command-line value, or nothing.
- The cluster-up branch (`*)`, `Makefile:177`) passes `K3DM_APP` set to that output. When APP was not given on the command line, `K3DM_APP` is left as it was in the environment, not overwritten with an empty value.
- Do **not** add `APP ?=` / `APP :=` / `APP =` at top level. `APP` is the required argument of `fix-restart`, `fix-delete-pod`, `fix-sync` and `fix-force-sync` (`Makefile:1464-1484`).
- `make hub-up APP=none` and `make hub-recover APP=none` fail through the same check (they run `up` with `CLUSTER_PROVIDER=k3d`). That is intended.
- `make help` for `up` mentions `APP=none`.

### 2. `bin/cluster-up`: resolving the app

- New function `_acg_resolve_app`. It runs on the provisioning path only, after argument parsing and after the `--trust-vault-ca` early exit (`bin/cluster-up:460` and the code that acts on it), and before Step 0.
  - `K3DM_APP` empty or `shopping-cart` → shopping-cart; `none` → none; anything else → `_err "K3DM_APP must be 'shopping-cart' or 'none'"`.
  - `none` with `ARGOCD_APP_CLUSTER_SHOPPING_CART=true` already in the environment → `_err` (conflict).
  - Under `none`, it exports `ARGOCD_APP_CLUSTER_SHOPPING_CART=false`. Leave `bin/cluster-up:1003` byte-identical: it is pinned by `scripts/tests/bin/cluster_up.bats:785`, and its `:-true` default then yields `false` under none. On the default path an explicit `ARGOCD_APP_CLUSTER_SHOPPING_CART=false` stays honoured, as today.
- **Persistence, so resume cannot flip the label.** Write the resolved app to `${_ACG_STATE_DIR}/app`, beside the checkpoints (`_ACG_CHECKPOINT_DIR`, `bin/cluster-up:119`), before Step 0.
  - When `K3DM_RESUME` is set and `K3DM_APP` is empty, use the stored value. The Slack/webhook resume (`scripts/lib/webhook/lifecycle.py:363-365`) never passes APP.
  - When both are set and they differ → `_err` with both values.
  - The checkpoint clear at `:490` also removes `app`.
- `_acg_app_step <step-id>`: returns 0 when the step should run. Under none, for a §3 step id it logs `[acg-up] <step-id> — skipped (APP=none)` once and returns 1. Every §3 guard calls it with a fixed step id. Don't scatter string comparisons.

### 4. Kept under `APP=none`

- **Platform pieces of the wrappers, called directly from `bin/cluster-up` under none, in the same order and with the same Step log lines:**
  - `shopping_cart_create_vault_bridge` (Step 6);
  - `shopping_cart_install_helm_and_eso` (Step 8);
  - `shopping_cart_apply_vault_token_and_cluster_secret_store` (Step 9).
  - The default path still calls the two wrappers, unchanged.
- Steps 0–4c, 7, 10 (registration, with the label `false`), the argocd-redis secret, 10f's `default-gateway` apply, 10g.11 Grafana, 10h tunnel, 11 ClusterSecretStore, 12 TTL watcher, 14/14b/14c observability.
- `/etc/hosts` entries (`:820-822`): unchanged. `argocd.shopping-cart.local` is the ArgoCD browser host.
- Providers: registration, TTL and remote observability run only for k3s-aws today. GCP and Azure exit earlier (`bin/cluster-up:909`), so they keep that behaviour under none as well.

### 5. ArgoCD label (the contract)

With the label `false`, the two ApplicationSets that select on it generate nothing for the cluster:
- `data-git.yaml:16`;
- `services-git.yaml:28`.

`eso` and `grafana-dashboards-acg` deliberately do not select on it (`argocd_app_cluster_generator.bats:53-55`). The label-independent deploy paths (`deploy_shopping_cart_data`, the identity Application, `register_shopping_cart_apps`) are all in §3.

### 6. Reused hub

APP=none does not delete anything on the hub. If shopping-cart Applications that target the app cluster already exist on the hub from an earlier run (for example the `shopping-cart-apps` parent or the identity Application), they can keep deploying to the new cluster. Under none, after Step 10, `bin/cluster-up` lists the hub Applications whose destination is the app cluster and whose name or labels mark them as shopping-cart (`app.kubernetes.io/part-of: shopping-cart` or a `shopping-cart` name prefix). For each one it prints a `_warn` with its name and the delete command. It never deletes them.

### 7. Docs

The README section (or the `docs/howto/` page) that documents `make up` gets one paragraph covering:
- APP=none and what it skips and keeps;
- the reused-hub warning;
- the Known limits.

### Known limits (record, do not fix)

- `bin/cluster-refresh` (`:512`, `:532`) still reinstalls the Keycloak and frontend port-forward wrappers. They fail quietly with no app. `bin/cluster-preflight:493` and `make sync-apps` assume shopping-cart. The plug-in plan makes these app-aware.
- On a fresh hub (Step 3.6 bootstrap) with none, ArgoCD gets admin login only: no Keycloak SSO or RBAC config, because 10c–10f are skipped. On a persistent hub the existing SSO config stays.
- Fresh Slack `/acg-up` runs default to shopping-cart. Only resume honours the stored app.

## What NOT to Do

- Do not change behaviour when APP is not given or is `shopping-cart`. No step reordering, no renamed log lines.
- Do not edit `shopping_cart.sh`, `argocd.sh`, the ApplicationSets, `bin/cluster-refresh`, `bin/cluster-down` or `lifecycle.py`.
- Do not delete hub Applications.
- Do not run `make up`, `make down`, `make -n <lifecycle target>`, or `bin/cluster-up` unstubbed. Test the Makefile wiring through `bin/k3dm-up-app-check`. For `up:`, check only that the recipe's first line calls it (structural), and run that one line with `make --dry-run` only inside a scratch copy of a 3-line Makefile, never the repo Makefile.
- Do not push, open a PR or skip hooks. Leave changes uncommitted.
