# v1.45.1 — Codex model routing and end-to-end dispatch efficiency

**Status:** PROPOSED — specification only; not dispatched
**Approval:** Operator requested a spec on 2026-10-13; no approval to change the runtime model or enable automatic escalation.
**Milestone:** v1.45.1 (third of five plan slots)
**Branch for implementation:** `k3d-manager-v1.45.1`, cut from `main` after v1.45.0 merges; never implement on `main`.
**Depends on:** v1.43.0 worktree-isolated Codex dispatch and its ledger; v1.43.2 per-spec Agent Dispatch dashboard/metrics fixes must land before implementation.
**Default:** Preserve the operator's local `~/.codex/config.toml` default (`gpt-5.6-luna` at time of filing), without writing to that file.
**Intent:** Claude may *propose* using Astra for unusually difficult work, but model changes require explicit operator approval until enough comparative evidence exists.

## Problem

`bin/k3dm-codex-dispatch` invokes `${K3DM_CODEX_BIN:-codex} exec` and `exec resume` without a `--model` override. This inherits the local CLI default, so historical runs cannot be reliably attributed to Luna or Astra after the operator changes their configuration. The existing agent-dispatch ledger tracks tokens, landing outcomes and some timings, but it cannot measure whether a more capable model reduces Claude's review, correction and total engineering effort. The operator observes that Astra consumes quota faster and wants to use it only when implementation complexity justifies it.

## Scope / contracts

1. **Explicit opt-in model override.** Add optional `--model MODEL` to `bin/k3dm-codex-dispatch start`. An omitted flag must preserve existing CLI-default behavior. Do not change `~/.codex/config.toml`, automatically upgrade models, or hard-code Astra as default. An operator-configured allowlist maps approved aliases to exact CLI model identifiers (do not guess the Astra CLI model ID). Reject empty, unknown, shell-special, or unapproved values before creating a worktree. Never interpolate a model identifier into `eval` or `sh -c`.
2. **Resume continuity.** Persist the requested model in the private task run directory and pass it explicitly to `codex exec resume` when set. Resumes must use the original selected model; changing model requires an explicit new task, not silent switching. For no-override legacy tasks, preserve the original unpinned behavior and report it as unknown unless the recorded run metadata verifies the model.
3. **Verified model identity.** Capture both `requested_model` and `effective_model` when the Codex CLI/session output reports the latter. The effective model must be parsed from documented machine-readable output where possible, with safe fallback `unknown`; never infer historical model solely from the current config. Record whether the model was explicitly selected, inherited, or unverified. Do not store credentials, prompts, or full model output in metrics.
4. **Claude escalation policy.** Claude starts with the configured default; for unusually challenging specs it may recommend Astra, explaining why a stronger model might reduce retries and review burden. No arbitrary complexity scoring or automatic switching in this release. Escalation requires explicit operator approval and the exact approved model identifier. Never re-dispatch merely to consume more tokens.
5. **End-to-end task evidence.** Extend the existing dispatch `ledger.jsonl` with backward-compatible `model_selected`, `codex_exit`, `resume`, `land` and `land_refused` metadata as appropriate. Track per-task model, input/output/cached tokens when the CLI actually reports them, execution duration, resume count, land-test refusal count, verified landing outcome, and number of rework/review iterations that can be measured objectively. Mark unavailable values `unknown`/null, not zero. Do not invent Claude review token consumption: support a separately sourced, explicitly attributed review metric only if reliable per-task evidence exists; otherwise display `N/A`.
6. **Grafana/Prometheus.** Extend existing `bin/k3dm-dispatch-metrics` and the Agent Dispatch dashboard with model labels of bounded cardinality (allowlisted model IDs, release, status; avoid prompt text/session IDs as metric labels). A per-spec table must show model, tokens, elapsed time, resumes, land attempts, and outcome. Summaries by model show first-pass land success, mean/median duration where computable, and reported token consumption. Label any dollar cost as **API-equivalent estimate**, never subscription cost or weekly quota usage. Flat-rate quota consumed remains **unavailable** unless a real supported meter exists. Preserve existing dashboard panels and data series.
7. **Data integrity.** Do not double-count resumed Codex sessions: Codex may report session-total rather than incremental tokens. Use the latest verified cumulative total per task or valid deltas only; record the method. Make writes atomic where applicable, tolerate partial/old ledgers, and prevent failed parse or metric pushes from disrupting execution/landing.
8. **Safety.** Preserve per-task worktree isolation, scope enforcement, landing lock, mandatory test/no-test choice, network exclusivity, and current approval policy. The model flag must not widen permission to execute commands or modify files. No calls to paid APIs solely to identify a model or test the exporter.

## Definition of Done

- [ ] With no `--model`, emitted Codex argv is unchanged from pre-fix behavior (test uses a stub; no real model call).
- [ ] An explicit approved `--model` reaches both initial `codex exec` and `codex exec resume`; a disallowed model exits before worktree creation.
- [ ] Existing in-flight and historical runs remain readable; missing identity becomes `unknown`, not an invented Luna/Astra value.
- [ ] Stubbed sessions with two resumes and cumulative token totals publish *one* correct task total; malformed/absent usage does not publish zero as measured use.
- [ ] A task whose landing tests fail never counts as a successful landing. Subsequent successful landing is attributed correctly with its refusal count.
- [ ] Model metrics and Grafana preserve existing panels, expose no secret/prompt data and avoid unbounded labels.
- [ ] Tests verify that no model switch weakens scope, sandbox, network, locks, or required landing verification.
- [ ] Use offline negative tests for each failure path (unknown model, invalid input, missing metadata, malformed usage, failed push).
- [ ] Run existing dispatcher/metrics tests plus the repository's ordinary lint, agent-audit and applicable full regression suite; record commands, counts and failures.
- [ ] Operator may compare Luna/Astra on several **similarly difficult** tasks; dashboard warns that non-random assignment of hard tasks to Astra biases simple averages. No unsupported claim of model superiority.
- [ ] Record the actual implementation commit, evidence and dashboard verification in Git/memory-bank when implemented; do not claim live proof from tests alone.

## Acceptance scenarios

**A — routine:** Without a model override, the dispatcher uses local Codex defaults, writes an inherited/unknown identity unless directly verified, and performs an ordinary gated landing.

**B — challenging:** Claude recommends Astra with a short rationale, operator approves the exact identifier, and dispatcher pins it for start and resume; Grafana reports actual task usage and the landing result.

**C — failure:** Astra task fails verification, then resumes. Its cumulative tokens are counted only once, retry/land-refusal counts increase correctly, and the dashboard does not show success before actual landing.

**D — historical:** Old ledger with no model field still renders without failure or invented model attribution.

**E — unavailable quota:** The dashboard never equates API-priced usage with flat-rate subscription quota or promises a weekly-quota number that the CLI cannot supply.

## Non-goals

Automatic AI model selection, self-escalation, model benchmarking on live production infrastructure, buying API credits, changing subscription configuration, replacing Claude's review, and embedding a generalized multi-agent scheduler.
