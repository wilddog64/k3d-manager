# v1.41.0 — Link-enriched `find-similar-docs` results

**Status:** DONE `a4996800` (Claude-verified 2026-10-03)
**Target branch:** `k3d-manager-v1.41.0`

## Problem

`/k3dm find-similar-docs Q=...` and `make find-similar-docs Q=...` return document paths and
similarity scores, but a reader must manually locate the repository and branch before opening a
result. This is especially inconvenient in Slack, where the result should be immediately
actionable.

## Goal

Keep retrieval and ranking unchanged, but add a clickable GitHub URL for every result. A result must
remain useful in a terminal, Slack, and `--json` automation.

## URL contract

For a result path `docs/bugs/example.md`, emit a URL of the form:

```text
https://github.com/wilddog64/k3d-manager/blob/<branch>/docs/bugs/example.md
```

The branch is resolved in this order:

1. explicit `K3DM_DOCS_BRANCH`, when set;
2. the current checkout's branch when it is a valid `k3d-manager-vX.Y.Z` release branch;
3. `main` as the safe public fallback.

The repository base URL must be configurable through `K3DM_DOCS_REPO_URL`, defaulting to
`https://github.com/wilddog64/k3d-manager`. URL path components must be percent-encoded as needed,
while the branch is shell- and URL-safe validated before interpolation. Never construct a link from
untrusted query text.

## Output behavior

The existing score, path, and title remain unchanged. Add the URL without changing result ordering.

Human-readable output should remain terminal-friendly and Slack auto-linkable, for example:

```text
  0.873  docs/bugs/example.md
         https://github.com/wilddog64/k3d-manager/blob/k3d-manager-v1.41.0/docs/bugs/example.md
         Example title
```

`--json` must add a `url` field to each result while retaining `score`, `path`, and `title`:

```json
{"score": 0.873, "path": "docs/bugs/example.md", "title": "Example", "url": "https://..."}
```

If retrieval is unavailable or returns no documents, preserve the current advisory behavior and do
not emit a fabricated link. The command must continue to exit 0 in those cases.

## Scope

Expected files:

- `scripts/find-similar-docs.py` — branch/repository resolution and text/JSON formatting;
- `scripts/tests/bin/test_find_similar_docs.py` — offline output and fallback coverage;
- `docs/howto/find-prior-art.md` — document the link and branch override;
- `CHANGELOG.md` and `memory-bank/` on completion.

Do not change the vector search algorithm, embedding/indexing behavior, Slack relay parser,
permissions, or the `/ask-docs` proposal. Slack should receive the same command output; no second
Slack posting path is needed.

## Tests

Add offline tests that stub `search()` and assert:

1. human output contains the expected branch-pinned URL;
2. JSON output contains `url` and preserves the existing fields;
3. `K3DM_DOCS_BRANCH` overrides checkout branch;
4. a non-release checkout falls back to `main`;
5. `K3DM_DOCS_REPO_URL` changes only the repository base;
6. path/title/query text cannot inject into the URL; and
7. retrieval unavailable and empty-index behavior remains unchanged and exits 0.

Run the focused Python tests, `make test-pytest`, `python3 scripts/check-doc-links.py`, and the
repository agent gates. Tests must not call the network, read the host Keychain, or require the
vector store.

## Completion criteria

- Every returned document has a directly clickable GitHub URL in terminal and Slack output.
- JSON consumers receive the same URL in a stable `url` field.
- Links point to the branch that was searched or the explicit safe fallback.
- Retrieval remains advisory and unavailable retrieval never becomes a new failure mode.
