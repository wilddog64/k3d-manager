# v1.39.0 — Slack Q&A over the documentation corpus

**Target branch:** `k3d-manager-v1.39.0`
**Status:** QUEUED. **Hard-blocked on v1.38.0 WS5 publishing a measured recall@5.**
**Filed:** 2026-09-23, on operator direction, so the idea is not lost between releases.

---

## Why this spec exists

v1.38.0 builds a retrieval layer (`scripts/lib/hermes/prior_art.py`, `search(text, k=5)`) and gives
it exactly one caller: Hermes, appending a `## Possible prior art` section to newly filed bug docs.
A library with one caller has not been shown to be a library.

This release adds the second caller, and it is deliberately the *easy* one:

| | Hermes (v1.38.0 WS4) | Slack Q&A (this release) |
|---|---|---|
| Query source | machine, slug-derived | human, conversational |
| Vocabulary | matches the corpus | frequently does **not** |
| Failure mode | silent — a suppressed filing | loud — a person reads a bad answer |
| Audit | none at query time | a human, in the same second |

The vocabulary mismatch in the right-hand column is the entire reason semantic retrieval was
proposed. Hermes' queries are the *least* representative traffic the retriever will ever see. Slack
is where the design assumption actually gets tested, and it tests it with a human reading every
result. Ship the forgiving consumer before the unforgiving one.

### What already exists — do not rebuild it

`docs/plans/v1.6.0-slack-ai-analysis.md` already established this exact path end to end:

```
Slack slash command → Cloudflare Worker (validates signature, routes) → k3dm-webhook
                                                                             ↓ async job
                                                                        Slack response_url
```

and `/api/v1/analyze` already calls the Claude API from `k3dm-webhook` and posts the result to
Slack. `workers/slack-relay/index.js`, the signature validation, the `response_url` async pattern
and the 3-second-ack discipline are all in place, with
`scripts/tests/plugins/slack_slash_commands.bats` and `scripts/tests/plugins/slack_relay_ack.bats`
covering them.

**This release is a new handler on proven infrastructure.** If the implementation starts adding
Worker plumbing, signature code, or a second Slack posting path, it has gone wrong.

## Blocking precondition — do not start without this

v1.38.0 WS5 must have run and published **recall@5 for both the embedding scorer and the stdlib
TF-IDF control**, per directory.

- If embeddings did not beat the lexical control, **this release uses the control.** That is not a
  downgrade; it is the measurement being allowed to decide, which is the entire point of WS5.
- If neither scorer clears its floor, **this spec does not ship.** A Q&A bot on a retriever known
  not to retrieve is worse than no bot, because it launders a bad answer through a confident
  presentation. Escalate to the operator rather than lowering the floor.

Record which scorer was chosen, and the number that chose it, in the guide.

## WS1 — The `/ask` slash command

- New command `/ask <question>` in the relay, routed exactly as the existing commands are.
- Update the Slack app manifest **in the same commit** as the relay change.
  `docs/bugs/2026-07-01-slack-slash-command-manifest-is-out-of-sync-with-relay-code.md` and
  `2026-07-01-slack-manifest-drift.md` are both this repo, both this failure. The manifest drifting
  from the relay is a known, twice-filed defect — do not make it three.
- Ack within 3 seconds, answer via `response_url`. Retrieval plus a model call will exceed the
  Slack timeout; the ack path already exists and is tested.

## WS2 — The handler

New endpoint in `bin/k3dm-webhook`, following `/api/v1/analyze`'s structure:

1. Retrieve top-k documents via v1.38.0's `search()`. **No model call yet.**
2. If retrieval is unavailable or returns nothing above the floor, reply with exactly that — "no
   matching documents" — and **stop**. Do not fall through to an unretrieved model answer. An
   ungrounded answer that looks identical to a grounded one is the failure this whole design is
   organised against.
3. Otherwise, pass the retrieved excerpts to Claude with an instruction to answer **only** from
   them, and to say when they do not contain the answer.
4. Reply with the answer followed by the source list.

**Every answer carries its sources.** File paths, always, no exceptions, including when the model
says it does not know. The sources are the part a human can verify; the prose is the part they
cannot. If a formatting constraint forces a choice, drop prose and keep paths.

Use Haiku (`claude-haiku-4-5-20251001`), as `/api/v1/analyze` does. This is summarisation over
supplied text, not reasoning.

## WS3 — Authorisation and disclosure

This is the part that has no precedent in the repo, and it is the reason this could not be a
paragraph appended to v1.38.0.

- **Who may ask.** The existing slash commands act on infrastructure and are already restricted;
  reuse that restriction rather than inventing a second model. Decide and write down whether `/ask`
  is broader than `/acg-up`, and justify it either way.
- **What is returnable.** `docs/bugs/` and `docs/issues/` are incident write-ups. They contain
  hostnames, cluster topology, account-shaped identifiers and the occasional verbatim error
  containing a path or an address. The corpus was written on the assumption that its readers are
  operators with repo access. A Slack channel may be wider than that.
  - Enumerate the corpus directories that are returnable, as an **allowlist, not a denylist**.
  - Return **excerpts with paths**, never whole documents.
  - The existing redaction discipline applies to the response path: no tokens, no credentials,
    addresses and phone numbers redacted.
- **Never echo the question back into a log** that is wider than the channel it came from.
  `docs/bugs/2026-06-19-codex-slack-banner-echoes-prompt.md` is the precedent for prompt echo in
  this exact transport.
- API key from env or Keychain, never argv. Register any new sensitive flag in
  `_args_have_sensitive_flag` (`scripts/lib/system.sh`).

## WS4 — Evaluation

Carry forward v1.38.0 WS5's binding lesson, which was learned the hard way on 2026-09-23: a suite
that stubs the component under test measures the half that cannot fail. `test_alert_delivery.py`
was 8/8 green while the probe it consumed reported a healthy cluster as a total alerting blackout,
because the tests injected a stubbed `run` and the probe never executed.

- At least one test must run the handler **end to end as a subprocess** against the real `docs/`
  tree, asserting that the reply contains real paths that exist on disk.
- Stub the **network calls only** — Claude and Slack — and assert against **recorded real
  responses**, never synthesized ones.
- A question with no good answer must be tested explicitly: assert the "no matching documents" path
  fires and that **no model call is made**. This is the guardrail most likely to rot silently.
- Assert the source list is present in **every** reply shape, including the no-answer one.
- Mutation-prove each guardrail: remove the floor check and confirm the no-answer test goes red.
  A guardrail whose test cannot fail is decoration.

## What NOT to do

- Do NOT start before v1.38.0 WS5 has published a number. The whole design depends on it.
- Do NOT lower a recall floor to make this shippable. Escalate instead.
- Do NOT answer from the model when retrieval returns nothing. Fail closed and say so.
- Do NOT return whole documents, or any directory not on the allowlist.
- Do NOT build new Worker, signature or Slack-posting plumbing. It exists; reuse it.
- Do NOT let this command mutate anything. It is read-only. There is no `/ask` that also fixes.
- Do NOT edit `scripts/lib/foundation/` or `scripts/lib/acg/` — subtrees, fixed upstream.

## Risks

- **The corpus is written for operators, not for a channel.** WS3 is the real work of this release;
  WS1 and WS2 are small. If WS3 turns out to need its own release, split it out rather than
  shipping a bot with an unresolved disclosure boundary.
- **A confident wrong answer is the product's natural failure mode.** Sources are the mitigation,
  which is why they are non-negotiable in every reply shape.
- **Scope drift into "and it can also run commands."** That is a different spec with a different
  risk profile. This one is read-only.
