# v1.31.0 — Hermes R4 auth via GitHub App installation token (+ scope preflight)

**Status:** SPEC / follow-up (filed during v1.30.0). Not started.
**Motivation:** v1.30.0 ships R4 (`rerun-failed-jobs`) authenticated by a **fine-grained PAT** (`k3dm-hermes-gh-token`) stored in the macOS Keychain. That works, but token management is manual and fragile:

- GitHub has **no API to create or re-scope a PAT** (fine-grained or classic) — minting/scoping is an interactive web-UI step, by design. So "grant `actions:write`" cannot be automated as long as R4 uses a PAT.
- The token is long-lived and broadly present in the Keychain; scope drift (a missing `actions:write`) is only discovered at approve-time.

This spec replaces the PAT auth backend for R4 with a **GitHub App installation token** and adds a startup **scope preflight**. It is an **auth-swap only** — the Phase 2 repair logic (allowlist, preconditions, `propose`/`approve`, invariants) is unchanged.

---

## Goal

Hermes authenticates as a **GitHub App installation** and mints a **short-lived (~1h), least-privilege installation token** on demand for R4, instead of reading a static PAT from the Keychain.

### Why a GitHub App is the right fix
- **Automated, rotating tokens.** Installation tokens are minted via API (JWT signed by the app private key → `POST /app/installations/{id}/access_tokens`), expire in ~1h, and never need manual re-scoping.
- **Least privilege by construction.** The installation grants exactly the permissions the app declares (`actions: write`, `contents: read` for CI status if needed) — nothing more.
- **No standing broad secret.** Only the app private key is stored; the usable token is ephemeral.
- Consistent with the repo's existing direction (see memory `github-actions[bot] can't bypass rulesets → use a GitHub App`).

## Design

### 1. App registration (manual, one-time — documented, not automated)
- Register a GitHub App `k3dm-hermes` on `wilddog64`.
- Repository permissions: **Actions: Read and write** (add `Contents: Read` only if the CI sensor's authenticated reads need it — verify against `sensors.ci`).
- Install on `wilddog64/k3d-manager` (single repo).
- Store the **app id**, **installation id**, and **private key** in the Keychain:
  - `k3dm-hermes-app-id`, `k3dm-hermes-app-installation-id`, `k3dm-hermes-app-private-key`.

### 2. Token-minting helper (`scripts/lib/hermes/github_app.py`, NEW)
- `installation_token(app_id, installation_id, private_key, now=...) -> str`
  - Build a JWT (RS256, `iat`/`exp` ≤ 10 min, `iss = app_id`) signed with the private key.
  - `POST https://api.github.com/app/installations/{installation_id}/access_tokens` with `Authorization: Bearer <jwt>`.
  - Return the `token` field. Cache in-process until ~5 min before `expires_at`.
- No new third-party dep if avoidable: RS256 JWT can be built with `hashlib`/`hmac`? No — RS256 needs RSA signing. Prefer the stdlib-free path via `openssl` through `_run_command`/`subprocess` (sign the JWT signing-input with the private key) to avoid adding `PyJWT`/`cryptography`. Decide at implementation time; if a dep is unavoidable, pin it.
- Secret hygiene: private key read from Keychain via stdin/env only, never argv/logs. JWT and installation token never logged.

### 3. Wire R4 to the app token (`scripts/lib/hermes/repairs.py`)
- `_r4_command(records)` currently does `{"GH_TOKEN": _keychain_secret(GITHUB_SERVICE)}`.
- Change the token source to `github_app.installation_token(...)` behind a small indirection so tests can inject a fake minter.
- **Fallback:** if app credentials are absent, fall back to the PAT (`GITHUB_SERVICE`) so existing deployments keep working; log which backend was used (backend name only, never the token).
- R4's existing 403 degrade (`"skipped: token lacks actions:write"`) stays as a backstop.

### 4. Startup scope preflight (`scripts/lib/hermes/preflight.py`, NEW — the piece deferred from v1.30.0)
- `run_preflight(keychain, runner, now=...) -> (report: dict, exit_code: int)` — fully dependency-injected (no direct network/Keychain in the function body) so it is unit-testable without live calls.
- Checks:
  - Presence of each required secret (webhook, argocd; and either the app trio **or** the PAT).
  - GitHub **Actions read**: `GET .../actions/runs?per_page=1` succeeds.
  - GitHub **Actions write**: POST `rerun-failed-jobs` against the most recent **succeeded** run — classify `"resource not accessible"` → no write; `"cannot be retried"`/any-other → write present (the safe probe proven in v1.30.0).
- `bin/k3dm-hermes preflight` subcommand prints the JSON report and exits non-zero if a required secret is missing or `actions:write` is absent. Wire it into `_usage` and the arg dispatch (currently only `approve`/`list`).
- Optionally run a lightweight presence-only check at poll startup and log a warning (avoid the write-probe API call on every cycle).

## Tests (`scripts/tests/hermes/`)
- `test_github_app.py`: JWT claims (`iss`/`iat`/`exp`), token caching until near-expiry, minter called with correct installation id (mock the runner/HTTP; never hit GitHub).
- `test_preflight.py`: token-missing → non-zero; Actions-read-fail → non-zero; write-missing (`resource not accessible`) → non-zero; write-ok (`cannot be retried`) → zero. All via injected `keychain`/`runner`.
- `test_repairs.py`: R4 uses the injected app-token minter; PAT fallback path when app creds absent; 403 degrade unchanged.

## Gates
- `pytest scripts/tests/hermes/ -q` — all green
- `py_compile bin/k3dm-hermes scripts/lib/hermes/*.py` — clean
- No secret in argv/logs (grep the new code for token interpolation into argv)

## What NOT to do
- Do NOT auto-execute repairs (Phase 2 invariant stands: execution only in `approve()`).
- Do NOT add cooldowns/budgets/durable audit/auto-verification (that is Phase 3, separate scope doc).
- Do NOT commit the app private key or any token. Do NOT edit `scripts/lib/foundation/` or `scripts/lib/acg/`.
- Do NOT remove the PAT fallback in the same release the App lands — keep both until the App path is proven live.

## Definition of done
- R4 mints a short-lived App installation token; PAT fallback retained and logged.
- `k3dm-hermes preflight` reports token presence + Actions read/write and exits non-zero on a missing `actions:write`.
- `docs/guides/hermes.md` documents the App setup + preflight; this file's manual registration steps captured there.
- Memory-bank updated; retro notes that R4 token management is no longer manual.
