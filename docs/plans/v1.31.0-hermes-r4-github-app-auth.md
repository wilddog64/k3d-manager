**Motivation:** v1.30.0 ships R4 (`rerun-failed-jobs`) authenticated by a **fine-grained PAT** (`k3dm-hermes-gh-token`) stored in the macOS Keychain. That works, but token management is manual and fragile:

- GitHub has **no API to create or re-scope a PAT** (fine-grained or classic) — minting/scoping is an interactive web-UI step, by design. So "grant `actions:write`" cannot be automated as long as R4 uses a PAT.
- The token is long-lived and broadly present in the Keychain; scope drift (a missing `actions:write`) is only discovered at approve-time.

This spec replaces the PAT auth backend for R4 with a **GitHub App installation token** and adds a startup **scope preflight**. It is an **auth-swap only** — the Phase 2 repair logic (allowlist, preconditions, `propose`/`approve`, invariants) is unchanged.

---

## Goal

Hermes authenticates as a **GitHub App installation** and mints a **short-lived (~1h), least-privilege installation token** on demand for R4, instead of reading a static PAT from the Keychain.

### Why a GitHub App is the right fix
- **Automated, rotating tokens.** Installation tokens are minted via API (JWT signed by the app private key → `POST /app/installations/{id}/access_tokens`), expire in ~1h, and never need manual re-scoping.
- **Least privilege by construction.** The installation grants exactly the permissions the app declares (`actions: write`, `contents: read` for CI status if needed) — nothing more.
- **No standing broad secret.** Only the app private key is stored; the usable token is ephemeral.
- Consistent with the repo's existing direction (see memory `github-actions[bot] can't bypass rulesets → use a GitHub App`).

## Design

### 1. App registration (manual, one-time — documented, not automated)
- Register a GitHub App `k3dm-hermes` on `wilddog64`.
- Repository permissions: **Actions: Read and write** (add `Contents: Read` only if the CI sensor's authenticated reads need it — verify against `sensors.ci`).
- Install on `wilddog64/k3d-manager` (single repo).
- Store the **app id**, **installation id**, and **private key** in the Keychain:
  - `k3dm-hermes-app-id`, `k3dm-hermes-app-installation-id`, `k3dm-hermes-app-private-key`.

### 2. Token-minting helper (`scripts/lib/hermes/github_app.py`, NEW)

**DECISION (locked — do NOT choose an alternative):** NO new third-party dependency. `PyJWT`/`cryptography` are
**forbidden** — Hermes is stdlib-only. The RS256 signature is produced by **`openssl` via `subprocess`**, and both the
signer and the HTTP call are **dependency-injected** so unit tests never shell out or hit the network.

- **Signature:**
  `installation_token(app_id, installation_id, private_key, *, signer=<default>, http=<default>, now=None, _cache=<module dict>) -> str`
  - Build the JWT: header `{"alg":"RS256","typ":"JWT"}`, payload `{"iat": now-60, "exp": now+540, "iss": app_id}`
    (9-minute window, ≤10 min as GitHub requires; the -60 clock-skew backoff is intentional). `now` defaults to
    `int(time.time())`. base64url-encode (no padding) header and payload; the **signing input** is
    `f"{header_b64}.{payload_b64}"`.
  - `signer(signing_input: str, private_key: str) -> bytes` returns the raw RS256 signature. The JWT is
    `f"{signing_input}.{b64url(signature)}"`.
  - **Default signer** = `_openssl_sign`: writes `private_key` to a temp file created with `mode=0o600` in a
    `tempfile.mkstemp` path, runs `openssl dgst -sha256 -sign <keyfile>` with the signing input piped on **stdin**
    (`input=signing_input.encode()`, `capture_output=True`), returns `result.stdout`, and **always deletes the
    keyfile in a `finally`**. Key never on argv, never logged.
  - `http(url, data: bytes, headers: dict) -> dict` performs the POST and returns parsed JSON. **Default http** uses
    `urllib.request` (mirror `bin/k3dm-hermes:_http_json`, but `Request(url, data=..., headers=..., method="POST")`).
  - Mint: `http("https://api.github.com/app/installations/{installation_id}/access_tokens", b"",
    {"Authorization": f"Bearer {jwt}", "Accept": "application/vnd.github+json", "X-GitHub-Api-Version": "2022-11-28"})`
    → return the `token` field.
  - **Cache in-process**: keep `{token, expires_at}` keyed by `installation_id` in a module-level dict; reuse the
    cached token until ~5 min (300 s) before `expires_at` (parse GitHub's ISO-8601 `expires_at`); otherwise re-mint.
- Secret hygiene: private key and JWT and installation token are **never** logged and never placed on argv.

### 3. Wire R4 to the app token (`scripts/lib/hermes/repairs.py`)

Add a small, monkeypatchable indirection `_r4_token()` and call it from `_r4_command`. Keychain service names for
the app trio: `k3dm-hermes-app-id`, `k3dm-hermes-app-installation-id`, `k3dm-hermes-app-private-key`.

**Add these module constants** near the existing `GITHUB_SERVICE` import usage (top of file):
```python
APP_ID_SERVICE = "k3dm-hermes-app-id"
APP_INSTALLATION_SERVICE = "k3dm-hermes-app-installation-id"
APP_PRIVATE_KEY_SERVICE = "k3dm-hermes-app-private-key"
```

**Add the indirection** (new module-level function; import `github_app` lazily inside it to keep import-time clean and
tests simple):
```python
def _r4_token():
    """Return (token, backend). Prefer the GitHub App installation token; fall back to the PAT."""
    app_id = _keychain_secret(APP_ID_SERVICE)
    installation_id = _keychain_secret(APP_INSTALLATION_SERVICE)
    private_key = _keychain_secret(APP_PRIVATE_KEY_SERVICE)
    if app_id and installation_id and private_key:
        from hermes import github_app
        return github_app.installation_token(app_id, installation_id, private_key), "github-app"
    return _keychain_secret(GITHUB_SERVICE), "pat"
```

**Change `_r4_command`** — literal old → new:
```python
# OLD
def _r4_command(records):
    data = (_rec(records, "ci") or {}).get("data", {})
    return (["gh", "api", "--method", "POST",
             f"/repos/{data['repo']}/actions/runs/{data['run_id']}/rerun-failed-jobs"],
            {"GH_TOKEN": _keychain_secret(GITHUB_SERVICE)})

# NEW
def _r4_command(records):
    data = (_rec(records, "ci") or {}).get("data", {})
    token, _backend = _r4_token()
    return (["gh", "api", "--method", "POST",
             f"/repos/{data['repo']}/actions/runs/{data['run_id']}/rerun-failed-jobs"],
            {"GH_TOKEN": token})
```

- The backend name may be logged (stderr) for observability — **never** log `token`. Do not change `approve()`: its
  existing `if key == "r4" and not env.get("GH_TOKEN")` guard already covers "no app AND no PAT" (both empty → empty
  token → skipped). The existing 403 degrade (`"skipped: token lacks actions:write"`) and the business-logic-403
  fall-through stay exactly as they are.
- **Fallback is mandatory this release** (see What NOT to do): app-trio present → App token; else → PAT.

### 4. Startup scope preflight (`scripts/lib/hermes/preflight.py`, NEW — the piece deferred from v1.30.0)
- `run_preflight(keychain, runner, now=...) -> (report: dict, exit_code: int)` — fully dependency-injected (no direct network/Keychain in the function body) so it is unit-testable without live calls.
- Checks:
  - Presence of each required secret (webhook, argocd; and either the app trio **or** the PAT).
  - GitHub **Actions read**: `GET .../actions/runs?per_page=1` succeeds.
  - GitHub **Actions write**: POST `rerun-failed-jobs` against the most recent **succeeded** run — classify `"resource not accessible"` → no write; `"cannot be retried"`/any-other → write present (the safe probe proven in v1.30.0).
- `bin/k3dm-hermes preflight` subcommand prints the JSON report and exits with `run_preflight`'s exit code. Wire it
  into `_usage` and the arg dispatch (currently only `approve`/`list`).

**`bin/k3dm-hermes` — literal edits:**
```python
# OLD (_usage)
def _usage():
    print("Usage: k3dm-hermes [approve <action-id>|list]", file=sys.stderr)

# NEW (_usage)
def _usage():
    print("Usage: k3dm-hermes [approve <action-id>|list|preflight]", file=sys.stderr)
```
Add a `preflight` branch in `main()` alongside the existing `list` branch (before the `approve` arg validation), e.g.:
```python
    if args and args[0] == "preflight" and len(args) == 1:

```
Import `run_preflight` lazily inside the branch (keep it out of module import time). Reuse the existing
`_keychain_secret` and `_repair_runner` already defined in `bin/k3dm-hermes` as the injected `keychain`/`runner`.
The exact `runner` contract preflight expects for its GH probes must match how the spec's `run_preflight` calls it —
define that contract in `preflight.py` and adapt here; do NOT invent a second runner shape.
- Do NOT add a per-cycle write-probe to the poll path (avoids an API call every cycle). A lightweight presence-only
  warning at poll startup is optional and out of scope unless trivial.
