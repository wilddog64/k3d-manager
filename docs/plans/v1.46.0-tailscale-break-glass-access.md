## Problem

1. **No second way in.** Every remote path into the Macs runs through cloudflared (web console, plan 4) or the
   GitHub-mediated cloud bridge, which depends on the webhook. When either is down (2026-10-26 webhook outage) the
   operator has detection (Healthchecks.io) but no repair channel.
2. **GUI dialogs nobody can click.** All three Macs run clamshelled and unattended. A TCC or Keychain prompt on m5 hung
   the password-bundle publish on 2026-11-22 with nobody to press Allow. SSH and the web console cannot answer a GUI
   dialog; only a screen can.
3. **Different networks.** The operator travels with only the iPad Air (hotel Wi-Fi, cellular or a phone hotspot). The
   Macs reach each other today only over the home LAN (`*.local`).

Tailscale gives each device an outbound-initiated, WireGuard-encrypted connection to the others: direct where NAT
traversal succeeds, relayed through Tailscale's DERP servers otherwise. No home-router port forwarding. It is still an
**inbound path to the Macs**, a deliberate exception to the no-inbound-home-control architecture, fenced by the grants
below and by each Mac's own SSH key and macOS password.

## External behaviour (proof)

Tailscale knowledge base, fetched 2026-11-25 (pages "last validated" 2025-12-02 to 2026-07-24):

- **Grants** (`/kb/1324/grants`): a grant has `src`, `dst` and `ip` (and/or `app`); ports as `"tcp:443"`; sources
  `group:<name>`, destinations `tag:<name>`.
- **Policy tests** (`/kb/1337/policy-syntax`): `tests` "make assertions about access policies (ACLs and network-level
  grants)"; fields `src`, `accept`, `deny` (`host:port`), `proto` (omitted = either TCP or UDP); "If an assertion
  fails, Tailscale rejects the updated tailnet policy file with an error" (verbatim, re-checked by Fable). `src` as a
  group is likely allowed but only a user example is shown, so the tests use the placeholder user.
- **Tagged devices** (`/kb/1068/tags`): "When you apply a tag to a device for the first time and authenticate it, the
  tagged device's key expiry is disabled by default." The iPad is not tagged, so its key expires (180 days by default).
- **macOS variants** (`/kb/1065/macos-variants`): "We always recommend installing the Standalone variant." Neither the
  App Store nor the Standalone variant can be a Tailscale SSH server. After a reboot, FileVault blocks the network until
  someone unlocks the Mac at its keyboard, whatever the variant. The Standalone CLI is
  `/Applications/Tailscale.app/Contents/MacOS/Tailscale` (not on an SSH session's `PATH`).
- **Different networks** (`/kb/1257/connection-types`): "All connections start as relayed through a DERP server, and
  Tailscale then tries to upgrade them to a direct connection"; `tailscale status` shows `direct`, `relay` or
  `peer-relay`; `tailscale ping` prints `via DERP(...)` for relayed and `via <ip>:<port>` for direct.
- **Tailnet Lock vs device approval** (`/kb/1226/tailnet-lock`): "You cannot enable both Tailnet Lock and device
  approval—they are mutually exclusive features." (D5.)

## Scope

- Tailscale networking only: no subnet routes, exit nodes, Funnel, Serve, app connectors or `nodeAttrs`; Hostinger is
  not a peer.
- SSH stays **macOS Remote Login** (OpenSSH, key-only), already on. No Tailscale SSH. The iPad uses its own key with an
  identifying comment in `authorized_keys`; its host-key fingerprints are compared on the home LAN before the first
  tailnet connection.
- GUI is **macOS Screen Sharing** (VNC, `tcp:5900`), per Mac, "Only these users": the operator account, legacy VNC
  password off. The macOS password is typed each time, never saved in the VNC app (it is also the sudo, login-Keychain
  and FileVault password). Lock the Mac's screen before disconnecting.
- The Macs leave "Use Tailscale DNS settings" off, so MagicDNS never touches the hub's resolver (k3d, cloudflared);
  only the iPad uses MagicDNS names.
- Identities: the operator's Tailscale login (`group:operator`); Macs carry `tag:k3dm-mac` (owner `group:operator`),
  applied at enrollment so they never sit untagged; the iPad is a personal device under the operator's login. No work or
  shared device under that login.
- Device approval on. No agent gets a Tailscale identity, auth key, OAuth client or admin-console access. An agent shell
  on an enrolled Mac could run that node's `tailscale` CLI; the fence is the policy (no `nodeAttrs`, no auto-approvers,
  device approval in a browser the agent cannot reach).
