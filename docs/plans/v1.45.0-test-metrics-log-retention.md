# v1.45.0 — Durable test-metrics logs and progress visibility

**Status:** PROPOSED — enhancement. Moved from v1.43.0 to v1.45.0 on 2026-10-09 to make room for worktree-isolated Codex dispatch.
**Problem:** `make test-metrics` redirects the entire `test-all` run to
`${TMPDIR:-/tmp}/k3dm-test-all-<timestamp>.log`, so the terminal is silent during a long run and
the evidence disappears with temporary-file cleanup.

## Goals

- Store test-metrics logs under a durable, user-owned k3d-manager data directory.
- Keep the log available for live `tail -f`, post-run diagnostics, and metrics-parser recovery.
- Preserve the existing metrics contract and exact test exit status.
- Provide clear start/progress/completion messages without duplicating the test output.
- Bound disk usage with configurable retention and size limits.
- Keep logs private and avoid changing cloud/webhook job-log behavior.

## Proposed storage contract

Default directory:

```text
${K3DM_TEST_METRICS_LOG_DIR:-$HOME/.local/share/k3d-manager/test-metrics}
```

The directory must be created with mode `0700`; log files must use mode `0600`. An explicit
`K3DM_TEST_METRICS_LOG_DIR` override is supported for CI, external volumes, and tests. Reject an
empty, relative, or unsafe override rather than silently falling back to the repository root.

Use a UTC filename that is easy to sort and correlate:

```text
make-test-all-YYYYmmddTHHMMSSZ-<pid>.log
```

The PID suffix prevents collisions when two local runs overlap. Do not use a job ID or question
text as a filename component.

## User-visible behavior

Before starting the suite, print:

```text
[test-metrics] recording full output to ~/.local/share/k3d-manager/test-metrics/make-test-all-....log
```

The existing test output continues streaming into the file. The command may remain quiet on the
terminal while tests run, but the path is known immediately and can be followed with `tail -f`.
At completion, print the parsed case totals, publication result, and final log path. A metrics
Pushgateway failure remains non-fatal and must be visibly distinct from a test failure.

Optional progress mode may mirror only coarse milestones (`test`, `test-bin`, `test-python`) to
stderr; it must not duplicate every test line or interfere with the captured parser input.

## Retention

After a run completes, prune only files inside the configured log directory:

- default maximum age: 14 days;
- default maximum total size: 500 MiB;
- configurable with `K3DM_TEST_METRICS_LOG_RETENTION_DAYS` and
  `K3DM_TEST_METRICS_LOG_MAX_BYTES`;
- never delete the current run's file before the exporter has parsed it;
- prune oldest completed files first;
- if pruning fails, warn but preserve the test result and metrics outcome.

An explicit `make test-metrics-clean` target is optional only if the normal retention pass is
insufficient; it must not delete outside the configured directory.

## Compatibility and safety

- Keep `TMPDIR` behavior only as an explicit fallback when the durable directory cannot be
  created, and print a warning naming the fallback and reason.
- Preserve `--run-duration`, `--exit-code`, target selection, and exporter parsing unchanged.
- Do not publish full logs to Pushgateway, Grafana, Slack, or cloud-request artifacts.
- Do not include secrets in terminal status messages; the log retains existing command-output
  redaction expectations and file permissions.
- Cloud-bridge `make-test-all` continues using its webhook-owned `make.log`; this spec covers
  the local `make test-metrics` recipe only.

## Verification

- Tests verify default and override directory selection, `0700` directory/`0600` file modes,
  UTC collision-resistant names, and immediate path announcement.
- Tests verify the exporter reads the durable file before retention removes anything.
- Tests verify old files are pruned by age/size while current and unrelated paths are untouched.
- Tests verify a failed suite remains failed even when metrics publication or pruning fails.
- Tests verify an unavailable durable directory uses the documented safe fallback and warning.
- A live run confirms `tail -f` shows progress and the final file remains available after the
  command completes.

## Release decision

This is a local test-operator usability enhancement, not a test correctness fix. It was the fifth
v1.43.0 plan until 2026-10-09, when it moved to v1.45.0 to make room for agent isolation.
