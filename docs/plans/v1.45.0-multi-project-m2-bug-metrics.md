## Design

### Entry point

A new function `_publish_registry_bugs(docs_root, ref=None)`, called from `main()` after `publish_bug_metrics(ROOT, ...)` as
`_publish_registry_bugs(ROOT, os.environ.get("K3DM_INDEX_REF"))`. `docs_root`/`ref` are the k3d-manager root and ref used for
**legacy** docs. `scripts/bug-tally.py` is still located via the module `ROOT`. `publish_bug_metrics` never reads the registry
(so its existing tests are unaffected).

### Registry

Path from `K3DM_PROJECTS_LIST`, default `ROOT/scripts/etc/projects.list`. Same rules as `bin/k3dm-codex-dispatch:14-50`: 5 `|`
fields, name `[A-Za-z0-9._-]{1,64}`, scheme `branch|tag`, `#` comments and blank lines skipped. Also: `local path` non-empty;
default branch matches `[A-Za-z0-9._/-]{1,100}` and does not start with `-`; duplicate names make the registry malformed. A
relative `local path` resolves against `ROOT` (the `k3d-manager|.` row is skipped anyway). A malformed registry skips all
registry projects with one stderr line. Rows named `k3d-manager` or `lib-foundation` are skipped (existing passes own them).

### Per project

1. **Clone.** Expand `~`. If `git -C <path> rev-parse --git-dir` fails, print `project <name> bug metrics skipped (missing clone):
   <path>` to stderr and push nothing for that project. Otherwise `git fetch --quiet --tags origin <default branch>` with a
   **15 s** timeout (`--tags`, because a release tag pushed later onto an already-fetched commit is otherwise never fetched —
   Argon reproduced). On failure print one line and continue with the existing `origin/<default branch>`. Code root = the clone;
   code ref = `origin/<default branch>`.
2. **Docs location, decided at a ref, never from a working tree.** Non-empty stdout of
   `git -C <clone> ls-tree -d <code ref> docs/bugs` → **in-repo**: docs root = clone, bugs dir = `docs/bugs`, docs ref = code ref.
   Else non-empty `git -C <docs_root> ls-tree -d <ref or HEAD> docs/<name>/bugs` (working tree `is_dir()` only when `ref` is
   None, as `_bug_texts` does today) → **legacy**: docs root = `docs_root`, bugs dir = `docs/<name>/bugs`, docs ref = `ref`.
   Neither → skip with a stderr line, push nothing. If both exist (mid-migration), in-repo wins and one stderr line names the
   legacy dir as ignored.
3. **Read, all with `bugs_dir` threaded through.** Add a `bugs_dir="docs/bugs"` keyword to `_bug_texts` and `_bug_open_history`
   (which passes it to `_bug_texts` at `:212`); in the ref path of `_bug_texts`, require `p.endswith(".md")` only when
   `bugs_dir != "docs/bugs"` (k3d-manager and lib-foundation output must not change). Bug texts, open history
   (`_bug_open_history(docs root, docs ref, bugs_dir=...)`, so it walks the docs root's commits and reads only `bugs_dir` at
   each; dates before the directory existed report 0) and `verification_times = _verification_times(docs root, docs ref, texts)`
   all use the docs root. Pass `texts=` and `verification_times=` explicitly to `_bug_status_metrics` (its `texts is None`
   fallback at `:671` reads `docs/bugs`). Fix-commit ancestry uses the existing `evidence_check=` parameter (`:659`, `:715`) with
   `lambda fix, ev: _evidence_contains_fix(<clone>, fix, ev)`; no new `code_root` keyword.
4. **Release.** In-repo: `_tally(..., repo=<name>, repo_dir=<clone>)` as lib-foundation does, so a bug's release is a project
   tag. Legacy: no tally (doc commits are k3d-manager commits); release `unassigned`; the fix commit comes from the doc's
   `**Fix commit:**` line only.
5. **Release gates.** New keyword `k3dm_release_gates=True` on `_bug_status_metrics`; when False, all three gated call sites
   (`:706`, `:730`, `:735`) are skipped. Registry projects pass False; k3d-manager and lib-foundation callers are unchanged.
6. **Labels.** `repo="<name>"` on every series. `branch`: legacy rows keep the k3d-manager scan branch (where the doc lives; M3
   builds the link from it); in-repo rows use `<default branch>`. Legacy `verified_sha` is a k3d-manager commit and `fix_sha` a
   project commit; the guide says so.
7. **Push.** Same groups and methods as lib-foundation, `instance=<name>`: `k3dm-bug-docs` (POST), `k3dm-bug-open-history`
   (PUT), `k3dm-bug-open` (PUT), and `k3dm-bug-releases` for in-repo docs only.
8. **Freshness signals** (in the project's `k3dm-bug-docs` payload; that group is POSTed, so an omitted line keeps its last value):
   - `k3dm_project_clone_fetch_timestamp_seconds{repo}` = `time.time()` **only when the fetch returned 0**; omitted after a
     failed or timed-out fetch. (A failed `git fetch` truncates `FETCH_HEAD` and advances its mtime — reproduced by both
     reviewers — so `FETCH_HEAD` mtime must not be used.)
   - `k3dm_project_bug_scan_timestamp_seconds{repo}` = `time.time()` when that project's pass completes and pushes. Hermes kills
     the scanner at 120 s (`bin/k3dm-hermes:875`) and the registry pass runs last, so a stale value is the visible signal that
     the pass was not reached (M3 alerts on it).
9. **Isolation.** Each project is wrapped so its exception skips only that project, with one stderr line.

Out of scope: plan metrics for other projects and `scripts/bug-tally.py` changes (parent plan's M2 lists both; deferred to M4,
recorded in the parent plan), the Bugs dashboard selector and doc links (M3), moving dirused docs (M4), removing Pushgateway
groups for a project later deleted from the registry (manual `DELETE`, noted in the guide), and the same missing `--tags` in the
lib-foundation fetch (`:1091`; pre-existing, captured separately).

## Rules

- Minimal patch; no refactor of the k3d-manager or lib-foundation passes beyond default-preserving keywords (`bugs_dir=`,
  `k3dm_release_gates=`).

  test uses its own fixture registry, a fixture clone with a bare `origin` under `tmp_path` (asserted first), and stubs
  `urllib.request.urlopen` as `_publish_both` does. No test reads the real registry, the real dirused clone, or the network.
- Gates to paste: `python3 -m pytest -q scripts/tests/bin/test_vectordb_bug_metrics.py scripts/tests/bin/test_bug_tally.py`,
  bare `python3 -m pytest -q scripts/tests/bin`, `make lint-python`, `git diff --stat`.
