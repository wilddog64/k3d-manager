## Design

For each registry entry other than `k3d-manager` (`name|local path|github repo|release scheme|default branch`):

1. **Clone.** Expand `~` in `local path`. If the directory is not a git checkout, print
   `project <name> bug metrics skipped (missing clone): <path>` to stderr and push nothing for that project.
   Otherwise `git fetch --quiet origin <default branch>` (30 s timeout); on failure print a line and continue with the
   existing `origin/<default branch>`, exactly as `_publish_lib_foundation_bugs` does. The **code root** is that clone at
   `origin/<default branch>`.
2. **Docs location.** If the code root has a `docs/bugs/` tree at `origin/<default branch>`, the docs are **in-repo**: docs root =
   code root, bugs dir = `docs/bugs`, ref = `origin/<default branch>`. Otherwise, if k3d-manager has `docs/<name>/bugs/`, the
   docs are **legacy**: docs root = k3d-manager `ROOT`, bugs dir = `docs/<name>/bugs`, ref = the same ref the k3d-manager scan
   uses (`K3DM_INDEX_REF`, or the working tree when unset). Neither: skip with a stderr line, push nothing.
3. **Read.** Bug texts come from the docs root's bugs dir (top level only, `*.md`, same rules as today). Verification times
   (`git log -G` on the doc path) run in the docs root. Fix-commit ancestry (`merge-base --is-ancestor`) runs in the
   **code root**.
4. **Release.** In-repo docs: tally from the code root as lib-foundation does (`_tally(..., repo=<name>, repo_dir=<clone>)`),
   so a bug's release is a project tag. Legacy docs: no tally (their doc commits are k3d-manager commits, whose tags are
   k3d-manager releases); release is `unassigned` and the fix commit comes from the doc's `**Fix commit:**` line only.
5. **No k3d-manager release gates for registry projects.** The `(1, 43, 2)` / `(1, 43, 4)` gates in `_bug_status_metrics` apply
   only to k3d-manager and lib-foundation (callers unchanged); registry projects report real `verified`, `live_verified`
   and `live_evidence` values. Implement as a keyword argument whose default keeps today's behaviour.
6. **Push.** Same groups and methods as lib-foundation, with `instance=<name>` and `repo="<name>"` on every series:
   `k3dm-bug-docs` (inventory), `k3dm-bug-open-history`, `k3dm-bug-open`, and `k3dm-bug-releases` for in-repo docs only.
7. **Clone freshness.** The inventory payload for a project adds `k3dm_project_clone_fetch_timestamp_seconds{repo="<name>"}`:
   the mtime of the clone's `FETCH_HEAD` after the fetch attempt (0 if absent). The parent plan's decided question needs this for M3.
8. **Registry.** Path from `K3DM_PROJECTS_LIST`, default `ROOT/scripts/etc/projects.list`. Parse with the same rules as
   `bin/k3dm-codex-dispatch` (5 `|` fields, name `[A-Za-z0-9._-]{1,64}`, scheme `branch|tag`, `#` comments and blank lines
   skipped). Also require the default branch to match `[A-Za-z0-9._/-]{1,100}` and not start with `-`. A malformed registry
   skips all registry projects with one stderr line; it never stops the k3d-manager or lib-foundation scans.
9. **Isolation.** The registry pass runs after the existing k3d-manager and lib-foundation passes, in `main()`, and each project is
   wrapped so one project's exception (or a missing clone) skips only that project. A project named `lib-foundation` in the
   registry is skipped (the existing pass owns it).

Out of scope (later milestones): plan metrics for other projects, the Bugs dashboard repo selector and doc links (M3), moving
dirused docs (M4), `scripts/bug-tally.py` CLI changes (its existing `--repo-dir` / `--repo-name` suffice for in-repo docs),
cloning dirused on the M5 (an operator-go live step below).
