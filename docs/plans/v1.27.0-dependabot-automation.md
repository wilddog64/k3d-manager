# v1.27.0 — Dependabot CI and merge automation

**Status:** QUEUED (design only; implementation requires explicit handoff)
**Scope:** reusable GitHub Actions workflow in `shopping-cart-infra`, called by the
shopping-cart repositories.

## Problem

Dependabot pull requests repeatedly require manual handling for transient CI failures,
stale branches, merge conflicts, Copilot review requests, and auto-merge setup. PR #51 in
`shopping-cart-product-catalog` demonstrates the current behavior: the Dependabot
auto-merge job was skipped because the PR author was `wilddog64`, while the workflow is
explicitly gated on `dependabot[bot]`. That skip is expected for a feature PR, not a CI
failure.

## Design

1. On `pull_request_target`, identify Dependabot PRs by
   `github.event.pull_request.user.login == 'dependabot[bot]'` and validate the repository
   before granting write permissions.
2. Fetch Dependabot metadata, apply standardized labels, and request Copilot review.
3. For a branch that is behind or conflicted, issue `@dependabot rebase`; never attempt
   an unreviewed semantic conflict resolution.
4. Retry a failed check once for known transient classes. Persistent failures post a
   concise summary, retain the PR open, and create or update a linked issue.
5. Enable auto-merge only for allowlisted patch/minor or security updates after required
   checks and approvals pass. Major updates and ambiguous failures remain manual.
6. Notify Slack for persistent CI failures, unresolved conflicts, skipped jobs, and PRs
   blocked by required approval.

## Safety and permissions

- Keep `pull_request_target` steps free of untrusted checkout/build execution.
- Use least-privilege `contents: write` and `pull-requests: write` only in the guarded
  Dependabot job; do not expose repository secrets to PR code.
- Preserve branch protection and required human/Copilot approval. Auto-merge must not
  bypass required status checks.
- Cap retries and add idempotency markers so an event storm cannot loop indefinitely.

## Acceptance criteria

- A Dependabot patch PR is labeled, reviewed, tested, and auto-merge-enabled when green.
- A stale Dependabot PR receives one rebase request; a semantic conflict is escalated.
- A transient failed check is retried once; a repeat failure produces a Slack/issue
  diagnostic with run URL and owner.
- Non-Dependabot PRs (including product-catalog PR #51) do not run the Dependabot
  auto-merge job and are not auto-approved or auto-merged.
- Workflow permissions, repository allowlist, retry cap, and major-update hold are
  covered by actionlint/YAML validation and workflow tests.

## Out of scope

No automatic source-code edits, semantic conflict resolution, branch-protection bypass,
or forced merge. This plan does not change PR #51; its skipped job is correct behavior.

## Implementation-ready artifact (2026-08-29)

**Status:** design → implementation-ready. Grounded in the existing baseline
`shopping-cart-product-catalog/.github/workflows/dependabot-automerge.yml` (already
`pull_request_target` + author-gated on `dependabot[bot]`, `permissions: {}` default,
`fetch-metadata` pinned to a SHA, allowlisted `--auto --squash`). This section factors that
baseline into a **reusable** workflow in `shopping-cart-infra` and thins each repo's file to
a caller — adding labels, rebase-on-dirty, and Slack-on-failure. **Routing:** shopping-cart
repos are spec-not-direct + branch/PR-gated — land via a branch + PR per repo (gated),
never a direct main push. Copilot review request and the transient-retry loop are best-effort
follow-ons (marked below) to keep the security-sensitive core minimal and reviewable.

### A. Reusable workflow — `shopping-cart-infra/.github/workflows/dependabot-automation.yml`
```yaml
name: Dependabot automation (reusable)

on:
  workflow_call:
    inputs:
      merge-method:
        type: string
        default: squash
      allowlist-major:
        type: boolean
        default: false        # non-security major bumps stay manual (D2)
    secrets:
      SLACK_WEBHOOK_URL:
        required: false

permissions: {}               # least-privilege default; elevate per job only

jobs:
  dependabot:
    # author gate is robust across reopened/edited events (unlike github.actor)
    if: ${{ github.event.pull_request.user.login == 'dependabot[bot]' }}
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      security-events: read
    steps:
      # NOTE: no checkout/build of PR code under pull_request_target (untrusted).
      - name: Fetch Dependabot metadata
        id: meta
        uses: dependabot/fetch-metadata@25dd0e34f4fe68f24cc83900b1fe3fe149efef98 # v3.1.0
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          alert-lookup: true

      - name: Apply standardized labels
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          PR_URL: ${{ github.event.pull_request.html_url }}
          UPDATE_TYPE: ${{ steps.meta.outputs.update-type }}
          ALERT_STATE: ${{ steps.meta.outputs.alert-state }}
        run: |
          labels="dependencies"
          case "$UPDATE_TYPE" in
            *semver-patch) labels="$labels,patch" ;;
            *semver-minor) labels="$labels,minor" ;;
            *semver-major) labels="$labels,major" ;;
          esac
          [ "$ALERT_STATE" = "OPEN" ] && labels="$labels,security"
          gh pr edit "$PR_URL" --add-label "$labels" || true

      - name: Rebase a behind/conflicted PR (one request; never resolve conflicts)
        if: ${{ github.event.pull_request.mergeable_state == 'behind' || github.event.pull_request.mergeable_state == 'dirty' }}
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          PR_URL: ${{ github.event.pull_request.html_url }}
        run: gh pr comment "$PR_URL" --body "@dependabot rebase" || true

      - name: Enable auto-merge (allowlisted patch/minor + security; major only if opted in)
        if: >-
          steps.meta.outputs.update-type == 'version-update:semver-minor' ||
          steps.meta.outputs.update-type == 'version-update:semver-patch' ||
          steps.meta.outputs.alert-state == 'OPEN' ||
          (inputs.allowlist-major && steps.meta.outputs.update-type == 'version-update:semver-major')
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          PR_URL: ${{ github.event.pull_request.html_url }}
        run: gh pr merge --auto --${{ inputs.merge-method }} "$PR_URL"

      - name: Notify Slack on job failure
        if: ${{ failure() && env.SLACK != '' }}
        env:
          SLACK: ${{ secrets.SLACK_WEBHOOK_URL }}
          PR_URL: ${{ github.event.pull_request.html_url }}
        run: |
          curl -fsSL -X POST -H 'Content-type: application/json' \
            --data "{\"text\":\"Dependabot automation failed for $PR_URL (run ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }})\"}" \
            "$SLACK" || true
```

### B. Caller (per repo) — replaces the current `dependabot-automerge.yml`
```yaml
name: Dependabot auto-merge
on:
  pull_request_target:
    branches: [main]
permissions: {}
jobs:
  automation:
    uses: wilddog64/shopping-cart-infra/.github/workflows/dependabot-automation.yml@<pinned-sha-or-tag>
    secrets: inherit
```

### C. Best-effort follow-ons (separate, after the core is proven on one repo)
- **Copilot review request:** a step calling the PR requested-reviewers API with the Copilot
  reviewer slug (varies by account; verify against a live PR before wiring).
- **Transient-retry-once:** a `workflow_run`-triggered companion that re-runs failed required
  checks once, then on a second failure posts the Slack/issue diagnostic (run URL + owner).
  Kept separate because it needs the check-suite conclusion, not the PR event, and carries
  the event-storm idempotency cap.

### D. Rollout
1. PR the reusable workflow into `shopping-cart-infra` (branch + PR, gated).
2. Pin callers to that merged SHA/tag; PR the thin caller into ONE repo
   (`shopping-cart-product-catalog`) first; validate on a real Dependabot PR.
3. Roll the caller to the remaining 5 repos once validated.

### Validation (pre-merge, no live Dependabot PR needed)
`actionlint` on both files; confirm `permissions: {}` default + per-job least privilege;
confirm the author gate and the allowlist `if:` exclude non-Dependabot and major bumps.
