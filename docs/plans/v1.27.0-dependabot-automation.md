# v1.27.0 — Dependabot CI and merge automation

**Status:** QUEUED (design only; implementation requires explicit handoff)
**Scope:** reusable GitHub Actions workflow in `shopping-cart-infra`, called by the
shopping-cart repositories.

## Problem

Dependabot pull requests repeatedly require manual handling for transient CI failures,
stale branches, merge conflicts, Copilot review requests, and auto-merge setup. PR #51 in
`shopping-cart-product-catalog` demonstrates the current behavior: the Dependabot
auto-merge job was skipped because the PR author was `wilddog64`, while the workflow is
explicitly gated on `dependabot[bot]`. That skip is expected for a feature PR, not a CI
failure.

## Design

1. On `pull_request_target`, identify Dependabot PRs by
   `github.event.pull_request.user.login == 'dependabot[bot]'` and validate the repository
   before granting write permissions.
2. Fetch Dependabot metadata, apply standardized labels, and request Copilot review.
3. For a branch that is behind or conflicted, issue `@dependabot rebase`; never attempt
   an unreviewed semantic conflict resolution.
4. Retry a failed check once for known transient classes. Persistent failures post a
   concise summary, retain the PR open, and create or update a linked issue.
5. Enable auto-merge only for allowlisted patch/minor or security updates after required
   checks and approvals pass. Major updates and ambiguous failures remain manual.
6. Notify Slack for persistent CI failures, unresolved conflicts, skipped jobs, and PRs
   blocked by required approval.

## Safety and permissions

- Keep `pull_request_target` steps free of untrusted checkout/build execution.
- Use least-privilege `contents: write` and `pull-requests: write` only in the guarded
  Dependabot job; do not expose repository secrets to PR code.
- Preserve branch protection and required human/Copilot approval. Auto-merge must not
  bypass required status checks.
- Cap retries and add idempotency markers so an event storm cannot loop indefinitely.

## Acceptance criteria

- A Dependabot patch PR is labeled, reviewed, tested, and auto-merge-enabled when green.
- A stale Dependabot PR receives one rebase request; a semantic conflict is escalated.
- A transient failed check is retried once; a repeat failure produces a Slack/issue
  diagnostic with run URL and owner.
- Non-Dependabot PRs (including product-catalog PR #51) do not run the Dependabot
  auto-merge job and are not auto-approved or auto-merged.
- Workflow permissions, repository allowlist, retry cap, and major-update hold are
  covered by actionlint/YAML validation and workflow tests.

## Out of scope

No automatic source-code edits, semantic conflict resolution, branch-protection bypass,
or forced merge. This plan does not change PR #51; its skipped job is correct behavior.
