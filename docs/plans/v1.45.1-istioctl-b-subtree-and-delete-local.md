## Problem

k3d-manager carries its own `_install_istioctl` in `scripts/lib/core.sh:457-493`. `scripts/k3d-manager` sources the
subtree `core.sh` (`:82`) and then always the local one (`:86`), so the local copy shadows the foundation one, so even after part A lands the dispatcher would still run the unpinned master-script installer. Deleting
the local copy makes the subtree v0.5.9 definition the only one.

## Behaviour

1. `scripts/lib/core.sh` no longer defines `_install_istioctl` (delete `:457-493` as one block; nothing else in the file
   changes).
2. The definition the dispatcher loads, in `scripts/k3d-manager`'s library order, is the subtree v0.5.9 one.
3. Through the real provider path (`k3d.sh:102-107`, `k3s.sh:86-91`), a refused istioctl stops the deploy: `_err` exits
   the shell, so `_istioctl x precheck` and `_istioctl install` never run.

  spec defect to report, not to fix.
