## Task A — parameterize the report scaffolding (tier/project are hardcoded to Tier 1)

The v1.25.0 spec claims `scripts/plugins/e2e.sh` was "carved so Tier 1 later drops
`e2e_verify_vcluster` into the same file without collision". The scaffolding was **not** actually
carved for two tiers: `_e2e_write_summary` hardcodes Tier 1's identity. Tier 2 must emit
`tier:"sandbox"` / `project:"stripe"` (v1.25.0 spec, D5 and step 6), which is impossible today.

The *consumer* side is already correct — the event publisher reads `s.get("tier")` from the
summary (`scripts/plugins/e2e.sh:541`), so only the producer needs changing.

### A1 — pass tier and project in as env

In `_e2e_write_summary` (`scripts/plugins/e2e.sh:356`), the env block that fronts the `python3`
heredoc. **Old:**

```bash
  E2E_COMMIT="$commit" \
  E2E_LOG="$log_file" \
  E2E_RUNNER="${E2E_RUNNER:-local-m4}" \
  python3 - "$summary_file" "$failures_file" <<'PY'
```

**New:**

```bash
  E2E_COMMIT="$commit" \
  E2E_LOG="$log_file" \
  E2E_RUNNER="${E2E_RUNNER:-local-m4}" \
  E2E_TIER="${E2E_TIER:-vcluster}" \
  E2E_PROJECT="${E2E_PROJECT:-api+flows}" \
  python3 - "$summary_file" "$failures_file" <<'PY'
```

### A2 — read them in the heredoc

**Old** (just after `runner = os.environ.get("E2E_RUNNER") or "local-m4"`):

```python
runner = os.environ.get("E2E_RUNNER") or "local-m4"
```

**New:**

```python
runner = os.environ.get("E2E_RUNNER") or "local-m4"
tier = os.environ.get("E2E_TIER") or "vcluster"
project = os.environ.get("E2E_PROJECT") or "api+flows"
```

### A3 — use them in the summary dict

**Old:**

```python
    "tier": "vcluster",
    "runner": runner,
    "service": service,
    "candidate_digest": candidate,
    "project": "api+flows",
```

**New:**

```python
    "tier": tier,
    "runner": runner,
    "service": service,
    "candidate_digest": candidate,
    "project": project,
```

### A4 — declare the two new knobs with the other defaults

At the top of `scripts/plugins/e2e.sh` (the `E2E_*` default block, lines 4–19), add alongside the
existing defaults and add both names to the `export` lines:

```bash
E2E_TIER="${E2E_TIER:-vcluster}"
E2E_PROJECT="${E2E_PROJECT:-api+flows}"
```

**The defaults must preserve Tier 1's current output byte-for-byte.** A Tier 1 summary written
after this change must be identical to one written before it, apart from fields that legitimately
vary per run (`run_id`, `timestamp`, `duration_seconds`, `commit`).

### A5 — the failure-classifier port map is Tier-1-only

`scripts/plugins/e2e.sh` classifies `service-unreachable` failures by port:

```python
        targets = {"8000": "product-catalog", "8080": "order",
                   "8083": "basket", "8084": "payment"}
        match = re.search(r":(8000|8080|8083|8084)\b", text)
```

Tier 2's service ports are **different and non-obvious** — the v1.25.0 spec records order `8081`
(not 8080) and product-catalog `8082` (not 8000). On a Tier 2 run every connection failure to
order or product-catalog would therefore classify as `target: "unknown"`, silently losing the
attribution that makes the summary useful. Extend both the map and the regex to cover all six
ports, keeping the existing four:

```python
        targets = {"8000": "product-catalog", "8080": "order",
                   "8081": "order", "8082": "product-catalog",
                   "8083": "basket", "8084": "payment"}
        match = re.search(r":(8000|8080|8081|8082|8083|8084)\b", text)
```

### A6 — the replay selector hardcodes the tier

`scripts/plugins/e2e.sh:603` builds a label selector with `k3dm.k3d.io/e2e-tier=vcluster` baked
in. Replace the literal with `${E2E_TIER}` so a Tier 2 result can be fetched by the same path.
Because `E2E_TIER` defaults to `vcluster`, Tier 1 behaviour is unchanged.

## Task B — implement `e2e_verify_sandbox`

Add a public `e2e_verify_sandbox` to `scripts/plugins/e2e.sh`, following the shape of
`e2e_verify_vcluster` (:76) and implementing the v1.25.0 spec's "### Codified sequence" steps 1–6
exactly. Do not invent steps and do not reorder them.

Set `E2E_TIER=sandbox` and `E2E_PROJECT=stripe` for the run so Task A's plumbing carries them into
the summary.

**The three substrate overrides (v1.25.0 spec items a/d/e) are the heart of this function.** They
are applied by the harness at deploy time — as a kustomize patch layer or a post-sync ConfigMap
edit plus rollout — and the **app repos stay untouched**:

| # | Service | Override the harness applies |
|---|---|---|
| a | order | `BASKET_URL=http://basket-service.shopping-cart-apps:8083`, `PAYMENT_URL=http://payment-service.shopping-cart-payment:8084` (in-cluster svc DNS, not ambient `localhost`) |
| d | payment | `payment.gateway.default=stripe`, `mock.gateway.enabled=false` (the mock declines Stripe test cards) |
| e | payment | `oauth2.jwk-set-uri=https://keycloak.3ai-talk.org/realms/shopping-cart/protocol/openid-connect/certs` (the public issuer — this was the 401→403 fix) |

**Hard invariant, from D2:** `e2e_verify_sandbox` must **never** call `register_app_cluster`. That
call is the entire hub-orphan source; a sandbox that self-expires after registering leaves
Applications generated against a dead cluster.

Do **not** tear the sandbox down (D4) — it self-expires on TTL.

## Task C — structural BATS (no live cloud)

Add cases to `scripts/tests/plugins/e2e.bats`. The v1.25.0 spec's BATS contract, made concrete:

1. **`register_app_cluster` is never invoked on this path.** Spy the function (define a stub that
   writes a marker file and fail if the marker appears), not a `grep` of the source — a grep
   proves the token is absent, a spy proves the call does not happen.
2. **`E2E_TIER=sandbox` and `E2E_PROJECT=stripe`** reach the summary: drive `_e2e_write_summary`
   with a fixture log and assert the emitted JSON has `"tier": "sandbox"` and `"project": "stripe"`.
3. **Tier 1 is unchanged:** the same fixture with no `E2E_TIER`/`E2E_PROJECT` set still emits
   `"tier": "vcluster"` and `"project": "api+flows"`. This is the regression guard for Task A.
4. **`OAUTH2_ENABLED=true` and `STRIPE_E2E=true`** are exported before the Job is created.
5. **The three substrate overrides resolve correctly** — assert against the *rendered* patch or
   ConfigMap, **not** against hard-coded literals in the function body. An assertion that greps
   the source for the string it just wrote there proves nothing.
6. **Port attribution:** a `service-unreachable` failure naming `:8081` classifies as `order`, and
   `:8082` as `product-catalog` (the Task A5 guard).

### Assertion rules — read `.github/copilot-instructions.md` § "Assertion Strength (v1.36.0+)"

These are hard requirements for this task, not style preferences:

- **No `run <binary>` plus a bare non-zero-status assertion.** Exit **127** (command not found)
  satisfies `[ "$status" -ne 0 ]`, so such a test is **vacuously green**. Assert on `output`, or
  guard with `command -v` + `skip`.
- **Never `grep -F` a whole line of source code.** Assert the semantically meaningful tokens.
- **Every assertion must be mutation-verified.** For each new case, confirm it passes against the
  real tree AND **fails** against a scratch copy with the asserted token removed. A green run is
  not evidence: a test that asserts nothing passes too. Paste the mutation results.

## The live half (NOT this spec's DoD, and not Codex's)

The v1.25.0 DoD's headline items are irreducibly live and irreducibly the operator's:

1. **ACG login live gate (P4)** — operator's. The false-green fix is vendored in
   `scripts/lib/foundation/` but has never passed live. Until it does, any green from a
   sandbox run is untrustworthy: the login layer is known to report success on a signed-out page.
   Building a Stripe acceptance gate on top of that would produce a green that means nothing.
2. **payment `KeycloakRealmRoleConverter` (P3)** — needs a PR in `shopping-cart-payment`. Until it
   merges, payment→Stripe returns **403** and Stripe acceptance cannot pass, however correct this
   harness is.
3. **The sandbox run itself** — Claude's, not Codex's and not Gemini's. One agent per ACG sandbox
   (serialize-live-sandbox rule), inside a 4h+4h TTL window. Live `kubectl`/`helm` mutations need
   the user's go.

- Do NOT create a PR, merge, commit to `main`, force-push, or use `--no-verify`.
