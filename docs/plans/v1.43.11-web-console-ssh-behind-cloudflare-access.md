## Problem

The operator wants to reach the M5 and M4 from anywhere: from a browser-only office machine, from the
phone, or from the M2 while away from home. From there they want to attach to tmux `work` or start
Claude Code. Today there is no remote path into either laptop. It must be interactive and for the
operator only: no agent, token or automation may use it.

## Design

### S1. Outbound tunnel, no inbound port

- Each machine runs its own `cloudflared` connector, so the path works wherever that laptop is and
  never goes through the other laptop or the LAN.
- **Hostnames:** `ssh-m5.<zone>` and `ssh-m4.<zone>`.
- **The tunnel config is per machine.** The M5 extends today's hub tunnel (`scripts/etc/cloudflared/config.yml`).
  The M4 gets its own tunnel, with its credentials file restored from its own Keychain item, the same
  way `bin/cluster-up` restores the hub's.
- **Ingress:** `ssh-<host>.<zone>` → `ssh://127.0.0.1:<WEB_CONSOLE_SSH_PORT>`. No other service is added.

### S2. Cloudflare Access is the only way in

The Access app is self-hosted, uses browser-rendered SSH, and has short-lived certificates turned on.

**Policy:**
- **Allow:** one rule, the operator's GitHub identity (login method GitHub, email equals the
  operator's address).
- **No other rules:** no `Bypass`, no `Everyone`, no service-token rule, no other identity provider.
- **Session duration:** 12 hours or less.

**Second factor:**
- The operator's GitHub account must require 2FA, using an **authenticator app (TOTP) or GitHub Mobile**.
- SMS is a recovery option only. Recovery codes are kept offline.
- Access cannot see which factor GitHub used. The how-to says so, and lists turning on GitHub 2FA and
  removing SMS as the primary method as the operator's own steps.

**How it is applied:**
- `bin/k3dm-web-console setup` creates or updates the app and policy through the Cloudflare API,
  idempotently, with a `--dry-run` that prints the planned change.
- It uses a **dedicated** API token scoped to Access apps and policies for this account only, stored
  in the Keychain as `k3dm-cloudflare-access-token`. It does not widen `k3dm-cloudflare-api-token`.
- Token presence is checked by name only. The token is never printed and never passed as an argument.

### S3. A dedicated `sshd` on a loopback-only, uncommon port that accepts only Access certificates

macOS Remote Login is socket-activated by launchd (`com.openssh.sshd`). It listens on `*:22` on every
interface and ignores `ListenAddress`. The console therefore does **not** use Remote Login, which
stays **off**. Instead:

- **A separate `sshd` instance** runs from a LaunchDaemon, `com.k3d-manager.web-console-sshd`, with its
  own config file, `/etc/ssh/k3dm-web-console_sshd_config`. Its command is `sshd -D -f <that file>`,
  and it uses its own host keys.
- **It listens on loopback only, on a configurable port.** The port is `WEB_CONSOLE_SSH_PORT` in
  `scripts/etc/machine/hosts.conf`, default **42722**.
  - **Bind rule:** listen on `127.0.0.1` and/or `::1` only, never `0.0.0.0`, `::` or `*`.
    - The rendered config has `ListenAddress 127.0.0.1:<port>`. When `WEB_CONSOLE_SSH_IPV6=1`
      (default off), it also has `ListenAddress [::1]:<port>`.
    - `AddressFamily` matches: `inet`, or `any` when IPv6 is on.
    - There must be no `ListenAddress` without an explicit loopback address, and no bare `Port` line,
      because `sshd` then binds every interface.
  - **The tunnel side follows the same rule.** The `cloudflared` ingress targets
    `ssh://127.0.0.1:<port>` literally, not `localhost`, which may resolve to `::1` while `sshd`
    listens on IPv4 only.
  - The default avoids ports that local tools commonly bind or scan. Vagrant uses 2222 (and 2200
    upward on collision), and 2022, 10222, 22222 and 8022 are also common, as is OrbStack's 32222.
  - It is below the macOS ephemeral range (49152–65535), so an outbound connection can never take it.
  - `setup` refuses `22` and those common ports, and refuses a port that something else is already
    listening on (checked with `lsof`). It does not pick a different port silently.
  - The port is not a security control: nothing is reachable from outside on any port. It prevents
    collisions with Vagrant, VMs and other SSH servers on the Mac, and keeps the console from being
    mistaken for Remote Login.

- **The config sets:**
  - `PasswordAuthentication no`, `KbdInteractiveAuthentication no` and `PermitRootLogin no`;
  - `AuthenticationMethods publickey`;
  - `TrustedUserCAKeys` pointing at the Access short-lived-certificate CA public key;
  - `AuthorizedKeysFile none`, so only certificates work, not stored keys;
  - `AllowUsers` set to the operator's local user, read at install time and written only to the config
    file, never to logs or metrics;
  - `ClientAliveInterval 300` and `ClientAliveCountMax 3`.
- **Installation is guarded.** Files and the daemon are installed through `_run_command --require-sudo`.
  `setup` runs `sshd -t -f <file>` before (re)loading the daemon, and removes its own files if the check
  fails. It never edits the system `sshd_config` or `com.openssh.sshd`.
- **`check` fails if Remote Login is on,** because that puts a listener on `*:22`. It tells the
  operator how to turn it off; it does not change it.

### S4. Working session

- The login lands in a shell. The how-to's first command is `tmux new -A -s work` (attach, or create
  if missing), so a dropped browser tab never kills work.
- Claude Code runs inside that tmux as usual.
- The laptop must be awake. A closed lid makes it unreachable (memory
  `reference_clamshell_sleep_ignores_caffeinate`). `check` prints the machine's sleep settings as a
  reminder and does not change them.

### S5. Check and revoke

- `make web-console-check HOST=m5|m4` reports, without changing anything:
  - the tunnel is connected and the ingress is present;
  - every listening socket of the console `sshd` (via `lsof`) is on `127.0.0.1` or `::1`, none on
    `0.0.0.0`, `::` or `*`, and Remote Login is off;
  - password and keyboard-interactive login are off;
  - the console daemon and its config are installed;
  - the Access app exists, and its policy has exactly one allow rule, no bypass, `Everyone` or
    service-token rule, and a session of 12 hours or less;
  - the GitHub account has 2FA enabled, via `gh api user`, which shows the flag only.
- `bin/k3dm-web-console revoke` is the emergency stop. It disables the Access app, removes the
  `ssh-<host>` ingress, and unloads and removes the console sshd daemon and config. The how-to also lists it as
  the first step for a lost phone or laptop, along with revoking Access sessions in the Cloudflare
  dashboard.

### Out of scope

- The Vault UI and other web apps behind Access (the queued `project_secure_vault_remote_access`).
  They reuse S2 later.
- The M2. It is a client here.
- Any agent, webhook or Hermes access through this path.

## What NOT to Do

- Do not open a router port, enable macOS Remote Login, bind any `sshd` beyond loopback, or allow password login.
- Do not reuse or widen an existing Cloudflare token, and never print a token.
- Do not add a service-token, bypass or `Everyone` rule, even for testing.
- Do not give agents, the webhook or Hermes any access through this path.
- Do not create a PR, commit to `main`, or skip pre-commit hooks.
