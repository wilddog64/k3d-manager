## Behaviour

### 1. `docs/howto/tailscale-break-glass.md`

Title `# Tailscale break-glass access (SSH and Screen Sharing from the iPad)`, then these `##` sections in this order,
with exactly these headings:

1. `## What it is and is not` — a second, human-only way in (SSH + Screen Sharing) that does not depend on cloudflared,
   the webhook, the cloud bridge or GitHub; not for agents; it cannot reach a Mac that is powered off or waiting at the
   FileVault unlock screen after a reboot.
2. `## Before you start` — Tailscale login with MFA (passkey or hardware key); D4 apps installed on the iPad; P1 done;
   no work or shared device under this login.
3. `## Set the policy first` — paste `docs/howto/tailscale/policy.hujson` with the real login substituted, before
   enrolling anything; the save succeeds only if its tests pass; remove the default allow-all; turn on device approval;
   the P2 check (break one test, see the save rejected, restore).
4. `## Enroll the Macs and the iPad` — D2 order (m2, m5, m4); Standalone client (remove m4's App Store copy and the
   Homebrew CLI first); apply `tag:k3dm-mac` at once; leave "Use Tailscale DNS settings" off on the Macs; confirm key
   expiry shows disabled; iPad: App Store Tailscale app, same login, approve it only after checking it is refused while
   unapproved. After m5: the hub health check and rollback trigger from the parent's L-E1.
5. `## Set up SSH from the iPad` — a dedicated key generated in the iPad SSH app (Keychain or Secure Enclave), added to
   `~/.ssh/authorized_keys` on each Mac with a comment naming the iPad; compare each Mac's host-key fingerprint on the
   home LAN before the first tailnet connection.
6. `## Turn on Screen Sharing` — per Mac, "Only these users": the operator account; "VNC viewers may control screen with
   password" off; type the macOS password each time, never save it in the VNC app; the P1 display finding (HDMI dummy
   plug if needed).
7. `## Before each trip` — check the iPad's key-expiry date (re-authenticate if under 30 days); pause macOS automatic
   updates and Tailscale auto-update on the Macs while away (an update prompt or restart cuts the path); one test
   connection from a phone hotspot.
8. `## Use it while travelling` — SSH to the Mac's MagicDNS name; Screen Sharing to `<name>:5900`; `tailscale status`
   in the iPad app or `/Applications/Tailscale.app/Contents/MacOS/Tailscale status` on a Mac shows `direct` or
   `relay`; relayed is slower but works.
9. `## Answer a stuck dialog` — the 2026-11-22 case: Screen Sharing in, unlock with the macOS password if locked, click
   the dialog, lock the screen, disconnect.
10. `## Webhook outage` — the evidence-first sequence from
    `docs/bugs/2026-10-26-webhook-unresponsive-minimal-diagnosis-recovery.md`: collect state, at most one
    `make restart-webhook` by the operator, verify end to end; never as a demonstration.
11. `## Lost or stolen iPad` — remove the device in the admin console from any browser; remove its key line from
    `authorized_keys` on each Mac (via another device or at home); if the macOS password was ever saved on it, change it
    on every Mac; a replacement device is approved from the browser (device approval, D5).
12. `## Roll back` — remove grants, delete devices, uninstall the clients, turn Screen Sharing off.
13. `## Limits` — FileVault after a reboot (no network until unlocked at the keyboard); no `autorestart` after a power
    cut; Tailscale control-plane or DERP outage; Screen Sharing listens on the LAN too (the user restriction is the
    fence there); the Standalone client is not a Tailscale SSH server; Tailnet Lock is not used (D5) and why.

No real login, tailnet name, device address or fingerprint; use `<mac>`, `<login>` placeholders.
