## Context

`make test-operator-acceptance` (`bin/k3dm-operator-acceptance`, `scripts/lib/acceptance/`) is an **offline** harness:
its own rule (p3a A-N2) is that a run never executes a real `launchctl`, `kubectl`, `security`, `docker` or `git push`,
and (A-N4) that no planted secret appears in any run-directory file. The opt-in live profile (`live.py`, p3b) reads a
Grafana Viewer token (`glsa_…`) from Keychain `k3dm-grafana-viewer-token` and must never write it anywhere.

Claude reproduced on m4 (2026-11-27): with a recording `security` stub first on `PATH`, one offline run made
`security find-generic-password -s k3dm-slack-signing-secret -a k3dm -w` and the same for `k3dm-slack-role-map`; and
`<run>/job/make.log` contained `password=CanarySecret-123`.

## Defects to fix

1. **B1 — offline run reads the real Keychain.** `scenarios/jobs.py` `run_job` loads `bin/k3dm-webhook` in-process;
   importing it imports `webhook.auth`, which at import time calls `_keychain_secret("k3dm-slack-signing-secret")`
   (`scripts/lib/webhook/auth.py:33`, guarded by `os.environ.get("SLACK_SIGNING_SECRET") or …`) and the role-map read
   (`auth.py` ~113-127). The Makefile target (`Makefile:1730-1731`) runs the CLI without `scripts/tests/tripwire.sh`
   (and tripwire would not fail anyway: it classifies `security find-generic-password` as a known read).
   Fix: no `security` process may start during an offline run. Either load the webhook with placeholder values for
   every Keychain-backed setting already in the environment (`SLACK_SIGNING_SECRET`, the role-map variable `auth.py`
   reads first) restored afterwards, or run the scenario in a guarded child with the stub `PATH`. Also wrap the
   Makefile target with `scripts/tests/tripwire.sh`.
2. **B2 — exporter pushes bypass the guard and honour `HTTP_PROXY`.** `scenarios/k3dm_tests.py` `metrics_sequence`
   calls `module.push_metrics(..., endpoint=fake.url)` in-process with the default opener. Fix: `guard.validate_url(fake.url)`
   first, and pass an opener built with `urllib.request.ProxyHandler({})` (the way `live.py` `_open_grafana` does).
   `test_parent_environment_sentinels_do_not_change_results` discards both runs' `passed`; assert them, and add
   `HTTP_PROXY`, `http_proxy`, `SLACK_SIGNING_SECRET` to the sentinel set.
3. **B3 — canary left in the run directory.** `run_job` writes `job/make.log` (with the canary) under `ctx.run_dir`
   and leaves it; `transport.log` (`k3dm_tests.py` ~40) is written unredacted; `runner.run_scenarios` chmods only direct
   children. Fix: build the job fixture in a temporary directory outside the run dir (or remove it in `finally`),
   write `transport.log` through `runner.redact`, and set `0600` files / `0700` dirs recursively under the run dir.
4. **M4 — offline `--with-prior-art` and draft provenance.** `bin/k3dm-operator-acceptance` accepts `--with-prior-art`
   without `--live` and then calls `hermes.prior_art.search`. Fix: `parser.error("--with-prior-art requires --live")`.
   `drafts.py` hardcodes `**Should have been caught by:** live check`; pass `offline test` for offline runs. `drafts.py`
   resolves `run_root` without `.expanduser()`; use the same resolution as `runner.py`.
5. **M7 — Grafana token redaction.** `runner.SECRET_RE` lacks `glsa_[A-Za-z0-9_]+`; `live.py` calls `run_scenarios`
   (which writes reports) before `_rescrub_run_dir`. Fix: add the `glsa_` pattern to `SECRET_RE`, and let
   `run_scenarios` accept `extra_secrets` so the live token is redacted before the first write and in the returned
   report. Also: `live.py` `_bridge_gated` swaps `webhook_proc._spawn_capture_text` while importing the bridge, which
   leaves `webhook.auth._spawn_capture_text` replaced if `webhook.auth` is first imported there; restore it too.
6. **M9 — empty "Run complete" panel passes.** `live.py` ~589 `complete_ok = api_ok and (panel9_val is None or
   panel9_val == 1)`. Fix: `panel9_val == 1`.
7. **M10 — live tests can write to the real `docs/bugs/`.** `scripts/tests/bin/test_operator_acceptance_live.py`
   calls `run_live_profile` at lines ~333 and ~633 without `bugs_dir`/`repo_root`. Fix: pass scratch values in every
   call (or make the fixture default them), and add a test asserting the real `docs/bugs/` tree hash is unchanged
   after the whole live test module's scenarios run.
