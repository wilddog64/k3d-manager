## Goal

On 2026-11-08 three Hermes failures passed every offline test and were found only when the operator pressed a
button: the Slack app had Interactivity off, `/hermes-auth` pointed at the interactivity Request URL instead of the
commands one, and the cards were posted by a different app from the relay's. The first two are Slack app
*settings*. A probe sent straight to the relay skips Slack and cannot see them; only the app manifest can. This plan
adds two sensors that are silent on a healthy stack and degrade within a day of such a setting going wrong.

## Design

Constants in `scripts/lib/hermes/sensors.py`: `SLACK_RELAY = "https://k3dm-slack-relay.k3dm.workers.dev"`,
`SLACK_APP_ID = "A0B863SCQUV"` (app `k3d-manager`, the one whose signing secret the relay verifies; not
`k3dm-notices` A0CFHA9KCNQ), `SLACK_CONFIG_SERVICE = "k3dm-slack-config-token"`,
`SLACK_CONFIG_REFRESH_SERVICE = "k3dm-slack-config-refresh-token"`, `SLACK_RELAY_NAMED_ROUTES = ("/slack/interactivity",
"/slack/events", "/hermes/approvals")` (from `workers/slack-relay/index.js:342-352`), `SLACK_REQUIRED_COMMANDS =
("/hermes-auth",)`.

**Sensor `slack_app_config(api, state, store, now, threshold=1)`.** `api(method, token, fields)` POSTs a form to
`https://slack.com/api/<method>` with `Authorization: Bearer <token>` as a header (never in the URL or body for
`apps.manifest.export`) and returns the decoded JSON. `store` has `read(service) -> str` and `write(service, value) ->
bool`; the default is Keychain-backed (read = existing `_keychain_secret`; write = `security -i` fed
`add-generic-password -U -a k3dm -s <service> -X <hex-of-value>` on **stdin**, the method `bin/k3dm-machine-secrets:199`
already uses, then a read-back compare). `store.write` refuses any service other than the two constants above.

1. **Cadence.** The manifest is read at most every `K3DM_HERMES_SLACK_CONFIG_INTERVAL` seconds (default 3600, floor
   60), tracked in `state["slack_config"]["checked_at"]`. Between checks the sensor returns the last record unchanged
   (same status and evidence, `data.cached: true`) and does not touch the debounce counter.
2. **Rotation.** Before the manifest call, if `state["slack_config"]["expires_at"]` is absent or within 3600 s of
   `now`, or if the manifest call returns `token_expired` or `invalid_auth`, rotate once per cycle:
   `api("tooling.tokens.rotate", None, {"refresh_token": <refresh>})` (the refresh token goes in the form body, the
   documented parameter; no Authorization header). On `ok: true`: write the new **refresh** token, then the new access
   token, read both back, store `expires_at = exp` from the response, then call the manifest with the new token. The
   old refresh token is dead once rotate returns, so any write or read-back failure sets
   `state["slack_config"]["needs_regenerate"] = true` and returns unknown with evidence
   `config token rotation could not be stored; regenerate at api.slack.com/apps (Your App Configuration Tokens) and
   re-store both items`. A crash between rotate and the writes leaves the old refresh token in Keychain; the next
   rotate then fails with a Slack error and the sensor returns the same unknown + hint, so the loss is reported, not
   silent. `needs_regenerate` clears on the next successful manifest call.
3. **Checks on `.manifest`** (paths from capture 1 below). Raw-degraded, with one evidence item per finding naming the
   field and the expected value, never a token:
   - `settings.interactivity.is_enabled` is not `true`;
   - `settings.interactivity.request_url` is not `SLACK_RELAY + "/slack/interactivity"`;
   - a command in `SLACK_REQUIRED_COMMANDS` is missing from `features.slash_commands[].command`;
   - any `features.slash_commands[].url` whose scheme+host is not `SLACK_RELAY`'s, or whose path equals or starts with
     a `SLACK_RELAY_NAMED_ROUTES` entry. The bare root, `/slack/command` and `/slack/commands` are all healthy
     today (capture 1: they fall through to the command handler) and must stay healthy.
   `data` carries `commands` (count), `findings`, and `event_url` (recorded, not judged: capture 1 finding b).
4. **Status.** Findings → `_debounced("slack_app_config", True, threshold, state)`; with the hourly cadence and
   threshold 1 that is degraded on the second consecutive real check. No findings → healthy and debounce reset.
   Missing token or refresh token, any `ok: false` other than the rotate path, a network error, or a manifest without
   the expected keys → unknown with the Slack error code or `credential unavailable: <service>`. Unknown never
   resets or advances the debounce counter. Note: `pager.py:79-82` texts the operator after 6 unknown cycles (30
   min); that is the wanted escalation for `needs_regenerate`.

**Sensor `slack_relay_reachable(probe, state, threshold=2)`.** `probe(url)` sends an unsigned `POST` with an empty
body, no `X-Slack-Signature` or `X-Slack-Request-Timestamp` header, timeout 5 s, and returns the HTTP status code
(4xx/5xx included) or raises on timeout or connection error. It probes `/slack/interactivity` and `/slack/commands`.
Both `401` → healthy, evidence `relay deployed and verifying signatures` (capture 3: 401 proves deployment and the
signature check, **not** routing, since any unmatched POST also gets 401; routing is `slack_app_config`'s job). Any
other code, a timeout or a connection error on either path → raw-degraded with the path and code (or `timeout`),
debounced at threshold 2. `data` carries the code per path. No unknown state: a failed probe is the signal.

Both are wired in `bin/k3dm-hermes` after `alert_delivery` (`bin/k3dm-hermes:217`), with transports defined there
next to `_http_json` (`:80`): a form-POST helper for `api` and a `_relay_probe` that maps `urllib.error.HTTPError` to
its code. The Grafana Hermes dashboard lists `hermes_sensor_status` generically
(`scripts/etc/argocd/platform-ops/grafana-dashboard-hermes.yaml:38-56`), so it needs no change.

**Out of scope:** checking that Hermes posts from the relay's app (the incoming-webhook URL carries no app id); judging
whether Event Subscriptions should go through the relay (operator question, capture 1 finding b); tidying the 13
non-canonical command URLs.

   **approved by the operator 2026-11-13** ("go for your recommendation"). The spec must add: rotate writes both items
   (new refresh token first is not enough; a crash between `tooling.tokens.rotate` and the Keychain write must not leave

3. The unsigned-POST status codes from the live relay for both paths.

## What NOT to do

- Do not copy the relay's signing secret to the hub or sign any probe.
- Do not send a real button click, post anything to Slack, or call any Slack method other than
  `apps.manifest.export` and `tooling.tokens.rotate`.
- Do not write any Keychain item other than the two named; do not pass a token as a process argument.
- Do not treat an API error as healthy, and do not demand `/slack/commands` exactly.
- Do not edit `workers/slack-relay/index.js` or the Slack app settings.
