## Problem

Agent Dispatch shows only per-spec averages for time. "Time to land" (top right) is the mean
first-dispatch-to-land per spec, and the Per spec table's Total row sums Codex time but leaves
Time to land blank. Nothing answers "how long did this release take?"

Two answers are wanted:

- **Release span** — calendar time from the release's first dispatch (the earliest Codex `start` of
  any spec in the release, including specs later abandoned or never landed) to its PR merge. While
  the release is unmerged, it ends at the last successful landing (`land`) so far.
- **Active time** — the time at least one spec of the release was in flight (first `start` to `land`,
  per spec), with overlaps counted once. Summing per-spec times double-counts parallel specs.

Worked from the ledger and `gh` on 2026-10-24:

| Release | Specs | Span to last land | Span to merge | Active | Mean time to land |
|---|---|---|---|---|---|
| v1.43.3 | 7 | 2.1 h | — | 47.4 min | 9.51 min |
| v1.43.4 | 8 | 24.9 h | ≈ 42 h (PR #145, merged 2026-10-18 19:01 UTC) | 63.4 min | 7.92 min |

The merge time is fixed once a release merges, so the exporter must not ask GitHub for it on every
run. `/post-merge` already looks up each merged PR; it records the merge time in the ledger once.

## Fix

### F1. Ledger: `release-merged`

New subcommand in `bin/k3dm-codex-dispatch`:

`bin/k3dm-codex-dispatch release-merged --version vX.Y.Z --pr N --merged-at <ISO-8601 UTC>`

- Validates `--version` against the existing version pattern, `--pr` as a positive integer, and
  `--merged-at` as `YYYY-MM-DDTHH:MM:SSZ`; any invalid or missing value exits 2 with a message and
  writes nothing.
- Appends one ledger event via `_dispatch_ledger_event`: `event: "release_merged"`, `version`,
  `slug: "release"`, `pr`, `merged_at` (epoch seconds). `ts` stays the write time.
- Idempotent: if the ledger already has a `release_merged` event for that version with the same
  `merged_at`, print `already recorded` and write nothing. A different `merged_at` for the same version
  is appended (the exporter uses the latest-written one).
- Makes no network call. Add a `codex-release-merged` Makefile target beside the other `codex-*`
  targets, passing `VERSION`, `PR`, `MERGED_AT`, and add it to `.PHONY`.

### F2. Exporter

In `_render_scope`, for **release scopes only** (`time_scope` false), from the landed specs in scope:

- `k3dm_dispatch_release_span_minutes{window="<version>",end="merge|last_land"}` = (end − start) / 60.
  Start is the earliest `start` ts of **any** spec in the version, landed or not. End is the version's
  latest-written `release_merged.merged_at` when present (`end="merge"`), else the latest `land` ts
  (`end="last_land"`). Only `land` events end anything; `land_refused`, `abandon` and `codex_exit`
  never do.
- `k3dm_dispatch_release_active_minutes{window="<version>"}` = length of the union of the per-spec
  intervals [first `start`, last `land`], / 60.

For active time, a spec counts only if it has both a `start` and a `land`. Emit neither series when
the version has no `land` at all. Do not emit them for time windows (1d/7d/30d). `release_merged` events must not count
as specs, tasks, runs or lands anywhere else in the exporter.

### F3. Dashboard

Add two stat panels next to "Time to land", titled **Release span** and **Active time**, unit
minutes (Grafana auto-scales to hours/days), querying the two series with `window="$window"`.
Release span's description says it ends at the PR merge, or at the last land while the release is
unmerged; time windows show no data.

The existing "Time to land" stat is the per-spec mean; add "Mean per spec." to its description so it
is not read as a total. Leave the Per spec table footer as it is: Grafana 11.4 applies one reducer to
every footer column, so it cannot show a mean for one column and sums for the others.

## Tests

`scripts/tests/bin/test_dispatch_metrics.py`, synthetic ledgers only:

1. Two specs in one release, intervals [0,600] and [300,900], no merge event: span 15 min with
   `end="last_land"`, active 15 min.
2. Two specs, [0,600] and [3600,4200]: span 70 min, active 20 min.
3. Case 2 plus `release_merged` with `merged_at` 7200: span 120 min with `end="merge"`, active 20 min.
4. A rework spec with two `start`s: its interval begins at the first `start`.
5. A spec with `start` but no `land`, dispatched before every landed spec, moves the span's start
   earlier and leaves active time unchanged.
5b. A `land_refused` later than every `land` does not move the span's end.
6. Time windows (`7d`) emit neither series.
7. A `release_merged` event changes no other series (landed count, tasks, runs identical with and without it).

`scripts/tests/bin/codex_dispatch.bats` (ledger in `BATS_TEST_TMPDIR`):

8. `release-merged` with valid args appends exactly one `release_merged` event with epoch `merged_at`.
9. Running it twice with the same args appends nothing the second time.
10. A bad `--merged-at`, `--pr` or `--version` exits 2 and leaves the ledger unchanged.

Show tests 1, 3, 5, 6 and 8 red against the pre-fix code.
