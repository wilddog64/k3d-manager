## Problem

The Plans table shows each plan's Order and its declared `**Depends on:**` plans. It does not show
how the release will actually run:

1. **Which plans can run together.** On v1.43.8, plans 1, 2 and 4 share no files and can be
   dispatched at once; plan 3 must wait for plan 1. The table shows Order 1–5, which reads as a
   sequence.
2. **Timing constraints.** Plan 5 (Hostinger edge) should run only after the 2026-10-29 hub
   rebuild. That is a window, not a plan, so it cannot go in `Depends on`, and today it lives only
   in the roadmap prose.
3. **Missing dependencies.** Until 2026-10-25, v1.43.8 plans 1 and 3 both listed
   `bin/k3dm-dispatch-metrics` and the Agent Dispatch dashboard in `**Component:**` with no
   `Depends on` between them. Nothing flagged it; Claude found it by reading the specs.

## Scope and design

### W1. Wave column, derived from dependencies

- For each plan, Wave = 1 when it has no `Depends on` plan in the same release. Otherwise Wave = 1
  plus the highest Wave among its same-release dependencies. Dependencies on other releases do not
  change the Wave; they stay in Depends on.
- A dependency cycle within a release shows Wave `cycle` for every plan in it.
- Plans not yet assigned a plan order (no `**Release:** … (plan N of …)`) keep the current
  behaviour and show `-`.

### W2. Optional `**Wave:**` header for timing constraints

- Format: `**Wave:** <n> — <reason>`, for example
  `**Wave:** 3 — after the 2026-10-29 hub rebuild`.
- A declared Wave may only move a plan **later** than its derived Wave. If it is lower, the table
  shows the derived Wave and the Wave note says `declared <n> < required <m>`.
- The reason is shown in a **Wave note** column. It is sanitised like the title (quotes,
  backslashes and control characters removed) and capped at 80 characters.

### W3. Undeclared overlap column

- Each plan's files are the backticked paths on its `**Component:**` line (the body is not read; it
  mentions files for context, which would be noise). A path ending in `/` matches every path under
  it.
- Two plans in the same release **overlap** when they share a file and neither depends on the
  other, directly or through other plans.
- An **Overlaps** column lists them as `plan <n>: <file>`, at most three, then `+<k> more`. Empty
  shows `-`.
- A per-release count, `k3dm_plan_undeclared_overlaps{repo,release}`, backs a small stat beside the
  Plans table so a nonzero count is visible without scrolling.

### W4. Docs

- `docs/guides/grafana-dashboards.md` explains Wave, Wave note and Overlaps, and how to clear an
  overlap: add `Depends on`, or accept it by listing the overlap in the plan's body (it stays
  flagged, by design).
- The plan-filing guidance says to keep `**Component:**` complete, because overlap detection reads
  only that line.

- Do not infer dependencies from overlaps; overlaps are shown, never turned into Depends on.
- Do not change Order, Depends on or any existing column's meaning.
- Do not create a PR, commit to `main`, or skip pre-commit hooks.
