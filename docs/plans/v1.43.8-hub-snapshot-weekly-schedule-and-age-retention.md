## Problem

`make snapshot` (`hub_snapshot_capture`) only runs by hand. On 2026-10-24 the newest verified snapshot was
`20261009T170742Z`, 358 hours old. Retention is by count only: after a capture, `_hub_snapshot_prune_verified`
keeps the newest `K3DM_SNAPSHOT_KEEP` (3) verified snapshots, whatever their age. The operator wants:

- a capture once a week (daily is not wanted: each snapshot is about 3.4 GB and the capture copies the hub's
  datastore and PVCs while the hub runs);
- verified snapshots older than 30 days purged.

On 2026-10-24 the M2 store (`m2jump:k3dm-snapshots`) held two verified snapshots of 3.4 GB and 3.3 GB, with
351 GB free.

## Fix

### F1. Age-based retention, with a floor

Add `K3DM_SNAPSHOT_MAX_AGE_DAYS="${K3DM_SNAPSHOT_MAX_AGE_DAYS:-30}"` next to the other defaults.

Change `_hub_snapshot_prune_verified` to take the floor and the age:

- Walk the verified snapshots, newest first (names are `YYYYMMDDTHHMMSSZ`, UTC).
- The newest `K3DM_SNAPSHOT_KEEP` verified snapshots are always kept, whatever their age. `K3DM_SNAPSHOT_KEEP`
  becomes this floor. Its default stays 3, so if captures stop, the last three good snapshots are never purged.
- Every other verified snapshot is removed when its timestamp is more than `K3DM_SNAPSHOT_MAX_AGE_DAYS` days
  before now. A verified snapshot within the age limit is never removed for being over the count.
- A name that does not parse as a timestamp is kept and warned about: `_warn "[hub-snapshot] keeping
  <name>: name is not a timestamp"`.
- `K3DM_SNAPSHOT_MAX_AGE_DAYS` must be a positive integer. If it is not, return 2 with an `_err`, the same
  way `K3DM_SNAPSHOT_KEEP` is checked.

Compute the age in bash from the name and `date -u +%s`. On macOS, `date -j -u -f %Y%m%dT%H%M%SZ` gives the
epoch. Fall back to GNU `date -u -d` so the BATS suite also runs on Linux CI. Do not run `date` on the M2
host.

`hub_snapshot_prune` and the post-capture auto-prune both use the new rule. Update `hub_snapshot_prune`'s
final message to: `retained verified snapshots newer than ${K3DM_SNAPSHOT_MAX_AGE_DAYS} days (at least ${_keep} newest)`.

### F2. Stale incomplete uploads

A failed capture leaves `<timestamp>.INCOMPLETE`. In `_hub_snapshot_capture_retention_notice`, after a
**successful** capture, remove any `.INCOMPLETE` directory whose timestamp is more than 24 hours old. Never
remove the current run's directory, and never remove one less than 24 hours old: another capture may be
uploading it. Still warn about the ones that remain.

### F3. Weekly scheduled capture

1. `hub_snapshot_scheduled`, a public function in a subshell like `hub_data_export_scheduled`. It does the
   following:
   - Takes a lock with `mkdir "${K3DM_SNAPSHOT_LOCK:-${HOME}/.local/share/k3d-manager/hub-snapshot.lock}"`.
     If the lock is held, it prints `_info "[hub-snapshot] another capture is running; skipping"` and
     returns 0. It releases the lock on EXIT.
   - Runs `_ssh_config_guard --repair "$K3DM_SNAPSHOT_HOST"` first when that function is defined, as
     `hub_data_export_scheduled` does.
   - Runs `hub_snapshot_capture` and returns its exit code.
   - Brackets the run with timestamped `_info` start and end lines that include the exit code, so the log
     shows each weekly run.
2. `hub_snapshot_capture` honours the same lock when it is called from `make snapshot`. It takes the lock,
   or skips when the lock is held, unless the scheduled wrapper already holds it (`HUB_SNAPSHOT_LOCK_HELD=1`).
   This stops a manual run and the weekly run from uploading at the same time.
3. New template `scripts/etc/launchd/com.k3d-manager.hub-snapshot.plist.tmpl`, copied from
   `com.k3d-manager.hub-data-export.plist.tmpl`:
   - Label `com.k3d-manager.hub-snapshot`.
   - Program `{{K3D_MANAGER_PATH}} hub_snapshot_scheduled`.
   - `StartCalendarInterval` `Weekday` 0, `Hour` 2, `Minute` 30: Sunday 02:30 local time, an hour before the
     daily 03:30 hub-data export.
   - The same `HOME` and `PATH` environment, and `RunAtLoad` false.
   - Log to `{{HOME}}/Library/Logs/k3dm-hub-snapshot.log`.
   - launchd runs a missed calendar slot when the Mac wakes, so a sleeping laptop delays the run rather than
     skipping it.
4. `hub_snapshot_schedule` and `hub_snapshot_unschedule`, copied from `hub_data_export_schedule` and
   `hub_data_export_unschedule` with the new label and template.
5. Makefile targets `snapshot-schedule` and `snapshot-unschedule`, next to `snapshot-prune`, each with a
   `##` help line, and list both in `docs/howto/makefile.md`.

### F4. Docs

In `docs/howto/hub-snapshots.md`, add a "Weekly schedule and retention" section covering:
- the Sunday 02:30 run, the log path, and `make snapshot-schedule` / `snapshot-unschedule`;
- the age rule with its floor of three;
- that `make status` warns when the newest snapshot is over 7 days old, which is how a broken schedule
  shows up.

   current run's are not.
7. `hub_snapshot_scheduled` with the lock directory already present returns 0 and does not call

8. `hub_snapshot_scheduled` returns the capture's exit code and removes the lock afterwards, on success and on
   failure.
