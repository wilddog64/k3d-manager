## Why this shape

The OCI provider already proves the CNI groundwork (flannel disabled + Cilium, commented
"required for Istio ambient mesh"). Neither the ACG-sandbox path nor Hostinger replicate it, and
**no ArgoCD ApplicationSet installs Istio anywhere in this repo** (`platform-helm` deploys only the
argo-cd chart) — so ambient is greenfield for app clusters.

Two hard constraints drove the design:

1. **`deploy_app_cluster` is shared.** `k3s-az` and `k3s-gcp` call the same installer. Ripping
   flannel out unconditionally would leave *their* nodes permanently `NotReady` (they get no
   Cilium). Therefore the CNI swap is **opt-in behind `K3S_AMBIENT_MESH=true`, default off** —
   az/gcp/default deploys stay on flannel, untouched.
2. **Cilium cannot be GitOps'd** (chicken-and-egg: no CNI ⇒ node `NotReady` ⇒ ArgoCD schedules
   nothing). Cilium stays a **provider bootstrap** step. Only **Istio** (istiod + istio-cni +
   ztunnel) goes through the new ApplicationSet.

**Critical ordering (both installers):** with `--flannel-backend=none` the node stays `NotReady`
until a CNI is installed. Cilium MUST run **between** the k3s install and the node-Ready wait, or
that wait times out.

### Change 1.4 — new `_ambient_install_cilium` (multi-node, in `shopping_cart.sh`)

Ported from `_oci_install_cilium`; Cilium is a DaemonSet so a single install on the server covers
agents as they join. `cni.exclusive=false` is mandatory so istio-cni can chain.

```bash
function _ambient_install_cilium() {
  local ssh_user="$1" external_ip="$2" ssh_key="$3"
  local ssh_cmd="ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -i ${ssh_key} ${ssh_user}@${external_ip}"
  _info "[shopping_cart] Installing Cilium ${_AMBIENT_CILIUM_VERSION} (CNI for Istio ambient)..."
  # shellcheck disable=SC2029
  ${ssh_cmd} "
    KUBECONFIG=/etc/rancher/k3s/k3s.yaml helm repo add cilium https://helm.cilium.io/ >/dev/null 2>&1 || true
    KUBECONFIG=/etc/rancher/k3s/k3s.yaml helm repo update >/dev/null 2>&1
    KUBECONFIG=/etc/rancher/k3s/k3s.yaml helm upgrade --install cilium cilium/cilium \
      --version '${_AMBIENT_CILIUM_VERSION}' \
      --namespace kube-system \
      --set operator.replicas=1 \
      --set cni.exclusive=false \
      --set kubeProxyReplacement=true \
      --set k8sServiceHost='${external_ip}' \
      --set k8sServicePort=6443
  "
  local attempts=0
  until ${ssh_cmd} "KUBECONFIG=/etc/rancher/k3s/k3s.yaml kubectl -n kube-system rollout status daemonset/cilium --timeout=10s >/dev/null 2>&1" 2>/dev/null; do
    (( attempts++ ))
    if (( attempts >= 18 )); then
      _err "[shopping_cart] Cilium DaemonSet not ready after 3 min"
      return 1
    fi
    sleep 10
  done
  _info "[shopping_cart] Cilium ready"
}
```

> **Implementation handoff:** `docs/plans/v1.16.0-phase2-istio-ambient-appset.md` supersedes the

### Change 2.1 — NEW `scripts/etc/argocd/applicationsets/istio-ambient.yaml`

Mirrors `observability-acg.yaml` (list generator, `destination.name: ${APP_CLUSTER_NAME}`, GitOps
sync). Ambient = istio-base → istiod → istio-cni → ztunnel. **The k3s CNI-path override is the
crux** — istio-cni must point at k3s's dirs or the node agent silently no-ops and ambient capture
never happens. Cross-Application ordering is not guaranteed by ApplicationSet; `sync-wave`
annotations + ArgoCD automated retry/self-heal converge (istio-cni/ztunnel fail until istiod's
webhook is up, then retry succeeds) — this is expected, see verification.

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: istio-ambient
  namespace: ${ARGOCD_NAMESPACE}
  labels:
    managed-by: k3d-manager
    app-type: mesh
spec:
  goTemplate: true
  generators:
    - list:
        elements:
          - name: istio-base
            chart: base
            wave: "0"
          - name: istiod
            chart: istiod
            wave: "1"
          - name: istio-cni
            chart: cni
            wave: "2"
          - name: ztunnel
            chart: ztunnel
            wave: "3"
  template:
    metadata:
      name: '{{.name}}'
      annotations:
        argocd.argoproj.io/sync-wave: '{{.wave}}'
    spec:
      project: platform
      destination:
        name: ${APP_CLUSTER_NAME}
        namespace: istio-system
      source:
        repoURL: https://istio-release.storage.googleapis.com/charts
        chart: '{{.chart}}'
        targetRevision: ${AMBIENT_ISTIO_VERSION}
        helm:
          releaseName: '{{.name}}'
      syncPolicy:
        automated:
          prune: true
          selfHeal: true
        retry:
          limit: 10
          backoff:
            duration: 15s
            maxDuration: 3m
        syncOptions:
          - CreateNamespace=true
          - ServerSideApply=true
```

> Codex: the per-chart `--set` values MUST be added as explicit `helm.parameters:` (name/value
> pairs) on the relevant elements — ArgoCD Helm sources take `parameters`, not a raw flag string.
> Required values, do not drop:
> - **istiod**: `profile=ambient`
> - **istio-cni**: `profile=ambient`, `cni.cniConfDir=/var/lib/rancher/k3s/agent/etc/cni/net.d`,
>   `cni.cniBinDir=/var/lib/rancher/k3s/data/current/bin`
> - **istio-base**: `defaultRevision=default`
>
> The cleanest expression is a per-element `params` list field carried through goTemplate into
> `helm.parameters`; if that complicates the generator, hard-code the parameters per generated
> Application by splitting into per-component templates. Keep the exact keys/values above.

### Change 2.2 — NEW `scripts/plugins/istio_ambient.sh`: `deploy_istio_ambient`

Mirrors `deploy_observability_acg` (`observability.sh:317`) — `envsubst | _kubectl apply -f -`.

```bash
#!/usr/bin/env bash
# scripts/plugins/istio_ambient.sh — install Istio ambient mesh on an app cluster via ArgoCD

function deploy_istio_ambient() {
  if [[ "${1:-}" == "-h" || "${1:-}" == "--help" ]]; then
    cat <<'HELP'
Usage: [APP_CLUSTER_NAME=<ctx>] ./scripts/k3d-manager deploy_istio_ambient

Applies the istio-ambient ApplicationSet to the hub ArgoCD, targeting APP_CLUSTER_NAME
(default: ubuntu-k3s). Requires the target cluster's CNI to be Cilium with cni.exclusive=false
(set K3S_AMBIENT_MESH=true at deploy_cluster time).
HELP
    return 0
  fi

  local _appset="${SCRIPT_DIR}/etc/argocd/applicationsets/istio-ambient.yaml"
  : "${ARGOCD_NAMESPACE:=cicd}"
  : "${APP_CLUSTER_NAME:=${ARGOCD_APP_CLUSTER_NAME:-ubuntu-k3s}}"
  : "${AMBIENT_ISTIO_VERSION:=1.24.2}"
  export ARGOCD_NAMESPACE APP_CLUSTER_NAME AMBIENT_ISTIO_VERSION

  _info "[istio_ambient] Applying istio-ambient ApplicationSet (target: ${APP_CLUSTER_NAME})..."
  # shellcheck disable=SC2016
  if envsubst '$ARGOCD_NAMESPACE $APP_CLUSTER_NAME $AMBIENT_ISTIO_VERSION' < "${_appset}" | _kubectl apply -f -; then
    _info "[istio_ambient] Applied — ArgoCD will sync istio-system on ${APP_CLUSTER_NAME}"
  else
    _err "[istio_ambient] Failed to apply istio-ambient ApplicationSet"
    return 1
  fi
}
```

## Rules

- `set -euo pipefail` semantics preserved; double-quote every expansion.
- **Opt-in flag `K3S_AMBIENT_MESH` defaults off** — az/gcp/default deploys must be byte-for-byte
  unaffected. `--flannel-backend=none` may appear ONLY inside a `K3S_AMBIENT_MESH == true` guard.
- Pin chart versions explicitly (no floating `latest`) — supply-chain rule.
- New service in its own namespace (`istio-system`) — never `default`.
- Route privileged/remote work through `ssh`/`_run_command`; do NOT call `sudo` directly.
- Minimal patch — do NOT touch the local-dev `_istioctl` path or `istio-operator.yaml.tmpl`.
- `shellcheck -S warning` zero new warnings on every changed `.sh`.
