## Run

- 30 consecutive days, with targets and stop conditions frozen at start (v1.63.0 plan 2) and sealed chaos
  (plan 3).
- The release branch stays open for the run. Fixes for defects found during the run land on it under the
  normal bug rules (bugs before features). Those fixes are themselves change load, and are counted.
- Other releases may proceed in parallel only if the operator chose that before the pilot. Either way,
  each merge is recorded as a change event.

## Report (`docs/retro/YYYY-MM-DD-saas-sim-30-day-report.md`)

- **Verdict:** yes, or "no, because S<n>" with the day and the cause.
- Scorecard over the whole run and per week.
- Chaos table: each fault with its injection time, time to detect, time to recover, whether it was
  detected by an alert or by a human, and its bug doc. Includes the revealed seed and the commitment check.
- Operator minutes per day and agent API-equivalent cost per day, by model.
- Bugs found, counted by "should have been caught by".
- The pre-registered predictions in v1.63.0 plan 1, each scored right or wrong.
- What to change first to pass next time, ranked by evidence from the run.
