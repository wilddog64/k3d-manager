## Problem

There is no per-PR view of CI. The Hermes `ci` sensor reads the newest workflow run in
k3d-manager and reports one healthy/degraded verdict. Watching a release PR such as #143 means
polling `gh run list` or the PR page by hand, and a check that hangs or fails between pushes is
noticed only when someone looks.

## Scope

- **Repos:** `wilddog64/k3d-manager` and `wilddog64/lib-foundation`. lib-foundation is a subtree
  of k3d-manager, but its PRs and CI run in its own repo, and a lib-foundation PR often gates a
  k3d-manager release (a fix there must merge, release and be subtree-pulled first). The
  shopping-cart repos retire after v1.50.x and stay out. The repos are one tuple, `REPOS`.
- **PR numbers repeat across repos** (both have a #66). Every series carries `repo`, and every
  join, sort and legend uses `repo` + `pr`, never `pr` alone.
- **What counts as a check:** GitHub **check runs** on the PR's head commit: the `CI` workflow
  jobs (`lint`, `alertmanager-behaviour`, `detect`, `stage2`), CodeQL, and any other Actions or
  app check. A Copilot review is a PR **review**, not a check run, and is **not** tracked here.
- **Credential:** the existing Hermes GitHub token (Keychain `k3dm-hermes-gh-token`, read through
  `_keychain_secret(GITHUB_SERVICE)`), which the `ci` sensor already uses against the same
  endpoints. No new credential and no new scope.

### 1. New module `scripts/lib/hermes/pr_checks.py` (pure, no I/O of its own)

```python
"""Collect and render the CI check state of open pull requests."""
import re
from datetime import datetime

REPOS = ("wilddog64/k3d-manager", "wilddog64/lib-foundation")
MAX_PRS = 20
FAILED = ("failure", "timed_out", "action_required", "startup_failure", "stale")
RUNNING = ("queued", "in_progress", "waiting", "requested", "pending")
```

Functions:

- `collect(fetch, repo)`: `fetch(path)` returns parsed JSON for a GitHub API path.
  - `pulls = fetch(f"/repos/{repo}/pulls?state=open&per_page={MAX_PRS}")`; must be a list, else
    `ValueError`.
  - For each PR: `runs = fetch(f"/repos/{repo}/commits/{head_sha}/check-runs?per_page=100")`;
    must be a dict with a `check_runs` list, else `ValueError`.
  - Keep **one run per check name**: the one with the highest `id` (a re-run supersedes the old
    one).
  - A check's `state` is its `conclusion` when `status == "completed"`, else its `status`.
  - Return a list of PR dicts:
    `{"number": int, "title": str, "head": head_sha[:8], "draft": bool, "checks": [{"name", "state",
    "started": epoch or None, "completed": epoch or None}]}`. Timestamps come from `started_at` /
    `completed_at` (ISO 8601, `Z` suffix).
- `overall(checks)`: `"none"` when there are no checks; `"failure"` if any state is in `FAILED`;
  else `"running"` if any is in `RUNNING`; else `"success"`. `cancelled`, `skipped` and `neutral`
  count as neither failed nor running, so a PR whose superseded run was cancelled reads `success`
  once its newer run is green.
- `label(value, limit=100)`: Prometheus label-safe text: replace `\`, `"`, tabs and newlines with
  a space, collapse whitespace, strip, and truncate to `limit` with a trailing `…` (same approach as
  the bug title in `bin/k3dm-vectordb-metrics`).
- `render(prs, now, repo)`: Prometheus text exposition, one line per series:

  ```text
  k3dm_pr_info{repo,pr,title,head,draft} 1
  k3dm_pr_overall{repo,pr,state} 1
  k3dm_pr_check_state{repo,pr,check,state} 1
  k3dm_pr_check_duration_seconds{repo,pr,check} <seconds>
  k3dm_pr_checks_open_prs{repo} <count>
  k3dm_pr_checks_last_scrape_timestamp_seconds{repo} <now>
  k3dm_pr_checks_scrape_success{repo} 1
  ```

  `pr` is the PR number as a string, `draft` is `"true"`/`"false"`. Duration is
  `completed - started` for a finished check and `now - started` for a running one; a check with no
  `started` emits no duration line. Every label value goes through `label()`.
- `render_failure(now, repo)`: only
  `k3dm_pr_checks_scrape_success{repo="…"} 0` and the last-scrape timestamp line.

### 2. `bin/k3dm-hermes`: publish once per poll

Add beside `_publish_disk_metrics`:

```python
def _publish_pr_checks(now=None):
    """Publish open-PR check state for each repo; never fails the poll."""
    from hermes import pr_checks
    now = time.time() if now is None else now
    base = os.environ.get("K3DM_PR_CHECKS_PUSHGATEWAY_URL", "http://localhost:19094").rstrip("/")
    try:
        token = _keychain_secret(GITHUB_SERVICE)
    except Exception as exc:
        print(f"pr checks publish skipped: {exc}", file=sys.stderr)
        return False
    if not token:
        print("pr checks publish skipped: no GitHub token", file=sys.stderr)
        return False
    headers = {"Authorization": f"token {token}", "Accept": "application/vnd.github+json"}
    ok = True
    for repo in pr_checks.REPOS:
        url = f"{base}/metrics/job/k3dm-pr-checks/instance/{repo.split('/')[1]}"
        try:
            try:
                prs = pr_checks.collect(lambda path: _http_json(f"https://api.github.com{path}",
                                                                headers, timeout=20), repo)
                body, method = pr_checks.render(prs, now, repo), "PUT"
            except Exception as exc:
                print(f"pr checks fetch failed for {repo}: {scrub_credentials(str(exc))[:200]}",
                      file=sys.stderr)
                body, method = pr_checks.render_failure(now, repo), "POST"
            request = urllib.request.Request(url, data=body.encode(), method=method,
                                             headers={"Content-Type": "text/plain; charset=utf-8"})
            urllib.request.urlopen(request, timeout=5).close()
            ok = ok and method == "PUT"
        except Exception as exc:
            print(f"pr checks publish skipped for {repo}: {exc}", file=sys.stderr)
            ok = False
    return ok
```

Adjust the imports to what `bin/k3dm-hermes` already has (`GITHUB_SERVICE`, `_keychain_secret`,
`scrub_credentials`); add only what is missing, from the modules that already define them.

- One Pushgateway group per repo (`instance` = the repo's short name), so each repo is replaced
  or kept on its own: a failed lib-foundation read never wipes k3d-manager's rows, and the loop
  carries on to the next repo.
- `PUT` replaces that repo's group, so a closed or merged PR's series disappear on the next
  successful poll.
- A failed fetch uses `POST` with only the two scrape lines, so the last good PR rows stay visible
  and `scrape_success` turns 0.
- The token never appears in a log line, an argument list or the metrics.

In `_poll_cycle`, call `_publish_pr_checks()` directly after `_publish_disk_metrics()`. Nothing
else in the poll changes.
