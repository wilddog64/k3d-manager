---

## Problem

The CVE auto-patch promoter works for **payment** and **product-catalog** but never remediates
**order** — order's promotion event carries empty `candidate`/`to_tag`/`from_digest` and sits at
`manual_review` forever.

Two **independent** root causes are tangled here; the decision is which to fix in v1.24.0.

### Root cause A — order has no immutable candidate (order-specific)

`_resolve_candidate_image` (`app-cve-scan.sh:244`) only promotes an **immutable `sha-*`** tag. order's
image pipeline publishes **bare tags** (`latest`/branch) with `imagePullPolicy: IfNotPresent`, so
`_resolve_candidate_image` returns empty → `STAGE order: failed to resolve immutable sha-* candidate …
promotion skipped` (line 333). payment/product-catalog publish `sha-<gitsha>` tags, which is why they
work. **This is a cross-repo CI-tagging gap in `shopping-cart-order`, not a promoter bug.**

### Root cause B — promotions live only in etcd, not git (all services)

`_promote_image` (`app-cve-scan.sh:280`) applies the patched image by
`_hub_kubectl patch application <app> --type merge` on `spec.source.kustomize.images` (line 292) — it
mutates the **live ArgoCD Application**, not git.

> **CORRECTION (verified live 2026-08-10):** the `services-git` ApplicationSet
> (`scripts/etc/argocd/applicationsets/services-git.yaml:10-12`) declares
> `ignoreApplicationDifferences: [ jqPathExpressions: [ .spec.source.kustomize.images ] ]`, so the appset
> controller does **not** revert the live patch on routine reconcile — the earlier "any reconcile wipes
> it" framing was wrong. The real durability gap is narrower but still real: the promotion exists **only
> in the live Application object (etcd)**, never in git. It is lost on any Application delete/recreate,
> hub re-bootstrap, or cluster rebuild, and — more importantly — **git (the GitOps source of truth) does
> not reflect what is actually deployed**, so an audit or a fresh sync from source silently reverts to the
> pre-promotion image. Option B closes that source-of-truth gap.

## Design for Option B (promoter → git) — RESOLVED 2026-08-10

The three open questions are now answered from the live cluster + repo. **The target is THIS repo, not
`shopping-cart-infra`** — which simplifies the token story (same-repo write, no cross-repo deploy key).

**Q1 — repo/path/format (RESOLVED).** Each service's kustomization lives in **k3d-manager itself** at
`services/shopping-cart-<svc>/kustomization.yaml`. The `services-git` ApplicationSet
(`applicationsets/services-git.yaml:16-20,43-46`) generates the apps from
`repoURL: https://github.com/wilddog64/k3d-manager`, `path: services/*`,
`targetRevision: ${K3D_MANAGER_BRANCH}`.
- Live state: `services/shopping-cart-product-catalog/kustomization.yaml` already has an `images:` block
  (`name: ghcr.io/wilddog64/shopping-cart-product-catalog`, `newTag: latest`); **payment and order have
  NO `images:` block yet** (payment's live override is the etcd-only patch).
- **Format difference:** the git edit uses kustomize's `images:` list (`name` + `newTag` + `digest`),
  NOT the Application-level `spec.source.kustomize.images` string (`repo=repo:tag@digest`). The promoter
  must translate its resolved `repo:tag@digest` into a kustomize `images:` entry
  (`name: <repo>`, `newTag: <tag>`, `digest: <sha256:...>`).

**Q2 — token (RESOLVED).** Because the write is to k3d-manager's **own** repo, no cross-repo infra token
is needed. Mint a **dedicated fine-grained PAT scoped to `wilddog64/k3d-manager` `contents:write` only**
(least privilege — CLAUDE.md OWASP A01), stored in a Keychain slot mirroring the existing
`platform-ops-app-rebuild` pattern (`argocd.sh:1384-1392`, which already warns "store a dedicated PAT
there … do NOT reuse a broad gh CLI token"). Do **not** reuse the broad gh CLI token, and do **not**
reuse the ArgoCD deploy keys (`secret/argocd/deploy-keys/*`) — those are read-only pull keys.

**Q3 — sync + which branch (RESOLVED, with a trap).** All six generated apps run
`syncPolicy.automated {prune: true, selfHeal: true}` (verified live), so ArgoCD **auto-syncs** a git
commit — the promoter does not need to trigger a sync. **But** `targetRevision: ${K3D_MANAGER_BRANCH}`
means the live apps track a **frozen release branch** (currently `k3d-manager-v1.22.0`, verified live),
not `main`. A promotion committed to `main` or a newer branch is **inert** until the appset is reapplied
at that branch — the exact `${K3D_MANAGER_BRANCH}` "merged config is not live config" trap in CLAUDE.md.
**The promoter must discover the live target branch** (read `spec.source.targetRevision` off the
Application it is promoting) and commit there — not to a hardcoded branch.

**Q4 — write mechanism (RESOLVED — use `git`, verified by inspecting the image).** `docker run
aquasec/trivy:0.63.0` shows the image is Alpine with **`git` 2.47.2**, `base64`, and **BusyBox `wget`
(POST-only — no `--method`, so it CANNOT `PUT`)**, no `curl`, no `kustomize`. A public
`git clone --depth 1` over HTTPS succeeds from inside the image. Therefore the write path is **plain
`git` over HTTPS-with-token**, NOT the Contents API (BusyBox wget cannot issue the `PUT`/`PATCH` the
Contents/Git-Data APIs require):
1. `git clone --depth 1 --branch <branch> https://x-access-token:${GIT_WRITE_TOKEN}@github.com/${MANAGER_REPO}.git`
2. Rewrite `services/shopping-cart-<svc>/kustomization.yaml`'s `images:` entry to pin `digest:` (no
   `kustomize` binary → an **awk** editor, tested below).
3. `git -c user.name=… -c user.email=… commit` + `git push origin <branch>`.
`${GIT_WRITE_TOKEN}` = the scoped `contents:write` PAT, injected as an env var from a Keychain-seeded
Secret; it appears only in the remote URL inside the job, never in a logged argv.

**Design points baked into the code below:**
- Pin by **`digest:` only** (immutable), dropping any `newTag:` — kustomize rejects tag+digest together.
- Idempotency: after the awk rewrite, `git diff --quiet` → if unchanged (digest already pinned), skip the
  commit/push entirely (no churn loops).
- Graceful degradation: if `GIT_WRITE_TOKEN` is unset or the branch can't be resolved, log and fall back
  to live-patch-only (the promoter must not hard-fail on the git step).
- Interaction with `ignoreApplicationDifferences`: the git `images:` block is the durable source of
  truth; the etcd live-patch stays as the pre-sync fast-path.
- The promotion event ledger records the returned git commit SHA as the durable promotion reference.

### Change 2 — `app-cve-scan.sh`: new helpers (insert directly above `_promote_image`)

```sh
_app_target_branch() {
  _hub_kubectl -n "${HUB_ARGOCD_NAMESPACE}" get application "$1" \
    -o jsonpath='{.spec.source.targetRevision}' 2>/dev/null
}

_write_image_editor() {
  cat > /tmp/set_image_digest.awk <<'AWK'
BEGIN { have_img=0; in_img=0; matched=0; skip=0 }
/^images:[[:space:]]*$/ { have_img=1; in_img=1; print; next }
in_img==1 && /^[^[:space:]]/ {
  if (matched==0) { print "  - name: " name; print "    digest: " digest; matched=1 }
  in_img=0; print; next
}
in_img==1 && /^  - name:[[:space:]]/ {
  ename=$0; sub(/^  - name:[[:space:]]*/, "", ename)
  if (ename==name) { print "  - name: " name; print "    digest: " digest; matched=1; skip=1; next }
  else { skip=0; print; next }
}
in_img==1 && /^    / { if (skip==1) { next } else { print; next } }
in_img==1 { skip=0; print; next }
{ print }
END {
  if (have_img==0) { print "images:"; print "  - name: " name; print "    digest: " digest }
  else if (in_img==1 && matched==0) { print "  - name: " name; print "    digest: " digest }
}
AWK
}

# echoes the commit SHA on success; non-zero + no output on skip/failure
_git_persist_promotion() {
  _p_svc="$1"; _p_name="$2"; _p_digest="$3"; _p_branch="$4"
  if [ -z "${GIT_WRITE_TOKEN}" ]; then
    _log "GITWRITE ${_p_svc}: GIT_WRITE_TOKEN unset — skipping git persistence (live-patch only)"
    return 1
  fi
  if [ -z "${_p_branch}" ]; then
    _log "GITWRITE ${_p_svc}: could not resolve target branch — skipping git persistence"
    return 1
  fi
  _p_work="$(mktemp -d)"
  _p_kfile="services/${_p_svc}/kustomization.yaml"
  if ! git clone --depth 1 --branch "${_p_branch}" \
      "https://x-access-token:${GIT_WRITE_TOKEN}@github.com/${MANAGER_REPO}.git" \
      "${_p_work}" >/dev/null 2>&1; then
    _log "GITWRITE ${_p_svc}: clone of ${MANAGER_REPO}@${_p_branch} failed"
    rm -rf "${_p_work}"; return 1
  fi
  if [ ! -f "${_p_work}/${_p_kfile}" ]; then
    _log "GITWRITE ${_p_svc}: ${_p_kfile} not found on ${_p_branch}"
    rm -rf "${_p_work}"; return 1
  fi
  _write_image_editor
  awk -v name="${_p_name}" -v digest="${_p_digest}" \
    -f /tmp/set_image_digest.awk "${_p_work}/${_p_kfile}" > "${_p_work}/${_p_kfile}.new"
  mv "${_p_work}/${_p_kfile}.new" "${_p_work}/${_p_kfile}"
  if git -C "${_p_work}" diff --quiet -- "${_p_kfile}"; then
    _log "GITWRITE ${_p_svc}: ${_p_name} already pinned to ${_p_digest} on ${_p_branch} — no commit"
    rm -rf "${_p_work}"; return 0
  fi
  git -C "${_p_work}" -c user.name="${GIT_AUTHOR_NAME}" -c user.email="${GIT_AUTHOR_EMAIL}" \
    commit -q -m "fix(cve): pin ${_p_svc} to ${_p_digest}" -- "${_p_kfile}" >/dev/null 2>&1
  if ! git -C "${_p_work}" push -q origin "${_p_branch}" >/dev/null 2>&1; then
    _log "GITWRITE ${_p_svc}: push to ${_p_branch} failed"
    rm -rf "${_p_work}"; return 1
  fi
  _p_sha="$(git -C "${_p_work}" rev-parse HEAD)"
  _log "GITWRITE ${_p_svc}: committed ${_p_name}@${_p_digest} to ${_p_branch} (${_p_sha})"
  rm -rf "${_p_work}"
  printf '%s' "${_p_sha}"
  return 0
}
```

```bash
function argocd_sync_git_writer_secret() {
   local _ns="${1:-platform-ops}"
   local _service="platform-ops-git-writer"
   local _account="k3dm"
   local _name="platform-ops-git-writer"
   local _token=""

   _token=$(_argocd_keychain_value "${_service}" "${_account}")

   if [[ -z "${_token}" ]]; then
      _info "[argocd] ${_service} not in Keychain (${_service}/${_account}) — optional CVE git-writer PAT; skipping (store a dedicated fine-grained PAT scoped to wilddog64/k3d-manager contents:write ONLY — do NOT reuse a broad gh CLI token)"
      return 0
   fi

   _info "[argocd] Syncing ${_name} Secret (git-token) into namespace ${_ns} from Keychain..."
   _no_trace _argocd_apply_secret_from_stdin "${_token}" "${_ns}" "${_name}" git-token
}
```

## Prerequisite (user — one-time, before the git-write activates)

The `GIT_WRITE_TOKEN` secret is `optional: true`, so the job keeps working (live-patch only) until the
PAT is seeded. To enable durable git persistence, the user seeds a dedicated fine-grained PAT into the
macOS Keychain (same pattern as `platform-ops-app-rebuild`):

```
security add-generic-password -s platform-ops-git-writer -a k3dm -w '<PAT>'
```
The PAT must be scoped to **`wilddog64/k3d-manager` → Contents: Read and write ONLY** (least privilege —
CLAUDE.md OWASP A01). Then `deploy_argocd_platform_ops` syncs it into the `platform-ops-git-writer`
Secret. Codex does NOT create the PAT — flag this as a user action in the handoff report.
