# v1.24.0 — Order remediation promoter: decision doc (task #18)

**Branch:** `k3d-manager-v1.24.0`
**Type:** design decision (two independent problems; pick the v1.24.0 slice, defer the rest)
**Files (this repo):** `scripts/etc/argocd/platform-ops/app-cve-scan.sh`
**Cross-repo:** `shopping-cart-order` (CI image tagging), `shopping-cart-infra` (kustomization)

---

## Problem

The CVE auto-patch promoter works for **payment** and **product-catalog** but never remediates
**order** — order's promotion event carries empty `candidate`/`to_tag`/`from_digest` and sits at
`manual_review` forever.

Two **independent** root causes are tangled here; the decision is which to fix in v1.24.0.

### Root cause A — order has no immutable candidate (order-specific)

`_resolve_candidate_image` (`app-cve-scan.sh:244`) only promotes an **immutable `sha-*`** tag. order's
image pipeline publishes **bare tags** (`latest`/branch) with `imagePullPolicy: IfNotPresent`, so
`_resolve_candidate_image` returns empty → `STAGE order: failed to resolve immutable sha-* candidate …
promotion skipped` (line 333). payment/product-catalog publish `sha-<gitsha>` tags, which is why they
work. **This is a cross-repo CI-tagging gap in `shopping-cart-order`, not a promoter bug.**

### Root cause B — promotions are ephemeral (all services)

`_promote_image` (`app-cve-scan.sh:280`) applies the patched image by
`_hub_kubectl patch application <app> --type merge` on `spec.source.kustomize.images` (line 292) — it
mutates the **live ArgoCD Application**, not git. Any appset reconcile or `argocd app sync` reverts the
promotion. This affects every service; it is latent for payment/product-catalog only because they have
not reconciled since their last promotion.

---

## Options

| Option | Fixes | Effort | Where it belongs |
|--------|-------|--------|------------------|
| **A. order CI publishes `sha-<gitsha>` immutable tags** (+ kustomize digest-pinnable ref) | Root cause A (unblocks order) | cross-repo (order CI + infra kustomization) | naturally with **v1.25.0** order/Stripe work (same repos, same PRs) |
| **B. promoter persists the override to git** (commit `kustomize.images` to the infra kustomization instead of / in addition to the live patch) | Root cause B (durable for all) | this-repo `app-cve-scan.sh` + a git-write path + a deploy-key/token | platform-side, fits **v1.24.0** |
| **C. do both now** | A + B | largest; cross-repo coupling | risks pulling v1.25.0 cross-repo scope into v1.24.0 |

---

## Recommendation

**Do B in v1.24.0; schedule A with v1.25.0.**

- **B** is the durable platform fix and is entirely within this repo's promoter plus a git-write path —
  it removes the "any reconcile wipes the promotion" foot-gun for *every* service, which is worth doing
  regardless of order. It is the correct home for the promoter's design debt.
- **A** is a `shopping-cart-order` CI change (publish `sha-<gitsha>`, stop relying on `IfNotPresent`) plus
  an infra kustomization tweak. It touches the exact repos and PRs that v1.25.0 already carries (order
  schema fix + image promotion + Stripe live E2E), so folding it there avoids opening the same cross-repo
  surface twice. Record it as a v1.25.0 carry-in now so it is not lost.

If the user prefers order unblocked **this** release, choose C and accept the cross-repo scope.

---

## Design for Option B (promoter → git)

- After a clean candidate is resolved, write the new `images:` entry to the service's kustomization in
  `shopping-cart-infra` (git) via a scoped deploy token, commit, and let ArgoCD sync — **instead of**
  live-patching the Application. Keep the live patch only as an optional fast-path before the sync lands.
- Least privilege: a dedicated fine-grained token/deploy key with write access to **only** the infra
  repo (mirror the existing `platform-ops-app-rebuild` token slot referenced in `argocd.sh`).
- Idempotency: skip the commit if the kustomization already pins the target digest (avoid churn loops).
- The promotion event ledger records the git commit SHA as the durable promotion reference.

**Open questions to resolve before implementing B:**
1. Which repo/path holds each service's `kustomize.images` — confirm it is `shopping-cart-infra` and the
   exact kustomization file per service.
2. Token: reuse the `platform-ops-app-rebuild` slot (currently optional/absent per `deploy_argocd_platform_ops`
   output) or mint a dedicated infra-write token? A dedicated one is least-privilege.
3. Does ArgoCD auto-sync the infra app, or does the promoter need to trigger a sync after the commit?
