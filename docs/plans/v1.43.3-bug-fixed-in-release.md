## Problem

The Bugs dashboard counts a bug under the release it was **filed in or scheduled for**: its
`**Branch:**` line, or else the first tag that contains the commit that added the doc. A bug filed
during v1.40.0 and fixed in v1.43.2 counts as "fixed" under v1.40.0. So **Fixed this release** and
**Bugs per release, open vs fixed** answer "bugs filed for this release that are now fixed", not
"bugs this release fixed". The operator asked for the second.

## Design

Derive the **fixed-in release** from git history. Nothing is added to the bug docs, and old bugs
need no backfill.

- A doc's **fixing commit** is the commit, walking history oldest first (`git log --reverse`, which
  is ancestry order, not timestamp order), at which the doc's `Status` value last changed from
  not-fixed to fixed. "Fixed" means `doc_status(...)[1] == "fixed"`
  (IMPLEMENTED, FIXED, VERIFIED, LIVE-VERIFIED, CLOSED, and the rest of `_CLOSED_RE`), the same rule
  the dashboard's Status column uses. A later change back to not-fixed (a reopen) clears it, and the
  next fix records a new fixing commit, so a bug fixed, reopened and fixed again counts **once**,
  under the release of its **most recent** fix. Moving between fixed values (IMPLEMENTED →
  VERIFIED) does not move it.
- A doc added with a fixed Status has its add commit as the fixing commit, with source
  `added_fixed` so it stays distinguishable from an observed transition.
- The **fixed-in release** comes from **tag ancestry only, never from commit or author dates**: the
  lowest-version `vX.Y.Z` tag that contains the fixing commit, chosen exactly as `_added_releases`
  chooses (`git tag --contains`, `min` by version). Each tag is cut on the release's squash-merge
  commit by `/post-merge` from the release ledger (`CHANGELOG.md` / `docs/releases.md`), so the tags
  are the ledger in git form. If no tag contains it, it is the release of the branch being scanned
  (`k3d-manager-vX.Y.Z` → `vX.Y.Z`): its commits are not merged yet. On any other branch (a
  diverged or non-release branch) it is `unknown`.
- Releases merge to `main` as squash commits that carry the tag, so history behind a release branch
  holds one commit per shipped release, and its fixing commit maps to that release's tag. Commits
  on the current branch are in no tag yet, so they count for the current release. This is the same
  property `_added_releases` already relies on.
- **Uncertainty is kept, never guessed.** A doc that is fixed now but has no detectable transition
  (for example, its status lives under a `## Status` heading, which the diff scan below does not
  see; 6 of today's 696 fixed docs) gets release `unknown`, source `no_transition`. It is **not**
  given its filed release. `unknown` docs are counted in their own series and never in a release's
  fixed count.

## Verification amendment (Claude, 2026-10-16)

The real history showed 427 docs credited to v1.42.0 as `added_fixed`: the 2026-10-09 status sweep
added a first, already-closed `**Status:**` line to old docs that had none. Under the
"preserve uncertainty" rule above, a first Status line that arrives already fixed on a doc that
**already existed** (the diff is not a file creation, `--- /dev/null`) is release `unknown`, source
`status_backfill`. `added_fixed` stays for docs created already fixed. `_release_of_commit` returns
`(release, source)` so each commit costs one `git tag --contains`. Result on today's history: 399
`status_backfill`, 224 `added_fixed`, 68 `status_change`, 6 `no_transition`; v1.42.0 57 fixes
instead of 447.

### 1. `scripts/bug-tally.py`: compute fixed-in per doc

Add `from hermes.prior_art import doc_status` to the existing import line.

Add a module-level helper:

```python
STATUS_LINE_RE = re.compile(r"^[+-](?:\*\*Status:\*\*|Status:)\s*(.*)$")


def _fixed_commits(ref):
    """Map each bug doc to the commit at which its Status last became fixed."""
    output = _git("log", "--reverse", "-p", "-U0", "--no-renames", "--format=commit %H",
                  "-G", "Status:", ref, "--", "docs/bugs/")
    fixed = {}
    is_fixed = {}
    commit = None
    path = None
    for line in output.splitlines():
        if line.startswith("commit ") and re.fullmatch(r"[0-9a-f]{40}", line[7:]):
            commit = line[7:]
            path = None
        elif line.startswith("+++ "):
            name = line[4:].removeprefix("b/")
            path = name if name.startswith("docs/bugs/") and "/" not in name[len("docs/bugs/"):] else None
        elif path and line.startswith("+") and not line.startswith("+++"):
            match = STATUS_LINE_RE.match(line)
            if not match:
                continue
            now_fixed = doc_status(f"**Status:** {match.group(1)}\n")[1] == "fixed"
            if now_fixed and not is_fixed.get(path):
                fixed[path] = (commit, "added_fixed" if path not in is_fixed else "status_change")
            elif not now_fixed:
                fixed.pop(path, None)
            is_fixed[path] = now_fixed
    return fixed
```

Only `+` lines set the state. A `-` line alone (status line deleted) does not change it. A path's
first `+` Status line is in its add commit, so `path not in is_fixed` there means "added already
fixed". The value is `(commit, source)`.

Add `_fixed_releases(ref, branch, paths_fixed)`, where `paths_fixed` is the `{path: (commit,
source)}` result above. Resolve each **distinct** commit once with the same tag rule as
`_added_releases` (factor the `tags` / `min` / `BRANCH_RE` block of `_added_releases` into a small
`_release_of_commit(commit, branch)` helper and call it from both, so the rule cannot drift; it
returns `None` when neither a tag nor the branch gives a version). Never read a commit date.
Return `{path: (release or "unknown", source)}`.

In `tally(ref)`, after the doc texts are read:

- compute `fixed_commits = _fixed_commits(ref)` and the releases for them;
- for each path whose `doc_status(raw)[1] == "fixed"`:
  - if it has a fixing commit, record `{"release": <its release or "unknown">, "source": <its
    source>}`;
  - otherwise record `{"release": "unknown", "source": "no_transition"}`;
- return the existing `result` unchanged, and expose the new map as a second value **without
  changing `tally`'s return type**: add `def fixed_in(ref)` that returns the map, and have `tally`
  and `fixed_in` share one internal `_scan(ref)` that reads the texts once and returns both.

In `main`, the `--json` payload gains one top-level key beside `"releases"`:
`"fixed_in": {path: {"release": ..., "source": ...}}`. The non-JSON text output gains one line per
release, after the existing summary line: `  fixed here: <n>` (the count of `fixed_in` entries with
that release), only when `<n>` > 0. Releases that only have fixed-in entries (no filed docs) are
not printed; text output stays keyed by filed release. When any entry is `unknown`, print one final
line: `fixed in an unknown release: <n>`.

### 2. `bin/k3dm-vectordb-metrics`: publish it

**2a.** `_tally(root, ref=None, full=False)`: return the whole parsed payload when `full`, else
`payload["releases"]` as now.

**2b.** `publish_bug_metrics`: call `_tally(root, ref, full=True)` once inside the existing `try`;
set `tally = payload["releases"]` and `fixed_in = payload.get("fixed_in", {})`. On failure both stay
`None`. Pass `fixed_in` to `_bug_status_metrics` and `_release_metrics`.

**2c.** `_bug_status_metrics(..., fixed_in=None)`: for a row with `status == "fixed"`, add a
`fixed_in="<release>"` label to its `k3dm_bug_info` series, where `<release>` is
`(fixed_in or {}).get(path, {}).get("release")` if it matches `_VERSION_RE`, else `"unknown"`.
Rows that are not fixed get no `fixed_in` label. **Do not** add `fixed_in` to the
`k3dm_bug_status_docs` aggregate or its key.

**2d.** `_release_metrics(..., fixed_in=None)`: for the same `releases` window and `order` values
it already computes, emit for every release and every priority in `PRIORITIES`:

```text
k3dm_bug_fixed_in_release_docs{release="<r>",order="<o>",priority="<p>"} <count>
```

`<count>` is the number of `fixed_in` entries with that release whose doc has that priority. The
priority comes from the tally: build `{path: priority}` from `open_paths`, `unknown_paths` and
`closed_paths` (as `_bug_status_metrics` already does for releases). Emit zeros like
`k3dm_bug_release_docs` does. `unknown` entries never count toward a release; instead emit one
`k3dm_bug_fixed_in_unknown_docs <count>` line (0 when none). When `fixed_in` is `None`, emit
neither series.

No other series changes.
