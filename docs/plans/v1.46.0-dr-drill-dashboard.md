## Problem

The weekly drill (`docs/howto/hub-dr-drill.md`, v1.43.0) publishes its result to the hub
Pushgateway with `make dr-drill-publish`. Prometheus scrapes it, and two rules alert on it
(`DRDrillFailed`, `DRDrillStale` in `scripts/etc/argocd/platform-ops/prometheusrule.yaml`).
Nothing shows the results. To see the last RTO, which check failed, or whether the drill has run
this week, the operator has to write PromQL in Grafana Explore.

## The series (already produced; do not change the producer)

`bin/dr-drill-publish` pushes these under job `k3dm-dr-drill`:

| Series | Meaning |
|---|---|
| `k3dm_dr_drill_last_run_timestamp_seconds` | epoch of the drill run (`run_timestamp`) |
| `k3dm_dr_drill_success` | 1 pass, 0 fail |
| `k3dm_dr_drill_rto_seconds` | restore time of that run |
| `k3dm_dr_drill_rpo_seconds` | age of the export it restored |
| `k3dm_dr_drill_check_ok{check="V0".."V7"}` | 1 pass, 0 fail, per check |

The Pushgateway keeps only the last push, so each series is a step function: it changes once a
week. Panels over time show one step per drill. That is the history; no new producer is needed.

## Deliverable

One ConfigMap, `scripts/etc/argocd/platform-ops/grafana-dashboard-dr-drill.yaml`, in the same
shape as `grafana-dashboard-host-disk.yaml`:
- name `grafana-dashboard-dr-drill`, namespace `monitoring`, labels `grafana_dashboard: "1"` and
  `release: kube-prometheus-stack`;
- title `k3dm DR Drill`, uid `k3dm-dr-drill`, tags `["k3dm", "dr"]`, refresh `5m`, default range
  `now-90d`.

### Panels (top to bottom)

| # | Type | Title | Query | Display |
|---|---|---|---|---|
| 1 | stat | Last drill | `k3dm_dr_drill_success` | value mapping 1 → `PASS` (green), 0 → `FAIL` (red); no-data text `never run` |
| 2 | stat | Days since last drill | `(time() - k3dm_dr_drill_last_run_timestamp_seconds) / 86400` | thresholds green, orange at 7, red at 8 (8 = `DRDrillStale`); 1 decimal |
| 3 | stat | RTO (last run) | `k3dm_dr_drill_rto_seconds` | unit `s` |
| 4 | stat | RPO (last run) | `k3dm_dr_drill_rpo_seconds` | unit `s`; orange at 93600 (26 h, the V7 limit) |
| 5 | state-timeline | Checks | `k3dm_dr_drill_check_ok` legend `{{check}}` | mapping 1 → `ok` green, 0 → `fail` red |
| 6 | timeseries | RTO and RPO per drill | panels 3 and 4 queries, legends `RTO`, `RPO` | unit `s`, line interpolation `stepAfter` |
| 7 | table | DR alerts firing | `ALERTS{alertname=~"DRDrill.*", alertstate="firing"}` | columns alertname, severity; empty table reads `none firing` |

Do not add `or vector(0)` to panels 1–4. "Never run" must read as no data, not as a pass or a
0-second RTO. This is the one deliberate exception to the guide's `or vector(0)` advice; say so in
a one-line panel description on panel 1.
