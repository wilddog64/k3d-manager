# v1.41.1 — Safe checkout load-test credentials and preflight

**Status:** PROPOSED
**Milestone:** `v1.41.1`
**Owner:** k3d-manager

## Problem

The checkout load-test implementation exists in `scripts/plugins/loadtest.sh` and
`scripts/etc/loadtest/checkout.js`, but operators must manually provide credentials and a working
Prometheus endpoint. The Grafana checkout dashboard consequently shows `No data` when no run has
successfully published `k6_checkout_load_*` metrics. The current runner does not distinguish a
missing credential, an unreachable target, and a failed metrics-ingestion path before generating
load.

This is a usability and safety gap, not a request to generate traffic automatically.

## Goal

Make an intentional checkout load-test easy to prepare and safe to validate, while preserving the
explicit `--confirm` gate before any checkout traffic is generated.

## Credential contract

The runner must use the existing documented identity contract:

- Keycloak issuer: `https://keycloak.3ai-talk.org/realms/shopping-cart`;
- client ID: `order-service`;
- test user: `developer`;
- user password: Vault `secret/keycloak/users/developer`;
- optional confidential-client secret: Vault `secret/keycloak/clients`.

Secret values must never appear in argv, logs, Grafana, Git, shell history, or the preflight
summary. The implementation may use a short-lived 0600 temporary curl config or an environment
variable scoped to the child process, following the existing token-minting pattern in
`loadtest.sh`.

Explicit `LOADTEST_USERNAME`, `LOADTEST_PASSWORD`, and `LOADTEST_CLIENT_SECRET` values remain
supported and take precedence over Vault when supplied. The default username may be `developer`,
but the password must not have a repository or Makefile default.

## Preflight contract

Add a read-only preflight path, for example:

```bash
./scripts/k3d-manager loadtest_preflight
```

It must validate, without calling the checkout API with load:

1. required tools are present (`k6`, `curl`, `jq`);
2. the Keycloak issuer is reachable;
3. the credential source exists, without printing its value;
4. the password grant can mint a token, then discard it;
5. `LOADTEST_TARGET_URL` resolves and the order-service health/auth boundary is reachable;
6. `LOADTEST_PROM_URL` is reachable and accepts the configured authentication;
7. Prometheus remote-write is configured consistently with the k6 output URL;
8. the dashboard metric contract is present or clearly reported as “no prior run”; and
9. the selected run ID, target URL, Prometheus URL, stage list, and duration are safe to display.

The preflight must not create an order, invoke k6, call `loadtest_run`, or write a persistent
credential file. A failed check must identify the check and remediation without exposing secrets.

## Run contract

`loadtest_run --confirm` remains the only path that may generate checkout traffic. Before the first
k6 stage it must either:

- require a successful preflight from the same configuration; or
- run the equivalent checks inline and stop before traffic if any required check fails.

The run must fail clearly when remote write is unavailable rather than completing with a dashboard
that silently has no metrics. It must preserve the existing stage gates and hysteresis behavior.

## Dashboard contract

No dashboard UI edits are allowed. The existing dashboard source remains the authority. Update it
only if needed to:

- show a clear “No completed load-test run” state when the run selector has no values;
- identify the selected `run_id` and its age;
- explain that metrics appear only after a successful remote-write run; and
- keep CPU and other infrastructure panels independent of the load-test selector.

Do not fabricate zero-valued checkout results when the metric is absent.

## Planned files

Implementation should be limited to the load-test runner, its focused tests, the dashboard source
if required, and this plan's linked documentation. Expected files are:

- `scripts/plugins/loadtest.sh`;
- `scripts/tests/plugins/loadtest.bats`;
- `scripts/etc/grafana/dashboards/checkout-loadtest-configmap.yaml` (only if the dashboard contract
  needs the explicit empty-state improvement);
- `docs/plans/v1.41.1-loadtest-credentials-and-preflight.md`;
- `CHANGELOG.md` and `memory-bank/` on completion.

No shopping-cart application repository, Keycloak realm data, cluster credential, or live load test
is changed by this spec.

## Tests and gates

Add focused tests for:

1. explicit environment credentials override Vault lookup;
2. missing credentials fail before any token or checkout request;
3. Vault lookup never prints the secret;
4. token-mint failure identifies the Keycloak check;
5. Prometheus query and remote-write failures stop preflight;
6. a missing `k6_checkout_load_*` metric reports “no prior run” rather than zero;
7. `--confirm` remains mandatory for real traffic; and
8. the dashboard keeps the run selector and empty-state text source-controlled.

Run the full `scripts/tests/plugins/loadtest.bats` suite, the dashboard regression suite, shellcheck
on touched shell files, `python3 scripts/check-doc-links.py`, and the repository’s required agent
gates before committing. Use realistic stubs; tests must not read the host Keychain, print real
secrets, call the network, or create checkout orders.

## Completion criteria

- An operator can run the preflight and know whether credentials, target access, Prometheus query,
  and remote write are ready without generating load.
- A confirmed run either publishes the dashboard's `k6_checkout_load_*` metrics or fails with an
  actionable ingestion error.
- No secret value appears in command output, process arguments, repository files, or test output.
- Existing dry-run behavior, explicit confirmation, stage gates, and load-test tests remain green.
