# v1.25.0 — Slack `/e2e-verify` async trigger for the Tier 1 e2e harness

**Filed:** 2026-08-16
**Component:** `bin/k3dm-webhook` (command registry + async job worker), Slack relay
(`k3dm-slack-relay` Cloudflare Worker)
**Depends on:** a green live smoke of `e2e_verify_vcluster` — blocked today by
`docs/bugs/2026-08-16-e2e-vcluster-kubeconfig-proxy-port-drift.md`. Do NOT wire Slack to a red
harness; it would only post failures.
**Sibling triggers:** `make e2e` (local, blocking — landed this session) and a future GitHub Actions
caller. All three funnel through the one entrypoint `./scripts/k3d-manager e2e_verify_vcluster [digest]`.

## Goal

Let an operator kick the Tier 1 e2e harness from Slack and get the pass/fail JSON summary posted back
to the thread, without holding the Slack request open. This is a **trigger surface**, not new harness
logic — it reuses the existing webhook async-job + cooldown machinery verbatim.

## Why async is mandatory (not a preference)

An e2e run is ~7–15 min (vCluster cold start + one syncer restart + substrate apply + Playwright Job).
Slack's slash-command contract requires an ack within **3 seconds**. So the handler MUST:

1. Validate role + cooldown, ack immediately (`202`-style "🧪 e2e run started…"),
2. Run the harness in a background thread/detached job (existing `_posix_spawn_job` + JOB_DIR pattern),
3. Post progress + the final pass/fail summary back to the captured `thread_ts`.

This is exactly how `cve-remediate` already behaves — copy that shape, do not invent a new one.

## Design — reuse existing webhook primitives

### 1. Command registry (`bin/k3dm-webhook`, ~line 260 `_API_COMMANDS`)

Add:

```python
"/api/v1/e2e-verify": {"name": "e2e-verify", "min_role": "operator"},
```

`operator` (not `reader`): the run consumes real laptop docker/k3d/vCluster resources and mutates
cluster state. Mirror `cve-remediate`'s role.

### 2. Thread surface (`_THREAD_COMMANDS` ~line 869 + `_THREAD_COMMAND_MIN_ROLE` ~line 273)

Register `e2e-verify` in `_THREAD_COMMANDS` and set its thread min-role to `operator` in
`_THREAD_COMMAND_MIN_ROLE` so it is reachable as a thread command with correct gating.

### 3. Concurrency guard — serialize-live-sandbox (HARD rule)

Only **one** e2e/vCluster may run at a time (memory: serialize-live-sandbox — a second run
re-provisions/destroys the first's cluster). Reuse the cooldown-file pattern
(`_CVE_COOLDOWN_DIR` / `_cve_cooldown_active` / `_cve_touch_cooldown`, ~lines 257, 399–413) as a
**busy lock**, not a 24h cooldown:

- New `_E2E_LOCK_DIR = Path.home() / ".k3dm" / "locks" / "e2e"` with a single `running` marker file.
- On trigger: if the marker exists AND its backing job is still `running`, reject with
  "⏳ an e2e run is already in progress (job `<id>`) — try again when it finishes." Otherwise create
  the marker, launch, and clear the marker in the worker's `finally`.
- Stale-lock recovery: if the marker's referenced job status is terminal (`success`/`failed`) or the
  job dir is gone, treat the lock as stale and reclaim it (log the reclaim).

### 4. Async worker (model on `_run_upgrade`, ~line 531)

New `_run_e2e_verify(job_id, digest="")`:

```python
def _run_e2e_verify(job_id, digest=""):
    job_dir = JOB_DIR / job_id
    out_file = job_dir / "output"
    (job_dir / "status").write_text("running")
    _notify_job(job_id, f"🧪 *e2e verify started* — Tier 1 vCluster harness"
                        + (f" (digest `{digest[:19]}…`)" if digest else ""))
    try:
        argv = ["./scripts/k3d-manager", "e2e_verify_vcluster"]
        if digest:
            argv.append(digest)                      # single arg; already validated (see §6)
        pid = _posix_spawn_job(argv, out_file, cwd=REPO_ROOT)
        _, st = os.waitpid(pid, 0)
        rc = os.WEXITSTATUS(st) if os.WIFEXITED(st) else -os.WTERMSIG(st)
        # Read the machine summary the harness wrote, not the exit code alone.
        summary = _latest_e2e_summary()              # newest ${E2E_REPORT_DIR}/*.json
        (job_dir / "status").write_text("success" if rc == 0 else "failed")
        _notify_job(job_id, _format_e2e_result(summary, rc))
    except Exception as exc:
        (job_dir / "status").write_text("failed")
        _notify_job(job_id, f"⚠️ *e2e verify error*: {exc}")
    finally:
        _e2e_release_lock(job_id)
```

- Use `_posix_spawn_job` + `os.killpg` teardown exactly as `_run_upgrade` does (process-group cleanup
  matters — the harness spawns docker/vcluster children).
- Add a `threading.Timer(120, …)` progress heartbeat (as `_run_cluster` does) so a 10-min run isn't
  silent: "still running… (Nm elapsed)".
- `_format_e2e_result` renders from the JSON summary keys already emitted by the harness
  (`result`, `passed`, `total`, `failed`, `duration_seconds`, `tier`, `service`, `run_id`,
  `candidate_digest`) — the SAME keys the Grafana Path-A ConfigMap uses. Do not re-parse Playwright
  output; the summary is the contract.

### 5. do_POST dispatch (~line 930+, alongside `cve-remediate`)

Wire `elif cmd == "e2e-verify":` to: read `thread_ts` from `JOB_DIR/job_id/thread_ts` (as the
siblings do), acquire the lock (§3), and `threading.Thread(target=_run_e2e_verify, args=(job_id,),
kwargs={"digest": digest}, daemon=True).start()`. Return the immediate ack.

### 6. Input safety — the `digest` argument (OWASP A03)

`digest` is the only user-supplied field and it flows into `argv` (a list — no shell), but validate
anyway and reject rather than sanitize:

- Accept only `^sha256:[0-9a-f]{64}$` (or empty). Anything else → reject the command with a usage hint.
- NEVER build a shell string; keep it a positional list element. `_posix_spawn_job` must receive a
  list, never `shell=True`.
- The digest is not a secret, but keep it out of any `eval`/`envsubst` path.

## Out of scope (do NOT build here)

- No new harness logic, no Tier 2 (ACG sandbox) trigger — Tier 1 vCluster only.
- No parallel/concurrent e2e runs — the serialize-live-sandbox rule forbids it.
- No auto-trigger on push/PR — that is the future GitHub Actions caller, a separate spec.
- No synchronous mode — physically impossible within Slack's 3s window.
