## Context

`bin/k3dm-webhook` posts every job message through `_notify_job` (`bin/k3dm-webhook:1296`). Its destination comes from files in
the job directory: `channel_id`, `thread_ts`, `response_url`. When none is set (every cloud request today) it posts to
`SLACK_CHANNEL_ID`; when a post fails and no thread exists it then falls back to the incoming webhook `SLACK_WEBHOOK_URL`
(`:1333-1351`), which is a different channel. Delivery is logged by `_record_notification_delivery` (`:1366-1386`) with a `route`
key that already means the delivery path (`bot_thread`, `bot_fallback`, ...).

This child lets the trusted bridge pass an **alias** (`notify_route`) for a job. The webhook resolves it with
`notify_routes.load_routes()` (p2a: `{alias: channel_id}`, plus status `ok`/`absent`/`invalid`), fixes the channel for the
job's whole life, and never lets a routed job's messages spill to another channel.

## Behaviour

1. **`POST /api/v1/make`** (handler near `:2806-2840`). Read optional body key `notify_route`. If present:
   - and any of `channel_id`, `response_url`, `thread_ts` is non-empty → 400 `{"error": "notify_route cannot be combined with Slack context"}`;
   - not a string matching `notify_routes.ALIAS_RE` (fullmatch), or `load_routes()` status is not `ok`, or the alias is not in
     the map → 400 `{"error": notify_routes.INVALID_REASON}` (never name aliases or IDs);
   - else set `channel_id` to the resolved ID and continue on today's path (which starts the "queued" thread in that channel,
     `:2822-2825`), and write `notify_route` (the alias) into the job directory next to `channel_id`.
   Absent key → today's code path unchanged, byte for byte.
2. **`POST /api/v1/cluster`** (handler near `:2664-2678`). Same rules for `notify_route`, accepted only when `action` is `up` or
   `down`; any other action with `notify_route` → 400 `{"error": notify_routes.UNSUPPORTED_REASON}`. Persist through
   `_persist_notification_context` (`:754`), extended with a `notify_route` keyword written like the others.
3. **`/api/v1/cluster-status`, `/api/v1/diagnostics`, `/api/v1/hostinger-status`**: a body containing `notify_route` → 400
   `{"error": notify_routes.UNSUPPORTED_REASON}`; without it, unchanged.
4. **`_notify_job`**: when the job directory has a `notify_route` file, skip the `webhook_fallback` branch (`:1347-1351`) and never
   post to `SLACK_CHANNEL_ID` (`channel_id` is always set for such a job, so `bot_fallback` retries the routed channel only).
   Record every attempt with `_record_notification_delivery(..., notify_route=<alias>)`: add a `notify_route` key to the record
   (alias or `None`); the `route` key keeps its meaning. An undelivered routed message is recorded `delivered: false`.
5. **Label escaping**: in `scripts/lib/webhook/lifecycle.py` `_run_make_target` (`:162-166`), when the job directory has a
   `notify_route` file, pass the job label through `notify_routes.escape_label` before it is used in any message; unrouted jobs
   unchanged.
6. **Restart**: the orphan notice (`:1753`) uses the persisted files, so a routed job's notice stays in its channel; no change
   needed beyond item 4. A changed map does not move a job already created (the ID was persisted at creation).

## Contract readers

- **Webhook body key `notify_route`** (new) on `/api/v1/make` and `/api/v1/cluster`. Writer after p2c: `bin/k3dm-cloud-bridge`
  `_request_body` (`:338-349`). Must not be written by the Slack relay (`workers/slack-relay/index.js:430-571` builds bodies
  with `channel_id`/`thread_ts`/`response_url`; unchanged).
- **Job-directory files** `channel_id` (existing) and `notify_route` (new). Writers: `bin/k3dm-webhook:758-761` and the make
  handler `:2836`. Readers: `_notify_job` `:1302-1307`, orphan handling `:679-680, 715-716, 746, 1753`.
- **`delivery.jsonl`** (writer `bin/k3dm-webhook:1366-1386`) gains a `notify_route` key. Readers: `git grep -n delivery.jsonl`
  — tests under `scripts/tests/bin/` that parse records (they read by key; a new key must not break them; run them).
- **`SLACK_CHANNEL_ID`, `K3DM_STATUS_CHANNEL_ID`, `SLACK_WEBHOOK_URL`**: read, not changed (`scripts/lib/webhook/config.py:35-39`).
- **Error strings** `invalid notification route`, `notification route not supported for this action` come from p2a constants;
  the bridge (p2c) maps a webhook 400 to its own response.

## What NOT to Do

- Do not change behaviour for any request without `notify_route` (the golden test enforces this).
- Do not add a route to the status, diagnostics or hostinger paths; do not change `status.py`.
- Do not read the map at startup or cache it across requests; call `load_routes()` per routed request.
- Do not log or return channel IDs in HTTP responses; do not escape text for unrouted jobs.
- Do not touch the bridge, CLI, approval card, relay or docs. Do not commit.
