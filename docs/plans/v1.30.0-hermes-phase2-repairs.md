## Governing invariants (grep-assertable — must hold at DoD)

1. **No auto-execution.** The poll cycle NEVER runs a repair lever. It only *proposes* (writes a pending
   entry to state + adds text to the Slack summary). Execution happens ONLY in the `approve` subcommand,
   invoked by a human. There must be no call site that runs a repair command outside the `approve` path.
2. **Closed allowlist.** Only the four `Repair` entries in `REPAIRS` are runnable. `approve` on an
   action-id whose `key` is not in `REPAIRS` is refused.
3. **Re-validation at execution time.** `approve` recomputes the proposal's precondition against a FRESH
   sensor cycle. If it no longer holds, the repair does NOT run.
4. **Least privilege preserved.** R1–R3 shell only local levers (make target / `launchctl` / a local
   lib-foundation function) — no new cluster/cloud credential. R4 uses the hermes GitHub PAT (with
   `actions:write`) via `GH_TOKEN` env on a `gh api` POST — never the operator's ambient gh auth, and never
   a token in argv.
5. **Secret hygiene (unchanged).** Secrets loaded from Keychain at runtime, never in argv, never logged,
   never committed. Double-quote all shell expansions in any shell you touch.

def record(sensor, status, evidence, sampled_at=None, data=None):
    """Create the uniform, source-agnostic sensor record."""

    return {

## Step 3 — `repairs.py`: the closed allowlist + propose/approve

Create `scripts/lib/hermes/repairs.py`. Concrete required behavior (implement literally; helper names may
vary but the table, the preconditions, and the two public functions must match):

```python
"""Hermes Phase 2: closed repair allowlist with human-approved execution.

No repair runs outside approve(); the poll cycle only proposes. See
docs/architecture/hermes-phase2-repair-scope.md. Phase 3 (cooldowns, budgets,
durable audit, auto-verification) is NOT implemented and needs its own scope doc.
"""

import hashlib
import subprocess
from hermes.records import timestamp


def _rec(records, name):
    for item in records:
        if item.get("sensor") == name:
            return item
    return None


def _status(records, name):
    item = _rec(records, name)
    return item["status"] if item else "unknown"


def _sustained(history, predicate, cycles):
    """True if `predicate(cycle_degraded_list)` held for the last `cycles` cycles."""
    window = history[-cycles:]
    return len(window) >= cycles and all(predicate(cycle) for cycle in window)
```

**The allowlist preconditions** (pure functions of the current `records` list + `history`, where
`history = state["correlation_history"]`, a list of per-cycle degraded-sensor-name lists maintained by the
Correlator):

- **R1 restart webhook** — the webhook status source is unavailable, corroborated across BOTH
  webhook-backed sensors, sustained ≥ 2 cycles:
  `_status(records,"eso")=="unknown"` AND `_status(records,"node_pressure")=="unknown"` AND both evidence
  strings contain `"source unavailable"` AND `_sustained(history, lambda c: "eso" not in c and "node_pressure" not in c, 2)` is NOT the test — instead require the unknown condition to have held; since `unknown` sensors are not in the Correlator's `degraded` history, track R1's own sustain counter in `state["repair_debounce"]["r1"]` incremented each cycle the unknown-both condition holds, fires at `> 1`. At `approve` time additionally require the webhook launchd agent to exist
  (`launchctl list` contains the webhook label — grep the repo/plist for the exact label).
- **R2 kick zombie port-forward** — single-service signature with the substrate healthy:
  `_status(records,"reachability")=="degraded"` AND `reachability.data.get("verdict")=="single-service"`
  AND `_status(records,"node_pressure")` in (`"healthy"`) (cluster substrate is fine — proves it's a local
  PF, not a broad outage) AND `reachability.data["failed_hosts"]` maps (via the grounded host→label table)
  to exactly one known port-forward label.
- **R3 refresh hostinger edge** — edge-down signature, sustained ≥ 2 cycles:
  `_status(records,"reachability")=="degraded"` AND `reachability.data.get("verdict")=="edge-down"` AND the
  reachability sensor has been degraded for ≥ 2 cycles (`_sustained(history, lambda c: "reachability" in c, 2)`).
- **R4 rerun transient CI** — a transient-classified CI failure with a run-id:
  `_status(records,"ci")=="degraded"` AND `ci.data.get("run_id")` is set AND
  `ci.data.get("conclusion")` in (`"timed_out"`, `"cancelled"`, `"stuck"`).

**The `REPAIRS` table** — each entry declares `key`, `name`, `precondition(records, history, state)`,
`build_command(records) -> (argv:list[str], env:dict)`, `cwd`, `blast_radius`, `reversible=True`,
`needs_scope` (None except R4 = `"actions:write"`). Command builders:

- R1 → `(["make", "restart-webhook"], {})`, cwd = repo root.
- R2 → `(["launchctl", "kickstart", "-k", <resolved PF label>], {})` — label resolved from the single
  failing host via the grounded map; cwd = None.
- R3 → the correct hostinger lever is `_hostinger_refresh_access_layer` (NOT `make refresh`). Since it is a
  shell function in the plugins, invoke it through the dispatcher:
  `(["scripts/k3d-manager", "_hostinger_refresh_access_layer"], {})`, cwd = repo root. (Confirm the function
  is dispatcher-invokable; if it is private/not routable, wrap via the smallest existing public entry point
  and note it — do NOT add `make refresh`.)
- R4 → `(["gh", "api", "--method", "POST",
  f"/repos/{repo}/actions/runs/{run_id}/rerun-failed-jobs"], {"GH_TOKEN": <hermes PAT>})`, cwd = None.
  The PAT is loaded via `_keychain_secret(GITHUB_SERVICE)` and passed ONLY through the subprocess `env`
  (never argv, never logged). If the POST returns a 403/permission error, treat R4 as propose-only:
  record the outcome as `"skipped: token lacks actions:write"` and do not raise.

**Public API:**

```python
def propose(records, state):
    """Return a list of pending proposals for every allowlist entry whose precondition
    holds AND that has not already been attempted in the current incident. Each proposal:
      {action_id, key, name, command, blast_radius, proposed_at, evidence}
    where command is the verbatim shell string the operator would see. Store each into
    state['pending_repairs'][action_id]. Do NOT execute anything."""

def approve(action_id, state, records_now, runner):
    """Look up the pending proposal; refuse if unknown, if key not in REPAIRS, or if the
    precondition recomputed against records_now no longer holds. Otherwise call
    runner(argv, env, cwd) -> (rc, output), append an audit entry to state['repair_audit']
    (action_id, command, key, approved_at, rc), mark the key attempted for this incident,
    and return the outcome dict. Never run a key absent from REPAIRS."""
```

- `action_id = f"{key}-" + hashlib.sha1((key + command + proposed_at).encode()).hexdigest()[:8]`.
- **One-incident guard:** track `state["repairs_attempted_this_incident"]` (a list of keys), reset it when
  the Correlator clears the incident (`state["incident_active"]` transitions to False). A key already in the
  list is not re-proposed. (True cooldowns/budgets are Phase 3 — do not add them here.)

## Step 4 — `bin/k3dm-hermes`: wire propose into the cycle + add `approve` subcommand

1. **Refactor** the body of `main()` that builds `records`, runs the correlator, and saves state into a
   reusable `_run_cycle(state) -> (records, event)` so the `approve` path can produce a fresh `records` for
   re-validation using the identical sensor wiring (same secret loads, same fetch closures).
2. **In the poll path**, after the correlator returns an `event` (an incident), call
   `repairs.propose(records, state)`. If there are proposals, append their verbatim commands + action-ids to
   the Slack `event["text"]` (so the operator sees exactly what to approve) before `post_summary`.
3. **Subcommand dispatch** on `sys.argv`:
   - no args → the poll cycle (current behavior).
   - `approve <action-id>` → load state, run a FRESH `_run_cycle` to get `records_now`, then
     `repairs.approve(action-id, state, records_now, runner)` where `runner(argv, env, cwd)` runs the argv
     via `subprocess.run(..., env={**os.environ, **env}, cwd=cwd, capture_output=True, text=True)` and
     returns `(returncode, stdout+stderr)`. After a successful run, run ONE more `_run_cycle` and report
     whether the proposal's precondition cleared. Print the outcome as JSON. Save state.
   - `list` → print pending proposals from `state["pending_repairs"]` (convenience; optional but recommended).
   Unknown subcommand → non-zero exit with a usage line.
4. Do not change the launchd/setup files. `approve` is operator-run.
