## Routing rule

Route by **who started it**:

| Started by | Channel | Examples |
|---|---|---|
| the operator or an agent | #acg-automation (`SLACK_CHANNEL_ID`) | slash commands, `/ask`, make and cluster jobs, their failure and stall analyses, cloud-bridge task replies |
| the system | #grafana-notification (`K3DM_STATUS_CHANNEL_ID`) | alert analyses, ACG expiry, scheduled credential rotations, CVE scan notices, cluster-status reports |

## Problem

Inventory 2026-10-24:

- Cluster-status reports already go to the status channel (`_post_status_report`).
- **Alert analyses** (Alertmanager → `/api/v1/analyze` → `_run_analyze`) post with
  `response_url or SLACK_WEBHOOK_URL`: an incoming-webhook URL whose channel was fixed when the URL
  was created, not the status channel.
- **ACG expiry, Grafana/Keycloak/ArgoCD credential rotators** (CronJobs) post to the incoming-webhook
  URL in Secret `platform-ops-notifications`, key `slack-incoming-webhook-url`. Slack fixes that
  URL's channel at creation, so code cannot redirect it; the operator replaces the URL (F2).
- The Prometheus rotation LaunchAgent (`com.k3d-manager.prometheus-credential-rotator.plist.tmpl`)
  sets no Slack URL, so its notice is probably never sent. Out of scope here; tracked separately.

## Fix

### F1. Alert analyses go to the status channel (Luna)

In `_run_analyze`, replace the post block:

```python
            notify_url = response_url or SLACK_WEBHOOK_URL
            if notify_url:
                _slack_post(notify_url,
                    f"🔍 *{alert_name}* — `{display_name}`\n{analysis}")
```

with this order:

1. `response_url` set (someone asked from Slack): post there, as today.
2. Else, when `SLACK_BOT_TOKEN` and `STATUS_CHANNEL_ID` are set: `_post_slack_bot(text, channel_id=STATUS_CHANNEL_ID)`. A non-empty ts means done.
3. Else, or when step 2 returns `""`: `_slack_post(SLACK_WEBHOOK_URL, text)` if the URL is set (today's behaviour, so a failed bot post still reaches Slack).

The text is unchanged. Do not route analyses through `_notify_job` (that is the task channel).
Nothing else in the webhook changes channel.

### F2. Scheduled notices (operator, after landing — not Luna)

1. In the Slack app's Incoming Webhooks page, add a webhook for #grafana-notification.
2. Replace the value of `slack-incoming-webhook-url` in Secret `platform-ops/platform-ops-notifications`
   on the hub (the command `deploy_argocd_platform_ops` prints). Claude never handles the URL.
3. The CronJobs read the Secret per run, so no restart is needed.

### F3. Docs (Luna)

`docs/howto/webhook-operations.md`: a "Which channel" section with the routing table above, the F1
order for alert analyses, and the F2 steps.
