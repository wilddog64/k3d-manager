## Problem

The operator rotates the lead role between Claude Opus, Gemini Argon, and OpenAI Sol and Terra. The dashboards cannot show what a lead did:

- **Agent Dispatch** lists workers per spec. Its coordinator columns are 83% `unknown`.
- **Agent Activity** counts Codex, agy and Claude sessions as workers or as context use, never as "lead of task X".
- **The 2026-11-03 run.** Argon led for about 5 h: forensic report, spec narrowing, six Luna dispatches, five lands. Argon's own 3.49M input, 87.0M cache-read and 322K output tokens appear nowhere.
- **The keychain stall.** The stall that ran 2026-11-02 to 11-03 (24 runs, 23 correction or clarification resumes, no land) is not visible as a lead-steering problem.

## Design

### Activity sources

The collectors are read-only and local. They run on every machine that pushes agent metrics.

| Source | Gives |
|---|---|
| Dispatch ledger `ledger.jsonl` | `start`, `resume` by reason, `intervention`, `land`, `land_refused`, `verify` pass/fail, `abandon`, `handoff`, `primary_coordinator`. Each carries `coordinator_identity` |
| Claude transcripts `~/.claude/projects/*/*.jsonl` | Claude lead turns, tokens, tool calls (existing collector) |
| agy transcripts `~/.gemini/antigravity-cli/brain/*/.system_generated/logs/transcript_full.jsonl` | agy lead steps, tokens, tool calls (new collector, from the agy bug) |
| Codex sessions `~/.codex/sessions` that the cost-attribution plan categorises as interactive | Sol/Terra lead sessions |
| Git trailers on the release branch (`Co-Authored-By`, `Coordinator:`) | specs and bug docs filed, fixes landed, by lead |

A lead session is linked to a task when the session's tool calls name the task slug or spec path. The rule is the same one used for Claude cost attribution. An unlinked lead session still counts toward the lead's totals, under `task="none"`.

### Metrics

Pushed by `bin/k3dm-dispatch-metrics` to one Pushgateway group, so Prometheus retention does not matter. Windows are 7d and 30d, per lead `vendor/model`:

- `k3dm_lead_actions_total{window,lead,action}`. `action` is one of `spec_filed`, `dispatch`, `resume_correction`, `resume_clarification`, `resume_continue`, `intervention`, `land`, `land_refused`, `verify_pass`, `verify_fail`, `abandon`, `handoff_out`.
- `k3dm_lead_tasks{window,lead,outcome}`. `outcome` is `landed_first_run`, `landed_after_resume`, `open`, `abandoned` or `stalled`. `stalled` means the plan-6 rule: three or more correction or clarification resumes with no new commit.
- `k3dm_lead_tokens_total{window,lead,kind}` with `kind` in `input|cache_read|output`, and `k3dm_lead_active_seconds{window,lead}`.
- `k3dm_lead_cost_usd{window,lead}`, with `k3dm_lead_cost_state{state=measured|estimated|unpriced}`. Where a model has no published price, the state is `unpriced`, never 0.
- `k3dm_lead_attribution_coverage_ratio{window}` is the share of dispatches with a named lead. Below 90%, the dashboard shows a banner.

### Dashboard: `k3dm Lead Model Activity` (platform-ops, new YAML)

1. **Header row.**
   - Attribution coverage, with a red banner below 90%.
   - Leads active this window.
   - Tasks landed.
   - Tasks stalled now.
2. **Per-lead comparison table.** Columns:
   - tasks led
   - landed on the first run (%)
   - corrections per landed task
   - verify pass rate
   - median spec→land time
   - tokens
   - cost per landed task
   - stalled or abandoned count
3. **Actions over time.** A stacked bar chart per lead, broken down by action.
4. **Open tasks by lead.** Each row shows age, resumes by reason and the last commit age. A red row means stalled. This is where the 2-day keychain run would have shown up on day one.
5. **Lead timeline.** The last 50 lead actions: time, lead, action, slug and outcome.
6. **Hand-offs.** Which lead passed which task to which, with the outcome after.

A guide goes in `docs/guides/grafana-dashboards/k3dm-lead-model-activity.md` and is linked from the dashboards index.

## Out of scope

- Selecting or rotating models automatically. Model choice stays with the operator.
- Live per-turn streaming. A 5-minute push matches the other agent dashboards.
- Pricing for models without published prices. They show as `unpriced`.
