## Part A — lib-foundation `_run_parallel` (upstream first)

`_run_parallel` in `scripts/lib/system.sh` runs one command per input item, N at a time, and reports per item.

- Input: NUL-separated items on stdin. A command template (argv after `--`), with the item appended as the last argument.
- Uses only base-OS tools: `xargs -0 -n 1 -P N` (BSD and GNU both). No GNU parallel.
- Jobs: `--jobs N`, else performance cores (`sysctl -n hw.perflevel0.physicalcpu` on macOS when present), else
  `getconf _NPROCESSORS_ONLN`, else 1.
- Writes, under `--out DIR`, per item a log, its rc and its seconds. The item name is made filesystem-safe. A summary
  prints one `PASS|FAIL <item> <s>s` line per item, then `SLOWEST <item> <s>s` and `TOTAL <s>s`, in the format
  `scripts/ci/fast_gate.sh:217` uses.
- `--order-by FILE`: a `seconds item` list from a previous run. Known items run longest first, unknown items first of all.
- `--retry-failed`: a failed item reruns once, alone, after the pool drains. If it passes, the summary marks it `FLAKY`
  and the overall rc stays non-zero unless `--flaky-ok` is given. A blanket retry is never applied.
- Overall rc: 0 only when every item passed (or was flaky with `--flaky-ok`).

## Part B — k3d-manager

1. `make test-all PARALLEL=1` runs the three suites' files through `_run_parallel`. Each job still runs under
   `scripts/tests/tripwire.sh`, in its own `TMPDIR`, with the same environment as the serial recipe for that suite.
   Without `PARALLEL`, `test-all` is unchanged: serial is the default and the reference.
2. Timings from the last parallel run are kept in `${XDG_CACHE_HOME:-$HOME/.cache}/k3d-manager/test-times.txt` for
   `--order-by`.
3. The log still carries `[test-all] stage-complete test|test-bin|test-python` once each stage's files have all finished,
   so `bin/k3dm-test-metrics` and the Test dashboard keep working.
4. Failures rerun once (`--retry-failed`). Flaky items are listed by name at the end of the run, and the run stays red.
5. Split `scripts/tests/bin/codex_dispatch.bats` into files of at most about 60 s each, moving cases unchanged, so the
   floor drops from about 340 s.
6. CI is unchanged in this plan (`.github/workflows/ci.yml:120-134` keeps its serial steps). CI parallelism is a
   separate idea once the local runner has a clean month.
