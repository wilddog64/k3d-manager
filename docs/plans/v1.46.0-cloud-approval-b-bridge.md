## Context

`bin/k3dm-cloud-bridge` polls the `cloud-requests` branch and sends each valid request to the local webhook. Four actions use the
cloud-runner token and today run on push alone: `sandbox-up`, `sandbox-down`, `make-e2e`, `make-e2e-remote` (token choice at `:332`).
From now on each of them waits for an operator Approve on a Slack card. Reader actions must not change at all.

`scripts/lib/webhook/cloud_approval.py` (landed by a sibling) provides: `load`, `save`, `StoreError`, `admit` (returns `Pending` or
`Refusal`), `card(pending) -> (text, blocks)`, `decide(store, approvals, now) -> list[Decision]` (`kind` `execute` with `request`,
`expire` with `request_id`, `drop` with `approval_id`; decided records are removed from the store), and `CLOUD_ACTION_ID_RE`. Read it.

## Change

1. **`gated(action) -> bool`**: true exactly for actions whose `ACTION_ALLOWLIST` target is `e2e` or `e2e-remote`, or that are in
   `LIFECYCLE_TIMEOUTS`. Rewrite the token choice at `:332` to `_get_cloud_runner_token() if gated(action) else _get_reader_token()`.
2. **Config** read once per tick: `drain_url = os.environ.get("K3DM_HERMES_APPROVAL_DRAIN_URL", "")`, drain token from Keychain
   `k3dm-hermes-approval-drain-token`, relay URL from Keychain `k3dm-slack-webhook` (use the existing Keychain helper the bridge or
   `webhook.auth` already has; never print or log the values). Config is complete only if all three are non-empty and `drain_url` starts
   with `https://`.
3. **Store**: `APPROVALS_PATH = STATE_DIR / "approvals.json"`. Load at the start of each tick. On `StoreError`, log one error line (no
   file content), answer no gated request this tick (leave them claimed-but-unanswered, as a slow request is) and still process reader
   requests.
4. **New gated request** (in the claim loop, after `prepare_request` returns no error response, `:639-643`): instead of `_call_webhook`:
   - config incomplete -> commit `responses/<id>.json` `rejected`, reason `operator approval is not configured on the bridge`;
   - `admit` returns `Refusal` -> commit `rejected` with its reason;
   - else `save` the store, build `card`, `post_interactive(relay_url, text, blocks)`. Post failed -> remove the record, `save`, commit
     `rejected` `approval card not delivered; file a new request`. Post succeeded -> commit `responses/<id>.pending.json` with
     `_response(id, action, "ok", 202, body={"status": "approval-pending", "approval_id": <id>, "expires_at": <ISO Z>})` and
     `record_processed=False`. Do not add the id to `processed`. The nonce never goes into a response, the outbox, a log line or a commit.
   Each of these counts toward `MAX_PER_TICK` like any other answered request.
5. **Every tick, before the `if not changed: return` early exit**: if the store has pending records and config is complete, call
   `fetch_approvals(drain_url, token, id_pattern=CLOUD_ACTION_ID_RE)` and `decide(store, approvals, time.time())`; `save` the store
   **before** acting on the decisions (a crash after the save cannot run a request twice). Then for each decision: `drop` ->
   `delete_approval(..., id_pattern=CLOUD_ACTION_ID_RE)`; `expire` -> commit `responses/<id>.json` `rejected`, reason
   `not approved before the request expired`, and add to `processed`; `execute` -> run the stored request through the same code path a
   reader request takes after `prepare_request` (`_call_webhook`, `scrub_credentials` for `job-status`, `job_artifacts`, `_watch_entry`,
   outbox, `_write_commit`, `processed`). Factor that tail into one function both paths call; do not copy it. With pending records but
   incomplete config, still `expire` records past their `expires_at` (call `decide` with an empty approvals list).
6. **Orphan recovery** (`_recover_orphaned_claims`, `:236-253`): skip a request id that is in the pending store, as it skips
   `_slow_pending`.
7. **Plist**: add `K3DM_HERMES_APPROVAL_DRAIN_URL` = `https://k3dm-slack-relay.k3dm.workers.dev/hermes/approvals` to
   `EnvironmentVariables` in the bridge plist template (same value as `com.k3d-manager.hermes.plist.tmpl:25-26`).

## Tests (`scripts/tests/bin/test_cloud_bridge.py`, extend; follow its existing fakes)

Use fake Keychain, fake `post_interactive`, fake `fetch_approvals`/`delete_approval`, a counting fake for both token getters and for
the webhook opener, and a tmp `STATE_DIR`; first assert each fake is the one in use (patched target, tmp dir), per the repo's test
rules. Cover: `gated` is true for exactly the four actions and false for every other `ACTION_ALLOWLIST` key; a gated request posts one
card, commits `.pending.json` without the nonce, reads no cloud-runner token and opens no webhook connection; a matching approval runs it
once and commits the normal response; wrong nonce, unknown id, expired record, denied (no approval) never open the webhook or read the
cloud-runner token; expiry commits the exact reason; caps give the exact reason; config missing gives the exact reason; post failure
removes the record; restart (new process state, same `STATE_DIR`) keeps the pending record and orphan recovery does not answer it;
`StoreError` leaves reader requests working; a reader request is answered in the same tick with three records pending; the existing
65 tests still pass unchanged.
