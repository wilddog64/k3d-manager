## Why Tier 1 is not trivial (read before implementing)

The existing `shopping_cart_reconcile_*` functions in `scripts/plugins/shopping_cart.sh` are hardcoded to
the **live app cluster** (`--context ubuntu-k3s`, `shopping-cart-apps` namespace, ESO force-sync, `kubectl
exec` into `postgresql-products-0`). They **assume the full ArgoCD/ESO/Vault/Postgres stack is already
running** — they are NOT reusable to stand up three bare services in a throwaway vCluster.

The reusable primitives that DO apply:
- Each service repo ships a **`k8s/base` kustomize** (confirmed: `shopping-cart-product-catalog/k8s/base`
  is applied via `kubectl kustomize … | kubectl apply` in `shopping_cart_reconcile_product_catalog`).
- The e2e repo's **`docker-compose.yml`** already declares the exact datastore + env contract the services
  need. The vCluster bundle is essentially **"docker-compose.yml translated to k8s manifests."**

So Tier 1 has two sub-parts: **(A) a self-contained e2e substrate bundle** (3 services + minimal
datastores + seed, no ESO/Vault/ArgoCD, `OAUTH2_ENABLED=false`) and **(B) the test image + in-cluster Job +
contract**. (A) is the real design work; (B) is mechanical.

## Service/datastore contract (from `shopping-cart-e2e-tests/docker-compose.yml` — authoritative)

| Service | Image (compose) | Port | Backing store | Key env |
|---|---|---|---|---|
| product-catalog | `shopping-cart/product-catalog` | 8000 | Postgres db `products` | `DATABASE_URL=postgresql://postgres:postgres@postgres:5432/products`, `OAUTH2_ENABLED=false` |
| basket | `shopping-cart/basket` | 8083 | Redis | `REDIS_HOST=redis`, `REDIS_PORT=6379`, `REDIS_PASSWORD=testredis123`, `OAUTH2_ENABLED=false` |
| order | `shopping-cart/order` | 8080 | Postgres db `orders` | `SPRING_DATASOURCE_URL=jdbc:postgresql://postgres:5432/orders`, `SPRING_DATASOURCE_USERNAME=postgres`, `SPRING_DATASOURCE_PASSWORD=postgres`, `OAUTH2_ENABLED=false` |

Runtime images for the vCluster come from **GHCR** (`ghcr.io/wilddog64/shopping-cart-<svc>`), pinned by
digest, pulled with the GHCR secret (§Part 2 step 3). The compose `shopping-cart/<svc>:latest` refs are the
local-build names only — do NOT use `:latest` in the bundle (A08).

## Part 1 — `shopping-cart-e2e-tests`: publishable e2e image + `workflow_call`

**Branch (e2e repo):** `feat/e2e-image-and-workflow-call` (from `origin/main`).

### 1a. New `Dockerfile`

Pin the base image to the **exact** Playwright version resolved in `package-lock.json` (the manifest is
`@playwright/test: ^1.40.0` — read the locked version and substitute; example uses `v1.40.0`):

```dockerfile
# syntax=docker/dockerfile:1
FROM mcr.microsoft.com/playwright:v1.40.0-jammy
WORKDIR /e2e
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
# Tests are invoked by the k8s Job command; default to the api+flows projects.
ENV CI=true
ENTRYPOINT ["npx", "playwright", "test"]
CMD ["--project=api", "--project=flows"]
```

Add `.dockerignore`:

```
node_modules
playwright-report
test-results
.git
```

### 1b. New publish workflow `.github/workflows/publish-image.yml`

Builds and pushes `ghcr.io/wilddog64/shopping-cart-e2e-tests` tagged `sha-<gitsha>` (immutable) + `latest`,
emitting the digest. Pin every action to a tag; `contents: read` + `packages: write` only.

```yaml
name: Publish E2E Image
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  packages: write
jobs:
  build-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - id: meta
        uses: docker/metadata-action@v5
        with:
          images: ghcr.io/wilddog64/shopping-cart-e2e-tests
          tags: |
            type=sha,prefix=sha-,format=long
            type=raw,value=latest,enable={{is_default_branch}}
      - uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
```

### 1c. `workflow_call` trigger on `e2e-tests.yml` (reusable-invocation surface)

Add a `workflow_call` trigger alongside the existing `workflow_dispatch`, with four inputs mapped onto the
env each job already reads. **Do NOT re-enable `push`/`schedule`.** Precedence: input → repo var → localhost
default.

**Old (`on:` block, lines 3–19):**
```yaml
on:
  workflow_dispatch:
    inputs:
      environment:
        description: 'Environment to test against'
        required: true
        default: 'staging'
        type: choice
        options:
          - staging
          - production
  # schedule disabled — re-enable once ImagePullBackOff resolved and app cluster healthy
  # schedule:
  #   - cron: '0 6 * * *'
  # push/pull_request disabled — api-tests and flow-tests require live services
  # at localhost:8083 (basket), localhost:8000 (catalog), localhost:8080 (order)
  # which do not exist in GitHub Actions CI; re-enable after adding service containers
```

**New:**
```yaml
on:
  workflow_dispatch:
    inputs:
      environment:
        description: 'Environment to test against'
        required: true
        default: 'staging'
        type: choice
        options:
          - staging
          - production
  workflow_call:
    inputs:
      basket_url:
        type: string
        required: false
        default: ''
      product_catalog_url:
        type: string
        required: false
        default: ''
      order_url:
        type: string
        required: false
        default: ''
      oauth2_enabled:
        type: string
        required: false
        default: 'false'
  # schedule / push / pull_request remain DISABLED — no reachable services in GH CI.
  # Substrate-backed runs come via workflow_call (k3d-manager Tier 1) only.
```

Then in **each** job's `env:` (api-tests, flow-tests, all-tests), change each of the three URL lines and the
oauth line to prefer the `workflow_call` input, e.g. for api-tests (lines 49–52):

**Old:**
```yaml
          PRODUCT_CATALOG_URL: ${{ vars.PRODUCT_CATALOG_URL || 'http://localhost:8000' }}
          BASKET_URL: ${{ vars.BASKET_URL || 'http://localhost:8083' }}
          ORDER_URL: ${{ vars.ORDER_URL || 'http://localhost:8080' }}
          OAUTH2_ENABLED: 'false'
```
**New:**
```yaml
          PRODUCT_CATALOG_URL: ${{ inputs.product_catalog_url || vars.PRODUCT_CATALOG_URL || 'http://localhost:8000' }}
          BASKET_URL: ${{ inputs.basket_url || vars.BASKET_URL || 'http://localhost:8083' }}
          ORDER_URL: ${{ inputs.order_url || vars.ORDER_URL || 'http://localhost:8080' }}
          OAUTH2_ENABLED: ${{ inputs.oauth2_enabled || 'false' }}
```
Apply the same three-line change to the `flow-tests` and `all-tests` env blocks.

## Part 2 — k3d-manager: `scripts/plugins/e2e.sh` + substrate bundle + BATS

**Branch:** `k3d-manager-v1.25.0` (already checked out).

### 2a. Substrate bundle `scripts/etc/e2e/` (the self-contained overlay — the core new asset)

A kustomize overlay applied into the vCluster's `shopping-cart-apps` namespace that stands up the 3 services
+ minimal datastores, no ESO/Vault/ArgoCD. Files (all pinned images, no `:latest`):

- `scripts/etc/e2e/kustomization.yaml` — namespace `shopping-cart-apps`; resources = datastores + the three
  service `k8s/base` refs (or vendored copies) + the seed job; `commonLabels: k3dm.k3d.io/e2e-substrate: "true"`.
- `scripts/etc/e2e/postgres.yaml` — single Postgres Deployment + Service `postgres:5432`, image
  `postgres:16.4` (pinned), env `POSTGRES_USER=postgres POSTGRES_PASSWORD=postgres`, an initdb ConfigMap
  creating **both** `products` and `orders` databases. **Dev-only credentials, e2e substrate only — never a
  production path** (CLAUDE.md test-credential rule).
- `scripts/etc/e2e/redis.yaml` — Redis Deployment + Service `redis:6379`, image `redis:7.4-alpine` (pinned),
  `--requirepass testredis123`.
- Service Deployments/Services for product-catalog (8000), basket (8083), order (8080): **reuse each repo's
  `k8s/base`** where a clean base exists; otherwise vendor minimal Deployments here. Image refs point at
  `ghcr.io/wilddog64/shopping-cart-<svc>` pinned by digest; env exactly per the contract table above;
  `OAUTH2_ENABLED=false` on all three. The **candidate digest** (harness arg) overrides the image for the
  service under test.
- `scripts/etc/e2e/seed-job.yaml` — the product-catalog seed (mirror the existing
  `product-catalog/k8s/base` seed job selected by `app.kubernetes.io/component=seed`).

> Assembly guidance: derive every value from `shopping-cart-e2e-tests/docker-compose.yml` (already the
> service+datastore contract) and each service's `k8s/base`. Keep it flat and self-contained; this bundle
> must bring the app up with **zero** dependency on Vault/ESO/ArgoCD.

### 2b. New plugin `scripts/plugins/e2e.sh`

Public `e2e_verify_vcluster`; privates `_e2e_*`. Idioms from `vcluster.sh`: `set -euo pipefail`, `_info`/
`_err`/`_warn`, `_run_command`, `_kubectl`, DRY_RUN-aware, unique DNS-label name, `trap … EXIT` teardown.

```bash
#!/usr/bin/env bash
set -euo pipefail

E2E_IMAGE="${E2E_IMAGE:-ghcr.io/wilddog64/shopping-cart-e2e-tests}"
E2E_IMAGE_TAG="${E2E_IMAGE_TAG:-latest}"
E2E_NAMESPACE="${E2E_NAMESPACE:-shopping-cart-apps}"
E2E_JOB_TIMEOUT="${E2E_JOB_TIMEOUT:-1200}"
E2E_REPORT_DIR="${E2E_REPORT_DIR:-${HOME}/.k3dm/e2e}"
export E2E_IMAGE E2E_IMAGE_TAG E2E_NAMESPACE E2E_JOB_TIMEOUT E2E_REPORT_DIR

function _e2e_load_deps() {
  # Load sibling plugins we depend on, unless already sourced (probe a known function of each).
  local plugin
  if ! declare -f vcluster_create >/dev/null 2>&1; then
    plugin="${SCRIPT_DIR}/plugins/vcluster.sh"
    [[ -r "$plugin" ]] || _err "e2e: required plugin not found: ${plugin}"
    # shellcheck source=/dev/null
    source "$plugin"
  fi
  if ! declare -f shopping_cart_resolve_ghcr_pat >/dev/null 2>&1; then
    plugin="${SCRIPT_DIR}/plugins/shopping_cart.sh"
    [[ -r "$plugin" ]] || _err "e2e: required plugin not found: ${plugin}"
    # shellcheck source=/dev/null
    source "$plugin"
  fi
}

function e2e_verify_vcluster() {
  local candidate_digest="${1:-}"
  local run_id name
  run_id="$(date +%s)-${RANDOM}"
  name="e2e-${run_id}"

  _e2e_load_deps
  local kubeconfig
  kubeconfig="$(_vcluster_kubeconfig_path "$name")"

  # ALWAYS tear the vCluster down — success or failure.
  trap '_e2e_teardown "$name"' EXIT

  vcluster_create "$name"
  _e2e_deploy_substrate "$kubeconfig" "$candidate_digest"
  _e2e_run_job "$kubeconfig" "$run_id" "$candidate_digest"   # sets _E2E_EXIT + writes summary
  local rc="${_E2E_EXIT:-1}"

  _e2e_write_summary "$run_id" "$candidate_digest" "$rc"     # JSON summary → $E2E_REPORT_DIR
  return "$rc"
}

function _e2e_teardown() {
  local name="${1:-}"
  [[ -z "$name" ]] && return 0
  vcluster_destroy "$name" || _warn "e2e: teardown of ${name} failed (manual cleanup may be needed)"
}
```

`_e2e_deploy_substrate <kubeconfig> [candidate_digest]`:
- Provision the GHCR pull secret in the vCluster (reuse `shopping_cart_resolve_ghcr_pat`; create the
  `docker-registry` secret against the vCluster kubeconfig — do NOT reuse
  `shopping_cart_create_ghcr_pull_secret` verbatim; it targets `APP_CONTEXT`/ubuntu-k3s).
- `KUBECONFIG="$kubeconfig" kubectl apply -k "${SCRIPT_DIR}/etc/e2e"` (patch the candidate digest onto the
  service under test when `candidate_digest` is set).
- Wait for postgres, redis, product-catalog, basket, order rollouts; run + wait for the seed job.

`_e2e_run_job <kubeconfig> <run_id> [candidate_digest]`:
- Apply a Playwright **Job** into the vCluster from `E2E_IMAGE:E2E_IMAGE_TAG` (or pinned digest),
  `imagePullSecrets` = the GHCR secret, `restartPolicy: Never`, `backoffLimit: 0`, env pointing at ClusterIP
  DNS: `PRODUCT_CATALOG_URL=http://product-catalog.shopping-cart-apps.svc:8000`,
  `BASKET_URL=http://basket.shopping-cart-apps.svc:8083`,
  `ORDER_URL=http://order.shopping-cart-apps.svc:8080`, `OAUTH2_ENABLED=false`.
  Command: `sh -c 'npx playwright test --project=api --project=flows; rc=$?; cat test-results/results.json;
  exit $rc'` so the JSON report reaches `kubectl logs`.
- `kubectl wait --for=condition=complete/failed`; capture pod logs; set `_E2E_EXIT` to 0 only if the Job
  succeeded. Ship raw logs to `$E2E_REPORT_DIR/<run_id>.log` (Path B / Loki source, plan #2).

`_e2e_write_summary <run_id> [digest] <rc>`:
- Emit the flat JSON summary (schema from plan #2 / observability):
  `{run_id,tier:"vcluster",service,candidate_digest,project:"api+flows",passed,total,failed,
  duration_seconds,timestamp,commit}` to `$E2E_REPORT_DIR/<run_id>.json`. Parse totals from the captured
  `results.json`. **This is the gate-consumable contract (v1.26.0) — MUST be exit-code-faithful.**
- (The `k3dm.k3d.io/e2e-result=true` **event ConfigMap** write + exporter/dashboard are plan #2, not here —
  but emit the same JSON so #2 is a drop-in.)

### 2c. BATS `scripts/tests/e2e.bats` (structural, no live cluster)

- `e2e_verify_vcluster` is a public function (no leading underscore).
- Sourcing `e2e.sh` under `set -euo pipefail` succeeds; `shellcheck -S warning` clean.
- DRY_RUN path: stubs for `vcluster_create`/`vcluster_destroy`/`kubectl` assert the harness sets **exactly**
  the three service URLs + `OAUTH2_ENABLED=false`, applies `-k scripts/etc/e2e`, and calls
  `vcluster_destroy` even when the Job stub returns non-zero (teardown-on-failure).
- Exit-code contract: Job-failure stub → `e2e_verify_vcluster` returns non-zero; Job-success stub → 0.
- A JSON summary file is written with the required keys.

## Rules (CLAUDE.md)

- **Never point e2e at live Hostinger prod** — ephemeral vCluster only.
- **Always `vcluster_destroy` via `trap … EXIT`** — even on failure; unique name per run.
- **Secrets:** GHCR PAT via `shopping_cart_resolve_ghcr_pat` (env/Vault/gh) — never in argv/logs (A02).
  Postgres/Redis dev creds are e2e-substrate only, never a production path.
- **Least privilege:** no `cluster-admin`; reuse `scripts/etc/vcluster/argocd-manager-rbac.yaml` if RBAC needed.
- **Pin everything** (A08): Playwright base image to the locked version; postgres/redis image tags; all GH
  actions `@vN`; service images by GHCR digest — no `:latest` in the bundle.
- `shellcheck -S warning` clean on `e2e.sh`; BATS green; `set -euo pipefail`; LF only; no inline comments in
  shell unless requested.
- **Do NOT** build the promoter dispatch-and-wait, the event ConfigMap exporter/dashboard, or Tier 2
  (`e2e_verify_sandbox`) here — those are plan #2 / v1.26.0. Only guarantee the exit-code + JSON-summary
  contract.

## What NOT to do

- Do NOT run e2e against live Hostinger prod; ephemeral vCluster only.
- Do NOT leave vClusters running — always `vcluster_destroy` via trap.
- Do NOT re-enable `push`/`schedule` in `e2e-tests.yml`.
- Do NOT reuse `shopping_cart_create_ghcr_pull_secret`/`reconcile_*` verbatim — they target the live app
  cluster context; the harness targets the vCluster kubeconfig.
- Do NOT use `:latest` for any service/datastore image in the bundle — pin (A08).
- Do NOT build Tier 2, the exporter/dashboard, or the promoter gate here (plan #2 / v1.26.0).
- Do NOT create a PR, skip pre-commit hooks (`--no-verify`), or commit to `main`.
