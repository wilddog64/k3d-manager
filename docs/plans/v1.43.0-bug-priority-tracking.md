## Problem

`docs/bugs/` held 673 docs when this was filed (2026-10-08), and none had a priority. 266 had a `**Status:**` line and 199 had
a `**Severity:**` line, with values spelled every way: `high`, `High`, `Medium`, `P2`, `P3`.
Update 2026-10-09: docs filed since then carry `**Priority:**` by hand (14 top-level docs, 3 of
them P1 in v1.42.0); every older doc is still `unset`. A model reading the sentence above as current
told the operator "no bug has a priority" — see item 9's 2026-10-09 note.
Nobody can answer "what is the most important open bug?" without reading files. Grafana sees
nothing, and `/ask-docs` cites bug docs without knowing whether a bug is open or closed, or how
urgent it is.

## Definitions (the contract every later item uses)

**Priority** is urgency, meaning when this must be fixed. It is separate from Severity (impact),
which stays as it is.

| Priority | Meaning | Expectation |
|---|---|---|
| `P0` | Outage, data loss, security exposure or alerting silenced **now** | Fix before other work |
| `P1` | A feature or alert path is broken with no workaround | Fix in the current release |
| `P2` | Degraded, but a workaround exists | Next release |
| `P3` | Cosmetic, hygiene or test-only | Backlog |

Header line, placed directly under `**Status:**`: `**Priority:** P1` (exactly `P0`–`P3`;
free text may follow after ` — `).

**`doc_meta(text) -> (priority, state)`** is a single parser, shared by every consumer:
- `priority` is the first `^\*\*Priority:\*\*\s*(P[0-3])\b`. If there is none, it falls back to a
  legacy `^\*\*Severity:\*\*\s*(P[0-3])\b`, and otherwise it is `"unset"`.
- `state` comes from the first status value found, in this order (the repo uses all three
  formats: 268 bold, 11 `## Status` headings, 6 bare `Status:` lines):
  1. `^\*\*Status:\*\*\s*(.*)`;
  2. `^Status:\s*(.*)`;
  3. a `^## Status\s*$` heading: the first non-blank line after it.

  The value maps as follows:
  - `"closed"` when the value starts, case-insensitively, with one of `FIXED`, `CLOSED`,
    `RESOLVED`, `DONE`, `WONTFIX`, `WON'T FIX`, `SUPERSEDED`, `DUPLICATE`, `VERIFIED` or `LIVE-VERIFIED`,
    or when it starts with `Fixed on` / `Fixed in` (the `## Status` prose form);
  - `"open"` for any other value;
  - `"unknown"` when there is no Status line.

## Fix

### 1. `scripts/lib/hermes/prior_art.py`
- Add `doc_meta(text)`, exactly as defined above, with the regexes compiled at module level.
- `SCHEMA_SQL`: after the `CREATE TABLE`, add
  `ALTER TABLE {TABLE} ADD COLUMN IF NOT EXISTS priority text NOT NULL DEFAULT 'unset';` and the
  same for `state text NOT NULL DEFAULT 'unknown'`. Existing stores must upgrade in place, with
  **no re-embed**.
- Add `fetch_doc_meta(paths) -> {path: (priority, state)}`, a single `SELECT` over the given paths.
  `search()`'s return shape does **not** change, because it has other callers.

### 2. `scripts/index-docs.py`
- On every run, after the upsert and prune, write `priority` and `state` for **all** corpus docs
  through a metadata-only staging script: `COPY` path, priority and state, then
  `UPDATE ... FROM staging`, in one transaction. This must not touch `content_hash` or
  `embedding`, and it costs no embedding calls.
- `doc_meta` reads the same text the indexer already reads. That includes the `--ref` path, so
  Hermes (which indexes `K3DM_INDEX_REF`) gets metadata from the same ref it embeds.
- A run with no doc changes still makes zero embedding calls. Assert this in a test.

### 3. `scripts/lib/webhook/ask_docs.py`
- `_sources` calls `fetch_doc_meta` for the kept paths. If it raises `RetrievalUnavailable`, use
  `{}` and continue.
- `_excerpt` adds `Priority: <p> · State: <s>` after the `Date:` line, for `docs/bugs/` paths
  only.
- In the `Sources:` list, each bug link gets the suffix ` [P1 · open]`. Non-bug docs are unchanged.

### 4. `scripts/find-similar-docs.py`
For `docs/bugs/` results, print `         priority=<p> state=<s>` under the title line, and add the
same two fields to the `--json` output. If metadata is unavailable, print nothing extra.

### 5. `bin/k3dm-vectordb-metrics`: push bug counts
- New function `_bug_metrics(root, ref)`:
  - read `docs/bugs/*.md` from `ref` when `K3DM_INDEX_REF` is set (reuse `iter_corpus`'s ref
    reader), otherwise from the working tree;
  - emit `k3dm_bug_docs{priority="<P0..P3|unset>",state="<open|closed|unknown>"} <count>` for
    **every** combination, with zeros included, so a series never disappears;
  - also emit `k3dm_bug_docs_scan_timestamp_seconds <epoch>`.
- Push these to a **separate** group, `/metrics/job/k3dm-bug-docs`, so a failed bug scan never
  blanks the vectordb gauges. Retry and non-fatal behaviour stay the same as `publish()`.
- Scope is `docs/bugs/*.md`, top level only. `docs/bugs/archive/` is excluded, and so is
  `docs/issues/`.
- If reading or parsing any doc fails, push **nothing** for that run. The last good counts stay in
  the Pushgateway, and the scan-timestamp gauge going stale is the signal. Never push a partial
  or all-zero snapshot after a failure.
- No document title, path or text ever goes into a label. Only the two fixed enums are labels.

### 6. Grafana: `scripts/etc/argocd/platform-ops/grafana-dashboard-bugs.yaml` (new)
Model it on `grafana-dashboard-vectordb.yaml`, with the same ConfigMap shape and labels. Panels:
- Stat **Open P0**: `sum(k3dm_bug_docs{state="open",priority="P0"})`. Red when > 0.
- Stat **Open P1**: the same with `P1`. Orange when > 0.
- Stat **Open, untriaged**: `sum(k3dm_bug_docs{state=~"open|unknown",priority="unset"})`.
- Bar gauge **Open by priority**: `sum by (priority) (k3dm_bug_docs{state="open"})`.
- Time series **Open by priority over time**: the same query.
- Stat **Scan age**: `time() - k3dm_bug_docs_scan_timestamp_seconds`.

- Panel descriptions: the time series is an **inventory snapshot**. A falling open count does not
  prove a fix, because a doc can be archived, superseded or deleted.

### 8. Per-release bug tally: `scripts/bug-tally.py` (new) and `make bug-tally`

Added 2026-10-09. In Slack, the operator asked "how many bugs are open and how many are fixed in
v1.42.0":
- `/ask-docs` and Gemini both said the excerpts didn't contain it. That was correct, because
  retrieval returns 5 passages and a count needs every doc.
- Codex answered **"3 bugs were fixed"**, citing the three newest fix commits. That was wrong.
  The real figures were 35 docs: about 24 fixed, 3 open and 8 with no Status line.

A count must come from a deterministic tally, never from a model.

**`doc_release(text, added_release) -> (release, source)`** goes in `prior_art.py`, next to
`doc_meta`, and is a pure function:
1. If a `^\*\*Branch:\*\*` line exists, use the first `v(\d+\.\d+\.\d+)` on that line, giving
   `source="branch_line"`.
   - This matches both `k3d-manager-v1.42.0` and `target **v1.44.0**`.
   - A doc that names a target release counts toward that target. This is intended.
2. Otherwise use `added_release`, which the caller computes (below):
   - `source="added_tag"` when it came from a tag;
   - `source="added_branch"` when it came from the current branch.
3. Otherwise return `("unknown", "unknown")`.

`added_release` is computed once per run in `bug-tally.py`, not per doc:
- One pass of `git log --diff-filter=A --name-only --format=%H <ref> -- docs/bugs/` gives the
  commit that first added each path. Use the oldest commit when a path was added more than once.
- For each distinct commit, the release is the lowest `v[0-9]*` tag that contains it, in version
  order. Cache the result per SHA. main is squash-merged, so a doc's add commit on main is the
  squash commit, which that release's tag contains.
- If no tag contains it and the ref's branch name matches `k3d-manager-v(\d+\.\d+\.\d+)`, use that
  version, giving `added_branch`. This covers the release in progress.
- Otherwise the result is `None`.

**CLI:**
```
scripts/bug-tally.py [--ref REF] [--release vX.Y.Z] [--json]
```
- Scope: `docs/bugs/*.md`, top level only, with archive excluded. This is the same scope as item 5.
- `--ref` defaults to `K3DM_INDEX_REF` if set, otherwise `HEAD`.
- Text output, one block per release, newest first, or only the `--release` one:
  ```
  v1.42.0  total 35 · closed 24 · open 3 · unknown 8   (branch_line 27, added_branch 8)
    open:    <path> [P1]
    unknown: <path>
  ```
  - List open and unknown paths. Never list closed ones.
  - `unknown` means the doc has no Status line. Print it as its own number; never fold it into
    open or closed.
- `--json` output: `{"ref":…, "generated_at":…, "releases": {"v1.42.0": {"total":…, "closed":…,
  "open":…, "unknown":…, "by_source": {…}, "by_priority": {…}, "open_paths": […], "unknown_paths": […]}}}`.
  - `by_priority` has one key per `P0`–`P3` plus `unset`, always all five, each
    `{"total":…, "closed":…, "open":…, "unknown":…}`, from `doc_meta`.
  - `open_paths` and `unknown_paths` entries are `{"path":…, "priority":…}`.
- `--priority P0..P3` limits the text output to that priority, and prints
  `(<n> docs in this release have no Priority line)` from `by_priority.unset.total`.
- Exit codes: 0 on success; 2 if any doc fails to read or parse. On exit 2 it prints nothing to
  stdout, so a partial count is never shown.
- `make bug-tally` passes `RELEASE=` and `JSON=1` through to the script.

Release is **not** added as a Prometheus label in item 5. There are 40+ releases, which would
multiply the cardinality. The Grafana panels stay as specified.

### 9. Route counting questions to the tally: `ask`, `ask gemini` and `ask codex`

A new module, `scripts/lib/webhook/bug_count.py`:
- `match(question) -> CountQuery | None`, where `CountQuery` is a `NamedTuple(release, priority, state)`.
  It returns `None` unless the question has both:
  - a count word: `how many`, `count`, `number of` or `tally`;
  - the word `bug` or `bugs`.

  The other fields are optional qualifiers, never requirements:
  - `release`: the first `v?\d+\.\d+\.\d+`, normalised to a leading `v`; `"*"` (all releases) if absent.
  - `priority`: the first `\bP[0-3]\b` (case-insensitive, normalised upper); `None` if absent.
  - `state`: `"open"` for `open`/`outstanding`, `"closed"` for `fixed`/`closed`/`resolved`/`verified`;
    `None` if absent.

  The regexes are compiled at module level.

  **Why no state word is required (2026-10-09).** The first draft required one. The operator then
  asked `/ask-docs how many P1 bugs we have in v1.42.0 branch`, which has no state word. It went to
  retrieval, and the model answered from this spec's own stale "none has a priority" sentence:
  "the data is insufficient". The real answer was 3 P1 docs in v1.42.0, all closed. Any count
  question about bugs must reach the tally.
- `reply(query) -> str` runs `bug-tally.py --json` through `proc._spawn_capture_text` (the existing capture
  helper), with `--ref` set to the webhook's `K3DM_INDEX_REF`, or `HEAD`, and a 30s timeout. It
  formats a Slack answer, for example:
  `v1.42.0: 35 bug docs — 24 fixed, 3 open, 8 with no Status line.`
  - With `query.priority`, the counts come from `by_priority[<p>]`, and the open list holds only that
    priority. Example: `v1.42.0: 3 P1 bug docs — 3 closed, 0 open, 0 with no Status line.`
    Always add `<n> docs in v1.42.0 have no Priority line, so they are not counted here.` when
    `by_priority.unset.total > 0`. Without it, the count looks complete when it is not.
  - With `query.state`, lead with that number (`3 open`). Still show the other two.
  The answer:
  - names the open docs as links, using `ask_docs._doc_link`;
  - names at most 10 unknown docs;
  - ends with `_Counted from docs/bugs/ at <ref>; release = Branch: line, else the release the
    doc was added in._`

  On a non-zero exit or a timeout, it returns
  `Could not count bugs — tally failed (<exit code or timeout>).` It never falls back to a model.
- Wiring:
  1. In `ask_docs.answer`, after `_sanitize_question`, `query = bug_count.match(question)`.
     If it is not `None`, return `_reply(bug_count.reply(query), [], scrub_prose=False)`
     **before** retrieval, and before the recency path's `_recent_docs`.
  2. In `agent._run_cluster_ask`, after the injection check (just after
     `question = _q_stripped`), the same check applies for every agent (claude, gemini and codex).
     On a match it calls `_finish(bug_count.reply(query))` and returns **without spawning the
     agent CLI**. The reply is prefixed with `📊 Counted, not asked (<agent> was not consulted):`
     so the user can see why the named agent did not answer.
- Only counting questions are intercepted. "Which open bug is most urgent?" or "what is
  bug X about" do not match, because there is no count word. Those keep their current paths.

## What NOT to Do
- Do NOT create a PR, commit to `main`, or use `--no-verify`.
- Do NOT change `search()`'s return shape, `content_hash` semantics, or the embedded text. A
  priority edit should cost at most one re-embed, of that one doc.
- Do NOT run `make index-docs` against the live store, `make test`, or `make e2e`. Do NOT
  push to a real Pushgateway.
- Do NOT backfill or edit existing bug docs.
- Do NOT put doc paths or titles in metric labels.
- Do NOT let a model produce or "correct" a bug count; a failed tally reports the failure.
