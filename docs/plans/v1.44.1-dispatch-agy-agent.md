## Problem

`agy models` lists `gemini-4-argon-low`, `-medium` and `-high`. The operator wants to try Argon on
k3d-manager specs and compare it with Luna (Codex). Two gaps block that:

1. **`bin/k3dm-codex-dispatch` runs only `codex exec`.** Running `agy` by hand records nothing on the
   dispatch dashboard, and the operator needs that data for research ("please don't by pass tool. I
   need data for research purpose").
2. **`scripts/plugins/gemini.sh` hardcodes retired models.** It lists `gemini-3.5-flash-medium`,
   `gemini-3.6-flash-medium` and `gemini-3.1-pro-low`, and none of them is in `agy models` on
   2026-10-24. This is the same model-name drift recorded before.

## Fix

### F1. An `--agent` option on `start`

- `bin/k3dm-codex-dispatch start --spec PATH [--agent codex|agy] [--model ID]`. The default stays `codex`.
- The worker runs `agy` in print mode:
  `agy --print --output-format json --model "$model" --sandbox --add-dir "$run/state" --dangerously-skip-permissions`.
  The prompt comes from `"$run/prompt.md"` on stdin or as the argument, whichever `agy` accepts (check `agy --help`; do not guess).
  The output goes to `"$run/agy.log"`.
- The default model is `gemini-4-argon-medium`.
- Before launch, `--model` is checked against the output of `agy models`. An unknown ID fails with
  `unknown agy model` and the list. This is the drift guard; never hardcode a fallback list.
- The prompt is the same as Codex's.
- `agy` has no read-only `.git`, so after exit the worker checks the task branch:
  - **A commit was made:** `HEAD` no longer equals `"$run/base"`. The worker writes a `scope_violation` ledger event and `status` shows `VIOLATION: agent committed`.
  - **The tree is unchanged:** `land` still works from it, as it does for Codex.
- `resume` with `--agent agy` uses `agy --conversation <id>` when the first run returned an ID.
  Otherwise it fails with a clear message. `--continue` is never used, because it picks the most recent conversation, which may not be this task's.
- `--network` is refused for `agy` in this plan.

### F2. Ledger and metrics carry the agent

- The `start` ledger event gains `"agent"` and `"model"`.
- `codex_exit` and `codex_usage` keep their names for Codex. `agy` writes `agent_exit` and
  `agent_usage`, and `usage` is filled from the JSON output's usage fields if present, otherwise null.
  Do not invent a token count.
- `bin/k3dm-dispatch-metrics` adds an `agent` label to every per-spec series. A ledger event with no
  `agent` field means `codex`, so the existing history keeps its numbers.

### F3. Side-by-side runs

- The same spec may be dispatched to both agents with different slugs, for example
  `--slug <slug>-agy`.
- `land` refuses to land a second slug for the same spec while the first is landed, unless
  `--superseding <slug>` is given. Only one implementation of a spec reaches the release branch.
- The ledger records the landed one as `chosen=true`.

### F4. `gemini.sh` model list

- Replace the hardcoded model list in `scripts/plugins/gemini.sh` with a read of `agy models`. Prefer
  `gemini-4-argon-*`, then the newest `gemini-*-flash-*`.
- Update `scripts/tests/plugins/antigravity.bats` to stub `agy models`.

### F5. Make targets, dashboard, docs

- `make codex-dispatch SPEC=... AGENT=agy MODEL=...`. `AGENT` and `MODEL` are optional.
- The agent dispatch dashboard gets an `agent` variable, and the Per spec table gets an Agent column.
  Each stat panel can be split by agent.
- `docs/guides/grafana-dashboards/k3dm-agent-dispatch.md` and the dispatcher's how-to describe the
  agy path and the side-by-side workflow.

## Tests

`scripts/tests/bin/codex_dispatch.bats`. Fake `agy` and `codex` binaries come through `K3DM_AGY_BIN` and `K3DM_CODEX_BIN`; there are no real calls:

1. `--agent agy` runs the fake `agy` with `--model gemini-4-argon-medium` and `--sandbox`. The ledger `start` event has `agent=agy`.
2. An unknown `--model` fails before a worktree is created.
3. A fake `agy` that commits gives `scope_violation`, and `land` refuses.
4. With no `--agent`, the fake `codex` runs with the same arguments as before (byte-compare the argv).
5. Side by side: the second `land` for the same spec is refused without `--superseding`.
6. Metrics: history with no `agent` field exports `agent="codex"`, and its values match the pre-change exporter on the same fixture.
7. `gemini.sh`: the model list comes from the stubbed `agy models`. No ID from the old hardcoded list appears in the source.
