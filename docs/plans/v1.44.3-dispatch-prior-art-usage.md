## Problem

The retrieval quality probe measures whether search can return relevant, current documents. It does not establish whether a dispatched agent consulted a result. The dispatcher records task lifecycle events, but `scripts/find-similar-docs.py` records no lookup event. Without a link between task, lookup, and later task activity, Agent Dispatch cannot distinguish whether prior art was available, read, or cited.

These are distinct signals: a ledger lookup proves what the retriever returned; an agent-reported read is self-reported evidence; a commit citation records an explicit reference; and any relationship to rework or verification is correlation, not causation.

## Scope

For dispatcher-launched tasks, make a best-effort prior-art lookup part of dispatch, record returned candidates, ask the agent to report which it read, record citations at land, and show aggregate usage on Agent Dispatch by release. Dispatch continues if retrieval is unavailable.

This plan does not change retrieval ranking or corpus scope, claim use from retrieval alone, observe agent tool calls, or instrument tasks launched outside the dispatcher. It does not parse `~/.codex` or other private agent session files; that requires separate operator approval.

## Design

### D1. Lookup event and prompt context

At `codex-dispatch`, run existing `scripts/lib/hermes/prior_art.py::search` against the spec's Problem text, exclude the current spec, and return up to five candidate paths with scores and indexed corpus revision. Add concise candidate paths/titles to the prompt as advisory context.

Append one `prior_art` ledger event tied to the task, containing candidates, scores, indexed revision, and timestamp. If lookup is unavailable or deliberately skipped, record that state with a bounded reason. Empty/unavailable lookup never blocks dispatch. Do not store raw query text. Retrieval is not evidence that an agent read a result.

### D2. Agent-reported reads

Give Codex, Luna, agy, and vendor-LLM trials the same prompt contract: report a `Prior-art-read:` section listing candidate paths actually consulted, or `none`. Validate paths against that task's lookup candidates. Unknown paths are excluded and their validation outcome recorded. An omitted section is `unreported`, not `none`.

This signal is self-reported. Do not infer reads from prompt inclusion, shell history, filesystem access, or task success. Do not parse session files or widen the session exporter.

### D3. Landed references

Accept an optional `Prior-art:` commit trailer listing repository-relative document paths. At `codex-land`, validate paths against that task's lookup candidates and record citations plus validation outcome. Missing trailer means `none`; malformed or non-candidate paths are not counted. Invalid telemetry must not block land.

### D4. Metrics and dashboard

Add a **Release knowledge usage** row to Agent Dispatch, filtered by the selected release Window. Show:
- successful lookups / eligible dispatched tasks, plus unavailable and skipped counts by reason;
- candidate, agent-reported-read, and landed-citation counts;
- landed task count and verify-pass rate split by cited / not cited;
- resume/rework rate split by cited / not cited.

Show denominator `n` beside every rate. Missing or unreported signals remain missing; do not backfill historical tasks as zero or uncited. Document that outcome comparisons are observational correlation, release volume is a few tasks a week, and neither group supports conclusions below 30 tasks.

This belongs on Agent Dispatch because the contract covers dispatched tasks and follows release Window. Keep paths and query text out of Prometheus labels; detailed paths and scores stay in JSONL. Use bounded release/task labels.

### D5. Parity and failure handling

Use one event schema and prompt contract for Codex, Luna, agy, and vendor-LLM. Lookup failure records a state and continues. Malformed reports or trailers do not block dispatch, completion, or land; record validation failure and exclude them from counts. Use existing ledger append/locking helpers for concurrent events.

## Tests

Use synthetic ledgers and isolated fixtures; never write to the real dispatch ledger or query live VectorDB.

1. Dispatch records task identity, candidates, scores, revision and timestamp, and supplies advisory results in the prompt.
2. Current spec is excluded; empty results differ from unavailable.
3. Unavailable and skipped states have bounded reasons and dispatch still succeeds.
4. Every supported agent receives the same reporting contract and event schema.
5. Valid reads are recorded; `none`, omitted/unreported, malformed, and unknown paths stay distinct; unknown paths do not count.
6. Valid `Prior-art:` trailers record candidate citations; absent, malformed, and non-candidate paths do not block land.
7. Synthetic exporter data produces lookup, retrieved/read/cited counts, denominators, and cited/uncited resume and verify rates for selected release.
8. Missing history fabricates no zero, none, or uncited values; time-window behavior is unchanged.
9. Metrics contain no path/query labels; dashboard panels follow release Window and show `n`.
10. Concurrent appends preserve valid JSONL and task association.

Show lookup, nonblocking-unavailable, report validation, trailer validation, historical missingness, and bounded-label cases red against pre-change code or focused test doubles.
