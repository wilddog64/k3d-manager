## Why

On 2026-09-24 `shopping-cart-payment`'s aggregate `/actuator/health` was returning **HTTP 503**
and had been for an unknown length of time. Every monitoring surface we own read green:

| Surface | What it saw | Why |
|---|---|---|
| Kubernetes | pod `1/1 Running`, in the Service | polls only `/actuator/health/liveness` and `/readiness`, both `UP` |
| ArgoCD | `Healthy` | derives from the pod, which is Ready |
| Hermes `argocd` sensor | healthy | reads ArgoCD |
| Hermes `node_pressure` sensor | healthy | reads nodes and pod phase |
| Prometheus / Alertmanager | silent | nothing scrapes the aggregate endpoint |

The cause was a mis-nested YAML key putting `rabbitmq:` at column 0 instead of under `spring:`,
so Spring Boot's `RabbitHealthIndicator` targeted `localhost:5672` and failed. **That indicator is
in neither probe group.** The aggregate endpoint went `DOWN`; the groups stayed `UP`; and because
Kubernetes only ever polls the groups, nothing anywhere noticed.

The only thing that caught it was an e2e assertion — days later, as an opaque
`Expected: "UP" / Received: "DOWN"` string mismatch that took a full manual investigation to
attribute.

### The generalisation — this is the point of the sensor

Do not build a RabbitMQ check. The defect class is:

> **the aggregate health endpoint disagrees with the probe groups Kubernetes actually polls.**

Whenever `aggregate != UP` while `liveness == UP` and `readiness == UP`, a real component is
broken *and, by construction, no orchestration-level signal can ever fire*. That delta is
precisely the set of failures our stack is blind to. It is cheap to measure, has no false-positive
story (the pod is genuinely serving while genuinely reporting a broken dependency), and it
generalises across every Spring service we run, present and future.

The inverse case — aggregate `DOWN` **and** a group `DOWN` — needs no new sensor. The pod goes
unready, ArgoCD degrades, and the existing `argocd` sensor fires. The new sensor must report that
case as healthy-for-its-own-concern and say so in its detail, so a reader is never misled into
thinking it is the only health signal.

## S1 — `app_health` in `scripts/lib/hermes/sensors.py`

A pure sensor in the established shape: caller injects the transport, the sensor builds real argv,
returns `record(...)`, and never raises.

Add near `status_checks` (the other sensor that reads a cluster substrate):

```python
APP_HEALTH_PROBE_GROUPS = ("liveness", "readiness")


def _health_payload(run, context, namespace, service, port, path):
    """Read one actuator endpoint through the API server's service proxy."""
    proxy = f"/api/v1/namespaces/{namespace}/services/{service}:{port}/proxy{path}"
    code, output = run(["kubectl", "--context", context, "get", "--raw", proxy], {})
    if code != 0 or not output:
        return None
    payload = json.loads(output)
    return payload if isinstance(payload, dict) else None


def _health_delta(run, context, target):
    """Return (delta_detail, down_components) for one service; delta_detail is '' when none."""
    namespace = target["namespace"]
    service = target["service"]
    port = target["port"]
    aggregate = _health_payload(run, context, namespace, service, port, "/actuator/health")
    if aggregate is None or not aggregate.get("status"):
        raise ValueError(f"{service}: aggregate health unavailable")
    if aggregate["status"] == "UP":
        return "", []
    groups = {}
    for group in APP_HEALTH_PROBE_GROUPS:
        payload = _health_payload(run, context, namespace, service, port,
                                  f"/actuator/health/{group}")
        if payload is None or not payload.get("status"):
            raise ValueError(f"{service}: {group} group unavailable")
        groups[group] = payload["status"]
    if any(value != "UP" for value in groups.values()):
        return "", []
    components = aggregate.get("components") or {}
    down = sorted(name for name, body in components.items()
                  if isinstance(body, dict) and body.get("status") not in (None, "UP"))
    return f"{service} aggregate {aggregate['status']} while both probe groups UP", down


def app_health(run, state, targets=None, context="", threshold=2):
    """Flag services whose aggregate health disagrees with the probe groups k8s polls."""
    if not targets:
        return record("app_health", "unknown", "no app health targets configured")
    if not context:
        return record("app_health", "unknown", "no app cluster context configured")
    deltas, down = [], {}
    try:
        for target in targets:
            detail, components = _health_delta(run, context, target)
            if detail:
                deltas.append(detail)
                down[target["service"]] = components
    except Exception:
        return record("app_health", "unknown", "app health source unavailable")
    if not deltas:
        _debounced("app_health", False, threshold, state)
        return record("app_health", "healthy",
                      f"{len(targets)} service(s) agree with their probe groups "
                      "(a group-visible outage is covered by the argocd sensor, not this one)")
    status = "degraded" if _debounced("app_health", True, threshold, state) else "healthy"
    detail = "; ".join(deltas[:3])
    if len(deltas) > 3:
        detail = f"{detail} (+{len(deltas) - 3} more)"
    return record("app_health", status, redact(detail),
                  data={"deltas": [redact(item) for item in deltas],
                        "down_components": {key: [redact(name) for name in value]
                                            for key, value in down.items()}})
```

Design points that are **not** negotiable, each for a stated reason:

- **The service proxy, not a port-forward.** `kubectl get --raw
  /api/v1/namespaces/…/services/<svc>:<port>/proxy/actuator/health` is one read-only API-server
  call, needs no listening socket on the laptop, and cannot leave a stale LaunchAgent behind.
  A port-forward is exactly the mechanism that silently broke the Pushgateway metrics for 64 days.
- **`raise` inside the loop, caught once and mapped to `unknown`.** A sensor must never report
  `healthy` because it could not measure. `unknown` is the honest third state and the correlator
  already understands it. Do not swallow per-service errors and continue — a partial sweep
  reported as healthy is a false green.
- **Both groups are fetched only when the aggregate is not `UP`.** In the healthy case that is one
  call per service, so the sensor costs almost nothing on a normal poll.
- **`redact(...)` on every string that reaches a record.** Health payloads can carry hostnames,
  usernames and broker URLs. `redact` is already imported in `sensors.py` from `e2e_triage`.
- **`_debounced` with `threshold=2`**, matching `eso` and `node_pressure`. A single 503 during a
  rollout must not page anyone.

## S3 — `scripts/lib/hermes/app_health_triage.py` (new)

A pure module mirroring `status_triage.py` exactly in shape — same `classify`/`triage` split, same
`group_slug` use, same redaction at the boundary. It turns the sensor's `data` into bug-filing
groups.

```python
"""Pure, rule-based triage for Hermes app-health deltas."""

from hermes.e2e_triage import group_slug, redact

_KIND = "health-probe-gap"


def triage(down_components):
    """One group per service whose aggregate health disagrees with its probe groups."""
    groups = []
    for service in sorted(down_components or {}):
        components = [redact(name) for name in (down_components[service] or [])]
        target = redact(service)
        groups.append({
            "kind": _KIND,
            "target": target,
            "slug": group_slug(_KIND, target),
            "count": len(components) or 1,
            "titles": [{"file": name, "title": f"{name} reports DOWN"} for name in components[:10]],
            "samples": [f"aggregate /actuator/health is not UP while liveness and readiness are UP; "
                        f"DOWN component(s): {', '.join(components) or 'not reported'}"],
        })
    return groups
```

The `titles`/`samples`/`count` keys are the contract `e2e_bugs._lines` and `file_bugs` already
consume. Match them exactly — do not invent a new group shape.

**`group_slug` hardcodes an `e2e-` prefix** (`e2e_triage.py:106-109`:
`f"e2e-{kind}-{target}"`). So the filed doc will be named
`YYYY-MM-DD-e2e-health-probe-gap-payment-service.md`, which reads oddly for a sensor that has
nothing to do with e2e. **Leave it alone.** `status_triage` already carries the same prefix, so the
oddity is pre-existing and consistent. Changing `group_slug` would change the slug of every
existing bug doc, and `file_bugs` dedups by globbing `*-{slug}.md` — every open doc would stop
matching and Hermes would file a duplicate of each one. If the prefix is worth fixing it is its own
task with a rename migration, not a drive-by edit here. Note it in your report; do not act on it.

must stay unset until its own live verification.

### Bug filing

In the poll path, after the cycle, file only on a **debounced degrade** — never on the first
sample:

```python
def _file_app_health_bugs(records, slot):
    health = next((item for item in records if item.get("sensor") == "app_health"), None)
    if not health or health.get("status") != "degraded":
        return None
    groups = app_health_triage.triage((health.get("data") or {}).get("down_components"))
    if not groups:
        return None
    return e2e_bugs.file_bugs(ROOT, groups, {"source": "app-health", "run_id": slot}, slot)
```

The record keys are confirmed against `hermes/records.py::record`: `sensor`, `status`, `evidence`,
`sampled_at`, `data`. Note that `evidence` is **truncated to 200 characters** by `record`, which is
why the full per-service delta list also goes into `data["deltas"]` — the triage step in S5 must
read `data`, never parse `evidence`.

Call it from `_poll` alongside the existing status-triage filing, and fold its return into the
Slack summary the same way. `file_bugs` already refuses to act unless the repo is on a
`k3d-manager-v<x.y.z>` branch, already dedups by slug, and already only reopens docs whose status
is `FIXED`/`CLOSED` — so a persistent delta produces **one** doc, not one per poll. Do not add
your own dedup on top; verify the existing one covers it and say so in your report.

## Tests — `scripts/tests/hermes/test_app_health.py` (new)

**No test may stub the thing it measures.** `scripts/tests/hermes/test_alert_delivery.py` was 8/8
green while the probe it claimed to cover was never executed, because it injected a stubbed `run`
at the wrong seam. Here the injected `run` is the **transport** — the network boundary — and the
classification logic under test is real, imported, and never stubbed.

Build a fake `run` that maps a proxy path to a canned `(code, json)` pair.

1. **`test_delta_is_degraded_after_debounce`** — aggregate `DOWN`, both groups `UP`. First call
   returns `healthy` (debouncing), the third returns `degraded`, and the detail names the service.
   This is the payment defect, reproduced.
2. **`test_down_components_are_reported`** — aggregate `DOWN` with
   `components: {rabbit: {status: "DOWN"}, db: {status: "UP"}}`; assert `data["down_components"]`
   is `{"payment-service": ["rabbit"]}` — `rabbit` present, `db` absent.
3. **`test_group_visible_outage_is_not_this_sensors_concern`** — aggregate `DOWN` **and**
   readiness `DOWN`; assert `healthy`, and that the detail mentions the `argocd` sensor. This is
   the test that stops someone widening the predicate into a duplicate of existing coverage.
4. **`test_all_up_is_healthy_with_one_call_per_service`** — aggregate `UP`; assert `healthy` and
   that the fake `run` was called **exactly once** (the group endpoints were not fetched).
5. **`test_unreachable_aggregate_is_unknown_not_healthy`** — transport returns `(1, "")`; assert
   `unknown`. Then the same for malformed JSON, and for a `200` with no `status` key.
6. **`test_missing_group_endpoint_is_unknown`** — aggregate `DOWN` but `/liveness` returns
   `(1, "")`; assert `unknown`, **not** `degraded`. Guessing a delta from an unmeasured group
   would file a bug on no evidence.
7. **`test_one_bad_service_does_not_mask_the_others`** — two targets, the second unreachable;
   assert `unknown`. A partial sweep must never report healthy.
8. **`test_no_targets_and_no_context_are_unknown`** — `targets=[]`, and targets set with
   `context=""`; both `unknown`. This is the default-off path.
9. **`test_triage_produces_a_stable_slug`** — `app_health_triage.triage` on the same input twice
   yields the same `slug`; two services yield two groups sorted by service name. A slug that
   varies would defeat `file_bugs`' dedup and file a fresh doc every poll.
10. **`test_app_health_doc_names_the_component_and_the_gap`** — call `e2e_bugs._doc` with
    `{"source": "app-health"}` and assert the text contains the component name, the phrase about
    probe groups being UP, and the `2026-09-16` precedent path. Assert **meaningful tokens**, not
    whole rendered lines — whole-line assertions rot.
11. **`test_commit_subject_says_app_health`** — the `source` used by `_commit_push` for an
    `app-health` run is `app-health`, not `e2e`.

Also append to `scripts/tests/hermes/test_hermes.py` if it asserts the sensor roster or the
`records` length — find out whether it does and keep it truthful rather than adding a parallel
assertion.
