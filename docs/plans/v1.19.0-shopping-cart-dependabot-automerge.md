## Change — add one workflow file per repo

Create **`.github/workflows/dependabot-automerge.yml`** (identical in all 5 repos — the logic is
language-agnostic; it keys off Dependabot metadata, not the ecosystem):

```yaml
name: Dependabot auto-merge

on: pull_request_target

permissions:
  contents: write
  pull-requests: write

jobs:
  automerge:
    # only Dependabot's own PRs
    if: ${{ github.actor == 'dependabot[bot]' }}
    runs-on: ubuntu-latest
    steps:
      - name: Fetch Dependabot metadata
        id: meta
        uses: dependabot/fetch-metadata@d7267f607e9d3fb96fc2fbe83e0af444713e90b7 # v2.3.0
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}

      - name: Enable auto-merge for minor/patch and security updates
        # semver-minor OR semver-patch, OR any PR flagged as a security update
        if: >-
          steps.meta.outputs.update-type == 'version-update:semver-minor' ||
          steps.meta.outputs.update-type == 'version-update:semver-patch' ||
          steps.meta.outputs.alert-state == 'OPEN'
        run: gh pr merge --auto --squash "$PR_URL"
        env:
          PR_URL: ${{ github.event.pull_request.html_url }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

**Behaviour**
- `--auto` waits for the required status checks (already configured) to pass, then squash-merges.
  If CI fails, the PR stays open — no forced merge.
- Majors (`semver-major`) fall through the `if` → left open for review.
- Security updates (`alert-state == 'OPEN'`) auto-merge regardless of semver bump — closing the
  CVE loop hands-off. (Confirm this is desired; a security major will auto-merge. If you want
  security-majors reviewed too, add `&& steps.meta.outputs.update-type != 'version-update:semver-major'`.)

## Notes / gotchas

- `pull_request_target` (not `pull_request`) is required so `GITHUB_TOKEN` has write scope on
  Dependabot PRs. Because it runs in the base-repo context, the job **must not** check out or
  execute PR head code — this workflow only calls `gh`/metadata, so it is safe. Do NOT add a
  `checkout` of `github.event.pull_request.head.sha` here.
- `GITHUB_TOKEN`-driven `--auto` merges do not re-trigger downstream `on: push` workflows in some
  setups; the deploy pipelines here run on `main` push and are unaffected (they already run
  post-merge). Confirm a deploy fires after the first auto-merge.
- Pin `dependabot/fetch-metadata` to the SHA above (v2.3.0) per supply-chain rule — no `@v2`.
- One file per repo, no other files touched.
