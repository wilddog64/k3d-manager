## Why

A lab that is not shopping-cart (the dirused Windows rehearsal, a future project) needs only machines. Today `make up` always builds k3s plus the hub, Vault, ArgoCD, observability and shopping-cart.

With `make up CLUSTER_PROVIDER=k3s-aws APP=none`, the same command gets the ACG sandbox, launches the nodes and starts the TTL watcher. It prints how to SSH to each node and stops.

## Proof of external behaviour (Make)

Probed on m4-air, GNU Make 3.81 (`/usr/bin/make`), 2026-11-20, with a scratch 9-line Makefile.

The rule used `ifeq ($(origin APP)$(APP),command linenone)` to pick `up: up-nodes`, else the normal recipe. Results:
- `make up APP=none` ran the `up-nodes` recipe.
- `make up` ran the default recipe, with the environment `APP` empty.
- `APP=none make up`, from the environment, ran the **default** recipe, so a stray exported APP is ignored.
- `make up "APP=x'y"` ran the default recipe, and the recipe saw `$APP` = `x'y` in its environment. A command-line value reaches the recipe as an environment variable, so a script can read it without Make pasting it into shell text.
- Each recipe line is its own shell (no `.ONESHELL`). Recipe lines after the first still run when the first exits 0.

## Behaviour

### 1. Makefile

- Wrap the existing `up:` rule (`Makefile:170-183`) in a Make conditional:

  ```make
  ifeq ($(origin APP)$(APP),command linenone)
  up: up-nodes
  else
  up:
  	@bin/k3dm-up-app-check "$(CLUSTER_PROVIDER)" "$(origin APP)"
  	<existing up recipe, byte-identical>
  endif
  ```

  - Under none, the existing recipe does not exist. `observability`, `platform-ops` and the k3d pushgateway lines (`Makefile:179-183`) never run.
  - On the default path, the existing lines are byte-identical; the only change is one new first line.
- New target `up-nodes` (also callable directly, for scripts): `@bin/acg-up-nodes "$(CLUSTER_PROVIDER)" "$(URL)"`. Its help line says it is what `make up APP=none` runs.
- Do **not** add a top-level `APP ?=`, `APP :=` or `APP =`. `APP` is the required argument of `fix-restart`, `fix-delete-pod`, `fix-sync` and `fix-force-sync` (`Makefile:1464-1484`). It is unaffected, because the conditional only changes the `up` rule.
- `make help` for `up` mentions `APP=none`.

### 2. `bin/k3dm-up-app-check <provider> <origin-of-APP>` (new, `set -euo pipefail`, under 40 lines)

It runs only on the default path. It reads the value from the environment variable `APP`, never from its arguments.
- When the origin is `command line` and `APP` is not `shopping-cart`: exit 2 with `APP must be 'shopping-cart' or 'none'`. `none` never reaches this script.
- When the origin is anything else: ignore `APP`.
- **Resume refusal.**
  - When `K3DM_RESUME=1` and the bare-nodes marker (§3) exists for the provider: exit 2 with `the last make up was APP=none; resume does not apply — run make up CLUSTER_PROVIDER=<p> APP=none again, or make down first`.
  - This is what the Slack resume hits: `scripts/lib/webhook/lifecycle.py:490` runs `make up CLUSTER_PROVIDER=… K3DM_RESUME=1`. It exits non-zero, so lifecycle's post-success hooks (`:508-513`) do not run.
- **Fresh default run.** When `K3DM_RESUME` is not 1 and `DRY_RUN` is not 1, remove the marker. The full build that follows replaces the bare nodes' role.
- Otherwise exit 0, printing nothing.

### 3. `bin/acg-up-nodes <provider> [sandbox-url]` (new, `set -euo pipefail`)

Source the same libraries `bin/cluster-up` sources for the k3s-aws path, and nothing app-related.

- **Provider check.** Anything other than `k3s-aws` exits 2 with `APP=none is supported on k3s-aws only`.
- **Refuse over a live full cluster.** If `k3s-aws` is recorded active (the record written by `_acg_record_provider`, `bin/cluster-up:2057`; removed by `bin/cluster-down:196-197`), exit 2 with `k3s-aws already has a full make up; run make down first`.
- **Order of steps.** No checkpoints; every run does all of them. Reusing a healthy stack makes a rerun cheap.
  1. The same sandbox sign-in prompt as `bin/cluster-up` (`:470-487`), shown under the same condition.
  2. Credentials: the k3s-aws branch of Step 1 (`bin/cluster-up:534-545`). It calls the same functions, so copying those ~10 lines is acceptable.
  3. `k3s_aws_provision_nodes --confirm` (§4).
  4. TTL watcher: `acg_watch_start "${sandbox_url:-${_ACG_SANDBOX_LIST_URL}}"`.
     - On macOS, a non-zero return, or the launchd job not listed by `launchctl list "${_ACG_WATCH_LAUNCHD_LABEL}"` afterwards, is a failure (exit 1). There is no in-shell fallback, unlike `bin/cluster-up:1914-1927`.
     - With `K3DM_AGENT_LOAD=0`, print `watcher install deferred (K3DM_AGENT_LOAD=0)` and continue.
  5. Write the marker `${_ACG_STATE_DIR}/bare-nodes`. Use the same state-dir helper as `bin/cluster-up:105`; the content is a timestamp.
  6. Clear the CloudFormation ownership marker the same way `_acg_up_clear_stack_marker` does (`bin/cluster-up:336`). Call that function if it can be sourced; otherwise copy its body, and say which.
  7. Summary. Read `ServerPublicIP` and `Agent*PublicIP` from the stack outputs (`aws cloudformation describe-stacks`, the same query as `acg.sh:197-200`), whether or not the stack was just created.
     - For each node, wait with `_ubuntu_k3s_wait_ssh_ready` (`scripts/plugins/shopping_cart.sh:1169`), using the key in `_ACG_KEY_PEM`.
     - Print one line per node: `server|agent<N>  <ip>  ssh ubuntu|ssh ubuntu-<N>`. The aliases are written by `acg_provision` (`acg.sh:320-325`).
     - A node that does not become reachable is a failure (exit 1). The line still prints, marked `unreachable`.
- **Not done here:**
  - no deployment metric;
  - no `_acg_record_provider`, so `cluster-status` does not show a bare stack as a live cluster (Known limits);
  - no tunnel, Docker check, hub, Vault, ArgoCD or app step.
- **DRY_RUN=1.** Run the provider check and the refusal check. Then print `DRY_RUN: would provision nodes / start watcher / write marker / print summary`. Make no AWS call, launchctl call or state write.
- Log prefix `[acg-up-nodes]`, and a `-h|--help` text.

### 4. `k3s_aws_provision_nodes` (in `scripts/lib/providers/k3s-aws.sh`)

- Extract the pre-flight TTL extend and the CloudFormation create/reuse/recreate block (`k3s-aws.sh:213-238`) into `_k3s_aws_ensure_stack`.
  - It returns 1 on the same three failure exits.
  - It sets `_K3S_AWS_STACK_ACTION` to `reused`, `recreated` or `created`.
  - `deploy_cluster` calls it, with its behaviour and log lines unchanged.
- `k3s_aws_provision_nodes`:
  - repeats the `ACG_AGENT_COUNT` check (`:206-210`);
  - calls `_k3s_aws_ensure_stack`;
  - on `reused`, warns `reusing existing stack — nodes may still have k3s from an earlier make up; run make down first for clean nodes`;
  - never calls `deploy_app_cluster`, labels nodes or merges a kubeconfig;
  - has `-h|--help`.

### 5. Docs

The README section on `make up` gets one paragraph covering:
- what `APP=none` gives you and what it leaves out;
- that it is k3s-aws only;
- that resume does not apply;
- the follow-on plan;
- the Known limits.

### Known limits (record, do not fix)

- `make refresh` after `APP=none` fails at its k3s steps. It has no app-awareness yet (follow-on plug-in plan).
- `make down` after `APP=none`:
  - deletes the stack as today;
  - may warn about hub deregistration when the hub is down;
  - does not stop the launchd TTL watcher, which is existing behaviour for every run;
  - may return non-zero from `docker system prune` (`bin/cluster-down:434`) when Docker is installed but not running.

  Claude files the last two as a `docs/bugs/` capture, because they also affect full runs.
- `cluster-status` and `require-unambiguous-provider` do not see a bare stack as an active provider.
- Fresh Slack `/acg-up` always builds shopping-cart.
