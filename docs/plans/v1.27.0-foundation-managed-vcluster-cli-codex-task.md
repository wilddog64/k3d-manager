## Part A — lib-foundation `foundation_ensure_vcluster_cli` — do all of it, then STOP

Add one public entry point plus private helpers in `scripts/lib/system.sh`. Public function:
**no** underscore prefix; private helpers: `_` prefix.

### A1 — Public contract: `foundation_ensure_vcluster_cli <version>`

- Single argument: the exact vCluster version **without** a `v` prefix (e.g. `0.20.0`).
- **Validate first, fail closed:** reject a missing/empty/malformed version (anything not
  `<major>.<minor>.<patch>` numeric-dotted) with a clear `_err` and non-zero exit **before** any
  filesystem write or network call. No writes on rejection.
- On success, print **only** the absolute path of the verified managed executable on **stdout**.
  All progress/diagnostics go to **stderr**.
- This function is the **sole supported installer/verifier** for vCluster. It must not call
  `brew`, `apt`, `dnf`, `npm`, or `pip`.

### A2 — Managed location + platform/arch resolution

- Managed path: `${XDG_DATA_HOME:-$HOME/.local/share}/lib-foundation/vcluster/<version>/vcluster`.
- Resolve the release asset from `uname -s` / `uname -m` to the Loft naming
  (`darwin|linux` × `arm64|amd64`, e.g. `vcluster-darwin-arm64`). **Note:** existing
  `_detect_platform` (line 751) returns a *family* token (`mac|wsl|debian|redhat|linux`) — it is
  **insufficient** for the asset name. Write a dedicated small resolver mapping
  `Darwin→darwin`, `Linux→linux`, `arm64|aarch64→arm64`, `x86_64|amd64→amd64`.
- **Unsupported OS/arch fails clearly before any write** (no partial managed dir, no temp files left).

### A3 — Existing-binary reuse (offline fast path)

- If the managed `<version>/vcluster` already exists **and** identifies as the requested version
  (invoke it, e.g. `vcluster --version`, and match `<version>`), return its path with **no network
  access**.
- A managed binary that reports a **different** version is not silently accepted — fall through to
  the verified re-acquisition path (A4), do not return it.

### A4 — Integrity-gated acquisition

- Download the release **checksum manifest** and the **matching asset** into a `mktemp -d`
  directory. Derive URLs from the `loft-sh/vcluster` release
  `https://github.com/loft-sh/vcluster/releases/download/v<version>/`. **Confirm the exact asset and
  checksum-manifest filenames against that release before hardcoding**; a 404 must fail clearly.
- **Verify SHA-256 of the asset against the manifest before** marking it executable or replacing any
  managed binary. Never `chmod +x` or execute an unverified download.
- Install into a **temp file inside the managed `<version>/` directory**, then **atomically rename**
  into place only after verification succeeds.
- Remove temp files on **both** success and failure (trap-based cleanup).
- If `curl` is unavailable, report the **exact** missing prerequisite and return non-zero **without
  modifying the host**.

### A5 — Concurrency + failure safety

- Use a **per-version lock** (e.g. a lockfile/`flock`-style guard under the managed dir) so concurrent
  callers serialize; the loser waits and reuses the winner's result. No stale lock/temp left behind.
- A **failed update must leave an already-verified managed binary usable** — never delete the good
  binary before the replacement is verified and renamed.
- **Offline + absent + unfetchable** → non-zero with an actionable message. **Never** fall back to an
  arbitrary `vcluster` on `PATH`.

### A6 — BATS (stubbed `curl`/`uname`/`sha256`/`vcluster`) in `scripts/tests/lib/system.bats`

Prove **all** of:

- a verified existing exact-version binary is **reused without any download** (stubbed `curl` asserts
  it was never called);
- a version **mismatch** is rejected and replaced through the verified acquisition path;
- **malformed version** and **unsupported OS/arch** fail **with no writes** (managed dir stays absent);
- a **checksum mismatch never activates** the binary (no executable left, prior binary untouched);
- a **failed download preserves** a prior verified binary;
- **concurrent callers** leave exactly one valid executable and no stale lock/temp files;
- **no package-manager command** (`brew`/`apt`/`dnf`/`npm`/`pip`) is invoked (stub them to fail-loud).

### A7 — Docs

- Document `foundation_ensure_vcluster_cli` in `README.md` **and** `docs/api/functions.md`: public
  signature, managed location, host prerequisites (`curl`), supported OS/arch, offline behavior.
