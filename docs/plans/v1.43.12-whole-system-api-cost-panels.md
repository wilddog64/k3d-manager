## Why

The operator wants to know what the engineering system would cost if Claude and Codex were paid
through their APIs instead of the flat subscriptions. Every input is already exported:

| Input | Metric |
|---|---|
| Claude at API prices | `k3dm_dispatch_claude_api_cost_usd{window}` |
| Codex at API prices, sessions in the dispatch ledger | `k3dm_dispatch_api_cost_usd{window}` |
| Codex at API prices, sessions outside the ledger (time windows only) | `k3dm_dispatch_unledgered_api_cost_usd{window}` |
| Live-verified specs and bugs | `k3dm_claude_verified_specs{window,level="live"}` |
| Days the cost data covers | `k3dm_dispatch_api_cost_observed_days`, `k3dm_dispatch_claude_api_cost_observed_days` |
| Subscription plans | `k3dm_dispatch_subscription_usd_per_month{plan}` (`claude`, `chatgpt`, `gemini`, `github`, `hostinger`) |

A dry-run of the generator on 2026-10-29 gave, for 7d: Claude $292.58, Codex ledgered $5.41,
Codex unledgered $0.10, 93 live-verified, i.e. **$3.21 per live-verified spec**. The dashboard
today shows only the Claude share (`Claude cost per live-verified resolution`, panel 93) and a
monthly projection that leaves out unledgered Codex sessions.

The cost side counts every session in the window, so failed dispatches, rework and review are
already in the numerator. That is intended: the panels measure the whole system, not one model.

## Change

One file of dashboard JSON, its tests and its guide page. No generator change.

In `scripts/etc/argocd/platform-ops/grafana-dashboard-agent-cost.yaml`, add a row titled
**Whole system at API prices** below every existing panel (today the lowest panel ends at y=43),
with four stat panels using new unused ids:

1. **Claude + Codex at API prices** (`currencyUSD`): Claude cost + Codex ledgered cost + Codex
   unledgered cost for `$window`.
2. **Claude + Codex per live-verified spec** (`currencyUSD`): panel 1's sum divided by the `live`
   verified count for `$window`; No data when the count is 0 (`> 0` guard, as panel 93 does).
3. **API run rate / month** (`currencyUSD`): from the 7d window, each of the three cost terms
   divided by its observed days and scaled to 30 days. Unledgered cost has no observed-days series
   of its own; use `k3dm_dispatch_api_cost_observed_days{window="7d"}`. Independent of `$window`.
4. **API vs replaced plans** (unit `x`, 1 decimal): panel 3 divided by the sum of the `claude`
   and `chatgpt` subscription plans, the two plans an API switch would replace. Gemini, GitHub and
   Hostinger stay. Independent of `$window`.

PromQL rules:

- Wrap every term in `sum by (window) (...)` before arithmetic (the cost series carry different
  job/instance labels; v1.43.10 fixed panel 93 the same way). For panels 3 and 4, where windows
  differ or are fixed, aggregate with `sum(...)` so the terms combine.
- The unledgered series exists only for `1d`/`7d`/`30d`, not for a release window. A missing
  unledgered term must count as 0, not blank the whole panel: for example
  `(sum by (window) (k3dm_dispatch_unledgered_api_cost_usd{window="$window"}) or sum by (window) (k3dm_dispatch_claude_api_cost_usd{window="$window"}) * 0)`.
- Each panel's `description` states what it divides and that prices are list API prices.

Keep the existing panels, ids and positions unchanged. Panels must not overlap (an existing test
checks this).

Docs: in `docs/guides/grafana-dashboards/k3dm-agent-cost.md`, add a short section for the new row
naming the four panels, what each divides, that rework and failed dispatches are included, and
that plan 4 compares against Claude + ChatGPT plans only. Add a CHANGELOG `[Unreleased]` entry.
