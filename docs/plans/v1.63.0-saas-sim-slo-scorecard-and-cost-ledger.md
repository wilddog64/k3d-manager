## Why

Without fixed numbers and a failure condition, "the platform supported it" is true by default. This plan
fixes both before any run starts and makes them visible on one dashboard.

## Targets (frozen at run start; changing one mid-run voids the run)

| Measure | Target | Source |
|---|---|---|
| Availability | ≥ 99.5% over the run (about 3.6 h of budget in 30 days) | external probe of the sim's login and one read path every 60 s |
| Latency | p95 ≤ 800 ms on the read path during traffic hours | the same probe plus the app's request histogram |
| Secret exposure | 0 | gitleaks on new commits, a log scan for the sim's Vault values, the existing CodeQL |
| Traceability | 100% of production changes trace to a spec or bug doc and a dispatch record | the dispatch ledger joined to ArgoCD sync history |
| Operator time | ≤ 60 min per day, as a 3-day rolling mean | operator log (below) |

The probe runs from a machine other than the hub (M2 runner or M4), so a hub outage is counted rather
than going unseen. Exact latency and probe hosts are confirmed during the pilot: each is recorded with
the host and date it was measured on, per the prove-external-behaviour rule.

## Stop conditions (any one ends the run and answers "no, because X")

- S1: availability error budget fully spent.
- S2: any confirmed secret exposure.
- S3: operator time above 60 min/day for 3 consecutive days.
- S4: a production change with no spec and no dispatch record.
- S5: the operator ends the run for safety.

## Ledgers

- **Operator time.** `make saas-sim-log MIN=<n> WHAT="<text>"` appends a timestamped entry to a local
  JSONL file that the metrics exporter publishes. Uncounted time is the main way this experiment could lie
  to itself, so the daily report asks for a zero entry on quiet days rather than leaving a gap.
- **Agent cost.** Read from the existing `k3dm-dispatch-metrics` series, API-equivalent dollars per
  day by model, including agy and Claude after the v1.43.15 fixes. No new collector.
- **Incidents.** Each SLO breach or injected fault gets a `docs/bugs/` entry. Time to detect is
  measured from injection or breach to first alert. Time to recover is measured to probe green.
