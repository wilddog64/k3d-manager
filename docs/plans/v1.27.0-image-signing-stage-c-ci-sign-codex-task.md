## The signing pattern (apply consistently)

Images are multi-arch (`linux/amd64,linux/arm64`); `docker/build-push-action` reports the **index
digest** in `steps.<id>.outputs.digest`. Sign THAT digest. The key is delivered as GH Actions
secrets `COSIGN_KEY` (the cosign private key) and `COSIGN_PASSWORD` (Claude seeds these separately —
do NOT hardcode or generate them). Pin `sigstore/cosign-installer@v3.7.0` (A08 — never `@main`).

The two steps to add immediately AFTER the push step, gated so builds don't fail before the secret
is seeded:

```yaml
      - name: Install cosign
        if: env.COSIGN_KEY != ''
        uses: sigstore/cosign-installer@v3.7.0

      - name: Sign image by digest
        if: env.COSIGN_KEY != ''
        env:
          COSIGN_KEY: ${{ secrets.COSIGN_KEY }}
          COSIGN_PASSWORD: ${{ secrets.COSIGN_PASSWORD }}
        run: |
          cosign sign --yes --key env://COSIGN_KEY "${IMAGE_REF}@${DIGEST}"
```

where `${IMAGE_REF}` is the pushed image name (no tag) and `${DIGEST}` is the push step's
`outputs.digest`. Set them via `env:` from the correct expressions per repo (see below). Never put
the key or password in `run:` args or echo them.
