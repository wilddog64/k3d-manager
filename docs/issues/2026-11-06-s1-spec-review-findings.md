## Blocker

1. **The two readers do not have a complete shared replay contract.** The spec says ledger order does not matter for the ladder, but “latest” and “falls while it is the latest run” require ordering, and the streak mixes run order with a clearance timestamp (plan lines 219–228). The dispatcher timestamps only to the second (`bin/k3dm-codex-dispatch:23`–24); the CA replay already has intervention and resume at the same timestamp (`scripts/tests/fixtures/dispatch-gates/ca-trust-stall.jsonl:6`–7). Multiple assessments, verifies, clears or exits at the same timestamp, late assessments, and a correction arriving after a clear have no defined tie-break or placement. There is also no definition for an absent coverage marker, equal start/coverage timestamps, duplicate slugs across versions, or the identity of an open architecture event (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:204,223,226–236`). **Change:** define task key and slug resolution, stable ordering (including ties), latest assessment/verify, classification and reset timing, missing coverage and boundary semantics, and open/clear transitions; add shared fixtures for each. Specify the JSON shape and next-action precedence as well, so M7 can compare concrete outputs.

2. **The existing ledger has two exit event types, but the S1 fixture covers only one.** `codex_exit` emits `run` and `exit` (`bin/k3dm-codex-dispatch:150`–158); agy emits `agent_exit` with the same fields (`bin/k3dm-codex-dispatch:163`–174,247–257). Existing metrics explicitly recognizes both (`bin/k3dm-dispatch-metrics:740`–745). S1 speaks of an exit without naming event types (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:221,226`), and every synthetic exit is `codex_exit` (e.g. `scripts/tests/fixtures/dispatch-gates/synthetic.jsonl:2,13,19`). A reader that handles only the latter misclassifies agy runs. Conversely, historical resumes in the CA fixture have `n` but no `run` (`scripts/tests/fixtures/dispatch-gates/ca-trust-stall.jsonl:4,7`), although current resumes emit both (`bin/k3dm-codex-dispatch:1041`). The schema does **not** supply historical pinned `baseline_sha` or `parent`/`role`: current start supplies `spec`, `run`, agent and identity, not these fields (`bin/k3dm-codex-dispatch:694`–698); `verify` has no run number (`bin/k3dm-codex-dispatch:407`–412). **Change:** explicitly map both exit types and historical `n` fallback, define missing-field behavior and association of unnumbered events, and add agy and legacy cases. Do not invent historical baselines.

3. **The split metrics conflict with the unbounded-label prohibition and leave aggregation undefined.** N7 prohibits any unbounded label (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:299`), while the specified series expose arbitrary `parent` strings (`:251`–256); restricting them to explicitly split tasks does not bound the number or values. No validation, cardinality limit, or overflow behavior is specified. The contract also omits reassignment, repeated links/combines, orphan combines, role zero series and elapsed-time behavior for late links (`:212`–215,240,251–254); the fixtures exercise only a single clean combine (`scripts/tests/fixtures/dispatch-gates/synthetic.jsonl:86`–94). **Change:** choose a genuinely bounded representation or explicitly revise N7 and define a cardinality policy; define membership, latest-combine and elapsed semantics, and add adversarial fixtures. Both halves otherwise can produce different valid interpretations.

4. **The mandatory red-on-pre-fix condition cannot be met literally for every S1 negative.** The pre-fix dispatcher has no `gate-status`, `mark`, or `gate-record` (`bin/k3dm-codex-dispatch:1129`–1146); a missing-command failure is not evidence that a behavioral refusal or no-mutation assertion caught the defect. N4 asks that existing start/resume/land remain unchanged with advisory open state (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:296`), which pre-fix has no gate to block; its positive behavior should already pass, not turn red. N7's new series also do not exist pre-fix, so a negative-only label assertion can pass vacuously. N1–N3 and N5–N7 are testable after implementation, but pre-fix absence can only make an explicit interface/positive-control check red, not demonstrate the prohibited behavior; N4 is a non-regression property. E3 tests only resume, though N4 also names start and land (`:296,303`); E1 checks the ledger and listing, not contents of other existing files (`:293,301`). **Change:** distinguish new-interface red checks from behavioral regressions, require positive controls and mutation tests for each negative, and explicitly treat N4 as a pre-fix-green non-regression test. Cover all three operations and hash/snapshot relevant existing files for N1. Resolve this against the dispatch rules before work starts.

## Should-fix

1. **Manual replay checks mostly agree, but coverage semantics are inconsistent.** (a) `stalled-task`: two correction resumes charge runs 1 and 2; run 3 has no exit, giving streak 2, open and implemented pending (`scripts/tests/fixtures/dispatch-gates/synthetic.jsonl:18`–22; `expected.json:365`–379). (b) `double-count`: the nonzero exit and correction both charge run 1 once; intervention adds nothing, giving streak 1 (`synthetic.jsonl:23`–26; `expected.json:131`–144). (c) `evidence-reset`: correction charges run 1, assessed progress with digest resets, then correction charges run 3, yielding unsuccessful [1,3] and streak 1 (`synthetic.jsonl:43`–51; `expected.json:146`–160). (d) CA replay: run 1 becomes unsuccessful at resume 2; run 2 at resume 3, so 1793622701 is clear/1 and 1793622702 open/2 (`ca-trust-stall.jsonl:1`–7; `expected.json:3`–11). These cases agree with the fixed rules (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:221,226`–232); this is not a claim that every fixture row has been independently validated. However N5 says outside-coverage rungs without a source must be unknown (`:297`), while the ladder makes missing verify pending and missing exit/land pending even outside coverage (`:221`–224). The old-task example avoids exposing this because it has a digestless passing verify and a land (`synthetic.jsonl:1`–5; `expected.json:230`–241). **Change:** enumerate precisely which rungs N5 covers and add an old unverified, unlanded task.

2. **The evidence contract cannot reproduce the specified synthetic twin without further interface details.** `gate-record` says schema fields are flags and refuses absent evidence (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:206`–211,238), but null evidence is explicitly valid for an assessment, and no flag spellings, array encoding, baseline SHA validation, empty-file policy, or duplicate assessment policy is specified. The schema also supplies a plan digest rather than an `evidence_path` for replan. **Change:** give complete command examples and flag types per event, identify optional versus required files and validation, and define handling of repeated events. This is S1 design work, not a dependency on later enforcement.

3. **Dashboard query tests and combined check need more exact observability.** The exporter emits aggregate counts (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:247`–254), while M7 asks for the same task-level stall and ladder answers (`:291,306`). Multiple tasks in a bucket cannot be individually matched to `gate-status` without a controlled single-task ledger or separately computed expected aggregate. The exporter’s existing grouping includes every `(version, slug)` including slugless events (`bin/k3dm-dispatch-metrics:732`–737), so coverage and combine records need explicit exclusion from task counts. **Change:** define M7 using isolated one-task cases plus aggregate fixtures and specify task discovery and zero/absent series behavior.

4. **S1 has no necessary implementation dependency on S2–S5, but its claims must stay advisory.** S1 explicitly excludes the rest of the document and does not block launches (`docs/plans/v1.43.14-dispatch-stall-detection-and-escalation-gates.md:187`–191). Its recorded SHA and evidence digest are sufficient for a *reported* mark, not proof of independent verification, deployed revision, authenticated reviewer, or enforcement (`:205`–211,237`–238`). The reviewer check compares literal model/agent strings only; it does not establish identity. **Change:** label these as self-reported/advisory in CLI and dashboard documentation, and explicitly defer evidence provenance, authenticated approvals, canonical aliases and enforcement to later slices. Separately, the stated D3/alert prerequisites are explicit rollout gates, not hidden S2–S5 code dependencies (`:189`).
