Reviewer: Codex, 2026-11-06. Scope: S1 only.

## Blocker

1. **The required status output and oracle disagree.** The fixed JSON contract makes `open_scope` and `open_architecture` lists of objects (plan:253,261), but the committed oracle stores numbers, including zero for `late-assessment` (scripts/tests/fixtures/dispatch-gates/expected.json:374-375). M1 requires every stored field to match and exactly the listed keys (plan:356). An implementation cannot satisfy both. Change the oracle to arrays with the specified objects and make M1 explicitly compare them; review all fixture fields against the exact output before dispatch.

2. **The combined replay loses coverage context.** M7/E6 require each synthetic task replayed as its own ledger and compared to the full-ledger status (plan:362,386), yet coverage depends on the global marker and its line position (plan:225,238). The fixture places `boundary-before`, marker, and `boundary-task` in that order at the same second (scripts/tests/fixtures/dispatch-gates/synthetic.jsonl:7-9). A ledger containing only the latter task has no marker and produces unknown instead of pending. Specify that each isolated replay retains the original global marker in its original relative position, along with relevant non-task context, and define the aggregate comparison.

3. **The new prompt denominator can be zero for a counted prompt.** Existing human prompts count all scoped intervention lines regardless of marker timestamp (bin/k3dm-dispatch-metrics:1497-1508); the new numerator must sum to that series (plan:310-312,365), but its denominator counts only events at or after the marker (plan:313). A scoped pre-marker intervention with no later qualifying event has a numerator and no model task; the 10-task ratio also has an undefined population. The fixture has starts before the marker but no pre-marker intervention (scripts/tests/fixtures/dispatch-gates/prompts.jsonl:1-3). Specify whether all counted prompts contribute a distinct task regardless of coverage, or change the invariant and existing-series policy; add a pre-marker prompt and marker boundary case. Also define timestamp versus line order for the intervention coverage boundary, since existing code uses the earliest timestamp.

4. **The pre-fix and mutation proof is not executable as written for every negative.** N4 requires start on an open stalled task (plan:372,383), but a new start resets the attempt and its stall and open gates (plan:227); the parent has none of these commands or states (plan:352). E3 cannot establish identical open-state behavior on the parent as stated. N11 also requires identical resume lines to the parent (plan:379), although timestamps and other dynamic fields vary. Define controlled fixtures and observable equivalence, including which start is tested and normalized fields, and specify a meaningful parent baseline and mutants for each distinct prohibition. N1's snapshot and E2's ledger-only checks also do not establish that every refusal writes nothing anywhere (plan:265,369,382): snapshot all relevant scratch paths for refusals.

## Should-fix

1. **Prompt model history and cardinality need a complete window contract.** The rule walks all task lines (plan:259), while series use scoped events (plan:310); explicitly require replay of prior out-of-window and pre-marker starts to establish current model before filtering counted events. Otherwise the fixture's crossing task is ambiguous. Define how literal `other` and invalid/overflow names merge before ranking and how distinct tasks and numerator are merged, including a task that touches multiple overflow models. The 12-model rule (plan:316) and N10's 14-model test (plan:378) do not fully specify those collisions. Add adversarial cases.

2. **Panel checks prove names, not usable tables.** M12 only checks that queries name produced series (plan:366,385); it does not prove the model table joins tasks, prompts and optional ratios per model or that sender/cause/reason totals are correct. Similarly M6 does not prove the split table combines its four series (plan:304-307,361). Require query/transform assertions on sample output, including absent ratio/conflicts and zero counts, and verify dashboard descriptions required at plan:324-326.

3. **Flags and scope are useful but should be a follow-up.** `sent_by`/`cause`, model attribution, three series and two tables add a separate analytics contract and cardinality problem (plan:217,259,286,310-316,326), while S1's gate replay already needs independent implementations and reconciliation (plan:193-198). Split these additions into a follow-up after S1's gate contract is stable; preserve the operator's goal and explicitly sequence the follow-up. If retained, resolve the blocker and specify tests for both flags on both commands, omission and invalid values.

4. **Negative evidence needs more precision.** N2 combines several independent non-effects and two controls (plan:370), while E9 asks for only one mutant per must_not (plan:389); a single mutant cannot demonstrate that each assertion detects its corresponding defect. N3's positive control does not exercise a valid offline mark; N7 and N10 each combine several different bounds (plan:359,371,375,378). Require a targeted mutant and positive control for each independent behavior, and document the allowed pre-fix interface failure separately from behavioral red. The brief's own N1 is a diff-scope property: its requested pre-fix red cannot establish a prior violation when no finding file existed; a scope check is a non-regression control.
